## 零、结论摘要（v4 更新）

1. **规则封闭、对象开放（v4 定稿）**：层本体 = 缓存语义七条（零签名、无恒等式 → 无封顶）；对象（条目、配方、标注）无界——任何范式的值都装得下。**规则封闭 = 维护有界；对象开放 = 表达无界。** 新范式不动层本体、不动判定规则，只做三件事：图标注空间加标签（统一空间）、CIC 内部定义新结构（健全性继承）、硬件映射（不可避免的工程，非层工作）——**不按范式枚举**
2. **无格承诺（v4 定稿）**：任何具体格 = 签名 + 恒等式 = 封顶。解法：语义写在比格更弱的理论里（最弱理论 = 最多模型 = 无界）。判定/定理只在关系层面陈述（共存关系连预序公理都不需要——共存无传递性，是对称关系）；格（Lattice 代数）降级为**映射实例的组织参数**（经典行用乘积格组织状态、量子行用别的、未来范式用未知格），与字节/区域/寄存器同族。category theory 原则：**用函子式/普适构造定义层，不用情形分析**（函子性 = 无 case 语句）
3. **M1 定论（v4）**：**语义保鲜线不需要「能力」独立概念**——还原测试通过：身份 = 图节点身份（已存在）、无配方 = 标注（已存在）、授权 = 治理层「可能关系」标注。能力 = 一等公民的**提升判据未触发**（图 + 格 + 映射规则已自然表达）；不提升且**可逆**（提升是表面/API 决策，不是语义决策，语义层不随提升与否变化）——零成本 YAGNI，选项永远保留
4. **M4 输入（v4）**：边界公理（条款 4）只覆盖图边界；神谕/FIXPT/BSS 是**图内不可重算**——驱逐不变量/再生等价对其不成立（重跑神谕 ≠ 原结果），缓存七条需显式「图内不可重算」条款（§5.3）
5. **寄存器分配 = 缓存语义映射实例（v4 定稿方向）**：与区域/arena/字节权限同族（条款 7）。驱逐不变量 = 语义保持定理——正确性与执行顺序无关（对所有可能执行成立，强于任何 CFG 正确性）。判定单层（一致性）、分配算法定案 = 上下文贪心（零证明）。CFG 算法（线性扫描/图着色/SPL）都是线性化退化实例（§11.5）
6. **该用能力（v2 保留，v4 重定位）**：能力不是「存储位置的原语」（那是条目标识 + 偏移，已定稿），而是**不可重算结构的身份与授权机制**——v4 定稿：语义内容还原图上（身份/无配方/域），**授权集归治理层**（consult/assume/measure/pass = 可能关系标注，非语义本体）
7. **判据 = 表达范围**：存储半边（缓存语义，已定稿）∪ 执行标注空间（非因果/模糊/超图灵/共归纳，dataflow-design §8）
8. **三层映射定位（v3 定、v4 晋升更名）**：图 = 关系空间（跨范式语义中轴）、格 = 状态/存储空间（内存模型 = 中间存在空间）、编码 = 物理编码空间（2026-08-27 更名：原「二进制」硬编码经典惯例）；跨范式发生在图层，超图灵性属于图不属于格
9. **验证主线（v3 保留）**：Graph → Lattice 映射通用性 8 项清单（§十二）——每项通过 = 三层链成立的证据；v4 新增实证：寄存器分配判定以纯格对象写出（无路径结构）= 「格不重引入顺序」判据（#10）的实例化

## 一、背景：抽象升华系列（v1 保留）

1. **核心语义 = 数学/逻辑/结构，零硬件惯例**——惯例只允许以「后端实现选择」或「可忽略注解」存在
2. **范式普适**：语言要跨越所有范式（量子、分布式、GPU、未来未知范式）
3. **用户面上手成本极低**：内部可以复杂（编译器承担），表面必须简单

## 二、位置抽象的两难（v1 保留）

```
太复杂（全一般理论，如完备格代数全套）
  → 上手成本爆炸——用户要学格运算

太低端（纯 1D 扁平地址）
  → 范式特例跨不过——量子寄存器（纠缠是位置间关系，不是顺序）、
    分布式（node 是身份不是偏移）、GPU（bank 冲突）
```

## 三、结构性论证：位置识别的两种必然形式（v1 保留）

「存东西」要求位置**可识别**。「指认位置」只有两种结构：

```
有序的位置 → 偏移原语（±4、连续坐标）
命名的位置 → 标签原语（内容寻址=hash、图节点、属性标识、句柄）
```

纯值流范式（函数式/数据流）**无位置概念**——位置抽象自动失效（§五 半边二的 CORE 共归纳即此例）。

## 四、三层映射：图 → 格 → 编码（v3 新增 + v4 晋升；2026-08-27 第三层更名：二进制 → 编码）

```
不同范式 / 计算语义
        ↓
       图（HDFG）       —— 关系空间：发生什么
        ↓ 图 → 格映射
       格（内存模型）    —— 状态/存储空间：如何存在
        ↓ 格 → 编码映射
     编码              —— 物理编码空间：如何实现
```

### 4.1 为什么需要格这一层

图回答「这个计算世界中有什么关系、什么可能发生」；格回答「这些东西如何成为具有状态和位置的可实现存在」。若图 → 二进制直连，大量「如何存在」的问题（节点是什么内存对象、关系怎么保存状态、两个可能分支的状态怎么共存、非因果怎么落地址、节点生命周期）都会被迫塞进一个万能的图→机器码映射器。

### 4.2 三层的数学定位

- **图 = 关系空间**：表达可超越经典图灵机执行模型的语义（非因果、模糊、超图灵）——**超图灵性属于图，不属于格**
- **格 = 状态/存储空间**：提供足够一般的状态模型使图能够被映射下来；格不需要「理解超图灵」，只需让可被当前执行环境实现的部分拥有状态/位置/关系/可访问性
- **编码 = 物理编码空间**：把格编码成具体机器的地址、字节、指令、位模式
- **格不重新引入「程序顺序」**：传统 IR（SSA/LLVM）本质上仍是「另一种程序」——按执行路径组织；格 = 中间存在空间，不必重新引入程序顺序。这是三层链成立的关键判据（见 §十二 清单第 8 项）

### 4.3 跨范式自由度（格的价值）

「跨范式用格」比「格作为内存模型」更准确：

- 不同范式（命令式/函数式/数据流/并发/事件驱动/非确定/模糊/超图灵）的差异首先被图吸收（图层标注空间，dataflow-design §8）
- 格不被某个有限、固定的传统计算范式预先封顶——允许递归构造、关系组合、无界规模，可构造表达空间无界
- 于是真正的问题是「C 的语义能否找到一个格映射」，而不是「格能不能表示 C」——**格本身不需要知道范式是什么**

### 4.4 术语澄清：格的两义

「格」在本备忘（及全仓库）有两义，阅读时先判定语境：

| 术语 | 含义 | 位置 |
|---|---|---|
| 格（层） | 内存模型 = 中间存在空间（第二层映射） | 本节；`docs/maintainer/design/memory-model.md` |
| 格（Lattice） | 层内组织代数成分（偏序 + join/meet） | §九 代数（PCM × 布尔格）；**v4：映射参数，非层本体承诺** |

### 4.5 规则封闭、对象开放（v4 定稿）

层本体的构成与界限：

- **规则（封闭，永不新建）** = 缓存语义七条 + 最弱理论（关系层面）。新范式出现时层本体一字不改——**规则封闭 = 维护有界**
- **对象（开放，无界）** = 条目、配方、标注。任何范式的值都装得下（量子振幅、FIXPT 不动点、模糊隶属度……配方产生任何值）——**对象开放 = 表达无界**
- **一切结构是图层导出或映射参数**：共存关系是图层的导出（图活性，RegionCheck 已实现），不是格层的承诺；格（Lattice）代数、区域、字节、寄存器都是映射实例

新范式真正要做的事只有三件，没有一件是「新建格」：

1. 图标注空间加标签——统一空间，加标签不是新机制（FUZZY/FIXPT/Oracle/CORE 已是标签）
2. CIC 内部定义新结构——一个逻辑，健全性继承（翻译桥既存）
3. 硬件映射——不可避免的工程，但它是映射工作，不是层工作

判定规则是**条目泛型**的：操作「条目」这个类别（位置 + 配方 + 存在），不读值的内容——新条目的种类不需要新判定规则。

### 4.6 无格承诺（v4 定稿）

- 任何具体格 = 签名 + 恒等式（幂等、吸收、分配……）→ 恒等式封顶表达空间。解法不是「选一个更宽的格」，而是**把语义写在比格更弱的理论里**——最弱理论 = 最多模型 = 无界
- 分配/存储判定需要的最弱结构：共存关系（对称关系——共存无传递性：a 与 b 共存、b 与 c 共存，a 与 c 不必共存），连预序公理都不需要
- 格（Lattice 代数）降级为**映射实例的组织参数**：经典行用乘积格组织状态、量子行用别的、未来范式用未知格——与「范式映射表 = 映射正确性定理表」同构，每范式引入自己的代数都是参数
- 数学原则：**用函子式/普适构造定义层，不用情形分析**——函子对一切输入统一作用（category theory 里「无 case 语句」的写法）；对象由普适性质定义（直到同构唯一），不选具体结构
- 验证视角：判定/定理写在最弱理论里，对一切格成立；CIC 内核里任何具体格都是该理论的一个模型——健全性对理论成立，就对所有模型成立。将来格定成什么都行，验证基座不动

## 五、表达范围（v2 判据推导 + v4 补充）

表达范围 = 系统必须表达的语义，分两半边：

### 半边一：存储（缓存语义，已定稿）

maintainer/design/memory-model.md §一 七条条款：值 = 配方、驱逐不变量、再生等价、边界公理、赋值 = 版本化、地址 = 映射、映射实例正确性。位置语义 = (条目标识, 偏移)；区域 = 图锚定字节域（推论 B: split/merge/share）；字节权限层（Freeable > Writable > Readable > Nonempty > Empty）= **经典映射实例的权限面**（条款 7），非语义本体。

### 半边二：执行标注空间（dataflow-design §8）

| 结构 | 要表达什么 | 对语义公理的突破 |
|---|---|---|
| FIXPT 非因果环 | 不动点（μ/ν, Knaster-Tarski），声明性、执行后置（PSPACE 难） | 再生等价（不可重算） |
| FUZZY 模糊软分支 | 格值隶属度（剩余格），两路都执行按隶属度加权融合 | 分支互斥 + 可重算（融合共享归属） |
| 超图灵·神谕 | 「此节点计算函数 F」，F 可不可计算；验证 = 例外入口（unsafe 同层） | 值 = 配方（无配方条目） |
| 超图灵·连续（BSS） | 无限精度实数 = 原子符号 | 值 = 配方（无限信息） |
| 超图灵·超限（ITTM） | 序数时间位置、limsup 极限阶段 | 有序位置原语扩展（链/格） |
| CORE 共归纳 | 流 = 终余代数（CoNode），有限前缀可算 | 无（纯值流范式，§三 豁免） |

### 5.3 图内不可重算条款（v4，M4 输入）

- **现状缺口**：边界公理（条款 4）只覆盖**图边界**（MMIO/FFI/输入/测量）；但执行标注空间的不可重算结构（神谕、BSS 实数、FIXPT 声明、模糊融合）在**图内**而非边界——条款 1–3 与条款 4 之间存在未覆盖地带
- **语义内容**：驱逐不变量/再生等价对图内不可重算条目**不成立**（重跑神谕 ≠ 原结果）——「必须有 home、驱逐必写回」不是便利，是唯一正确的语义
- **建议条款（待并入 maintainer/design/memory-model.md）**：图内不可重算条目（无配方且非边界）= 例外条目；其存储必须持久（home 保有材料），驱逐必须写回；身份 = 产生节点（图节点身份），无独立身份符号
- **一视同仁规则**：对所有无配方条目（边界 + 图内）统一处理——不按范式枚举（这正是 M1「能力不需要」的实证之一，§六）

**关键判据（v2/v3 保留）**：缓存语义条款 1–3 只覆盖**可重算结构**；不可重算结构需要「无配方」标注 + 统一写回规则——这是语义层的最小必需，不需要独立「能力」概念（§六）。

## 六、该不该用能力 → v4 定论

> **v4 定稿（2026-08-27）**：M1 判定——**语义保鲜线不需要「能力」独立概念；能力不提升为一等公民（可逆、暂不执行）**。三步还原：
>
> 1. **身份 → 图节点身份**（已存在，零新概念）。无配方条目必须能区分实例（两次咨询神谕可能返回不同值）——但「这个条目是哪个节点产生的」本来就写在图上
> 2. **无配方 → 标注**（已存在）。统一规则（必须有 home、驱逐必写回）只需要一个 flag，对所有无配方条目一视同仁
> 3. **授权集 → 治理层**。consult/assume/measure/pass 是「什么操作被允许」的策略，不是「操作结果是什么」的语义——语义保鲜不依赖授权，治理才依赖；治理形态 = 图上「可能关系」标注（A ──可能执行──> B，v3 已定），非顶层原语
>
> **提升判据（#11）未触发**：图 + 格 + 映射规则已自然表达（§4.5/§4.6）——「无法自然表达」不成立。**不提升可逆**：提升是表面/API 决策，不是语义决策——语义层不随提升与否变化；暂不提升 = 零成本 YAGNI，选项永远保留。
>
> **架构不对称性**：标注可长，原语不可长。授权策略将来要细化，在标注层扩展 = 加标签（廉价、统一空间）；提升成原语后每次扩展都是语言变更（枚举维护）。「不提升」把扩展性留在正确的位置。

v3 定位（保留）：能力 = 图上「可能关系」的实例，与 FUZZY 模糊分支 / 非确定路径 / 非因果统一（都是图的关系语义，不是独立类型）；consult/assume/measure/pass 授权标注即「可能关系」的落地形态。只有当「图 + 格 + 映射规则」无法自然表达时（确实需要独立生命周期 / 权限 / 内存布局 / 执行语义），才把能力提升为一等概念——判定见 §十二 清单。

能力三件套（CHERI 式句柄/权限/边界）对照表达范围（v2 保留）：

| 能力成分 | 表达范围对照 | 结论 |
|---|---|---|
| 句柄（不可算术的身份） | 可重算侧：条目标识（配方身份）已覆盖；不可重算侧：神谕/BSS 实数/FIXPT 声明需要符号身份——**v4：身份 = 图节点身份，无独立身份符号** | 还原为图结构 |
| 边界 | ProvenanceVerify 已覆盖（off + width ≤ alloc_size，2026-08-16 统一） | 已定稿不动；对应物 = 域约束（类型签名） |
| 权限 | 字节 R/W/X = 经典映射实例（字节权限层）；语义授权（consult/assume/measure/pass）| **v4：归治理层**（可能关系标注） |

- 格的组织职责（区域包含/组合/细化）保留——「设计决定用格」成立；**v4：格代数 = 映射参数，非层本体承诺（§4.6）**
- 能力的不透明句柄机器形态（CHERI tag）不进语义层——语义层一切透明（值 = 配方）；不透明是经典机器防护形态（威胁模型差异，§十一）
- 先例与约束：Karger & Herbert 1984（能力架构 + 格安全组合）；Kain 1986 警告——不是所有能力设计都能强制格策略，**约束 = 细化 ⊑ 必须可强制**

## 七、能力成分（v2 定形，v4 重定位 = 治理层形态）

能力 = **⟨身份符号, 授权集, 域约束, 派生源⟩**（v4：身份符号 → 图节点身份；授权集 → 治理层）

| 成分 | 内容（v2） | v4 定位 |
|---|---|---|
| 身份符号 | 指向什么——神谕符号、BSS 实数符号、声明式不动点名 | 还原为图节点身份（无独立符号） |
| 授权集 | 能做什么——consult / assume / measure / pass | 治理层（可能关系标注，非语义本体） |
| 域约束 | 适用边界——神谕类型签名 F: ℕ→ℕ 等 | 保留（语义边界，非字节长度） |
| 派生源 | 从哪个声明/能力派生而来 | 保留（例外入口授权可追踪，信任链） |

**排除**：基址/长度/字节 R/W/X——经典映射实例（字节权限层已有定稿）。

## 八、结构：能力树（v2 定形，v4 重定位 = 治理层结构）

- **能力树**（seL4 CNode / KeyKOS-EROS 节点树先例）：每子图一棵——寻址（树路径）、派生（mint/copy 沿树）、撤销（剪枝/alloc count 失效）、隔离（每域一棵）——**一个结构**（治理层形态）
- **表是多余的**：命名树的层级 ≠ 语义层级——平级符号（神谕/实数）只是树上的叶子
- 共享/融合：Copy 别名（多槽引用同一对象）；merge/share 是区域代数的语义（§九 PCM），不归寻址结构管
- **兑现 = 编译期**：能力树是语义层图数据（与字节权限层同定位），能力流分析编译期消费，证明完毕不下发
- 用户面：声明式进图（alloc_at 先例：声明即注册、生命周期随子图），句柄不透明——零管理，上手成本不变

## 九、代数：PCM × 布尔格（v2 定形，v4 重定位 = 映射参数层）

> **v4 补充**：以下代数是**经典映射实例的组织参数**，不是层本体的承诺（§4.6 无格承诺）。判定/定理只在关系层面陈述，对一切格成立；本代数是对经典行的选择，量子行/未来行可另选。

### 候选品谱系（v1 §四 保留 + v2 判决）

| 候选 | 第一原语 | 判决（v2） |
|---|---|---|
| 格（Lattice） | 偏序 + join/meet | 组织职责保留，但作为能力代数不够精确（见下） |
| PCM（偏交换幺半群） | 分割/组合 `·` | 区域分量采用（分离逻辑底座） |
| 树/层级 | 唯一父结构 | 命名/派生结构采用（§八），非代数 |
| 向量空间 | N-D 坐标 | 否决（区域/组合语义缺席） |
| 能力模型（Capability） | 句柄 + 权限 | 采纳，职责重划（§六/§七） |

### 淘汰判决

| 候选 | 判决 |
|---|---|
| 积格（区域格 × 授权格） | 区域分量不是全格（树 + 部分 merge）——总 join 制造无意义合并，丢分离精确性——**否决** |
| 纯 PCM | 授权细化（⊆ 收窄）不是 PCM 的组合导出序——**否决** |
| 剩余格（FUZZY 同构） | 分级授权不在当前表达范围（模糊加权在数据层，不在授权层）——**扩展点** |
| **PCM × 布尔格（+可复制性）** | **采用（经典行组织参数）** |

### 结构

- **区域分量 = PCM**（偏交换幺半群）：`·` 分离组合（部分、精确），序从组合导出（a ⊑ b ⟺ b = a·c）——Iris ghost state / Boyland 分数权限 / separation algebra 同构
- **授权分量 = 幂集格**（布尔格）：授权集 ⊆ 收窄 = 细化 ⊑，∩/∪ = meet/join；**可复制性区分**（Iris 1.0→1.1 RA duplicable core 教训）：只读/consult = 可复制（share），写/assume = 独占
- 总序：`(r₁,a₁) ⊑ (r₂,a₂) ⟺ r₁ ⊑ r₂ ∧ a₁ ⊆ a₂`（保序积）
- 分级扩展点：分数权限 π ∈ (0,1]（Boyland）与模糊隶属度 [0,1] 同构——未来模糊分级授权直接复用，当前 YAGNI

## 11.5 寄存器分配 = 缓存语义映射实例（v4 新增，本备忘的实测应用）

> 2026-08-27 讨论：寄存器分配的完全形式化验证问题，在缓存语义框架内得到定稿方向。这是「规则封闭对象开放 / 无格承诺 / 驱逐不变量」三原则的落地实测——分配判定以纯格对象写出（无路径结构），同时是 #10（格不重引入顺序）判据的实例化。
>
> 独立成文：`docs/maintainer/design/regalloc-cache-mapping.md`（正式参考文档）+ `docs/superpowers/specs/2026-08-27-regalloc-cache-mapping-design.md`（设计决策记录）。

### 定位

分配从「编译器 pass」重新定义为**格 → 编码的映射实例**（条款 7 家族：区域 / arena / 字节权限 / 寄存器同族）。CFG 是格的特例——线性扫描、图着色、SPL 语法分解都是**线性化退化实例**，不进入语义本体。「CFG 即将淘汰」对分配的正确含义：正确性不再对某条线性化路径陈述，而是对全部可能执行成立。

### 语义基座（律）

- **驱逐不变量 = 语义保持定理**——分配正确性与执行顺序无关（order-free）：CFG 正确性只对一个线性化成立，格正确性对所有可能执行成立
- 无格承诺：判定/定理只在关系层面陈述（§4.6）

### 对象（物）

- 条目 = IR 变量版本（条款 5 版本化）；配方 = 产生节点
- 存在区间 = 图活性（复用 RegionCheck 机制）；**共存 = 存在区间相交**（对称关系，无传递性要求）
- 无配方条目（边界 + 图内不可重算）一条通用规则：必须有 home、驱逐必写回（§5.3）——不按范式枚举

### 判定（验证，单层）

一致性四条（可判定、局部、条目泛型）：

1. 每寄存器至多一个条目的材料（共存互斥）
2. 读点无陈旧（材料版本对齐）
3. 驱逐配对：写回 home，或配方可再生（条款 3 再生等价 = rematerialization）
4. 调用点失效契约（caller-saved 失效 / callee-saved 保留）

**算法零证明**——正确性由判定保证，与分配算法选择无关；分配算法定案 = 上下文贪心（下方）。落点：`.corespec` 契约 + 编译器内 checker 实现期自检，双层消费同一规约（§2.7 验证体系）。

### 分配器（定案：上下文贪心）

共存偏序上的贪心放置：上下文 = 共存关系 + 再生成本（配方）+ region 生命周期 + 调用点。CFG 退化情形 = 区间序 First Fit = 最优（Dilworth：最小寄存器数 = 共存偏序的 width；区间序 χ = ω）。**定案（2026-08-27）：上下文贪心为唯一分配算法**；判定不依赖算法选择。

### 数学支撑（v4 文献补）

- Dilworth 定理 / 区间序：链分解 = 分配、width = 最小寄存器数、First Fit = 区间序最优（区间图 = 完美图）
- PCM/资源代数（Verus/Iris）：寄存器 = 可分离资源（每个寄存器一个位置的资源，alloc/join/split）——与 §九 代数同构，验证语言 = 格代数（可选参数，非必需）
- SPL 语法分解（Cai & Goharshady 2024–2026）：series-parallel 控制流图上带 spill 的最小代价分配多项式精确（O(|G|·|D|⁶)）——CFG 退化实例自身的精确解，反证「CFG 算法是格分配的线性化特例」
