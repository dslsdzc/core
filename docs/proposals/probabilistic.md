# Core 概率编程

> 定位:受众 = 维护者/贡献者;状态 = **proposal(讨论中)**——概率 = pass 的论点未落地,无实现痕迹

## 设计原则

- **概率不是新特性——是一个 pass。**
- `@` 不参与概率。抽样是库函数，观测是图上的约束，分支概率图自动推导。
- 不需要运行时概率系统。全部信息在编译期走完。

## 分支概率——自动推导

图上 `random() < p` 模式被 pass 认出，在分支边上标注概率权重。

```core
if random() < 0.3 {
    // true 边 → 概率 0.3
} else {
    // false 边 → 概率 0.7
}
```

pass 沿值流传播权重——任何变量的分布信息自动推导。

```core
result := if random() < 0.05 {
    "rare"      // 5%
} else {
    "common"    // 95%
};

// 图中下游使用 result 的节点知道：
// result 是 {5% "rare", 95% "common"}
```

## 抽样——库函数

`random()` 接受一个分布参数，返回样本。等价于 `read_file()`——编译器不用特殊对待，库函数。

```core
x := random(normal(0, 1));      // 标准正态分布
y := random(uniform(0, 10));    // 均匀分布
z := random(binomial(10, 0.5)); // 二项分布
```

运行时 `random(normal(0, 1))` 返回一个 double。编译期的概率 pass 看到 `random(...)` 的返回值的后续使用，但不影响运行时。

## 观测——图上的约束

观测是贝叶斯更新。在 Core 上不发生在运行时——发生在编译期的图分析。约束可以写在 `.corespec` 规约文件中，也可以直接在条件分支中表达：

```core
sensor := random(normal(true_temp, 0.1));
if sensor > 30 {
    // 编译器知道：sensor 的值 > 30
    // 同时知道 sensor 服从 normal(true_temp, 0.1)
    // 后验：P(true_temp | sensor > 30) 在图上可推导
}
```

没有 `@observe`，没有新语法。就是条件分支 + 规约。

## ProbabilityPass

```
输入：HDFG（已有分支边）

处理：
    1. 扫描 random() < p 模式 → 分支边标权重
    2. 沿值流传播权重 → 变量的分布信息
    3. 如果遇到 .corespec 中的观测约束 → 更新后验
    4. 结果的统计量（期望值、方差）附加到图节点上

输出：带概率标注的HDFG
```

消费端：

| 消费端 | 使用方式 |
|--------|---------|
| 优化器 | 概率低的路径放远，不内联 |
| 代码生成 | 冷热路径分离 |
| 验证器 | 统计性质检验 |

运行时不需要改动——概率信息是编译期的，不走 `@`，不产生运行时开销。

## 与现有机制的关系

| 概念 | 形式 | 是否新东西 |
|------|------|-----------|
| 分支概率 | `random() < p` 自动推导 | pass，不是语法 |
| 抽样 | `random(dist)` | 库函数 |
| 观测 | `if cond` + `.corespec` | 已有机制复用 |
| 后验推导 | pass 传播 | pass |

`@` 不参与概率。
