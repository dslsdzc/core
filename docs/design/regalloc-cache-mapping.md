## 零、术语对照表

| 术语 | 含义 |
|---|---|
| 条目（entry） | IR 变量**版本**（缓存语义条款 5：每次赋值 = 新版本 = 新条目） |
| 配方（recipe） | 条目值的产生方式 = (产生它的图节点, 输入边)（条款 1） |
| 驱逐（eviction） | 丢弃条目的存储物、保留配方（条款 2） |
| 再生（regeneration） | 重跑配方节点产生可观测等价的值（条款 3） |
| home | 条目的持久位置（经典映射 = 栈槽） |
| 存在区间 | 条目在图层上的存活区间 = 图活性（RegionCheck 机制） |
| 共存 | 两个条目的存在区间相交（对称关系，无传递性） |
| 寄存器映射实例 | 寄存器文件 = 缓存层、home = 经典映射的映射实例（条款 7） |

## 一、定位：分配是映射实例，不是编译器 pass

寄存器分配与区域 / arena / 字节权限同族，是**格 → 编码的映射实例**（缓存语义条款 7）：

```
图（HDFG）      —— 关系空间：值流、配方、图活性
格（存在空间）   —— 条目存在：版本、共存、驱逐（缓存语义本体）
编码（物理）     —— 映射实例：寄存器（缓存层）/ 栈槽（home）/ 字节
```

推论：

- **CFG 是格的特例**。线性扫描、图着色、SSA 弦图、SPL 语法分解都是**线性化退化实例**——不进入语义本体
- **正确性 order-free**：不对某条线性化路径陈述，而对**全部可能执行**成立（§二）
- 范式映射表（`z-vision.md`）= 映射正确性定理表——寄存器映射实例是其中一行（经典行），与字节内存行同构：证明缓存语义 ⊇ 该实现

## 二、语义基座（律）：驱逐不变量 = 语义保持定理

公理 = 缓存语义七条（`memory-model.md` §一）。其中：

- **驱逐不变量（条款 2）**：⟦G ∖ storage(e)⟧ = ⟦G⟧——驱逐图内任意条目（丢弃存储物、保留配方）不改变可观测语义
- 分配器把条目放寄存器还是栈、放多久，只是**放置/替换策略**——与缓存替换策略（LRU 等）同理，**算法零证明**。语义保持不依赖具体贪心
- **无格承诺**（`memory-model-capability-lattice.md` v4 §4.6）：判定/定理只在**关系层面**陈述——共存关系连预序公理都不需要（共存无传递性，是对称关系）；对一切格成立

## 三、对象（物）

| 对象 | 定义 | 来源 |
|---|---|---|
| 条目 | IR 变量版本（每次赋值 = 新版本） | 条款 5 版本化 |
| 配方 | 产生节点 + 输入边 | 条款 1 |
| 存在区间 | 图活性存活区间 | 图层导出（RegionCheck 机制，`pointer-model.md`） |
| 共存 | 存在区间相交 | 对称关系（无传递性、无路径结构） |
| home | 栈槽（经典映射） | 映射实例 |

**无配方条目**（边界 + 图内不可重算，见 `memory-model-capability-lattice.md` v4 §5.3）一条通用规则：**必须有 home，驱逐必写回**——驱逐不变量/再生等价对其不成立（重跑神谕 ≠ 原结果）。对所有无配方条目一视同仁，不按范式枚举。

## 四、判定（验证）：一致性四条

「寄存器映射实例合法」= 一致性判定，全部**可判定、局部、条目泛型**（只操作「位置 + 配方 + 存在」，不读值的内容）：

1. **共存互斥**：每时刻每寄存器至多一个条目的材料（共存 = 存在区间相交 → 同寄存器条目不共存）
2. **读点无陈旧**：读到的材料与条目的当前版本对齐（条款 5）
3. **驱逐配对**：寄存器回收（驱逐）时材料不丢——写回 home，或配方可再生（条款 3 = rematerialization）；无配方条目必写回（§三）
4. **调用点失效契约**：调用点 = 缓存失效边界——caller-saved 失效（材料归 home）、callee-saved 保留（ABI = 缓存保留契约）

**算法零证明**：正确性由判定保证，与分配算法选择无关（生成器 + 验证器分离；2025 年 VeriLocc 同构先例）。分配算法 = 上下文贪心（§五，定案）。

**落点**：判定写成规约契约（`.cr` 内联，`spec-design.md` §2.7 体系：翻译桥 → CIC 内核，健全性由内核保证；独立 `.corespec` 格式已退役，见 ADR-0001）+ 编译器内 checker 实现期自检，双层消费同一规约。

## 五、分配器（定案）：上下文贪心（Context-Aware Greedy, CAG）

**正式名：上下文贪心**——存在结构上的 First Fit 贪心扫描。上下文 = 共存关系 + 再生成本（配方）+ region 生命周期 + 调用点 + 使用次数。**定案（2026-08-27）：上下文贪心为唯一分配算法**；判定（§四）不依赖算法选择。

算法规格：

```
对每个函数：
1. 条目表构建：变量 × 版本（IR_STORE 切分，条款 5）→ 存在区间 [start, end]
   （图活性；region 嵌套序上结构化计算，非 CFG 数据流不动点）
2. 遍历序：region 嵌套序（存在结构拓扑序）——CFG 退化时 = 指令序 = 经典线性扫描
3. 活跃集合：当前点存在区间覆盖的条目 = 共存集合
4. 分配：对每个新活跃条目 e：
     free = 寄存器全集 \ 活跃集合已占
     free 非空 → e 取最小空闲寄存器（First Fit）
     无 free → 驱逐决策：对候选驱逐者 e′ 比较
       cost = region 深度 × 使用次数 ×（写回 + 装载）vs 配方重算代价（remat）
       选便宜的：材料写回 home（spill）或直接重算（remat）；e 占释放的寄存器
5. 调用点：活跃的 caller-saved 条目 → 驱逐写回 home（缓存失效契约）；callee-saved 保留
6. 输出：条目 → 位置（寄存器/home）映射 + 驱逐/装载点表 → g_opt_meta / 格形态
```

谱系：主干 = Poletto-Sarkar 线性扫描的**存在结构版本**；spill = 成本感知驱逐（second-chance bin-packing 变体 + remat 选项）；调用点失效 = 解锁 caller-saved（x86-64 通用寄存器 16 个 + XMM；现实现仅用 5 个 callee-saved）。复杂度 ~O(V+E)（活跃集合维护 O(条目 × 寄存器数)）——分配器本身不拖编译速度。

- 版本区间（IR_STORE 切分）——对应条款 5 版本化，比 first/last 全函数区间精确
- spill = 驱逐写回 home；remat = 配方重算（成本 = 产生节点重算代价）
- **CFG 退化情形 = 区间序 First Fit = 最优**（Dilworth：最小寄存器数 = 共存偏序的 width；区间图 = 完美图，χ = ω）——数学闭合
- 非区间序（有分支）时 = 贪心近似（最优性本质 NP-hard），质量靠上下文信息拉高，验证不依赖它

## 六、数学支撑

| 结果 | 内容 | 位置 |
|---|---|---|
| Dilworth 定理 / 区间序 | 链分解 = 分配；width = 最小寄存器数；区间序 First Fit 贪心 = 最优 | §五（CFG 退化情形的精确性） |
| PCM / 资源代数（Verus/Iris） | 寄存器 = 可分离资源（每寄存器一位置的 `Resource<P>`，alloc/join/split）——验证语言与能力+格备忘 §九 代数同构 | 验证的可选代数层（非必需，§四 判定已足够） |
| SPL 语法分解（Cai & Goharshady 2024–2026） | series-parallel 控制流图上带 spill 的最小代价分配多项式精确（O(\|G\|·\|D\|⁶)） | 退化实例自身的最优解参考——证实「CFG 系算法是格分配的线性化特例」；其 DP 表可作最优性证书的形态参考 |
