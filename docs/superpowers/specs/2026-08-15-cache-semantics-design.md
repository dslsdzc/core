# 缓存语义设计（Cache Semantics：语义本体定稿）

日期：2026-08-15
状态：已批准（brainstorming 会话，四节逐节确认）

## 1. 背景与动机

### 1.1 现状

- `z-vision` 目标一（语义保鲜）：HDFG 保留全部语义信息，与执行硬件解耦；范式迁移时"语义不动，只换后端映射"。其中**范式映射表未做**（设计上每范式一张表）。
- 存储侧现状：`docs/memory-model.md` 的语义本体 = CompCert v2 字节模型（块 + (块 ID, 字节偏移) + 每字节权限）。**字节寻址本身是经典范式概念**——存储语义仍然绑死经典硬件。
- 执行侧已范式无关（HDFG + `region`/`state edge`/`provenance` 已实现），存储侧没有跟上：这正是"范式映射表"的**存储半边**缺口。

### 1.2 关键观察

**实现早已是缓存语义**：HDFG 节点 = 配方（值的产生方式），边 = 值流，`state edges` = 顺序约束，驱逐/再生 = 丢令牌/重跑节点。IR（`.cir`/`.ccr`）从来不是字节内存——它是数据流。

落后的不是实现，是**文档层**：`memory-model.md` 在描述一个实现里不存在的本体（字节内存为语义根基）。本次工作是语义层面的文档纠偏，与"文档大量过时、实现以源码为准"属于同一类问题，只是问题出在语义层。

### 1.3 目标

把存储语义本体正式定稿为**缓存语义**（范式无关），字节内存降级为"缓存语义在经典硬件上的映射实例"。

- 语法表面一行不改：语义本体正式定为缓存/数据流语义
- 零代码改动：图本身就是缓存语义，无任何实现变更
- 范式无关性可证明化：范式映射表在形式上是"映射实例正确性定理表"

## 2. 核心模型：语义本体（七条条款）

以下条款是 `memory-model.md` 上部的正文，写成可形式化的陈述，将来供验证器（翻译桥/CIC 内核）消费：

1. **值 = 配方**。条目的语义 = (产生它的图节点, 输入边)。不存在独立于配方的"存储事实"。

2. **驱逐不变量**。驱逐图内任意条目（丢弃存储物、保留配方）不改变可观测语义——只影响性能，不影响正确性。形式化目标：⟦G ∖ storage(e)⟧ = ⟦G⟧。这是"缓存语义"的定义性质。

3. **再生等价**。重跑配方节点产生的值与原条目可观测等价。这是条款 2 的机制保证，也是"任何范式都能换映射"的语义依据。

4. **边界公理**。图边界输入（MMIO/FFI/输入/测量）是唯一无配方条目，语义上是符号常量。语法层叫 `unsafe`（边界标注），语义层只叫"边界"。边界之外才需要 state，边界之内全是可重算的。

5. **赋值 = 版本化**。`x = x + 1` 在语义上 = "x₁ 创建、x₀ 失效、绑定移动"，不是修改内存单元。顺序约束由 `state edges` 表达。"可变"不是内存单元的属性，是绑定可移动的许可。

6. **地址 = 映射**。`&x` = (条目标识, 偏移)，字节地址只是经典投影，不是语义对象。指针算术合法性由条目标识 + 偏移域验证（现有 `provenance` 三 pass 保留不动）。

7. **映射实例正确性**。区域/arena/字节权限（CompCert v2）是经典映射实例，其正确性标准 = 保持条款 1–6 的可观测语义。

**推论（范式映射表 = 映射正确性定理表）**：经典行 = 证明缓存语义 ⊇ 字节内存实现（CompCert 式语义保鲜）；量子行 = 将来证明缓存语义 ⊇ 量子存储实现。语义保鲜从"编译正确性定理"升级为"映射正确性定理"。

## 3. 经典映射（降级清单）

- 区域（Region）、Arena、字节权限（CompCert v2）不再是语义本体，而是"缓存语义在经典硬件上的映射实例"
- 其设计内容（图锚定区域、无碎片 bump、size class、每字节权限）全部保留，身份从"模型"变为"一个映射的实现"

## 5. 术语对照表

"内存"的三层含义（放 `memory-model.md` 开头，防术语歧义）：

| 术语 | 含义 | 例子 |
|------|------|------|
| 物理内存 | 硬件 | DRAM、寄存器、量子存储 |
| 语义存储 | 缓存（范式无关本体） | 条目、配方、驱逐、再生 |
| 映射 | 实现 | 字节寻址、区域、arena |
