# HIT M2：运行时核事件集和全表驱动

## 概述

HIT M1 只覆盖直线数据计算，事件集是 sub、nand、load、store 四个纯数据事件，没有控制转移能力。

M2 把事件集扩展为运行时核九事件，补齐控制流、调用和系统边界，并推进单指令编码的表驱动化。

设计状态：设计定稿。批次 M2a 到 M2d 因后续架构调整暂停。表数据已迁到架构轴，检查按边界设计修订为行为等价和投影正确性，不再要求逐字节复刻旧发射器。原始方案、拍板记录和风险清单见 `docs/superpowers/implementation/2026-09-07-hit-m2-audit.md`。

## 事件模型

运行时核九个事件：

| id | 事件 | 语义 | x86 投影 |
|---|---|---|---|
| 1 | sub | 减法 | M1 模板 |
| 2 | nand | 与非 | M1 模板 |
| 3 | load | 读取 | M1 模板 |
| 4 | store | 写入 | M1 模板 |
| 5 | jump | 无条件转移，目标为事件流位置 | rel32 跳转 |
| 6 | branch | 条件转移，条件为槽值非零，真假双目标 | 比较加条件跳转 |
| 7 | call | 函数调用，目标为函数索引 | call rel32 |
| 8 | ret | 函数返回 | ret |
| 9 | extern | 外部符号调用 | call 外部符号 |

数据计算可移植子集仍然只需要前四个事件。完整程序需要九个事件，每张表都必须包含运行时核。

扩展直通事件，例如 add、and、or、xor、mul、div、cmp 和 shift，可以从 id 10 开始。表声明了就直通，没有声明就用四个核事件合成。

`branch` 天然是双目标，IR 的 `s1` 是条件，`s2` 是真目标，`s3` 是假目标。模板支持双 rel32。

## 表格式 v2

模板步骤从 M1 的五个字段扩展为完整形态描述：

```text
step = {
  prefix: [u8...]
  rex: {w, r, x, b}
  opcode: [u8 1..3]
  modrm: {reg_role, rm_role, rm_mode}
  disp: {size, src}
  imm: {size, src}
  rel: {role, kind}
  cond: {role}
  seq: [step...]
}
```

回填角色有三类：

- 事件流内部目标：jump、branch 和 call 的函数体。
- 函数起点。
- 外部符号。

操作数角色解析为槽或事件流位置，复用 M1 的槽和常量池机制。

一个事件可以有多个投影形态，例如 load 的不同寻址模式。发射时按操作数形状选择。

## 降低层

降低策略是直通优先，合成后备。

数据操作：

- 表里有直通事件时直接发射。
- 没有直通事件时用四个核事件合成。例如 add 使用反减，nand 使用 and 加 not，or 使用德摩根，xor 使用组合，cmp 使用 sub 加符号判别，const 使用常量池加载。
- 常量的负值和宽值需要扩展常量池记录，8 字节槽装不下时使用借位链。

控制流：

- `IR_LABEL`、`IR_JUMP` 和 `IR_BRANCH` 转为 jump 和 branch 事件。
- 标签到事件流位置使用两遍法：第一遍记录位置，第二遍回填 rel32。
- 循环和条件分支已经在 IR 层展开为标签序，区域结构不进入事件流。

调用：

- `IR_CALL` 转为 call 事件，callee 是函数索引。
- `IR_RETURN` 转为 ret 事件，并处理返回值槽约定。
- `IR_CALL_EXTERN` 转为 extern 事件。

多字值：

- 2L 快路径走表直通或合成。
- 溢出慢路径保留为序列算法代码，块内单指令查表，块序保留。

并发：

- `IR_SPAWN` 等操作属于编译器自用面。
- 降低层接现有运行时函数，用 extern 或 call 事件表达。
- 没有事件且不能合成的操作保留旧路径，到 M2d 前列出清单并逐项清理。

## 发射数据化

数据化范围是单指令编码形态。序列算法保留代码。

单指令编码包括前缀、REX、opcode、ModRM、disp、imm 和 rel，改为表数据。`instr.cr` 按形态族逐块迁移，每块独立提交和检查。

保留为解释器算法的序列：

- prologue 和 epilogue。
- 参数拷贝。
- 2L 慢路径块。
- 函数帧布局。
- 分配和判定，属于格形态层。

结束状态：`emit_instr` 的硬编码分发改为表查询加模板解释器。旧路径和表路径汇合为同一条，表是唯一发射出处，混合模式消失。

## 运行时条目

运行时条目数据进入表并校验：

```text
runtime = {
  call: {机制, 返回地址位置, 栈生长方向}
  param: {传递方式}
  save: {callee-saved 集合}
  extern: {入口约定, 符号解析}
}
```

解释器读取运行时条目生成 call 和 ret 序列。参数拷贝和栈帧是代码算法，按条目参数化。x86 当前是一档实例。

表校验：运行时核九个事件必须齐全，rel kind 必须和模板一致。

## 测试

1. 模板对照：每个新形态或新事件都用同源程序对照。后续按边界设计改为行为等价和投影正确性，不再要求逐字节相同。
2. suite 覆盖：控制流、循环、函数调用、递归、打印、内存和位运算。表模式运行结果通过。
3. 组合验证：HIT 和 2L、表模式与链接和静态模式、表模式下的寄存器分配。
4. 自举：M2b 结束时混合表模式能编译自己；M2d 结束时纯表模式能编译自己。

表模式当前固定在 O0。优化属于格形态层，与表正交。表模式 O2 恢复挂在 M3。

## 阶段

| 阶段 | 内容 |
|---|---|
| M2a | 事件集和模板语言 v2，控制流、调用和外部符号模板，模板解释器新形态，逐模板对照 |
| M2b | 降低层全操作覆盖：标签映射、调用降低、合成规则、suite 和自举快速验证 |
| M2c | 发射结束：`instr.cr` 逐块数据化，旧路径和表路径汇合 |
| M2d | 运行时条目数据化，call、ret 和 extern 序列参数化，纯表自举终验 |

## 风险

- 自举工程量大。表模式必须覆盖编译器自用的全语言面。处置是按 IR 操作全集做降低覆盖，先用混合态验证。
- 模板表达力边界。schema v2 可能覆盖不了个别编码形态。处置是先盘点形态族，迁移中发现新形态时扩展字段并先写对照测试。
- call 和 ret 与 2L 慢路径、帧布局交互复杂。当前保持与旧路径相同的语义边界，不扩展 2L 调用协议。
- 事件流和回填规模可能影响性能和体积。对照测试先行，必要时优化降低器。
- `instr.cr` 逐块迁移有回归风险。每块独立提交，跑全套回归。
