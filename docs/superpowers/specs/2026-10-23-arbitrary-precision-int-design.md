# 任意精度整数设计

## 概述

`int` 是数学整数，没有固定宽度。前端只处理数学整数和运算，不决定立即数、装箱或机器字范围。`.ccr` 保存完整值和必要的编码信息。后端决定值在目标机器上的表示，并在指针、FFI 和原始字边界做转换。源语言不新增用户可见的整数类型。

## 语义

### 值与字面量

- `int` 的取值范围是全体有符号数学整数。
- 零只有一种表示，不出现负零。
- 十进制、十六进制、八进制和二进制字面量都表示精确值。
- 字面量没有 64 位上限。
- 负号是语法层的一元运算，`-9223372036854775808` 合法。
- 数字分隔符保持现有规则。

### 算术

| 运算 | 语义 |
|---|---|
| `+`、`-`、`*` | 精确整数运算，不溢出 |
| `/` | 向零截断 |
| `%` | 余数符号与被除数相同，满足 `a == (a / b) * b + a % b` |
| `==`、`!=`、`<`、`>`、`<=`、`>=` | 精确比较 |
| 一元 `-` | 精确取负 |
| 除以零 | 运行期错误 |

### 转换

- `int` 转 `dex` 按当前 `IR_I2F` 的规则转换。
- `dex` 转 `int` 按当前 `IR_F2I` 的规则向零截断。
- `char` 与 `int` 的转换保持当前范围规则。
- `int_str` 和 `str_int` 支持任意精度。`str_int` 遇到非数字字符时按当前规则停止。

### 机器字边界

以下位置要求值能放进 64 位机器字：

- `@ptr_of`、`@str_of`
- `@raw_int` 的地址来源
- `w64`、`r64`
- `syscall3`、`syscall4` 的参数
- `extern` 的 C ABI 参数和返回值
- 指针加减的偏移
- 数组长度、索引、切片边界和分配大小

值超出机器字范围时报运行期错误。不能静默截断，也不能把大整数对象的指针当作机器字交给外部代码。

`@ptr_of(string)` 返回地址的数学整数。当前 x86-64 用户地址小于 2^62，因此通常落在后端的立即数范围。`@str_of` 接受数学整数地址，值必须落在可表示的用户地址范围。

### 数组和结构体

- `int` 数组元素仍占一个 8 字节槽，槽里是后端决定的整数值表示。
- 结构体字段、元组元素和枚举 payload 中的 `int` 同样占一个槽。
- 数组长度和索引在进入分配或寻址前转换成机器字，并做范围检查。
- 大整数不能作为数组长度或索引。编译期常量越界直接报错，运行期值越界报运行期错误。

## 前端与 .ccr 的分工

前端只负责保留精确值，不负责决定机器表示。

- 小整数继续使用 `EXPR_INT` 的 64 位字段。
- 超出有符号 64 位的字面量使用 `EXPR_BIGINT`，保存规范十进制字符串。
- 小整数继续使用 `IR_CONST`，`s1` 是有符号 64 位值。
- 超出有符号 64 位的整数使用 `IR_CONST_BIG`，`s1` 是规范十进制字符串的 intern 下标。
- 前端可以在 64 位处选择存储形式，这个选择只影响载体编码。它不改变值，不产生溢出诊断，也不决定后端的立即数阈值。
- `.ccr` 的 NOD 记录大小不变。`IR_CONST_BIG` 复用 STR 段，不新增段。
- `.ccr` 版本为 v9.1。版本字段编码为 `(9 << 16) | 1`，即 `0x00090001`。loader 只接受 major 9、minor 1；旧 v9 的整数值 9 被拒绝。
- `.cir` 快照保存 `IR_CONST_BIG` 的 opcode 和字符串下标，`CIR_CACHE_VER` 从 22 提升到 23。

`dex` 的 binary64 位模式不是数学整数，继续使用 `IR_CONST` 的 64 位载荷。编译器内部的浮点字面量转换通过原始字边界处理，不使用 `int` 的数学值。

## 后端表示

后端用 8 字节 tagged value 表示 `int`：

| 最低位 | 含义 |
|---|---|
| 0 | 立即数，存的是数学值的两倍 |
| 1 | 指向 BigInt 对象的指针加一，对象地址 8 字节对齐 |

立即数范围是 `[-2^62, 2^62-1]`。零是立即数 0。超出范围的值装箱。这个编码只存在于后端，不出现在前端或 `.ccr`。

使用最低位而不是最高位，是为了让 Core 运行时不需要 64 位掩码或 2^63 常量。立即数装箱是乘 2，拆箱是除 2；BigInt 指针装箱是加 1，拆箱是减 1。对象地址由 `alloc` 保证 8 字节对齐。

BigInt 对象布局：

```text
offset 0:  sign   int   -1, 0, 1
offset 8:  len    int   digit count
offset 16: digits int[len]   每个元素保存 0..2^30-1
```

- 采用 30 位 digit 的小端序表示。两个 30 位 digit 的乘积小于 2^60，加上进位后仍小于 2^62，因此运行时自身的 limb 运算保持在 Core 的立即数范围内。
- 吸收 GMP 的规范化表示、schoolbook 乘加、Knuth 除法和小整数快路径；不链接 GMP，也不复制 GMP 源码。
- 零的 `sign = 0`、`len = 0`。
- 非零对象去掉高位零 digit。
- 对象不可变，运算分配新对象。
- 大整数对象从当前 arena 分配，arena 重置时统一回收。

后端 lowering 为每个 IR 值标记表示：立即数、装箱或未知。常量、循环计数和已证明范围的值保持立即数。整数运算先尝试立即数快路径，可能越界时调用 BigInt 运行时。比较在两侧都是立即数时直接比较，否则调用运行时。

同一个 `.ccr` 可以被不同后端用不同的立即数阈值执行。前端不参与这个判断。

## 运行时契约

BigInt 运行时用 Core 写成 `src/runtime/bigint.cr`。实现参考 imath 的整数算法结构和 GMP 的若干优化技术，不链接 C 源码，也不引入 libc 或 C 编译器依赖。运行时使用 30 位 digit，limb 中间值保持在立即数范围内，避免在 limb 运算中递归进入 BigInt 路径。

运行时提供：

```text
bi_from_word
bi_from_uword
bi_from_dec
bi_to_dec
bi_add
bi_sub
bi_mul
bi_div
bi_mod
bi_cmp
bi_neg
bi_is_zero
bi_to_word_checked
bi_to_uword_checked
```

- 除 `bi_from_word`、`bi_from_uword`、`bi_to_word_checked` 和 `bi_to_uword_checked` 外，输入和输出都是 tagged value。
- `bi_from_word` 接收原始有符号 64 位机器字，返回 tagged value。
- `bi_from_uword` 接收原始无符号 64 位机器字，返回 tagged value。
- `bi_to_word_checked` 接收 tagged value，返回原始有符号 64 位机器字。
- `bi_to_uword_checked` 接收 tagged value，返回原始无符号 64 位机器字。
- `bi_div` 和 `bi_mod` 使用向零截断，余数符号跟随被除数。
- 除数为零时进入统一的运行期错误入口。
- `bi_to_word_checked` 检查有符号 64 位范围；地址场景使用单独的无符号范围检查。
- 分配失败走现有 OOM 路径，不返回半初始化对象。

## 指针、FFI 和解释器

### 指针

- `IR_ADDR_INDEX`、`IR_SLICE` 和指针加减先把 `int` 转成机器字。
- 越界、负地址和超出用户地址范围都报运行期错误。
- 现有 8 字节槽布局不变。指针写入的仍是原始机器字，不写 tagged value。

### C ABI

- `extern` 的 `int` 参数和返回值在调用边界转换。
- 参数超出有符号 64 位时，调用前报运行期错误。
- C 返回的机器字转换成 `int`；在立即数范围内保持立即数，否则装箱。
- `dex`、`string`、`bool` 的现有 ABI 不变。

### 解释器

- `g_ir_vals` 的 `int` 槽保存 tagged value。
- 解释器自己的 `int` 运算使用语言语义，因此自动得到任意精度。
- `IR_CONST_BIG` 从字符串或静态对象装入。
- 指针、`w64`、`r64`、`@str_of` 等边界使用与 ELF 后端相同的检查和错误文本。

## 约束

1. 不新增用户可见的 `word`、`usize` 或 `i64` 类型。
2. 不改变 `dex` 的 binary64 语义。
3. 不实现大整数到 C ABI 的自动多字传递。超出 64 位直接报错。
4. 不保证大整数运算与立即数运算有相同性能。
5. 不改变 arena 的生命周期模型。
6. 自举链的 stage0 由 Python 后端生成。Python 前端使用 Python 整数；Python 后端和运行时必须使用与 corec 相同的 tagged value 和对象布局，否则 stage0 与 self-hosted 输出不一致。
7. 旧 2-limb `tag2l` 机制只覆盖局部加减，已在新实现完成后移除；raw 编译器/回退路径只使用 64 位裸值。

## 未决

1. `and`/`or` 作用于 `int` 时是否保留位运算语义。当前没有用户级移位运算符，实现前需要审计现有语法和测试。
2. 大整数常量在 `.ccr` 中使用规范十进制字符串还是 limb 记录。本文选择十进制字符串，优先保证前端简单和可审计。
3. 大整数打印是否在 `int_str` 中直接使用 `bi_to_dec`，还是先在 Core 层用除法实现。前者快，后者更容易自举。
