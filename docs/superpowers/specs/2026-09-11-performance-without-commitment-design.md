## 0. 范围与裁决

### 0.0 论题：Performance without implementation commitment

现状（各语言的通病）：为了性能，程序员不断把机器知识写回源码——SIMD intrinsic、CUDA / NPU 各一套方言、硬件换代重写内核。Core 的立场：

> 程序意义里不含机器形状（承既有定案：宽度移出语言 / 地址 = 映射 / 表示层归处 = 映射参数）。因此**性能决策 = 映射实例的选择，不是程序的一部分**。

关键同构（本 spec 的论题展开）：单 CPU 上的 SIMD / cache / NUMA / inlining / layout / parallelization 与异构 placement（GPU / NPU / 加速器）是**同一个问题**——在「图 + 目标描述」上选择事件组合与资源绑定。差别只在目标描述的表内容（HIT 运行条目 / hw-map 设备表）：**机制同一，无第二条性能路线**。禁止为 SIMD / CUDA / NPU 各开特判通道（与 §1.2.2「禁止内建特判」同构）。

### 0.1 本 spec 的决策面

- 决策对象：格 → 编码映射的选择/放置/调度（内联、放置、并行分派、事件选择、布局）。
- 不修改：值流、state edges、region 语义（图本体）——承「执行/副作用/内存的命令式下限不动」（契约 §1.2.5）；先例 = 寄存器分配 = 缓存语义映射实例（已定稿）。
- 判据基调：合法性可判定、收益启发式；**任何变换的缺失都可接受**（直接形态恒合法）。

### 0.2 裁决（设计已定 D1-D7）

| # | 裁决 | 依据 |
|---|---|---|
| D1 | **机器形状不进程序意义**：源码/图零机器名词（无宽度、无寄存器、无 SIMD 宽度、无设备名）；性能变化不构成语义变化 | width-out-of-language / 地址 = 映射 / 定长裁决「表示层归处 = 映射参数」 |
| D2 | **优化 = 映射选择，非图修改**：决策作用于「格 → 编码」；图本体不动 | 契约 §1.2.5；regalloc-cache-mapping 先例 |
| D3 | **合法性可判定、收益启发式**（分离原则）：变换分两层——合法性前提（图可判定，unknown = 不选）/ 收益估计（成本模型，可错）；启发式失效的唯一后果 = 回落语义直接形态 | 本 spec §2.2 |
| D4 | **优化不得削弱义务**：不得移除/绕过 enforcement；检查消除只允许走义务判定（prove 档），不由成本模型决定；MMIO/volatile 不消除/不重排/不合并 | 与 S-A 的边界；hw-map §2 既有条款 |
| D5 | **成本模型 = 数据 + 可替换组件**：成本事实随表走；成本模型（加权/阈值/搜索）是编译器侧可替换件——不进图语义，也不进表的「放置策略」面 | HIT §3.3「优化不走表」 |
| D6 | **标注 = 开放标注/事实来源，不是新 primitive**：不新建属性轴、不新增语言关键字；显式面仅允许「可选性能提示」（可被任何目标忽略 → 退化合法） | 契约 §1.2.1 |
| D7 | **决策与缺席都要有理由**（§5）——「不静默」原则在本线的形态（弱承诺：可解释，非拒绝编译） | 与 S-D 的接口 |

**待论证清单**（不假装已定）：成本模型的精度/量纲/校准方法论；启发式阈值（调度开销 vs 收益）；局部性显式提示是否需要语法载体（R3）；PGO 数据的信任形态；决策记录规模与裁剪。逐条见 §8。

## 1. 标注面

**总原则**：

1. **自动推导优先**——能从图结构/显式边推导的一律不要求用户写（依赖、纯度/效应、使用计数、索引来源）。
2. **显式仅在意图不可推导处**——精度（apx）/ 资源约束（意图）类；显式面恒为**可选提示或策略数据**：缺失不改变合法性，被忽略只改变性能（= 无承诺的机制保证）。

| 面 | 内容 | 来源 | 形态 | 现状锚点 |
|---|---|---|---|---|
| **依赖** dependency | 数据依赖 + 顺序/副作用序（并行合法性的全部输入） | **自动**（图结构） | 值边 + state edges | 已显式（region 化控制流落地）——自动并行的可判定性地基（TODO auto-parallel 条的机制根据） |
| **纯度/效应** purity-effect | 节点/region 的效应集（无效应 = 纯） | **自动**（`effect` 轴 + 显式效应边） | 推导事实 | S-A §1.1 的 `effect` 轴**只引不扩**；state edges 已存在 |
| **局部性** locality | 访问模式 / 复用距离 / 步长 / 嵌套深度 | **自动优先**（图 + 索引来源链） | 推导事实 | 「边界判定图 pass」的 idx/slice 来源链是其数据源；**显式提示 = 待论证**（R3 表示提示通道，判据 = 可忽略性） |
| **精度需求** precision | apx（精度降级）/ dex 精度意图 | **显式（唯一）** | 既有语言标签 | TODO 定案「明确不自动 apx」——编译器猜不了意图 |
| **资源约束** resource | 内存上界 / 并行度上界 / deadline 类 | **显式（策略数据）** 或目标默认 | policy 数据（契约 §1.1：数据而非语法） | S-D 负责「上界可预测」；本 spec 消费为上界约束（只做满足检查，不重做证明） |

注：

- 局部性/表示类显式提示（如内联容量存储）承 R1 裁决「对非经典范式可退化」——**提示必须是可忽略的**（D6 的落地形态）；是否建语法载体 = 待论证。
- 精度轴**只读不写**：优化器不得替用户降精度（不自动 apx）；apx 一旦显式给出，本线可消费它做映射选择（如选宽事件/近似事件）——这是「标注 → 映射」的正向消费，反向不许。
- 事实推导的输出面 = 事实集合（效应集 / 使用计数 / 依赖闭包 / 索引来源 / 生命周期），供 §2 候选门消费。

## 2. 优化器与决策

### 2.1 流程（六段）

```
① 事实推导（图 pass）      依赖闭包 / 效应集 / 使用计数 / 索引来源 / 生命周期
② 候选生成（可判定性门）    每条变换附合法性前提清单；前提不可判 → 候选缺席（保守）
③ 成本评分（成本模型接口 ← 表成本事实 + 资源约束）
④ 选择（策略数据：目标描述 + 阈值/约束）
⑤ 记录（决策记录 → §5）
⑥ 发射（实例层：编码 / 布局 / 调度）
```

各段失效语义（全部**有向退化**，无静默改义）：① unknown → 按最保守事实（有依赖 / 有效应 / 索引未知）；② 前提不成立或不可判 → 不选该变换；③ 成本缺失/未知 → 退化用默认形态；④ 无候选或超约束 → 直接形态；⑤⑥ 与语义无关（记录缺失不影响判定）。

### 2.2 可判定性与启发式的分界（本 spec 的承重墙）

| 层 | 判据 | 性质 | 失效后果 |
|---|---|---|---|
| **合法性** soundness | 图前提：无依赖路径（并行）/ 无效应（memo）/ 索引仿射可证（向量化）/ 无递归 + 无逃逸（内联）/ 单消费点（惰性下沉） | **可判定**（保守：unknown = 否） | 该变换不选——语义不变 |
| **收益** profitability | 成本估计 + 阈值（调度开销 vs 收益；代码膨胀 vs 调用开销） | **启发式**（可错，待论证） | 只影响性能，绝不影响语义 |

- 承重属性（已定 D3）：**任何变换的缺失都可接受**——直接形态恒合法。这与安全线的「义务不静默消失」正交：那是义务，这是可选性。
- 要求：候选门的判定输出必须**引用图事实**（哪条边 / 哪个效应 / 哪个索引来源）——为 §5 记录与 S-D 解释提供证据面。

### 2.3 成本模型接口（接 hw-map）

**设计已定 = 接口形态；待论证 = 精度与量纲。**

- 输入 ①（**表成本事实**）：事件条目 + 运行时条目（调用/存储/系统边界/宽度形状——HIT §3.3）+ hw-map 设备层事实。事实随表走 → 换表换输入。
- 输入 ②（**形状上下文**）：宽度 / 布局 / 嵌套 / 访问模式（来自 §1 事实）。
- 输入 ③（**约束**）：资源约束（§1）——约束由 S-D 判定/证明为上界；本模型只做**满足检查**。
- 输出：相对成本估计 + 约束满足判定；**不输出**任何语义事实。

契约四条：

1. 事实/模型分离：成本事实 = 表条目字段（材料属性）；「如何用事实决策」= 编译器侧可替换件（HIT §3.3「表只描述材料，不描述放置策略」保持）。
2. 缺失 = 保守退化，**不猜**。
3. 相对量纲，不承诺绝对值、不承诺最优（§7）。
4. 模型可替换：多目标/多范式各一套实例，机制不换。

### 2.4 与义务/安全性的交互（硬条款，承 D4）

- 变换不得消除 enforcement（运行时检查/强制通道），除非按四档义务判定升格为 prove 档（消除流程 = 义务判定通道，非成本模型）。
- volatile / MMIO：不消除、不重排、不合并（hw-map §2 既有条款在本线重申为约束）。
- 效应序：state edges 是顺序唯一来源；重排/并行只在无依赖证明下允许——这正是自动并发「非依赖猜测」的机制根据（TODO auto-parallel 条：区别于四十年失败史的根源）。

## 3. 目标描述

### 3.1 形态（数据，非代码）

编译器持有通用机制 + 实例参数（x86 实例 spec §0 同构原则）：

```
目标描述 = 三轴组合（架构 × 格式 × OS）
         + 表：语义表（事件签名）+ 投影条目（经典编码 / 通道映射 / 连续类演化描述…）
              + 运行时条目（call/ret 机制、地址语义、系统边界、宽度/形状）
         + 设备/投影表（hw-map：device id → 物理基址）
         + 架构特化参数（machine / reloc 等——波 2 机制）
         + 成本事实（§2.3 输入①）
```

- **表是唯一允许出现机器名词的地方**（D1 的载体）；图的语义完整性不依赖任何表（换表可重建语义）。
- 表的三种范式形态（编码 / 接通 / 演化）与「无实现：条目缺失 → 编译期拒绝或 unsafe 外部入口」承 HIT §3.2，不重定义。

### 3.2 判据：换目标不改语义（可迁移判据）

1. **观测等价**：同程序 + 不同目标描述 → 值 / 效应序 / rc / 输出一致（判据形式：双目标运行比对，精确 rc；外部效应按登记比对）。
2. **源码零改动**：换目标不得要求改源码——**这是「无实现承诺」的操作性判据**（要改源码 = 机器形状漏进程序意义，违反 D1）。
3. **义务判定不变**：换目标后 S-A 的义务档位/判定结果不变（安全不因目标而弱化）。
4. **决策自由**：映射选择（内联 / 向量化 / 并行 / 布局 / placement）可完全不同——判据**只约束语义，不约束决策**。
5. **可移植子集**：只用最小核事件的程序 = 任意表可跑（HIT §4 既有条款，本 spec 承接为可移植判据的基线）。

反向（泄漏检测，用 lattice-encoding-boundary G3「可换性」判据）：a) 换目标需改源码；b) 决策结果被写回图/源码语义；c) 源/图中出现机器名词——三项任一 = 违反，登记为「泄漏待归一」。

## 6. 最小可实施切片 + 判据

**切片设计（一条标注 → 一个决策）**：

- **事实**：纯度（效应集）——已有显式边（state edges + `effect` 轴），零新语法、零用户可见变化。
- **决策**：**自动记忆化 safe 子集**（纯节点/region + ≥2 次使用 + 无分配/无 arena 交互 + 单线程）。
- 选择理由：闭环最小（合法性前提最少：无效应边 + 使用计数）；与自动惰性共用基础设施（TODO 原文的机制重叠）；**不接线成本模型**——收益规则用平凡保守启发式（「≥2 次使用」），把成本模型留成可替换桩。即：切片先跑通「**合法性可判定**」，把「**收益启发式**」留白（与 §2.2 分界一致）。
- **切片前置**（不属切片、但计划须显式列出）：判定 pass 的时点必须在数据流分析（使用计数）产出之后——TODO 已登记 use_count 时序缺陷（ir_gen 当时读取恒 0，`ir_gen.cr:1108` vs `dataflow.cr:381`）；本切片在 pass 层消费，规避该缺陷。

**判据**：

1. **零标注**：源程序不变（无新语法），切片前后源码零改动。
2. **语义等价**：全回归 + 双路径（interp / ELF）精确 rc + 效应次数不增（纯节点无效应）。
3. **生效证据**：决策记录出现 memo 选择（≥1）+ 求值次数下降（解释器计数通道）——「生效」必须可观测，不能只看产物没崩。
4. **退化路径**：事实推导失败 / 使用计数未知 → 不 memo 且记录理由（无静默）。
5. **开关**：决策 pass 可关；关态 = 现状行为（产物/rc 与基线一致）。
6. **记录通道 stub**：§5 R1/R2 的最小记录随切片落地（为 S-D 预留消费面）。

**切片不做**：成本模型接线（③）；并行 / 惰性下沉 / 向量化（后续切片，共用本切片的事实面）。

## 7. 不承诺

承共享契约 §1.3（**逐字引用**）：

> - **错误 specification**：Core 只能证明"程序忠实实现了规则"，不能证明规则本身正确。
> - **恶意/失陷外部实体**：供应链、编译机、密钥、硬件后门——用可复现构建/签名/provenance/最小权限**缩小**，不能用语言语义**证明**。
> - **需求本身允许危险行为**：shell/browser/kernel/JIT 必须执行外来代码——目标不是禁止能力，而是**证明隔离边界**。

本族逐条落点：

- **错误 specification**：优化器不救错算法——「忠实实现规则」包含「忠实地慢」；本线承诺的是「不把机器写回程序」，不是「程序一定快」。
- **恶意/失陷外部实体**：**表与剖析数据是外部输入**——恶意/损坏的目标描述或 PGO 数据可改变性能甚至改变所选映射；用 provenance / 签名 / 最小权限**缩小**，语言语义**不证明**；信任归治理层（与 M1 定论一致）。
- **需求本身允许危险行为**：unsafe / extern 边界内手写机器相关代码（HIT extern 事件 / unsafe 外部入口）**不被禁止**——本 spec 不管理它，只保证它不污染其它部分的程序意义（机器相关区域须显式留在边界内）。

本线自有不承诺（成本模型 / 启发式）：

- **成本模型不保证最优**——选择 = 启发式；最优性证书 = 远期独立项，不在本 spec。
- **启发式可退化**——退化 = 回落语义直接形态；不承诺任何程序变快，不承诺优化一定发生。
- **不承诺性能可移植**——语义可移植（§3.2）是承诺；不同目标的性能表现可完全不同（决策自由是其推论）。
- **不承诺自动推断意图**——精度（apx）等意图类标注永远显式；推断不出的局部性事实不猜。

## 8. 不做项 + 开放问题

**不做项**（YAGNI / 已裁）：

- 自动 apx（精度意图——编译器猜不了，显式标签保留——TODO 定案）；
- 数据结构自动选择（依赖意图，太远——TODO 定案）；
- 最优性证书 / 性能证明（远期独立项）；
- 非经典范式的成本模型实例（本 spec 只给接口形态；经典实例先行，范式扩展随 M3）；
- 手动性能标注的**语言化**（不新增关键字/属性轴——D6）；
- 对 unsafe / extern 内手写机器代码的管理（§7）。

**开放问题**：

1. **成本事实的载体与量纲**：表字段 vs 侧表；相对权重 vs 绝对量的表达——影响表的稳定性与判据形态。
2. **局部性/表示提示的语法载体**：是否需要显式提示，或全自动即可（R3 定）；判据 = 可忽略性。
3. **并发安全子集的边界**：alloc 下沉 / arena 归属约束（TODO 惰性条已列约束）+ 多 M 未验证（TODO 预存 #1）——auto-parallel 的真实前置面。
4. **PGO 数据的信任与可复现**：数据 provenance / 签名形态；跨机器剖析数据的有效性。
5. **成本模型校准方法论**：基准套件；与 S-D 上界的关系（上界 = 证明，估计 = 启发式——两套数字冲突时以谁为准）。
6. **决策记录的规模与裁剪**：全图记录可能很大——采样/摘要策略归 S-D 还是本线。
7. **优化与义务判定的接口**：prove 档升格后消除 enforcement 的流程归属（§2.4 硬条款的实施细节）。
8. **「同一问题」的最终验收形态**：单 CPU 优化与异构 placement 用同一机制表达的首个端到端实例（何时/哪个范式实例——如 M3 第二张表）。
