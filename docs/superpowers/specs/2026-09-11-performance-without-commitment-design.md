# 性能无实现承诺

## 概述

为了性能，程序员经常把机器知识写回源码：SIMD intrinsic、CUDA 或 NPU 方言、硬件换代后重写内核。Core 的立场是：

> 程序意义里不包含机器形状。性能决策是映射实例的选择，不是程序的一部分。

单 CPU 上的 SIMD、cache、NUMA、内联、布局和并行，与异构放置到 GPU、NPU 或加速器，是同一个问题：在“图加目标描述”上选择事件组合和资源绑定。差别只在目标描述的表内容。机制只有一条，不能为 SIMD、CUDA 或 NPU 各开特判通道。

设计状态：定稿，尚未实现。修订记录、决定编号、TODO 收纳细节和自检见 `docs/superpowers/implementation/2026-09-11-performance-without-commitment-audit.md`。

## 决策面

决策对象是从格到编码的映射选择，包括内联、放置、并行分派、事件选择和布局。

不修改值流、state 边和区域语义。执行、副作用和内存的命令式下限不动。寄存器分配是缓存语义的映射实例，是这条原则的既有先例。

检查基调：

- 合法性可以判定。
- 收益是启发式估计。
- 任何优化变换缺失都可以接受，直接形态始终合法。

## 原则

1. 机器形状不进入程序意义。源码和图里没有宽度、寄存器、SIMD 宽度或设备名。性能变化不构成语义变化。
2. 优化是映射选择，不是图修改。决策作用在从格到编码的映射上。
3. 合法性和收益分开。合法性前提由图判定，无法判定就不选。收益由成本模型估计，可以出错。启发式失效的唯一后果是回退到直接形态。
4. 优化不能削弱义务。不能移除或绕过 enforcement。检查消除只能走义务判定中的 prove 档，不能由成本模型决定。MMIO 和 volatile 不消除、不重排、不合并。
5. 成本模型是数据加可替换组件。成本事实随表走。成本模型是编译器侧的可替换件，不进入图语义，也不进入表的放置策略面。
6. 标注是开放标注或事实来源，不是新的 primitive。不新建属性轴，不新增语言关键字。显式面只允许可选的性能提示，任何目标都可以忽略它并退化到合法形态。
7. 决策和缺席都要有理由。可解释，但不强制拒绝编译。

## 标注面

总原则是自动推导优先。能从图结构或显式边推导的，不要求用户写。

| 面 | 内容 | 来源 | 形态 |
|---|---|---|---|
| 依赖 | 数据依赖和顺序、副作用序，是并行合法性的全部输入 | 自动 | 值边和 state 边 |
| 纯度和效应 | 节点或区域的效应集，无效应即纯 | 自动，使用 `effect` 轴和效应边 | 推导事实 |
| 局部性 | 访问模式、复用距离、步长、嵌套深度 | 自动优先，使用图和索引来源链 | 推导事实 |
| 精度需求 | `apx` 精度降级和 `dex` 精度意图 | 显式 | 既有语言标签 |
| 资源约束 | 内存上界、并行度上界、deadline | 显式策略数据或目标默认 | policy 数据 |

效应规则：效应等于除引擎判定纯者外的一切调用。当前纯度计算使用保守起点、调用图不动点、递归和强连通分量保守、不可解析调用保守。未证纯的可解析调用也进入 state 链。

state 链每个函数重置，跨函数不连接。调用节点表示被调者的效应序。新增 IR opcode 必须同步 `purity_op_effect` 的清单。

精度轴只读不写。优化器不能替用户降精度，不自动使用 `apx`。用户显式给出 `apx` 后，优化器可以用它选择更宽的近似事件。

局部性和表示类提示必须是可忽略的。提示缺失不改变合法性，被忽略只改变性能。

资源约束由上界判定负责证明，本设计只做满足检查。deadline 类只做诊断，不改变运行时语义，也不承诺时间上界。

## 优化器流程

```text
1. 事实推导：依赖闭包、效应集、使用计数、索引来源、生命周期
2. 候选生成：每条变换附合法性前提，前提不可判则不生成候选
3. 成本评分：使用表成本事实和资源约束
4. 选择：目标描述、阈值和约束
5. 记录：决策记录
6. 发射：编码、布局和调度
```

每段的失效语义都是退化，不是改变语义：

- 事实未知时，按最保守事实处理：有依赖、有效应、索引未知。
- 前提不成立或不可判时，不选该变换。
- 成本缺失或未知时，使用默认形态。
- 没有候选或超出约束时，使用直接形态。
- 记录缺失不影响判定。

### 合法性和收益

合法性检查是图前提，包括：

- 没有依赖路径，用于并行。
- 没有效应，用于记忆化。
- 索引仿射可证，用于向量化。
- 没有递归和逃逸，用于内联。
- 单一使用位置，用于惰性下沉。
- 汇合点确定，用于并行类变换。

合法性是可判定的，无法判定按“否”处理。收益是成本估计加阈值，是启发式，可以出错。收益只影响性能，不影响语义。

候选门的判定输出必须引用图事实，说明是哪条边、哪个效应、哪个索引来源。这样决策记录和解释才有证据。

效应门使用真实纯度时，必须在 `compute_all_purity` 写回之后。IR 生成期仍然读取冻结的乐观默认值，此时使用会读到旧行为。

## 成本模型

输入有三类：

1. 表成本事实：事件条目、运行时条目、硬件设备事实。换表就换输入。
2. 形状上下文：宽度、布局、嵌套和访问模式。
3. 资源约束：由上界判定证明，本模型只检查是否满足。

输出是相对成本估计，必须包含：

```text
cost
band              不确定带，必填
model_id
model_ver
assumptions[]     模型成立的前提
```

成本模型不输出任何语义事实。

六条约定：

1. 事实和模型分离。成本事实是表条目字段。“如何使用成本事实决策”是编译器侧可替换件。
2. 缺失时保守退化，不做推断。
3. 使用相对量纲，不承诺绝对值，不承诺最优。
4. 模型可替换。多目标和多范式各有一套实例，机制不变。
5. 模型不是证明。估计值不能呈现为最坏执行时间证明或时间上界。`MODELED` 必须标注“模型估计，非证明”。`band` 必填。模型不可用时按 `UNKNOWN` 处理，不能用经验常数回退成 `MODELED`。
6. 和上界不混报。成本估计只进入 `MODELED` 层。结构层的 `PROVED` 数字，例如分配次数、进行中任务数和通信量，不能与成本估计合并、覆盖或相减。同层冲突取更宽的界。

模型版本变化后，相关决策记录和报告自动失效。

## 与安全机制的交互

优化变换不能消除 enforcement，除非按四档义务判定提升到 prove 档。消除流程属于义务判定通道，不属于成本模型。

volatile 和 MMIO 不消除、不重排、不合并。

state 边是顺序的唯一来源。重排和并行只在无依赖证明下允许。

任何移动、重排或合并都必须满足三个检查面：

1. 发射层：lowering 不得引入顺序依赖，包括把非结合算子降低为顺序敏感实现。
2. 调度器：就绪队列或线程 id 不能成为影响观测的 tie-break。
3. 编译器 pass：不得改变汇合点的输入到达集合或引入顺序依赖。CSE 合并两个 `race` 点会改变观测集合基数，禁止，除非已经证明观测等价。

自动并发需要两个条件都通过：依赖门和汇合点确定性门。只通过依赖门就分派是非法移动。`merge_ordered` 的保序并行可以纳入移动集合，但 lowering 必须证明 state 边序等于观测序。

## 目标描述

目标描述是数据，不是代码：

```text
目标描述 =
    三轴组合：架构、格式、操作系统
    语义表：事件签名
    投影条目：经典编码、通道映射、连续类演化描述
    运行时条目：调用和返回机制、地址语义、系统边界、宽度和形状
    设备表：设备 id 到物理基址
    架构特化参数
    成本事实
```

表是唯一允许出现机器名词的地方。图的语义完整性不依赖任何表，换表可以重建语义。

表的三种范式形态是编码、接通和演化。条目缺失时，编译期拒绝或走 `unsafe` 外部入口。

换目标不改语义的检查：

1. 观测等价：同一程序加不同目标描述，值、效应顺序、返回码和输出一致。
2. 源码零改动：换目标不要求改源码。
3. 义务判定不变：换目标后安全义务的档位和判定结果不变。
4. 决策自由：内联、向量化、并行、布局和放置可以完全不同。检查只约束语义，不约束决策。
5. 可移植子集：只使用最小核事件的程序可以在任意表下运行。

反向泄漏检查：

- 换目标需要改源码。
- 决策结果被写回图或源码语义。
- 源码或图中出现机器名词。

任一成立就是泄漏，需要登记并归一。

## 与既有性能工作的关系

性能自动化条目统一为“事实推导、决策、目标描述”一条线：

- 自动并发：使用依赖事实和汇合确定性判定。
- 自动记忆化：使用纯度和效应事实。
- PGO：作为成本模型的校准输入，收集和回灌基础设施单独立项。
- 自动向量化：使用局部性事实和 SIMD 表条目。
- 自动内联：作为映射决策，显式 `@inline` 是可选提示。
- 自动软件流水：作为映射决策。
- 控制流自动惰性：和记忆化共用纯度和使用计数基础设施。
- 边界判定 pass：提供索引来源和恒安全、恒越界、不可判三类事实。
- 寄存器分配：合法性和收益分离的既有先例。
- hw-map 和 HIT：提供目标描述的数据面。

仍然独立的事项只有四项：PGO 收集基础设施、边界判定 pass、表实现、多 M 调度验证。

## 解释接口

决策记录使用 S-D 的记录表，不另立 schema。本设计补充变换和模型版本，通过 `evidence` 与 `phase_ver` 保存。

要求：

1. 记录是结构化数据，不是文本日志。
2. 已做决策和未做决策都有记录。“为什么这里没有优化”的原因必须能落到缺前提、成本不划算或无候选之一。
3. 图对象引用使用稳定身份，可以在源码、图和产物之间桥接。
4. 可以按函数、图对象或决策类型查询。
5. 成本面透明，能回答为什么选 A 不选 B。
6. 记录通道可以关闭，关闭后产物零差异。记录缺失不影响语义。

## 最小切片

切片是：一条标注到一个决策，先实现合法性可判定，把收益启发式留白。

选择的对象是循环不变的纯节点或区域，做自动记忆化。三条前提：

1. 节点在循环体内，输入不随迭代变化。输入定义在循环外，或者由图证明是迭代不变量。
2. 按真实纯度判定为纯。含任何效应 opcode 或未证纯、不可解析调用，都视为有效应。
3. 没有分配，没有 arena 交互，单线程。

选择这个对象的理由：每轮迭代重复求值，记忆化后求值次数下降，收益真实存在；合法性前提仍然很小，只需要无效应和迭代不变性；它和自动惰性共用基础设施。

切片不接成本模型，收益规则使用平凡的保守启发式。成本模型保留为可替换的模拟件。

切片前置：

1. 判定 pass 必须在数据流分析产出使用计数之后运行。当前存在使用计数时序缺陷，切片在 pass 层使用，规避该缺陷。
2. 求值计数通道不存在，切片需要自带最小计数，或者退用解释器既有可观测面。

检查：

1. 源码零改动。
2. 语义等价：全回归，解释器和 ELF 双路径返回码一致，效应次数不增加。被记忆化的节点满足无调用、无效应、输入不随迭代变化三条断言。
3. 生效证据：决策记录出现记忆化选择，求值规模下降。不能用 IR 节点数或发射指令数下降代替，因为本切片实现位置在解释器侧。
4. 退化路径：事实推导失败、使用计数未知、迭代不变性不可判或保守规则判为有效应时，不记忆化，并记录理由。
5. 开关：决策 pass 可以关闭，关闭后行为和基线一致。
6. 记录通道：实现最小决策记录，字段使用 S-D 的记录表。

切片不做成本模型接线、并行、惰性下沉和向量化。

## 不承诺

1. 错误的 specification。Core 只能证明程序忠实实现了规则，不能证明规则本身正确。
2. 恶意或失陷的外部实体。供应链、编译机、密钥和硬件后门不能用语言语义证明。
3. 需求本身允许危险行为。shell、浏览器、内核和 JIT 必须执行外来代码，目标是证明隔离边界，不是禁止能力。

本设计另外不承诺：

- 成本模型精确或最优。
- 所有程序都能优化。
- 优化一定发生。
- 时间上界。成本估计只是模型，不是证明。
- 自动选择数据结构。
- 自动降低精度。

## 不做项

- 不为 SIMD、CUDA 或 NPU 开特判通道。
- 不把机器形状写进源码或图。
- 不自动使用 `apx`。
- 不自动选择数据结构。
- 不用成本模型决定义务判定。
- 不消除或重排 volatile 和 MMIO。
- 不做时间上界证明。
