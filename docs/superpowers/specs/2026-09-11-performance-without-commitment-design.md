## 0. 范围与裁决

### 0.0 论题：Performance without implementation commitment

现状（各语言的通病）：为了性能，程序员不断把机器知识写回源码——SIMD intrinsic、CUDA / NPU 各一套方言、硬件换代重写内核。Core 的立场：

> 程序意义里不含机器形状（承既有定案：宽度移出语言 / 地址 = 映射 / 表示层归处 = 映射参数）。因此**性能决策 = 映射实例的选择，不是程序的一部分**。

关键同构（本 spec 的论题展开）：单 CPU 上的 SIMD / cache / NUMA / inlining / layout / parallelization 与异构 placement（GPU / NPU / 加速器）是**同一个问题**——在「图 + 目标描述」上选择事件组合与资源绑定。差别只在目标描述的表内容（HIT 运行条目 / hw-map 设备表）：**机制同一，无第二条性能路线**。禁止为 SIMD / CUDA / NPU 各开特判通道（与 §1.2.2「禁止内建特判」同构）。

### 0.1 本 spec 的决策面

- 决策对象：格 → 编码映射的选择/放置/调度（内联、放置、并行分派、事件选择、布局）。
- 不修改：值流、state edges、region 语义（图本体）——承「执行/副作用/内存的命令式下限不动」（契约 §1.2.5）；先例 = 寄存器分配 = 缓存语义映射实例（已定稿）。
- 判据基调：合法性可判定、收益启发式；**任何变换的缺失都可接受**（直接形态恒合法）。

### 0.2 裁决（设计已定 L1-L7）

| # | 裁决 | 依据 |

## 1. 标注面

**总原则**：

1. **自动推导优先**——能从图结构/显式边推导的一律不要求用户写（依赖、纯度/效应、使用计数、索引来源）。
2. **显式仅在意图不可推导处**——精度（apx）/ 资源约束（意图）类；显式面恒为**可选提示或策略数据**：缺失不改变合法性，被忽略只改变性能（= 无承诺的机制保证）。

| 面 | 内容 | 来源 | 形态 | 现状锚点 |
|---|---|---|---|---|
| **依赖** dependency | 数据依赖 + 顺序/副作用序（并行合法性的全部输入） | **自动**（图结构） | 值边 + state edges | 已显式（region 化控制流落地）——自动并行的可判定性地基（TODO auto-parallel 条的机制根据） |
| **纯度/效应** purity-effect | 节点/region 的效应集（无效应 = 纯） | **自动**（`effect` 轴 + 显式效应边）——**已取真纯度事实**（2026-09-11 修复；时点约束见 §2.2 C2） | 推导事实 | S-A §1.1 的 `effect` 轴**只引不扩**；state edges 已存在。**前置缺陷已于 `762bd429`+`c9099d73` 修复（2026-09-11 效应/纯度修正批）**：`fi_ispure` = `compute_all_purity`（`checker.cr:2938`）真计算（保守起点 + 不动点 + 递归/SCC/不可解析保守）；入链判据 = 单一真源 `purity_op_effect`（`checker.cr:2891`，含 `IR_CALL_EXTERN`/`IR_SPAWN`/`IR_YIELD`/`IR_HOTPATCH_ROUTE`/`IR_DYN_DISPATCH`/`IR_STORE_PTR`/`IR_AWAIT`）⇒ 一切可解析但不纯的调用（`print`/`read_file`/`chan_send`/`sched_go`…）入 state 链；链**每函数重置**（设计不变——`df_replay_state_chain` 链头重置；跨函数不连，调用节点 = 被调者效应的序代理）。修复前（历史，保留备查）：`checker.cr:1107`/`:1142` 值恒 1 ⇒ 上述调用皆被标"纯"、不入链 |

## 2. 优化器与决策

### 2.1 流程（六段）

```
① 事实推导（图 pass）      依赖闭包 / 效应集 / 使用计数 / 索引来源 / 生命周期
② 候选生成（可判定性门）    每条变换附合法性前提清单；前提不可判 → 候选缺席（保守）
③ 成本评分（成本模型接口 ← 表成本事实 + 资源约束）
④ 选择（策略数据：目标描述 + 阈值/约束）
⑤ 记录（决策记录 → §5）
⑥ 发射（实例层：编码 / 布局 / 调度）
```

各段失效语义（全部**有向退化**，无静默改义）：① unknown → 按最保守事实（有依赖 / 有效应 / 索引未知）；② 前提不成立或不可判 → 不选该变换；③ 成本缺失/未知 → 退化用默认形态；④ 无候选或超约束 → 直接形态；⑤⑥ 与语义无关（记录缺失不影响判定）。

### 2.2 可判定性与启发式的分界（本 spec 的承重墙）

| 层 | 判据 | 性质 | 失效后果 |
|---|---|---|---|
| **合法性** soundness | 图前提：无依赖路径（并行）/ 无效应（memo——**按 §1 单一真源**：含任何效应 opcode 或未证纯/不可解析调用即视为有效应；2026-09-11 修复后可消费真纯度，时点见 §2.2 C2）/ 索引仿射可证（向量化）/ 无递归 + 无逃逸（内联）/ 单消费点（惰性下沉）/ **汇合点确定性（并行类变换：S-E §1.5 决策序——可判定性 + 确定性判定两道门槛，★D21/I2）** | **可判定**（保守：unknown = 否） | 该变换不选——语义不变 |
| **收益** profitability | 成本估计 + 阈值（调度开销 vs 收益；代码膨胀 vs 调用开销） | **启发式**（可错，待论证） | 只影响性能，绝不影响语义 |

- 承重属性（已定 L3）：**任何变换的缺失都可接受**——直接形态恒合法。这与安全线的「义务不静默消失」正交：那是义务，这是可选性。
- 要求：候选门的判定输出必须**引用图事实**（哪条边 / 哪个效应 / 哪个索引来源）——为 §5 记录与 S-D 解释提供证据面。
- **效应门纪律（C2，2026-09-11 修复后修订）**：纯度事实**已可靠**（`compute_all_purity`，`762bd429`+`c9099d73`；见 §1 回填记录）⇒ 首切片与实施批**可以 `fi_ispure` 旗标 / state 链边为真值**——"无效应"结论的判据 = 「无 store 家族 ∧ 无效应 opcode（§1 单一真源清单）∧ 调用全被真纯度证纯（不可解析调用恒计效应）」。**时点约束（硬性）**：该字段在 IR 生成期仍是 checker 的**冻结乐观默认值**（`ir_gen.cr:1590` 的 lazy 判定有意不解冻）⇒ 消费必须发生在 `compute_all_purity` 写回之后（IR 生成 + `df_state_finalize`）；生成期消费 = 读到恒 1（即修复前的老行为）。

### 2.3 成本模型接口（接 hw-map）

**设计已定 = 接口形态；待论证 = 精度与量纲。**

- 输入 ①（**表成本事实**）：事件条目 + 运行时条目（调用/存储/系统边界/宽度形状——HIT §3.3）+ hw-map 设备层事实。事实随表走 → 换表换输入。
- 输入 ②（**形状上下文**）：宽度 / 布局 / 嵌套 / 访问模式（来自 §1 事实）。
- 输入 ③（**约束**）：资源约束（§1）——约束由 S-D 判定/证明为上界；本模型只做**满足检查**。
- 输出：相对成本估计 + **必填四项**：`band`（不确定带——单点数字给人"精确"错觉 = 过度承诺）/ `model_id` / `model_ver` / `assumptions[]`（接口形态**以 S-D §1.7.3 的 `cost_model_query` 为准**，本 spec 不另立）；**不输出**任何语义事实。**注（B 线 N5）**：早稿并列的「约束满足判定」**不在** S-D §1.7.3 的返回面——约束满足检查是**消费侧（优化器 ④ 选择段）的内部动作**，其结论经决策记录的 `choice` / `alternatives` / `evidence` 呈现（§5 R1），不属成本模型返回字段；本 spec 不要求模型返回它。

契约六条：

1. 事实/模型分离：成本事实 = 表条目字段（材料属性）；「如何用成本事实决策」= 编译器侧可替换件（HIT §3.3「表只描述材料，不描述放置策略」保持）。
2. 缺失 = 保守退化，**不猜**。
3. 相对量纲，不承诺绝对值、不承诺最优（§7）。
4. 模型可替换：多目标/多范式各一套实例，机制不换。
5. **模型非证明（硬性，承契约 §1.4；C1/★D24）**：估计值**不得**呈现为 WCET 证明 / 时间上界——`MODELED` 渲染必须明标「模型估计，非证明」（S-D §1.7.2）；`band` 必填；模型不可用（未落地 / 预算耗尽）⇒ 消费方按 `UNKNOWN`，**不得**用"经验常数"兜底成 `MODELED`（S-D §1.7.3 禁令）。
6. **与上界不混报（C1/★D24）**：成本估计只进 `MODELED` 层；与 S-D 结构层 `PROVED` 数字（分配次数/在飞任务数/通信量）**不得合并/覆盖/相减**——三层不可混报（S-D §2.1）；同层内冲突取保守（更宽界）。`phase_ver` 含 `model_ver` ⇒ **模型换代 ⇒ 相关记录与报告自动失效**（S-D §3.3）。

### 2.4 与义务/安全性的交互（硬条款，承 L4）

- 变换不得消除 enforcement（运行时检查/强制通道），除非按四档义务判定升格为 prove 档（消除流程 = 义务判定通道，非成本模型）。
- volatile / MMIO：不消除、不重排、不合并（hw-map §2 既有条款在本线重申为约束）。
- 效应序：state edges 是顺序唯一来源；重排/并行只在无依赖证明下允许——这正是自动并发「非依赖猜测」的机制根据（TODO auto-parallel 条：区别于四十年失败史的根源）。
- **物理 ⇏ 语义：承接 S-E §2.2 的三个检查面（I2/★D21）**：本线任何搬运/重排/合并（自动并发 lowering、CSE、LICM、惰性下沉等）须同时满足——① **发射层**：lowering 不得引入序依赖（含把非结合算子降低为序敏感实现）；② **调度器**：就绪队列/线程 id 不得成为 tie-break 并影响 `obs`；③ **编译器 pass**：不得改变 merge 点的输入到达集合或引入序依赖——**CSE 合并两个 `race` 点 = 改变 `Obs(M)` 基数 ⇒ 禁止**（除非按 S-E §1.4(i) 已证观测等价）。**可陈述不变量：每个变换都保 `obs`**（S-E §2.2）。
- **自动并发的两道门槛（承 S-E L7；互引 `2026-09-11-merge-semantics-design.md` §4.3）**：依赖门（可判定性）**与**汇合点确定性门（S-E §1.5 决策序）**两道都过才搬运**；只过依赖门即分派 = 该次分派非法。搬运集合含 `merge_ordered` 保序并行（S-E Q5 已裁：纳入），其 lowering 须证明「state 边序 = 观测序」。

## 3. 目标描述

### 3.1 形态（数据，非代码）

编译器持有通用机制 + 实例参数（x86 实例 spec §0 同构原则）：

```
目标描述 = 三轴组合（架构 × 格式 × OS）
         + 表：语义表（事件签名）+ 投影条目（经典编码 / 通道映射 / 连续类演化描述…）
              + 运行时条目（call/ret 机制、地址语义、系统边界、宽度/形状）
         + 设备/投影表（hw-map：device id → 物理基址）
         + 架构特化参数（machine / reloc 等——波 2 机制）
         + 成本事实（§2.3 输入①——**载体 = `.ccr` 新段，随 R2 P4 同波**：段 tag 空间可扩展（`2026-09-09-lattice-ir-v7-format.md:44` 的 `7+` **未固定分配**，既有注明用途 = 驱逐标注段 / 证书段，新段名随实施批定）；策略随产物分发，★D4 裁决。B 线 N8）
```

- **表是唯一允许出现机器名词的地方**（L1 的载体）；图的语义完整性不依赖任何表（换表可重建语义）。
- 表的三种范式形态（编码 / 接通 / 演化）与「无实现：条目缺失 → 编译期拒绝或 unsafe 外部入口」承 HIT §3.2，不重定义。

### 3.2 判据：换目标不改语义（可迁移判据）

1. **观测等价**：同程序 + 不同目标描述 → 值 / 效应序 / rc / 输出一致（判据形式：双目标运行比对，精确 rc；外部效应按登记比对）。
2. **源码零改动**：换目标不得要求改源码——**这是「无实现承诺」的操作性判据**（要改源码 = 机器形状漏进程序意义，违反 L1）。
3. **义务判定不变**：换目标后 S-A 的义务档位/判定结果不变（安全不因目标而弱化）。
4. **决策自由**：映射选择（内联 / 向量化 / 并行 / 布局 / placement）可完全不同——判据**只约束语义，不约束决策**。
5. **可移植子集**：只用最小核事件的程序 = 任意表可跑（HIT §4 既有条款，本 spec 承接为可移植判据的基线）。

反向（泄漏检测，用 lattice-encoding-boundary G3「可换性」判据）：a) 换目标需改源码；b) 决策结果被写回图/源码语义；c) 源/图中出现机器名词——三项任一 = 违反，登记为「泄漏待归一」。

## 7. 不承诺

承共享契约 §1.3（**逐字引用**）：

> - **错误 specification**：Core 只能证明"程序忠实实现了规则"，不能证明规则本身正确。
> - **恶意/失陷外部实体**：供应链、编译机、密钥、硬件后门——用可复现构建/签名/provenance/最小权限**缩小**，不能用语言语义**证明**。
> - **需求本身允许危险行为**：shell/browser/kernel/JIT 必须执行外来代码——目标不是禁止能力，而是**证明隔离边界**。

本族逐条落点：

- **错误 specification**：优化器不救错算法——「忠实实现规则」包含「忠实地慢」；本线承诺的是「不把机器写回程序」，不是「程序一定快」。
- **恶意/失陷外部实体**：**表与剖析数据是外部输入**——恶意/损坏的目标描述或 PGO 数据可改变性能甚至改变所选映射；用 provenance / 签名 / 最小权限**缩小**，语言语义**不证明**；信任归治理层（与 M1 定论一致）。
- **需求本身允许危险行为**：unsafe / extern 边界内手写机器相关代码（HIT extern 事件 / unsafe 外部入口）**不被禁止**——本 spec 不管理它，只保证它不污染其它部分的程序意义（机器相关区域须显式留在边界内）。

本线自有不承诺（成本模型 / 启发式）：

- **模型非证明（承契约 §1.4，硬性）**——成本估计是启发式，**不得**呈现为 WCET 证明 / 时间上界；`MODELED` 数字必带 `band` + `model_id`/`model_ver` + `assumptions[]`（§2.3 契约第 5 条），且与 `PROVED` 层不混报（第 6 条）；模型不可用 ⇒ `UNKNOWN`，不得用经验常数兜底。
- **成本模型不保证最优**——选择 = 启发式；最优性证书 = 远期独立项，不在本 spec。
- **启发式可退化**——退化 = 回落语义直接形态；不承诺任何程序变快，不承诺优化一定发生。
- **不承诺性能可移植**——语义可移植（§3.2）是承诺；不同目标的性能表现可完全不同（决策自由是其推论）。
- **不承诺自动推断意图**——精度（apx）等意图类标注永远显式；推断不出的局部性事实不猜。
