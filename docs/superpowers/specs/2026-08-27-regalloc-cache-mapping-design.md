# 寄存器分配设计：缓存语义映射实例（Register Allocation as a Cache-Semantics Mapping Instance）

日期：2026-08-27
状态：**设计定稿（方向）**——语义基座、对象、判定、分配器四层结构定稿；实现待落地（§8）。关联备忘：`docs/memory-model-capability-lattice.md` v4 §11.5。

## 1. 背景与动机

### 1.1 问题

寄存器分配的**完全形式化验证**需在候选算法空间（图着色 / 线性扫描 / SSA 弦图 / SPL 语法分解）中取舍；该空间内各方案都存在同一障碍：**正确性绑定在 CFG 结构上**——验证要么证明算法机制（CompCert 式，随算法变、贵），要么在运行时再跑一遍检查（双重验证）。

### 1.2 关键转向：缓存语义视角

在 Core 的框架里，寄存器分配不是「编译器 `pass`」，而是**格 → 编码的映射实例**——与区域 / `arena` / 字节权限同族（缓存语义条款 7）。寄存器文件 = 缓存层，`home`（栈槽）= 经典映射。由此：

- **驱逐不变量（条款 2）就是现成的语义保持定理**——驱逐任意条目不改变可观测语义。分配器把哪个条目放寄存器、放多久，只是放置/替换策略（与 `LRU` 无需证明同理），**算法零证明**
- **验证义务收敛为映射实例的一致性判定**——单层、可判定、局部
- **`CFG` 算法（线性扫描/图着色/`SPL`）都是线性化退化实例**——不进入语义本体；「`CFG` 即将淘汰变成格」对分配的正确含义：正确性不再对某条线性化路径陈述，而是对**全部可能执行**成立（`order-free`）

### 1.3 已排除的方向（讨论记录）

| 方向 | 排除原因 |
|---|---|
| Go 式 Chaitin 图着色 | 机制最重（干扰图 + 合并 + spill 反馈），验证成本不成比例 |
| SSA + 弦图贪心（PEO） | 需要 IR 转 SSA（架构级改动）；弦图最优性只覆盖着色，spill 仍启发式 |
| SPL 语法分解（2024–2026 新结果） | 多项式精确（O(\|G\|·\|D\|⁶)）是 CFG 退化实例自身的最优解，但整个方法建立在 CFG 上——与格演化方向相反（仅作退化实例参考，§6） |

## 2. 语义基座（律）

- **公理 = 缓存语义七条**（`memory-model.md` §一）——零签名、无格承诺（能力+格备忘 v4 §4.6）
- **驱逐不变量 = 语义保持定理**：⟦G ∖ storage(e)⟧ = ⟦G⟧——分配正确性与执行顺序无关，对全部可能执行成立（强于任何 `CFG` 正确性：`CFG` 只对一个线性化成立）
- 判定/定理只在**关系层面**陈述（共存关系连预序公理都不需要——共存无传递性，是对称关系）；对一切格成立，`CIC` 内核中任何具体格都是该理论的一个模型

## 3. 对象（物）

| 对象 | 定义 |
|---|---|
| 条目（entry） | IR 变量**版本**（条款 5 版本化：每次赋值 = 新版本 = 新条目） |
| 配方（recipe） | 产生条目值的图节点 + 输入边 |
| 存在区间 | 图活性（图层的导出，复用 RegionCheck 机制——引用者存活区间） |
| 共存 | 两个条目的存在区间相交（对称关系；互斥分支中的条目永不共存——无路径结构，由状态空间直接给出） |
| home | 条目的持久位置（经典映射 = 栈槽） |

**无配方条目**（边界 + 图内不可重算，能力+格备忘 v4 §5.3）一条通用规则：**必须有 `home`，驱逐必写回**——驱逐不变量/再生等价对它们不成立（重跑神谕 ≠ 原结果）。对所有无配方条目一视同仁，不按范式枚举。

## 4. 判定（验证，单层）

一致性四条（全部可判定、局部、**条目泛型**——只操作「位置 + 配方 + 存在」，不读值的内容）：

1. **共存互斥**：每时刻每寄存器至多一个条目的材料（共存 = 存在区间相交）
2. **读点无陈旧**：读到的材料与条目的当前版本对齐（条款 5 版本化）
3. **驱逐配对**：驱逐（寄存器回收）时材料不丢——写回 `home`，或配方可再生（条款 3 再生等价 = `rematerialization`）；无配方条目必写回（§3）
4. **调用点失效契约**：调用点 = 缓存失效边界——`caller-saved` 失效（材料归 `home`），`callee-saved` 保留（`ABI` 即缓存保留契约）

**算法零证明**：正确性由判定保证，与分配算法选择无关（生成器 + 验证器分离——2025 年 `LLM` 分配器 `VeriLocc` 同构先例）。分配算法定案 = 上下文贪心（§5）。

**落点**（双层消费同一规约）：
- `.corespec` 契约——「寄存器映射实例合法」判定写成规约（`spec-design.md` §2.7 体系：翻译桥 → `CIC` 内核，健全性由内核保证）
- 编译器内 `checker`——实现期自检（每编译一次，失败 = 分配器 bug 即时暴露）

## 5. 分配器（定案：上下文贪心）

**共存偏序上的贪心放置**：上下文 = 共存关系 + 再生成本（配方）+ `region` 生命周期 + 调用点。**定案（2026-08-27）：上下文贪心为唯一分配算法**；判定不依赖算法选择（算法规格见 `docs/regalloc-cache-mapping.md` §五）。

- 版本区间（`IR_STORE` 切分）——对应条款 5 版本化，比 `first`/`last` 全函数区间精确
- `spill` = 驱逐写回 `home`；`remat` = 配方重算（成本 = 产生节点重算代价）
- 调用点感知：解锁 `caller-saved` 寄存器（x86-64 通用寄存器 16 个 + `XMM`，现实现仅用 5 个 `callee-saved`）
- **`CFG` 退化情形 = 区间序 `First Fit` = 最优**（`Dilworth`：最小寄存器数 = 共存偏序的 width；区间图 = 完美图，χ = ω）——数学闭合

## 6. 数学支撑（文献）

| 结果 | 内容 | 在本文的位置 |
|---|---|---|
| Dilworth 定理 / 区间序 | 链分解 = 分配；width = 最小寄存器数；区间序 First Fit 贪心 = 最优 | §5（CFG 退化情形的精确性） |
| PCM / 资源代数（Verus/Iris） | 寄存器 = 可分离资源（每寄存器一个位置的 `Resource<P>`，alloc/join/split）——验证语言与能力+格备忘 §九 代数同构 | 验证的可选代数层（非必需，§4 判定已足够） |
| SPL 语法分解（Cai & Goharshady 2024–2026） | series-parallel 控制流图上带 spill 的最小代价分配多项式精确（O(\|G\|·\|D\|⁶)） | 退化实例自身的最优解参考——证实「CFG 系算法是格分配的线性化特例」；其 DP 表可作最优性证书的形态参考 |

## 7. 范围边界（YAGNI）

- ❌ 不做 `SSA` 转换（版本化语义已在，§3 条目 = 版本；IR 不需要 `SSA` 化）
- ❌ 不做图着色机制、不做 `SPL` 分解实现（`CFG` 系，方向已弃）
- ❌ 不做格代数承诺（§2：关系层面陈述；格 = 映射参数，将来挂接）
- ❌ 不做 `spill` 指令级插入（后端映射细节，判定先行）
- ✅ 做：共存关系定义落定 → `.corespec` 判定规约 → 贪心放置实现 → `checker` 自检

## 8. 落地顺序

1. **共存关系落定**：图活性存活区间相交（复用 `RegionCheck` 的 `cur_seq`/`exit_seq` 机制），确认条目版本的图表示
2. **判定规约**：一致性四条写成 `.corespec`（先规格后实现）
3. **贪心放置策略**：版本区间 + 共存检查 + 驱逐写回（现 `opt.cr` `alloc_registers` 增量升级）
4. **`checker`**：编译期一致性自检（`debug` 模式全开，`release` 可选）
5. **（远期）证书层**：最优性证书（`DP` 表重放或 `ILP` 对偶）——验证「最优」而不只是「一致」

## 9. 验收标准

- 判定：可判定、局部、条目泛型；对一切格成立（关系层面陈述）
- 分配器：任意替换/升级贪心策略，判定与语义保持不受影响
- 语义保持：驱逐不变量成立（`order-free`，对所有可能执行）
- 无配方条目：统一规则（有 `home`、驱逐必写回），无范式枚举
- 与 #10 判据联动：判定以纯格对象写出（无路径结构）=「格不重引入顺序」的实证
