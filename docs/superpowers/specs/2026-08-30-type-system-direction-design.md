# 类型系统方向

## 摘要

图是本体，接口是契约，类型是推导，编码是映射。

类型概念不显式。类型等于值集合，集合运算自动判定。显式性最小集是 `where` 值约束。

声明式上限和命令式下限共用一张图。声明式上限包括类型、契约和验证；命令式下限包括执行、副作用和内存。

设计状态：定稿。学术对照、论文地图和原始论证见 `docs/superpowers/implementation/2026-08-30-type-system-direction-audit.md`。

## 定案

### 图本体

1. 图本体原则。HDFG 是唯一真相层。类型是图节点的标注，接口是图上声明的契约，类型检查是图的良构性验证 pass，与 PointerAnalysis、RegionCheck 和 ProvenanceVerify 同级，不建第二套数据结构。
2. 接口统一。用户面和检查层只有接口一个概念。`int`、`dex`、`string`、`bool` 是原生接口条目，规则内建在编译器，公理引用规约层，用户不能实现。公理由编译器负责，防止伪造证明。
3. 实现决策。使用一张动态接口注册表，`int` 是表头原生条目。检查器删掉类型特判，统一查表验证。发射层原语映射不动，例如 `+` 对应 `addq` 是机器知识，归硬件映射编码层，不做表驱动化的大重构。
4. 类型检查等于图验证 pass。标注一致性和操作数兼容性按注册表规则判定，与指针三个 pass 同一层级。

### 约束和泛型

5. `where` 值约束。实现内联的轻量前置条件。三档语义：编译期常量约束产生编译错误或通过；符号约束产生验证条件；动态约束生成运行时检查。
6. 泛型等于编译期接口具体化。类型参数是“实现了某接口的具体类型”。声明处绑定接口，实例化时检查，不做运行期字典。

### 自动推导

7. 宽度移出语言。机器形状归硬件映射。语言侧清理可以立即做：删除死条目、删除 `_f32` 和 `_f64` 死路径、复核 `1_000` 在两个编译器中的分歧。编码层宽度由目标自动决定。
8. 类型标注自动。子类型关系自动判定，使用集合包含。枚举自动化为联合类型，穷尽性检查等于补集空性。可选和可空是联合类型的副产品，例如 `Node?` 等于 `Node | Null`。类型等价自动判定，使用双向包含。元组和记录是 product 自动组合。数组和切片是序列接口加元素接口加长度值约束。转换是集合包含判定。借用已经自动：逃逸检查是 pass，释放由 arena 完成，用户零标注。Rust 的 `&` 和 `&mut` 标注体系在 Core 中不存在。
9. 借用收缩，不取消。逃逸安全由 RegionCheck pass 替代，可判定，成本低，保留。释放安全由 arena 结构性消除，不需要额外机制。并发共享需要在借用或验证中二选一，多 M 尚未验证，这是唯一未确定的地方。完全用验证替代借用会新增一笔代价，因为验证条件不一定能证明，而借用永远可判定。默认保留可判定的逃逸 pass，验证处理借用覆盖不到的共享。
10. 递归类型隐式化。递归是注册表引用图上的环，环检测自动，没有 `rec` 关键字。值递归导致无限大小，编译错误。引用递归大小固定，自动支持。归纳原理自动派生，供验证使用。
11. 函数类型隐式化。函数是子图，机制已有：arena 绑定、callee 内联和区域实例化。函数类型是子图端口签名的自动派生。函数值是子图引用，`@addr` 机制已有。高阶参数使用签名，不是独立的函数类型概念。闭包后置，从纯引用开始。规约挂在子图接口上，验证条件自动生成。
12. 接口声明自动，用法驱动推导。接口是用法集合。函数体对参数的操作和字段访问自动构成参数的接口，走约束推断路线。调用点自动检查。可读性由 coreview 显示推导出的接口视图。全推断的错误在调用点报告，用图到源码的映射缓解。
13. 显式性最小集是 `where` 值约束。语义层不能自动推导，例如 `b != 0` 是语义属性，用法推不出来，它本身就是验证内容。返回类型可以推断，是否保留可选。

### 边界

14. 声明式边界。声明式上限是类型、契约和验证；命令式下限是执行、副作用和内存。两者共用一张图。数据依赖是声明式，状态依赖是命令式，使用 state edge、区域和调度。验证器只能使用声明式信息，所以声明式化是验证的必要条件，不是风格选择。执行层必须保持命令式，否则内核路线会偏离。

### 明确不做

- 完整接口一等化，包括存在类型和运行期字典。推迟到平台桥或硬件映射实施时做受限接口值。
- 完全不要类型系统。已有实证表明这会导致类型混淆。
- 高阶泛型。

## 设计推理

- 单范式原则：一个概念树贯穿原语到用户类型，没有第二标签范式，没有第二类型体系。
- 语义保持：图保留一切。类型、接口和契约都是从图推导的投影。标注可以自动算出，用户不需要标注。
- 数学语义：`int` 无上限，`dex` 精确。两者都是公理化接口加原生实现，原语语义也可以对照验证。
- 与既有定案一致：身份等于图节点，无生成方法等于标注，授权归治理层，图到格的验证清单不变。内存模型已经是图本体，类型系统在同一层补充一致性。
- 接口等于信息加规则：节点上存储标注，解释标注的规则在验证 pass，公理在规约层。
- 先例形态：Verus、Dafny 和 F* 使用声明式规约加命令式代码。Core 的不同点是契约层和实现层共用同一张图。

## 代价

| 代价 | 说明 | 处理方式 |
|---|---|---|
| 构造期的循环依赖 | 图构造需要类型来选择操作，类型又依赖图分析 | 临时标注，事后验证，重新发射。现有管线已经是这个形态 |
| 报错时机 | 全推断和用法推导缺少标注时，错误在调用点报告 | 图到源码映射和 LSP。参数标注可选保留 |
| 枚举穷尽性 | `match` 覆盖检查属于类型层性质 | 由集合论类型补偿，穷尽性等于补集空性 |
| 变型和子类型规则 | 接口需要显式变型规则，否则会留下健全性漏洞 | 语义子类型可判定化 |
| 健全性定理 | 不再从标准类型系统继承 | 变成验证管线的证明义务 |
| 类型级结构信息丢失 | 忘记重新编码的信息会被丢弃 | 显式设计标注和公理的防漏清单 |
| 验证替代借用的可判定性 | 验证条件不一定能证明，借用永远可判定 | 保留可判定的逃逸 pass，验证处理高级共享 |

## 演进顺序

1. `where` 值约束，作为验证切片的语法入口。
2. 泛型等于编译期接口，成本低。
3. 验证切片，支持规约、验证条件和自动证明。
4. 格形态，属于 IR 根基改造。
5. 类型概念收敛，自动推导全量实施，远期进行，不改动根基。

约束：两条根基改造，格形态和类型收敛，不能同时进行。它们的交叉区域是 checker 和 `ir_gen` 的全部。
