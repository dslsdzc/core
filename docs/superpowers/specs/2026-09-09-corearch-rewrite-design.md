## 0. 定位与判据

### 0.1 起因与定性

边界 spec 裁决：corearch 病灶 = 与经典计算机绑定太深（病灶 = 转换编码层；.ccr 大体成立局部不纯）。转换器契约（C1-C3）：输入 = 纯格、输出 = 实例形态、核心只含通用机制。用户拍板（2026-09-09）：**一个范式无关的小核心，其他架构针对各自范式/机器定制**——本设计为该拍板的蓝图实质化。

### 0.2 本设计回答的问题

1. 「小核心」的实际内容是什么（§1.1）
2. 实例层的定制边界是什么、x86 实例由什么组成（§1.2）
3. 现 corearch 每个模块归核心还是实例（§2 裁决表）
4. 以什么顺序演进到目标形态（§3）

### 0.3 判据

- 输入 = v7 图载体（.ccr 格语义文件——边/条目/区域；op 字典 = 显式遗留的配方种类引用）
- 重写判据 = **行为等价 + 语义正确性方向**（边界 C4 已裁：逐字节复刻判据废止——实例算法可自由设计，正确性判据 = 投影/映射正确性方向，缓存语义条款 7）
- 哲学约束：内核判定**不读值内容**（条目泛型）；规则封闭（永不新建）；无格承诺（具体代数 = 映射参数）；最弱理论（共存 = 对称关系）
- **内核不需要理解 op 字典语义**——判定作用于条目类别（位置+配方+存在），配方内容（字典含义） = 消费侧解释

## 1. 目标架构

```
v7 图载体(.ccr) ──► 范式无关小内核 ──► 实例(每范式/机定制)
                   │ ①语义对象模型     │ x86 实例: 调度重建 + lower/发射
                   │ ②判定/分配引擎族  │          + 帧/ABI/tag 算法 + 实例数据
                   │ ③实例注册契约     │ 范式 B 实例: (未来)
                   └────────────────────
                     判定结果(home/共存/驱逐) 回传实例
```

### 1.1 范式无关小内核（三组件）

**① 语义对象模型**（输入契约 C1 的执行者）
- v7 图载体 → 条目 × 版本 × 区域语义对象流（loader/解析 = 内核职责——格式校验/拓扑不变量/ENT 校验属内核输入契约守卫）
- 对象 = 条目（位置 + 配方 + 存在）、版本区间、区域嵌套、无配方/持久条目（统一规则，条款 4b）
- op 字典：NOD 的 op = 配方种类**引用**——内核持有引用但不解释语义（最弱理论：判定不需要知道值怎么算出来的，只需要知道它存在、由谁产生、何时失效）
- 归一化角色：v7 载体的「槽语义投影」解释（v7 设计 §2.3 双通道的槽语义通道）不在内核——那是执行型实例的翻译事务

**② 判定/分配引擎族**（语义侧通用——regalloc-cache-mapping 判定四条的推广）
- 共存关系推导（sweep，条目泛型——v6 §4.2 算法 = 内核成员）
- 资源互斥约束（判定四条：共存互斥/读点无陈旧/驱逐配对/调用失效——**与资源域无关的语义判定**）
- 驱逐候选/写回规则（持久条目 home 保真——条款 4b 的判定形态）
- **资源域参数化**：引擎判定「互斥」但不知「寄存器/槽/量子位」——资源域 = 实例声明（无格承诺：实例的资源代数 = 映射参数传入引擎）
- 先例确认：regalloc-cache-mapping 判定四条 = 本引擎族第一个已实现成员——内核抽取 = 从 regalloc.cr 拆出语义侧（§2 裁决）

**③ 实例注册契约**
- 实例 = {能力声明（接受什么语义对象流、产出什么）、资源域/代数参数、请求分派形态（实例消费判定服务的方式）}
- 注册/校验/选择机制——corearch 引导时选实例
- 注册契约 = 内核与实例的唯一耦合面——新范式实例 = 新注册，不碰内核（规则封闭对象开放）

**核心不包含**：任何机器编码知识（寄存器名/帧/ABI/ELF）、任何调度/执行序知识（执行者才需要调度——验证器消费不需要）、op 字典语义解释、HIT 表概念（表 = 实例数据形态，非内核概念——边界 spec C4 已定位表为实例数据载体）。

### 1.2 实例层（每范式/机定制）

实例 = 该范式/机器把语义对象变成自己编码的**全部定制内容**——无跨范式共性，不强建通用翻译层：

**x86 实例组成**（从现 corearch 模块归位，§2）：
1. **调度重建**（v7 设计 §3 投影契约）：图载体 → 线性调度（文件序合法化 + REG 展开）——只有执行型实例需要；合法性校验（沿边约束）在实例内（内核不做调度承诺）
2. **lower/发射翻译**：语义对象/调度 → x86 编码（现 instr.cr 发射 + lower_to_core 的翻译逻辑下放——其泄漏面（帧/ABI/调用）在实例内**不再叫泄漏**：实例 = 经典绑定合法域）
3. **实例算法族**：帧布局（prologue/epilogue/帧公式）、调用序列（参数拷贝/返回协议）、tag/2L 编码选择、寄存器物理分配（CAG）——按边界 C2/C3：映射参数实例（推广 regalloc-cache-mapping 先例，同族必同类）
4. **实例数据**：HIT 表/模板/投影条目（M1/M2 资产 = 实例数据机制；字节层数据化 = x86 实例的内部优化，判据 = 行为等价/投影正确性——C4 裁决）
5. 运行时/ELF/链接/syscall 输出面（编码层合法内容）

**x86 实例与内核的接口**：实例向内核注册（资源域 = 寄存器/槽的代数）→ 内核判定（共存/互斥/驱逐写回）→ 判定结果（home 分配等）回传实例 → 实例完成物理编码。语义对象流 = 内核输出、实例输入。

## 2. 现 corearch 模块归属裁决表

| 模块（现） | 现状职责 | 裁决 |
|---|---|---|
| ccr_io.cr loader 侧（load_ccr/段表/校验/ENT parse） | 文件 → 内存指令流 + ENT 校验 | **内核**（语义对象模型——v7 后对象 = 边/条目/区域） |
| ccr_io.cr ENT/区间校验 + REG root span 守卫 | 输入契约守卫 | **内核** |
| regalloc.cr compute_live_ranges/compute_entries | 存在区间/版本推导 | **内核**（判定引擎——v6 §4.1 规则 = 语义侧） |
| regalloc.cr entries_coexist/判定四条 | 共存/互斥/驱逐/失效 | **内核**（引擎族核心——参数化资源域后实例复用） |
| regalloc.cr CAG alloc_registers/物理分配 | 寄存器物理分配 | **x86 实例**（实例算法——寄存器 = x86 资源域） |
| regalloc.cr verify/注入钩子 | 判定自检/测试通道 | 判定部分 = 内核、分配部分 = 实例（随拆分） |
| dataflow 概念（corearch 侧无图——重建线性） | — | 实例调度重建（v7 §3——输入图载体的重建方 = x86 实例） |
| instr.cr emit_instr 发射 | 线性指令 → x86 字节 | **x86 实例**（lower/翻译——泄漏面在实例内合法化） |
| instr.cr 帧/ABI/调用/ret_patch 序列（R1-R12 面） | 实例算法硬编码 | **x86 实例**——按 C2/C3 参数化为实例算法（数据 + 序列函数） |
| elf.cr/ld.cr/resolve.cr | ELF/链接/回填 | **x86 实例**（编码层输出面） |
| HIT hit.cr/表/模板解释器/注入通道/lower_to_core | 表驱动编码 | **x86 实例**（实例数据机制——表 = x86 实例的编码数据载体） |
| corearch.cr 编排/flag 分派 | 引导/测试通道 | **内核引导 + 实例注册**（flag = 实例选择参数） |
| MW tag 语义 vs 编码 | 耦合在帧/op 面 | 语义（int 无上限/2L 值域） = 格/图层（文件）；编码 = x86 实例算法 |
| v7 EDG/ENT 消费 | （v7 后新增） | 语义对象 = 内核；EDG 的调度消费 = x86 实例 |

**拆分原则**：语义侧（存在/区间/共存/驱逐/写回/互斥——不读值内容、不知资源名） → 内核；机器侧（物理资源/编码/布局/协议） → 实例。含糊处按 G3-2 先例类推（对缓存语义的机器侧资源决策 = 实例算法；对条目的语义判定 = 内核）。

## 3. 演进序（蓝图裁决——实施另立）

1. **v7 实施**（计划 d76d14c3 已就绪）：图载体落盘 + loader 双端改——内核输入契约的前提。先行理由：内核对象模型的数据源 = v7 文件；ENT/EDG 不落盘则内核无对象可管
2. **内核抽取**：loader → 语义对象模型 + 判定引擎从 regalloc 拆出（compute_entries/live_ranges/共存/判定四条入内核；CAG 留实例）——**行为判据**：抽取中每步回归绿（判定语义不动只搬家——regalloc 移后端先例同款流程）；内核接口 = 注册契约最小面先立
3. **x86 实例化**（= M2 复启的接续形态）：实例边界内的数据化/参数化（帧/ABI/调用序列/tag 编码 → 实例算法 + HIT 表数据化推进）——判据按边界 C4 重定（行为等价/投影正确性，非逐字节复刻）；M2 挂起资产的承接点
4. **第二范式/非经典实例验证**（远期）：注册契约的实证——范式 B 实例 = 新注册 + 新算法数据，零内核改动（规则封闭的验收）

**时机注记**：步骤 1（v7）与步骤 2-3（重写）可分可合——v7 的 loader 改动若按内核对象模型的形状做（loader 产出语义对象而非线性流假设），可避免二次重构（实施计划的接缝优化项）。

## 4. 风险与挂账

- **内核抽取最大风险 = regalloc 拆分的行为零变化**：判定四条语义不动只搬家——判据 = 每步回归绿（O2 分配 + verify 通道先例）；拆分时禁止顺手改语义
- **调度重建归属**：内核不做调度承诺（语义消费不需要）——若未来验证器消费发现需要调度无关的图接口 = 语义对象模型的扩展（对象 API 先立最小面）
- **HIT 表定位**：表 = x86 实例数据形态——蓝图不承诺其他范式实例用表（换表即换平台表述校准为：换实例即换平台；表 = x86 实例的数据化方式）
- **op 字典**：内核不解释 → 验证器（语义消费通道）需要字典语义 = 字典语义文档化/形式化的独立工作（语义革命级——v7 设计 §2.2 显式遗留的后续）
- **M2 资产**（Task 0/1/2 完成品）：实例数据机制的既有实现——实例化推进（步骤 3）时按 C4 判据承接，不报废
- 本设计不包含：任务分解（实施另立）、x86 实例内部的具体数据/算法设计（实例化推进时按 C2/C3 出）
