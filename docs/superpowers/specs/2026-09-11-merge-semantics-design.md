## 0. 范围与裁决

### 0.1 论题

> **汇合点的语义必须由图决定，不得由调度决定。**
> 物理到达顺序可以决定"谁来处理"，但只有两种情形合法：① 图中已**证明**该影响不可观测（`merge_deterministic`）；② 图中已**显式声明**该影响（`race` / `select_any`）。二者之外 = 隐式竞争 = 拒绝编译。

本 spec 处理的是**执行模型层**的语义：汇合（merge）这个图事件。它不碰属性轴与义务机制本身的定义（S-A），不碰报告面的 CLI 与输出契约（S-D）——只给二者的**接口需求**（§5）。

**现状缺陷（用户 2026-09-11 裁决 = 待修）**：三处文档把 `select` 的语义写成「**最早到达的令牌**」（`docs/dataflow-design.md:102`、`docs/project-book.md:241`；`docs/dataflow-design.md:61-74` 的 load_balancer 例是该语义的实例）。这是**把物理调度顺序泄进语义**——而 `docs/execution-model.md:15` 同时宣称「DAG ⟹ 依赖偏序——无反馈，确定性」。两句互相拆台：要么 DAG 的确定性是假的（汇合点可以由物理顺序注值），要么 select 的语义是错的。按共享契约 §1.4 的「不确定性 = 显式请求」，**后者是错的那一个**。

### 0.2 覆盖 / 不覆盖

| | 范围 |
|---|---|
| **覆盖** | 四形态的**图级**定义与判定判据、每形态的义务落档、观测可见性；物理⇏语义的降级义务（发射层/调度器/求值顺序三检查面）；`select` 现状的重定、兼容窗口与文档同步清单；与 state edges / region / 自动并发的接口；给 S-A / S-D 的接口需求；正负控判据 |
| **不覆盖** | 属性轴与四档的定义（**S-A**）；`core analyze --determinism` 的 CLI/输出契约与 provenance 链的呈现格式（**S-D**，本 spec 只给链的**形状要求**）；成本模型与并行粒度启发式（**S-C**）；调度器实现（部署配置面，本 spec 只给"不得引入"的判据）；内存模型的数据竞争（不同问题——本族管可观测语义序，不管字节级竞争）；`recv` / channel 的语法面 |

### 0.3 裁决清单（本族的定案）

- **D-1 汇合点 = 图对象，四形态 = 图标注**。汇合点 M 定义为「**入数据边 ≥ 2** 的 DFNode」（`g_df_edges` kind=0；state 边 kind=1 另计——见 §4.1）。四形态**不是四个关键字**，而是 `determinism` 轴族（契约 §1.4）上的**开放标注**：`deterministic` / `ordered(src)` / `race(k)` / `any`。**命名对照**（本文两套记法同义，避免误读为八种东西）：形态名 `merge_deterministic` ↔ 标注名 `deterministic`；`merge_ordered` ↔ `ordered(src)`；`race` ↔ `race(k)`；`select_any` ↔ `any`。形态名用于论述，标注名是图上实际标注的拼写。不加关键字、不改 Graph 本体（承契约 §1.2-1「属性不升格为语言 primitive」、定案 1「类型 = 图标注」）。标注的载体与注册通道归 S-A；本 spec 只给**语义内容**与**必填字段**（§5.1）。
- **D-2 四形态的区分量 = 观测结果对到达序的函数依赖**。设 M 的语义函数 `F_M(c, π) → obs`，其中 `c` = 输入值多重集、`π` = 物理到达序（**π 不是图对象**，这是本 spec 一切定义的前提）：恒定 → `deterministic`；仅经显式顺序源 σ 依赖 π → `ordered`；依赖但**声明允许** → `race`；只声明对**来源身份**不敏感 → `any`。未证明且未标注 → **reject**（唯一执法点）。
- **D-3 观测（observation）面必须先定义，否则四形态不可判定**。`obs(·)` = ① 值输出（数据边出边上的值）；② 效应（`STORE` / 通道 send / extern 调用 / `YIELD`）；③ 控制去向（后续 region 归属，SG_IF/SG_LOOP 的走向）。**唯一不在观测面内的量 = 到达位置 / 到达时刻 / 到达顺序本身**——这就是本族的去物理化操作。任何把物理序升格为可观测值的图结构（读时钟、自旋计数、原子序号、优先级抢占痕迹）都是 π 的**代理量**，见 §2.2。
- **D-4 `race` 的结果集语义 = 只承诺集合，不承诺元素**。`Obs(M) ≜ { obs(F_M(c, π)) : π ∈ Π }`——**集合本身确定**，唯一的不确定是"集合内选哪个"。声明的附加义务：**集合可枚举**（或显式声明不可枚举 → 高安全模式 reject）。
- **D-5 `merge_ordered` 的顺序源白名单（首版）= state 边链 ∪ region 迭代序**。两者都是**图上显式对象**。**白名单外的一切"顺序"都不是顺序源**：物理时间戳、`sleep`、线程 id、就绪队列位置、声明式优先级——它们读的是 π 的代理，落 `race` 或 reject（见 §1.2 否定例）。显式序号域（用户标注 order key）是否纳入 = **开放问题 Q2**（【待论证】）。
- **D-6 `select` 保留关键字拼写，语义重定为 `race(1)` 的糖衣**。存量无实现（§3.1 已核实），因此迁移是**文档语义迁移**而非代码迁移。未标注的 `select` 默认结论 = 「未证明未标注 → reject」；兼容窗口内降为 warning + 自动标注 `race(1)`（§3.3）。
- **D-7 自动并发只搬运已证明的 `merge_deterministic`**（承 TODO 2026-08-30 与契约 §1.4）。搬运 = lowering，须满足 §2 的全部三条检查面。`merge_ordered` 的"保序并行" = **开放问题 Q5**（【待论证】）。
- **D-8 本族**没有** enforce 通道（定稿结论）**。确定性**不可能**运行时强制：事后检测到"结果不同"已经太晚，事前强制 = 换实现 = 改语义形态（那是 `ordered` 的事，需要用户同意）。因此本族在四档上只落 `prove` / `proof-required` / `reject`——**enforce 档空白**。**S-A §1.9 已按此裁决**：族级 policy 取 `allow_enforce=false`（隐式竞争因此固定落 ④ reject，无需改决策树）。**不得**用"插入运行时检查"充数（§5.1-(2)）。

## 1. 四形态语义（图级定义）

### 1.0 共同图模型与判定问题

| 记号 | 含义 | 是否是图对象 |
|---|---|---|
| `M` | 汇合点：入数据边 ≥ 2 的 DFNode | 是（`g_df_nodes`） |
| `c` | M 的输入值多重集（无视顺序） | 否（运行时值） |
| `π ∈ Π(M)` | M 的输入令牌的**物理到达排列** | **否**——不是图对象，不可读、不可命名 |
| `obs(·)` | 观测（D-3）：值 + 效应 + 控制去向 | 是（出边 + state 边 + region 归属） |
| `F_M(c, π)` | M 的语义函数（图 + 输入 → 观测） | 是（图决定其形状） |
| `σ` | 显式顺序源：图上的定序对象 | 是（state 边链 / region 迭代序） |

**判定问题**：`∀ π, π' ∈ Π(M)，obs(F_M(c, π)) = obs(F_M(c, π'))` 是否成立？

四个形态 = 对这个问题四种**语义承诺**，其区别只在「F 对 π 的依赖被如何处置」：

| 形态 | 承诺 |
|---|---|
| `merge_deterministic` | **恒定**：F 与 π 无关 |
| `merge_ordered` | **投影依赖**：`σ(π) = σ(π') ⟹ F(c,π) = F(c,π')`，且 σ 由**图**决定 |
| `race(k)` | **集合确定**：`Obs(M)` 是确定的有限集，元素由实现自由选 |
| `select_any` | **身份不敏感**：F 只依赖"有输入"这件事，不依赖"从哪条边来" |

这四行是**语义**，不是实现建议；下文的图表示 / 判据 / 落档 / 可见性全部从这四行导出。

---

### 1.1 `merge_deterministic`

**图表示**：M 携带 `deterministic` 标注（或因无标注而被分析器**证明**后赋予）。要求 M 的输入集合**闭合**：所有可能到达 M 的输入边在图上是可枚举的（无"运行时新连的边"——动态图重连须先经 §2 判据）。

**判定判据（三合取）**：

| # | 判据 | 判定面 | 手段 |
|---|---|---|---|
| (a) | **无 state 边入边**：M 不在副作用链上（kind=1 入边计数 = 0） | 结构 | 分析器自动（O(边数)） |
| (b) | **无 π 代理量**：从 M 沿 def-use + state 链可达的节点中，不存在读取到达位置/时刻/顺序的量（`now_monotonic`、自旋计数、原子序号、线程 id、就绪队列位置），也不存在以"到达次数/第几个到达"为条件的 BRANCH | 结构 | 分析器自动（**π 不可命名 ⇒ 一切"序依赖"都必然经由代理量**，故本条可判定） |
| (c) | **组合函数序无关**：M 的计算在输入多重集上良定义——组合算子满足交换 ∧ 结合（+ 幂等，若存在重复到达路径） | 值 | 引擎判定（R2：类型项/形状项）；证不出 → 用户给证明 |

**判据 (b) 的可判定性论证（本族的关键结构事实）**：π 不是图对象，图上没有"到达序号"这种输入端口。因此"依赖物理序"在实践中**只能**通过代理量实现，而代理量是图上的普通节点、可被扫描。这使「隐式竞争」成为**可判定**的（而非传统自动并行化那样靠依赖猜测——TODO 2026-08-30 记的同一论据）。

**判据 (a) 的可靠性前提（已核实，硬性——假阴性风险）**：判据 (a)「无 state 边入边」只在 **state 链覆盖全部可观测效应**时才是充分的；否则 (a) 会**假阴性**——把实际有序依赖的汇合误判为 `deterministic`。**今日不满足该前提**：`df_connect_state`（`dataflow.cr:160-177`）的分类表 = `IR_STORE` / `IR_STORE_FIELD` / `IR_STORE_INDEX` / `IR_STORE_INDEX_VAR` / `IR_CALL`（函数名解析不出或非纯则计副作用），**不含 `IR_CALL_EXTERN`（`ast.cr:572` = 45）**；且纯度标注今日**乐观**（`checker.cr:1103`「all functions are pure」/ `checker.cr:1138`「extern functions are pure」）。⇒ **外部效应今日无保证的序通道**（与本族同源的问题，**S-B5 §0 已点名同一事实**，其处置面在那边）。
**本 spec 对 (a) 的实施要求（保守判定，不要求改链）**：在链覆盖修复（或 S-B5 的切片面）落地前，(a) 的实施必须**降级**为「显式效应清单检查」——`IR_CALL_EXTERN` 与一切"纯度不可判"的调用**一律视为可观测效应**，其下游汇合**不得**仅凭 (a) 判为 `deterministic`（须另有定序通道，否则落 ③/④）。方向选择理由：**误判 deterministic 是不可修复的语义错误**（报告面事后看不见），而保守只损失优化面（由报告面呈现，可查可回收）。

**义务落档**：(a)(b) 自动 → 贡献零成本；(c) 自动证不出 → **proof-required**（用户提供证明/契约）。**不落 enforce**（D-8）。

**观测可见性**：完全确定。**不得出现在 S-D 的"不确定"列表**（可出现在"已证明"列表）——这条是 §1.5 证明优先规则的产物。

### 1.2 `merge_ordered`

**图表示**：M 携带 `ordered(src)` 标注，`src ∈ {state-chain, region-order}`（D-5 白名单）；且图上存在从 `src` 到 M 的**每条**入边的定序见证（witness）。标注必填字段 = src 的类型 + 见证的边集。

**判定判据**：

1. **溯源**：M 的每条入数据边可溯源到一个顺序源（state 边链的链序，或 region 迭代序 `nstart → … → exit`）；
2. **全序**：src 在 M 的输入集合上是**全序**（任意两条输入可比较；不冲突、不并列）；并列时不得静默 tie-break（那会把 π 从后门放回来）；
3. **非代理**：src 是图上显式对象，**不是** π 的代理（即 §1.1(b) 的反面检查——src 自身不得含 π 代理量）。

**否定例表（必须写清，否则"优先级 select"会被误当 ordered）**：

| 候选 | 为什么不是顺序源 |
|---|---|
| 物理时间戳 / `sleep` 时长 | 读物理时间 ⇒ π 的代理 |
| 线程 id / 就绪队列位置 | 调度器内部状态 ⇒ π 的代理 |
| **声明式优先级**（"req 优先于 signal"） | 只决定**谁赢在同时就绪时**；而"同时就绪"本身由物理决定 ⇒ 仍是 π 的函数。⇒ 落 `race`（可选：优先级作为 **tie-break 规则**记录进报告，但不消除不确定性） |
| 通道 FIFO 序 | **半合法**：同一 channel 上的 send 序是图上的（生产者之间的 state 边链），跨 channel 则不是。⇒ 只在"每个输入边各自有 state 链"时可作 src |

**义务落档**：**prove**（src 全序 + F 被唯一确定）；src 存在但覆盖不全 → **proof-required**（补顺序源或补证明）。

**观测可见性**：确定。不进不确定列表；可进"已证明（顺序源：state 边 / region 序）"列表。

### 1.3 `race`

**图表示**：M 携带 `race(k)` 标注（k = 胜者数；缺省 k=1）。**必须显式**——无标注的竞争 = 隐式竞争 = reject（§3.3 窗口内降为 warning）。

**判定判据**：`Obs(M) = { obs(F_M(c, π)) : π ∈ Π }` 良定义且**可枚举**（基数已知或可静态上界），或显式声明为不可枚举（→ 高安全模式 reject）。

**义务落档**：**① prove + 报告义务**（S-A §1.9 已裁决：显式请求 = 义务已被「程序说的是它想说的」处置，**不新增第五档**）+ **报告面强制登记**（S-D）。**prove 的证明内容不是空话**——须证明「该汇合点是此处**唯一**的不确定源」（声明不得成为隐藏相邻不确定性的挡箭牌）；证明范围的宽窄 = **开放问题 Q1**。

**观测可见性**：报告面**必须**列出：① race 点 id；② 输入边集；③ k；④ 结果集 `Obs(M)` 的基数上界（或"不可枚举"标记）；⑤ provenance 链（§5.2）。
**禁止**：分支体把"我是第一个到达"当作可读事实（例如以到达序索引写共享输出而不经 witness 通道）。胜者**身份**能否作为显式出参暴露 = **开放问题 Q4**（【待论证】）——它是 `select` 现有分支体写法（`req = recv => …` 用了 `req`）能否平迁的关键。

**race 不豁免确定性**：它承诺的是"**集合**确定"。把 race 读成"此处随便"是误读——`Obs(M)` 本身是程序语义的一部分，报告面要能把它列出来。

### 1.4 `select_any`

**图表示**：M 携带 `any` 标注。语义 = `obs` 对**来源身份**不敏感：分支体的观测不依赖"哪个输入先到/到了哪个"。

**判定判据（两条路径）**：

| 路径 | 条件 | 结果 |
|---|---|---|
| (i) **等价升级** | 各分支体**观测等价**（值 + 效应 + 控制去向三项等价，由引擎的等价判定给出） | 升级为 `merge_deterministic` → **prove**，零成本 |
| (ii) 默认 | 不可证等价 | 与 `race` 同：**显式不确定** + 报告面；`Obs(M) = { 各分支体的观测 }`（有限，可枚举） |

**路径 (i) 的地位（区分设计与待论证）**：【设计已定】等价即确定的推理是直接的（分支选谁都一样 ⇒ obs 恒定）。【待论证】"观测等价"的**判定能力**——R2 引擎目前判定 `ty_sub`/`ty_equiv` 等类型项，**尚无效应等价（effect equivalence）判定器**。因此 (i) 是目标形态，落地依赖引擎的效应判定扩展；在此期间 (ii) 是实际路径。**不得**把 (i) 呈现为已可用。

**义务落档**：(i) **prove**（确定性，零成本）；(ii) **① prove + 报告义务**（同 race：证明内容 = 该点是此处唯一不确定源）。

**观测可见性**：(i) 不进报告；(ii) 进报告，附"来源身份不敏感"说明。

### 1.5 判定序（本族的决策过程）

给定 M，按下序判定，**先到先得**：

```
1. 结构预筛：无 state 边入边 ∧ 无 π 代理量 ∧ 输入集闭合    → 候选 deterministic
2. 引擎判定组合函数序无关（交换 ∧ 结合）                   → merge_deterministic   [prove]
3. 顺序源 σ 在白名单内 ∧ 对 M 的输入全序 ∧ src 非代理       → merge_ordered         [prove]
4. 顺序源存在但覆盖不全                                    → proof-required（补证明/补顺序源）
5. 有 race/any 显式标注                                    → ① prove（声明与实现一致）+ 报告义务（+ 可枚举义务）
6. 其余（未证明 ∧ 未标注）                                 → reject  ← 唯一执法点
```

**证明优先于声明（冲突规则）**：若第 2 步已证明序无关，则即使 M 带 `race`/`any` 标注，**报告面按实际分类**（= 确定），标注降级为**冗余声明**诊断（warning，非错误）。理由：报告必须显示程序**实际**的不确定性，而不是用户**声明**的不确定性——否则 `race` 会成为"掩盖本来可证的程序"的通道，与「不确定性 = 显式请求」的意图相反（请求要显式，但不得伪装）。

## 2. 物理 ⇏ 语义：降级义务

### 2.1 「引入不确定性」的判据（定义）

> **引入**：存在同一张图 G、同一输入 c 的两次执行 e₁, e₂，使 `obs(G, c, e₁) ≠ obs(G, c, e₂)`，而 `G` 上**没有**任何节点声明 `race`/`any`，**且**差异可归因于 {发射层, 调度器, 求值顺序} 三个物理面之一。

即：`∀G, c：obs(G,c,·)` 恒定，除非 G 上有对应声明。**违反 = reject**（编译错误，属"物理⇏语义被破坏"）；无法判定 → proof-required。

**本节论题句（写进实现规则）**：被限制的**不是调度器的自由度**，而是「自由度泄漏进 `obs`」。调度器可以任意选择（性能面），只要选择不影响观测。

### 2.2 三个检查面

| 面 | 检查内容 | 例子（合法 / 非法） |
|---|---|---|
| **发射层（lowering）** | IR → 机器码 / 表条目的 lowering 不得引入序依赖 | 合法：`merge_deterministic` 的 n 输入加法降低为"按寄存器分配顺序发射的链"——加法可结合，序不影响值。**非法**：把非结合算子（浮点加/乘、饱和加法、定长截断/溢出包裹、多字 tag/2L 编码下的**饱和**路径）降低为序敏感实现；或把"先到先累加、超界即截断"当作确定性汇合 |
| **调度器** | 就绪队列顺序（round-robin / work-stealing）不得成为语义输入 | 选择函数只允许读**图上声明的顺序源**（state 边就绪标记、region 迭代指针）；**禁止**用时间片计数 / 线程 id 作 tie-break 并让该 tie-break 影响 `obs` |
| **求值顺序（编译器内部）** | pass 重排 / 内联 / CSE / 寄存器分配不得改变 merge 点的输入到达集合，或引入序依赖 | 特别：LICM / 惰性下沉**不得**把带 state 边的节点跨越 merge 点移动；CSE 合并两个 race 点会改变 `Obs(M)` 基数 ⇒ 须检查 |

**这条给编译器 pass 的可陈述不变量**：每个变换都保 `obs`。原文（TODO / pass 文档）里"凭感觉安全"的表述，应由本判据替代。

### 2.3 与「部署配置不改语义」的关系

`docs/execution-model.md:19`「执行方式（串行/并行/调度策略）由部署配置决定，图语义不变」——本节的判据正是这句话的**可检查形式**：部署配置切换调度策略后 `obs` 必须不变（除已声明点）。因此本族**加强**而非削弱该原则：把"图语义不变"从口号变成合规条件。

### 3.2 迁移目标

`select { p = recv => body }` 重定为：**多输入汇合 + 内容相关分派**，其图级默认 = **未标注**。语义不再是"最早到达"——"最早"是 `race(1)` 的**实现选择**，不是**语义承诺**。

| 情形 | 判定形态 | 落档 |
|---|---|---|
| 分支体观测等价（可证） | `select_any` → 升级 `deterministic` | prove |
| 到达顺序由 state 边 / region 序固定 | `merge_ordered` | prove |
| 分支体不等价 ∧ 无顺序源 ∧ 有显式标注 | `race(1)`（+ `any` 若身份不可观测） | ① prove + 报告义务 |
| 分支体不等价 ∧ 无顺序源 ∧ 无标注 | **reject**（窗口内：warning + 自动 `race(1)`） | reject / 窗口内警告 |

### 3.3 兼容窗口

| 阶段 | `select` 行为 | 诊断 |
|---|---|---|
| **W0**（现状 → 本 spec 生效前） | 文档语义 = 最早到达（无实现） | — |
| **W1**（窗口期） | 未标注 `select` **接受**，自动按 `race(1)` 处理 | **warning**：「隐式竞争：`select` 隐式请求不确定性；请显式声明 `race(k)` / `any`，或提供确定性证明（顺序源 / 分支等价）」+ 报告面登记 |
| **W2**（窗口关闭） | 未标注 `select` = **reject** | error + 指向三形态修复通道 |

- **窗口触发条件** = 首个 `select` 实现落地（当前无实现 ⇒ 窗口尚未开始，W0）。
- **窗口长度** = 由用户裁决（**开放问题 Q3**）。
- **关键区分**：窗口内容是「**接受并标注**」，**不是**「保留旧语义」。旧语义（最早到达）在**任何阶段**都不再是语义——它降格为 `race(1)` 的一种实现选择。这条必须写进诊断文案：**不承诺"最早到达"**，因为承诺它等于承诺调度器行为。

**裁决：保留拼写、重定语义。**

## 4. 与既有机制的接口

### 4.1 state edges（`dataflow.cr`，kind=1）

- **双重角色**：① `merge_ordered` 的**第一顺序源**（副作用链的链序 = 图上全序）；② `merge_deterministic` 判据 (a) 的**排除面**（有 state 边入边 ⇒ 不是候选确定）。
- **方向性提醒（易错）**：state 边保证的是**序**，不是**结果与序无关**。两条边的作用方向相反——`ordered` 用序定结果，`deterministic` 用"无序可依赖"绕过序。实现时不得把"有 state 边"直接判成"确定"或"不确定"，须按 §1.5 走判定序。
- 现有构件：`df_add_edge_kind`（`:136`）、`g_last_state_node` 副作用链（`:174`）、loop exit 终止依赖（`:93`）、`ESZ_DFEDGE` = 32B（`dyn_arr.cr:102`，kind 字段已在）。
- **`select` 不是顺序源**（承接 S-A §1.9 硬约束，§5.1-(5)）：汇合点的定序**只能**来自 state 边链或 region 迭代序；`select` 的"胜出边"是 `race` 的结果，**不得**回填为顺序源用于 prove（否则把"最早到达"从后门固化为证明前提）。
- **外部效应的序缺口（已核实，与 S-B5 同源）**：`IR_CALL_EXTERN`（`ast.cr:572` = 45）不在 `df_connect_state` 的分类表内 ⇒ **外部调用的效应不进 state 链**。两个后果：① `merge_ordered(state-chain)` 无法为 extern 效应定序；② 判据 (a) 出现**假阴性**通道（explicit effect 无入边却被判"无副作用"）。**处置见 §1.1 的保守判定要求**——本 spec 不要求在 S-E 内修链（属 S-B5 切片面 / 独立修复），只要求分析器在链未覆盖时**取保守方向**。

### 4.2 region（SG_* 与 `g_df_node_region`）

- **第二顺序源**：SG_LOOP / SG_FOR 的迭代序（`nstart → … → exit`）是图上全序。
- **SG_FLOW** = 动态汇合的容器（跨执行流汇合的默认 region）。
- **SG_IF** = merge 后的**控制去向**——是观测面的一部分（D-3 第 ③ 项），故 `merge_deterministic` 的判据必须覆盖"汇合后的分支走向是否稳定"。
- **跨 region 汇合**（汇合点在父 region、输入来自两个子 region）是典型候选；判定用 `g_df_node_region` 归属 + parent 链 O(1) 查询（照 region-cfg §6 的迁移方式）。

### 4.3 自动并发（`TODO.md` 2026-08-30 记）

- **硬性接口（D-7）**：自动并行**只搬运已证明的 `merge_deterministic`**。搬运 = 一次 lowering（引入 `IR_SPAWN` + 汇合），因此**必须**满足 §2 的三个检查面；违反 ⇒ 该次分派非法。
- **与 TODO 原文的衔接**：TODO 说"无依赖 region → 自动分派"（"可判定"而非"依赖猜测"）。本 spec 补上的是**第二道门槛**：可判定性给的是"能并行"，确定性判定给的是"并行后语义不变"。**两道都过才搬运**。
- **merge_ordered 的 region 能否并行**：**保序并行**（pipeline）**待论证**（Q5）——若并行 lowering 保证 state 边序 = 观测序，则属 §2 的可证情形；否则不搬运。
- **与 R-HLS 的差异**（TODO 已引）：RVSDG 动态调度暴露图内并行面；本 spec 新增"搬运前必须证明序无关"的门槛——**这是 Core 与常规自动并行化的分野**，也是 40 年自动并行化失败史的正面回应。
- **成本模型**（调度开销 vs 收益）= **S-C 范围**，本 spec 不碰。

- 汇合点识别（入度 ≥ 2）、四形态标注、顺序源见证**全部落在现有 DFNode/DFEdge 结构上**：只加标注（`determinism` 轴族，S-A 的机制），**不加新段/新字段**。若实现上必须有索引，用 `g_df_node_region` 同款的并行数组（跟随 `g_df_node_cap` 增长的旁路数组），作为实现选项，实施批定。

### 5.1 给 S-A（轴 / 四档 / 义务机制）

本 spec **不定义**轴与四档，只给这三项输入：

| `merge_ordered` | **① prove** / **③ proof-required** | 顺序源全序可证 / 覆盖不全 |

| `select_any`（不可证等价） | 同 `race` | |
| `select_any`（可证等价）→ deterministic | **① prove** | 依赖引擎的效应等价判定（【待论证】，§1.4） |
| 未证明 ∧ 未标注（隐式竞争） | **④ reject** | 唯一执法点；族级 policy `allow_enforce=false` + `strict=true`，决策树固定落 ④（S-A §1.9/§2.2） |

**(2) enforce 档空白（D-8）**：本族**没有** enforce 通道。确定性不可运行时强制（事后太晚 / 事前=改语义）。S-A §1.9 已按此给族级 policy 取 `allow_enforce=false`——**本项已闭合**，不再是待裁决项。**不得**用"插入运行时检查/比较器"充数（那是把义务做成 lint，违反契约 §1.2-2 的精神）。

**(3) 标注的语义内容与必填字段**（载体/语法由 S-A 定）：

| 形态 | 必填字段 |
|---|---|
| `deterministic` | 证明引用（结构性 (a)(b) 自动；值的 (c) 由用户提供时记录其引用） |
| `ordered(src)` | src 类型（`state-chain` / `region-order`）+ 定序见证（边集） |
| `race(k)` | k + `Obs(M)` 基数上界（或 `non-enumerable` 标记） |
| `any` | 无（+ 若走了 §1.4(i) 的等价升级，记录引擎判定的引用） |

**(4) π 不可命名（本族的结构性前提，建议 S-A 纳入机制约束）**：图上**不提供**"到达序号"这类输入端口。这不是实现约定，是**语义主张**——它使"隐式竞争"可判定（§1.1 判据 (b) 的论证）。

**(5) 承接 S-A §1.9 的硬约束**：其末条要求「在 S-E 完成 `select` 重定之前，`select` **不得**被当作『显式顺序源』用于 prove——否则等于把现有语义缺陷固化为证明前提」。本文**满足并加强了**该约束：
- §3.2 已把 `select` 重定完成（默认形态 = 未标注，判定走 §1.5 决策序）；
- §1.2 否定例**永久排除** `select` 与优先级作顺序源（不只是迁移期）——`select` 语义本身**不含**任何定序承诺，重定后亦然；
- 唯一合法的定序来自 D-5 白名单（state 边 / region 序），与 `select` 无关。

### 5.2 给 S-D（`core analyze --determinism` 报告面）

**provenance 链的形状要求**（本 spec 只给形状，格式归 S-D）：

```
来源节点 ──(传播)──▶ 汇合点 ──(传播)──▶ 观测点
boundary #27  →  parser  →  branch  →  output
   ↑                ↑           ↑          ↑
 外部输入面    数据边/state边   race/any    ACTIVE_OP
 (D_external)   (图传播)        标注点    (可观测)
```

即：每条不确定性的报告项 = **从源到可观测点的一条链**，链上必须标出**汇合点**（不确定性被引入/放行的位置）与**形态**。要点：

1. **汇合点是链上的检查点**，不是链的起点——起点是外部来源（boundary），终点是可观测效应。同一汇合点可出现在多条链上，报告应能按汇合点聚合。
2. **已证明的汇合不得出现在不确定列表**（§1.5 证明优先）；"冗余声明"（标了 `race` 但已证明确定）单独列一类，供用户清理。
3. 本族**必须**提供的字段（最小面）：形态 / 汇合点 id / 输入边集 / 顺序源（`ordered`）/ k 与 `Obs(M)` 基数界（`race`）/ 见证引用 / 分类（已证明 · 已声明 · 冗余声明 · 拒绝）。
4. `boundary #27` 式的**外部输入面**（`D_external` 轴）由 S-D/S-A 定义，本 spec 只在链中引用它，不定义它。

## 6. 判据（验收）

### 6.1 正控

| # | 场景 | 期望 |
|---|---|---|
| P1 | 两个无依赖 region（各自纯计算）汇合到可交换组合（整数加法） | `analyze --determinism` 报**已证明**，零诊断 |
| P2 | 汇合的两条入边在同一 state 边链上（副作用序固定） | 报**已证明（顺序源：state 边）** |
| P3 | `select` 各分支体观测等价 | 升级 `merge_deterministic`，**prove**，不进不确定列表 |
| P4 | SG_LOOP 内两迭代产出的汇合（region 迭代序固定） | 报**已证明（顺序源：region 序）** |

### 6.2 负控

| # | 场景 | 期望 |
|---|---|---|
| N1 | **隐式竞争必须 reject**：两处 `go` 的输出汇合到同一消费点，组合**非**可交换（如字符串拼接顺序敏感）、无标注、无 state 边定序 | **error**，文案含三条修复通道（声明 `race` / 补顺序源 / 证等价） |
| N2 | `race(1)` 显式标注 | **进报告**：race 点 id、输入边集、k=1、`Obs(M)` 基数的界 |
| N3 | 标了 `race` 但分析器证明确定 | **冗余声明 warning**（非 error），报告列为"已证明" |
| N4 | 「优先级 select」（优先级 + 就绪竞速），无别的序 | **不得**判为 `merge_ordered`（白名单外，§1.2 否定例）→ 落 `race` 或 reject |
| N5 | **lowering 引入序**：把非结合组合（浮点加 / 饱和加 / 截断）的 `deterministic` 汇合降低为序敏感实现 | 须被捕获。判据 = 结构单测（降到序敏感发射模式即失败）**或**双调度对拍（同一图、两种调度、`obs` 不同即失败） |
| N6 | **判据 (a) 假阴性**：extern 调用（`IR_CALL_EXTERN`，不在 state 链上）下游的汇合 | **不得**仅凭"无 state 边入边"判为 `merge_deterministic`——须按 §1.1 的保守判定落 ③/④（除非另有定序通道）。**这是"宁可保守"的执法点**：误判确定 = 语义错误，且报告面看不见 |

### 6.3 判据的表述原则（**本族的方法论立场**）

- 一切判据表述为「**图 + 输入 → 观测**」，**不得**表述为"运行 N 次结果一致"——后者是**概率证据**，不是判据（承契约 §1.2-3「义务不静默」：判据不得靠采样）。
- N5 的"双调度对拍"是对**判据"的实证手段**（用于在实施早期捕获 §2 违规），**不是**验收判据本身。两者不得混同——这条要在实施批的测试设计里写明。

## 7. 不承诺

逐条对齐共享契约 §1.3 的三类不可消残留（本族落在哪里）：

1. **错误 specification**：本族证明的是"汇合与调度无关"，**不是**"用户的 `race` 声明是合理的"。`race(k)` 的内容（此处允许竞争是否满足需求）是**需求层**的事，语言只保证它被显式化并进报告。⇒ 本族不承诺"程序的所有不确定性都是可接受的"。
2. **恶意 / 失陷外部实体**：外部输入本身的不确定性（`D_external`）**不由本族消除**。本族承诺的是：外部不确定性**进入图之后**不得被放大为隐式竞争，也不得被悄然隐藏（必须出现在 provenance 链上，§5.2）。恶意来源可以通过 boundary 提供的时序影响**哪些** race 结果出现——本族不证明其结果集之外的任何事情。
3. **需求本身允许危险行为**：**并发竞争本身可能正是需求**（负载均衡器抢单、超时竞速、取消传播）。本族**不禁止竞争**，只要求它**显式**（`race`/`any` 声明 + 报告 + 可枚举义务）。与 §1.3 的对应：本族做的是"把能力与它的代价同时写进图"，而不是禁止能力。

**本族另外明确不承诺**：

- **不承诺"Core 程序无数据竞争"**——那是内存模型面（arena/region 隔离、借用检查）的事。本族只管**可观测语义序**，不管字节级并发访问。两者**不互相蕴含**（隔离的内存上仍可有汇合语义的不确定；反之亦然）。
- **不承诺 `race` 的结果集在跨机器 / 分布式执行下可枚举**——那是 `D_mapping`（跨机器语义确定性）面，与 S-C / S-D 的衔接点。**语义 ≥ 映射**：映射换而集合语义不变，但**集合的具体元素分布**是映射的事。
- **不承诺代价模型**（并行是否值得）= S-C。

## 8. 不做项（YAGNI）与开放问题

### 8.1 不做项

| 不做 | 理由 |
|---|---|
| 运行时确定性检查器 / 强制器 | D-8：确定性不可运行时强制；且会退化为 lint（契约 §1.2-2 禁止） |
| `select` 的语法实现、关键字表变更、`recv` 语法 | 本 spec 只定**语义**；语法实施属实施批（§3.4 清单） |
| 调度器改动 | §2 只给"不得引入"的判据；调度器实现属部署配置面 |
| 分布式 / 跨机器汇合的语义 | `D_mapping` 面，另议（§7） |
| `recv` / channel 的语法面重定 | 非汇合语义问题（channel FIFO 只在 §1.2 顺序源白名单里被引用） |
| 成本模型 / 并行粒度启发式 | S-C |
| 修改 `docs/dataflow-design.md` / `project-book.md` / `execution-model.md` | 属实施批（§3.4）；本 spec 只列清单 |
| 报告面 CLI / 输出格式 | S-D（本 spec 只给链的形状要求，§5.2） |

### 8.2 开放问题（供用户裁决，≤5）

- **Q1（`race` 声明的证明范围）**：S-A §1.9 已定 `race` 落 **① prove + 报告义务**，但"prove 什么"的**范围**需裁决：仅证明**汇合点本身**的不确定性被声明覆盖（局部，便宜，但相邻/下游的未声明不确定性可能借道通过），还是证明**到下一个已声明点或观测点**的整条路径（传递，严，成本高）。
  **本 spec 建议**：至少覆盖到观测点的路径（"声明不得成为邻居的挡箭牌"，§1.3）；纯局部证明作为性能优化选项登记。
- **Q2（顺序源白名单）**：`merge_ordered` 是否纳入**显式序号域**（用户/库标注 order key）？纳入 ⇒ 需要一种新的标注语法（与"不加关键字、属性不升格"的张力最小化方式是走 S-A 的标注通道而非新语法）；不纳入 ⇒ 首版只有 state 边 + region 序两个源，能覆盖的场景更窄但门槛更硬。
- **Q3（`select` 默认形态与窗口长度）**：未标注 `select` 的默认结论——严格（直接 reject）还是宽松（`race(1)` + 强制报告）？窗口 W1 的长度（按版本？按发布？按用户批准？）；W2 之后是否给"永久 lenient"模式？
- **Q4（race 的胜者可见性）**：是否允许 / 要求把"胜者身份"作为**显式出参**（witness）？**允许** ⇒ `select` 现有分支体写法（`req = recv => 用 req`）可平迁（身份经 witness 通道 = 图上的显式值，不是 π 代理）；**不允许** ⇒ 所有 `select` 分支体必须改造为"不看来源"，表达力显著下降（load_balancer 例作废）。**本 spec 建议允许但要求 witness 显式化**（把"哪条边赢了"从隐含变成图上的一条值边）。
- **Q5（自动并发的搬运面）**：`merge_ordered` 的**保序并行**（pipeline）是否纳入可搬运集合（作为 §2 的可证情形）？纳入 ⇒ 自动并发的适用面显著扩大（顺序源固定 ⇒ 语义不变），但 lowering 须证明"state 边序 = 观测序"，成本更高；不纳入 ⇒ 首版只搬运 `merge_deterministic`，最保守。

## 附录 B：术语速查（本族新增，不覆盖契约术语）

| 术语 | 定义 |
|---|---|
| **汇合点**（merge point） | 入数据边 ≥ 2 的 DFNode |
| **到达序** π | 输入令牌的物理到达排列；**不是图对象**，不可命名 |
| **π 代理量** | 任何把物理序升格为可读值的图结构（时钟、自旋计数、原子序号、线程 id、优先级抢占痕迹） |
| **观测** `obs` | 值输出 + 效应 + 控制去向；**不含**到达位置/时刻/序 |
| **顺序源** σ | 图上的显式定序对象：state 边链 / region 迭代序 |
| **结果集** `Obs(M)` | `{ obs(F_M(c,π)) : π ∈ Π }`——race 承诺此集合确定 |
| **隐式竞争** | 未证明 ∧ 未标注的汇合 ⇒ reject |
| **物理⇏语义** | lowering / 调度 / 求值顺序不得把物理序泄漏进 `obs` |
