# 授权族设计：Can 等价于存在合法 capability path

## 概述

授权的语义不是运行时的一次可否询问，而是图上一条路径是否存在。

```text
Can(a, o, r, v) 等价于
    存在一条从主体 a 到 (o, r) 的合法路径 π
    并且版本见证 v 与路径边的版本一致
```

`a` 是主体，`o` 是对象，`r` 是权限，`v` 是状态版本见证，`π` 是 capability path。

传统做法中，权限检查失败时返回错误，失败分支是一条没有被写出来的代码路径。漏写这条路径就是越权。`Can` 的失败是图上的形状事实：写不出越权，因为对应的 effect 生成不出来。

设计状态：定稿，尚未实现。修订记录、决定编号和自检见 `docs/superpowers/implementation/2026-09-11-policy-authorization-audit.md`。

## 与能力格 M1 定论对齐

M1 定论是：语义一致性不需要“能力”成为独立概念。身份等于图节点身份，无生成方法等于标注，授权归治理层的关系标注，能力不提升为语言 primitive。

本族不申请修订 M1：

- 主体 `a` 是图节点身份，例如子图、函数或 `go` 实例。
- 对象 `o` 是条目标识，即产生节点和输入边。
- 授权边是治理层的关系标注，与既有标注空间共用。
- `Can` 是导出判定，不是新的类型或原语。判定走类型引擎。

本族补充两点：

1. 治理层的策略可以增长，判定器不能增长。新增授权模型只增加授权边数据，判定算法不变。
2. 引用能到达不等于有授权。语义层回答“能否到达”，治理层回答“是否允许”。两半分开，正是 M1 的切分点。如果把治理半边塞进语义层，语义一致性就会被“谁被允许”污染。

## unsafe 和授权

`unsafe` 消解语义层义务，不消解治理层授权义务。

- 在 `unsafe` 块内，provenance 无法追踪，capability path 的语义半边无法证明。该 effect 归入 proof-required 或 reject，不能归入 prove。这是“无法判定”，不是“不合法”。
- 治理层授权义务独立存在。`unsafe` 里读同一个对象仍然需要治理层声明覆盖，否则在缺省拒绝下 `Can` 确定不成立，属于违法，不是 4 reject。出路是显式治理层声明。
- 如果 `unsafe` 能顺带免掉授权检查，它就成了权限提升通道。本族存在的意义就是封堵这种形态。
- 唯一合法通道是显式治理层声明，包括 grant 边或例外条目，并且派生源必须可追踪。

授权族的条目是 S-A 放行和声明条目中的 `kind=grant` 或 `kind=deny`。字段包括主体或身份、目标或范围 `(o,r)`、理由、派生源和义务引用。条目必须进入清单。形态是声明型边集合，不是图节点。它需要显式豁免节点形态，并补齐审计字段。

## 能力路径

一条合法路径满足三个条件：

```text
合法路径 π 等价于 SemOK(π) 且 SrcOK(π) 且 非 Deny(π)
```

| 条件 | 含义 | 来源 |
|---|---|---|
| `SemOK` | 引用真的能到达：provenance 不断链，生命周期包含，区域组合合法 | provenance、RegionCheck、借用检查 |
| `SrcOK` | 治理层允许：路径每条边的授权标注沿路径单调限定，不得提权 | 治理层的 `E_grant` 标注 |
| `非 Deny` | 没有显式拒绝边覆盖 | 治理层的 `E_deny` 标注 |

`SemOK` 失败表示引用根本到不了对象，例如过期引用或越出区域。`SrcOK` 失败表示引用能到达，但授权不允许。诊断必须区分两者，否则越权和野指针会被混为一谈。

### 节点和边

节点全部复用已有身份：

| 角色 | 表示 |
|---|---|
| 主体 `a` | 图节点身份，治理层可以绑定角色符号 |
| 对象 `o` | 条目标识，即产生节点和输入边 |
| 权限 `r` | 授权集元素，授权集是幂集格 |

边有四类，全部是标注：

| 边类 | 语义 | 复用 |
|---|---|---|
| `E_ref` | 值流或引用边，主体持有指向对象的引用 | provenance 边 |
| `E_derive` | 能力树派生，例如 mint 或 copy | 能力树 |
| `E_delegate` | 主体把 `(o,r)` 交给另一个主体 | 能力树 |
| `E_grant` 和 `E_deny` | 治理层显式授权和拒绝声明 | policy 数据 |

合法边约束是 Kain 约束：沿路径授权集只能限定，不能扩大。这条约束把能力派生和权限提升分开。copy 可以复制而不降权，mint 必须限定。

### 判定式

```text
W(a,o) = 对所有从 a 到 o 的路径 π：
            如果 SemOK(π)，取路径上所有边授权集的交集
            否则取空集
         再对所有路径取并集

Can(a,o,r,v) 等价于
    r 属于 W(a,o)
    且没有被 Deny 覆盖
    且版本见证 v 一致
```

路径内取交集，每条边都必须允许。路径间取并集，存在一条合法路径即可。

`W(a,o)` 是格上的最宽路径问题。授权分量是分配格，最宽路径有定义，并且可以在多项式时间内求解，使用 Dijkstra 变体或在有限主体集上迭代到不动点。递归能力树成环不破坏可判定性。

state edge 表达“先发生”的顺序，capability path 表达存在性，两者正交。唯一交叉点是撤销：撤销前后的能力不同，属于状态版本族。本族只使用版本见证，不定义版本机制。

外部地址空间指针没有 Core provenance，`SemOK` 恒假。capability path 必须经过例外入口，因此自动落入 `unsafe` 规则。

## 判定

判定分两步。

| 步骤 | 内容 | 归属 |
|---|---|---|
| 1 导出 | 从图和策略计算 `Cap(o,r)`，即能对 `o` 行使 `r` 的主体集合，并给出派生链见证 | 图验证 pass |
| 2 判定 | `Can(a,o,r,v)` 等价于 `ty_sub(τ_subject(a), Cap(o,r))`，并检查版本见证 | 类型引擎 |

图上“沿 def 链倒推”的分析只实现一次，包括 capability path、派生链合法性、根封闭和 handle 身份溯源。输入是 provenance、RegionCheck 和 ProvenanceVerify 的既有结果，输出是 `Cap` 和派生链见证。其他设计使用这个输出，不各自实现。

`Cap(o,r)` 是主体全集上的形状类型项。`Can` 不是新的判定体系，只是一次包含判定。

### 可判定边界

可判定要求三条同时成立：图有限，主体和对象身份在图上有名，策略在正片段，即只有正存在边和显式 deny。

| 边界 | 处置 |
|---|---|
| 主体身份是运行时值，例如外部读入的 uid | 符号化主体，停到 enforce，在图边界做一次检查 |
| 对象身份是运行时计算，例如拼接的 pathname | 不可判定，修复面在路径限制族；本族归入 proof-required |
| 策略包含计数、聚合或时态表达 | 超出片段，归入 proof-required 或 reject，不扩展判定器 |
| 路径枚举预算超限 | 显式诊断“判定预算耗尽”，不能与“无权限”混淆 |

预算超限是工具的能力边界，无权限是程序的事实。混淆两者会产生误报，最终导致工具被关闭。

### deny

先求 `W(a,o)`，再检查 `E_deny` 是否覆盖。deny 一律优先。

理由有三条：

1. 显式拒绝不能被任何 grant 覆盖，这是保守且可判定的。
2. “最近优先”会把路径顺序引入判定，与存在性判定的形态冲突。
3. 显式优先级会引入策略语言，违反零新语法。

### 诊断

失败时输出非空反例路径：

```text
拒绝：主体 f 对 (o, write) 没有合法 authority path
断点：SrcOK，路径 f 到 g 到 o 上，边 g 到 o 没有 write 授权标注
候选：f 到 h 到 o 存在 write，但 SemOK 失败，h 的引用已经离开区域 R
```

诊断必须指出断在哪条边，以及断在 `SemOK` 还是 `SrcOK`。用户才能分辨是改授权声明，还是改引用结构。

## effect 轴耦合

effectful 操作的定义不新造，由两个权威面给出：

1. HIT 事件条目的副作用类字段，值为纯、effect 或 volatile。effect 和 volatile 是 effectful。最小核中的 load 和 store 就是 effectful。
2. 图上的 `effect` 轴标注，属于声明式上限，任何节点都可以加。

两者不一致时产生编译期诊断。图标注是上限，HIT 副作用类是下限。

义务：

> effectful 操作必须产出 `Can(a,o,r)`，否则不能生成该 effect。

判定在图 pass 完成。义务在 effect 生成点使用，例如 IR 合成层或事件发射。这里不重新判定，只使用已经验证的证明。不能在发射层做策略特判。

“不能生成该 effect”意味着该 IR 操作或事件发射被拒绝，不是生成后再检查。

本族不使用 `integrity` 轴。本族的耦合面是 `effect` 和 `authority`。

### 归入档位

| 档 | 触发条件 | 本族形态 |
|---|---|---|
| 1 prove | 主体身份、对象身份和路径都能在编译期确定，`ty_sub` 通过 | 零运行时残留 |
| 2 enforce | 主体身份是图边界值，但路径形状编译期已知 | 图边界一次授权检查 |
| 3 proof-required | 策略依赖运行期外部判定，或者放行本身需要证明 | 要求 proof 或 contract，并显式声明来源和派生源 |
| 4 reject | 高安全档下无法处置，或策略超出片段且没有 contract | 拒绝编译，给出反例路径 |
| 违法 | 治理层缺省拒绝且没有声明覆盖，或 `SemOK` 确定失败 | 硬编译错，任何 policy 都拒绝 |

`unsafe` 内 provenance 中断属于无法判定，走 3 或 4，不是违法。

默认档：enforce 默认启用；没有 enforcement 点时归入 3 并继续编译；高安全档关闭 enforce，归入 4。enforce 必须留下证据，包括诊断登记和图边界检查点，否则等同于无提示通过。

## 与既有机制

| 机制 | 接口 |
|---|---|
| `unsafe` 边界 | 消解语义义务，不消解治理义务。`unsafe` 内 effectful 操作归入 proof-required 或 reject，唯一合法通道是带派生源的显式治理声明 |
| extern | extern 是系统边界，调用是 effectful，也是例外入口。`SemOK` 不可证，合法性只能来自治理层显式声明 |
| HIT 事件 | 副作用类是 effectful 的运行层权威。HIT 表是编译器和平台的能力协商面。运行时条目是 enforce 档的保存面 |
| go 和调度 | `go` 创建新主体，新主体能力集从创建者派生，沿能力树单调不增。捕获环境是显式传递，即派生边。并发让“可能关系”随时间变化，授权判定必须带状态版本 |

## 治理层接口

policy 是数据，不是语法。新增授权模型不改 Graph 本体，不加关键字。

三个保存面：

| 面 | 内容 | 定性 |
|---|---|---|
| `.cr` 内声明式条目 | 主体或角色符号、`E_grant` 和 `E_deny`、授权集 | 语义源，进图，可验证，随子图生命周期 |
| 外部策略数据 | 同一数据的序列化和配置视图 | 视图，不是语义源 |
| HIT 运行时条目 | extern 和入口点约定处的授权声明 | 运行面保存，与声明式条目同源 |

用户面 handle 的内部表示不影响判定。`W(a,o)` 只需要图上可达性，不需要 handle 的编码形态。`Handle<R>` 是独立类型，`bind(p)` 是显式转换点，也是检查和使用的唯一边界。`bind` 的原子性由映射层提供。

授权集是治理层开放词汇表，判定层只使用集合包含，不特判元素符号。新增元素就是加数据行，判定器不变。最小切片使用 `execute`，并沿用治理层已有的 `consult`、`assume`、`measure` 和 `pass`。

gate 是 effectful 操作节点上的义务标注，不是新的节点种类，也不是新的关键字。gate 是义务的接入点，不是判定的接入点。

## 最小切片

一句话：一张声明表，一条判定，一个 effectful 操作的义务，一组正负用例。不包含运行时强制、撤销、动态主体和策略语言。

| 项 | 内容 |
|---|---|
| 策略条目 | 主体符号、对象、授权集，包含 `execute`。没有 deny 表达式，只有 grant 加缺省拒绝 |
| 导出 | 计算 `Cap(o,r)`。`SemOK` 复用既有 provenance 和 RegionCheck 结果，`SrcOK` 用最小闭包 |
| 判定 | `Can(a,o,r,v)` 等价于 `ty_sub(τ_subject(a), Cap(o,r))`，加版本见证，走类型引擎 |
| effectful 操作 | 一个：`store`，属于 HIT 最小核，副作用类明确，不需要运行时主体身份 |
| 档位 | 只实现 prove 和拒绝两档，enforce 和 proof-required 后续实现 |
| 检查 | 见下 |

检查：

1. 正向：授权声明覆盖的 store 通过，产物与没有授权标注的版本一致。
2. 负向：没有声明覆盖的 store 拒绝，诊断给出反例路径和断点。
3. 区分：`SemOK` 失败和 `SrcOK` 失败产生不同诊断。
4. 缺省拒绝：没有 grant 时 `Can` 不成立，不能当作通过。
5. 无特判：编译器侧没有 `read`、`write`、`execute` 等领域特判，授权集只做集合包含。
6. 零回归：没有使用授权策略的语料产物逐字节相同。

## 不承诺

1. 错误的 specification。Core 只能证明程序忠实执行了授权策略，不能证明策略本身正确。漏写 grant、错误的对象身份和过宽的授权集都在策略面，不在语言语义内。
2. 恶意或失陷的外部实体。治理层声明本身可能被伪造或篡改。本族只能让声明显式、可审计、可追踪，不能证明声明来源可信。
3. 需求本身允许危险操作。内核、驱动和系统服务必须执行特权操作。目标是证明隔离边界，不是禁止能力。
4. 运行期授予和运行期撤销。图是编译期的。运行期由外部授予能力时，本族归入 proof-required，由治理层外部机制承担。
5. 权限枚举的完整性。授权集是开放词汇表，本族只决定 `execute` 必须进入，其余元素由治理层细化。

## 不做项

- 不把能力提升为语言 primitive。
- 不新增运行时能力对象。
- 不做运行期动态策略注入。
- 不做策略语言，不做优先级表达式。
- 不做逐节点的运行时授权查询。
- 不在本族定义 `integrity` 和 `secrecy` 轴的用法。
- 不改 Graph 本体，不加关键字。
