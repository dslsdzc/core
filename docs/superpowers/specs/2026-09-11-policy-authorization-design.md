## 0. 范围与裁决

### 0.1 论题

**授权的语义不是「运行时问一句能不能」，而是图上一条路径是否存在。** 判定式（路线图 §2 S-B2 定义；**带状态版本参数**，2026-09-11 裁决 D13）：

```
Can(a, o, r, v)  ⟺  ∃π : a ⇝ (o, r)，π 合法  ∧  v 与路径边的版本见证一致
```

`a` = 主体（subject）· `o` = 对象（object）· `r` = 权限（right）· `v` = **状态版本见证**（D13；κ 粒度 = **对象身份 + 版本见证**）· `π` = capability path。

与传统做法的差别是**量的差别变成质的差别**：`if (!has_permission(...)) return error;` 的失败分支是一条**没人写的代码路径**（漏写 = 越权）；`∃π` 的失败是一个**类型/图形状事实**（写不出越权，因为该 effect 生成不出来）。本族的全部工作就是让后者成立。

### 0.2 与 capability-lattice v4 的 M1 定论对齐（**裁决：不改变，本族是 M1 的兑现**）

M1 定论（v4 §六）：**语义保鲜线不需要「能力」独立概念**；身份 = 图节点身份（已存在）· 无配方 = 标注（已存在）· **授权 = 治理层「可能关系」标注**；能力**不提升一等公民**（可逆、暂不执行）。

**本 spec 不申请修订 M1。** 理由逐条：

| M1 命题 | 本族的落法 | 是否构成「提升」 |
|---|---|---|
| 身份 = 图节点身份 | 主体 `a` = 图节点身份（哪个子图/函数发起）· 对象 `o` = 条目标识 `(产生节点, 输入边)`（memory-model 条款 1，已存在） | 否——零新概念 |
| 授权归一治理层标注 | 授权边 `E_grant` = 图上「可能关系」标注（glossary §六：`A ──可能执行──> B`），与 FUZZY/非确定统一 | 否——统一标注空间加标签 |
| 不提升一等公民 | `Can` 是**导出判定**（§2），不是新的类型/原语；判定走 R2 引擎，不建第二判定体系（契约 §1.2 原则 4） | 否——判定复用 |
| 「可逆」 | §0.4 给出**修订触发条件**（精确判据），当前未触发 | 否——判据在案 |

**本族对 M1 的两点增量（补充，非修订）：**

1. **不对称性的推广**：M1 说「标注可长，原语不可长」（v4 §六 架构不对称性）。本族把它推广到治理层——**策略可长（数据），判定器不可长（固定为集合包含 + 图上可达性）**。新增安全模型 = 新增授权边数据；判定算法一字不改。这是契约 §1.1 `policy` 定义（数据而非语法）在授权族的具体兑现。
2. **M1 的证成（而非只是裁决）**：M1 断言「授权不是语义」。本族给出它**为什么不是**——因为 capability path 的语义半边（引用能否到达、生命周期是否包含）**已经在图上了**（provenance / RegionCheck / 借用逃逸，`pointer-model.md`）。缺的只有治理半边。**有引用 ≠ 有授权**；语义层给「能不能到」，治理层给「许不许」。两半分开，正是 M1 的切分点。若把治理半边塞进语义层，就等于让「谁被允许」污染「这程序算什么」——语义保鲜线立刻失守。

### 0.3 `unsafe` 与治理层的关系（本族最重要的一条边界裁决）

`unsafe` 是**例外入口**（`pointer-model.md:205-221`：provenance 断点；capability-lattice §十：`unsafe / alloc_at | 例外入口授权 = 能力创建点`）。裁决：

> **`unsafe` 消解语义层义务，不消解治理层授权义务。**

- 在 `unsafe` 块内，provenance 不可追踪 → capability path 的语义半边**不可证** → 该 effect 落 **proof-required 或 reject**（§3.3），**绝不落 prove**。
- 治理层授权义务**独立于 unsafe 继续存在**：`unsafe` 里读同一对象仍需治理层声明覆盖，否则**硬编译错 = 违法**（缺省拒绝下的**确定**判定，不是 ④「无法处置」；S-A §2.2 点 1 分栏，§3.3 表）——出路 = 显式治理层声明（下行）。理由：若 unsafe 能顺带免掉授权检查，`unsafe` 就成了**权限提升后门**——这正是 broken access control 的经典形态，本族存在的意义就是堵它。
- 唯一合法通道 = **显式治理层声明**（grant 边 / 例外条目），且**派生源必须可追踪**（capability-lattice §七：派生源 = 例外入口授权可追踪，信任链）。这是路线图 §1.1 `declassify` 在授权族的同构对应物：`¬Can → Can` 的唯一合法通道 = 带派生源的显式声明，不是 `unsafe`、不是运行时绕过。
- **收口到统一 schema（2026-09-11 裁决 D2(a)）**：本族条目 = **S-A §3.1「放行 / 声明条目」** 的 `kind = grant｜deny`，字段 = 主体/身份 · 目标/范围（`(o,r)`）· 理由 · **派生源** · 义务引用；**必须落台账**（S-A §5.2b）。**形态 = 声明型边集合（`E_grant`/`E_deny`），显式豁免节点形态**——理由：授权归**治理层数据面**（M1），它是**标注/声明**而非「变换一个值」的图节点（与 `declassify` 的语义角色不同）；豁免理由 + 审计字段二者缺一即**拒装**（S-A §3.6）。

### 0.4 M1 修订触发条件（判据在案，当前未触发）

按 capability-lattice §十二 #11 判据形态（「图 + 格 + 映射规则无法自然表达」），**若**发生下列任一，本族**申请修订 M1**，并把「能力」提升为一等公民：

| # | 触发条件 | 当前状态 |
|---|---|---|
| C1 | enforcement 需要运行期**持有的不透明能力对象**（而非图边界一次检查）——如 seL4 式 CSpace 走查 | 未触发：enforce 档复用图边界检查形态（capability-lattice §十：`IR_BOUNDS_CHECK` = 图边界授权检查 = 运行期唯一触点），无新运行时对象 |
| C2 | 撤销（revocation）必须**运行期强制**，且无法表达为图上状态版本 | 未触发：按 v4 §11，Core 参照 seL4 的**结构**不参照其**运行时机制**；撤销落 S-B5 状态版本族（编译期） |
| C3 | 策略表达力需求超出图上正存在边 + 显式 deny（如需要运行期动态策略注入对象） | 未触发：超片段需求按 §3.3 落 proof-required/reject，不扩判定器 |

C1/C2 的**代价必须写明**（诚实账）：不提升 = **无法表达「运行期授予且运行期撤销的能力」**。图是编译期的；`grant` 发生在运行时的场景（能力在程序运行中由外部授予）**不在本族可证范围**——它落 §3.3 的 proof-required 档，由治理层外部机制承担。这条代价不做隐藏。

**代价的接受（2026-09-11 裁决 D14）**：**接受**该代价（能力不提升一等公民），代价条款同时写进**路线图 §2 的 S-B2 行**。**延伸路径**（未来若确需运行期授予 / 撤销）= **D13 的能力对象 + 版本见证**（`Can(a,o,r,v)`，§1.3）——「撤销 = 版本推进 ⇒ 旧版本见证失效」，在语言面可表达，不需回溯修订 M1。触发条件仍以 §0.4 的 C1/C2/C3 为判据（当前全未触发）。

## 1. capability path 的形式化

### 1.1 路径的三条合取条件（**设计定稿**）

```
合法 π  ⟺  SemOK(π)  ∧  SrcOK(π)  ∧  ¬Deny(π)
```

| 条件 | 含义 | 来源（**全是既有机制**） |
|---|---|---|
| `SemOK(π)` | 引用**真的能到**：provenance 不断链 + 生命周期包含 + 区域组合合法 | provenance 边（`pointer-model.md`）· RegionCheck（区域逃逸）· 借用逃逸 pass |
| `SrcOK(π)` | 治理层**允许**：路径每条边的授权标注沿路径**单调收窄**（⊑ 细化，不得提权） | 治理层 `E_grant` 标注（**本族新增数据**，非新机制） |
| `¬Deny(π)` | 无显式拒绝边覆盖 | 治理层 `E_deny` 标注 |

**为什么必须是三条而不是一条**：`SemOK` 是语义层的（M1 已在图上），`SrcOK`/`Deny` 是治理层的（M1 说归治理层）。缺 `SemOK` 的失败 = 「你根本到不了这东西」（UAF/逃逸类）；缺 `SrcOK` 的失败 = 「你能到，但你不许」——**后者才是本族**。诊断为二者给出**不同断点**（§2.5），这是「越权」与「野指针」不被混为一谈的形式保证。

### 1.2 节点与边（**设计定稿**；内部布局实施批定）

节点（**全部复用已有身份，零新节点种类**）：

| 角色 | 表示 | 依据 |
|---|---|---|
| 主体 `a` | 图节点身份（子图/函数/`go` 实例）——治理层可绑定角色符号 | M1：身份 = 图节点身份；capability-lattice §七 身份符号 |
| 对象 `o` | 条目标识 = `(产生节点, 输入边)` | memory-model 条款 1——**对象身份本来就在图上** |
| 权限 `r` | 授权集元素（幂集格元素）；见 §5.3 枚举 | capability-lattice §九 授权分量 = 布尔格 |

边（四类，**全部是标注，不是原语**——M1 不对称性）：

| 边类 | 语义 | 复用 |
|---|---|---|
| `E_ref` | 值流/引用边：`a` 持有指向 `o` 的引用 | provenance 边（PointerAnalysis 输出） |
| `E_derive` | 能力树派生：mint / copy（沿树） | capability-lattice §八 能力树；"能力流分析 = PointerAnalysis 推广" |
| `E_delegate` | 传递：`a` 把 `(o,r)` 交给 `b` | 同上 |
| `E_grant` / `E_deny` | 治理层显式授权 / 拒绝声明（**数据**） | 契约 §1.1 `policy`；glossary「可能关系」 |

**合法边约束 = Kain 约束**（capability-lattice §六：「细化 ⊑ 必须可强制」）：沿路径授权集**只许收窄**。这条约束是把「能力派生」与「权限提升漏洞」分开的唯一机制——`copy` 可复制不降权（可复制性，v4 §九），`mint` 必须收窄。

### 1.3 判定式（**设计定稿**）

```
W(a,o) ≜ ⋃π∈Paths(a,o)  SemOK(π) ? ⋂e∈π auth(e) : ∅        -- 沿路径授权交集，跨路径取并
Can(a,o,r,v) ⟺ r ∈ W(a,o)  ∧  ¬DenyCovered(a,o,r)  ∧  v 一致（版本见证）
```

- **状态版本参数（2026-09-11 裁决 D13）**：`Can` **带状态版本参数** `v`；**κ 粒度 = 对象身份 + 版本见证**（不是裸对象身份）。版本载体 = **S-B5 的 ENT `(var_id, version)`**（v7 既有，**不引入第二套版本机制**）。⇒ 「撤销」在语言面**可表达**（撤销 = 版本推进 ⇒ 旧版本见证失效），与 S-B5 的 check/use 判定同源。§8.2-3 随之关闭。

- **路径内取交（⋂ = 幂集格 meet）**：每条边都必须允许。
- **路径间取并（⋃ = 幂集格 join）**：**存在**一条合法路径即可。
- 这正是 capability-lattice §九 代数（授权分量 = 幂集格，`∩`/`∪` = meet/join）与保序积总序 `(r₁,a₁) ⊑ (r₂,a₂) ⟺ r₁ ⊑ r₂ ∧ a₁ ⊆ a₂` 的直接消费。
- **可判定性（好消息）**：`W(a,o)` 是 **格上最宽路径（widest / bottleneck path）问题**。因为授权分量是**分配格**（幂集格 ⇒ 分配律成立），最宽路径良定义且**多项式时间可解**（Dijkstra 变体 / 有限主体集上迭代到不动点 = Datalog 半朴素求值）。递归能力树成环**不破坏可判定性**（格上可达性对环封闭；与 R2 引擎 μ 展开的余归纳 memo 同族处理）。
- **与 state edges 的接口（正交，**裁决：不耦合**）**：state edges 是「先发生」顺序约束（命令式下限，定案 14 不动）；capability path 是**存在性**，不是顺序——两者正交，判定**不消费顺序**。唯一的表面交叉 = **撤销**：撤销前后的能力不同，是**时间**概念 → 归 **S-B5 状态版本族**（图上两个版本），本族**只消费其版本见证**（D13：`Can(…,v)`），不定义版本机制。
- **与 provenance 的接口（`asp`）**：外部地址空间指针（`asp=1`，`pointer-model.md:221`）**没有 Core provenance** → 其 `SemOK` 恒假 → capability path 必然经例外入口 → 落 §0.3 的 unsafe 裁决。这条把「外部来源引用」自动排除出可证子集，无需特判。

## 2. 判定：`Can` 如何落到引擎

### 2.1 两步分离（**设计定稿**——契约 §1.2 原则 4 的兑现）

| 步 | 做什么 | 归属 | 先例 |
|---|---|---|---|
| **① 导出** | 从 `G + P` 算出 `Cap(o,r)` = 「能对 `o` 行使 `r` 的主体集合」（图上的闭包）**+ 派生链见证** | **图验证 pass**（与 PointerAnalysis / RegionCheck / ProvenanceVerify 同级，定案 1/4）——**「沿 def 链倒推」图面分析的唯一 owner（2026-09-11 裁决 D22）** | 图上稀疏分析 |
| **② 判定** | `Can(a,o,r,v) ≜ ty_sub(τ_subject(a), Cap(o,r))`（+ 版本见证一致，§1.3） | **R2 引擎**（`ty_sub`） | `type-interface-unification-design.md` §3.2 |

- **唯一 owner 声明（D22，规范性）**：图上「**沿 def 链倒推**」的分析（capability path / 派生链合法性 / 根封闭 / handle 身份溯源）**只在本步实现一次**——**输入** = provenance / RegionCheck / ProvenanceVerify 的**既有结果**（**不新写分析**），**输出** = `Cap` + **派生链见证**（供诊断与下游消费），**`g_*` 表只读**。**S-B4**（其 Q4：派生链合法性落点）与 **S-B5**（其 §3.2：κ 可靠性）**消费本步输出，不各自实现**；三份 spec 的回引已就位（S-B4 §7.2 Q4、S-B5 §3.2）。§6.3 的侦查项据此收窄为「**复用既有 pass 结果是否真的零新分析**」。
- `τ_subject(a)` = 「主体 `a`」的类型项（**记号更名**：旧稿用 `A_a`，与 S-A §3.3 的**轴取值类型项** `A_a(v)` 记号冲突 —— §3.3 单式语境下同现会读错，故统一改 `τ_subject(a)`；评审 M3）。
- `Cap(o,r)` = 一个**形状类型项**（主体全集上的子集）。
- **零新判定规则**：`Can` 不是新的判定体系，是引擎上的一次**包含判定**——与横切接口「满足判定 = 一条包含判定 `T <: 形状`」（R2 §2.2）**完全同构**。「能访问 `(o,r)` 的主体」就是一个形状。
- 这是 M1「不提升」在判定面的硬证据：**授权不新增判定器，只是引擎的一个新形状**。

### 2.2 可判定子集与边界（**设计定稿**；边界项逐条给出落档）

可判定 ⟺ 三条同时成立：① 图有限（现状恒真）② **主体与对象身份在图上有名** ③ 策略在正片段（正存在边 + 显式 deny）。

| 边界 | 处置（按 S-A 四档） |
|---|---|
| 主体身份是**运行时值**（如外部读入的 uid）→ 符号化主体 | 判定到「符号化主体」即停 → **enforce**（图边界一次检查，§3.3） |
| 对象身份是**运行时计算**（如拼接的 pathname） | **不可判定** → 修复面在 S-B4（围栏族：`Path<Root>` 让对象可命名）；本族据实落 proof-required |
| 策略含**否定以外的表达力**（计数/聚合/时态） | 超片段 → **proof-required**（要求用户提供 contract）或 reject；**不扩判定器**（§0.2 增量 1） |
| 路径枚举**预算超限** | **显式诊断「判定预算耗尽」**——**绝不与「无权限」混淆**（R2 §3.3 同款守卫；契约 §1.2 原则 3 不静默消失） |

- **预算超限 vs 无权限** 的区分是本族**必须**做对的判定卫生：前者是工具的能力边界，后者是程序的事实。混淆两者 = 误报 = 工具被关掉 = 全盘失效。
- **默认强度分层（2026-09-11 裁决 D3(c)；规范形态见 S-A §2.2 附）**：② **enforce 默认启用**（可 enforce 一律 enforce）；无 enforcement 点 ⇒ **③ 登记 + 继续编译**（默认档**不拒编**）；**高安全档**关闭 enforce 通道 ⇒ ④；**未声明的边界条目取 `unknown`**（保守判定方向）+ 报告面可见。**CI 门槛 = 严**（strict 档运行，台账非空即失败）。

### 2.3 deny 语义（**设计定稿**）

- **两阶段**：先求 `W(a,o)`（正片段闭包），再查 `E_deny` 覆盖 → **deny 优先**（默认拒绝底色的显式化）。
- **冲突消解 —— 已裁（D30，2026-09-11）：deny 一律优先**。理由：① 「显式拒绝不得被任何 grant 覆盖」= 保守且**可判定**（一次集合查询）；② 「最近优先」把**路径次序**引入判定，与 §1.3「存在性判定」的形态冲突（存在性不带序）；③ 显式优先级序 = 引入策略语言（违反 D5 零新语法）。§8 开放 4 随之关闭。

### 2.4 增量与缓存（**待论证**，依赖 S-D）

`Cap` 表的失效面 = `ΔG`（图变化）∪ `ΔP`（策略变化）。**2026-09-11 裁决（D29）**：增量 / 报告接口（`Cap` 表失效面、竞态报告链格式、台账格式）**归 S-D 线统一**——本族只写**消费点**，**不设计缓存键、不写格式**。

### 2.5 诊断（**设计定稿**）

失败输出 = **非空反例路径**（同 R2 `ty_witness` 精神：给具体值，不给「不匹配」）：

```
拒绝：主体 f 对 (o, write) 无合法 authority path
  断点：SrcOK —— 路径 f → g → o 上边 g→o 无 write 授权标注
  候选：f → h → o 存在 write，但 SemOK 失败（h 的引用已逃逸区域 R）
```

- **必须指到断在哪条边、断在 `SemOK` 还是 `SrcOK`**——用户才能分辨「改授权声明」与「改引用结构」。
- 位置与图→源码映射走 `diag.cr` + LSP 基建（R2 §7 同款）。

## 3. effect 轴耦合

### 3.1 哪些 operation 算 effectful（**设计定稿**——不在本族发明，查权威来源）

effectful op 的定义**不新造**，由既有两个权威面给出：

1. **HIT 事件条目的「副作用类」字段**（`specs/2026-09-05-hardware-interface-table.md` §3.1：`纯 | effect | volatile`）——**这是运行层的权威声明**。`effect`/`volatile` 类事件 = effectful。最小核里即 `load`（读世界）/ `store`（写世界）（HIT §2）。
2. **图上 `effect` 轴标注**（路线图 §1.1 七轴之一，开放标注）——声明式上限侧，任何节点可加。

两者关系：**图中标注 = 上限（用户/库声明什么算 effectful）；HIT 副作用类 = 下限（编码层事实）**。二者不一致 = 编译期诊断（契约 §1.2 原则 3：不静默）。

### 3.2 义务（**设计定稿**）

> **effectful operation 须产出 `⊢ Can(a,o,r)`，否则不能生成该 effect。**

- **判定在图 pass 完成（声明式上限），义务在 effect 生成点被消费（命令式下限）**——这正是定案 14「两者共用一张图」在授权族的具体形态。
- 消费点 = **effect 生成点**（IR 合成层 / 事件发射）——比 checker 更低一层。此处**不重新判定**，只**消费**已验证的证明（`g_cap_*` 标注 / gate 标记，`ast.cr` 惯例的 kind 常量，实施批定）。**禁止**在发射层做策略特判（契约 §1.2 原则 2：不把某类漏洞做成内建特判）。
- 「不能生成该 effect」的落点 = **该 IR op / 该事件发射被拒绝**，不是「生成后再检查」。

### 3.3 无证明时的落档（**设计定稿**）

| 档 | 触发条件 | 本族形态 | 成本 |
|---|---|---|---|
| **prove** | 主体身份 + 对象身份 + 路径全编译期可定，`ty_sub` 通过 | 零运行时残留 | **零**（能力 = 编译期图数据，证明完毕不下发——capability-lattice §十一） |
| **enforce** | 主体身份是**图边界值**（运行时），但路径形状编译期已知 | **图边界一次授权检查** | 与已有 `sub+cmp+jae+ud2` 同级（capability-lattice §十：`IR_BOUNDS_CHECK` = 图边界授权检查 = 运行期唯一触点；**编码措辞待 T9 统一**） |
| **proof-required** | 策略依赖运行期外部判定（外部 PMS / 动态策略加载 / 运行期授予，§0.4 C3）；或**放行本身**（unsafe / 例外入口 / 治理层声明的正确性）需证（S-A §2.2：放行登记为义务） | 要求用户提供 proof/contract（显式声明来源 + 派生源） | 用户负担，**显式** |
| **④ reject** | **高安全档**下不可处置（如路径形状不可判且无 enforce 通道）；或策略超片段且未提供 contract | 拒绝编译 + 反例路径 | 零 |
| **违法**（**不属于义务梯档**——判定结论为假） | 治理层**缺省拒绝**且无声明覆盖（`¬Can` 确定成立，§6.1「缺省拒绝」）；或 `SemOK` 确定假（**`asp=1`** = 显式外部地址空间、确定无 Core provenance）。**注**：`unsafe` 内 provenance **追踪中断 / 不可判** = `unknown` ⇒ 走 ③/④，**不是**违法（「不可判定 ≠ 不合法」，S-A §2.2 点 2） | **硬编译错**（任何 policy 档位拒绝）+ 反例路径；**出路 = 显式治理层声明**（S-A §3.1 放行/声明条目 `kind=grant`，登记落台账） | 零 |

**默认档裁决（2026-09-11 裁决 D3(c) 对齐）**：**② enforce 默认启用**（可 enforce 的一律 enforce）；无 enforcement 点 ⇒ **③ 登记 + 继续编译**；**高安全档**（用户显式声明）**关闭 enforce 通道** ⇒ ④ reject。理由：契约 §1.2 原则 3 不静默——enforce 是**显式可见**的（产物里有检查、诊断里有登记），不是「反正运行时查了」的无声漏斗。**enforce 必须留下证据**（诊断登记 + 图边界检查点），否则等同于静默通过。

## 5. 治理层接口

### 5.1 策略 = 数据（**设计定稿**，契约 §1.1 逐字遵守）

`policy` = 一组图上约束（`G + P ⊢ Safe` 里的 `P`），**数据而非语法**——新增授权模型不改 Graph 本体、不加关键字。本族消费三个承载面：

| 面 | 内容 | 定性 |
|---|---|---|
| **(a) `.cr` 内声明式条目** | 主体/角色符号、`E_grant`/`E_deny`、授权集 | **语义源**（进图、可验证、随子图生命周期）。先例 = `alloc_at`（声明即注册，`pointer-model.md:192`）；形态 = **库侧声明**（契约 §1.2 原则 2「策略面归库」），**不新增关键字**（D5），复用现有声明形式，实施批定。**本族条目在 S-A §3.1「放行 / 声明条目」栏的形态（D2(a)）**：`kind=grant｜deny`，主体 = 主体/角色符号，目标/范围 = `(o,r)`，理由 / **派生源**（例外入口授权链，capability-lattice §七） / 义务引用 = 必填；**形态 = 声明型边集合，显式豁免节点形态**（理由见 §0.3）；**每条落台账**（S-A §5.2b） |
| **(b) 外部策略数据** | 同一数据的序列化/配置投影 | **投影，非语义源**（定案 1：图是唯一真相层）——与 S-C 序列化面共裁 |
| **(c) HIT 运行时条目** | extern/入口点约定处的授权声明 | **运行面承载**（§4），与 (a) 数据同源 |

### 5.2 用户面句柄（**开放问题——引用而非裁决**）

capability-lattice §十三 开放问题 3：「用户面句柄形态细节：树路径 vs 槽位引用（内部表示）」。

**本族立场**：判定层**不依赖**句柄内部表示（`W(a,o)` 只需图上可达性，不需要句柄的编码形态），故**本族不裁决其内部编码**。**表示形态**的裁定权（S-B4 §1.4 交给「S-B5 + 映射层」）**已裁（2026-09-11，D30 采纳 S-B5 §3.2 建议）：并列类型**——`Handle<R>` 独立于 `Path<R>`，`bind(p) -> Handle<R>` 为显式转换点（= 唯一的 check/use 边界 = S-B5 C1 的判定对象）；`bind` 的原子性来源（fd / dirfd / `openat` 类）由**映射层**确认。本族据此消费 handle 身份（`o` 的对象身份可取自 handle）。**诊断与解释的呈现**（§2.5 反例路径怎么给用户看）依赖它 → 登记为**依赖项**（§8 开放 5），不阻塞最小切片。

### 5.3 授权集枚举（**承接 capability-lattice 开放 1**）

capability-lattice §十三 开放 1：「授权集完整枚举：consult/assume/measure/pass 之外还需哪些（execute？deliver？）」——治理层问题。

**本族裁决一处**：**`execute` 必须进**。理由：本族的核心消费面是 **effectful op**（§3），而「执行」是 effect 的原型关系；缺 `execute` 则 §3 的义务无对应授权元素，耦合成空。

**枚举面的口径（2026-09-11，D30）**：授权集 = **治理层开放词汇表**（数据）——判定层只消费**集合包含**，**不特判元素符号**（新增元素 = 加数据行，判定器一字不改）。最小切片用 `{execute}`（+ 治理层既有 `consult`/`assume`/`measure`/`pass` 词汇）；`deliver` 等其余元素的**闭包**留治理层细化（§8 开放 6 关闭为「开放集 + 加数据行」）。

### 5.4 gate（**本族新增的治理层接口，最小**）

effectful op 节点上挂**义务标注**（§3.2 消费点）——**不新增节点种类、不新增关键字**（标注可长，原语不可长）。gate 是「义务的挂点」，不是「判定的挂点」（判定在图 pass）。

## 7. 不承诺（引路线图 §1.3，逐条说明本族落在哪类）

### 7.1 错误 specification（**本族首当其冲，必须写透**）

> Core 只能证明「程序忠实实现了规则」，不能证明规则本身正确。

**本族不可能消掉这一类，而且它是本族最大的残留。** 硬例子：策略声明 `E_grant(everyone, account, withdraw)`（「人人可提款」）——Core **会证明通过**。判定式 `Can(a,o,r) ⟺ ∃π` 忠实实现了这个规则；规则错了，`∃π` 依然成立。编译器在此**完全无话可说**。

本族真实消除的是：**规则与实现的不一致**——即 CWE-284/285/639 族的主力形态（漏写检查、检查顺序错、路径混淆、TOCTOU 窗口）。形式化陈述：

```
保证：G ⊢ Can(a,o,r) 与 P 一致（可判定、反例非空）
不保证：P 本身安全
```

**推论（必须对用户说清）**：本族把「越权」的**发生率**大幅压低（漏写检查变成编译错误），但**不把授权变成安全**——它把授权策略从「散落在代码里的判断」提升为「一处可审计、可 diff、可验证一致性的数据」。审计价值是真实的，安全承诺是没有的。

### 7.2 恶意 / 失陷外部实体

供应链、编译机、密钥、身份提供者被攻陷——本族**不能用语言语义证明**。缩小手段（本族提供的）：**派生源可追踪**（信任链，§0.3）+ **最小权限**（本族给最小权限的**判定机制**，不给威胁证明）。`a` 的身份符号**绑定是否正确**（uid 是不是真 uid）在治理层外，本族不管。

### 7.3 需求本身允许危险行为

shell/browser/kernel/JIT 必须执行外来代码——本族目标是**证明能力边界**（谁被允许做什么），不是禁止能力。`unsafe`/例外入口的存在是**需求**，不是缺陷；本族对它的贡献是让「例外**必须显式且可追踪**」（§0.3），而非消灭例外。
