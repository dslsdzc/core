## 2. 根因与修法

**根因（一句话）**：dex 形式转换契约（「存储/边界处按槽位形式转换」）只在 **5 类落点**接线，而跨函数边界的**唯一**实参转换通道——调用实参环——以 `ast_kind(func_node) == EXPR_IDENT` 为门 ⇒ **方法调用与模块限定调用整段跳过**；聚合四类写点（字段/元素/元组/载荷）、指针写与全局运行期初值**无漏斗**；聚合读**硬定型 `TI_INT`**（#78）使下游「按 IR 值型触发」的转换连锁失效。两后端在调用边界只做运输、零 dex 逻辑（`callseq.cr` 按 `irv_type` 分类；`interp.cr` 按位置拷贝）⇒ 漏转实参**双路径同错**。

**修法（维护者背书方向 = 唯一漏斗 + 声明型触发）**：
1. **漏斗** `dex_slot_norm`——依 §0 推论「`apx` 是 LET 专属标签 ⇒ 聚合面不存在 apx 形式 ⇒ 规范槽形式恒为精确」；非 apx **零 IR**；**零类型表查询**（不变量 GC 12）。
2. **8 写点接线**（字段赋值 · 下标赋值 · **指针写** · 枚举载荷 · 结构体字面量 · 数组字面量 · 元组元素 · 全局运行期初值）。
3. **环覆盖面重写**——门放宽为「命中 Core/extern 函数」，**逐形态**覆盖直调/方法/**模块限定**（**不是「凡调用都进环」**）；实参节点改取 `arg_nodes[cpi]`（与 `arg_vars` 同表锁步）。
4. **比较点声明面查表**（`dex_decl_form_of_expr`，**节点级零 alloc**）——作用域内替代 #78，不改读点定型。
