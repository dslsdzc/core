## 0. 一句话结论

**`checker.cr` 的 `infer_expr` 在「被调已解析为 Core `fn`」时提前 return（`:2817`），而推实参的循环在函数尾（`:2833-2839`）——对任何**有名**被调都是**死码** ⇒ 已解析直调的实参表达式**从不被推断**。1339 只是它在「实参位的内层调用是 `EXPR_FIELD` 被调」下的表现；更危险的另一半是**静默通过**（实参里的未定义函数零诊断）。**

## 1. 根因（`file:line`）

| 坐标 | 内容 |
|---|---|
| `src/compiler/checker.cr:2817` | `return sym_type(si);  // return type` —— 直调分支里，被调名 `find_gsym` 命中 `SYM_FN`（已注册 Core `fn`）时**提前 return** |
| `src/compiler/checker.cr:2833-2839` | `// Infer arg types (for side effects)` + `loop { infer_expr(ast_a(an)); an = ast_b(an); }` —— **在函数尾**，仅当 `func_ni < 0`（连名字都没有）时才可达 ⇒ **对任何有名被调是死码** |
| `src/compiler/checker.cr:2584` / `:2645` | 模块限定调用 / 方法调用的 `ast_set_data(node, func_ni)`（被调名索引）——**只有**这两个分支会回填 |
| `src/compiler/checker.cr:2623` | 「推实参」循环在**模块/方法分支内**另有一份（**这才是 c4/c9 能正常解析的原因**） |
| `src/compiler/ir_gen.cr` 调用发射处 | `func_ni = ast_data(node)`（`EXPR_FIELD` 被调）——读出 **0** |

### 1.1 139 的产生链

```
实参位的内层调用 = EXPR_FIELD 被调（方法 / 模块限定）
   ⇒ 其 ast_data（被调名索引）只能由 checker 的模块/方法分支回填（:2584/:2645）
   ⇒ 但该分支从没跑（外层直调在 :2817 已提前 return）⇒ 字段 = parser 初值 0
   ⇒ ir_gen 读出 func_ni = 0 ⇒ istr_get(0) = 文件**首个 interned 串**
        （有 `import` 语句时恰为 "import" —— 这就是 .cir 里 `call import(unresolved, int)` 的出处）
   ⇒ 后端按名查不到 ⇒ 落外部位重定位（未定义符号）
   ⇒ **SIGSEGV 139**
```

**对照（为何「绑定到变量就正常」）**：`x := fmt.int_str(7)` 的模块调用在 **LET 值位** ⇒ `infer_expr` 真正跑 ⇒ 模块分支回填名字 ✓。而 `str_eq(fmt.int_str(7), "7")` 的内层在**实参位** ⇒ 外层提前 return ⇒ 从不被推断 ✗。

### 1.2 静默面（同因、更隐蔽）

既然实参不被推断，则**已解析直调的实参完全不进检查**：`g(nosuchfn(1))`（`g` 为本文件 `fn`）**`check` rc=0、零诊断**（实测），且运行时同样 139。
⇒ **#93 的正确标题是「实参推断缺失」**：139 响亮、静默通过不响，**后者才是本项目头号敌人**。

## 2. 可达性边界

### 2.1 判别矩阵（同形单变量）

| 内层被调形态 | 外层 = **已解析 Core `fn` 直调** | 外层 = 模块限定调用 | 外层 = 方法调用 | 外层 = extern / 未解析 |
|---|---|---|---|---|
| **模块限定 `m.f(x)`** | **139** | 绿 | — | 绿 |
| **方法调用 `s.m(x)`** | **139** | — | 绿 | — |
| 直调 `f(x)` | 绿 | 绿 | 绿 | 绿 |
| 泛型实例化 `idf(x)` | 绿 | — | — | — |

**判据**：崩 = **内层 `EXPR_FIELD` 被调** ∧ **外层已解析 Core `fn` 直调**（外层实参推断被跳过）。
外层若是**模块限定 / 方法调用**（`checker.cr:2623` 有推实参）或 **extern / 未解析**，实参被推断 ⇒ 安全。

### 2.2 日常形态（**反直觉**）

| 形 | 结果 |
|---|---|
| `println(fmt.int_str(7))` | **绿**（`println` 走 extern/未解析路径 ⇒ 推实参） |
| `show(p.get())` / `log2(fmt.int_str(7))`（**自己的 helper**） | **139** |

⇒ **最外层用 stdlib I/O 反而安全；包一层自己的 helper 反而崩**。

## 4. 修法候选（**本侦查不实施**）

### (a) 补实参推断（**根因修，推荐主体**）
- **做法**：把 `:2833-2839` 的循环抽成小函数，在 `:2817`（及其它「已解析」return 点）**之前**调用。
- **改动面**：`checker.cr` 一处 + 一个小函数。
- **风险（必须显式设防）**：**行为放大**——实参一旦被真正推断，此前静默通过的形态会开始出诊断（`g(nosuchfn(1))` → `error[N06]`；类型不符也可能开始报）⇒ **现有语料 `check` 可能由绿转红**。
  ⇒ 纪律：**腿① 全语料逐档对拍 + 每一条新诊断逐条归因**（哪条是「本来就该报的」、哪条是「新引入的误报」）。**不许把新增诊断一律当成「修好的证据」**（本仓「判据面混类」之防）。**归因不清 ⇒ 停下上报**。
- **判据**：腿 A 各例由 139 → 精确值；**腿 B `g1` 由「零诊断」→ `error[N06]`（这一条是「修好了」的正据，缺了它本批只修了一半）**；腿① 差异逐条归因；canary / `.ccr` 不变。

### (b) fail-closed 护栏（**兜底，建议同批**）
- **做法**：`ir_gen` 的 EXPR_CALL 处，callee 是 `EXPR_FIELD` 且 `ast_data(node) <= 0`（从未被解析）⇒ 报硬错 + **拒绝产物**。
- **改动面**：`ir_gen.cr` 一处（小）。**风险**：低；**但只把静默 139 变响亮**，不修根因 ⇒ 按铁律「不许绕过」**应与 (a) 组合**。
- **判据**：139 → **rc=1 + 定位诊断**（不得静默）；绿形态与 canary 不变。

### (c) 预先回填名字（**退路**）
- **做法**：parser 构造 `EXPR_CALL` 时，若 callee 是 `EXPR_FIELD` 且 obj 是模块符号 ⇒ 立即写 `ast_data`。
- **前提未实证**：需模块符号在 **parse 期**可用（`res_imports` 在 parse 前跑，但**符号注册时序未核**）⇒ 不可行则本路作废。
- **判据**：同 (b) 的 139 例；但 **`g1` 仍不报 N06** ⇒ **治标**。

**推荐**：(a) 为主 + (b) 兜底；(c) 退路。
