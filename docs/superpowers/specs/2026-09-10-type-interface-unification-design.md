# 接口化主设计：类型等于图标注、双轴注册表和语义子类型引擎

## 概述

类型不再由独立类型系统维护，而是图上的类型项标注。类型判定是一次包含判定：

```text
A <: B 等价于 ⟦A⟧ 包含于 ⟦B⟧
```

类型项由双轴接口注册表描述：

- 本质轴：每个原子构造子一条条目，描述良构性、操作许可和字面量定型。
- 横切轴：结构自动判定的形状项，例如序列、可比较、可索引、可迭代。
- 用户轴：`interface` 和 `impl` 产生的形状项和满足关系。

三类接口使用同一个判定入口 `iface_satisfies`。

设计状态：定稿。P0 到 P6 已实施，实施记录、决定编号、对拍数据和偏差清单见 `docs/superpowers/implementation/2026-09-10-type-interface-unification-audit.md`。

## 语义基础

类型项的语义是值集合：

```text
τ 的语义 = ⟦τ⟧
A <: B 等价于 ⟦A⟧ 包含于 ⟦B⟧
等价 = 双向包含
不相交 = 交集为空
穷尽性 = 补集为空
```

类型项语法：

```text
τ ::= ⊥ | ⊤ | ⊤ₖ | τ₁ ∪ τ₂ | τ₁ ∩ τ₂ | ¬τ | μX.τ | X | k(τ₁…τₙ)
```

- `⊥` 是空集，`⊤` 是全集，`⊤ₖ` 是原子类 k 内的全集。
- `k` 是原子构造子。原生类型有 `int`、`dex`、`string`、`bool`、`unit`、`never`、`char`、`dyn`。结构构造子有 `product`、`sum`、`sequence`、`ref`、`ptr`、`fn`。参数化命名使用 `named<τ…>`。
- `μX.τ` 的递归对应注册表引用图上的环。没有 `rec` 关键字，环检测自动完成。值递归导致无限大小，编译期拒绝。

规范化使用 DNF，即 union of products。product 由原子和否定原子集合组成。判定输入是规范化形态，规范化结果按结构哈希缓存。

声明式边界：本层只处理类型和契约。执行、副作用、内存和调度的命令式下限不动。

## 双轴接口注册表

### 本质轴

每个原子构造子一条条目：

| 字段 | 内容 |
|---|---|
| kind id | 原子构造子标识 |
| 名字和语义域 | 例如 `sequence` 是长度加元素集合，`int` 是数学整数 |
| 良构性规则 | 构造合法性，例如序列需要元素项，product 需要字段表，递归环可接受 |
| 操作许可 | 哪些操作可以作用，例如加法对 `int`、`dex` 和 `string` 合法 |
| 字面量定型 | 字面量得到的类型项 |
| 尺寸和对齐 | 映射层或硬件映射领域，语义层不承诺布局 |

原生条目是公理内建，用户不能实现。用户类型的条目是结构构造子的实例化。

### 横切轴

每条横切接口是一个形状类型项。满足判定就是包含判定：

```text
T <: 形状
```

初始条目：

- 序列接口，等价于 `sequence<⊤>`，后续细化为只读和可写两种形状。
- product 接口，等价于 `product<⊤…>`。
- 可比较。
- 可索引。
- 可迭代。

只读视图协变，可写视图不变。变型规则记录在条目内。

### 用户轴

```text
interface I { ... }
impl I for T
```

`interface I` 得到形状类型项，方法集是 product of fn 原子，方法签名各自是 `fn(τ₁…τₙ) -> τ` 项。

`impl I for T` 在图上增加满足关系，进入注册表并加边。

满足判定统一使用 `iface_satisfies(T, I)`。方法解析不再使用 `Type.method` 字符串拼接查找，改为类型项加接口条目查表。旧 mangling 行为不保留。

### 与既有表衔接

本质轴条目对应现有类型表。原表保留为原子条目层，新增语义域、操作许可和字面量规则字段。

横切轴和用户轴对应现有接口表和实现关系表，升级为“条目引用形状类型项”加“满足关系”。原有方法数和参数数上限随升级解除或显式登记。

编号撞车必须清理。现状存在 `TYP_*`、`TY_*` 和 `TI_*` 数值相同但含义不同的情况。本轮按命名空间分家，或在实施时合并为单一空间并记录。

### 查询 API

```text
iface_kind_of(ti)       行号得到原子 kind
iface_ops(kind)         操作许可集
iface_satisfies(T, I)   原生、横切、用户三类统一入口
iface_size(ti)          映射层尺寸标注
iface_align(ti)         映射层对齐标注
iface_of_term(τ)        类型项得到本质 kind
```

checker 只能通过这些入口查询，不再直接比较 `TI_*` 常量。

## 类型项层和判定引擎

### 存储

类型项表使用定长条目：

```text
{tag, a, b, c, d}
tag ∈ {BOT, TOP, TOP_K, UNION, INTER, NOT, MU, ATOM, VAR}
a..d = 子项索引
ATOM 的 a = 原子条目行号
```

类型项构成 DAG，共享子项按结构哈希去重。

### 判定 API

```text
ty_sub(a, b)       包含
ty_equiv(a, b)     双向包含
ty_disjoint(a, b)  不相交
ty_inhabited(a)    可空性
ty_witness(a, b)   失败时的反例值
ty_exhaustive(...) 穷尽性
```

算法先做 DNF 规范化，再做结构对照。product 覆盖判定加同类原子分解，只有同类原子需要展开子项。`μ` 展开使用假设和判定的 memo。

判定失败时给出非空反例值。例如 `[int;2] <: [int;3]` 的反例是“长度为 2 的序列”。

### 性能和预算

- `(a,b)` 判定结果缓存。
- 规范化结果按结构哈希缓存。
- 有界原子宇宙使用位集合快路径，例如枚举变体集、可选集和穷尽性。64 位上限需要解除或显式登记。
- 判定步数有预算守卫。预算超限时给显式诊断，并登记未覆盖面，不能与类型不兼容混淆。

### 图标注表示

当前状态：`OFF_DF_TK` 是类型项引用，是类型面的唯一依据。`OFF_DF_AUX` 是辅码，保存旗标、宽度、计数和不可逆行原码。派生码由类型项和辅码共同计算，`emit`、`lower_to_ccr` 和装载侧使用同一个函数。

分类表是唯一分类出处，区分类型面行和辅码面。复合行不建类型项，原码进入辅码槽保真。

跨进程不引入进程内类型项索引。需要跨边界时，唯一允许的形态是 TYPE 段文件内项索引。

## 检查器迁移

迁移分四步：

| 步 | 内容 | 检查 |
|---|---|---|
| 1 建层 | 类型项表、引擎和查询 API，checker 不动 | 用例表通过，零产物变化 |
| 2 旁挂对拍 | 旧判定和新判定并行，产生差异清单 | 差异逐条裁决并留档 |
| 3 逐点替换 | `type_equal` 改为 `ty_equiv`，公理区改为 `iface_ops`，索引、字段、match 和转换改用引擎 | 全套件、自举逐字节相同、差异归零 |
| 4 结束 | 删除旧分支、旧映射和双槽，单源化 | 同上，并完成单槽化 |

每步共同检查：

- 自举套件和 bootstrap 套件全部通过。
- `corec2` 和 `corec3` 的 `cmp` 结果相同。
- N06 为 0。
- 快速验证返回 42。

既有代码在新语义下不合法时，修改源码并逐处记录文件、用例、旧判定、新判定和原因。语义有争议时停下上报。

## 能力实现位置

### 定长退役

`[T; N]` 不再是原子构造子实例。语法保留为表示提示，携带 N 供实例使用。语义判定不看 N。

类型呈现是 `sequence<T>` 加长度约束项，按三档处理：

- 常量档在编译期判定。
- 符号档生成验证条件。
- 动态档生成运行时检查。

子类型关系是 `[T;N] <: [T]`。只读序列视图协变，可写视图不变。

### 泛型

```text
fn f[T]
fn f[T: I]
```

约束是类型项。实例化检查是 `ty_sub(实参, 约束)`，失败时给非空反例。

单态化时类型参数以类型项传递，不再使用文本字符串替换。实例去重使用类型项结构哈希，不使用字符串相等。

没有运行期字典。

### impl 和 interface

`interface I` 是形状类型项。`impl I for T` 是图上满足关系。满足判定走引擎。

方法解析查表，不再拼接名字。变型规则记录在条目内。

现有测试覆盖很少，需要新建 impl-for 正向、反向、多接口、泛型约束交互和错误例。

### 穷尽性和联合类型

`match` 穷尽性是补集空性，不再使用“定义了从不抛”的旧判定。失败时给具体反例模式。

枚举是 `sum` 类型项，变体乘 payload product。`T?` 和 Option 是 `T ∪ null`，不再依赖内建 Option 枚举名。

## 实现格式

`.ccr` 新增两段：

| 段 | 内容 |
|---|---|
| TYPE | 类型项表序列化，包括 DAG 的 tag 和子项，以及原子条目扩展 |
| IFACE | 原生、横切和用户条目，以及 impl 满足关系 |

`.ccr` 只支持当前版本，不设兼容层。旧版本整类拒收。

当前版本是 9。NOD 记录是 40 字节，增加 `item` 字段，表示 TYPE 段文件内项索引。`tk` 仍是派生码。装载时检查项存在，且 `atom_of(项)` 等于盘上码，不一致直接拒绝。

`corearch` 可以读回 TYPE 和 IFACE 段，重建类型项表，供 `atom_of` 和验证工具使用。

## 诊断和测试

诊断：

- 判定失败给出期望项、实际项和非空反例值。
- 穷尽性失败给出未被覆盖的具体反例模式。
- 预算超限给出“判定预算耗尽”诊断、建议和未覆盖面登记。
- 位置使用图节点到源码的映射。
- 错误码沿用现有体系，新增类型引擎、接口和穷尽性码段。

测试：

1. 引擎单元用例：子类型、等价、不相交、可空、穷尽性、递归、参数化、否定和最小反例。
2. 检查器行为：自举套件、bootstrap 套件、suite 和新增能力用例。
3. 对拍：影子差异清单归零后才允许替换。
4. 自举链：每阶段 `corec2` 和 `corec3` 逐字节相同，N06 为 0，快速验证返回 42。
5. 零回归：没有使用新能力的程序产物逐字节相同。
6. 收紧清单：每处“旧接受到新拒绝”都要记录。

## 不做项

- 不保留独立类型系统。
- 不保留旧 mangling 行为。
- 不引入运行期类型字典。
- 不引入 `rec` 关键字，递归环自动检测。
- 不为旧 `.ccr` 版本设兼容层。
- 不把尺寸和对齐放进语义层。
- 不在类型判定中处理执行、副作用和内存的命令式下限。
