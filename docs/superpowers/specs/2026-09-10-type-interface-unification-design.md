## 1. 语义基座

### 1.1 语义解释

- 类型项 τ 的语义 = 值集合 ⟦τ⟧；子类型 `A <: B` ⟺ ⟦A⟧ ⊆ ⟦B⟧
- 等价 = 双向包含；不相交 = ⟦A⟧ ∩ ⟦B⟧ = ∅
- **穷尽性 = 补集空性**：模式集 P 对域 D 穷尽 ⟺ ⟦⋃P⟧ ⊇ ⟦D⟧（判定实现为 `¬(⋃P) ∩ D` 的可空性）

### 1.2 类型项语法（内部表示）

```
τ ::= ⊥ | ⊤ | ⊤ₖ | τ₁ ∪ τ₂ | τ₁ ∩ τ₂ | ¬τ | μX.τ | X | k(τ₁…τₙ)
```

- `⊥` = 空集；`⊤` = 全集；`⊤ₖ` = 原子类 k 内的全集（如「任意 int 值」）
- `k` = 原子构造子：
  - **原生八员**：`int`（数学整数，无上限）`dex`（定点/指数族）`string`（字节序列）`bool` `unit` `never` `char` `dyn`
  - **结构构造子**：`product`（tuple / struct / 记录）、`sum`（enum / variant）、`sequence`（数组 / 切片）、`ref`、`ptr`、`fn`
  - **参数化命名**：`named<τ…>`（用户类型 + 泛型实参）
- `μX.τ` 绑定的递归 = 注册表引用图上的**环**（定案 10：无 `rec` 关键字，环检测自动；值递归自动拒绝 = 无限大小 → 编译错误，唯一必须存在的规则）

### 1.3 规范化与判定输入

- **DNF 规范化**：类型项规范化到 union of products（product = 原子 + 否定原子集合）；`⊤ₖ`/`⊥` 为规则内建项
- 判定算法输入 = 规范化形态；规范化结果按结构哈希缓存（见 §3.3）
- **声明式边界（定案 14）**：本层只碰声明式上限（类型/契约）；执行/副作用/内存的命令式下限（state edges / region / 调度）不动

## 2. 双轴接口注册表

### 2.1 本质轴（每原子构造子一条目）

条目字段：

| 字段 | 内容 |
|---|---|
| kind id | 原子构造子标识（与 `TYP_*`/`TI_*` 的对应见 §2.4） |
| 名字 / 语义域 | 如 `sequence` = 长度 + 元素集合；`int` = 数学整数 |
| 良构性规则 | 构造合法性（如 `sequence<τ>` 需元素项；`product` 需字段表；递归环可接受） |
| **操作许可** | 哪些 op 可作用（如 `+` 对 `int`/`dex`/`string` 合法）——**就地替代现状 `infer_expr:1397-1441` 的内联公理区** |
| 字面量定型 | 字面量 → 类型项（替掉 `infer_expr:1371-1376` 的内联 if 链） |
| 尺寸 / 对齐 | **标注为映射层 / hw-map 领域**（非语义；语义层不承诺布局） |

- **原生条目**（公理内建、用户不可实现）：`int` `dex` `string` `bool` `unit` `never` `char` `dyn`
- 用户类型（struct/enum/…）的条目 = 结构构造子的实例化（其「本质」由 `product`/`sum` 条目 + 其字段/变体项给出）

### 2.2 横切轴（结构自动判定，用户不声明）

- 每条横切接口 = **一个形状类型项**：满足判定 = 一条包含判定 `T <: 形状`（与引擎同一套判定，不另建规则体系）
- 初始条目：`序列接口` ⟺ `sequence<⊤>`（**待细化**为只读/可写两形状，见 §5.1 变型）｜`product` ⟺ `product<⊤…>`｜`可比较`｜`可索引`｜`可迭代`
- 只读/可写分野：只读视图**协变**、可写视图**不变**（变型规则落地点）

### 2.3 用户轴

- `interface I { … }` → 形状类型项：方法集 = `product` of `fn` 原子（方法签名各自为 `fn(τ₁…τₙ)->τ` 项）
- `impl I for T` → 图上「`T <: I`」的**满足关系**：入注册表 + 图上边
- 满足判定统一入口 `iface_satisfies(T, I)`（原生 / 横切 / 用户三类同入口）
- **mangling 废弃**：方法解析从「`Type.method` 字符串拼接查找」（现状 `find_func`/`type_has_method`）改为「类型项 + 接口条目」查表
- 旧语义不兼容窗口：**无**（用户裁决 5）——`impl` 语义按本节重定义，旧 mangling 行为不保留

### 2.4 与既有表的衔接

- **本质轴条目** ↔ 现有 `g_types`（24B/条 `kind/data/extra`）：`g_types` 保留为**原子条目层**（原子实例 + 用户类型 + 参数化模板头）；新增语义域/操作许可/字面量规则字段（扩展条目或旁挂规则表，实施批定布局）
- **横切/用户轴** ↔ 现 `g_ifaces`（1432B/条：name + 16 方法 × 88B）+ `g_impl_for`（16B：iface_ni, type_ni）：**升级**为「条目（形状类型项引用）+ 满足关系」，上限（16 方法 / 8 参数）随升级**解除或显式登记**
- **编号撞车清理（必办）**：现状 `TYP_GENERIC_PARAM=7 == TY_GENERIC_PARAM=7 == TI_DYN=7`、`TYP_GENERIC_APPLY=8 == TY_DEX_S=8`、`TYP_NAMED=1 == TY_DEX=1` 为纯数字撞车（`checker.cr:379` 靠巧合成立）——本轮**按命名空间分家**（`TYP_*` = 条目 kind / `TY_*` = 基类型码 / `TI_*` = 行号，或合并为单空间；实施批择一并记录）

### 2.5 统一查询 API（checker 唯一入口）

```
iface_kind_of(ti)            // 行号 → 原子 kind
iface_ops(kind)              // 操作许可集（替 72 处 == TI_* 直比）
iface_satisfies(T, I)        // 原生/横切/用户三类统一
iface_size(ti) / iface_align(ti)   // 映射层标注（语义层不消费）
iface_of_term(τ)             // 类型项 → 其本质 kind（若非单一原子 → 分解/⊥/⊤）
```

## 3. 类型项层与判定引擎

### 3.1 存储（分层）

- `g_types`（24B/条）= **原子条目层**（保留）
- 新增 `g_type_terms` = **类型项表**：定长条目 `{tag, a, b, c, d}`
  - `tag ∈ {BOT, TOP, TOP_K, UNION, INTER, NOT, MU, ATOM, VAR}`
  - `a..d` = 子项索引；`ATOM` 的 `a` = 原子条目行号（+ 参数项索引）
  - 类型项构成 **DAG**（共享子项 + 结构哈希去重 → 同一化免费）

### 3.2 判定 API 与算法

```
ty_sub(a, b) -> int      // 包含
ty_equiv(a, b) -> int    // 双向包含
ty_disjoint(a, b) -> int
ty_inhabited(a) -> int   // 可空性（穷尽性/反例用）
ty_witness(a, b) -> term  // 反例值（判定失败时给具体值示例）
```

- **算法**：DNF 规范化（union of products；product = 原子 + 否定原子集）→ 结构对照（product 覆盖判定 + **同类原子分解**：仅同类原子需展开子项）→ `μ` 展开用**假设-判定 memo**（递归判定标准做法）
- 判定失败时输出**非空反例值**（`ty_witness`）：如 `[int;2] <: [int;3]` 的反例 = 「长度为 2 的序列」

### 3.3 性能与诚实

- **记忆化**：`(a,b) → 结果` 判定缓存；规范化结果按结构哈希缓存
- **位集合快路径（路线 2）**：有界原子宇宙（枚举变体集 / 可选集 / 穷尽性）用位运算（先例：`g_dyn_type_sets` 64 位图；**须解除或显式登记 64 上限**）
- **判定步数预算守卫**：预算超限 → 显式诊断（见 §7），并登记「未覆盖面」——**不与「类型不兼容」混淆**

### 3.4 图标注承载（迁移期双槽 → 收尾单槽）

- **迁移期**：`irv_type`（原子 ti；后端/解释器读，**语义不变、零风险**）+ 新增 `irv_type_term`（完整类型项；前端/验证/载体读）
- **收尾**：单槽 = 类型项引用 + `atom_of(term)` 取原子（后端改动面 ≈ 20 处比较点，收尾批一并改）
- 理由：引擎未对拍完之前**不扰动后端**（后端现在只认 `TI_INT/TI_DEX/TI_STR` 基类型常量）

**收尾落地（R2 P5 Task 2，2026-09-13；✅ 已实施）**：单槽 = **类型面单源 + 辅码显式分离**（**非**「字段减一」——`tk` 是混用槽，同槽承载旗标/宽度等非类型信息，物理上不可减）：

- 布局（`dyn_arr.cr`）：`OFF_DF_TK`(40) 语义改为**类型项引用**（`g_type_terms` 行号；-1 = 无项）= **类型面唯一依据**；原 `OFF_DF_TK_TERM`(64) 更名 **`OFF_DF_AUX`** = 辅码（旗标/宽度/计数/不可逆行原码；0 = 无）；`ESZ_DFNODE` 保持 72B ⇒ **布局与版本位零改动**（`CCR_VERSION=8` · `CIR_CACHE_VER=17` · NOD 36B · `.cir` 快照 64B/节点）。
- **码 = 派生量**：`iri_tk` / `.ccr` NOD / `.cir` 快照一律 `sh_dfn_code_of_slots(项, 辅码)`（emit / `lower_to_ccr` / 装载侧**单源**）。**分类表**（`ty_shadow.cr`：`sh_tk_is_type_face` / `sh_tk_face_of_code` / `sh_tk_split(_load)` / `sh_atom_of_term`）= 唯一分类出处：类型行面 = `{IR_CONST, IR_BINARY}` ∪ P4 六排除项再裁 `{IR_ALLOC, IR_CALL, IR_LOAD, IR_I2F, IR_F2I}`（P4 排除理由「后端不按 ti 分派」= **发射面**判据，不适用于**语义**类型面）；辅码面 = `{IR_BOUNDS_CHECK, IR_DEREF, IR_STORE_PTR, IR_SPAWN, IR_HOTPATCH_ROUTE}`；其余无面。
- **可逆行判据**：分类表只覆盖**原子行**（`atom_of(项) == 行号`）；**复合行**（ptr/ref/array/slice/optional/null/tuple）**不建项**（`term=-1`，不近似），原码进**辅码槽保真** ⇒ 派生码逐字节 ≡ 旧混用码。
- **两条不变量**（D22）：① 派生码 ≡ 旧值（94 档 338,207 节点逐节点 diff，仅 F1 的 3 节点 = 已裁决偏差）；② 两槽互斥。
- **D23 闸**：类型面行不可译 ⇒ `ccr_seg_prepare_save` 拒绝落盘（rc=1 + 诊断）；**仅 emit 路径**计数（暖进程类型表可小于冷态 ⇒ 装载侧重派生不计数，缓存命中绝不误拒）。
- **稳定引用形态（D20 规范，立即生效）**：本批**不引入任何跨进程项引用**——凡跨边界者一律派生码；未来需要时唯一许可形态 = **TYPE 段文件内项索引**；**禁令**：进程内项表索引不得跨进程/跨复位边界（`bad_term=329` 红证）。
- **β（盘面项索引 + corearch `atom_of` 读回）推迟 P6**（P5 计划裁-1：β = 新能力而非收尾，无在野消费者）；**登记**：缓存命中跳过 `ir_gen` ⇒ 暖态类型/项表可**小于**冷态，越出暖表处项不可重建（`term=-1`）——派生码面/发射面/盘面零影响，根治 = β。
- 判据（P5 T2/T7 实跑）：`selftest-types` +12 例（终值 404/404）· `test_ccr_types` 34→**40** · ELF canary IDENTICAL · `.ccr` 两套形式四条与 P4 记录逐字节同 · `--dump-objects` 逐字节同（`generics_test` 两种形式 3521 行；P4/T2 期的 2427 行为当时语料与约定）· 突变控制 4 条（T2）+ 2 条（T7 网复核）。详见 `plans/2026-09-13-r2-p5-cleanup.md` Task 2/7。

## 5. 能力落点

### 5.1 定长退役（R1 裁决的兑现）

- `[T; N]` **不再是原子构造子实例**；语法保留为**表示提示**（映射参数层，携带 N 供实例消费——`type_size`/`arr_len_lit_of` 继续读它，**语义判定不看**）
- 类型呈现 = `sequence<T>` + **长度约束项**，档位按 F11 三档：
  - 常量档（N 字面量）→ 判定编译期定（恒真/恒假）
  - 符号档 → VC 义务（验证管线消费）
  - 动态档 → 运行时检查
- 子类型：`[T;N] <: [T]`（长度约束更强者为子类型）；**变型**：只读序列视图协变、可写视图不变
- 改造点（现状消费面，侦查已定位）：`checker.cr:110-119`（身份判等分支）**删除**；`:2080-2089`（F2 字面量越界）改读长度约束；`:2062-2075`（F11 切片界）升级为约束项；`ir_gen.cr:120-135`（`arr_len_lit_of`）与 `:476-480`（`type_size`）**保留**（表示提示层）
- 自举源码 10 处 `[T; N]` 用法**零改造**（R1 已注记；表示提示语义不变）

### 5.2 泛型 = 编译期接口具体化

- 声明：`fn f[T]`（约束 = `⊤`）/ `fn f[T: I]`（约束 = 类型项 `I`）；**结构/枚举泛型补上约束**（现状仅函数泛型有 `g_generic_constr`）
- 实例化检查 = `ty_sub(实参, 约束)`；失败给非空反例
- monomorph 升级：类型参数以**类型项**传递（现状 `gen_build_subst` 的**纯文本字符串替换** → 类型项替换）；实例去重 = 类型项**结构哈希**（现状 `istr_eq` 字符串相等去重，脆弱）
- 无运行期字典（定案 6）

### 5.3 impl/interface 重定义（用户轴）

- `interface I` = 形状类型项；`impl I for T` = 图上满足关系；满足判定走引擎
- mangling 废弃（`type_has_method` 从名字查找 → 表查询）；变型规则记条目内
- 现状**零测试覆盖**（`test_impl.py` 5 例全为固有方法、`interface` 零命中）→ **新建覆盖集**（impl-for 正向/反向/多接口/泛型约束交互/错误例）

### 5.4 穷尽性 + 联合/可选

- `match` 穷尽性 = 补集空性（`EC_TM_EXHAUST`：从「定义了从不抛」→ **真判定**）
- enum = `sum` 类型项（变体 × payload product）；`T?`/Option = `T ∪ null`（**不再依赖内建 Option 枚举名**——现状 `checker.cr:591-599` 自动注册内建枚举的做法退役）
- 反例给**具体值**；有界变体集走位集合快路径

## 6. 载体（设计全、实施分期）

### 6.1 `.ccr` 新增段（v7 格式扩展）

| 段 | 内容 |
|---|---|
