# Core 源码全量伪代码翻译设计（TDD + 形式化基础）

日期：2026-08-08
状态：已获用户逐节认可

## 一、背景与目标

将 Core 语言全部 `.cr` 源码（56 个文件，19,749 行）翻译为**无任何编程语言关键字的汉语伪代码**，每文件一个 markdown 文档，镜像源码目录结构。

用途（按优先级）：
1. **TDD 主导**：伪代码内嵌每个函数的「测试要点」，作为后续编写测试的行为依据
2. **形式化基础**（远期）：伪代码必须信息完整、无歧义，之后要支撑完全形式化（`.csp`/`.csr`/`.corespec` 方向）

## 二、范围

**翻译对象**（`src/` 下全部 `.cr` 文件，共 56 个）：

- `src/compiler/*.cr`（29 个）
- `src/stdlib/*.cr`（18 个）
- `src/runtime/*.cr`（2 个：`rt.cr`、`arena_globals.cr`）
- `src/arch/linux/ld/*.cr`（7 个）

**明确排除**（在 README 中注明）：`rt.s`（汇编）、`rt.ccr`（编译产物）、`bootstrap.c`/`compiler_rt.c`（C 代码）、`tests/`、`examples/` —— 均非 Core 语言源码。

**大文件拆分规则**（用户补充要求，2026-08-08）：源文件 ≥800 行时，其伪代码拆为多个部分文档 `<源名>-<序号>.md`（序号从 1 连续），每部分覆盖一个逻辑相关的函数组，伪代码量约 400-600 行；每部分独立使用下方骨架；拆分不改变全量逐语句要求。命中拆分：`parser`（4 部分）、`checker`（5 部分）、`ir_gen`（4 部分）、`arch/elf`（4 部分）、`instr`（3 部分）。文档总数：56 源文件 → 71 个 .md。

## 四、翻译约定

### 4.1 关键字替换表

| 源码 | 伪代码 |
|------|--------|
| `if` / `else` | 如果 条件，那么：… / 否则：… |
| `else if` | 否则如果 条件，那么：… |
| `while` | 循环（当 条件 成立时）：… |
| `for` | 对 集合 遍历（每次取 元素）：… |
| `break` / `continue` | 跳出循环 / 继续下一次循环 |
| `return` | 返回 |
| `match` | 匹配 值：… 分支 值，那么：… |
| `fn` / `struct` / `enum` | 函数 / 结构 / 枚举 |
| `:=` / `: type =` | 令 名字 = 值（声明） |
| `mut` / `pub` / `import` | 可变 / 公开 / 引入 |
| `true` / `false` / `None` | 真 / 假 / 无值（None） |
| `and` / `or` / `not` | 且 / 或 / 非 |
| `==` `!=` `<` `<=` `>` `>=` | 等于 / 不等于 / 小于 / 不大于 / 大于 / 不小于 |
| `+ - * / %` 及位运算 | **保留符号**（语言中性的通用符号） |
| 源码注释 | 译成中文，保留在对应位置 |

### 4.2 标识符规则（首次中英对照）

- 所有标识符（全局、函数、结构、枚举、字段、局部变量）译成中文语义名；**首次出现**写作 `中文名（原名）`，之后只用中文名
- 共享标识符（`g_*` 全局、公开函数、结构名）必须以《标识符对照表》为准，**禁止自造**
- 内置类型：整数（`int`）、字符串（`string`）、布尔（`bool`）、字节（`byte`）、浮点数（`float`）；自定义类型按标识符规则

### 4.3 格式约定

- 4 空格缩进，嵌套层级与源码一一对应
- 条件块：`如果 条件，那么：` 后换行缩进；`否则：` 同层
- 循环：`循环（当 条件 成立时）：` 或 `对 列表 遍历：`
- 解引用/取地址 → `解引用（*ptr）` / `取地址（&x）`
- 赋值 → `令 名字 = 值`
- **禁止模糊词**（"适当地"、"相应地"、"处理"等无信息量表述）；每个分支/循环条件必须写全，包括边界情况
- 伪代码正文禁用英文关键字与 `{` `}` `;`

### 4.4 示例

```
函数 检查赋值（check_assign）：
    如果 目标 是全局变量，那么：
        返回
    否则：
        如果 目标 是局部变量 且 目标 未声明，那么：
            报告错误（报错位置："未声明的变量"）
            返回 假
        否则如果 目标 已冻结，那么：
            报告错误（报错位置："试图给不可变变量赋值"）
            返回 假
```

## 五、详细程度与测试要点

**全量逐语句翻译**（用户修订，2026-08-08）：所有函数均逐语句展开为缩进式伪代码，不做概括；仅空文件与纯引入文件（`entry.cr`、`_import.cr`、`linker.cr` 等）可两三句话带过。理由：之后要做完全形式化，信息不可省略。

**作用说明**（用户补充要求，2026-08-08）：每个函数节除伪代码与测试要点外，必须有 `### 作用` 小节——用自然语言说明该函数的职责、在编译管线/模块中的位置、输入输出语义。与逐语句「逻辑」区分：作用是"为什么和干什么"，逻辑是"怎么做"。

**测试要点**：每个函数下方 `### 测试要点`，编号列表（不用 emoji），内容包括：
- 边界条件（空输入、最大/最小值、溢出、未初始化）
- 代表性输入 → 预期输出
- 错误路径（报错位置、返回值、部分结果）
- 状态转换（全局变量的变化）
- 简单函数 1-2 条，复杂函数可到 5-8 条

## 八、质量控制与完成标准

4. **完成标准**：71 个 `.md` 全产出（56 源文件全覆盖，含 5 个大文件拆分）+ 上述校验通过
