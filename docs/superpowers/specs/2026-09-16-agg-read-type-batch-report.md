## 2. 根因与修法

**根因**：聚合槽的**规范存储形式恒为精确（scaled）**（apx 批不变量「聚合面不存在 apx 形式」，写点漏斗 `dex_slot_norm` 保证），
但四个读点把结果槽**硬定 `TI_INT`**：字段读 `ir_gen.cr:2590` · 元素读 `:2655` · match 臂载荷 `:2393` · match 结果槽 `:2299`
⇒ 「按 IR 值型触发」的下游全部失明（`dex_store_adjust` / `dex_scale_int` / 二元分流 / extern 边界 / LET 继承 / 泛型键名串）。

**修法（裁-AGG-1 ①）**：读点定型取**声明面形式**——4 个**节点级零 alloc** helper：

| helper | 声明面来源 | 手段 |
|---|---|---|
| `agg_read_form_is_dex` | — | `ast_kind(tn)==0 && ast_type_val(tn)==TY_DEX`（**不调** `res_type_node`）|
| `agg_field_read_form` | 结构体字段类型节点 | `find_struct` + `si_field_type_node` + 节点判；数字元组下标 ⇒ `TI_INT` |
| `agg_elem_read_form` | 数组/切片的元素 ti | `elem_ti_of_decl(slot_decl_ti(arr))` **纯表读**；`TI_DEX`/`TI_DEX_S` 均归一 `TI_DEX_S` |
| `agg_payload_read_form` | 枚举变体载荷类型节点 | `find_gsym`+`find_enum_row_of`+`ei_variant_type_node` + 节点判 |

接线 3 读点：字段读（`fi` 解出后 `irv_set_type`）· 元素读 · match 载荷绑定。**非 dex 形态恒 `TI_INT`** ⇒ 非 dex 程序**逐字节不变**。

**为何不直接取完整类型**：`res_type_node` 对命名/聚合/指针类型会 `alloc_type`（GC12′）⇒ 只用 **dex 轴二值**判定；
且 `TI_DEX_S` 是**预置常量**（非新分配的类型行）。

## 7. 方法学 · **GC12 的自我修正顺序**（维护者指定必写）

侦查时发现：`ir_gen.cr:2455` **今天已有**非 optrep 门控的 `res_type_node`（带注解 LET），且 `res_type_node` 对
**基类型节点**走 `ty_code_to_ti`（`iface_registry.cr:274`）是**纯查表零 alloc**，只有命名/聚合/指针类型才 `alloc`。
⇒ 把 GC12 从「不得新增 `alloc_type` 站点」**收紧为**「**不得新增可能 alloc 的类型站点**」（更准），
**然后仍然不用它**（本批一律走节点判 + 纯表读）。

> **顺序本身就是方法**：**先把规则改准，再决定用不用**——若先按粗口径办事（「res_type_node 一律禁止」），
> 会误伤正确的路径；若先松后紧（「反正基类型不 alloc 就随便用」），则会漏掉聚合/命名类型的 alloc 面。

## 11. 判据可行性经验（工具链能不能表达 X）

**不是「想断言 X 就写 X」，而是先确认工具链能不能表达 X**：本轮想直接断言「读槽型 = `TI_DEX_S`」，实核发现

- `.cir` 文本转储**不打印普通 IR 变量类型**（`dump.cr:50-60` 的 `type_kind_name` 只在 `alloc`/`const` 行输出）；
- 且 `TI_DEX`(1) 与 `TI_DEX_S`(8) 在该表**同名 `"dex"`，不可区分**；
- 权威通道 = `.ccr` SYM 的 per-var 型字节（`ccr_io.cr:690`），但需自写二进制解析。

⇒ 改成**门控忠实见证**：`dex_scale_int`（门 = `irv_type(var) == TI_INT`）的唯一产物 `binary _dxt = …` 出现 ⇒ 读槽仍是 int；
`dex_scaled_to_bits`（门 = `irv_type(var) == TI_DEX_S`）的非字面量产物 `binary _dxdiv = …` 出现 ⇒ 读槽已是 scaled。
**见证的门恰好就是我们要断言的类型谓词 ⇒ 忠实**；两条合起来同时覆盖「**槽型正确**」与「**无重复转换**」（维护者指定的两条验收）。
（`.ccr` SYM 解析列为可选加固，未做。）
