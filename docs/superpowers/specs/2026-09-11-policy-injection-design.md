# 注入族策略设计

## 概述

本设计把“不可信数据到达解释器语法位”变成非法边。

```text
值位合法
语法位非法
参数化通道合法：结构由库的类型化构造器给出，数据走值位
```

检查的第一性来源是构造器封闭：库声明的形状项只能由库自己的构造器产生，不是污点传播。污点属性只在“未包装 API 的裸位置”这一备选路径上使用，属于属性轴基础设施，不是本族自建的第二套体系。

设计状态：定稿，尚未实现。修订记录、决定编号和自检见 `docs/superpowers/implementation/2026-09-11-policy-injection-audit.md`。

## 语法位和值位

位置 π 是领域 D 的语法位，当且仅当下游解释器 D 会对 π 处的字节做分隔符或结构再扫描。字节中出现 D 的元字符会改变 D 对结构的判断。否则 π 是值位。

| 位置 | 再扫描 | 种类 |
|---|---|---|
| `execve` 的 argv 元素 | 否，内核按 NUL 边界取整段 | 值位 |
| `sh -c` 的命令行 | 是，`;`、`|`、`$()` 和空白会分词 | 语法位 |
| SQL 绑定参数 | 否，协议按长度把值传给引擎的值槽 | 值位 |
| SQL 查询文本 | 是，`;`、`'` 和 `--` 会改变结构 | 语法位 |
| HTML 元素体文本节点 | 否，解析器到这里已经按文本节点处理 | 值位 |
| HTML 属性值、URL、内联 JS | 视上下文，引号、`&`、`:` 和 JS 元字符会改变结构 | 语法位 |
| HTTP 头字段值 | 是，CRLF 是分隔符 | 语法位 |
| 长度前缀协议的载荷 | 否 | 值位 |

这个定义只能由库声明，不能由编译器推断。它描述的是下游解释器的性质，编译器看不到下游。语言不内建任何领域的元字符表。

## 合法性关系

记号：

- `τ(v)`：值 v 的类型项。
- `trust(v)`：v 的可信度标注，由推导产生。
- `φ`：位置 π 声明的形状类型项。
- `κ`：附着在 φ 上的档位约束，分常量档、符号档和动态档。

合法性：

```text
Legal(v, π) 等价于
    位置是值位，结果为真
  或位置是语法位(D, φ)，ty_sub(τ(v), φ) 为真，并且档位约束 κ 满足
  或位置是裸语法位(D)，可以证明 Trusted(v)
```

非法边是不存在可构造的合法语义边。拒绝的原因是图不完备，不是“边存在后再加运行期守卫”。

判定统一写成：

```text
ty_sub(τ(v) ⊓ trust(v), Shape(π))
```

`Shape(π)` 由 policy 数据给出：

- 值位：`⊤`，恒真。
- 语法位：`φ` 加档位约束。
- 裸语法位：该策略的 `Trusted` 形状项。

判定失败时用反例值给出具体诊断，例如“值 X 来自 `io.read_file`，不是 `SQL<Structure>`”。

### 防止判定退化

`trust` 的展开必须是加约束式单调展开。可信映射为 `Trusted`，不可信映射为 `⊤`，不加约束。属性要求写在右侧 `Shape(π)`。

如果 `trust` 用否定形式展开，例如不可信映射为 `¬Trusted`，左侧值项和否定属性项求交可能变成 `⊥`。`⊥` 包含于任意形状，判定会对所有位置放行。这是结构性风险，必须用 S-A 的五条健全性约定堵住：

- `Shape(π)` 在语法位和裸语法位不得为 `⊤`，装载期拒绝。
- 每个轴取值必须有非退化正例，例如 `Trusted ⊓ string ≠ ⊥`。
- 判定为假是违法，无法判定归入 3 或 4，两者必须分因。
- 未定义原子取 `unknown`，不能取真。
- 否定形式展开必须有负向对照，断言不放行。

无法判定时不能当作通过。预算耗尽和未覆盖面按 S-A 决策树归入 3 或 4，并登记。

检查只读 `τ(v)` 和 `trust(v)` 两处标注，与值的定义路径、别名和中间传递无关。把不可信字符串存进结构体、经函数返回或经容器移动，都不会改变它到不了语法位这一事实。这是形状项检查相对污点分析的结构性优势，也是控制流校验不能绕过检查的原因。

这个论证依赖图的边和区域覆盖全部语义依赖。该前提需要独立的依赖完备性审计，覆盖率报告没有缺失项之前不启动实现。

## 构造器封闭

`φ` 是库声明的形状类型项。满足 `φ` 的值只能由声明返回 `φ` 的构造器产生。

类型层封闭自动成立：任何 `fn f(...) -> φ` 的函数体如果返回非 `φ` 的值，会被普通返回类型检查拒绝。凭空造一个 `SQL<Structure>` 在类型层做不到。

数值层封闭需要策略给出。如果 `φ` 的某个构造器同时接受不可信来源可以满足的类型，例如 `string`，它就是开口。策略必须二选一：

1. 给构造器附档位约束。解析式位置使用常量档，动态实参不满足。
2. 把构造器登记为净化节点，并附带后置条件义务。

Core 当前不强制 `pub`，库外代码可能构造 `φ`。因此封闭性依靠受控命名空间和装载期校验：形状项和根声明只在受控命名空间内有效。谁有权声明形状项或根，记入 policy 面，装载器可见。库外伪造在装载期被拒绝，不再依赖运行期约定。

结论：“不可信数据不能到达语法位”的原因不是追踪，而是语法位的类型里没有一条从 `string` 出发的边。唯一存在的边由库把守。库的边要么带常量档，要么是一处显式、可审计的净化节点。

`string` 不变。它仍是原生类型，不拆成 `Trusted<string>` 和 `Untrusted<string>`，既有签名零改动。不可信性是一处推导标注和一条形状项检查：`string` 不包含于 `SQL<Structure>`。

## 领域库接口

库只声明三件事：

1. 未包装的语法位。
2. 不可信来源函数集。
3. 净化节点及其后置条件。

构造器不需要在策略里声明。返回 `φ` 的函数就是构造器。这是策略面最小的关键。

这些声明是 S-A policy 条目中 source 声明集、sink 声明集和 declassify 通道三栏的填法。声明走 policy 数据表和既有插件标签通道，不新增声明语法。

示意结构：

```text
shape  D<Ph>            形状项，Ph 是阶段或上下文参数
ctor   ... -> D<Ph>     构造器，返回形状项即成立
src    fn_name          返回不可信值的来源函数
pos    fn:slot ...      语法位声明，只用于未包装 API
decl   fn -> Trusted    净化或降密节点，可带后置条件
```

### SQL

下游是数据库引擎的 SQL 解析器。元字符 `;`、`'`、`--` 和 `/*` 会改变结构。

形状项是 `SQL<Ph>`，`Ph` 可以取 `Text`、`Structure`、`Frag` 和 `Param`。

解析式表示：

```text
sql_text(lit: string) -> SQL<Text>
```

`lit` 带常量档约束，查询文本必须是编译期已知的常量。动态字符串不满足，编译期拒绝，不是运行时验证。

结构式表示：

```text
sql_select(cols: [SQLFrag], from: TableRef, where: Cond) -> SQL<Structure>
sqlfrag(x: SQL<Frag>) -> SQL<Frag>
SQL<Frag> + SQL<Frag> -> SQL<Frag>
sql_param[T](v: T) -> SQL<Param>
SQL<Frag|Structure> + SQL<Param> -> SQL<Structure>
SQL<Structure> + SQL<Structure> -> SQL<Structure>
```

输出点：

```text
sql_exec(q: SQL<Structure>, binds: [SQL<Param>])
```

`q` 是语法位，类型本身就是形状项，检查自动成立。`binds` 是值位，使用 prepared bind，不可信数据可以合法搭载。

库不提供 `db_raw_exec(text: string)` 这类整串文本执行 API。如果某个库坚持提供，策略必须把该槽声明为裸语法位，检查退到属性面。

来源包括 `io.read_file`、`cli.argv`、`net.recv` 和 `os.get_env`。

### HTML

下游是 HTML 解析器。元字符包括 `<`、`>`、`&` 和引号。上下文很重要：元素体、属性值、URL 和内联 JS 的规则不同。

形状项是 `HTML<Ctx>`，`Ctx` 可以取 `Text`、`AttrValue`、`URL` 和 `Elem`。JS 上下文单列为高危子形态，默认不进入允许清单。

```text
html_text(s: string) -> HTML<Text>
html_attr_value(s: string) -> HTML<AttrValue>
html_elem(tag: Tag, attrs: [Attr], children: [HTML<Text>]) -> HTML<Elem>
html_parse(lit: string) -> HTML<Elem>
```

`html_text` 把字符串放进元素体文本节点这个值位。`html_elem` 的 `children` 要求 `HTML<Text>`，直接传 `string` 是非法边。

`HTML<AttrValue>` 对 URL 上下文不安全，因为 `javascript:` 是合法的属性值文本。库需要为 `href` 另立 `HTML<URL>` 并提供 URL 校验构造器。粒度不足是库的规格错误。

### shell

下游是 `/bin/sh -c` 的整行。元字符包括 `;`、`|`、`&`、`$()`、反引号和空白分词。

argv 形态是值位：

```text
sh_run(prog: Sh<Prog>, args: [Sh<Arg>])
sh_arg(s: string) -> Sh<Arg>
```

`sh_run(sh_prog("ls"), [sh_arg(read_file("p.txt"))])` 合法。内核不解析参数。argv 值位只保证不改变结构，不保证参数语义安全，选项注入不在本族检查范围内。

文本形态是语法位：

```text
sh_text(lit: string) -> Sh<Text>
sh_quote(s: string) -> Sh<Quoted>
sh_run_text(c: Sh<Text|Quoted>)
Sh<Text> + Sh<Quoted> -> Sh<Structure>
```

`Sh<Quoted>` 和 `Sh<Text>` 的区分防止把未引用片段拼进来。

裸位置是唯一必须退到属性检查的地方。libc 的 `system(cmd)` 和 `popen(cmd)` 参数是 `string`，库无法重新定型：

```text
pos syntax_raw(sh) system:0
pos syntax_raw(sh) popen:0
```

`system("ls -l")` 的常量可以证明 `Trusted`，通过。`system(read_file("x.sh"))` 拒绝。本仓库的 `src/stdlib/os.cr` 中 `system(cmd: string)` 就是这类输出点。

### 其他领域

`fmt` 格式串、`ld` 路径段、HTTP 头、JSON 键名和字符串、regex 模式文本、`LD_PRELOAD` 都使用同一检查，只是领域 D 和形状项 φ 不同。编译器代码路径零增长。新增领域只需要库新增策略数据和形状项声明。

## 净化和降密

### 净化是位置化

库的净化构造器不做“从字符串里删掉危险子串”的语义，而是把不可信值放进下游解释器当作数据使用的位置，并把这个事实写进返回类型项。

- `html_text(u)` 表示 u 被放进元素体文本节点这个值位。
- `sh_quote(u)` 表示 u 被放进单引号片段，shell 分词器到这里不再切分。
- `sql_param(u)` 表示 u 走 bind 协议进入引擎的值槽。

净化的正确性条件是位置声明的正确性，不是正则写得对不对。HTML 的例子说明位置声明的粒度决定精度。

### declassify 节点

`declassify` 是唯一合法通道。本族有三条约束：

1. 必须显式成节点。合法通道只有两类：类型变化的位置化构造器，以及同型放行的 `declassify`。两者在图上都是节点，不是标注，也不是 pragma。
2. 可审计。节点进入诊断面、义务清单面和产物面，并进入 `core explain` 决策通道。不可信数据从哪里进入、经过哪次放行、在哪里停止，可以用一条命令回答。
3. 产生义务，不是免除义务。`declassify` 声明库的后置条件，义务是证明后置条件成立，归入 proof-required。不能因为“它是库给的”就当作通过。

### 禁止隐式降密

控制流上的校验不构成净化：

```text
if is_valid(s) {
    sh_run_text(sh_text(s))
}
```

`s` 仍然是 `string`，不是 `Sh<Text>`，因此仍然拒绝。检查在类型项上，不在控制流上，所以不存在“校验函数没有建模”“校验的是另一个东西”“校验被短路”这类绕过。

如果库希望让某个校验器真正放行，唯一途径是把它声明为净化节点，显式、可审计、带后置条件义务。校验器如果证不出，义务归入 proof-required，不是本族的失败。

净化节点产出的是新类型项，不是新属性。`html_text: string -> HTML<Text>` 成立的原因是返回类型，与 `trust` 标注无关。裸位置没有构造器可用，因此那条路径只有 `declassify` 或改用已包装 API。这个不对称是刻意的：类型检查优先，属性检查是备选方案。

## 与既有机制的关系

### 类型引擎

位置形状项是类型项，检查使用 `ty_sub`。形状满足使用 `iface_satisfies`。失败诊断使用 `ty_witness`。常量档使用已有的档位约束机制。不新增判定体系。

### string 的渐进引入

| 档 | 状态 | 检查 |
|---|---|---|
| 0 现状 | 没有策略和声明，因此没有义务 | 产物逐字节相同 |
| 1 审计 | 加载库策略，只报告不拒绝 | 产出审计清单，产物相同 |
| 2 库级强制 | 声明了语法位就拒绝，默认模式 | 正向通过，负向拒绝，回归通过 |
| 3 高安全 | 无法判定或证不出就拒绝，`unsafe` 和 FFI 需要显式证明 | 未覆盖面登记，不能无提示 |

`string` 本身、既有函数签名和既有库调用在四档中都不变。变的是是否存在声明的语法位，以及未处置义务的处理方式。

### 与 S-A

本族是 S-A 的第一个使用者，只使用不定义：

- 使用 `trust` 轴做裸位置检查。
- 使用四档决策树。
- 使用 policy 条目。
- 使用诊断和清单通道。

### 与 S-B2

“能否执行 SQL”是授权，“文本能否进入 SQL 语法位”是本族。两者正交。一次 `sql_exec` 可以授权完备但存在非法边，也可以文本合法但未授权。不能用本族检查替代授权。

### 与 S-B3

本族使用 `trust` 轴，防止坏结构进入解释器。S-B3 使用 `secrecy` 轴，防止秘密流出。检查方向相反。本族不受控制流影响，S-B3 需要登记隐式流。

### 与 S-B4

路径段既是语法位，也是限制。本族检查“不可信字节不能拼进路径语法位”。S-B4 检查“无法构造指向根之外的 capability”。`Path<Root>` 和形状项使用同一机制，边界在于谁声明：路径结构的语法正确性归本族，根约束归 S-B4。

## 义务归入档位

| 情形 | 档位 |
|---|---|
| 值位实参 | 无义务，`Shape` 为 `⊤` |
| 判定为真 | 1 prove，零成本 |
| 常量档解析位，实参是编译期常量 | 1 prove |
| 常量档解析位，实参不是常量 | 违法 |
| 语法位，实参不满足形状项 | 违法，任何档位都拒绝，唯一放行是净化节点 |
| 语法位，无法判定 | 3 proof-required，严格模式 4 reject |
| 裸位置，无法证明 `Trusted` | 3 或 4；如果库提供全函数校验器且 policy 允许，可以 2 enforce |
| 净化节点的后置条件 | 3 proof-required |
| 符号档位置约束 | 3 proof-required |
| 库提供全函数校验器 | 2 enforce |

强制档的失败语义默认是硬陷阱中止。`degrade` 只允许指向库的净化构造器，即“校验失败后改走 `html_text` 或 `sh_quote` 这类声明过的节点”。转义正确性是库的规格。如果允许应用侧自写转义，策略面会被搬回语言面，并制造一条没有清单条目的隐式放行。

## 最小切片

切片范围是：一个领域、一个形状项、三个构造器、一条检查、一组正负向对照。不引入属性推导、参数化判定和验证条件。

| 项 | 内容 |
|---|---|
| 领域 | SQL |
| 形状项 | 单一形态 `SQL`，非参数化 |
| 构造器 | `sql_text(lit)` 带常量档，`sql_param[T](v)`，`SQL + SQL -> SQL` |
| 输出点 | `sql_exec(q: SQL, binds: [SQL])`，槽 0 是语法位 |
| 来源 | `io.read_file` 和 `cli.argv`，只用于诊断和清单 |
| 检查 | `ty_sub(τ(实参), SQL)` 加常量档 |
| 接入点 | 调用实参槽，进入引擎判定，再产生诊断或清单 |
| 依赖 | 类型引擎已就位；形状项建表；常量档通用化；S-A 的 policy 注册、诊断清单和装载校验；依赖完备性审计无缺失项 |
| 不依赖 | 属性标注和传播、参数化原子判定、验证条件、类型接口的后续接线 |

正向对照：

1. `sql_exec(sql_text("SELECT 1"), [])` 通过。
2. `sql_exec(sql_text("SELECT * FROM t WHERE x = ?"), [sql_param(read_file("u"))])` 通过，不可信值走值位。
3. `sql_exec(sql_text("..."), [sql_param(42)])` 通过，类型参数实例化。

负向对照：

1. `sql_exec(read_file("q.sql"), [])`，不可信字符串直落语法位。
2. `sql_exec(sql_text(read_file("q.sql")), [])`，常量档不满足。
3. `sql_exec(sql_concat(sql_text("SELECT * FROM "), runtime_string), [])`，拼接路径试图引入字符串。
4. 实参判定无法完成时，归入 3 或 4 并登记。
5. 否定形式展开不得放行；`Shape` 为 `⊤` 的策略在装载期拒绝；非退化正例必须通过。

检查：

1. 没有加载策略时，全部产物逐字节相同。
2. 负向对照全部拒绝，错误码落在语法位检查段，不是普通类型不匹配。
3. 正向对照全部通过，不可信值不产生附加检查代码。
4. 编译器侧不存在 `sql`、`html`、`sh` 这些领域标识符。新增领域只需要策略数据和形状项声明，代码零增长。
5. 全套件、自举比较和快速验证按共同检查行执行。

## 不承诺

1. 错误的 specification。Core 只能证明程序忠实实现了规则，不能证明规则本身正确。库可以把值位误声明为语法位，造成过度拒绝；也可以漏声明语法位，造成漏保护；还可以把 `HTML<AttrValue>` 用在不安全上下文。缓解方式是声明随库分发、可审计，并按再扫描检查逐条自查。
2. 恶意或失陷的外部实体。供应链、编译机、密钥和硬件后门不能用语言语义证明。本族对应的具体形态是库的实现，包括数据库驱动、HTML 转义函数、`sh_quote` 和 FFI 边界之后的代码。本族能做的是让每一处放行显式成节点、把净化正确性变成记录中的义务、不把“库说了算”伪装成“语言证明了”。
3. 需求本身允许危险行为。shell、浏览器、内核和 JIT 必须执行外来代码。本族证明的是隔离边界：不可信值以数据身份到达解释器，结构只能由库的构造器产生。这不等于“shell 安全”。

附加边界：

- 值位不等于语义安全。argv 值位只保证不改变结构，不保证参数语义无害，例如 `rm -rf` 的选项注入和 `--` 终结符约定不在检查范围内。
- 编码层混淆不在检查内。非法 UTF-8、Unicode 规范化、同形字和大小写折叠改变的是字节解释，不是结构再扫描。这些归库的构造器和编码层议题。
- 引擎无法判定时保守拒绝并登记，不承诺所有程序都能判定。
- 本族判定不替代授权、限制、信息流和密码学机制。

## 不做项

- 不做语言内建的 source、sink、领域关键字或漏洞类别特判。编译器不知道 `sql`、`html`、`sh` 这些字符串是领域标识。
- 不做完整污点分析作为主要检查。主要检查是形状项包含。
- 不做转义正确性证明，这是库的责任。
- 不做流敏感或别名分析，不需要。
- 不做各语言语法模型内建，元字符表、SQL 文法和 HTML 上下文规则全部归库。
- 不做运行时转义作为默认处理。
- 不在本族定义 `integrity`、`secrecy` 和 `authority` 轴的用法。
- 不改 Graph 本体，不加关键字，不动命令式下限。

## 开放问题

| # | 问题 | 状态 |
|---|---|---|
| 1 | 构造器封闭性的强制手段 | 装载期校验加 policy 授权，受控命名空间加声明权登记 |
| 2 | 属性项的展开约定 | 使用 S-A 的五条健全性约定，不二次设计 |
| 3 | 常量档的通用化范围 | 声明面使用 policy 数据表；判定侧改动是切片硬前置 |
| 4 | 隐式降密的通道 | 不允许。唯一放行是 `kind=declassify` 条目 |
| 5 | 策略的携带形态 | 随 `.ccr` 的 POLICY 段，随格式批次实现；过渡期随编译输入 |
| 6 | 跨领域组合语义 | 一个领域的输出成为另一个领域的输入时，位置化类型项如何参与后续检查，待定 |
| 7 | 与 S-B4 的路径重叠 | 需要统一的分工检查 |
| 8 | 未包装 API 的规模 | 是否允许在审计档下自动推断候选裸位置并生成清单供人工决定，需要论证不会产生自动特判 |
| 9 | 错误码段和清单格式 | 由 S-A 和 S-D 统一分配 |
