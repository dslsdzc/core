## 背景：现状问题

`docs/language-syntax.md`（701 行、13 章）混合了「语言设计愿景」与「实际语法参考」两种定位，且多处与最新定案、源码现状冲突：

1. **宽度类型与定案矛盾**：3.2 节教 `0x1000_u64` / `100_i32` 后缀语法、4.4 枚举示例用 `u8/u16`、八章接口示例返回 `u64` —— 全部与 2026-08-30 width-out-of-language 定案（宽度移出语言）矛盾。
2. **虚构语法**：七章 `a := vec![1, 2, 3];` —— `vec!` 在源码中不存在。
3. **自相矛盾**：文末「设计要点」称「无指针操作符（\*, ->）和地址运算」，3.3 指针节却教 `*p` / `&arr[0]` / `cast<int*>`。
4. **关键字表错误**：称「共 35 个」且「self 按标识符解析」——实际 lexer.cr `lookup_keyword()` 为 **37 个**，且 `self` 是关键字（T_SELF）。
5. **markdown 表格断裂**：3.2 基础类型表被 `dyn` 说明行打断，unit/never 行落在表格外。
6. **愿景内容混排**：十二章「HDFG 视图」、十三章「π 示例」、5.4 requires/ensures 示例均未实现（源码零出现），与参考内容无区分地混排。
7. **标准库示例渗入**：8.1 HashMap/HashSet、9.4 通道 —— 语言语法文档不应包含标准库表层。

## 目标结构（13 章，无「类型系统」概念）

> Core 没有独立类型系统：类型 = 图标注、接口 = 图上契约、类型检查 = 图良构性验证（见类型方向定案）。文档只有「类型标注语法」的描写，不设类型系统章。

1. **设计要点**（短文，**以格形态为标准解释方式**）：按三层映射「图 → 格 → 编码」讲（`docs/memory-model-capability-lattice.md` v4 §四 + `2026-08-27-lattice-form-ir-design.md`）——图（`.cir`）= 结构表达（关系空间），格（`.ccr`）= 存在表达（状态空间，存在/条目/共存/驱逐），编码 = 机器形状（hw-map 领域）；语义保鲜 = 格形态全量承载类型/语义信息供形式验证直接消费；正确性陈述对全部可能执行成立（非 CFG 路径）；无独立类型系统（类型 = 图标注、接口 = 图上契约）；无 let；无生命周期标注；默认借用
2. **词法**：注释、标识符、关键字表（37 个，以 `src/compiler/lexer.cr lookup_keyword()` 为准）、字面量（int / dex / string / char / bool / unit / None / Some）、运算符记号（`*` 解引用、`&` 取地址、`->` 返回类型、`:=` 声明、`..` 范围、`?` 可选与错误传播、`@` 内建前缀）
3. **模块与导入**：fileid / mod / import / `::` 路径 / `@项目名` / _import.cr
4. **类型标注语法**（非类型系统）：类型表达式——基础类型（int / dex / bool / string / char / unit / never / Self，另含 dyn 动态类型[设计内容，见 `docs/dynamic-typing.md`]）、复合类型（元组 / 数组 / 切片 / 可选 / 引用）、接口作类型；标注位置（变量 / 参数 / 返回类型 / 泛型参数）；标签体系（mut / pub / apx）；auto 与 `.`
5. **变量声明**：`:=`、`: Type =`、批量声明、move、标签
6. **表达式与运算符**：优先级链（按 `grammar/core.ebnf` 顺序）、运算符表、调用 / 字段访问 / 下标、`?`、`as`、@ 内建调用
7. **语句与控制流**：if / else、loop / while / for、break / continue、match、return、unsafe 块
8. **函数与方法**：fn 声明、参数、返回类型（含 auto）、单行形式、impl、self（&self / &mut self）
9. **接口与泛型**：interface 声明、impl for、泛型声明与接口绑定、编译期具体化
10. **规约**：requires / ensures / old / result + where 值约束（拟定语法，三档语义）
11. **并发**：go / await / flow / yield / recv
12. **指针与 unsafe**：`&` 取地址、`*` 解引用、偏移运算、cast、RawRef、unsafe 块
13. **@ 内建原语**：元数据查询 / 编译控制 / 安全检查（详见 `docs/at-intrinsics.md`）

**删除内容**：HDFG 愿景章、π 示例章、标准库表层（HashMap / HashSet / 通道 / Result 枚举——`?` 运算符本身保留在表达式章）、`vec!` 等虚构语法。

## 内容处理规则

1. **宽度类型全面消失**：u8/u16/u32/u64/i32 等任何宽度类型名称与后缀（`_u64` / `_i32` / `_f32` / `_f64`）不出现在示例中。接口示例改用 int / dex 返回（如 `fn hash(&self) -> int`）。机器形状归属一句话带过（hw-map，未来显式控制通道）。
2. **矛盾修复**：删除「无指针操作符」表述；`vec!` 示例删除；关键字数 35→37、`self` 标注为关键字；3.2 表格断裂修复（dyn 定为基础类型之一，按定位不标实现状态）。
3. **拟定语法**（未定稿，文档给出第一份设计）：
   - where 值约束：`where <布尔表达式>` 附加在函数签名后（与 requires 同层），三档语义——常量约束 → 编译错误/通过；符号约束 → VC 义务；动态约束 → 运行时检查。
   - 泛型接口绑定：`fn first[T: Eq](...)`，声明处接口绑定 + 实例化检查，无运行期字典。
4. **示例规则**：全部示例只用语言本体语法（int / dex / string / bool / char / 复合类型 / 可选 / 接口），可读且不依赖标准库与未定语法（where 示例除外，其语法为本文档拟定）。
5. **实现状态**：全文不出现「已实现 / 未实现 / 待实现」标注（定位决策）。
6. **要点解释标准**：设计要点与语义解释一律以格形态为标准框架（格 = 存在空间、图 = 关系空间、编码 = hw-map；语义保鲜 = 格全量承载），不用传统的 CFG/编译器视角解释语言行为。
7. **出处原则**：关键字表以 lexer.cr 为准；优先级与语法形式以 `grammar/core.ebnf` 为准；冲突时 lexer.cr / parser.cr 优先于 EBNF（仓库惯例：实现以源码为准）。
