# 格形态 IR 设计：.ccr 升级为格形态（C 路线）

日期：2026-08-27
状态：**方向定稿 → 已实质化实施（2026-09）**——v6 格式与数据面落地（`specs/2026-09-05-lattice-ir-v6-format.md` 格式定稿 + `plans/2026-09-05-lattice-ir-v6.md` 实施计划 Task 1-5 完成：存在区间/条目版本化/共存推导/段表 IO/判定自检）；v5→v6 一次性转换按定稿取消（.ccr 中间产物零生态，v6-only）。关联：`docs/regalloc-cache-mapping.md`、`docs/memory-model-capability-lattice.md` v4。

## 1. 背景与动机

### 1.1 三层形态命名体系

三层映射正式晋升后（图 → 格 → 编码，见 `docs/memory-model-capability-lattice.md` v4 §四），IR 形态与之对应：

| 形态 | 层 | 格式 | 职责 |
|---|---|---|---|
| 图形态 | 图 = 关系空间 | `.cir`（HDFG） | 表示结构 |
| **格形态** | 格 = 存在空间 | `.ccr`（**本设计对象**） | 承载存在（状态/条目/共存/驱逐） |
| 编码形态 | 编码 = 物理编码空间 | ELF | 运行 |

### 1.2 .ccr 的名实不符

- 缩写：`.ccr` = Core **Control-flow** Representation（`docs/ir-schema/coreir-schema.md`）——名字写着 CFG
- 内容：v5 格式已是 **SG region 段**（`sg_count × 24B`：kind/enter/exit/parent/nstart/ncount）——内容早已是区域结构（图锚定存在结构），不再是「基本块控制流」
- 语义：CFG 即将淘汰变成格（正确性不再按 CFG 路径陈述，而是对全部可能执行成立）——「控制流表示」的定位描述全部过时

### 1.3 时机：趁程序生态小

格形态马上要出；当前 `.cr`/`.ccr` 程序生态很小。**改名与格式升级现在定案 = O(仓库)；以后定案 = O(仓库 + 生态 + 产物/缓存)**。C 路线：改名与格式升级合一，**一次迁移**。

## 2. 定位

格形态 = 格层（存在空间）的承载格式：

- **条目**（IR 变量版本，条款 5 版本化）、**配方**（产生节点）、**存在区间**（图活性）、**共存**（存在区间相交）、**驱逐/再生**（缓存语义条款 2/3）、**无配方条目标注**（图内不可重算，条款 4b）
- **寄存器分配判定直接消费格形态**（`docs/regalloc-cache-mapping.md` §4 的一致性判定：共存互斥 / 读点无陈旧 / 驱逐配对 / 调用失效——存在区间与共存的宿主）
- 与 `.cir`（图形态）的关系：图 = 结构表达（关系空间）；格形态 = 存在表达（状态空间）——`lower_to_ccr()` 从图派生线性投影的机制保留，v6 在其上加入存在结构

## 3. 命名决策

| 候选 | 方案 | 成本 |
|---|---|---|
| **A（已定案）** | 扩展名 `.ccr` 保留，缩写展开改为 **Core Region Representation**；格式 v6 内部升级 | 零生态成本：扩展名 / magic（`CCR1`）/ CLI / 文件路径全不动 |
| B | 新扩展名（`.rir` / `.cer` / `.exr`）+ 新 magic + CLI 子命令 | 全链改名（代码/测试/文档），与 v6 升级同一迁移批次 |

**推荐 A**：改名（语义）与格式升级合一的关键是「一次迁移」——扩展名不动则迁移面最小；region 一词准确反映 v5 已落地的 SG region 段与图锚定存在结构。若未来需要显式区分「格形态」与「线性投影」两种格式，再引入 B 不迟。

**已定案（2026-08-27 拍板）：方案 A**——扩展名 `.ccr` 保留，缩写展开 = Core Region Representation；扩展名 / magic（`CCR1`）/ CLI / 文件路径全不动，零生态成本。

## 4. 格式设计方向（v6）

### 4.1 现状（v5）

- 指令数组（28B/条：opcode/dest/src1-3/type_kind）+ 变量表 + 字符串表 + 全局段
- SG region 段（24B/条：kind/enter/exit/parent/nstart/ncount）——区域结构已落地
- DFEdge 不落盘（仅内存与 `.cir` 缓存）

### 4.2 v6 增量（存在结构段）

**不做格式兼容**：v6 与 v5 是数学结构大改（线性程序 → 存在结构）——条目/存在区间/共存/驱逐不是「追加段」能表达的（v4→v5 的 SG 段只是尾部超集扩展，先例不适用）。提供 **v5 → v6 一次性转换**（从线性投影重建存在结构：图活性推导 + 版本化重建），趁程序生态小转换成本最低：

1. **条目版本段**：版本化条目（变量 × 版本）→ 存在区间 [start, end]（图活性，RegionCheck 语义）
2. **共存关系**：存在区间相交的显式标注，或推导规则（从图活性派生，避免冗余存储）
3. **home 标注**：条目持久位置（栈槽）声明
4. **无配方条目标记**：边界 + 图内不可重算（条款 4b）——「必须有 home、驱逐必写回」规则的输入
5. **驱逐/填充点**（可选，v6.1）：spill/load 插入位置的标注

### 4.3 与分配判定的接口

- 判定（`regalloc-cache-mapping.md` §4 四条）消费：存在区间、共存、home、无配方标记
- 证书落点：分配结果（映射）与判定规约（.corespec）挂在格形态之上
- 实现顺序：存在结构段 → 判定消费 → 贪心放置（`opt.cr` 升级）
