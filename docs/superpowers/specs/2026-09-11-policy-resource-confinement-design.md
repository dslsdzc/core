# 路径与资源限制

## 概述

路径遍历（例如 `../../etc/passwd`）在普通语言里是危险字符串：安全性依赖每个调用点都记得检查。

本文把目标资源从“字符串可达”改为“无法构造目标 capability”。路径值携带来源和域约束，派生只能落在根声明的命名空间内。

## 设计原则

- 限制由库类型和图上派生链实现，不加关键字，不改 Graph 本体。
- 不做字符串消毒或排除清单筛查。判定对象是“这个名字是否在命名空间的名字集合里”，不是“这个字符串是否危险”。
- `..` 在派生处一律非法，不做消解尝试。
- `string` 到 `Path<R>` 没有公开转换。唯一入口是根声明和 `child` 派生。
- 语义层只判构造合法性。symlink、mount、hardlink 的解析身份属于映射层。
- 细化范围走图上派生链，不走类型子类型。

## 类型表示

```text
Path<Root>
```

`Root` 是根身份符号，不是字符串，也不是路径前缀的字面量类型。它的身份等于根声明节点的图节点身份。

`Path<Root>` 的值是：

```text
(根身份, 组件序列)
```

组件序列不可算术，只能沿派生增长。没有 `parent()` 派生；“向上”是 `..` 的另一种拼写，同样不可构造。

## 与 string 的关系

| 面 | 规则 |
|---|---|
| `string` | 名字原材料。未定域，没有 capability，可以在任意调用点使用 |
| `string` 到 `Path<R>` | 没有公开转换，没有隐式转换，没有 `from_string`，没有 `cast` |
| 唯一入口 | 根声明，然后 `child` 派生 |
| `Path<R>` 到 `string` | 只用于诊断显示，单向。显示结果拿去重建，要重新走 `child`，不会恢复 capability |
| 合法性 | 在命名空间的名字集合上判成员性，不做字符串重写、规范化或过滤 |

## 派生规则

```text
child(self: Path<R>, name: string) -> Path<R>
```

合法名字是单个非空组件，并且：

1. 不含命名空间分隔符。经典文件系统下是 `/`。
2. 不是 `.`。
3. 不是 `..`。
4. 不是绝对路径，没有前导分隔符。

名字是编译期常量时，编译期判定。合法就零成本通过；非法就硬编译错。

名字是动态值时，运行时检查成员性。检查是单遍比较，无分配；失败时明确拒绝。

失败语义：

- 非法派生绝不产出落在其他资源上的 capability。
- 不回退，不截断，不回退父路径，不不报错地取根，不“尽力而为”。

失败形态可以是 panic、`Option` 或 `Result`。形态是策略选择，不改变“非法派生不产生 capability”这一性质。第一版建议用明确拒绝。

## 命名空间

一个根定义三样东西：

- 名字集合 `N(R)`。
- 派生运算 `child : (R, name) ⇀ R'`。这是部分函数，不合法就没有定义。
- 根封闭规则：派生结果仍在同一个根内。

具体算法是映射参数。POSIX 目录树、对象存储前缀、URL 路径、配置键空间各自实现自己的名字集合和 `child`。语义层不固定算法。

## `..` 的处理

`..` 不在 `N(R)` 中。命名空间里没有它指向的目标，因为根的父不在这个 capability 的域内。

因此 `child("..")` 不是“检查后拒绝”，而是没有对应的派生。危险从“检查点”移到了“构造不存在”。

已知边界：对非根路径，`..` 在经典文件系统里可能可以消解，例如 `images/../css`。本设计仍然一律禁止。原因是局部性：单组件判定不需要知道前缀，不需要文件系统状态，也不引入规范化算法。编码、多次编码、尾随字符都是经典绕过面。

## 与 pointer-model 的对应

| pointer-model | 本设计 |
|---|---|
| 条目标识 | 根身份符号 |
| 偏移 | 组件序列 |
| 边界判定 | 组件合法性加根封闭 |
| `ALLOC` / `ALLOC_AT` | 根声明入口 |
| 外部地址空间 | 未受限的 `string` 名字 |
| `unsafe` 边界 | 根声明入口 |
| 沿 def 链倒推 | 派生链倒推到根声明节点 |

两者都是沿 def 链倒推的图稀疏分析，不新增 pass。本设计的判定由类型引擎的身份判等和图上派生链组成。

## 义务分级

| 档 | 条件 | 处置 |
|---|---|---|
| 1 prove | 名字是常量，且合法 | 编译期通过，零运行时成本 |
| 2 enforce | 名字是动态值 | 运行时成员性检查；失败明确拒绝 |
| 3 proof-required | 需要证明根声明或稳定性，但引擎不可判 | 要求用户或领域库提供 contract |
| 4 reject | 高安全档下无法构造合法 capability | 拒绝编译 |

非法派生不落到第五种“算了”。失败必须可见。

## 与 handle 的关系

`Handle<R>` 是独立类型，不嵌入 `Path<R>`。

```text
bind(p: Path<R>) -> Handle<R>
```

`bind` 是唯一的 check/use 边界，也是 S-B5 状态版本检查的判定对象。绑定之后不再按名字重查。

`bind` 的原子性由映射层提供，例如 fd、dirfd 或 `openat` 一类机制。第一版切片不包含 handle，只做纯值级路径限制。

## 最小切片

第一版只做纯值级路径限制：

1. `Path<Root>` 类型和 `child` 派生。
2. 常量名字的编译期判定。
3. 动态名字的运行时成员性检查。
4. 根声明入口。
5. 检查：未使用路径限制时，现有程序零影响。

切片不改 stdlib，不做 handle 化，不做跨过程派生链传播。

## 不包含

- 不做 TOCTOU 和 check/use 分离；那属于 S-B5。
- 不做注入语法位；那属于 S-B1。
- 不做 `Secret ↛ Public`；那属于 S-B3。
- 不做 `Can(a,o,r)` 授权判定；那属于 S-B2。
- 不新增关键字。
- 不做字符串消毒或排除清单。
- 不尝试消解 `..`。
- 不做 symlink、mount、hardlink 的解析身份判定；那属于映射层。
- 第一版不做 handle。
