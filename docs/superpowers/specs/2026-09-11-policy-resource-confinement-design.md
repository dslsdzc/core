## 0. 范围与裁决

### 0.1 论题

路径遍历（`../../etc/passwd`）在既有语言里是**危险字符串**：安全性依赖"每个程序员在每个调用点都记得检查"。本族的论题（承路线图 §0 的机制）：

> 把目标资源从"字符串可达"改为"**无法构造目标 capability**"——路径值携带 provenance/capability，派生只能落在 capability 定义的 namespace 内。

判据形态：不是"我们拒绝了 `..`"，而是"**`..` 没有对应的构造**"——攻击面从"检查是否遗漏"变成"类型/图上是否存在这条边"。

### 0.2 本族覆盖 / 不覆盖

| | 范围 |
|---|---|
| **覆盖** | 路径值的**定域构造**（根身份 + 派生）、namespace 成员性判定、围栏的义务落档、与 handle 化/状态版本族的接力点 |
| **不覆盖** | TOCTOU / check-use 分离（**S-B5**）、注入语法位（**S-B1**）、`Secret ↛ Public`（**S-B3**）、`Can(a,o,r)` 授权判定本体（**S-B2**——本族只**供给** capability 与派生链） |

### 0.3 裁决清单（本族的定案）

- **D-1 围栏 = 库类型 + 图派生链**，不加关键字、不改 Graph 本体、不建第二套数据结构（承契约 §1.2-1/-2、定案 1/4）。用户面 = 类型化构造器（同 SQL/HTML/shell 的领域库纪律）；**不做字符串消毒/黑名单筛查**（那是 lint 换皮，契约 §1.2-2 明文禁止）。
- **D-2 `..` 在派生处一律非法，不做消解尝试**。理由 = **局部性**：单组件判定不需要知道路径前缀、不需要文件系统状态、不引入规范化算法（编码/多次编码/尾随字符是经典绕过面）。备选 D-2b（允许 `..` 但要求消解后仍在根内）显式登记、**不采用**，见 §2.3。
- **D-3 围栏的语义内容 = (根身份, 组件序列)**，与底层路径字符串表示无关（同 pointer-model「地址 = 映射」：字节地址从来不是语义对象）。
- **D-4 唯一信任点 = 根声明入口**（声明式进图，同构 `alloc_at` / `unsafe` 边界）；`string → Path<R>` **无任何公开转换**。宿主绝对路径只允许出现在根声明处，且全程序可枚举（可审计面）。**声明权（2026-09-11 裁决 D6(a)）**：根声明只在**受控命名空间内有效** + **装载期校验**；「谁有权声明根」记入 policy 面、对装载器可见（S-A §3.6）——不是空白（§7.2 Q2 已裁）。
- **D-5 语义层只判 L-1（构造合法性）；L-2（解析身份：symlink/mount/hardlink）显式登记为映射层义务**，只能由 handle 化强制（接 §3）。**L-1 通过不蕴含 L-2 安全**——本族不得含糊带过此条。
- **D-6 类型参数 = 根身份（稳定，不随派生变化）；细化（收窄到子树）走图上的派生链，不走类型子类型**。判定归 S-B2 的 capability path（本族只提供证据），从而**不依赖** R2 P3 的参数化变型规则，也不与 S-B2 重复判定。
- **D-7 消费的属性轴 = `authority`（授权，与 S-B2 边界）+ `trust`（不可信名字来源，与 S-B1 边界）；本族不新增属性轴**（轴的定义是 S-A 的事）。本族的 policy 数据 = **根声明表**（哪些根存在、各自命名空间算法）——数据而非语法（契约 §1.1 policy 条）。

## 1. 围栏对象

### 1.1 类型表示

```
Path<Root>      // Root = 根身份符号（不透明、用户不可伪造）
```

- `Root` 是**身份符号**，不是字符串、不是路径前缀的字面量类型。它的还原面承 M1 定论：身份 = 图节点身份（根声明节点），无独立身份符号；派生源 = 沿图可追踪（能力成分 ⟨身份符号, 授权集, 域约束, 派生源⟩ 的 **身份 + 派生源** 两成分，v4 定位）。
- **域约束**（能力成分第三项）= 该根声明的命名空间算法 + 名字集合——即"这个 capability 的适用范围"，语义边界而非字节长度（与 lattice §七 一致）。
- `Path<Root>` 的值 = (根身份, 组件序列)。**组件序列是偏移域的对应物**：不透明、不可算术、只能沿派生增长（§2.2）。无 `parent()` 派生——"向上"是 `..` 的另一种拼写，同样不可构造。

### 1.2 与 `string` 的关系

| 面 | 规则 |
|---|---|
| `string` 的角色 | 名字**原材料**（字节序列）；未定域、无 capability、可在任意调用点被消费 |
| `string → Path<R>` | **无公开转换**（无隐式转换、无 `from_string`、无 `cast`）。唯一通道 = 根声明（信任点）+ `child` 派生（D-4） |
| `Path<R> → string` | **仅诊断渲染**（`display()` 类，单向）；渲染结果拿去重建 = 重新走 `child`，不恢复 capability |
| 合法性判定 | 在**命名空间的名字集合**上做成员性判定，**不做字符串重写/规范化/过滤**（D-1）。"名字不合法" ≠ "字符串被清洗成合法" |

**D-1 的边界说明（区分设计与待论证）**：本族与"输入校验库"的差别不在实现而在**判定对象**——校验库判"这个字符串危险吗"（可被绕过、需枚举攻击面）；本族判"这个名字在命名空间的名字集合里吗"（定义即判据，无枚举）。因此本族**不承诺**任何字符串层面的安全性，只承诺构造层面无非法 capability。

### 1.3 与 provenance / asp 的复用面（同构表）

| `docs/pointer-model.md` | 本族 |
|---|---|
| 条目标识（entry identity） | 根身份符号 |
| 偏移（偏移域，与物理地址无关） | 组件序列（派生链） |
| 边界判定 `0 ≤ off ∧ off+width ≤ alloc_size` | 组件合法性 ∧ 根封闭（§2） |
| `ALLOC` / `ALLOC_AT`（声明式进图） | 根声明入口（唯一信任点） |
| `asp=1` 外部地址空间（无 provenance） | 未围栏 `string` 名字 |
| `unsafe` 边界（外部地址的解引门槛） | 根声明入口（`string` 只在此处被信任） |
| ProvenanceVerify 沿 def 链倒推到 ALLOC | 派生链倒推到根声明节点 |
| 判定域 = 条目标识 + 偏移，**与字节地址表示无关** | 判定域 = 根身份 + 组件序列，**与路径字符串表示无关** |

**复用声明（不是类比，是同一判定形状）**：
0. **唯一 owner（2026-09-11 裁决 D22）**：图上「沿 def 链倒推」的判定**只在 S-B2 §2.1 步① 实现一次**（输入 = provenance / RegionCheck / ProvenanceVerify 的既有结果，输出 = `Cap` + 派生链见证，`g_*` 只读）。**本族只供给派生链证据**（§3 接口约定 ②），**不另写分析、不重复判定**——其 Q4（派生链合法性落点）据此关闭。
1. 两者都是**沿 def 链倒推的图稀疏分析**，都不新增 pass——本族判定 = R2 引擎的类型项判定（身份判等，定案 1/4 的图验证层级）+ 图上派生链判定。**共同前提（D12）**：仓库的边 / region 必须**覆盖全部语义依赖**——**覆盖率报告无缺口**前，本族的派生链判定与 S-B3 S1 一样**不启动**（独立侦查项，S-B3 §6.1 前置 3）。
2. 两者都把"外部/未验证入口"收敛到**唯一显式信任点**（`unsafe` / 根声明），且进信任点后重获追踪权（`alloc_at` 先例："声明是唯一信任点，之后编译器重新获得追踪权"）。
3. **能力三件套的边界成分**（lattice §六表：边界 → ProvenanceVerify 已覆盖，对应物 = 域约束）在本族 = 命名空间边界；两族的"边界"都**不是**字节长度（"排除：基址/长度/字节 R/W/X——经典映射实例"）。

**差异（须诚实标出）**：pointer-model 的边界判定在**已存在的分配**上做（`alloc_size` 是图数据）；本族的边界判定在**名字集合**上做，而名字集合的成员性在经典映射下可能依赖运行时文件系统状态（名字存在与否）——**"名字合法性"与"名字存在"是两件事**，本族只判前者（判据见 §2.2）。

### 1.4 handle 的类型表示（**登记**，本族不裁定）

handle（身份绑定载体）出现在本族值的什么位置，只有两种结构可行，**本 spec 不在此裁定**：

| 形态 | 表示 | 代价 |
|---|---|---|
| **内嵌槽** | `Path<R>` 值 = (根身份, 组件序列, **可选 handle**)——未绑定 = 空槽，①→② 档在消费点填充 | 值类型随绑定状态变化 → 需判定"空槽"档位（引入状态依赖） |
| **并列类型** | `Handle<R>` 独立于 `Path<R>`；`bind(p: Path<R>) -> Handle<R>` | 引入一次显式转换点 = check/use 边界（**正是 S-B5 的判定对象**） |

裁定归属：**S-B5 + 映射层**（表示形态取决于"绑定原子性"如何判定）。本族的既定立场（§3 共享不变量）：无论哪种表示，**一旦绑定身份就不再按名字重查**；且本族切片 v0 **不含 handle 槽**（§5.1）。

## 2. namespace 判定

### 2.1 命名空间 = 根 + 名字集合 + 派生运算

- **语义层固定的是判定形状**：一个根定义了一个**名字集合** `N(R)` 与一个**派生运算** `child : (R, name) ⇀ R'`（部分函数——不合法即无定义）。
- **具体命名空间算法是映射参数**（结构同 lattice §4.6 无格承诺）：POSIX 目录树、对象存储前缀、URL 路径、配置键空间各自实例化自己的 `N` 与 `child`；语义层不固定哪一个，也不按范式枚举。
- 与"无格承诺"的同构：**用普适构造定义层，不用情形分析**——本族只要求 `child` 是部分函数且**保根封闭**（§2.4），不要求它是字符串拼接，也不要求名字集合可枚举。

### 2.2 `child` 派生规则

```
child(self: Path<R>, name: string) -> Path<R>     // 失败语义见下
```

**合法名字（本族切片的最小名字集合）**：单个非空组件，且

1. 不含命名空间分隔符（经典映射下 = `/`）；
2. 不是 `.`；
3. **不是 `..`**（D-2）；
4. 非绝对（无前导分隔符）。

**判定档位**（义务落档的详细信息见 §4）：

- 名字是**编译期常量** → 编译期判定。合法 → ① **prove**，零运行时成本；非法 → **硬编译错**（判定失败，不是"运行时再说"）。
- 名字是**动态值** → ② **enforce**：运行时成员性检查（O(名字长度) 单遍比较，无分配），失败**响亮拒绝**。

**失败语义的硬性要求（安全性载体，与失败形态解耦）**：

> 非法派生**绝不产出**落在其它资源上的 capability；**绝不回退**（不截断、不回落父路径、不静默取根、不"尽力而为"）。

失败形态（panic / `Option`/`Result` 类错误值）是**策略选择**，不改变上述安全性 claim——推荐切片 v0 用响亮拒绝（panic，零新类型），优雅错误返回登记为生产形态（§7 Q1）。

### 2.3 `..` 的语义：消解失败即非法（D-2）

**精确表述**：`..` 不在 `N(R)` 中——命名空间里**没有它的目标**（根的父不存在于该 capability 的域内）。因此 `child("..")` 不是"被检查后拒绝"，而是**无对应派生**（unconstructible）。这正是 §0.1 论题的落地：危险从"检查点"移出，成为"构造的不存在"。

**诚实的边界（不得含糊）**：对**非根**路径，`..` 在经典文件系统里**技术上可消解**（`images/../css` 是合法资源）。本族裁决 D-2 仍**一律非法**，理由：

- **局部性**：单组件判定无需规范化算法——避免"判定一个名字是否安全"退化为"实现一个正确的路径规范化器 + 证明它"（编码、多次编码、尾随点/空格、大小写、Unicode 规范化都是经典绕过面）；
- **可强制**（lattice §六引 Kain 1986 约束：「细化 ⊑ 必须可强制」）：局部规则天然可强制，全局消解规则的强制依赖映射层正确性。

**备选 D-2b（登记，不采用）**：允许 `..` 但要求**消解后仍在根内**。代价 = 规范化算法 + 其正确性论证 + 与符号链接面交互后**不可判定**（§2.5）：值级消解"仍在根内"在 symlink 参与下不再蕴含解析后仍在根内 → 该备选的 L-1 判定不闭合。裁决保留在 §7 Q5。

### 2.3b 绝对路径

**语义**：绝对路径的含义 = **重绑搜索原点**（"从文件系统根开始"），与 capability 的定义（原点固定 = 该 capability 的根）**直接矛盾**。因此前导分隔符不在 `N(R)` 中——不是"检查后拒绝"，而是**无对应派生**（同 §2.3 的 `..`）。

**两个推论**：

1. **`child` 的实现不得是字符串拼接**。若实现为"根字符串 + 名字"，则拼接本身不是错误来源（前导 `/` 已在判定处排除）——但**判定与消费必须绑定同一个名字集合**，否则两处规则漂移。这是 §1.2"判定对象 = 名字集合成员性"的实现后果，登记为实施期检查项。
2. **宿主绝对路径只允许出现在根声明处**（D-4）。这使"程序能触达的宿主路径集合"**静态可枚举**——围栏的可审计面由此而来（§6-3）。

**与 §2.5 的关系**：排除绝对路径只解决 L-1——`child("images")` 仍可能解析到根外（symlink）。绝对路径面**不减少** L-2 的登记义务。

### 2.4 根封闭（传递性）

`child` 保根封闭：`Path<R> --child--> Path<R>`（D-6：类型参数稳定）。故派生链上任一点都在根域内，**归纳成立**，判定无需重算整条链。

**细化（收窄到子树）不在类型上**：`Path<R>` 不携带"我只被允许访问 `images/`"这一信息——**细化是派生链的性质（图数据），判定归 S-B2 的 capability path**（`Can(a,o,r) ⟺ ∃合法 capability path`），本族只保证派生链**忠实记录且不可伪造**。此裁决同时避免了与 S-B2 的判定重复、以及对 R2 P3 参数化变型规则的依赖（§7 Q3）。

### 2.5 符号链接面（**显式登记，不承诺**）

**判据（本族最重要的不承诺条目）**：

> **L-1 通过 ⊉ L-2 安全。** 构造合法性（纯值级）**不蕴含**解析身份安全性（文件系统级）。

| 层 | 内容 | 可判定性 | 归属 |
|---|---|---|---|
| **L-1 构造合法性** | 组件名字成员性 + 根封闭 | 纯值级：常量档编译期，动态档运行时单遍检查；零文件系统依赖 | **本族（本 spec 的判定面）** |
| **L-2 解析身份** | symlink 跳根外 / bind mount 把外部挂进根内 / hardlink 同 inode 两名 | **值级不可判**（依赖运行时文件系统状态与挂载表） | **映射层义务 + 治理面**（§3 handle 化） |

三条独立性（登记，逐条给出归属）：

1. **symlink**：组件 `images` 是合法名字，但它可能是指向 `/etc` 的符号链接 → 构造合法而目标越界。关掉方式 = 逐组件 `O_NOFOLLOW` + dirfd 链，或 `openat2(RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS)`——**映射层实现选择，不进语义层**。
2. **mount**：bind mount 可把根外资源挂进根内路径下——namespace 面**不可判**（不是名字问题），归治理/挂载面（"唯一信任点"外的第二个信任面，必须登记而非默认安全）。
3. **hardlink**：同一 inode 两个名字，其中一个在根内——同样不可判，归治理面。

**同构推广（登记，不在本批范围）**：HTTP 重定向 ≡ symlink（命名空间外的第二次解析）；对象存储前缀命名空间**无原子 handle** → L-2 不可强制 → 高安全档落 ④（§4）。此推广说明本族的判定形状跨命名空间成立，而**L-2 的可强制性是映射层属性**——正是"无格承诺"的结构（层不承诺具体算法）。

## 3. 与 S-B5（状态版本 / TOCTOU）的衔接

**接力点**：本族保证**名字 → capability 的构造**单步且不可回退（无"先检查字符串、再用字符串"）；S-B5 保证 **capability → 资源身份的绑定**是原子的（check/use 同一版本）。

**共享不变量（两族交接的核心，写入本族）**：

> **一旦绑定身份，不再按名字重查。** 检查与使用必须是**同一个对象**，而不是"同一个名字的两次解析"。

两条路径（把 §2.5 的 L-2 归属讲清）：

| 形态 | 构造语义 | TOCTOU 面 |
|---|---|---|
| **已 handle 化**（fd/dirfd） | `child` = `openat(dirfd, name, …)` → 新 handle = 新 capability。**构造即绑定身份** | 无重查 → 无 TOCTOU；本族产出即 S-B5 的**版本载体** |
| **未 handle 化**（纯值路径：配置值 / 对象存储前缀） | 值级派生，无资源绑定 | 值级无版本变化 → 无 TOCTOU；**"值 → 资源身份"的转换点**才有 TOCTOU 面 → 那是 S-B5 的判定对象 |

**接口约定（本族交给下游的三样东西）**：① 根身份（capability 身份）；② 派生链（授权细化证据，供 S-B2 `Can` 判定）；③ 可选的 handle 槽（身份绑定载体，S-B5 消费）。

**边界**：本族**不实现** handle 化——切片 v0 为纯值级（§5），故 v0 的安全 claim **只覆盖 L-1**（§2.5 判据在此重申）。两族的合并 claim（L-1 ∧ L-2）需要 v0 + handle 化映射同时到位。

**S-B5 未定稿的处理**（并行起草中）：本 spec 不依赖其细节，只固定上述接力点与共享不变量；若 S-B5 最终形态与本节冲突，以**两族共同复核**为准（§7 Q7）。

## 4. 义务落档（四档 + 判定失败）

档位定义逐字取路线图 §1.1（prove / enforce / proof-required / reject）；贯穿原则 = 契约 §1.2-3「义务不静默消失」。

| 判定 | 档 | 落法 |
|---|---|---|
| 常量合法名（`child("images")`） | ① **prove** | 编译期消解，零运行时成本 |
| 名字来源自带约束（枚举/白名单类型，或 where 常量档 —— 定案 5 三档） | ① **prove** | 构造者可静态证合法；**这是可证性的正当来源，不是白名单筛查** |
| 动态名 | ② **enforce** | 运行时成员性检查（单遍比较，无分配）；失败响亮拒绝、绝不回退 |
| 派生链身份/根封闭/身份判等 | ① **prove** | R2 引擎 `ty_equiv`（参数化原子同形判等）+ 图派生链判定，零运行时 |
| 需要"证明名字属于受限集合"但来源无静态约束 | ③ **proof-required** | 要求用户提供 contract/proof（形态由 S-A 定）；**本族暂不消费**（登记） |
| 动态名 + **策略禁止运行时检查**（如常量时间要求） | ④ **reject** | 高安全档拒编——**本族 ④ 仅在此边界出现** |
| L-2（symlink/mount/hardlink）且映射层**无 handle 化能力** | ④ **reject** | 高安全档拒编（有 handle 化 → 落 ② 由映射层强制） |
| **判定失败**（常量非法名） | **硬编译错** | 不属于义务梯档——是判定结论为假（非"义务待处置"） |

**默认强度分层（2026-09-11 裁决 D3(c)；规范形态见 S-A §2.2 附）**：本族 **② enforce 默认启用**（动态名 = 运行时成员性检查）；**④ 仅高安全档**（策略禁止运行时检查 / 映射层无 handle 化）；**③ = 登记 + 继续编译**（默认档不拒编）；**CI 门槛 = 严**。

**两条结构性观察（区分设计与待论证）**：

1. **本族的 ④ 面很窄**：因为 enforcement（运行时名字成员性检查）**总是可实现**，④ 只在"策略禁止运行时检查"或"映射层无 handle 化"时出现。这与 S-B1 注入族（参数化通道之外无 enforcement）形态不同——登记为族间差异，供 S-A 的义务分类消费。
2. **③ 的位置**：本族 ③ 是"把动态名升级为可证"的正当通道（契约第 14 条声明式上限），**不是**"证不出来就要求用户写证明"的兜底——后者会退化成把责任推回程序员（违反本族论题）。

## 5. 最小可实施切片 + 判据

### 5.1 切片 v0（纯值级 L-1，**不接 syscall、不做 handle**）

1. 领域库位落 `Path<R>` 类型 + 根声明入口（常量绝对路径，声明式进图，唯一信任点）+ `child` 构造器；
2. 常量档判定接编译器（实施细节 = S-A §3.6 装载面 + R2 P2b 字面量面接线——**S-A 已落盘（收敛批 v2）**，剩实施批；**D12 覆盖率门槛**同样适用于本切片的派生链判定，§1.3）；
3. 动态档运行时检查（成员性单遍比较，无分配）；
4. 无 `string → Path<R>` 公开转换（唯一通道判据）；
5. 判据落 `tests/selfhost/` 用例（编译错断言 + 运行时拒绝断言）。

**明确不在切片内**（登记）：handle/fd 化、syscall 接线、symlink/mount/hardlink 面、跨命名空间映射（HTTP/对象存储）、D-2b 消解备选、细化的 capability path 判定（归 S-B2）。

### 5.2 判据（正控 / 负控）

```
// 正控 ①：常量合法派生链
r := root("/var/www");          // 唯一信任点（宿主绝对路径只在此处出现）
i := r.child("images");          // ✓ 编译期 prove
f := i.child("logo.png");        // ✓ 根封闭传递

// 负控 ②：常量非法名 → 硬编译错（逐例断言诊断）
r.child("..")                    // ✗
r.child("../../etc/passwd")      // ✗
r.child("/etc/passwd")           // ✗
r.child("a/b")                   // ✗
r.child("")                      // ✗

// 负控 ③：动态名 → 运行时响亮拒绝，且不产出 capability
n := get_env("UNTRUSTED");       // n = "../../etc"
r.child(n)                       // ✗ 运行时拒绝（不截断、不回落、不静默取根）
                                 // 正控对照：n = "images" → ✓

// 负控 ④：身份判等 + 唯一通道
root("/srv").child("x")          // ✗ 与 Path<Root_www> 不等价（类型错）
cast<Path<Root_www>>(some_string)  // ✗ 无此转换（编译错）
```

**验收判据**：

| # | 判据 | 方式 |
|---|---|---|
| 1 | 正控链通过（含二级派生） | 正向编译/运行 |
| 2 | 负控 ② 五例逐一硬编译错（措辞分因，不得并成一条） | 逐例断言 |
| 3 | 负控 ③ 运行时响亮拒绝 + **不产出可用 capability**（拒绝后无对象可用） | 双路径（解释器 / ELF）rc 精确 |
| 4 | **无旁路**：`string → Path<R>` 公开转换不存在（类型面 + 转换面核查） | 类型错误断言 + 面核查 |
| 5 | 正控对照 ③：`"images"` 动态名通过（证明 ②③ 是判定而非"一律拒绝"） | 正向运行 |
| 6 | 根封闭传递（判据 1 的第二级派生） | 同 1 |
| 7 | **零成本面**（登记）：常量正控无新增运行时指令；动态档为 O(名字长度) 单遍比较 | 产物对比（实施期） |

**判据的诚实说明**：判据 1-6 全部在 L-1 面——**切片 v0 不证明任何文件系统安全性**（§2.5 判据）。把 v0 描述为"解决了路径遍历"是夸大；v0 的 claim = "非法 capability 不可构造"。

## 6. 不承诺（逐条落路线图 §1.3 三类）

1. **错误 specification**：Core 只证明"程序忠实实现了围栏规则"，不证明规则本身正确。本族的规则输入 = **根声明的选择**（把哪个宿主路径定为根）、**命名空间算法的选择**——声明错（例如根定为 `/`）则围栏忠实实现了一个无用规则。**"唯一信任点"就是这条边界的名字**：它把 spec 正确性的责任集中到一处可审计的声明，而不是消除它。
2. **恶意/失陷外部实体**：编译机、供应链、以及**谁能执行根声明**（治理面）不在语义可证范围。围栏缩小权限面（能力显式、可枚举、可审计），不证明声明者可信。硬件后门/内核被攻陷同属此类。
3. **需求本身允许危险行为**：程序若**确实要**读 `/etc/passwd`，本族不禁止——它要求程序**显式持有那个 capability**（对该根的一次显式声明）。即：围栏把能力从**隐含**（任何字符串可达）= 变为**显式**（可枚举、可治理、可审计），而不是禁止能力。这正是路线图"目标不是禁止能力，而是证明隔离边界"的本族实例。

**另加一条本族特有（源自 §2.5，非 §1.3 三类）**：切片 v0 **不承诺** L-2（解析身份）安全——symlink/mount/hardlink 面显式登记在映射层与治理面。
