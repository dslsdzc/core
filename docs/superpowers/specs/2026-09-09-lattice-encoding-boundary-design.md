# 格层边界：检查、v6 审计和转换器契约

## 概述

编码层与经典计算机绑定过深，会把机器形状带回格层。本设计给出四组检查、对 v6 格式的裁决，以及 corearch 转换器的输入输出契约。

设计状态：定稿。审计依据、逐项资产定位和历史裁决见 `docs/superpowers/implementation/2026-09-09-lattice-encoding-boundary-audit.md`。

## 检查

四组检查从既有定位点推导。任何一条答“泄漏侧”，就进入泄漏分类。

### G1 语义本体

判定问题：

1. 该对象有生成方法吗？移除它、保留生成方法，可观测语义会变吗？
2. 赋值表达为版本创建、失效和绑定移动，还是内存单元修改？
3. 位置语义是条目标识加偏移，还是字节地址？
4. 身份是产生节点，还是独立存储事实？
5. 无生成方法条目是否按统一规则处理，不按范式枚举？

### G2 层形状

判定问题：

1. 该结构是否按执行路径组织？如果顺序只是图的合法拓扑序列化，图语义可以完整重建，判为序列化，不判为程序顺序。
2. 规则和判定是否按范式枚举？层本体规则封闭，对象开放。
3. 判定是否只操作条目类别，即位置、生成方法和存在区间，不读值内容？
4. 语义是否写在比具体格代数更弱的理论里？例如共存只要求对称关系，不承诺传递性。

### G3 实例和参数

判定问题：

1. 换平台时该内容语义会变吗？会变是映射参数或实例数据，不变属于格层。换不掉且硬编码在通用机制里，是泄漏。
2. 是否与“寄存器分配等于缓存语义映射实例”同族？同族按实例化处理。
3. 具体代数、ABI 和帧序是否作为映射参数存在，而不是层本体的承诺？

### G4 泄漏分类

| 类 | 名称 | 定义 |
|---|---|---|
| 1 | 存储形状泄漏 | 变量等于可寻址存储位置，例如帧槽或字节内存操作进入格语义层 |
| 2 | 控制形状泄漏 | 经典控制流形状进入格语义层，例如函数等于可调用子程序、标签跳转、栈 call-ret |
| 3 | 编码选择泄漏 | 目标机编码选择固化进格格式或转换器通用机制，例如 tag 字节布局、2L 指针、溢出链 |
| 4 | 平台惯例泄漏 | 平台惯例出现在格层或转换器核心，例如 ABI 寄存器分派、参数栈序、ELF 布局 |

G1 到 G3 答“泄漏侧”的对象归入 G4 类别，再按转换器契约决定去向：实例数据、实例算法或入口归一化。

## v6 审计

### 格式结构

段表组织、变长记录和字节宽属于编码层事务，不构成格层问题。

坐标使用 NOD id，即图坐标。存在区间端点、区域边界和定值点都以图节点序为坐标，与 `.cir` 同坐标系。格侧成立。

只支持 v6、没有转换工具，可以作为管线中间产物。

### NOD

NOD 是图事件，每个节点表示一个生成方法，形状正确。

但 NOD 的 `op`、`dest` 和 `srcs` 语义沿用了 v5 的变量槽指令，这是显式妥协，不是原则性决定。它带有三类泄漏：

1. 存储形状泄漏：变量是槽，LOAD、STORE、字段和索引操作按字节内存操作定义。
2. 控制形状泄漏：JUMP、BRANCH、LABEL、RETURN 和 CALL 是行式控制流形状。REG 提供嵌套，但操作语义仍按执行路径组织。
3. 编码选择泄漏：tag 和 2L 相关操作、帧 tag 语义出现在操作码和类型码面。

正面先例是 ENT 的版本化规则。STORE 的定值目标是 `s1`，`ρ(s1) := ρ(s2)`，这是“赋值等于版本化”的正确语义雏形。

逐 op 裁决以操作码清单为底稿，按 G1 到 G4 判类。本设计不逐 op 落表，引用者按检查执行。

### ENT

ENT 的形状是条目加版本、定值节点、存在区间、home 和 flags。条目乘版本是赋值版本化的直接实现，位置是条目标识加偏移，身份是定值节点。ENT 是格层本体在 v6 里最纯的成分。

两个问题：

1. ENT 恒空，没有成为主干。寄存器分配移到后端后，存在结构在侧表，实际主干仍是 NOD 线性流。
2. home 字段的语义定位。home 是分配器回填的槽位。裁决是 home 属于缓存语义映射实例的注记。格本体最小集是 `var_id`、`version`、`def_nod`、存在区间和 flags。home 可以保留，但语义定位是实例层数据。

### REG

区域嵌套和区内条目范围是图绑定区域和共存推导的坐标实现。共存不落盘，由 sweep 推导，符合最弱理论形态。格侧成立。

区域是经典映射实例的组织面，但嵌套坐标本身是图语义，保留在格侧正确。

### NOD 边表缺席

边是生成方法的必要成分。生成方法等于产生节点加输入边。缺边则方法不完整，图作为真相层的文件实现不闭合，文件序会从序列化滑向程序顺序。

边是否落盘是编码层事务。边的语义存在性是格层必需的。格形态必须能从文件重建图语义，包括边。执行序只是图的一个投影。

### 不纯点

| # | 位置 | 泄漏类 | 程度 |
|---|---|---|---|
| P1 | NOD 操作语义等于 v5 变量槽指令 | 1、2、3 | 结构性 |
| P2 | ENT 恒空，未成为主干 | 本体缺位 | 结构性 |
| P3 | NOD 边表缺席 | 方法不完整 | 结构性缺口 |
| P4 | ENT home 混入格本体语义 | 实例注记定位不清 | 轻 |

本设计只定检查和目标纯度，不设计新格式，不改代码。P1 到 P3 指向未来格式演进。涉及格式重构的工作必须先通过本检查。P4 可以在不触格式的情况下修正语义定位。

## corearch 转换器契约

### 定位

corearch 是格到编码的投影器，把格语义对象投影为具体机器的物理编码。它不是执行器。执行标注空间属于图。格到编码的投影不需要理解范式。

编码层绑定经典机是合法且必须的。问题只在绑定形态。

### C1 输入契约

转换器输入必须是纯格形态：

- 条目和版本，ENT 是语义主干。
- 图事件和生成方法，包含边，语义完整可重建。
- 区域嵌套。
- 符号和类型信息。

v6 的泄漏在转换器入口归一化：把变量槽和字节操作形状还原为条目、版本和方法语义，再投影。泄漏不能作为转换器的输入假设向下传播。当前转换器把槽当成 `rbp` 帧偏移，这是问题的机制形态。

归一化层自身要做语义保真检查：还原后格语义必须包含原形状的可观测语义。

### C2 输出契约

输出是目标机物理编码，当前是 x86 ELF。经典绑定在实例层全部合法：

- 实例数据：投影表和模板。HIT 表是正确方向。
- 实例算法：帧布局、调用序列、寄存器缓存映射、tag 和 2L 编码选择。它们都是映射参数实例。

寄存器分配是已接纳的实例化先例。帧布局、ABI、调用序列和 tag 编码与它同族，都是对缓存语义的机器侧资源决策，必须同类处理，放入实例层，不放入通用机制。

### C3 核心只含通用机制

核心允许：

1. 格语义到实例请求的通用翻译：版本到位置分配请求，共存到资源互斥约束，生成方法到指令选择请求，区域到存储区段请求。
2. 实例注册和选择机制：目标机实例的登记、校验和按需装载。

核心禁止硬编码帧公式、寄存器名、ABI 参数序、tag 位布局、调用序列和 ELF 布局。核心中的硬编码就是泄漏点，去向是实例层。

### C4 HIT 和 M2 裁决

HIT 表驱动是编码层实例数据的正确实现方式，不废弃。

两个定位偏差：

1. 检查对象错了。M1 和 M2 的对照检查是“表路径 ELF 逐字节等于旧发射器产物”。模板的正确性检查应该是“格语义到实例的投影正确性”，使用行为等价、结构等价和映射正确性定理，不是复刻注定退役的旧发射器字节，包括冗余 REX 位、`jmp rel 0` 和 `ret_patch` 技巧。
2. 范围窄了。M2c 数据化只覆盖单指令编码形态，帧、ABI、调用和返回序列仍留在代码里。实例化边界应覆盖全部实例算法族。

ret 裸 C3 和 branch 模板的矛盾，是旧字节复刻检查的必然产物。重定检查后，模板是实例的正确语义序列，不再追旧字节。

### C5 挂账裁决

事件流和表数据是编码层事务，属于 x86 实例的投影内容，不进入格形态段。格形态携带语义对象，不携带目标机投影中间物。

寄存器分配移到后端是 C2 和 C3 的正面先例：分配判定在 corearch 内实例化，`.ccr` 不表示分配结果。

tag 和 2L 的语义属于图和格层，tag 字节、溢出链和堆指针表示属于实例选择。当前实现把两者耦合在帧布局和操作码面，这是泄漏，实例化时解耦。

### C6 资产定位

| 资产 | 定位 |
|---|---|
| `.ccr` 格式结构、NOD id 坐标、REG | 格语义对象，成立 |
| NOD 操作语义，v5 槽指令 | 泄漏，待归一 |
| ENT 条目版本、区间、定值节点 | 格语义对象 |
| ENT home | 实例数据 |
| NOD 边，当前缺席 | 格语义必要成分 |
| SYM 符号 | 符号和类型语义。函数形状的去留是格式演进裁决项 |
| 寄存器分配 | 实例算法，先例已接纳 |
| HIT 表和模板 | 实例数据，方向正确 |
| 帧公式、prologue、参数序列、ret_patch | 实例算法，当前硬编码是泄漏 |
| MW tag 语义和编码 | 语义归格层，编码归实例 |
| ELF、链接、系统调用 | 实例输出，编码层合法内容 |
| `lower_to_core` | 当前是泄漏输入假设的传播者，归一化后重定位 |

## 应用

新工作引用本设计时，按 G1 到 G4 逐条检查对象。答“泄漏侧”的条目进入 G4 分类，再按 C1 到 C3 决定去向。

格式重构必须先通过本检查。纯语义定位修正，例如 home 的定位，可以不触格式直接执行。
