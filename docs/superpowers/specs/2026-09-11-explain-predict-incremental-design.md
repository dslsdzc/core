### 0.2 论题

三条线索是**同一个机制**的三个投影：

> **把「编译器自己的决定」变成图上的一等对象（决策记录）**——
> 解释 = 读它（为什么这样做）；预测 = 它的一个子类（这样做的资源后果的界）；增量 = 它的依赖闭包（它依赖什么 ⇒ 什么变了它作废）。

可解释是**人**的通道，可预测是**调度/约束**的通道，语义增量是**机器**的通道；三者共用 §4 的记录表与依赖边，不各建一套。

**路线图 §1.4 的报告面（2026-09-11 追加）是同一机制在确定性轴族上的投影**：`D_value`…`D_mapping` 的逐项状态 = 该轴上的决定记录；**不确定性 provenance 链** = 同一条 `evidence` 闭包换个读法（从「为何选」读成「这个不确定性从哪来」）。故它是**第四条线索，不是第四个系统**（§1.7）。

## 1. 可解释（`core explain`）

### 1.1 原则：automation without opacity

编译器拿走工作，**不拿走理解**。可解释的判据不是「能打印一堆东西」，而是：

1. 用户能从一个**他能指认的锚点**（源码位置 / 符号 / 图节点）出发，问一个**他关心的问题类**，得到**编译器实际做过的决定**及其因由；
2. 答案是**产物的函数**，不是「再跑一遍编译器，这次开着日志」——同一产物两次查询必须逐字节同（与 §3 同一条纪律）；
3. 答不出就说答不出（`unattributed`），**不得编造理由**——这是 §1.2 原则 3「义务不静默消失」在解释面的同构条款：**解释不静默编造**。

反面（明确不做）：把 `explain` 做成「第 N 个 dump 通道」。现状已有 8 个 dump 旗标（`--dump-entries` / `--dump-coexist` / `--dump-regassign` / `--dump-objects` / `--dump-events` / `--dump-table` / `--check-regalloc` / `--type-shadow-dump`），它们是**整图转储**：无锚点、无问题类、无稳定 schema、不回答「为什么」。

### 1.2 查询面：锚点 × 问题类

**锚点**（用户指认得出来的东西）：

| 锚点形态 | 语法（草案） | 解析路径 |
|---|---|---|
| 源码位置 | `corec explain FILE.cr:LINE:COL` | 复用 `src/lsp/analysis.cr` 的「位置 → 令牌 → 符号」反查（快照只读，不触发检查） |
| 符号 | `--fn NAME` / `--global NAME` | `g_funcs` / 符号表 |
| 图对象 | `--node DFN` / `--instr IRN` / `--region ID` | `.cir` / `.ccr` 产物 + dump 通道 |
| 记录 | `--record ID` | 决策记录表（L9 内容寻址 id） |

**问题类**＝由**生产者注册的开放清单**（不是 CLI 硬编码 switch——否则每加一个 pass 就要改 CLI，退化成特判）：

| 问题类 | 问什么 | 生产者（决策产出点） | 就绪度 |
|---|---|---|---|
| `checks` | 这条指针/下标**为何插了 runtime check** | `ext_safety.cr:18` `ext_safety_on_array_access` + `ir_gen.cr:17-65` F11 长度侧表（`g_ir_slice_lens`）+ `IR_BOUNDS_CHECK`（`ast.cr:559`）+ checker R002 | **今天有**（S-D1 切片） |
| `ptr` | 这条指针**为何判安全** | `ptr_analysis.cr` 三 pass + `region_check.cr` + `provenance_verify.cr`；LSP hover v1 已有「points-to 闭包近似 / 配方 = 产生节点」 | **今天有（近似）** |
| `placement` | 这个节点**为何放 CPU / 为何被驱逐/再生** | `docs/regalloc-cache-mapping.md`（寄存器分配 = 缓存语义映射实例）+ `--dump-regassign` / `--check-regalloc` | 部分（后端侧已有 dump，缺记录化） |
| `bounds` | 这个循环/序列的**上界从哪来** | `bounds-inference`（**挂账**，TODO「边界判定图 pass」）+ F11 长度来源链 | 待 pass 落地（§2） |
| `vectorize` | **为何没向量化** | auto-vectorize（TODO 性能自动化族 → **S-C**） | **未实现**——`explain` 必须能答「生产者未产出记录（功能未实现）」，而不是猜 |

最后一行是设计的关键约束：查询面对**没有记录**的问题类必须给确定答案，答案分三种——「未实现」「未评估」「评估后拒绝」，三者不得混同（`alternatives` 字段区分：空 = 未评估，非空 = 已评估被拒）。

### 1.3 决策记录的承载（本 spec 的核心载体）

一条记录 = 一次编译器决定的**内容寻址**快照：

| 字段 | 语义 | 备注 |
|---|---|---|
| `id` | 内容哈希（kind + subject + 输入摘要 + 因由码） | **L9**：不随构建序号漂移 |
| `kind` | 记录类别（开放注册：`check_emitted` / `ptr_verdict` / `reg_choice` / `bound` / `obligation` / `cache_verdict` …） | 与问题类多对一 |
| `subject` | 图对象引用（DFNode / 边 / region / IR 指令 / 符号 / 源码 span） | 与 `.cir`/`.ccr` 的既有 id 空间对齐 |
| `phase` | 产生阶段（checker / ir_gen / dataflow / 判定引擎 / regalloc / emit） | 决定「谁负责」 |
| `choice` | `selected` / `rejected` / `forced` / `unknown` | 四态，与引擎三态（真/假/unknown）同构 |
| `cause` | 因由码 + 参数（规则 id / 启发式 id / 计数器 / 预算余量） | **因由码是稳定标识符，不是自由文本**；人读文本由渲染层生成 |
| `alternatives` | 被拒方案 + 各自因由码（可空） | 空 ≠ 拒绝，空 = 未评估 |
| `evidence` | 输入引用集（图节点 / 侧表项 / 类型项 / 约束） | **同时是 §3 的依赖边**（§4.1） |
| `determinism` | `det` / `heuristic` / `env` | **L3**；`heuristic`/`env` 记录不得跨构建复用（§3） |

**单一真源（★D27 / A 线 M1）**：本表 = 全仓**唯一** schema 真源；消费者（如 S-C §5 R1）只引用本表字段集 + 各自补充项，**不得**另立字段表（S-D §4.1 禁止双源漂移）。

**不重造的部分（复用判据）**：记录表**不是**新分析。它是对既有产出的**记录化**——`--type-shadow` 的分类计数（AGREE / OLD_STRICTER / OLD_LOOSER / UNKNOWN）已经是一条决策记录，只是没有 id、没有 subject、没有落盘；`--dump-regassign` 已经是 `placement` 记录，只是没有因由码。本 spec 要求的是**统一条目与统一查询**，不是重写这些 pass。

**开销纪律（承 R2 P1 先例）**：R2 P1 已实证「记录通道默认关 + 关/开两态产物逐字节同（sha256 `95084e7b…d475`）」。本 spec 沿用该纪律的**加强版**：

- **记录生成常开**（轻量：只写 `id/kind/subject/phase/choice/cause 码`）；
- **记录展开按需**（`explain` 时才把 `evidence` 引用与 `cause` 参数渲染成人读文本）；
- 关掉记录通道 = 产物逐字节同（守卫判据，见 §5 S-D1）。

理由：若记录生成也默认关，则**缓存命中路径上的决定永远不会被记录**（缓存条目里没有记录），`explain` 将随冷热态给出不同答案——这正是 L8 要禁止的。

### 1.4 输出契约

**一份数据，两种渲染**（人读由结构化生成，绝不反向）：

```
{
  "schema": "core.explain/1",
  "query":  { "anchor": {...}, "qclass": "checks" },
  "records": [
    { "id": "...", "kind": "check_emitted", "phase": "ir_gen",
      "subject": { "src": "FILE.cr:42:7", "instr": 118 },
      "choice": "selected",
      "cause": { "code": "E-CHK-SLICE-DYN", "args": {"len_source": "var"} },
      "alternatives": [ { "code": "E-CHK-NONE", "rejected_because": "E-CHK-SLICE-DYN" } ],
      "determinism": "det",
      "evidence": [ { "kind": "side_table", "ref": "g_ir_slice_lens:17" } ] }
  ],
  "unattributed": [ { "subject": ..., "qclass": ..., "why": "no_record" } ],
  "truncated": 0
}
```

硬约束：

1. **确定性**：同产物两次 `explain`（含 stdout）逐字节同——无时间戳、无 PID、无地址、无目录绝对路径；排序 = 记录 id 序。
2. **versioned**：`schema` 字段 + 破坏性变更 bump；golden 快照测试直接比字符串。
3. **`unattributed` 必须显式**：不可归因（启发式内部状态 / 记录缺失 / 功能未实现）走这一栏，**不得**以空 `records` 静默等价于「没发生任何决定」。
4. **人读模式**（默认）：`cause.code` → 稳定措辞表（`diag.cr` 风格：因由码 → 一句中文 + 一行证据链）；`--json` 出结构化。**因由码 → 措辞表**是独立文件/表（照 `error_codes` 先例），保证措辞可审、可译、可测。
5. **零协议扩展**（承 LSP spec §6）：LSP hover 用 markdown 渲染同一结构；coreview 读 JSON。不新增 LSP 方法。

### 1.7 确定性报告面：`core analyze --determinism`（路线图 §1.4，2026-09-11 追加）

**定位（L2/L12 的直接推论）**：`analyze --determinism` **不是新工具**——它是 §1.2 查询核在**程序级锚点**上的投影：

| 命令 | 锚点 | 问题 | 共用 |
|---|---|---|---|
| `corec explain FILE:LINE --qclass <类>` | 单锚点（源码/符号/图对象） | 为什么**这里**这样做 | 同一记录表 + 同一查询核 |
| `corec analyze --determinism [--at ANCHOR]` | 程序 / 每个**可观测输出**（边界 sink：打印/写文件/返回值/网络） | 这个输出的**不确定性从哪来** | 同上 |

#### 1.7.1 报告契约

输出 = **轴族逐项状态** + **不确定性 provenance 链**（两份都由 §1.3 的记录表生成）：

```
$ corec analyze --determinism FILE.cr
axis         status    evidence / residual
D_value      PROVED    merge_deterministic @12:3；无可达边界
D_effect     UNKNOWN   state edges 覆盖 #41→#44→#52（store 家族）；调用 print@#58 未入链——按保守面降级（硬约束 8）
D_memory     PROVED    region 锚定 + bump/reset 全静态（arena #0/#3）
D_timing     UNKNOWN   residual: 循环 #61 迭代次数依赖外部输入
D_resource   PROVED    结构层：在飞任务 ≤ 4（spawn_count）；值个数 ≤ …
D_external   EXPLICIT  boundary #27（stdin）——边界节点 = 一类合法显式源，主人 = #27（★D19）
D_mapping    PROVED    无机器相关假设（映射无关段）

uncertainty provenance:
  boundary #27 → parser → branch #61 → output "report"
  （每跳 = 记录 id + kind + 边类型；断链 → UNKNOWN + 断链位置登记）
```

硬约束（承本 spec §1.4 输出契约约束 1–5 + 路线图 §1.4 全部）：

1. **状态值域** = `{PROVED, MODELED, UNKNOWN, EXPLICIT}`（路线图 §1.4 逐字）；**`D_timing` 只用前三值**（时间三值化，硬性——不设 `EXPLICIT`：耗时的物理性使「源码明文允许」不构成状态；源码显式放行不确定时，该不确定落在 `D_value`/`D_effect`，`D_timing` 相应为 `UNKNOWN`）。
2. **每行必须带证据或残余**：`evidence`（可指认的记录链）或 `residual`（剩余不确定源清单）。**空 evidence + 空 residual 非法**（= 静默，路线图 §1.4 精神禁止）。
3. **链可指认性**：provenance 链的每一跳必须能在记录表里查到（L9 内容寻址 id）；查不到 ⇒ `UNKNOWN` + 断链位置登记（**L14**，不得补全猜测）。
4. **链终止**：终止于**边界节点**（缓存语义条款 4「边界公理」：MMIO / FFI / 输入 / 测量 = 唯一无配方条目）或**显式语义源标注**。到达既非边界又无配方的内部节点 ⇒ 断链（这同时是标注器/pass 的缺陷信号，须登记）。
5. **状态传播 = 沿依赖闭包取 join**（部分序，**不**假设全序）：
   - 任一环节 `UNKNOWN` ⇒ 整体 `UNKNOWN`（**不可归因优先暴露**——这是报告的诚实底线）
   - 无 `UNKNOWN`、含 `MODELED` ⇒ 整体 `MODELED`（时间轴专属：混入机器相关估计即**不得**称证明）
   - 无 `UNKNOWN`/`MODELED`、含 `EXPLICIT` ⇒ 整体 `EXPLICIT`
   - 全 `PROVED` ⇒ `PROVED`
   - `MODELED` 与 `EXPLICIT` **不可比**：同时存在 ⇒ **双标**（`MODELED + EXPLICIT`），并必须让 `EXPLICIT` 的源可指认——不得用任一值吞掉另一个。
6. **报告自身确定性**：同产物两次运行逐字节同（含 stdout，无时间戳/路径/地址；排序 = 轴名序 + 记录 id 序）——照本 spec §1.4 约束 1。
7. **汇合与不确定性的最小字段面（承 S-E §5.2.3；I3/★D20）**：报告项**必须**含——形态 / 汇合点 id / 输入边集 / 顺序源（`ordered`）/ k 与 `Obs(M)` 基数界（`race`）/ 见证引用（witness，若暴露）/ 分类（已证明 · 已声明 · 冗余声明 · 拒绝）。**`冗余声明` 类照 S-E §1.5 证明优先规则单列**（标了 `race` 而已证确定者）。此前「格式归 S-D」两侧都以为对方承载 ⇒ **落点即本条**（S-E §5.2-3 已回指）。
8. **效应证据的充分性（L17/I4）**：`D_effect` 的 `PROVED` 证据**必须声明 state 链的覆盖范围**；链未覆盖 `IR_CALL_EXTERN` 或未被判定为纯的调用时，按 **S-E §1.1 保守判定**降级 `UNKNOWN` + `residual`（**今日纯度标注恒「纯」⇒ 实际口径 = 「所有调用」**，见 §1.6 登记）。**「有 state 边 ≠ 确定」**（S-E §4.1 方向性提醒）——不得把「state edges 全序」单独读成 `PROVED`。
9. **局部 prove 的覆盖标注（L10）**：`race` / `select_any` 的 `EXPLICIT` 项**必须**标注「该保证未覆盖观测点」（S-E §5.2-6：prove 范围 = 局部，只覆盖汇合点本身）。

#### 1.7.2 时间三值化（`D_timing`，硬性）

| 值 | 语义 | 数字来源 | 呈现禁令 |
|---|---|---|---|
| **PROVED** | **机器无关上界**：分配次数/字节 · 在飞任务数 · 通信量（**可由 region / 图证明**） | §2 结构层（本 spec） | 不得声称这是「时间上界」（次数 ≠ 时间） |
| **MODELED** | 机器相关时间 = **成本模型估计** | **S-C 成本模型**（§2.6 接口） | **必须明标「模型估计，非证明」**；**禁止**呈现为 WCET 证明 |
| **UNKNOWN** | 判不出 / 模型不可用 / 链断 | — | 不得渲染为任何界（§2.2 同纪律） |

**「PROVED 的机器无关量」与「时间」的分界是本报告面的核心纪律**：分配次数/在飞任务数/通信量可证，但**它们不是时间**——报告面必须把两者分列，不得让读者把「已证明的指令数上界」读成「时间上界」（这正是路线图 §1.4「不许撒谎」的落点）。

#### 1.7.4 与 S-A / S-E 的边界（**只归因，不定义来源**）

**与路线图 §1.4 执法落档表的逐行对应**（本报告面只出「呈现列」，执法列为谁负责）：

| 路线图 §1.4 情形 | 本报告面呈现 | 执法归属 |
|---|---|---|
| 依赖/状态边足证「汇合与调度无关」 | `PROVED`（零成本） | S-A |

- `EXPLICIT` 的判定 = 「该不确定可追溯到一条**已登记的**显式语义源标注」**或**「链终止于**边界节点**」。**标注的存在性与合法性归 S-A（轴标注登记）/ S-E（汇合形态定义）**；本报告面只回答「归因到哪」，**不**判定「某个 `race` 标注是否该合法/是否该 reject」——**执法点（隐式竞争 → reject）归 S-A/S-E**（L12：本 slice 只读）。

- **局部 prove 的呈现（L10）**：`race` / `select_any` 的项标注「该保证未覆盖观测点」（硬约束 9）——保证范围与呈现范围必须一致，不得让读者把局部保证读成整条路径的保证。

## 2. 可预测（资源上界）

### 2.1 上界三层与可判定性

| 层 | 量 | 可判定性 | 归谁 |
|---|---|---|---|
| **结构层** | 最大**在飞任务数**（并发 goroutine 数）· 最大**通信条数/值个数** · 循环迭代次数上界 · 每 arena 的**值个数**上界 | 图 + region + state edges + spawn 计数**直接可判**（无依赖 region 的可并行性判定已有声明，TODO 性能自动化族） | **本 spec** |
| **映射层** | 最大**字节内存** · 最大**通信字节量** · 峰值 live storage | 需尺寸/对齐标注——R2 §2.1 已裁定「尺寸/对齐 = 映射层 / hw-map 领域，**语义层不承诺布局**」 | **S-C / hw-map**（本 spec 只定义记录格式与「界如何被消费」） |
| **时间层** | **deadline**（墙钟/周期上界） | **语义层不可判**（成本模型属 S-C；共享机器/OS 调度/中断不可归因——§1.3 残留第 2 类） | 只能 ②enforce / ③proof-required（§2.4） |

三层不可混报：`explain --bounds` 的输出必须标层。**结构层上界不蕴含映射层上界**（值个数少但值大）；把两层混成一个「内存上界」是本设计明确禁止的过度承诺。

### 2.2 保证 vs 平均：状态值域（**统一承路线图 §1.4**）

上界与轴族状态**共用同一个值域**（不另造一套标签——这是「三线共用一套」的直接后果）：

| 状态 | 含义 | 渲染约束 |
|---|---|---|
| `PROVED` | 对**声明的全部执行**成立（符号传播 + 图结构给出，机器无关） | 可称「保证」；须附 `assumptions[]`（空 = 无条件） |
| `MODELED` | 依赖**成本模型**（机器相关） | **必附 `model_id`/`model_ver`/`band`/`assumptions[]`**；人读必须打「模型估计，非证明」标（§1.7.2 禁令） |
| `UNKNOWN` | 判不出（预算耗尽 / 依赖不可判 / **生产者未实现** / 链断 / 模型不可用） | **不得渲染为 bound**；走 `unattributed`（本 spec §1.4 约束 3）+ 登记 |
| `EXPLICIT` | 语义**明文允许**该不确定（有主的不确定） | 必须指明**主人**（标注的位置与来源）；不得与 `UNKNOWN` 混同 |
| （`measured`） | 实测（PGO/剖析/回归数据） | **不是状态、不是保证**；只允许出现在诊断/建议语境，样式中不得与前四者同形 |

**假设是修饰不是状态**：`PROVED`/`MODELED` 都可以带假设清单（原「assumed」= `PROVED + 非空 assumptions` 的读法）；假设不成立则界不成立——此口径比单列一档 `assumed` 更诚实（不会让读者以为「有假设的界」与「无条件证明」是同一类东西）。

这就是 §1.2 原则 3「义务不静默消失」在预测面的同构条款：**上界不静默降级**——`PROVED` 退到 `MODELED` 必须写清模型与假设；退到 `UNKNOWN` 必须显式登记。**禁止**把 `MODELED` 呈现为 WCET 证明（L13，契约硬性）。

### 2.3 现状基础（可复用，不重造）

1. **每 goroutine 独立 arena + 不共享内存 + 值在 channel 边界拷贝**（`docs/superpowers/specs/2026-07-30-concurrency-design.md`；实现 `src/stdlib/goroutine.cr:54` 写 `arena_id`、`sched.cr:45` 主 goroutine `arena_id = -1`）。
   ⇒ **并发内存上界可分解**：无共享 ⇒ 最坏内存 = Σ(每 arena 上界)，无需全程序指针逃逸分析——这是本 spec 能承诺结构层的**唯一理由**。
2. **静态 spawn 计数已在 IR 里**：`IR_SPAWN`（`ast.cr:556`）`s3 = fn_name_ni`、`type_kind = spawn_count`，**`-1` = dynamic**。
   ⇒ 并发数上界对 `spawn_count ≥ 0` 的部分**今天即可判**（`PROVED`）；`-1` 部分登记为 `UNKNOWN`（不是猜）。
3. **region 嵌套 + state edges**（`dataflow.cr`：SG_IF/LOOP/FOR/FLOW/UNSAFE + state edges）：并发路径结构可判（TODO「无依赖 region 的可并行性可判定」）。
4. **F11 长度来源链**（`g_ir_slice_lens`）+ **bounds-inference 挂账**：迭代次数/序列长度上界的传播基建已存在（今天是侧表，目标是图化 + 三态：恒安全 → 不发射检查；恒越界 → R002 拒绝；判不了 → 保留检查**并带图推导必要性标注**——最后这条正是 §1 `checks` 问题类的答案来源）。
5. **判定走引擎**（原则 4）：资源约束的判定（如「迭代次数 ≤ 声明值」）复用 `ty_sub` 族；**不另建判定体系**。

**缺面（诚实）**：无值个数/尺寸的上界推导 pass（`bounds-inference` 挂账）｜无并发数收集通道（`spawn_count` 存在但无汇总查询）｜无成本模型（S-C）｜无「上界声明」的语法/数据载体（§2.5）。

### 2.4 deadline 约束的语义

**超时动作 = 仅诊断（已裁，★D8，2026-09-11）**：编译期标注 + 报告，**不改运行时语义**——语言只说「此处声明了 deadline 约束」，**不说「超时会怎样」**；超时的硬行为（终止 / 降级 / 补偿）留给**库 / 运行时**实现，且**不得**呈现为语言保证（与「模型非证明」一致：语言不承诺时间上界）。据此，deadline 在语言语义上只能是：

| 档 | 语义 | 何时可用 |
|---|---|---|
| ③ **proof-required** | 要求用户提供「步数/成本上界」的证明义务 | 硬实时子集，验证切片轮后 |
| ④ **reject** | 高安全模式下无法处置 → 拒绝编译 | policy 数据裁量 |
| （② enforce **不在语言面**） | 若库 / 运行时自行实现超时动作，那是**库的语义**——语言不承诺其行为，也不得把运行期动作升格为语言保证（L8） | — |

**明确不在 ①**：即使 someday 有成本模型，deadline 的 prove 仍依赖调度/硬件假设（路线图 §1.3 残留第 2 类）——`PROVED` 的 deadline 只可能在「声明域内 + 单核 + 无中断」这类**显式声明的封闭假设**下成立，且必须把假设挂在 `assumptions[]` 里。

**`MODELED` 的位置**：deadline 可以在**非安全关键**语境以 `MODELED`（S-C 成本模型估计 + 不确定带）呈现——但必须明标「模型估计，非证明」（L13），且**不得**作为调度/安全/适航类判据的输入。**超时动作 = 仅诊断**（已裁，★D8；O5 已闭合）：报告面只呈现「该约束的 `D_timing` 状态 + 残余」，**不得**承诺任何超时行为。S-C 侧同款（其 §1 资源行 + §8 O5）。

### 2.5 与义务阶梯的关系（实例化，不重定义）

资源上界 = **义务阶梯在资源轴上的实例**（本节只做映射，不新增档）：

| 资源约束的处置 | 四档落点 |
|---|---|
| 静态可证界 | ① **prove**（零成本，状态 `PROVED`） |
| 不可证界但可运行时强制（计数器 + 检查） | ② **enforce**（状态 `PROVED + assumptions[]` 或 `MODELED`+enforcement 记录） |
| 判不了也不可强制 | ③ **proof-required**（要求用户声明上界 = policy 数据） |
| 高安全模式仍无法处置 | ④ **reject** |

**载体 = policy 数据**（原则 2 / §1.1：`G + P ⊢ Safe` 的 `P`），**不升格为语言 primitive**——资源上界声明是图上约束数据，不是新关键字。**依赖 S-A**：`P` 的接口与义务判定通道归 S-A，本 spec 提供的是「结构层界的计算 + 记录格式 + 状态值域纪律」。

### 2.6 与 S-C 的接口（`MODELED` 数字的唯一来源，L15）

时间层的 `MODELED` 与映射层（字节）的数字来源**不在本 spec**：时间 = **S-C 成本模型**，字节 = **hw-map 尺寸标注**（R2 §2.1 已裁：尺寸/对齐是映射层领域，语义层不承诺布局）。接口形态与禁令见 **§1.7.3**（`cost_model_query`：`cost` + **必填 `band`** + `model_id`/`model_ver` + `assumptions[]`）：

- 本报告面**只调用 + 贴标签 + 记版本**；模型版本进 §3.3 `phase_ver` ⇒ **模型换代 ⇒ 报告与依赖它的记录自动失效**（这是增量面的直接收益）。
- **不读模型内部状态**（内部状态不可归因 ⇒ 违反「解释不静默编造」）。
- 模型不可用 ⇒ `UNKNOWN`；**不得**用经验常数兜底成 `MODELED`。
- 结构层（本 spec 承诺的部分）**不依赖** S-C：这也是 S-D2 结构档可先行的理由。

### 3.2 与现有缓存的差距（含两个已实测缺陷）

**现状**：函数级 `.cir` 快照，`CIR_CACHE_VER = 14`（`cir_cache.cr:16`，magic `C1C1…`），头部 = 格式版本 / 函数体指纹 / 签名指纹 / func_id；命中即跳过 check + IR gen。

**差距 A（TODO #5，预存）**：键**缺编译器身份分量** ⇒ 二进制重建后旧条目存活 ⇒ 旧 CIR 与新版字符串表（`g_strs` 驻留序）错位 ⇒ dump 通道变量名缺失/错位（实证：806 → 381 个 `name=` 翻转；清 cache 即复现判据）。

**差距 B（TODO #5 同族第二实例，2026-09-11）**：**`.ccr` 输出与缓存态相关**——同一二进制冷缓存首次 `corec ccr` sha256 `53ebcf12…`，紧接第二次（已填热）`5054e26d…`，三次起稳定。故现状**判据比较 `.ccr` 前必须 `clean-cache`**。

差距 B 是本 spec 的**核心证据**：它说明现状缓存的输出**不是产物状态的函数**，而是「历史路径」的函数。L7 把它写成可检验的目标。
**范围注（C4/★D25）**：差距 B 的**闭环**（命中路径产物保真：字符串驻留序 / 全局初始化注入的重放）落在「条目内容」面，**超出 S-D3 声明的范围**（S-D3 只做键的依赖集，明确不做增量后端与 `.ccr` 格式改动）⇒ 其判据② 已**降级为登记**（S-D3 表；不得按其字面读作 S-D3 的验收线）。

**差距 C（缓存 × 语义的静默交互，已有登记）**：缓存命中**跳过 `ir_gen_func(main)`** ⇒ 全局初始化注入（main 序言 IR 注入）在命中路径上**不重放**；配合差距 A ⇒ 升级编译器后旧 cache 让该修复**静默失效**（TODO「全局初始化机制」缓存交叉引用；批前该场景本就 rc=139，非回归）。
**差距 D**：缓存与单态化的交互脆弱（`main.cr:442-446` 注释明写：缓存命中不重放 monomorph ⇒ 泛型函数存在时缓存整关）——即「性能特性」与「正确性」在现状实现里靠**关掉缓存**兜底。
**差距 E**：命中判据只有 <函数体, 签名> 两维——**不含**构建配置（`--static` / opt-level / target / `--table` / 实例声明）、**不含** policy 集（S-A 落地后义务集变了缓存必须失效）、**不含**依赖闭包。

### 3.4 正确性判据（增量 ≡ 全量）

**主判据（L7）**：对任意源变更集，**增量产物 ≡ 全量产物**——三级，全部逐字节比较：

|---|---|---|

| L3 义务级 | 义务/证明集合（ΔProof 后） | 待验证管线 |

**反向判据（必须同时有，否则主判据可被「永远全量重编」作弊）**：**增量必须真的生效**——命中率/复用率统计 + 一条「改动 1 个函数 ⇒ 未变更函数的 `.cir` 条目**字节未变**」的断言。只测「等价」不测「真的省了」= 把缓存删掉也能全绿。

**负控集（失效面覆盖，每条一个断言）**：① 重建编译器（差距 A：跨重建不复用）② 改 stdlib 依赖（`deps_fp`）③ 改 policy 集（`policy_fp`，S-A 后）④ 改 `--static`/opt-level/target（`unit_fp`）⑤ 泛型/单态化路径（差距 D）⑥ 引擎版本变更（ΔProof）。
**验收升级（C4/L25 修正）**：现状纪律「判据比较前必须 `clean-cache`」的消灭 = **整体目标（L7）**，其闭环依赖「命中路径产物保真」机制（**不属 S-D3 范围**）；S-D3 的验收线改为「**差距 A 转绿 + 差距 B 仍红并附根因清单** + L7 保留为整体目标」（§5 S-D3 判据②/③）。

- 缓存条目损坏/版本不识别/指纹分量缺失 ⇒ **响亮回落全量重编**（`cir_cache.cr:251-254` 已有 ver/magic 拒绝先例，扩展为分量缺失 ⇒ miss），**不得**按旧条目静默采用（同「义务不静默消失」纪律）。

## 4. 三者的公共基建

### 4.1 一套记录表 + 三个投影 + 一条追踪

**是共用一套**，理由不是「省代码」，而是**语义上必须**：

- §1 问「**为何选**」——读记录的 `cause` / `alternatives`；
- §1.7 问「**这个不确定性从哪来**」——读**同一条记录**的 `evidence` 闭包（沿依赖边走，终止于边界/显式源）；
- §3 问「**依赖了什么**」——读**同一条记录**的 `evidence` / `determinism`；
- §2 的界是 `kind = bound` 的**同表记录**（`choice = selected` 的界 + `alternatives` = 被拒的更弱界 + `cause` = 判定来源）。

即：**失效追踪 = 决策记录的输入依赖闭包**。一条记录若没有 `evidence`，它就**不可增量**（只能整块失效）——这把「记录完整性」与「失效精度」变成同一个变量，是设计上必须承认的成本驱动（粒度先粗后细，§5）。

**三个投影**：解释视图（人读「为何选」）｜归因视图（人读「不确定性从哪来」= §1.7 的 provenance 链）｜失效视图（机器读依赖闭包）——**同数据、同边、不同渲染**。**不允许**为失效追踪或归因链另建一套依赖表：那会立刻产生「记录说 A 依赖 B，依赖表说 A 依赖 C」的双源漂移（先例：`res_type_node` 双份 TY→TI 映射，R2 §4 步 3 明确要合一）。

### 4.2 依赖图三层（一层是既有）

| 层 | 内容 | 来源 |
|---|---|---|
| 图内 | HDFG 节点/边 + region 嵌套 + state edges | **既有**（`dataflow.cr`，零改动） |
| 记录内 | 记录 → 其 `evidence`（输入引用） | 新增（§1.3） |
| 单元间 | 文件/符号/导入闭包/单态化实例/构建配置 | 既有 `module.cr res_imports` + 新增 `deps_fp` 摘要 |

### 4.3 开关与开销

- **记录生成**：常开（轻量条目）；**记录展开**：按需（§1.3）——保证缓存命中路径也有记录（L8），同时不给常态编译加可观测负担。
- **落盘位置**：**先行 = 旁路文件**（S-D1 落地路径；与产物同目录或 `.core/`，命名待实施批定）；**终态 = `.ccr` 决策记录段**（**已裁，★D4**：随 R2 P4 同波进段——**段 tag 空间可扩展**，`2026-09-09-lattice-ir-v7-format.md:44` 的 `7+` **未固定分配**（既有注明用途 = 驱逐标注段 / 证书段，与本段并列取号，段名随实施批定））——段化前旁路文件是唯一载体；段化后**两态产物须逐字节同**（守卫判据）。
- **守卫判据**：记录通道关 → 产物逐字节同（照 R2 P1 的 `--type-shadow` 先例，sha256 两态同）。

### 4.4 为什么不能各建一套（反例）

差距 B（`.ccr` 冷热两态 sha256 不同）就是「没有共用载体」的代价：**编译器的决定没有随产物走**，于是缓存命中路径「少做了一些决定」，而没有任何数据结构能告诉你少做了什么。若 §1 自建一套解释数据、§3 自建一套失效数据，则：
- `explain` / `analyze --determinism` 在冷/热两态给出不同答案（因为决定没随条目走）——**直接违反本 spec §1.4 约束 1 与 §1.7.1 约束 6**；
- 缓存键无法知道某条目依赖哪些 policy/配置（因为依赖边与解释数据分家）——**差距 E 无解**。

⇒ L8 的强制：**记录随缓存条目一起存取**。

## 6. 不承诺

### 6.1 路线图 §1.3 三类不可消残留在本 spec 的落法

| 残留 | 本 spec 的落法 |
|---|---|
| **错误 specification** | `explain` 报告的是「编译器**为何**这样做」，**不是**「这样做**对**」。记录的 `cause` 是因由码而非正确性证明；增量主判据（L1 逐字节同）是「同一编译器的两态一致」，**不等于语义正确**——不得当作验证证据引用。 |
| **恶意/失陷外部实体** | 决策记录的**载体是磁盘文件（旁路 + 缓存）**，可被篡改；伪造的记录能让 `explain` 撒谎、能让增量复用错误的决定。故：① `explain` 输出**不是**安全证据（它只谈编译器自己的决定）；② 对抗篡改靠可复现构建/签名（路线图范围内、本 spec 范围外）；③ 记录必须随缓存条目**一起**校验（分量不匹配即 miss，§3.5）。 |
| **需求本身允许危险行为** | 本 spec 不禁止任何能力：上界是**约束数据**，解释是**只读视图**。隔离边界（S-B 族）与上界声明是两件事——上界不构成隔离证明，反之亦然。 |

**路线图 §1.4 面的同一读法**（确定性报告）：

- **错误 specification**：报告说「这个输出的不确定性归因到边界 #27 / 标注 #12」——归因正确**不等于**该归因合法、也不等于该 `race` 标注是用户本意。报告面只呈现，不判合法性（执法归 S-A/S-E）。
- **恶意/失陷外部实体**：**物理不确定性的主要来源正是这一类**（调度、中断、外部输入、受损环境）——报告面能指出「不确定性从哪来」，**不能**消除它；`D_mapping`/`D_external` 的 PROVED 只对**声明域内**成立。
- **需求本身允许危险行为**：`race` / `select_any` 是**显式请求**的不确定（§1.4 第 3 档）——报告面把它呈现为 `EXPLICIT`（有主），**不阻止、不试图消除**；「不确定性 = 显式请求」的全部要求就是它**不得偷偷发生**。

### 6.2 本 spec 特有的四条不承诺

1. **不承诺所有决策都可解释**。启发式的内部状态（预算余量、搜索顺序、成本启发式）可能**不可归因**；此类情形**必须**落 `unattributed` + 登记（§1.4 约束 3），**不得**事后编造因由码。`heuristic`/`env` 分级（L3）就是为这条服务。
2. **不承诺上界对所有程序可判**。`UNKNOWN` 是**合法输出**（§2.2）；动态 spawn、外部输入驱动的循环界、无尺寸标注的映射层、`D_timing` 无成本模型——都落在 `UNKNOWN`。把 `UNKNOWN` 渲染成 bound 等同静默降级（禁止）。
3. **不承诺增量对所有变更正确**。承诺的是：**判据可测**（§3.4 三级 + 负控）＋ **失效面覆盖**（分量表 §3.3）＋ **未覆盖即响亮回落全量**（§3.5）。未覆盖的变更面**必须登记**（§7.2 / TODO），不得沉默。
4. **不承诺 `MODELED` 是证明，也不承诺报告面能消除不确定性**。报告面只**归因**（每条不确定性有一个主人：边界 / 显式源 / 成本模型 / 断链），不承诺把它变成 `PROVED`。`MODELED` 的数字永远带 `band` + `assumptions[]` + 模型版本，**禁止**呈现为 WCET 证明（L13）；`EXPLICIT` 是被明文请求的不确定，呈现它、不替用户消除它；`UNKNOWN`（含断链）是合法终局，**不得**用启发式常数补成 `MODELED`（§1.7.3 禁令）。

## 7. 不做项与开放问题

### 7.1 不做（YAGNI）

- **不建成本模型、不推导时间上界、不做 PGO/向量化决策** → S-C（+ hw-map）。
- **不做证明搜索/不变量推断**（ΔProof 只定义失效面）→ 验证切片轮（`src/kernel/`）。
- **不做节点级 ΔBinary**（O7；前置 = 稳定身份 L9 的全面落地）。
- **不做命中路径的产物保真机制**（字符串驻留序 / 全局初始化重放，§3.2 差距 A/C）——L7（冷 / 热逐字节同）保留为**整体目标**，其闭环机制另立项；S-D3 只做键的依赖集（C4/★D25）。
- **不做自动修复建议**（code actions）→ LSP P1。
- **不做分布式/跨机缓存的 explain**（`cir_cache_fetch`/`store` 预留接口保持原样，语义不变）。
- **不新增 LSP 协议扩展**（LSP spec §6 纪律）。
- **不做「解释优化器统计模型的内部量」**——内部搜索过程不是可审的对象；只解释**决定 + 因由码 + 输入证据**。
- **不把查询面做成 Datalog/图查询语言**——起步 = 锚点 + 问题类；复杂查询语言是复杂度陷阱（与「不把机器写进程序意义」同纪律）。
- **不定义汇合语义、不做不确定性执法**：`merge_deterministic` / `merge_ordered` / `race` / `select_any` 的图级定义与 `select` 重定 **逐字归 S-E**；「隐式竞争 → reject」的执法点归 S-A/S-E（路线图 §1.4 边界；本 spec 的 `analyze --determinism` = **只读**，L12）。
- **不做物理不确定性的消除**（调度固定化 / 时间隔离 / 确定性执行沙箱 / WCET 工具链）——那是执行模型面（S-E）与环境面，不是报告面。
