**性质**：只读审计（**零构建、零源码/测试改动**；全部结论来自实读 + `grep`）· **体例**：照 `2026-09-16-preexisting-bug-ledger.md`
**来源**：`criteria-strength-audit` 代理的判据强度审计全文（含 **05:54–05:58「判据载体化」批落盘后的状态修订**）+ `plan-capacity` 代理的坐标实核。
**扫描快照**：审计者 = 今日 23:21 前后的树，**05:54–05:58 一批落盘改变了数条结论与坐标**（下文逐条标「**已修 / 仍存**」）。
**缘起（实证）**：seam 批 sd 助手三处漏 `REX.B` —— `[r11]` 编码成 `[rbx]` ⇒ **野指针 139**；而当时的判据**各自独立 `find`**（一条查 `4c8d1d`、一条查 `f20f1003`），**中间插坏字节照样全绿** ⇒ 判据放跑了真缺陷。

## 0. 方法论条目（核心结论）

**弱点形态：片段式字节判据（disjoint-fragment matching）**——同一段期望序列被拆成**多个各自独立的 `find`/子串断言**，片段之间的字节**无任何约束**。
- 判据实际断言的命题是「这些片段各自出现过」≠「这段序列连续出现」⇒ **片段间的插入/替换**（多一字节、错一个 ModRM、换成等长异义指令）都不会变红。
- **实证**：seam 批三处 `REX.B`（现 `src/arch/x86_64/instr.cr:474/489/501` 注释：「漏它则 rm=3 变成 [rbx] ⇒ 野指针 139」）；修复后 A1 判据已改为**连续序列 + 精确 4B gap + REX.B 入列**（表 A 行 A1 = 修正后的强形态）。
- **④ 反例驱动（可操作自检问句，**本节的口味要求**）**：新增/评审任何字节判据时，**逐条问**：
  > **「什么坏实现能骗过这条断言？」**
  答不出 ⇒ 该判据**尚未被证明有效**（不是「够强」）；答得出且**真能骗过** ⇒ **弱判据**（进表 B + 登记 TODO）。
  **落地建议**：把这句话**写进判据所在测试函数的注释**（一行即可，例：`# 反例自检：改 modrm_reg_role 能否骗过本断言？`）⇒ 让「能不能被骗过」成为写判据时的**必答题**，而不是评审时才想起。
  **本日教训（维护者原话）**：判据弱**不是因为写得少，而是因为没人问过它能不能被骗过**。
- **强判据写法**：① **连续序列断言**（整条指令字节，含 `??` 通配位）；② **带定长 gap 的正则**（`..{0,N}`，N 尽量小并写明理由——A1 即此形）；③ **锚点 + 定长窗口**（长度可变段用**长度公式**，如 A2 的 `text[m+1]==0x83 and text[m+2]==0xEC → text[m+3]`）；④ **反例驱动**：每条字节判据评审时须回答「**什么坏实现能骗过它**」——写不出反例 ≠ 强，写得出而判据仍绿 = 弱判据。

## 0bis. 第二类假绿：**探针不触发**（probe-doesn't-reach）（2026-09-16，apx 转换缺口批 T1 实测）

**本文 §0 命名的是第一类：片段式判据**——判据**断言写弱了**，能被坏实现骗过（断言在骗，探针本身走到了路径）。
**本节的第二类与之正交**：**判据本身没问题，但探针根本没走到被测路径** ⇒ 同样产出**假绿**。

| 面 | 第一类（片段式判据） | 第二类（探针不触发） |
|---|---|---|
| **谁坏了** | **断言** | **探针 / 语料** |
| **为什么假绿** | 断言能被坏实现骗过（片段之间无约束） | 缺陷即使存在也必然显绿（被测路径压根没执行） |
| **修法** | 改**断言**（连续序列 / 定长 gap / 锚点窗口） | 改**探针**（让它真走到那条路径）+ **加覆盖面自证** |
| **自检问句** | 「**什么坏实现能骗过这条断言？**」 | 「**我怎么知道探针走到了那条路径？**」 |

### 实证（**决定性，2026-09-16**）：apx 探针的声明形

apx 审计（`2026-09-16-apx-conversion-audit.md`）表 B 的十条探针源**统一**写作 `d : ., apx = 7.0;`（类型位用 `.` 推断 + `apx` 标签）。而 `ir_gen.cr:2388-2393` 的 apx 槽建立**以 `declared_ti == TI_DEX` 为前提**；类型位写 `.` 时 `declared_ti = TI_UNIT`（`:2377-2378`）⇒ apx 分支**整段不进** ⇒ 槽型回落 `TI_DEX_S` ⇒ **apx 标签对槽形式零作用，探针退化为普通精确 dex**。
⇒ 该表十条**全部假绿**：不是断言写弱，而是**探针从未走到 apx 转换面**。

**判别法（本例，可机械执行）**：
1. **产物形态自证**——`.cir` 中 **`const dex = <binary64 位模式>` 序列的在场性**（显式形：`const dex = 4619567317775286272`（7.0 的 bits）+ `_dxs`/`_dxm`/`_dxc`/`branch`/`_dxh`/`F2I` 序列；推断形：只有 `const dex = 7000000` + `store`）；
2. **反向自证**——`corec run`（解释器）在**显式形**下**拒收 rc=255**（`IR_I2F/IR_F2I` 无 binary64 语义，`interp.cr:263-266`/`:704-705`），推断形则正常取值 ⇒ **拒收本身就是「apx 槽确已建立」的证据**；
3. **正据（数值反推执行路径）**——`bits(7.0) mod 2⁸` 与实测读数的逐例吻合（T1：`4619567317775 mod 256 = 15`，9 例同值）⇒ 证出「bits 原样入槽 + 读点定型 `TI_INT` + `@raw_int` 无转换」这条链**确实被执行**。

### 通用判别法（**写探针时的必答题，与 §0 的反例问句配对**）

> **「我怎么知道探针走到了那条路径？」**

可用的落法（任选 ≥1，写进探针注释）：① **产物形态自证**（IR/字节/段里能看见被测路径**独有**的标记物）；② **反向自证**（被测路径**存在时**必然产生的副作用/拒收/诊断，缺失即未走到）；③ **突变自证**（把被测路径**改坏** ⇒ 探针必红；不改坏时绿——这条同时覆盖两类假绿）；④ **数值反推**（用被测量反推执行路径，见上）。

**与 §0 的关系**：§0 问「断言能不能被骗过」，本节问「探针有没有走到」——**两问都答得出，判据才算被证明有效**。本条与 apx 批的**交叉引用**：`docs/superpowers/plans/2026-09-16-apx-conversion-fix.md` §1.1 校正 C / §7bis。

### 实证（追加，2026-09-16 判据网加固批）：两条同族实例

本批把 §0bis 的问句**用在了判据自身上**，当场抓到两条同族假绿（都不是推论，是改强过程里撞出来的）：

**实例 1：判据内部的 `sub` 分支从未被走到（`test_mw_task2.py` 慢路径块体模板，#85/B6）**
- 事实：块体模板加了 `is_sub` 分支断言（sub 站点块内多 3B `49 F7 D3` = `not r11`），而**原三例 `t1_add`/`t2_add_overflow`/`t3_bigfunc` 全是 add**（`x + 1`/`x + x`）⇒ 该分支在语料上**从未被走到**，断言即使写错也恒绿。
- 处置：加 `t4_sub_overflow`（`x = x - -4611686018427387904` ⇒ 2^63 正溢出）——sub 版块被真走到（`@O0/@O1/@O2` 三档 + 16B stdout 数值校验）。
- **判别法（可机械执行）**：**逐分支覆盖检查**——把判据里每个条件分支（`if is_sub` / `elif name == "store"` / 事件 id 集合 / 行类型分类…）列出来，逐个问「**哪条语料/哪个用例走到它？**」；答不出的分支 = 该分支断言**未被证明**（要么补语料，要么在注释里显式登记「本分支未覆盖」）。

**实例 2：fail-closed 解码器当场抓到「未登记指令形态」（`test_mw_task2.py` `x86_insn_len`，#90/B1）**
- 事实：零 diff 腿的判据侧长度解码器上线首跑即**判红**——慢路径块首 `4D 19 DB`（`sbb r11,r11`）的 opcode `0x19` 未登记（`_OP_MODRM` 漏了 `0x11/0x19` 两个 ALU 双操作数 opcode）。
- 意义：这正是「宁可红不静默」的**现场实证**——若解码器当初写成「未知 opcode ⇒ 当 1 字节放过」或「未知 ⇒ 跳过」，这条缺口会**静默留在判据里**（正是 §0bis 要消灭的形态）。fail-closed（未知形态 ⇒ 抛错 ⇒ 判红）把「未覆盖面」变成了「必须处理的显式事件」。
- **判别法（同族）**：任何判据侧的「解码/解析/分类器」都应当 **fail-closed**：未登记形态 ⇒ 红，而不是 `continue`/`pass`/默认值。判据的**未覆盖面**必须响，不得静默。

### 0quater 「**新增诊断 ≠ 修好**」**已被证明会工作**（2026-09-16 #93 批实证）

**机制**：一次**修改触发面**（补实参推断）会**同时**带来两类结果——① 真修好（原本静默的错被报出/被修）② **新引入误报**（原本合法的写法被判错）。二者在「诊断计数」上**不可区分** ⇒ 若用「新增诊断数上升」当修好证据，**必然把误报一起记成修好**。

**实证（#93 批 T4）**：该批修好实参推断后，74 档 rc 逐档不变、码集变化 11 档**逐条归因全部「本来就该报」**（零误报）——**但**另两条载体变红：`tests/probes/p_spawn.cr`（29 探针之一）rc 0→1、`tests/selfhost/test_interp_parity.py`（已挂 CI）23/23→22/23。
根因 = **`go i a..b body` 的迭代变量在 checker 里从未绑定**（checker 缺口，此前被「实参从不被推断」这个 bug 掩盖）⇒ 修好推断后**暴露为 N01 误报**。
⇒ **若按「新增诊断一律算修好」，这两处红会被记为修好**——而该批的**腿 C 纪律**（逐条归因 + **不许把新增诊断一律当修好**）**当场抓到了它**，遂停下取裁、补绑定、复验回归。

**落地要求（与 §0/§0bis/§0ter 并列的第四条）**：
> **凡是「改判定触发面」的批次，判据必须**把「新增诊断」默认按**回归嫌疑**处理**，逐条归因到「本来就该报」才计入修好；**且必须有「原载体回归」这一判据**（本例 = 29 探针 + 已挂套件的 rc 基线），因为**新形态的断言不等价于原载体的断言**。
