# `.crasm` 统一汇编抽象层设计

日期：2026-08-08
状态：已批准（brainstorming 会话，五节逐节确认）；2026-08-09 整理为正式文档 `docs/crasm.md`（本 spec 保留为批准记录）

> 2026-09-05 取消：独立 `.crasm` 格式不再使用。该格式与经典硬件耦合过紧，相关需求由硬件接口表（HIT）承接（见 `docs/superpowers/specs/2026-09-05-hardware-interface-table.md`）。本文保留为历史批准记录。

## 背景与动机

Core 的内核路线（`project-book` 第五阶段）需要汇编级能力（MMIO、特权指令、中断），但当前没有任何汇编层（`lexer`/`parser` 无 asm 语法；汇编只存在于 `rt.s` 手工汇编与 ELF 后端机器码发射）。设计目标（用户原话）：

- 不安全隔离：特权操作隔离在受控区域
- 能够验证绝大多数：普通级指令全部可自动验证，特权级用法也可以自动验证
- 跨平台统一：平台间指令不同，使用统一指令集和平台映射表解决

## 设计原则

### 统一指令集与无限虚拟寄存器

- `.crasm` 是新生态（无旧代码兼容义务），因此可以使用统一指令集
- 虚拟寄存器 `%0, %1, ...` 无上限。书写者不需要关心平台寄存器数量，由 ISA 后端自动分配（复用现有 `opt.cr alloc_registers` 线性扫描分配器）
- 平台映射表（普通和特权指令）负责翻译到真实 ISA

### 限制可写性

`.crasm` 有意保持较低的编写便利性，这是设计目标，不是缺陷：

- 寄存器强制使用 `%0/%1` 编号，不命名。代码难以维护，因此长汇编程序不容易出现
- 复杂逻辑既不适合写在汇编层，也无法写完整，复杂逻辑属于 Core 层
- 汇编层保持小范围：只表达明确意图，便于限制滥用，也便于集中验证
- 代码越简单越容易验证。限制可写性就是保障可验证性

### 生态边界

- `.crasm` 新代码按统一指令集写，无兼容义务
- 旧 `.c`/汇编代码原样保留（不迁移），互不干扰

## 架构

```
.cr 侧（平台无关接口）              .crasm 侧（统一抽象层）
extern fn port_read(addr: u64)      fn port_read(addr: u64) -> u8 {
  -> u8;                              %0 := load [addr];
                                      if %0 == 0xFF goto L1;
                                      return %0;
                                    }

        |                                   |
        +--- ABI（参数映射到虚拟寄存器） ---+
        |                                   |
        +--- 后端翻译 ----------------------+
                    |
          平台映射表（src/arch/<isa>/）
          x86-64 / ARM64 / RISC-V
          寄存器分配（alloc_registers 复用）
```

## 指令集（统一、平台无关）

### 指令类

| 类 | 指令 | 平台无关语义 |
|---|---|---|
| 数据传输 | `%d := load [addr]`、`store [addr], %s` | 内存读写 |
| 算术/逻辑 | `%d := %a + %b`（+ - * / & \| ^ << >>）、`%d := ~%a` | 无限虚拟寄存器运算 |
| 比较/分支 | `if %c == 0 goto L`（== != < > <= >=）、`goto L`、`call fn`、`ret` | 控制流 |
| 内存操作 | `%d := %a + off`（地址算术）、`%d := zext/ext` | 地址计算与宽度转换 |
| 特权级 | `mmio_read(addr)`、`mmio_write(addr, val)`、`barrier`、`cache_op`、`irq_enable`/`irq_disable`、`swap_context`、`halt` | 硬件访问（固定集） |

### 特权指令固定集

特权指令是标准手册定义的有限固定集（几十条）。固定意味着约束有限，可以形式化，也可以验证。

### 标识约定

| 标识 | 约定 | 示例 |
|---|---|---|
| 寄存器 | `%` 前缀编号（与 LLVM IR 相同） | `%0, %1` |
| 函数 | 普通标识符（与 Core 一致，无 @） | `fn port_read` |
| 标签 | `L` 前缀无符号 | `L1` |
| 立即数 | 裸写 | `42`、`0xFF` |

## 安全模型

### 指令分级与验证策略

| 级 | 指令 | 验证策略 |
|---|---|---|
| 普通级 | 数据传输/算术/分支/内存操作/地址计算 | 自动验证：寄存器生命周期 + 地址 provenance/边界（复用现有指针模型 pass），覆盖绝大多数情况 |
| 特权级 | mmio/barrier/irq/swap_context/halt | 用法验证（自动）：参数类型/宽度、放置规则、指令间约束（固定集可以形式化）；副作用隔离（unsafe 边界）：硬件行为/时序超出编译期验证范围，由人工保证 |

### 寄存器生命周期规则（新 pass，`.crasm` 专用）

| 规则 | 检查内容 | 违反示例 |
|---|---|---|
| 未初始化读 | 读操作数前必须被写过 | `%1 := %0 + 1` 而 %0 未定义 |
| 重复写 | 同一寄存器活跃期只写一次（SSA 式） | 两条路径写 %0 后汇合未合并 |
| 生命周期逃逸 | 寄存器值不能越过函数边界（除非经 ABI 声明） | 函数返回未声明的 %5 |
| 宽度一致 | 运算操作数宽度匹配（8/16/32/64） | `%0(8bit) := %1(64bit) + 1` |
| 分支一致性 | goto 目标存在；if 条件是条件寄存器 | `if %0 == 0 goto missing` |

### 与现有验证的关系

- 寄存器规则：新 pass（`.crasm` 专用，虚拟寄存器是抽象层概念）
- 地址/内存验证：复用 PointerAnalysis / RegionCheck / ProvenanceVerify（`.crasm` 的 `load [addr]` 转成与 IR 相同的 provenance 检查）
- 特权用法验证：固定指令集约束表（参数宽度/放置规则），由 pass 检查
- 错误报告：走新错误码体系（验证类，挂错误码规格类别表，实现时定归属）

### 示例

```crasm
unsafe fn port_write(addr: u64, val: u8) {
    // 用法验证：addr 必须 64 位、val 必须 8 位（与 MMIO 寄存器宽度匹配）
    // 副作用隔离：写入后的硬件行为由人工保证
    mmio_write(addr, val);
}
```

## 交互接口

### `.cr` 与 `.crasm` 的接口

```cr
extern fn port_read(addr: u64) -> u8;    // .cr 侧：C ABI 先例
data := port_read(0xFEED_0000);          // 普通函数调用
```

接口映射：参数映射到虚拟寄存器（ABI 参数寄存器），返回值映射到返回寄存器。平台 ABI 差异由后端处理。

### 平台映射表组织

```
src/arch/
├── x86_64/    指令映射表（普通 + 特权）、ABI 规则、寄存器分配
├── arm64/     同接口，不同映射
└── riscv/     同接口，不同映射
```

映射表是每个平台一份「统一指令到真实指令」的翻译表，属于编译器后端的一部分，做机械翻译，与现有 `src/arch/linux/ld/` 后端结构相同。特权指令映射在表内固定（`mmio_read` 对应 x86 的 `mov`，arm 的 `ldr`）。映射正确性由固定表保证。

### 编译流程

```
.crasm 解析（结构化指令，复用 AST）
       验证（寄存器/地址/特权用法）
       翻译（统一指令到目标平台指令，使用映射表）
       与 .cr 编译产物链接（现有 ELF 后端）
```

## 测试与阶段目标

### 测试策略

| 层 | 实现方式 | 覆盖 |
|---|---|---|
| .crasm 解析/验证单测 | tests/selfhost（Python 驱动） | 寄存器规则、地址边界、特权用法 |
| 翻译正确性 | 每平台一个映射测试（x86 先行） | 统一指令到真实指令的字节级断言 |
| 端到端 | .crasm + .cr 链接运行 | port_read/write 全链路 |
| 特权隔离 | unsafe 边界测试 | 普通函数使用特权指令时编译错误 |

### 阶段目标

1. `.crasm` 词法/解析（结构化指令转 AST）
2. 寄存器生命周期 pass + 测试
3. 特权约束表 + 用法验证 + unsafe 隔离
4. x86-64 映射表（翻译器）+ 字节级测试
5. `.cr` extern 接口接通 + 端到端
6. （后补）ARM64/RISC-V 映射表

### 明确不做（YAGNI）

- 模拟器/调试器支持
- .crasm 的 C 生态兼容（新生态无义务）
- 指令级时序验证（超出编译期验证范围）
- 特权指令副作用验证（隔离，人工保证）
