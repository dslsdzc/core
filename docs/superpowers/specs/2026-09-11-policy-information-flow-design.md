# 信息流判定：Secret 不能流向 Public

## 概述

程序里的值有两类安全属性：

- 机密性（`secrecy`）：值的内容能否被外部观测。
- 可信度（`trust`）：值的内容能否被不可信来源影响。

本设计要保证：带有 `Secret` 标签的值不能到达要求为 `Public` 的位置，带有 `Untrusted` 标签的值不能到达要求为 `Trusted` 的位置。唯一例外是显式的 `declassify` 节点。

判定不是对源码模式做扫描，而是在语义图上做一次标签传播，再对每个检查点做一次包含判定。

## 设计原则

- 标签由数据给出，传播规则由语言实现。标签的来源和格的实例由策略或领域库给出；语言只提供传播规则、`declassify` 节点和义务分级。
- 不加关键字，不按函数名做特殊处理。
- 格结构是策略参数。语言不固定格，默认实例是二元素布尔格。
- 传播由编译器自动完成，来源和降密必须显式写出。变量级不需要标注；标注只出现在边界声明、库的类型化构造器和可选的签名契约上。
- 判定统一由类型引擎完成：标签编码为类型项，检查是一次 `ty_sub`。
- `declassify` 是唯一降低标签的通道。`unsafe` 不改变标签。
- 判定不通过时，必须归入明确的义务档，不能被当作通过。

## 标签轴

| 轴 | 含义 | 默认值 | 序 | 降低标签的动作 |
|---|---|---|---|---|
| `secrecy` | 值的内容能否被外部观测 | `Public`、`Secret` | `Public ⊑ Secret` | `declassify` |
| `trust` | 值的内容能否被不可信来源影响 | `Trusted`、`Untrusted` | `Untrusted ⊑ Trusted` | 带验证规则的降标节点 |

本设计使用 `secrecy` 和 `trust` 两条轴。

`integrity`（值是否可能被非授权方改写）与 `trust` 对偶，但不是同一条轴。本设计不定义 `integrity` 的判定面；它由授权和状态版本两个设计使用。

`trust` 能判定的是不可信性在程序内的传播。来源本身的真实性（谁生产、谁签名、谁背书）不能由语言判定，只能通过可复现构建、签名和 provenance 缩小范围。

## 格结构与合并

默认格是二元素布尔格：

```text
Public  ⊑ Secret
Untrusted ⊑ Trusted
```

多级格（级别加类别）和按 principal 索引的格都是默认格的推广实例。语言侧只要求两个操作：

- `⊑`：序关系。
- `⊔`：最小上界，用于合并。

分支合流、PHI 节点和参数合并都取 `⊔`。传播因此是单调的，格高度有限时最小不动点存在且唯一。

## 序方向

安全序和类型序方向相反。这是实现时最容易写反的地方。

| 事实 | 安全表述 | 类型判定 |
|---|---|---|
| 公开数据可以进入机密上下文 | `Public ⊑ Secret` | `labeled<Public,τ> <: labeled<Secret,τ>` 成立 |
| 机密数据不能进入公开上下文 | `Secret` 不能到 `Public` | `labeled<Secret,τ> <: labeled<Public,τ>` 不成立 |
| 合流取更机密者 | 分支合流取上界 | `label(phi) = ty_join(A, B)` |

`Secret` 不能到 `Public` 在类型层表现为子类型关系不成立，不是一条单独的禁止转换规则。

## 标注

### 来源

标注只有三个来源：

| 来源 | 形态 | 写入方 | 默认值 |
|---|---|---|---|
| 边界声明 | 图边界输入点的标注，例如 MMIO、FFI、输入和测量 | 用户或部署策略 | 未声明时为 `unknown` |
| 库的类型化构造器 | `Password::read() -> labeled<Secret, string>` | 领域库 | 由库声明 |
| 签名契约 | 函数的标签契约，参与接口注册表，在调用点判定 | 库作者或用户 | 缺省时由函数体推导，取函数体的上界 |

未声明的边界条目取 `unknown`，不取 `Public`。`unknown` 不能被当作通过：默认模式把它登记为未判定并写入报告；`strict` 模式拒绝编译。

### 保存位置

| 保存位 | 内容 |
|---|---|
| 值标签 | 每个 IR 变量或数据边一个标签类型项 |
| 区域标签 | 每个区域（`SG_IF`、`LOOP`、`FOR`、`FLOW`、`UNSAFE`）一个标签 |
| 条目标签 | 每个分配条目一个标签，取所有存入值的 `⊔` |
| 降密记录 | `declassify` 节点的四个字段 |

## 流规则

### R1：值标签

```text
label(v) = (⊔ label(每条数据入边)) ⊔ region_label(region(v))
```

`region_label(ρ)` 是区域 ρ 及其全部祖先区域的标签的 `⊔`。

### R2：区域标签

- `SG_IF` 的两个子区域都取条件标签。
- `LOOP` 和 `FOR` 的循环体取循环条件或计数的标签。
- `FLOW` 和 `UNSAFE` 不增加自己的标签。

R2 处理的是实参为常量、R1 看不到的控制依赖。例如：

```text
if secret {
    print("A")
} else {
    print("B")
}
```

两条 `print` 的实参都是常量，但条件标签会进入两个分支区域，因此两次输出都带 `Secret` 标签。

循环次数经输出点外溢的情况也由 R2 处理：

```text
for i in 0..secret_n {
    send(x)
}
```

循环体区域带 `Secret` 标签。

R2 只覆盖结构化控制流。如果 IR 中存在 goto、长跳转或其他非结构化控制，需要单独审计；审计前登记为未覆盖。

### R3：条目标签

```text
label(entry e) = ⊔ label(每个写入 e 的节点)
label(load e)   = label(e) ⊔ label(地址或偏移值)
```

条目标签的粒度是整条目。一个数组里存入一个 `Secret` 值，整个数组都带 `Secret` 标签。这偏保守，但安全。按偏移的精度以后再做。

### R4：检查点

对每个检查点 `s`：

```text
obs(s) = (⊔ label(实参)) ⊔ region_label(region(s))
ty_sub(obs(s), required(s))
```

`required(s)` 的来源：

- 边界输出点（print、文件、网络、syscall、panic 等跨越图边界的操作）默认要求 `Public` 或 `Trusted`。这是默认拒绝：任何已经带 `Secret` 或 `Untrusted` 的到达都会被拒。
- 库内输出点由库声明 `required`。
- 非边界的内部函数调用不设 `required`，否则等于要求全程序加标注。

默认拒绝是策略数据，可以被策略覆写。

### 已知边界

`state` 边表达执行顺序，不是值依赖，不传播标签。一个副作用是否发生由它所在区域的标签决定，R2 已经覆盖。

顺序信息本身在机密性方向不构成信道：谁先谁后不泄漏内容。可篡改性方向由状态版本设计承担，本设计不使用也不重新定义 `integrity`。

`Secret` 不能到 `Public` 只能检出已经标注为 `Secret` 的流。如果库或用户漏标来源，本设计不推断秘密性，因为没有判断秘密性的静态来源。漏标不会无记录地通过：未声明的边界条目进入 `unknown` 类别，必须出现在报告里。

## 判定引擎

标签编码为类型项：

```text
labeled<L, τ> = product(label_atom(L), τ)
```

标签是 product 的一维。值语义和 R1 到 R4 的传播都是同一维度上的 `⊔`。

类型引擎需要提供四个性质：

1. 标签原子和序公理：`label_atom(Public) <: label_atom(Secret)` 等，作为引擎公理注册。
2. 维度隔离：标签原子和基类型原子属于不同维度。`labeled<Secret, int>` 和 `labeled<Public, string>` 可以同时成立，不能被互斥公理误判为不相交。
3. `join`：`ty_join(A, B)` 是序下的最小上界。如果引擎暂时不导出 `join`，可以用显式构造式实现。
4. 非退化：`label_atom(Trusted) ⊓ τ` 对正常基类型不等于 `⊥`；`Shape` 侧不能退化为 `⊤`。否则正向用例会全部失败，或者检查会被绕过。

检查是一次 `ty_sub(obs(s), required(s))`。失败时给出反例路径，指出哪条边把标签带到了检查点。

引擎预算耗尽或桥接失败时，结果按未判定处理，不能当作通过。`on` 模式登记并告警，`strict` 模式拒绝编译。

标签不做独立推断。泛型函数的标签多态按普通类型参数具体化处理：实例化时检查 `ty_sub(实参标签, 约束标签)`。

## 处理流程

```text
1. 建标   边界声明、库构造器、签名契约 -> 初始化标签
2. 传播   R1、R2、R3 单调不动点
3. 检查   R4：每个检查点一次 ty_sub
4. 落档   prove、enforce、proof-required、reject
```

前两步只读图并写标注，不改变 IR 结构，不影响代码生成。启用与否由策略控制。

标签和降密记录进入 `.ccr`。前端输出之后，验证和审计工具可以直接使用，不需要重跑前端。

## 覆盖范围

| 信道 | 规则 | 结论 |
|---|---|---|
| 显式值依赖（数据边） | R1 | 覆盖 |
| 显式分支和条件写 | R2 | 覆盖 |
| 循环次数经输出点外溢 | R2 | 覆盖 |
| 循环次数经纯计算影响时长 | 无 | 未覆盖，属于成本模型和硬件层 |
| 经堆的隐式流 | R3 | 覆盖，粒度为整条目 |
| 经 `unsafe` 或 FFI 写 | R4 | 覆盖为检查：`unsafe` 不改变标签 |
| 进程终止（panic、异常、提前返回） | R2 | 覆盖其发生；消息内容由 R1 覆盖 |
| timing、非终止 | 无 | 未覆盖 |
| 微架构（cache、分支预测、功耗、电磁） | 无 | 未覆盖，属于硬件层 |
| covert channel | 无 | 未覆盖 |
| 动态标签（反射、`dyn`、外部返回的标签） | enforce | 设计但不实现 |
| 非结构化控制流 | 无 | 假设不存在，待审计 |

## declassify

### 字段

`declassify` 是图上的显式节点，也是降低标签的唯一通道。

| 字段 | 内容 | 要求 |
|---|---|---|
| 目标标签 | 降到哪一档，不是隐含的“公开” | 必填 |
| 范围 | 只作用于流经本节点的那个值，不是此后该变量全部允许 | 由节点语义强制 |
| 理由 | 审计事实，例如 `"password-verify:1bit"`，随图进入 `.ccr` | 必填；`strict` 模式下空理由拒绝编译 |
| 授权 | 谁有权降密 | 交给授权设计判定 |

`declassify` 条目进入策略清单，包含目标、范围、理由、派生源和义务引用。`strict` 模式下，理由缺失或审计字段不完整时拒绝装载。

### 可审计性

1. 禁止隐式插入。任何 pass、库或默认行为都不能自动生成 `declassify`。
2. 优化必须保持标签。跨越 `declassify` 边界的变换不能改变释放了什么，不能把计算提升或下沉穿过降密点导致范围扩大。
3. 删除节点不删除记录。被 DCE 删除的 `declassify` 节点不产生运行期语义，但降密记录保留在审计通道里。
4. 可计数。降密点是有限、可枚举的图节点。审计就是枚举全图的 `declassify` 节点并读取四个字段。

### 与 unsafe 的关系

| | `unsafe` | `declassify` |
|---|---|---|
| 语义角色 | 边界标注：编译器无法追踪 provenance 的入口 | 降密节点 |
| 对标签的作用 | 无。进出 `unsafe` 不改变标签；`unsafe` 内产生的值继承输入的标签 | 唯一合法的降密动作 |
| 何时需要 | 外部地址、FFI、inline asm 等没有 provenance 的场合 | 需要把机密或不可信内容交给低标签位置时 |

`unsafe` 不清除标签。下面这段仍然是违例：

```text
unsafe { raw_write(fd, secret) }
```

如果确实需要在 `unsafe` 内降密，使用 `declassify` 并附上证据，不放宽 `unsafe` 的语义。

### 密码学操作

`encrypt(k, secret)` 的输出默认仍然带 `Secret`。加密不是自动降密。

正确形态是显式降密：

```text
declassify(encrypt_output, 目标=Public, 理由="AEAD:nonce+ciphertext")
```

加密是否达到语义安全，语言层不能证明，因此归入 proof-required 档，要求用户或库提供契约或证明工件。

哈希、编码、截断和启发式扫描同样不是降密。它们只能作为 `declassify` 的证据素材。

### trust 方向的降标

`trust` 方向的机制与机密性方向相同，只是方向相反，证据种类不同：

- 机密性方向需要说明为什么降密，附带可选的密码学证明。
- `trust` 方向需要说明依据什么规则判定为可信，例如解析、允许清单、转义或参数化的具体规则。

降标节点的形态和领域库接口约定属于注入设计。本设计只规定它在流规则中的语义：一个带 proof-required 证据的降标节点。

## 义务分级

| 判定结果 | 档 | 处理 |
|---|---|---|
| `ty_sub(obs, required)` 为真 | 1 prove | 零成本通过，无产物变化 |
| 标签是动态值，且存在强制点 | 2 enforce | 运行时检查标签，失败则中止。设计但不实现 |
| 降密或降标规则的正确性不能由语言证明 | 3 proof-required | 要求契约或证明工件；节点带有引用；缺失则不通过 |
| 引擎预算耗尽、桥接失败，或 `strict` 模式下遇到未覆盖项 | 4 reject | 拒绝编译 |
| 未声明的边界条目（`unknown`） | 3 登记并写入报告；`strict` 模式为 4 | 不能当作通过 |
| `ty_sub(obs, required)` 为假 | 违法，不属于义务档 | 硬编译错；唯一允许的降密动作是 `declassify` 或降标节点 |

档 1、2、3 的区别不是能不能判，而是证据从哪里来：

- 1 靠引擎。
- 2 靠运行时。
- 3 靠人或工具。

三者都不能被当作通过。

### 模式

| 模式 | 行为 | 用途 |
|---|---|---|
| `off` | 不做流验证，不建标，不检查，零产物变化 | 未启用策略的项目；零回归基准 |
| `on` | 执行 R1 到 R4 和边界默认拒绝；未判定面登记并告警 | 常规启用 |
| `strict` | 在 `on` 的基础上，未判定和未覆盖项拒绝编译；`declassify` 必须有理由和授权引用 | 高保证构建 |

默认 `off` 是工程选择：规则随策略启用，语言本身不加关键字，不改变既有程序语义。

### 义务可见性

- 判定不通过时必须归入 1、2、3、4 之一，不能被当作通过。
- 每次 `on` 或 `strict` 构建的报告必须列出未覆盖项：timing、非终止、微架构、covert channel。
- 未覆盖不等于已经证明安全。
- 预算耗尽不等于类型不兼容，也不等于存在泄漏。通过、违例、未判定三种结论分别记录、分别措辞、分别给错误码。

## 切片

| 切片 | 内容 | 依赖 | 检查 |
|---|---|---|---|
| 1 传播 | 建标（边界声明、库构造器）到 R1、R2、R3 不动点；图转储可见标签和区域标签 | 无，纯图分析 | 正向用例标注正确；`off` 模式零产物变化 |
| 2 检查与降密 | R4 边界默认拒绝；`declassify` 四字段；诊断码 | 切片 1 和 S-A 定稿 | 正向用例通过；负向用例拒绝编译，诊断指向边路径 |
| 3 保存与审计 | 标签和降密记录进入 `.ccr`，审计通道可以枚举降密点 | R2 P4 | 前端输出即带标签和降密记录 |

切片 1 开工前需要满足三个条件：

1. S-A 已经定稿，四档用语和属性轴不再变化。
2. R2 P2b 接线完成，判定统一接口就位。否则标签的 `ty_sub` 会成为第二套判定。
3. 依赖完备性审计完成。逐 op 核对语义依赖是否都表达为图上的边或区域，重点检查内存读写的地址和偏移、`dyn`、间接调用、间接写，以及是否存在非结构化控制。审计输出覆盖率和缺失项清单。

只有覆盖率报告没有缺失项时才启动切片 1。有缺失项时不启动，不能在有缺失项时开工。审计不完备的 op 一律列入未覆盖项。

## 检查

正向用例必须通过：

| # | 样例 | 通过理由 |
|---|---|---|
| 1 | `pw` 经 `hash` 到 `verify`，库契约返回 `labeled<Public,bool>`，再进入 `if ok { grant() }` | 契约级降密，1 bit 泄漏是需求本身要求的 |
| 2 | `secret` 经 `declassify(目标=Public, 理由="audit-export")` 到 `println` | 唯一合法通道，留下降密记录 |
| 3 | `secret` 经 `hash` 再经 `declassify` 到 `println` | 哈希不是降密，`declassify` 才是 |
| 4 | `argv` 经 `parse` 和 `validate(规则 R)` 到受信路径 | 降标节点加 proof-required 证据 |
| 5 | `public` 进入要求 `Secret` 的位置 | 上行合法 |
| 6 | `secret` 经计算、`declassify`、再计算到公开输出点 | 降密只解除流经该值的那部分标签 |
| 7 | 未启用策略的既有程序 | 产物逐字节相同 |

负向用例必须拒绝编译：

| # | 样例 | 违例规则 |
|---|---|---|
| 1 | `pw` 到 `println` | R4：边界输出点要求 `Public` |
| 2 | `if secret { print("A") } else { print("B") }` | R2：条件标签进入分支区域 |
| 3 | `arr[0] = secret; ... println(arr[0])` | R3：条目标签 |
| 4 | `secret` 到 `unsafe { raw_write(fd, p) }` | R4：`unsafe` 不清除标签 |
| 5 | `untrusted` 经 `concat` 到 SQL 语法位 | `trust` 传播加端口违例，本设计与注入设计只报一条诊断 |
| 6 | `secret` 经 `encrypt` 到 `println(ciphertext)` | 加密不是自动降密，缺少 `declassify` 和证据 |
| 7 | `if secret { panic() } else { ok() }` | R2：终止的发生受条件标签影响 |

未判定用例必须登记：

| # | 样例 | 处理 |
|---|---|---|
| 1 | `if secret { slow_public() } else { fast_public() }`，时长不同 | 未覆盖 timing；`on` 登记，`strict` 拒绝编译 |
| 2 | `while secret_cond { }` | 未覆盖非终止；同上 |
| 3 | 依赖 cache 行为的密钥表查找 | 未覆盖微架构，归硬件层和密码库 |

其他检查：

1. 序方向表逐行有用例，防止序写反导致全部允许或全部拒绝。
2. `off` 模式下既有语料产物逐字节相同；`on` 模式下未使用标签的语料同样逐字节相同。
3. 套件按 R2 的共同检查行执行，包括全量回归、`corec2` 和 `corec3` 的 `cmp` 结果、N06 计数和快速验证返回码。
4. `on` 和 `strict` 的构建报告必须包含未覆盖项清单；缺少该节视为检查未完成。

## 不承诺

| 不可消项 | 本设计的位置 |
|---|---|
| 错误的 specification | 策略说“这些数据是机密”是规则。Core 证明程序忠实执行了规则，不证明分类本身正确。误标为公开的医疗数据、写错 `required` 的库契约仍然会泄漏 |
| 恶意或失陷的外部实体 | 密钥被偷、硬件后门、编译机失陷、供应链投毒和侧信道测量不在语言语义内。本设计只把程序内部的降密变成显式且可审计的记录 |
| 需求本身允许危险行为 | 需求要求打印密码、管理员导出或调试输出时，本设计不禁止，只要求显式 `declassify`、留下记录，并可选地要求授权 |

本设计另外不承诺：

1. constant-time 或无计时信道。R2 和 R4 只判值流向，不判执行时长。常量时间需要密码库契约、成本模型和硬件层。
2. 无终止信道。`while secret {}` 这类程序不在判定范围内。
3. 无 covert channel。两进程约定和外部系统信道不在经典信息流判定的可判定范围内。
4. 无微架构信道。cache、分支预测、功耗和电磁不在本设计范围内。
5. 秘密不被读取。机密性不等于访问控制；访问控制属于授权设计，路径限制属于路径设计。

## 不包含

- 不做运行时影子标签的完整信息流实现。enforce 档保留为设计位置，当前切片不实现。
- 不做按偏移或按字节的标签精度。当前粒度是整条目。
- 不做独立的标签推断或子类型体系。标签是类型项的一维，由类型引擎判定。
- 不做常量时间或侧信道缓解。
- 不做 covert channel 检测。
- 不做非结构化控制流的流规则。发现这类形式时先登记，不进入当前切片。
- 不做动态标签的自动推理。`dyn`、反射和外部返回的标签归入 enforce 档或拒绝编译，不做猜测。
