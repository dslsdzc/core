## 0. 范围与裁决

### 0.1 论题

把保密性/完整性从「编译后再扫描一下」变成 **Semantic IR 本身的一部分**：

> `Secret ↛ Public`（除非经过显式 `declassify` 节点）；对偶地 `Untrusted ↛ Trusted`。
> 判定不是对源码模式的扫描，而是**图上的一次标注传播 + 一次包含判定**（§2）。

`password → hash → comparison` ✓ 与 `password → println` ✗ 的差别，在图上就是前者流到了 `declassify`/契约降密的出口、后者流到了边界 sink。**图已经有了全部依赖结构**（数据边、region 守卫、条目 provenance）——本族要做的是在同一张图上补一条标注轴与一套流纪律，不建第二套分析体系（承路线图 §1.2 原则 1/4 与定案 4「类型检查 = 图验证 pass」）。

### 0.2 覆盖三档声明（本 spec 的**边界**，逐条落到 §2.4）

| 档 | 含义 | 本族处置 |
|---|---|---|
| **覆盖（可判定）** | 有明确判定规则、可静态判、可给反例路径 | §2.1 四条规则覆盖的面：显式数据流、结构化控制守卫（含循环次数外溢到 effect）、经条目（堆）的隐式流、边界 sink |
| **设计但不落地** | 有明确落法，但本切片不含（成本/依赖） | 动态标签的运行时强制（enforce 档，§5.1）、per-offset 标签精度（§2.1 R3） |
| **登记不覆盖** | 本族**不**承诺，且**不静默**——报告中显式列出 | timing / 非终止 / 微架构 / covert channel（§2.4 T 档 + §7） |

### 0.3 六条裁决（本 spec 自定，供实施批引用；不与共享契约冲突）

| # | 裁决 | 理由锚点 |
|---|---|---|
| D1 | **标签是数据，纪律是语言**：标注以策略/库为源、以图上标注承载；语言内建的是**传播规则 + 释放节点 + 义务阶梯**，不加关键字、不做名字特判 | 路线图 §1.2 原则 1/2；定案 1（类型 = 图标注） |
| D2 | **格结构是策略参数**：语言不固化格；默认实例 = 二元素布尔格 `Public ⊑ Secret` / `Untrusted ⊑ Trusted`；多级（级别 + 类别）与 principal-indexed 是**格的实例**（数据） | 「规则封闭对象开放」（memory-model-capability-lattice v4）；路线图 §1.1「policy = 数据而非语法」 |
| D3 | **传播自动、源与释放显式**：变量级零标注；标注只出现在①边界声明②库的类型化构造器③**可选的**签名契约（契约参与接口注册表，调用点判定） | 定案 12/13（自动推导；显式性最小集）；路线图 §1.1「sink/source 模型由领域库提供」 |
| D4 | **两轴默认方向相反、且都不静默放行**：secrecy 源 = **声明式**（未声明 = `Public`）；integrity 源 = **默认不可信**（边界条目一律 `Untrusted`，纯计算保持） | 违例只由**已声明/已推导出的**高标签触发 → 纪律强度**取决于源侧标注**（库的构造器）；"忘标 = 漏报"是路线图 §1.3 第 1 类的落点，不是本族的静默通过（§5.3、§7） |
| D5 | **判定统一走引擎**：标签编码为**类型项**，检查 = `ty_sub(实测, 要求)`；**不做独立的 label 推断体系**，label 随泛型具体化走 R2 §5.2 | 路线图 §1.2 原则 4；R2 §3.2 判定 API |
| D6 | **释放唯一，且 `unsafe` 不洗标**：降标只有 `declassify` 一条通道；`unsafe` 只是**边界标注**（memory-model §一 条款 4），进出 `unsafe` **不改变任何标签** | 路线图 §1.1 `declassify` 定义；§7 第 2 类不可消 |

### 0.4 为什么这不是「lint 换皮」（路线图 §1.2 原则 2 的反面自查）

① 无关键字、无函数名匹配——标签与格实例是**数据**，换一种安全模型不改 Graph 本体；② 判定对象是**边**（图上的流），不是文本模式；③ 违例**可以拒绝编译**（四档硬落法），不是警告；④ 与 S-B 其余四族**共用同一传播与义务机制**（注入 = 语法位 sink、授权 = capability path、围栏 = 目标不可构造、TOCTOU = 版本等值）——**是基座而非特判**。

## 1. 标签轴

### 1.1 两条轴与格结构

| 轴（路线图 §1.1 术语，逐字引用） | 语义 | 默认实例 | 序 |
|---|---|---|---|
| `secrecy`（机密性） | 值的**内容**能否被外部观测 | `Public` / `Secret` | `Public ⊑ Secret`（低 → 高）；**释放 = 下降** |
| `integrity`（完整性） | 值的**内容**能否被不可信来源影响 | `Trusted` / `Untrusted` | `Untrusted ⊑ Trusted`；**净化 = 上升** |

- **格是参数**（D2）：`level × compartment`（Bell-LaPadula 形）与 principal-indexed（`{alice: Secret}` 形）都是默认二元素格的推广实例；多级格的 `⊔` = 级别取 max + 类别取并。语言侧只需要一个 `⊔`（join）与一个 `⊑`（序）的**接口**，实例由策略给定。
- **join 是唯一的合并算子**：汇合点（PHI / 分支合流 / 参数合并）取 `⊔`，故传播是**单调**的 → 最小不动点存在且唯一，chaotic iteration 收敛（配合 §2.3 的有限高度）。
- **标签是值的属性，不是类型的替代**：一个值同时有基类型（R2 类型项）与标签；推荐编码见 §2.2。

### 1.2 与 `trust` 轴的关系（定案）

路线图 §1.1 同时列了 `trust`（可信度）与 `integrity`（完整性）。二者分层如下，**不可互相替代**：

| | `trust` | `integrity` |
|---|---|---|
| 性质 | **源侧的世界事实**：谁生产/签名/背书了这个来源 | **流侧的导出标注**：这个值的内容是否被不可信源影响过 |
| 能否被语言判定 | **不能**——属路线图 §1.3 第 2 类「恶意/失陷外部实体」，只能靠可复现构建/签名/provenance **缩小** | **能**——沿图单调传播，纯编译期判定 |
| 与谁对接 | 治理层 / 供应链 attestation [S-A 的属性轴开放标注] | 本 spec `secrecy` 的对偶轴 |
| 关系 | `trust` 是 integrity 标签的**诞生地**（边界声明说"这个入口不可信"） | integrity 是 `trust` 在程序内部**传播后的形态** |

一句话：**`trust` 是标签的来源事实，`secrecy`/`integrity` 是标签的流动形态**；把 `trust` 直接当流纪律用会立刻退化成不可判定（"可信"无法从程序结构推出）。

### 1.3 标注的来源与承载

**来源（只有三处，D3）**：

| 来源 | 形态 | 谁写 | 默认 |
|---|---|---|---|
| ① 边界声明 | 图边界入口（无配方条目：MMIO/FFI/输入/测量，memory-model §一 条款 4；语法层即 `unsafe` 边界）的标注 | 用户/部署策略 | secrecy：**未声明 = `Public`**（低）；integrity：**未声明 = `Untrusted`**（D4；两轴的默认都朝"不静默放行"——见下） |
| ② 库的类型化构造器 | `Password::read() -> labeled<Secret, string>` 形（构造器即默认出口） | **领域库**（路线图 §1.1 sink/source 模型；§1.2 原则 2 策略面归库） | 由库声明 |
| ③ 签名契约（可选） | 函数的 label 契约（`fn verify(p: labeled<Secret,string>, h: labeled<Secret,Hash>) -> labeled<Public,bool>`）——契约参与接口注册表，调用点判定 | 库作者/用户 | 缺省 = 由函数体**推导**（保守取体上界） |

**承载**（图上对象，路线图 §1.1「图对象/边上的开放标注」）：

| 承载位 | 内容 | 实现位（待实施批核对） |
|---|---|---|
| 值标签 | 每个值（IR 变量/边）一个 label 类型项 | 与 `irv_type_term`（R2 §3.4 迁移期双槽）同源；label 是类型项的一部分（§2.2） |
| region 守卫 | 每个 region（`SG_IF`/`LOOP`/`FOR`/`FLOW`/`UNSAFE`）一个 label | 与 `g_df_node_region` 同结构，region 表加一列 |
| 条目标签（堆） | 每个**分配条目**一个 label（`⊔` 所有存入值） | 复用 provenance 的条目标识（memory-model §一 条款 6「地址 = (条目标识, 偏移)」） |
| 释放记录 | `declassify` 节点的四字段（§3.1） | 图上节点 + `.ccr` 段（§6.1 S3） |

### 1.4 序方向（**最易错点**，实施前必读）

安全序与**类型序方向相反**：

| 事实 | 安全叙事 | 类型判定（D5） |
|---|---|---|
| 公开数据可用于机密上下文 | `Public ⊑ Secret`（低可入高） | `labeled<Public,τ> <: labeled<Secret,τ>` ✓ **子类型** |
| 机密数据不可流出到公开上下文 | `Secret ↛ Public`（禁写入低） | `labeled<Secret,τ> <: labeled<Public,τ>` ✗ **非子类型** |
| 汇合取上界 | 分支合流取更机密者 | `label(phi) = ty_join(A, B)` |

`Secret ↛ Public` 在类型层表现为**子类型关系的缺失**（而非某个"禁止转换"的特判）。实现若把序写反，会把全部负控放行、全部正控拒绝——§6.2 的正/负控表即为此设的对拍锚。

## 2. 流纪律判定

### 2.1 四条规则（覆盖档的全部内容）

设 `guard(ρ)` = region ρ 的守卫标签，`guardᵗ(ρ)` = ρ 及其全部祖先 region 的守卫之 `⊔`。

| # | 规则 | 内容 | 图的依据 |
|---|---|---|---|
| **R1 值标签** | 传播 | `label(v) = (⊔ label(每条数据入边)) ⊔ guardᵗ(region(v))` | 数据边（值流）＋ region 嵌套 |
| **R2 守卫（隐式流 / pc 标签）** | 控制依赖 | `SG_IF` 的**两个**子 region 守卫均 `⊔` 条件标签；`LOOP`/`FOR` 的体 region 守卫 `⊔` 循环条件（或计数）标签；`FLOW`/`UNSAFE` 不加自身守卫 | region 是**结构化**的 → pc 标签是 **per-region 常量**（可判定的关键，见 §2.4） |
| **R3 条目标签（堆隐式流）** | 存储 | `label(条目 e) = ⊔ label(每个 store 到 e 的节点)`；`label(load e) = label(e) ⊔ label(地址/偏移值)` | provenance 的条目标识；**粒度 = 整条目**（per-offset 精度登记，§8） |
| **R4 sink 观测标签** | 检查点 | 对每个 sink/契约点 `s`：`obs(s) = (⊔ label(实参)) ⊔ guardᵗ(region(s))`，判 `ty_sub(obs(s), required(s))` | sink 声明（§2.1 末）；`required(s)` 由库/策略给定 |

- **R2 覆盖了什么**：`if secret { print("A") } else { print("B") }`——两条 `print` 的实参是常量，R1 什么也看不到；**R2 把条件标签外溢到 region 内的 effect 节点**，两条 print 的 `obs` 均为 `Secret` → 违例。循环次数信道 `for i in 0..secret_n { send(x) }` 同法被覆盖（体 region 守卫 = `Secret`）。
- **R2 不覆盖什么**：非结构化控制流（若存在 goto/长跳转/exotic 异常）。**假设**：region 覆盖全部结构化控制面——**待审计**（§6.4 前置 3）。
- **state edges 的位置**：state edges 表达**顺序**（命令式下限），不是值依赖，**不传播标签**。一个 effect 的"是否发生"由其所在 region 的守卫决定（R2 已覆盖），故无需沿 state edge 传播。反过来，顺序信息本身在保密性方向不是信道（谁先谁后不泄漏内容）；完整性方向由 S-B5（状态版本）承担，本 spec 不重定义。
- **`required(s)` 从哪来**：① 边界 sink（print/文件/网络/syscall/panic 等跨越图边界的 effect）**默认 `required = Public` / `Trusted`（default-deny：sink 不会"无要求"，因此任何已带 `Secret`/`Untrusted` 的到达都被拒）**；② 库内 sink 由库声明（类型化构造器自带 `required`）；③ 非边界的内部函数调用**不设** `required`（否则等于给全程序加标注，违反 D3）。default-deny 是**策略数据**，可被策略覆写。
- **纪律强度的诚实边界**：`Secret ↛ Public` 只能拦"**已被标注为 Secret 的流**"。库/用户忘记在源上标 `Secret` 时本族**不报**（无从推断——没有"秘密性"的静态 oracle）。这正是路线图 §1.3 第 1 类的落点（规则本身错/oracle 缺失 ≠ 语言语义缺陷），也是 §1.3①「源侧声明」必须由领域库承担的原因；`strict` 模式下的可选收紧见 §8.2 Q9。

### 2.2 判定如何落到引擎（D5）

R2 引擎（P0 已实施：`ty_sub`/`ty_equiv`/`ty_disjoint`/`ty_inhabited`/`tt_witness`，`g_type_terms` 类型项 DAG）是**唯一判定权威**（路线图 §1.2 原则 4）。标签作为类型项参与：

- **推荐编码**：`labeled<L, τ>` ≡ `product(label_atom(L), τ)`——标签是 product 的一维，值语义与 R1–R4 的传播都是"同维度 `⊔`"。
- **引擎义务（交实施批，落点为 R2 类型项扩展）**：
  1. **标签原子 + 序公理**：`label_atom(Public) <: label_atom(Secret)` 等，作为**引擎公理**注册（与 R2 P0「原子类互斥公理」同机制、同用例表形态）；
  2. **维度隔离**：标签原子与基类型原子是**不同维度**——`labeled<Secret,int>` 与 `labeled<Public,string>` 可同时成立，不得被互斥公理误判不相交；
  3. **join**：`ty_join(A,B)`（PHI 合成用）＝ 序下的最小上界；若引擎暂不导出 join，则以 `labeled<⊔, τ>` 的显式构造式落地（实施批择一，登记）。
- **检查 = 一次 `ty_sub`**：`ty_sub(obs(s), required(s))`；失败给**非空反例路径**（R2 §3.2 `ty_witness` 精神：报出**哪条边**把标签带上来的——图 → 源码映射，R2 §7）。
- **未判定的诚实落法**：引擎预算耗尽 / 桥接失败 → **不得静默当通过**（路线图 §1.2 原则 3）——`on` 模式登记并告警，`strict` 模式拒编（§5.2）。
- **不做独立 label 推断**：label 是类型项的一维，泛型函数的 label 多态 = R2 §5.2「泛型 = 编译期接口具体化」的普通实例（实例化时 `ty_sub(实参 label, 约束 label)`）。**不**引入 second-class 的 label 推断/子类型体系。

### 2.3 pass 形态

与既有三 pass（PointerAnalysis / RegionCheck / ProvenanceVerify）**同级同构**（定案 4：类型检查 = 图验证 pass）：

```
1. 建标   边界声明 + 库构造器 + 签名契约 → 播种标签
2. 传播   R1/R2/R3 单调不动点（worklist；格高度有限 → 收敛可证）
3. 检查   R4：每个 sink/契约点一次 ty_sub
4. 落档   四档义务（§5.1）：prove / enforce / proof-required / reject
```

- 前四步**只读图 + 写标注**，不改 IR 结构 → 不影响代码生成；启用与否由策略控制（§5.2）。
- 建标与检查都用**同一张图的同一套对象**——这就是"语义保鲜"在安全面上的兑现：`.ccr` 出前端即带标签与释放记录，验证/审计工具**直接消费**，不必重跑前端（R2 §6.4 的同款主张）。

### 2.4 隐式流边界表（覆盖到哪一档，逐条）

| 信道 | 本族归属 | 结论 |
|---|---|---|
| 显式值依赖（数据边） | R1 | ✅ 覆盖（切片 S1） |
| 显式分支 / 条件写（pc 标签） | R2 | ✅ 覆盖（S1；结构化 region → per-region 常量守卫） |
| 循环次数（经 effect 外溢） | R2 | ✅ 覆盖（体 region 守卫） |
| 循环次数（经纯计算影响**时长**） | — | ❌ 登记不覆盖（T1，§6.2）——归 S-C 成本模型/硬件层；**不承诺 constant-time** |
| 经堆（store/load 非结构化） | R3 | ✅ 覆盖（S1；粒度 = 整条目，per-offset 精度登记 §8） |
| 经 `unsafe`/FFI 写 | R4（边界 sink） | ✅ 覆盖为**检查**：`unsafe` 不洗标（D6），写边界 sink 需标签合格 |
| 进程终止（panic/异常/提前返回） | R2（发生受守卫） | ✅ 覆盖其**发生**（`panic` 登记为边界 effect）；消息内容 = R1 |
| timing / 非终止 | — | ❌ 登记不覆盖（T2） |
| 微架构（cache / 分支预测 / 功耗 / EM） | — | ❌ 登记不覆盖（T3）——硬件层（hw-map），本族不碰 |
| covert channel（两进程约定 / 系统外部信道） | — | ❌ 登记不覆盖（§7） |
| 动态标签（反射 / `dyn` / 外部返回的标签） | enforce 档 | ⚠️ 设计但不落地（§5.1）——本切片不含运行时影子标签 |
| 非结构化控制流 | — | ⚠️ **假设不存在**——**待审计**（§6.4 前置 3）；若不成立，登记为未覆盖 |

## 3. `declassify` 语义

### 3.1 节点契约（四字段）

`declassify` 是**图上显式节点**（路线图 §1.1：`Secret → Public` 的唯一合法通道；对偶地 `Untrusted → Trusted` 的净化节点，本 spec **沿用同一个词**，不新造第二个术语）：

| 字段 | 内容 | 强制性 |
|---|---|---|
| **目标标签** | 释放到哪一档（不是隐含的"公开"） | 必填 |
| **范围** | 只释放**流经本节点的那个值**——不是"此后该变量全部放行"，更不是全程序放行 | 结构强制（节点语义即此） |
| **理由（purpose）** | 审计事实（如 `"password-verify:1bit"`）；随图进 `.ccr` | 必填（`strict` 模式下空理由 = 拒编） |
| **授权** | **谁能降密**——本 spec **不判**，作为义务交 S-B2（`authority` 轴 / capability path） | 交 S-B2 [S-A] |

### 3.2 可审计性（本族的核心承诺之一）

1. **禁止隐式插入**：任何 pass/库/默认行为**不得**自动生成 `declassify`（不做"猜测意图式放行"）。
2. **优化必须保标**：跨越 `declassify` 边界的变换不得改变"释放了什么"（不得把计算提升/下沉穿过释放点导致释放范围扩大）。这是**对优化器的义务**（与 S-C 的接口），与缓存语义的「驱逐不变量」（memory-model §一 条款 2）同形：变换保持可观测语义——此处"可观测"额外包含标签。
3. **DCE 不留幽灵**：被删除的 `declassify` 节点（其值无消费者）不产生运行期语义，但**释放记录保留在审计通道**（`.ccr`/`explain`，接 S-D）——审计要看到"程序曾声明释放过什么"。
4. **可计数**：释放点是**有限、可枚举**的图节点——审计 = 枚举全图 `declassify` 节点 + 读四字段；不存在"未记录的降标路径"（前提 = §2.1 的判定完备性，其假设见 §2.4 与 §6.4）。

### 3.3 与 `unsafe` 的关系（D6）

| | `unsafe` | `declassify` |
|---|---|---|
| 语义角色 | **边界标注**：编译器无法追踪 provenance 的入口（memory-model §一 条款 4 / pointer-model「声明是唯一信任点」） | **释放节点**：显式降标 |
| 对标签的作用 | **无**——进出 `unsafe` 不改变任何标签；`unsafe` 内产生的值继承其输入的标签 | 唯一合法的降标动作 |
| 何时是必要的 | 外部地址/FFI/inline asm 等无 provenance 面 | 需要把机密/不可信内容交付给低标签面时 |

**关键裁决**：`unsafe` **不洗标**（`unsafe` 是标签的诞生地之一，不是释放通道）。`unsafe { raw_write(fd, secret) }` 仍是违例（R4 边界 sink）。若某场景确需在 `unsafe` 内释放（如与外部安全模块交互），走 `declassify` + 证据（§3.4），**不**放宽 `unsafe` 语义。

### 3.4 密码学降密 = proof-required 档

`encrypt(k, secret)` 的输出**默认仍带 `Secret`**——加密**不是**自动降密器：

- 正确形态 = `declassify(encrypt_output, 目标=Public, 理由="AEAD:nonce+ciphertext"))`，其正确性（语义安全）**不可由语言层证明** → 落**③ proof-required 档** [S-A]：要求用户/库提供契约或证明工件，节点携带其引用。
- 这不是过度保守：把"加密即安全"当公理会立刻把整条 IFC 变成可被任意包装绕过的空壳（现实漏洞的常见形态）。
- 同理，**哈希/编码/截断/启发式扫描都不是降密/净化**（§4.3）。

### 3.5 完整性的对偶面

完整性轴的 `declassify`（净化）与机密轴的**差别只在证据种类**：机密轴要"**为什么要释放**"（purpose + 可选密码学证明），完整性轴要"**依什么规则判定为安全**"（validation rule：解析/白名单/转义/参数化的具体规则）。完整性的净化构造器形态与领域库接口约定归 **S-B1**；本 spec 只定它在流纪律中的语义 = **降标节点 + proof-required 证据 + 唯一通道**。

## 4. 完整性轴

### 4.1 对偶规则

完整性 = 同一个传播机制、相反的释放方向：

| | secrecy | integrity |
|---|---|---|
| 违例 | `Secret → Public`（内容外泄） | `Untrusted → Trusted`（污染内容进入受信位置） |
| 默认源 | 声明式（1.3 ①） | **边界一律 `Untrusted`**（D4） |
| 出口 | `declassify`（释放） | 净化构造器（validate/parse/escape/参数化） |
| 义务档 | 多为 prove（静态判定）；密码学 → proof-required | 净化规则 → **proof-required**（"这条规则真的够吗"不可由语言证明） |
| 典型 sink | 边界输出（print/网络/文件/syscall） | 解释器语法位（S-B1）、特权操作、持久化受信位置 |

### 4.2 与 S-B1（注入族）的分界

| | S-B3 完整性轴 | S-B1 注入族 |
|---|---|---|
| 说什么 | **标签怎么流**：不可信性沿任意计算传播（拼接/取子串/哈希都洗不掉） | **端口怎么配**：哪些输入端口是"解释器语法位"，哪些是"值位" |
| 判定形态 | 图上的包含判定（`ty_sub(obs, required)`） | 构造器端口/形状纪律（`SQL<Structure>` 等类型化构造器）+ 非法边 |
| 失败例 | `untrusted → concat → SQL.exec(...)` 里"untrusted 仍是 untrusted" | `SQL.exec("... " + input)` vs `SQL.query(sql, input)` 的**端口**差别 |
| 关系 | **基座**：S-B1 的"非法边"= 完整性标签到达一个 `required = Trusted` 的语法位端口——S-B1 是 S-B3 完整性轴在"解释器端口"这一类 sink 上的实例化 | S-B1 依赖 S-B3（传播不洗白），S-B3 不重复 S-B1 的领域构造器约定 |

分界一句话：**S-B3 保证"脏的没洗干净"；S-B1 保证"洗的方式对不对（值位 vs 语法位）"**。二者相接处 = 调用 `sanitize`/参数化构造器时产生一个 proof-required 义务（`required(s)` 由库声明）。

### 4.3 「洗白」的非法手段（负控的语义来源）

以下操作**不降低**完整性标签（即不构成净化）：字符串拼接/切片、哈希、编码（base64/URL/HTML 实体——**编码不是转义上下文感知的**）、长度/格式启发式扫描（denylist/regex）、`dyn` 转换、序列化/反序列化（除非构造器声明为净化点并带规则）。它们只能作为 `declassify` 的**证据素材**，不能自动成立。

## 5. 义务落档

### 5.1 四档映射 [S-A]（术语逐字用路线图 §1.1）

| 判定面 | 档 | 落法 |
|---|---|---|
| `ty_sub(obs, required)` 判定为真 | ① **prove** | 零成本通过，无产物变化 |
| 标签为**动态**（反射/`dyn`/外部返回标签/策略运行期决定）且存在强制点 | ② **enforce** | 运行时标签检查（fail-closed：不过则中止，不静默放行）——**设计但不落地**（本切片不含；登记为 enforce 档设计落点） |
| 释放/净化的**规则正确性**（密码学/验证规则）不可由语言证明 | ③ **proof-required** | 要求契约/证明工件；`declassify` 节点携带其引用；缺失 = 不通过 |
| 引擎预算耗尽 / 桥接失败 / 未覆盖面在 `strict` 模式被触发 | ④ **reject** | 拒编（高安全模式），错误码段 `EC_IF_*`（段号实施批定，参照 R2 §7 码段做法） |

**要点**：①②③ 的**边界**不是"能不能判"，而是"**证据从哪来**"——prove 靠引擎、enforce 靠运行时、proof-required 靠人/工具。三者都不许"静默当通过"（路线图 §1.2 原则 3）。

### 5.2 模式（策略数据，D1）

| 模式 | 行为 | 用途 |
|---|---|---|
| `off`（默认） | 不做流验证（不建标、不检查、零产物变化） | 未启用策略的项目；**零回归锚**（§6.3） |
| `on` | 全量 R1–R4 + 边界 sink default-deny；未判定面**登记并告警** | 常规启用 |
| `strict` | `on` + 未判定/未覆盖面 → **拒编**；`declassify` 必填理由与授权引用 | 高保证构建（对齐四档 ④） |

默认 `off` 是诚实的工程选择：纪律面随策略启用（路线图「policy = 数据」），语言本体不加关键字、不改既有程序语义。

### 5.3 义务不静默消失（可承诺的强 claim）

- 判定不通过 → 必落 ①②③④ 之一，**绝不**当通过；
- **未覆盖面**（§2.4 ❌ 行）在每次 `on`/`strict` 构建的报告中**显式列出**"本构建未覆盖：timing/终止/微架构/covert"——不谎报覆盖，也不把未覆盖混同于"已证明安全"；
- 与 R2 §3.3 的**预算守卫**同款：预算耗尽 ≠ 类型不兼容，此处亦然 ≠ 泄漏；三类结论（通过 / 违例 / 未判定）**分因、分措辞、分码**。

## 6. 最小可实施切片 + 判据

### 6.1 切片定义（小、可独立验收、每片一个计划）

| 片 | 内容 | 依赖 | 判据 |
|---|---|---|---|
| **S1 传播** | 建标（①边界声明 ②库构造器标注位）→ R1/R2/R3 不动点 → 图转储可见标签与守卫 | 无（纯图分析，零语言面改动） | 图转储用例表：正控 P5–P6（§6.2）标注正确；`off` 模式零产物变化 |
| **S2 检查与释放** | R4 边界 sink default-deny + `declassify` 节点四字段 + `EC_IF_*` 诊断 | S1 + S-A 定稿（四档用语） | 正控 P1–P4 通过、负控 N1–N4 拒编且诊断指向**边路径** |
| **S3 载体与审计** | 标签/释放记录进 `.ccr`（依附 R2 P4 载体批次；段布局随批定） | R2 P4 | 出前端即带标签与释放记录；`explain`/审计通道可枚举释放点（接 S-D） |

**前置**（三件，全部解掉才开工 S1）：

1. **S-A 定稿**——四档义务与属性轴接口以 S-A 为准（本 spec 的 `[S-A]` 引用点会随其定稿校准）；
2. **R2 P2b 接线**——判定统一入口（`iface_ops`/`res_type_node` 合一）就位后，标签的 `ty_sub` 检查才不是第二套判定；
3. **依赖完备性审计（定点）**——把 §2.4 的**前提**从"结论"降回"待验证"：逐 op 核对"该 op 的语义依赖是否都表达为图上的边/region"（尤其：内存读写的地址/偏移是否为数据边；`dyn`/间接调用/间接写是否表达；有无非结构化控制）。**审计不完备的 op 列入未覆盖面**，不假设它完备（种子文档的"图上已有全部依赖"是本族的**待验证前提**，不是公理）。

### 6.2 正控 / 负控 / 登记控（语义判据表）

**正控（须通过）**

| # | 样例 | 通过的理由 |
|---|---|---|
| P1 | `pw → hash → verify(lib 契约: → labeled<Public,bool>) → if ok { grant() }` | **契约级降密**：1 bit 泄漏是需求本身要的（§7 第 3 类），显式在库契约里 |
| P2 | `secret → declassify(目标=Public, 理由="audit-export") → println` | 唯一合法通道，释放留痕 |
| P3 | `secret → hash → declassify(...) → println` | `hash` 不是释放，`declassify` 才是（§3.4） |
| P4 | `argv → parse → validate(规则 R) → 受信路径` | 净化构造器 + proof-required 证据（S-B1 交界） |
| P5 | `public → 机密上下文（sink requires Secret）` | 上行合法（§1.4 第一行） |
| P6 | `secret → 计算 → declassify → 再计算 → 公开 sink` | 释放**只**解除流经该值的那部分标签 |
| P7 | 未启用策略的既有程序 | **零产物变化**（byte-identical，同 R1/R2 判据） |

**负控（须拒编）**

| # | 样例 | 违例规则 |
|---|---|---|
| N1 | `pw → println` | R4：边界 sink `required=Public` |
| N2 | `if secret { print("A") } else { print("B") }` | R2：守卫外溢（实参是常量，R1 看不见） |
| N3 | `arr[0] = secret; ... println(arr[0])` | R3：条目标签 |
| N4 | `secret → unsafe { raw_write(fd, p) }` | R4 + D6：`unsafe` 不洗标 |
| N5 | `untrusted → concat → SQL 语法位` | 完整性轴（S-B1 交界：端口 + 传播双违例） |
| N6 | `secret → encrypt → println(ciphertext)` | 加密非自动降密（§3.4）；缺 `declassify` + 证据 |
| N7 | `if secret { panic() } else { ok() }` | R2：终止的发生受守卫（`panic` 登记为边界 effect） |

**登记控（须"未判定"且显式登记，不得静默通过、不得谎报为已覆盖）**

| # | 样例 | 落法 |
|---|---|---|
| T1 | `if secret { slow_public() } else { fast_public() }`（无标签 sink，时长差） | ❌ timing：`on` 模式登记；`strict` 拒编 |
| T2 | `while secret_cond { }`（无 effect 的非终止差） | ❌ 非终止：同上 |
| T3 | 依赖 cache 行为的密钥表查找 | ❌ 微架构：归硬件层/密码库，本族不判 |

### 6.3 判据

1. **用例表全绿**：P1–P7 / N1–N7 / T1–T3 语义判据（含诊断**指向边路径**与分因码）；
2. **零回归锚**：`off` 模式下既有语料产物 **byte-identical**（同 R1/R2 判据形态）；`on` 模式下未使用标签的语料同样 byte-identical；
3. **套件**：27 selfhost + 3 bootstrap + suite 全绿；自举 `corec2/corec3` `cmp` IDENTICAL + N06=0 + 冒烟 rc=42（沿用 R2 §4 判据）；
4. **序方向对拍**：§1.4 的表逐行有用例（防"序写反"这类全放行/全拒绝故障）；
5. **诚实性判据**：`on`/`strict` 构建报告**必含**未覆盖面清单（T 档 + §2.4 ❌ 行）——报告缺该节即视为未完成。

## 7. 不承诺（引用路线图 §1.3，逐条说明本族落在哪类）

| 路线图 §1.3 | 本族的落点 |
|---|---|
| **错误 specification** | 策略说"这些数据是机密"是**规则**；Core 证明的是"程序忠实执行了该规则"（`Secret ↛ Public`），**不证明**分类本身正确（误标为公开的医疗数据、写错 `required` 的库契约照旧泄漏）。 |
| **恶意/失陷外部实体** | **密钥被偷、硬件后门、编译机失陷、供应链投毒、侧信道测量**——本族**不**消除，只在"程序内部传播"这一小段缩小：把本该显式的释放变成**显式且可在 `.ccr` 审计的**释放点。机密不被盗的前提在此类之外（可复现构建/签名/provenance/最小权限，均非语言语义）。 |
| **需求本身允许危险行为** | **需求本身要打印密码**（管理员导出、调试输出、`verify` 的 1 bit 结果）：本族**不禁止**，只要求它是**显式 `declassify` + 留痕 + 可选授权**（P1/P2）。同理，crypto 库必须做危险事（计时、处理密钥）——目标是**证明隔离边界**，不是取消能力。 |

**本族专有的不承诺**（另立，避免读者把"流纪律"误当"侧信道安全"）：

1. **不承诺 constant-time / 无计时信道**——R2/R4 只判"值流向"，不判"执行时长"；常量时间需密码库契约 + S-C 成本模型 + 硬件层。
2. **不承诺无终止信道**（`while secret {}` 类）。
3. **不承诺无 covert channel**（两进程约定、外部系统信道）——经典 IFC 可判定性边界之外。
4. **不承诺微架构面**（cache/分支预测/功耗/EM）。
5. **不承诺**"秘密不被读"（confidentiality ≠ 不可访问；那是 S-B2 授权族与 S-B4 围栏族的范围）。

## 8. 不做项 + 开放问题

### 8.1 不做（YAGNI / 后置登记）

- **不做**运行时影子标签全量 IFC 落地（enforce 档保留为设计落点，本切片不含）。
- **不做** per-offset / 每字节标签精度（切片 = **整条目**粒度：一个数组里放一个秘密会"污染整个数组"——安全但粗；细分精度登记，先例 = provenance 的 (条目, 偏移) 已具备结构）。
- **不做**独立的 label 推断/子类型体系（label 是类型项的一维，走 R2 引擎与泛型具体化；D5）。
- **不做**常量时间/侧信道缓解（归密码库 + S-C + hw-map）。
- **不做** covert channel 检测。
- **不做**非结构化控制流的流纪律（若 IR 存在此类形态，先登记，不进本切片）。
- **不做**动态标签的自动推理（`dyn`/反射/外部返回标签 → enforce 档或拒编，不猜）。

### 8.2 开放问题（**待裁决/待审计**，非本 spec 可单方定）

| # | 问题 | 影响 |
|---|---|---|
