## 0. 范围与裁决

**论题**：`check(x); …; use(x)` 中间外部状态可变化 → 图上应是**两个分离的状态版本**；更合理的 API = `open → verified handle → operation`（**handle 绑定身份**，而非按 pathname 重查）。

**本族的轴**：拥有 `state-version`（路线图 §1.1）；借用 `effect`（变更事件）与 `authority`（S-B2）——只消费，不重定义。

**本族是否消费 `integrity`（A 线 N3，显式声明）**：**消费**——形式 = **`state-version × integrity`**（S-A §1.8 的耦合行）：**版本 = 完整性的时间证据**（check 与 use 必须同版本）⇒ 本族 §2.1 的 C1/C2 判据即该消费面。这是 `integrity` 目前**唯一经对侧确认**的消费关系（S-A §1.3 首消费方行已按此改回引）；S-B2 侧明示不消费（其对侧行已加）。

**与确定性轴族的关系（路线图 §1.4，2026-09-11 追加）**：本族 = `determinism` 族 `D_effect` / `D_external` 两轴在**外部不可见面**的具体化。§1.4「不确定性必须可归因到显式语义源」在本族读作：**外部世界的版本推进不得静默变成程序里的陈旧检查**——与「隐式竞争 → reject」同一条执法线（§2.1 对表）。

**族内裁决**：

- **决 1（版本载体）**：状态版本 = ENT `(var_id, version)`（v7 格式 §3.5）——本族**不引入第二套版本机制**；存在区间 = `live_start/live_end`，无配方 = `flags bit0`，序 = EDG `kind=1`。重造即偏离既有定案。
- **决 2（外部对象进图）**：外部对象 = **无配方条目**（memory-model 条款 4/4b 统一规则）——外部状态**不需要新通道**，它已经以边界条目身份在图里。
- **决 3（判据性质）**：图上只有**图版本**；**世界版本按定义不进图**。因此判据不是"版本号相等"本身，而是「图版本同版本支配 + 窗口内世界版本无变更」（§2），且后者**永不静默**（§4）。

**范围外**：并发线程/flow 间竞争（§7 开放问题 4）；OS 内核内部 TOCTOU（S-B4/平台面）；不新增关键字、不加语言 primitive（路线图 §1.2 原则 1）。

### 1.3 图版本 vs 世界版本（判据的诚实核心）

- **图版本** `v_g`：ENT 里那个版本号——图知道的状态。
- **世界版本** `v_w(κ, t)`：身份 κ 在运行时刻的真实状态——**按定义不进图**（无配方条目 = 符号常量，条款 4/4b）。
- 推进 `v_w` 的三类来源：
  - **(a) 图内变更节点**——图上可见（STORE 族；③）。
  - **(b) 外部代理**（另一进程 / 线程 / 硬件 / 系统调用内部副作用）——图上**不可见**。
  - **(c) 时间本身**——不推进版本；只有变更推进。（显式排除，免得判据退化成"时间过去了"这一无信息量条件。）
- **本族要立的不变式**：`v_w(κ)|use = v_w(κ)|check`（检查窗口内世界版本未推进）。
- 图上**能**证的是 (a) 的缺席 + ② 的身份不可重解析；**不能**证的是 (b)。这条边界就是 §4 四档的分界来源，也是 §6 引用路线图 §1.3「恶意/失陷外部实体」的落点。

## 2. TOCTOU 判据

### 2.1 判据形态（C1 ∧ C2 ∧ C3）

**记号**：
- check 节点 `C`：验证谓词 `P` 于身份 `κ` 的版本 `v(C)`。
- use 节点 `U`：作用于身份 `κ` 的版本 `v(U)`。
- state 可达 `→*`：EDG `kind=1` 的传递闭包。图语义 = 约束集 ⇒ 偏序可达（v7 载体设计 §1.3）；今日生产形态 = 链（`g_last_state_node`）⇒ 判定退化为区间包含（实施快路径）。
- mutator：图内变更（③ a）或带 `mutates(κ)` 的边界节点；未标注 extern = 变更一切 κ。

**TOCTOU 判据**：`U` 合法 ⟺ ∃C 使 C1 ∧ C2 ∧ C3：

- **C1（同版本支配）**：`v(C) ≡ v(U)` **且** C 支配 U——C 经数据边可达 U，或 U 直接消费 C 的版本见证（条目）。
- **C2（窗口无变更）**：状态路径 `C →* U` 上不存在 κ 的 mutator，**且 U 本身不是对 κ 的重观察**（2.2）。
- **C3（稳定性声明）**：κ 在图存在区间内被声明为"外部代理不推进它"（独占 / 不可变）。**形态与登记（2026-09-11 裁决 D2(a)）**：C3 = **S-A §3.1「放行 / 声明条目」**的 `kind = stability` 条目——形态 = **治理层注解**（**显式豁免节点形态**：它是关于世界的事实声明，无可变换之值），但**必须补齐审计字段**（主体/范围 = κ 与存在区间 · 理由 · **派生源** · 义务引用）并**落台账**（S-A §5.2b）；豁免理由或审计字段缺失 ⇒ **拒装**（S-A §3.6）。非语义本体（capability-lattice v4：授权归治理层）。

**与路线图 §1.4 执法表的对表**（两者是同一形状的两个入口）：§1.4「依赖/状态边足证汇合与调度无关 → prove」↔ 本族 C1∧C2∧C3；§1.4「语义明文允许（`race`/`select_any`）→ 显式不确定、必须进报告面」↔ 本族 C3 声明的登记面；§1.4 **「既未证明也未标注（隐式竞争）→ reject ← 真正的执法点」** ↔ 本族 ④（P3/C2 缺口）。

- **可判定分界（2026-09-11 裁决 D23；A 线评审 I3 收敛）**：两者是同一执法点，**不得两处各判一次**，分界**按变更源身份**判定——
  - `mutator ∈ 图节点集合`（图内可见的变更/并发主体）⇒ **S-E**（并发面）；
  - `mutator ∈ 边界条目 / 未知 extern`（图上不可见的外部推进）⇒ **本族**（外部不可见面）；
  - **交集非空**（同一 `go` 起的节点既是图节点又是并发主体）⇒ **先本族的保守面**，**S-E 不重复报**（只出一条诊断）。
  - 对应负控 = **交叉负控**（§5.4 新增：同一场景断言**恰一条**诊断）。S-E 侧的同款一行归其自身文本（B 线）。

### 2.2 版本分离的检测（本族要检什么）

- **重观察 = 新版本**：`use` 若重新读同一 pathname，则产生新边界节点 → 新条目 → 新 `def_nod` ⇒ `v(U) ≠ v(C)`，C1 不成立。**这就是 `check(x); use(x)` 的图形态：两次独立观察 = 两个分离的状态版本**（论题的直接兑现）。
- 版本分离**本身不是错误**（合法：写后重读）；**没有新 check 的 use 才是**——即分离出的版本上不存在同版本的 check。
- **pathname 重查识别**：边界节点以 pathname 形值（string）为输入、产出**新**条目，而作用域内已有同 κ 的活验证版本 ⇒ 重查模式（不必然非法，但**不继承既有验证**）。
- 判据落法：C1 走引擎（§2.3）；C2/C3 走图分析 + 注解——**不另建判定体系**（路线图 §1.2 原则 4）。

### 2.3 版本等价判定走引擎

- 版本身份编码为形状类型项（S-A 横切轴形态），如 `Observed<T, κ, v>` / `Verified<P, T, κ, v>`。**形状项定义属 S-A**；本族只规定判定 = `ty_sub(实际项, 要求项)`（R2 §3.2），要求项来源 = 操作的契约（领域库给出：`op` 要求 `Verified<P, Handle[κ], v]`）。
- 判定失败输出反例（`ty_witness`）：如"版本 v2 的 use 落到要求 v1 的契约上"。
- **不锁形状项语法**——S-A 定稿后对表（§7 开放问题 6）。

### 2.4 模式清单（本族「版本分离」图鉴；路线图 S-B5 行交付项）

| # | 模式 | 版本形态 | 判据结果 |
|---|---|---|---|
| P1 | `h = open(p); v = verify(h, P); op(v)`（身份绑定） | 单一版本 + 同 handle | C1 ✓ 构造性；C3 身份部分**被构造消解**（fd 不可重解析）→ prove |
| P2 | `v = observe(x); verify(v, P); use(v)`（值绑定：读一次、验缓冲、用缓冲） | 单一版本 | C1 ✓；C3 内容部分需稳定性声明或有界观察窗口 |
| P3 | `check(p); …; use(p)`（按名字重查） | 两版本（v1 ≠ v2） | C1 ✗ → enforce（版本重校验）/ reject |
| P4 | `v = verify(h, P); …; mutate(κ); …; op(v)`（同 handle 但窗口内变更） | 版本被推进 | C2 ✗ → enforce / reject |
| P5 | `check(p); …; use(p)`，窗口内无变更且 κ 独占 | v1 ≠ v2 | C1 ✗（仍分离）；即使可证观察等价 + 稳定性，**本族不默认放行**——重查默认不继承验证 |
| P6 | `write(h); v = observe(h); verify(v, P); use(v)`（写后重读） | 版本推进**合法** | C1 ✓（新 check 落在新版本上） |

- **P5 是本族最尖锐的裁决**：宁可 enforce 也不静默 prove——依据路线图 §1.2 原则 3「义务不静默消失」，且"两次读等价"本身需证明（内容可写）。
- P1/P2/P6 = 正控来源；P3/P4 = 负控来源（§5.4）。

## 3. handle 身份绑定

### 3.1 接口形态（open → verified handle → operation）

```
open(p, …)   -> Handle[κ]                       // 边界节点：一次身份解析，产出条目（flags bit0）
verify(h, P) -> Verified[P, Handle[κ], v]       // check 节点：把断言 P 绑到 (κ, v)
op(vh, …)    -> …                               // 操作只对 Verified 定义
```

- **关键性质**：`op` 不接收 pathname，只接收 handle ⇒ **重解析这个动作不存在**（② 身份 = 节点身份，v4 §六）⇒ C3 的身份部分**不靠证明、靠构造**。
- `verify` 携带版本见证 `v`（= 该条目 ENT `version`）⇒ C1 的判定输入。
- **谓词分流**：身份谓词（存在 / 类型 / 属主 / 路径）与内容谓词（权限位 / 内容摘要 / 大小）分开——前者 C3 由构造消解，后者 C3 不可消解 ⇒ 走 P2 值绑定或 enforce。

### 3.2 与 S-B4 围栏的衔接（回接其 §1.4 / §3 / Q7）

- **接力点（S-B4 §3 原文立场）**：S-B4 保证**名字 → capability 的构造**单步且不可回退（无"先检查字符串、再用字符串"）；S-B5 保证 **capability → 资源身份的绑定**是原子的（check/use 同一版本）。分工 = 命名空间判定（S-B4）∥ 时间判定（本族）；**两族互不重定义**：S-B4 不定义版本，本族不定义命名空间。
- **S-B4 交给下游的三样东西**（① 根身份 ② 派生链 ③ 可选的 handle 槽）中，本族消费 ③；① ② 归 S-B2 的 `Can` 判定。**唯一 owner（2026-09-11 裁决 D22）**：①② 的图面分析（沿 def 链倒推 / 根封闭 / 派生链合法性）**只在 S-B2 §2.1 步① 实现一次**（输出 = `Cap` + 派生链见证，`g_*` 只读）——本族**消费其输出**（κ 的可靠性上限 = 映射层 handle 化能力，见下），**不另写分析**。S-B4 只供给派生链证据（其 Q4 据此关闭）。
- **LV-1 / LV-2 分工（S-B4 L5 / §2.5）**：S-B4 语义层只判 LV-1（构造合法性）；**LV-2（symlink / mount / hardlink = 解析身份）值级不可判，显式登记为映射层义务**。本族随之划界：**κ 的可靠性上限 = 映射层 handle 化的能力**——无 handle 化时 ④ reject（**高安全档**；S-B4 §4 同款——该行的 ④ 只在「策略禁止运行时检查 / 映射层无 handle 化」时出现，不是默认档行为），有 handle 化时 LV-2 由映射层强制（本族 C3 的身份部分据此才成立）。
- **handle 类型表示的裁定（S-B4 §1.4 把裁定权交给「S-B5 + 映射层」）——本族裁定（2026-09-11，D30 采纳本节建议）：并列类型**。理由：本族需要 handle 携带版本见证 `(κ, v)`（§3.1），而"内嵌槽"方案使 `Path<R>` 值类型随绑定状态变化（状态依赖类型，与路线图 §1.2 原则 1「属性不升格 primitive」张力更大），且要求值级也带版本（S-B4 已裁定**纯值路径无版本变化**）。故取 `Handle<R>` 独立 + `bind(p: Path<R>) -> Handle<R>`：**转换点 = 唯一的 check/use 边界 = 本族 C1 的判定对象**（与 S-B4 §3 表述一致）。映射层确认项 = `bind` 的原子性由谁提供（fd / dirfd / `openat` 类；S-B4 §3「已 handle 化」行）。**S-B4 §1.4 的两种形态已由本裁定收敛为「并列类型」**（其 Q7 据此关闭）。
- **两侧的 TOCTOU 分工（S-B4 §3 表格）**：已 handle 化 ⇒ 构造即绑定身份、**无重查 ⇒ 无 TOCTOU**（S-B4 产出即本族**版本载体**）；未 handle 化（纯值路径）⇒ 值级无版本变化、无 TOCTOU，**"值 → 资源身份"的转换点才产生 TOCTOU 面 = 本族判定对象**（= 本族 P3 重查模式的另一投影）。
- **切片依赖（实测）**：S-B4 切片 v0 = 纯值级、**不含 handle 槽** ⇒ 本族切片（§5）的 handle 只能从边界 `open` 起（衔接退化为并列，不阻塞任何一方）。若本族最终形态与 S-B4 §3 冲突，按 S-B4 Q7「两族共同复核」处理。

### 3.3 与既有外部操作的关系（事实面）

- `syscall3/4` 是特判内置（`checker.cr:2021` 注释 / `:2024-2025` 返回点、`instr.cr:681`），`read_file` / `write_file`（`io.cr:27/72`）是 P3 形态——**切片不改 stdlib**（§5 只立判据面）；stdlib 的 handle 化 = 切片之后的独立批（§7）。
- 不引入新的外部操作原语（路线图 §1.2 原则 2：策略面归库）：`open` / `verify` 是**领域库**的类型化构造器形态，语言只给流纪律与义务阶梯。

## 4. 义务落档（四档，路线图 §1.1 逐字）

> ① **prove**（静态可证 → 零成本通过）② **enforce**（不可证但可运行时强制 → 插入 enforcement）③ **proof-required**（不可证也不可强制 → 要求用户提供 proof/contract）④ **reject**（高安全模式下仍无法处置 → 拒绝编译）

| 档 | 本族条件 | 处置 |
|---|---|---|
| ① prove | C1 ∧ C2 ∧ C3 | 零成本通过；绑定构造性的（P1/P6）不问 C3 |
| ② enforce | C1 成立或可重建，C2/C3 不可证 | 插入**版本重校验**：use 前紧邻一次同身份观察 + 见证比对；不等 = **失败封闭（fail-closed）**。若身份无可观察的版本见证 ⇒ 退化为「观察与使用**原子化**为同一步」（= P1/P2 的唯一化） |
| ③ proof-required | 需要「κ 独占 / 不可变」而引擎不可判 | 要求用户 / 领域库提供 contract（C3 声明面） |
| ④ reject | 高安全模式下：C1 ✗ 且无可执行的 enforce 通道（如 P3 且存在外部变更可能） | 拒绝编译 |

- **不可证 → 不静默通过**（路线图 §1.2 原则 3）：每个判定结果必须落到 ①②③④ 之一，无第五种"算了"。
- **enforce 的语义纪律**：版本重校验**必须紧邻 use 且 fail-closed**——"检查后再用一个可能已变的东西"不是 enforcement，是 TOCTOU 复现。
- 与 where 三档的关系（**2026-09-11 按 A 线 M5 修正**）：四档（**处置分类**）与 where 三档（**约束形态分类**）是**不同分类轴**（S-A §0.3 T2 明裁），**不得读作「三档在本族的展开形态」**；本族的对应只是**形态上的相邻**：C1 常量/结构可判 → 编译期；C3 符号 → contract（proof-required）；C2 动态 → 运行时（enforce）。
- **判定为假 ≠ 义务档（同 A 线 M5 修正）**：`verify` 的谓词判定为**假**（且与策略冲突）= **硬编译错**（= **违法**，与 S-B4 §4 表末行同款），**不属于义务梯档**——是**判定结论为假**，**不是 ④ reject**（S-A §2.2 点 1 分栏；本族 ④ 只在「高安全档且无可执行 enforce 通道」时出现，§4 表内已列）。

## 5. 最小可实施切片 + 判据

### 5.1 切片 S-B5-0（注解 + 判定，零载体改动）

1. **身份键 κ 与 `mutates(κ)` 注解面**（最小：handle 派生面 + 保守 extern 面）。切片**不落盘**；**持久化去向（2026-09-11 裁决 D4(a)）**= **`.ccr` POLICY / LABEL 段，随 R2 P4 载体批同波**（v7 `7+` 段位已预留）——不是 R2 §6.1 的 TYPE/IFACE 段扩展；v7 格式 §6 开放点 1 的 EDG `kind 2+` 保留位**不动**。
2. **版本等价判定** = `ty_equiv` 调用（R2 引擎）+ 离线小用例表。
3. **判定 pass（一个文件）**：对每个 use 求 C1（同版本支配）、C2（state 边可达性 + mutator 集）、C3（取注解，**形态 = S-A §3.1 `kind=stability` 条目**，§2.1）→ 输出四档分类 + 反例。
4. **判据（见 §5.4）** + 不变式：**零产物变化**（注解未启用 = 今日程序不受影响——策略面归库，路线图 §1.2 原则 2）；全套件 + 自举判据按 **R2 §4 每步共同判据行**（`2026-09-10-type-interface-unification-design.md:155`）执行，落地细节入实施计划。

### 5.2 切片边界（明确不做）

不改 stdlib、不改 extern 序通道（§1.2 事实底座）、不加载体字段、不做跨过程（过程间 κ 传播 = 切片后续）。

### 5.3 待论证（2026-09-11 收敛：三项中两项已裁）

- **κ 的粒度** —— **已裁（D13）**：**对象身份 + 版本见证**（不是裸对象身份，也不是纯类级）；**实例 / 类 / 全外部**的取舍退化为**策略数据**（粒度键由领域库给出），精度上界仍待实测（§7.2 Q1）。
- **C3 的声明形态** —— **已裁（D2(a)）**：**S-A §3.1 的 `kind=stability` 条目**（治理层注解形态，**显式豁免节点形态** + 审计字段 + 落台账；§2.1）。
- **C3 的 contract 面是否并入 S-A policy 接口** —— **已裁**：**并入**——**承载与登记** = S-A §3.1 policy 面；**撰写方**可以是领域库（原则 2：策略面归库），二者不矛盾（库写条目，S-A 管 schema / 装载校验 / 台账）。§7.2 Q3 据此关闭。
- 切片仍只要求「最小可用」。

### 5.4 正控 / 负控 / 精度控

- **正控 A（同 handle 复用 ✓）**：`h = open(p); v = verify(h, P); op(v)` → **prove**，零 enforcement 插入（P1）。
- **正控 B（值绑定 ✓）**：`v = observe(x); verify(v, P); use(v)` → **prove**（P2 / P6）。
- **负控 A（pathname 重查 + 中间 external mutation ✗）**：`check("p"); extern_mutate("p"); use("p")` → **必须非 prove**（enforce 或 reject），且反例指明两个分离版本。
- **负控 B（同 handle 但窗口内 mutator ✗）**：P4 形态 → C2 失败 → 非 prove。
- **精度控（不误杀）**：`verify(h, P)` 与 `op(h)` 之间夹一个**不同 κ** 的 extern 变更 → 仍 **prove**——证明判据不是一刀切拒绝。
- **交叉负控（2026-09-11 裁决 D23；与 S-E 的执法分界）**：构造「同一汇合点 / 同一身份的两次访问、无序边、无声明」两例——① 变更源 = **图节点**（并发面）、② 变更源 = **边界条目 / 未知 extern**（外部面）→ 断言**恰出一条诊断**：① 归 S-E、② 归本族；**交集场景**（同一 `go` 起的节点）**先本族保守面、S-E 不重复报**。

## 6. 不承诺

（逐条落路线图 §1.3 三类不可消残留）

1. **恶意 / 失陷外部实体**（本族主落点）：外部代理可在 C 与 U 之间推进世界版本，**语言语义不能证明其不发生**——`v_w` 按定义不进图（§1.3）。本族只做三件事：使分离**可见**、使义务**有主**、使好 API **可表达**。**本族不可能消掉"外部实体恶意"本身**——这是路线图 §1.3 第二条的正面承认，不是实现缺口。§1.4 读法：世界版本推进是**物理不确定性**，本族要求它**不得静默变成语义不确定性**（陈旧检查）；但"外部代理不推进"这一物理事实永远只能被**声明 / 缩小**，不能被证明——同一条界线。
2. **错误 specification**：`verify(h, P)` 的 P 本身写错（检了错的属性）——语言只保证"检查与使用同版本"，不保证 P 正确。
3. **需求本身允许危险行为**：CLI 按名字 open 之类的语义有其正当性——目标不是禁止能力，而是**把风险压到一个显式义务上**（证明隔离边界）。
4. **不承诺**检测所有 TOCTOU：只覆盖图上可表达、policy 覆盖的那些；未覆盖面要么按保守面处理（策略启用时），要么明确不在义务范围——**无第三种"看起来安全"**。

## 7. 不做项 + 开放问题

### 7.1 不做项（YAGNI / 边界）

- 不新增语言 primitive / 关键字；不把 TOCTOU 做成内建特判（路线图 §1.2 原则 1/2——那是 lint 换皮）。
- **不重造版本机制**：ENT + state 边是唯一版本 / 序载体（决 1）。
- 不做并发线程 / flow 间竞争判定（声明边界，见开放问题 4）。
- 不做 OS 内核内部 TOCTOU、不做平台 syscall 语义正确性（S-B4 / 平台面）。
- 不做 stdlib handle 化（切片后独立批）。
- 不锁形状项语法（S-A 定稿后对表）。

### 7.2 开放问题

1. **κ 粒度与可靠性的张力** —— **已裁（D13）**：κ = **对象身份 + 版本见证**；可靠性上限 = **映射层 handle 化能力**（S-B4 LV-2：symlink / mount / hardlink 值级不可判）。**精度上界保留为待实测**（精度控 §5.4 只给下界），登记不裁。
2. **无版本见证的外部对象** —— **已裁（D30）**：**需要第三形态**——采用**独占声明**（= C3 的 `kind=stability` 条目，**治理层声明形态**，§2.1/§5.3），不新增 enforcement 机制；**运行期锁属库**（不在语言面）。既无版本见证又无独占声明 ⇒ ② 退化为「观察与使用原子化」或 ④（§4 表）。
3. **C3 归谁** —— **已裁（D2(a)）**：**承载与登记 = S-A §3.1 policy 面**（`kind=stability`）；**撰写方可为领域库**（原则 2）——二者不矛盾（§5.3）。S-A **已落盘**（收敛批 v2），对表完成。
4. **与并发模型的关系** —— **已裁（D23）**：**可判定分界按变更源身份**——`mutator ∈ 图节点` ⇒ S-E；`mutator ∈ 边界条目 / 未知 extern` ⇒ 本族；**交集时先本族保守面、S-E 不重复报**（§2.1）；交叉负控见 §5.4。本族仍只碰外部不可见面。
5. **与条款 4b 写回规则的耦合** —— **已裁（D30）**：外部对象条目 = **无配方**（4b）⇒ **按定义图内不可重算** ⇒ 「驱逐必写回」**不适用于只读外部对象**（写回义务的前提 = 有配方可重算）；与 memory-model / M4 的对表登记为**实施期核对项**（不改本 spec 判据）。
6. **依赖对表** —— **已闭合（2026-09-11）**：S-B4 = **并行起草 / 待评审**（原「已定稿」表述已按 A 线 M6 修正），本族 §3.2 已按其 §1.4 / §3 / Q7 回接并**给出 handle 裁定 = 并列类型**（映射层确认 `bind` 原子性来源）；S-A **已落盘**（收敛批 v2），衔接点对表完成：§2.1（§1.4 执法表 + D23 分界）、§2.3（形状项）、§3.2（`bind`→Handle）、§4 末（四档 ↔ where 三档，**已按 A 线 M5 修正为不同分类轴**）、§1.2（D7 修链归属）。**遗留已闭合（2026-09-11 收敛批 v3）**：S-E 侧的 D23 同款一行已由其 §4.1 补入（按变更源身份分界 + 交集先本族保守面 + 恰一条诊断），交叉负控两侧文本齐备（本 spec §5.4 + S-E §4.1）。
