# int 无上限语义

## 概述

`int` 在语义层是数学整数，即整数集合 Z 的公理化接口。它不是任何位宽的机器整数。

`64 位`、`i64`、`环绕` 和 `溢出` 都是编码层的投影形状。溢出不是语义事件，溢出错误也不是语义错误。

设计状态：定稿。原始论证、错误路径归位、现状盘点和挂账见 `docs/superpowers/implementation/2026-09-06-int-unbounded-semantics-audit.md`。

## 语义层

`int` 的承诺：

- 加法、乘法满足结合律、交换律和分配律。
- 序是全序。
- 没有最大值和最小值，无界双向。
- 没有溢出概念。`x + y > x` 和 `x * 2 / 2 == x` 在语义层无条件成立。
- 不存在“值越出 int 域”的状态、错误或行为。值只会超出某个具体投影的表示形状。

接口地位：`int` 是原生接口条目。规则内建在编译器，公理引用规约层，用户不能实现。公理由编译器负责，防止伪造证明。

`int` 的性质是图上的契约，不是代码约定。

## 编码层

语义层没有宽度。宽度不进入语言类型或标签体系。`apx` 仍然是单一语义，即精度降级开关，不扩张为宽度标签。

经典 64 位机器字是一份快路径投影。当前编译器内部表示、ELF 后端和解释器都把数学整数投影到 64 位机器字。同一语义可以有其他投影，例如任意精度、多字、扩展表示或未来范式。

超界值属于编码层事务：

- 静态区间证明通过时，不发射检查，不升级表示。
- 区间证不出时，运行时检查或提升表示。检查和提升是编码层后备，不是语义事件。
- 表示策略，包括扩展、多字、BigInt、何时提升和提升形态，属于硬件映射或远期事项，不是语义层承诺。

三层映射：

```mermaid
flowchart LR
    A["图 / 格<br/>纯数学，int 无界"] --> B["编码<br/>64 位形状、环绕、字段宽度"]
    B --> C["硬件映射<br/>表示策略"]
```

语义是无上限，表示是怎么装得下，两者分属不同层。

## 错误分类

错误发生在哪一层，就归哪一层。“整数太大”不是语义错误，因为语义层没有上界。它是投影到经典 64 位目标时的形状限制。

| 错误路径 | 归类 |
|---|---|
| 词法分析器拒绝超出 64 位形状的整数字面量 | 编码层限制。编译器内部表示是 64 位机器字，字面量超出形状即拒绝 |
| `dex` 字面量整数部分过宽 | `dex` 表示层限制，属于定点形状，不并入 `int` 线 |
| `.ccr` 的 i32 字段越界时拒写 | 编码层文件格式限制，字段宽度属于格式形状 |
| 死错误码 `EC_P_LIT_OVERFLOW` 和 `EC_R_OVERFLOW` | 当前没有发射点。将来启用 R003 时，语义应是“经典投影运行时机器字环绕事件”，不是语义溢出 |

以上是分类，不是行为变更。字面量拒绝和 `.ccr` 拒写照旧，因为当前只有经典 64 位一份投影。错误文本和诊断码体系暂不改。

## dex 和 apx

`int` 无上限是语义层事实。`dex` 精确是表示层工程。两条线不混：

- `int` 的无上限在图和格层已经成立，不依赖表示工程。“装不下”永远是投影问题。
- `dex` 的精确依赖表示层现状。当前定点 `S = 10⁶`，有 64 位整数上限。设计意图和实现存在偏差，修复方向是动态位数任意精度，已挂账。
- `int` 不因 `dex` 挂账而等待。`dex` 不因 `int` 无上限而自动精确。
- `apx` 只作用于 `dex` 类表示层选择，不成为 `int` 的宽度标签。

## 验证

`int` 公理可以在 `.cr` 内联规约中表达。`#check(x >= 0)` 和 `#ensure(result * result >= 0)` 这类数学整数性质直接成立。

`int` 到 CIC 整数 Z 的翻译桥没有分歧。规约证明和图语义使用同一个整数域，不需要位向量或溢出模式建模。

原语语义可以对照验证：`int` 公理化接口是原语层的语义模型。编译器及其投影的正确性可以与公理接口对照。证明目标不是“int64 不溢出”，因为经典投影下可以证伪；证明目标是“编码层投影或拒绝行为与无界语义一致”。形状内值相符，形状外拒绝或显式提升，不会给出错误值。

静态区间证明免检与已有的“编译期证明免检”先例同族。三态：

1. 证明恒安全：不发射检查，零成本。
2. 证明恒越界：编译期拒绝。
3. 证明不了：保留运行时检查，并带图推导的必要性标注。

## 现状和挂账

当前行为都是经典 64 位投影实例：

- `int` 运算使用 64 位机器字，环绕，不陷阱。
- 字面量超出 64 位形状时由词法分析器拒绝。
- `.ccr` 字段超出 i32 时拒写。
- 解释器和 Python 自举前端使用任意精度整数，是同一语义的另一份投影。两个编译器的“分歧”不是语义分歧，是投影形状不同。

挂账：

1. 图推导区间证明 pass：值区间传播，免检、拒绝、保留检查三态。
2. 硬件映射表示策略：扩展、多字和提升形态。当前多字加法、减法和 128 位投影已实施，乘法、除法、打印和超过 64 位的常量仍挂账。
3. 词法分析器溢出消息和诊断码体系。
4. `R003` 和 `P019` 死错误码启用时的语义边界。

## 错误文本

当前溢出消息没有诊断码，词法分析器直接打印。`.ccr` 拒写返回 -1，没有消息。

决定：注释和文档归位，错误文本和错误码体系暂不改。原因是分类调整的消费方是人读的语义框架，文档和守卫注释已经表达；当前只有经典 64 位一份投影，拒绝是形状事实；自举重建成本高，收益接近零。

将来如果改，消息应写成“超出经典 64 位编码宽度”，或在诊断前缀区分层类别。启用 `R003` 时按错误分类一节的边界处理。
