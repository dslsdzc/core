# Core 数值类型设计：dex（精确小数）与 apx（后端变换许可）

日期：2026-08-16
状态：已批准（brainstorming 会话）
修订：2026-08-23，int 语义改为无上限整数（i64 快路径，溢出后自动升级为堆上 BigInt，不产生溢出错误）；spec-design 9.4 节随之修改

## 一、设计原则与决策链

1. 核心类型等于数学语义，不带硬件惯例：核心类型不携带“行为绑定硬件”的语义，惯例（IEEE 754 等）只能以“后端实现选择”或“可忽略注解”的形式存在。
2. 范式普适：语言要覆盖所有范式（量子计算以及以后出现的未知范式）。数学语义对所有范式成立，硬件惯例只属于发明它的范式。使程序无法移植的原因是“实现定义”的语义，不是数值类型。
3. 无生态等于零兼容成本：Core 没有外部用户，float 直接移除并做机械迁移，不设兼容层。
4. IR 只携带精确语义：近似是用户授权的后端变换，不进入 IR 语义。
5. 安全性优先于性能：默认精确（较慢但安全），近似需要显式授权。

## 二、核心类型系统

```
int      = 整数（精确，无上限），数学整数语义（任意精度，永不溢出）；实现为 i64 快路径，超出范围时自动升级为堆上 BigInt（Python 模型）；整数语义在任何范式下都成立（精确算术任何范式都有）
dex      = 精确小数，默认实数语义（缩放整数/定点实现，精度内置）
bool / char / string / 结构体 / 枚举 / 数组    现状不变
```

- dex 是实数类的默认类型：`3.14` 字面量默认精确。不需要 BigInt 扩展库，int 内建任意精度，BigInt 语义就是 int 本身，不是扩展（YAGNI）。
- 字面量：`3.14` 得到 dex（精确）；`42` 得到 int（整数快路径）。

## 三、apx 标签（后端变换许可）

```
x : ., apx = 3.14    // 变量级标签（与 mut/pub 同族，零新语法）
```

- 语义：授权后端对 dex 运算做语义级变换，结果可以改变，也就是允许近似实现。它不是性能提示。
- 位置：前端只透传注解，把注解挂在 IR 节点上，不参与类型语义。dex 永远是 dex，检查器规则不变。实际实现由后端完成。
  - CPU 后端：看到 apx 附注后，dex 运算降级为 binary64 FPU 快路径。
  - 其他范式：忽略附注，使用精确缩放整数运算（契约内回退）。
- 与 @fast 的区别（不共用通道，禁止混用）：
  - `@fast` 是性能提示：忽略它，行为不变（纯优化，与语义无关）。
  - `apx` 是语义级许可：授权“结果可以改变”；忽略它，回退到精确实现。
  - 实现上，apx 使用独立 IR 附注（IR_APPROX），与 IR_FAST 不共享任何通道，优化 pass 无权处理。
- 语义契约：“精确，或经授权的近似”。带 apx 的计算在所有范式下都满足契约（CPU 上近似，其他范式精确）。

## 四、实现位置

| 层 | 动作 |
|---|---|
| 字面量 | `3.14` 得到 dex；`42` 得到 int（i64 快路径，超出范围时自动升级为 BigInt） |
| 类型系统 | TYP_BASE 新增 dex（精确小数，缩放整数实现）；变量标签字段加 apx 位；int 类型不变，实现层加升级机制（i64 改为堆上 BigInt） |
| 检查器 | `x : dex` 类型规则（精确语义）；apx 只做注解透传，没有语义规则 |
| IR | 语义保持纯精确（dex 运算为缩放整数指令序列）；IR_APPROX 附注（非语义） |
| 后端 | CPU：带 apx 附注的 dex 运算使用 binary64 FPU；其他范式：忽略 apx，使用精确实现 |
| 验证层 | apx 授权记录随 IR 到达验证器，验证器因此知道用户允许近似（规格 9.4 节的决策点随本设计落定：默认数学语义，显式授权机器语义） |

## 五、过渡：float 移除与机械迁移

- `float` 类型名删除（无别名、无糖、无兼容层）
- 机械迁移：全仓库把 `x : float` 改为 `x : dex, apx`（旧语义为 binary64，也就是 apx 在 CPU 上的实现，行为逐位保持）
- 范围：编译器自身、stdlib、测试、文档、EBNF、TY_FLOAT 常量、后端 XMM/SysV 路径（`float_str_bits` 改为 dex 打印，保留为 apx 路径实现）
- `_f32`/`_f64` 后缀保留：暂作 apx 的 CPU 位宽标注（精确标注语法后议）

## 六、明确不做（YAGNI）

- BigInt 扩展库（int 即任意精度，i64 快路径加溢出自动升级堆上 BigInt 内建，扩展库不需要）
- 定点/有理数扩展库（dex 即定点语义）
- 隐式数值转换（所有数值转换显式，Coq 式分离，安全性来自显式性）
- 字面量重载（Coq Numeral Notation 式，有需要再议）
- 扩展类型注册机制（TYP_EXT，本设计不依赖它，dex 是核心类型不是扩展类型）

## 七、命名

| 名称 | 含义 |
|---|---|
| `dex` | 精确小数（默认实数语义） |
| `apx` | 近似授权（后端变换许可，变量级标签） |
| `BigInt` | int 的实现层升级机制（堆上任意精度整数，i64 超出范围时自动启用；不是独立类型，无用户可见名） |
| `float` | 删除（迁移为 `dex, apx`） |
