## 1. 目标载体

### 1.1 图 = 载体主干

v7 文件携带（语义层，无字节）：

1. **NOD——节点表**：图事件 = 配方载体。op/dest/srcs/类型码语义与 v6 相同（语义内容不变声明，§2.2）；**坐标 = NOD id = 图节点坐标（v6 D1 延续）**
2. **边表（v7 必落，P3 修复）**：每节点的输入边显式落盘。两类边（沿 dataflow.cr 现有分类）：
   - 数据边（kind 0）：值流 = def-use 引用
   - state 边（kind 1）：副作用序 = VSDG 状态链（dataflow.cr `df_connect_state` 机制：副作用节点按程序序连成链 + 区域退出终止依赖）
3. **REG——区域表**：SG 嵌套坐标（v6 不变——区域 = 图锚定存储的组织面，格侧成立已裁决）
4. **ENT——条目表（主干化，P2 修复）**：条目 = var × 版本的存在视图（§1.2）
5. **调度 = 文件序**：文件序 = 生产者选择的合法调度（沿边约束的拓扑序之一）——**不再是唯一语义**

**配方闭合（P3 的语义承诺）**：文件的语义载体 = 图（节点 + 边 + 区域）；「值 = (产生它的图节点, 输入边)」可直接从文件读出。驱逐不变量 / 再生等价 / 版本化（条款 1/2/3/5）成为可在载体上陈述的性质，而非格式注释。

### 1.2 ENT = 存在结构主干（P2 修复）

- 条目由 **corec 产时重建**（v6 §4.1 规则执行化——§4），恒空消灭
- 条目字段语义：var_id + version + def_nod + 存在区间 + flags（无配方 = 图内不可重算/边界）+ home
- **home 语义定位**（边界 spec §2.3 裁决沿用）：home = 实例映射注记——-1 直通（分配/缓存映射决策 = 实例层 = corearch/映射实例），格本体最小集不含 home 的决策权
- 条目与边的关联：条目 def_nod = 产生节点；版本区间端点 = NOD id（v6 D1 坐标延续）

### 1.3 调度 = 投影（执行序降级为投影）

- 执行序不再是文件主干——它是**图的线性投影**（重建规则 = §3）
- 文件序的角色 = 生产者的调度选择：合法（沿边约束）但非唯一——图语义允许的其他调度（验证器重排、未来执行模型）不被文件序封顶
- 这兑现 v6 原则 1「存在为主体，执行为投影」——v6 有承诺无载体（无真实边 → 无法验证调度合法性）；v7 以边为约束使该承诺可检验

## 2. 语义纯度声明与边界

### 2.1 结构性纯度（v7 达成的）

| 成分 | 判据通过项 |
|---|---|
| 图节点 + 输入边 | 配方闭合（G1-1：值 = 配方可直接陈述） |
| 条目 × 版本 | 赋值 = 版本化（G1-2）——STORE 的 ρ(s1):=ρ(s2) 勘定 = 版本推进的语义雏形 |
| 位置 = (条目标识, 偏移) | 条目标识 = (var, version)（G1-3）；字节地址 = 投影层 |
| 共存 = 对称最弱关系 + 不落盘推导 | 最弱理论（G2-4，v6 §4.2 延续） |
| 判定 = 条目泛型 | G2-3（v6 ENT 判定规则延续） |
| 区域 | 图锚定（REG = 格侧成立，边界 spec §2.4） |
| home = 实例注记 | G3-2（寄存器分配 = 缓存语义映射实例同族） |

### 2.2 显式遗留：op 字典（诚实标注）

- NOD op 全集语义 **不变**（v5 变量槽指令：LOAD/STORE/BRANCH/CALL/arena/tag 面等）——v7 不承诺 P1 语义侧修复
- 遗留的语义角色：op 字典 = 引用的「计算配方种类」参照——变量的槽解释 = 归一化解释层（§2.3）的一部分；泄漏从「载体结构泄漏」（v6：结构无图、语义无条目）降级为「**字典引用泄漏**」（v7：结构 = 图语义，字典 = 显式遗留，被载体声明包围并标注）
- op 字典演进（语义革命级）= 独立后续步骤：把字典逐族替换为配方/版本/区域上的定义——替换发生时以本 spec 的载体为底座，不动载体结构

### 2.3 归一化契约（双消费通道）

v7 载体的消费 = 两个通道，接口 = 载体（图 + 条目），归一化发生在消费侧：

1. **槽语义投影通道**（现状 corearch 路径的延续形态）：图 → 线性调度（§3）→ 槽语义投影（现 IR 发射语义）——行为 ≡ v6 链（§3.3 判据），保证自举链无中断切换
2. **语义消费通道**（验证/优化/未来后端）：直接在图 + 条目上推理——驱逐/再生/版本化/共存为可陈述性质；本通道的消费形态 = 验证链工作（翻译桥/证书）的设计输入，非本 spec 承诺

归一化的正确性判据（两通道共享）= 语义保真（引用缓存语义条款 7 的映射实例正确性方向）：投影/推理产物 ⊇ 载体可观测语义。

## 3. 投影重建契约（消费侧）

### 3.1 图 → 线性调度

重建规则（corearch 侧，字节 spec/实施计划落细节）：

1. 以文件序为基始调度（生产者已保证沿边拓扑合法——**合法性校验** = 重建时沿边约束验证，失败 = 文件损坏拒绝）
2. region 边界按 REG 展开（区域开始/结束标注，语义同 v6 消费方式）
3. 投影产物 = 线性指令流（现发射层输入形态）

### 3.2 state 边的调度角色

- state 链 = 副作用序约束：投影必须保持 state 链拓扑（同一副作用序）——文件序满足时直出；校验 = 沿 state 边验证
- 数据边 = 值流约束：不参与调度（值流经条目/槽解析），但为配方闭合与语义消费服务

### 3.3 行为判据（渐进验证）

**v7 重建产物 ≡ v6 重建产物**（同源程序：v6 链 vs v7 链——corearch 发射输入形态逐字节相同，ELF 逐字节/行为相同）。判据用途：

- v7 切换（corec 产 v7 + corearch 重建）可分步验证：先「v6 语义等价」后「结构正确」
- 测试族：ccr_v6（9/9）→ v7 同构测试 + 对照测试（v6 链产物 vs v7 链产物）
- 判据性质：这是**调度投影的等价判据**（新旧载体 → 同一投影），不是「复刻旧发射器字节」判据（边界 spec C4 裁决已废止后者在实例模板对照中的使用——两者不冲突：C4 裁的是实例模板的对照基准，本判据裁的是载体切换的安全性）

## 4. ENT 主干化执行化

### 4.1 条目重建规则（v6 §4.1 照搬执行化）

- 定值点收集：扫 NOD，dest ≥ 0 的节点 = 定值点 → 版本切分（def_nod、version）
- 两处 carve-out（v6 spec 勘定保留）：
  ① IR_STORE 单列：定值目标在 s1（ρ(s1):=ρ(s2)，dest 恒 -1）
  ② 三 op 排除：STORE_INDEX_VAR / STORE_PTR / DYN_DISPATCH 的 dest ≥ 0 非定值
- 活区间：图坐标扫描（[first_ref, last_ref] 逻辑，坐标单位 = NOD id）；版本 k 区间 = [def_k, def_{k+1}) 截断
- 参数/全局条目：def_nod = -1，区间 = [函数首节点, last_ref+1)
- 无配方条目（边界/图内不可重算）：flags 标注 + home 必须（持久存储语义——边界 spec 引用条款 4b 统一规则）

### 4.2 生产与消费分工

- corec（产）：图化（节点 + 边 + 区域——§5 机制先例）+ 条目重建（§4.1）→ 落盘
- corearch（消费）：loader 解载 → 判定（共存 sweep / 判定四条）消费条目区间；home 决策 = 实例层（分配器），不写回格式（v6 开放点 3 延续：.ccr = 传输中间物，内存态回填）
- 判定消费方式（区间在文件内后分配器是否直接消费 vs 内存重建） = 实施计划定夺，本 spec 不锁

## 7. 术语同步

- 「调度」在本 spec = 图 → 线性投影的产物（文件的合法拓扑选择），与「执行」区分：执行 = 图语义的运行时展开（未来执行模型/验证消费），调度只是其经典投影形态
- 「图载体」= 以图为语义主干的文件形态（.ccr v7），与 .cir（dump 视图）区分：前者 = 编译主链的格形态，后者 = 调试/可视化视图
