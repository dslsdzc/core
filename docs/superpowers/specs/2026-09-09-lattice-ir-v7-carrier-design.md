# v7 格形态语义设计

## 概述

v7 修复 v6 的三个结构问题：

1. NOD 操作语义沿用 v5 变量槽指令，带有存储、控制和编码泄漏。
2. ENT 恒空，存在结构在侧表，实际主干是 NOD 线性流。
3. NOD 边表缺席，生成方法不闭合，文件序从序列化滑向程序顺序。

修复范围是实现方式结构：真实边闭合、ENT 主干化、NOD 成为真图节点。操作语义不变，v5 槽操作仍在操作码面。操作码字典的语义修复是后续独立工作。

设计状态：已实施。背景、逐成分检查表、投影等价检查和实施注记见 `docs/superpowers/implementation/2026-09-09-lattice-ir-v7-carrier-audit.md`。

## 目标实现方式

v7 文件携带：

1. NOD，节点表。节点是图事件，也是生成方法的实现方式。操作码、目标和源操作数语义与 v6 相同。坐标是 NOD id，即图节点坐标。
2. 边表。每个节点的输入边显式落盘。数据边 kind 0 是值流，即 def-use 引用。state 边 kind 1 是副作用顺序，即 VSDG 状态链。
3. REG，区域表。区域嵌套坐标，与 v6 相同。
4. ENT，条目表。条目是变量乘版本的存在视图。
5. 调度等于文件序。文件序是生产者选择的合法拓扑调度，不是唯一语义。

生成方法闭合：文件的语义实现方式就是图，由节点、边和区域组成。值等于产生它的图节点加上输入边，可以直接从文件读出。移除不变量、重算等价和版本化成为可以在实现方式上陈述的性质，不是格式注释。

### 条目主干

条目由 `corec` 在生产时重建，恒空消失。

字段语义：

```text
var_id
version
def_nod
存在区间
flags      无生成方法、边界
home       实例映射注记，-1 直通
```

home 是实例映射注记。分配和缓存映射决策属于实例层，格本体最小集不包含 home 的决策权。

条目和边的关联：条目的 `def_nod` 是产生节点，版本区间端点是 NOD id。

### 调度是投影

执行顺序不再是文件主干，而是图的线性投影。

文件序的角色是生产者的调度选择：合法，沿边约束，但不是唯一。图语义允许的其他调度不受文件序限制。

v6 有“存在为主体，执行为投影”的承诺，但没有实现方式，因为没有真实边，无法验证调度合法性。v7 用边作为约束，使这个承诺可以检验。

## 语义纯度

### 结构性纯度

| 成分 | 通过的检查 |
|---|---|
| 图节点和输入边 | 生成方法闭合，值等于方法可以直接陈述 |
| 条目乘版本 | 赋值等于版本化，STORE 的 `ρ(s1) := ρ(s2)` 是版本推进的语义雏形 |
| 位置等于条目标识加偏移 | 条目标识是变量和版本，字节地址属于投影层 |
| 共存是对称最弱关系，不落盘推导 | 最弱理论 |
| 判定是条目泛型 | 不读值内容 |
| 区域 | 图绑定 |
| home 是实例注记 | 与寄存器分配映射实例同族 |

### 操作码字典遗留

NOD 操作码全集语义不变，仍是 v5 变量槽指令，包括 LOAD、STORE、BRANCH、CALL、arena 和 tag 面。v7 不承诺修复操作码语义。

操作码字典是“计算方法种类”的引用。变量的槽解释属于归一化解释层。泄漏从 v6 的实现方式结构泄漏，降级为 v7 的字典引用泄漏：结构已经是图语义，字典是显式遗留，被实现方式声明包围并标注。

操作码字典的演进是独立的语义层工作。替换时以本实现方式为基础，不改结构。

### 两个消费通道

1. 槽语义投影通道：图到线性调度，再到槽语义投影。行为等价于 v6 链，保证自举切换不中断。
2. 语义消费通道：验证、优化和未来后端直接在图和条目上推理。移除、重算、版本化和共存成为可陈述性质。

两个通道共享语义保真检查：投影或推理的产物必须包含实现方式的可观测语义。

## 投影重建

图到线性调度：

1. 文件序作为初始调度。生产者已经保证沿边拓扑合法。重建时沿边验证，失败则文件损坏，拒绝。
2. 按 REG 展开区域边界。
3. 投影产物是线性指令流，即当前发射层的输入形态。

state 边的调度角色：

- state 链是副作用顺序约束。投影必须保持 state 链拓扑。文件序满足时直接输出，校验时沿 state 边验证。
- 数据边是值流约束，不参与调度，但为生成方法闭合和语义消费服务。

行为检查：v7 重建产物与 v6 重建产物等价。同源程序的 v6 链和 v7 链，`corearch` 发射输入形态逐字节相同，ELF 行为相同。

检查用途：

- v7 切换可以分步验证：先验证 v6 语义等价，再验证结构正确。
- 测试族先跑 `ccr_v6`，再跑 v7 同构测试和对照测试。
- 这是调度投影的等价检查，不是复刻旧发射器字节。边界设计已经废止后者用于实例模板对照，两者不冲突。

## 条目重建

定值点收集：扫描 NOD，`dest >= 0` 的节点是定值点，据此切分版本。

两处例外：

1. `IR_STORE` 单列。定值目标在 `s1`，即 `ρ(s1) := ρ(s2)`，`dest` 恒为 -1。
2. `STORE_INDEX_VAR`、`STORE_PTR` 和 `DYN_DISPATCH` 的 `dest >= 0` 不是定值。

活区间使用图坐标扫描，逻辑是 `[first_ref, last_ref]`，坐标单位是 NOD id。版本 k 的区间是 `[def_k, def_{k+1})` 截断。

参数条目是从来没有定值但有引用的变量，例如函数参数。`def_nod = -1`，区间是 `[first_ref, last_ref]`。盘上 `live_end` 是半开区间，等于 `last_ref + 1`。

无生成方法条目，包括边界和图内不可重算条目，用 `flags` 标注，并且必须有 home。这是持久存储语义。

生产和消费分工：

- `corec` 生产：图化节点、边和区域，重建条目，落盘。
- `corearch` 消费：加载，判定共存和四条规则时使用条目区间。home 决策属于实例层，分配器决定，不写回格式。
- 判定是直接使用文件内区间，还是内存重建，由实施计划确定。

## 与既有实现的关系

| 实现 | 关系 |
|---|---|
| `dataflow.cr` 的 VSDG | 图构建机制先例：节点、def-use 数据边、state 链和区域。v7 生产者把该机制输出落盘，或等价重建 |
| `cir_cache.cr` v13 | 图序列化编码先例，字节格式的基线 |
| `ir-schema` 三形态 | `.ccr` 列语义从“线性化”改为“图实现方式”，执行序是投影 |
| `ccr_v6` 测试族 | v7 切换时迁移，保留 v6 链对照和 v7 结构测试 |
| v6 格式 | 原则“存在为主体，执行为投影”在本设计实现；操作码原则标为泄漏源；边表裁决为必须落盘 |
| 自举链 | 只支持 v7。`corec` 和 `corearch` 同日切换。管线中间产物没有持久生态 |
