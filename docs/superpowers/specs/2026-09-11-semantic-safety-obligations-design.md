## 1. 属性轴（基础七轴 + `determinism` 族）

### 1.0 轴的形式公设（**本 spec 的裁决**）

> 术语「属性轴（attribute axis）」按共享契约 §1.1 逐字使用：**图对象/边上的开放标注维度**，七轴 = `trust`（可信度）/ `secrecy`（机密性）/ `integrity`（完整性）/ `authority`（授权）/ `lifetime`（生命周期）/ `state-version`（状态版本）/ `effect`（副作用）。

- **A1 值域不固定**：**本 spec 不为任何轴固定值域、偏序或格代数**——三者均为 **policy 数据**。理由 = v4「无格承诺」（§4.6）：判定与定理只在关系层面陈述；任何具体格 = 签名 + 恒等式 = 封顶。
  - 各轴**必须**具备三件结构（形式要求，非具体取值）：① 值域（有限或无限）② 偏序（关系层面，用于「谁强于谁」）③ **传播规则**（沿值流边如何派生）。
  - 承 A1 的直接后果：新增轴 = 在标注空间加一个维度（v4「加标签不是新机制」），**不动 Graph 本体、不加关键字**（契约 §1.1 policy 定义）。
- **A2 不升格 primitive**：轴 = 开放 semantic annotation / relation；**只有义务可能拒绝编译**（契约 §1.2 原则 1，承 M1 定论与定案 1/12）。
- **A3 传播单调**：派生不提升信任、不降低机密性、不提升完整性、不延长生命周期（各轴方向由 policy 定，但**单调性本身是形式要求**）。唯一例外 = 显式**净化/降密节点**。
- **A4 唯一放行通道 = declassify**（共享契约 §1.1：`Secret → Public` 的唯一合法通道；同构地 `Untrusted → Trusted` 的净化节点）。且 declassify 节点**自身带 authority 义务**（降密需要授权）——这是轴间耦合的第一实例（§1.8）。

### 1.1 `trust`（可信度）

| 字段 | 内容 |
|---|---|
| 语义定义 | 值是否由受控方产生：`untrusted ⊑ trusted`（**信任只降不升**——派生不提高信任；唯一提升 = 净化节点） |
| 载面 | **节点标注（source 节点）+ 沿值流边的传播**（与 provenance 同族——出生节点记录来源，传播 = 图上可达性） |
| 来源 | **领域库声明**（不可信来源：`read_file`/`get_env`/argv/网络）+ **自动推导**（传播）+ **显式标注**（净化节点 = 库提供的类型化构造器，契约 §1.1 sink/source 模型） |
| 既有机制接口 | provenance（`docs/pointer-model.md`：出生节点即来源，**同一条边**，零新图机制）+ `ext_safety.cr` 钩子（enforcement 落点）+ parser 标签位/`g_plugin_tags`（标注载体，§3.5） |
| 首消费方 | **S-A 切片（§6）**、S-B1（注入——含 `syntax_raw` 裸位置判据）、**S-B3（对偶方向 `Untrusted ↛ Trusted` 的传播面）**、S-B4（围栏——不可信路径数据） |

**三份消费方对表（D1(a) 共同要求；2026-09-11 裁决）**：**谁定义** = 本表（S-A §1.1，术语唯一依据）；**谁判定** = 判定引擎（§3.3 单式 `ty_sub(τ_value ⊓ A_trust(v), Shape(π))`，三态，不另建体系）；**谁是消费者** = S-A §6 切片（裸位置）、S-B1（`syntax_raw` 裸位置）、S-B3（`Untrusted ↛ Trusted` 传播面）、S-B4（不可信路径数据）。**两面对照（不得混同）**：`trust` 的**程序内传播**可判（本轴，就是上表）；**来源真实性的 attestation**（谁生产/签名/背书该来源）**不可判**——属 §1.3 第 2 类，只能用可复现构建 / 签名 / provenance **缩小**（§8 第 2 行）。

### 1.2 `secrecy`（机密性）

| 字段 | 内容 |
|---|---|
| 语义定义 | 值是否允许流向公开观察面：`secret ⊑ public`；**降密 = declassify（唯一通道，A4）** |

## 2. 义务四档

> 术语「义务（obligation）」按共享契约 §1.1 逐字使用：**由属性轴导出的、必须在编译/验证期被处置的判定要求**。四档 = ① **prove**（静态可证 → 零成本通过）② **enforce**（不可证但可运行时强制 → 插入 enforcement）③ **proof-required**（不可证也不可强制 → 要求用户提供 proof/contract）④ **reject**（高安全模式下仍无法处置 → 拒绝编译）。

### 2.1 义务的形态

```
义务 O =（轴 a，源标注 S，汇要求 R，落档策略 policy）
判定输入 = 图上由 S 到 R 的「值可达性 / 形状包含性」判定（判定形态见 §3.3）
义务状态 = open → {proved | enforced | proof-provided | rejected}；**不存在 open → passed**（§5.1 禁令）
```

### 2.2 从义务到落档：判定决策树（**本 spec 的裁决**）

```
义务 O（轴 a，源标注 S，汇要求 R）
  │
  ├─ 引擎判定（ty_sub 三态；常量档 = 判定输入为编译期常量）
  │    ├─ 真 ⇒ ① prove（零成本通过；不下发任何字节）
  │    └─ 假 ⇒ **违法**（编译错误；任何 policy 档位都拒绝）
  │              唯一放行 = 显式例外入口（declassify / 净化节点 / unsafe 边界 /
  │              **授权族的 grant 声明**——均入 §3.1 放行·声明条目并落台账，D2），
  │              且放行本身**登记为义务**（不静默——v4「例外入口授权可追踪」）
  │
  └─ unknown（三态第三态：判定预算耗尽 / 桥接失败 / 名称不展开）
       ├─ **存在 enforcement 点**（检查语义定义良好 + 图上有插入面）
       │    ├─ policy 允许 ⇒ ② enforce（插检查节点；失败语义按策略，默认硬陷阱）
       │    └─ policy 档位 strict ⇒ ④ reject（或要求 proof 覆盖该检查点）
       └─ **不存在 enforcement 点**（不可强制：隐式流 / 信任假设 / 规范正确性）
            ├─ policy 允许 ⇒ ③ proof-required（登记义务 + 要求 proof/contract；
            │                  未提供时 = 显式诊断 + 台账条目，**不是通过**）
            └─ policy strict 且未提供 ⇒ ④ reject
```

三点关键区分（防误读）：

1. **「违法」与「④ reject」不同**：违法 = **已判定为不合法**（引擎返回假），任何档位下都拒绝；④ = **无法处置**（判不出、不可强制、又不满足 policy），是「不知道」的结果。前者措辞 = 违反（含反例值，复用 `tt_witness`）；后者措辞 = 未处置（含出路建议）。
2. **三态是决策树的地基**：R2 P0 引擎的三态（真 / 假 / unknown——unknown 含预算耗尽与未覆盖面）使「证不出」不是异常而是**第一等输入**。这与 R2 §3.3 的「预算超限 ≠ 类型不兼容」同构：**不可判定 ≠ 不合法**。
3. **档位选择是 policy 数据**：同一条义务在不同 policy 档位下落不同档——「同一程序、不同 policy、不同档」是特性而非缺陷，即「安全 = 相对 policy」的诚实面（§8 第 1 类）。

**附：默认强度分层（2026-09-11 用户裁决 D3(c)，规范性）**：

| 面 | 默认（本地 / 开发） | 严档（strict / CI / 高安全） | 依据 |
|---|---|---|---|
| 档 ③ | **登记 + 继续编译**（③ = `open`，**不是通过**） | **拒编**（④） | §5.1 状态机；§9.2-1 已裁 |

### 2.3 四档 × where 三档映射（定案 5 的补完）

| where 三档（定案 5） | 四档落位 | 说明 |
|---|---|---|
| **常量档**（约束输入 = 编译期常量）→ 编译错误/通过 | 真 → ① prove；假 → **违法** | 与三档原语义一致 |
| **符号档**（约束输入 = 符号项）→ VC 义务 | 真 → ①；unknown → **③ proof-required**（VC 义务，验证管线消费）；假 → 违法 | 三档的 VC 面 = 四档 ③ 的一个**来源** |
| **动态档**（约束输入 = 运行期值）→ 运行时检查 | **② enforce**（插运行时检查）；strict → ④ | **四档的收紧点**：三档把「运行时检查」当动态档的固定归宿；四档把它**降格为允许的兜底之一**（§0.3 T2） |
| （三档无对应）**不可强制义务** | **③ / ④** | 四档的**新增面**：隐式流（branch/timing）、信任假设（供应链）、规范正确性——三档结构上未覆盖。**实例**：确定性族的隐式竞争 → ④（该族 policy 固定，§1.9） |

- 三档自带的「防『证明不了也不静默』」措辞（定案 5 原文）与契约 §1.2 原则 3 同向——四档把它补完为**档位谱 + 拒编**。

### 2.4 每档的成本与可判定性边界

| 档 | 经典路径成本 | 可判定性边界 | 失败语义 |
|---|---|---|---|
| ① **prove** | **零新增字节**（证明完毕不下发——与 bounds-inference、缓存语义 v4 §十一同款） | 引擎可判定子集内且预算内返回真 | n/a |
| ② **enforce** | 检查节点字节（先例 `IR_BOUNDS_CHECK` ≈ cmp+jb+ud2）；最坏 = 每 sink 一次 | **不可判定但检查语义可定义**（检查点存在） | 默认**硬陷阱/中止**（与先例一致：「中止而非未定义值（安全优先）」，`ir-op-semantics.md:196`）；库可声明其他（§4.3） |
| ③ **proof-required** | 零运行期成本；成本 = 用户/领域库的 proof/contract 撰写 + 验证管线时间 | **不可判定且不可强制**（隐式流 / 信任假设 / 规范正确性） | 默认：诊断 + 清单条目（登记，**不是通过**）；strict：拒绝 |
| ④ **reject** | n/a | 策略档位的后果（非判定结果） | 编译错误（响亮 + 出路建议，§5.4） |

- 预算边界（**诚实项**）：引擎有判定预算守卫（R2 P0）。预算耗尽 → unknown → 按本决策树落 ②/③/④，**绝不当通过**；且诊断必须区分「预算耗尽」与「判定为假」（R2 §3.3 同款）。

### 2.5 判定的可靠性责任（**待论证，登记**）

本 spec 定的判定**入口** = 引擎（契约 §1.2 原则 4）；「判定为真 ⇒ 该族的流纪律成立」这一**可靠性**是**各族的证明义务**，不是本 spec 的承诺：

- 判定目标形态 = 单值判定：`ty_sub(τ_value ⊓ A_a(v), Shape(sink))`（§3.3）。
- **待论证的前提**：轴传播单调（A3）+ 单值判定的忠实编码 ⇒ 图上「源到汇」的路径性质（不可达性）。若某族该前提不成立（典型：隐式流——值未流动但信息流动），该族落 ③（不可强制）或另立图可达性 pass，**不得**用单值判定冒充。
- 登记项：各族在自身 spec 中给出「判定真 ⇒ 纪律成立」的论证或反例边界。

### 2.6 `determinism` 族的落档规则（§1.4 的实例化——**规范形态**）

> 本族**不新增档**：§1.4 逐字「执法 = 四档义务（与 §1.1 四档同构）」。轴表与载面见 §1.9；本节给**规范形态**（实施批以此为准）。

| 判定输入（图上事实） | 落档 | 依据（§1.4 对表） |
|---|---|---|
| 依赖 / 状态边**足证**「汇合与调度无关」 | **① prove**（零成本） | §1.4 行 1 |
| **显式顺序源**存在（`merge_ordered`） | 落到确定实现（义务已由显式顺序源处置——**不新增档**） | §1.4 行 2 |
| **显式不确定请求**（`race` / `select_any`）**且「声明-实现一致性」证明成立** | **① prove + 报告义务**（**非第五档**；报告面登记归 S-D） | §1.4 行 3——「语义明文允许 ⇒ 程序说的是它想说的 ⇒ 义务已处置」；**证明范围 = 局部**（报告面须标注「未覆盖观测点」）；**证明不成立 ⇒ ③ 登记**（D10(a)） |
| **既未证明也未标注**（隐式竞争） | **④ reject**（§1.4「真正的执法点」） | §1.4 行 4——该族 policy 取值 `allow_enforce=false` + `require_proof=false` + `strict=true`（§3.1 数据）→ §2.2 决策树**固定落 ④**，**无需改树** |

两条硬约束：

1. **④ 的直接性来自 policy 取值，不是判定结果**：隐式竞争在引擎侧是 **unknown**（判不出「汇合无关」，也不存在显式请求）；其 ④ 是**该族 policy 禁止 ②/③ 兜底**的结果。若未来放宽（例如「要求提供汇合证明」→ ③），改的是 **policy 数据**，决策树与判定器不动。
2. **`select` 判定侧禁令**（§1.9）：S-E 重定前，`select` 不得作为「显式顺序源」输入 prove——否则把现有语义缺陷固化为证明前提。

### 3.2 挂法：与 R2 双轴注册表**并列**，判定**共用入口**

- **并列表**（不复用 `g_ifaces`/`g_impl_for`），三条理由：
  1. **语义不同**：策略不是类型接口——混表 = 把漏洞类型做成类型特判（契约 §1.2 原则 2 禁止「lint 换皮」）。
  2. **布局遗产**：`g_ifaces`（1432B/条、16 方法 × 88B 上限）+ `g_impl_for` 的名字拼接遗留是 R2 §2.4 的**升级对象**；策略表另立 → 两者互不阻塞。
  3. **增量性**：策略新增 = 加数据行（契约：新增安全模型不改 Graph 本体）。
- **共用入口**：查询 API 与 R2 `iface_*` 家族**同风格**（`policy_*`），判定**唯一**走引擎（契约 §1.2 原则 4：「不另建判定体系」）。
- **现状事实**：`g_plugin_tags`（24B/条 `ns/name/data`）已是「插件可注册的开放表」原型——策略表是其**语义升格**（同一形态，语义从「标签位」升为「策略条目」），非新机制。

### 3.3 策略 → 图上的形状项/约束（**判定走引擎**）

```
A_a(v)        ：轴 a 的取值 v → 类型项（**policy 数据**，各族自定；A1 不固定值域）
Shape(sink)   ：sink 的形状项（policy 数据；语法位 / 值位的区分在此编码）
判定          ：ty_sub( τ_value ⊓ A_a(v) , Shape(sink) )   ← ⊓ = 引擎 INTER（不新增判定算子）
```

- 引擎返回三态 → 直接进 §2.2 决策树。
- 反例值：判定失败时用 `tt_witness` 给**具体值示例**（R2 §3.2 已有），诊断质量直接受益。
- **不新增判定算子、不新增规范化规则、不新增 memo 语义**——策略侧只提供数据（§0.3 T1）。
- **诚实边界**：`A_a(v)` 的声明责任在 policy（领域库）——声明错（漏 sink / 错形状）属「错误 specification」类，本族**不承诺**（§8 第 1 类）。

#### 3.3.1 健全性约定：`A_a` 只做加约束式单调展开（**规范性**；与 S-B1 约定/N5 互为对偶）

**风险（跨 spec 健全性洞，S-B1 提出）**：若 `A_a` 以**否定形式**展开（如 `untrusted ↦ ¬Trusted`），左侧求交可能塌为 `⊥`——而 `⊥ ⊑ 任意 φ` **恒真** ⇒ 判定对**所有** sink 放行 ⇒ **静默通过**（违反契约 §1.2 原则 3）。R2 类型项语言含 `¬`（`NOT` 构造子），故此洞是**判定形态的结构性风险**，不是表达力问题。

**两条腿都要堵（2026-09-11 A 线评审 C3 + 裁决 D11）**：C1/C3 堵住**左腿**（否定展开 ⇒ 左项塌 `⊥`）；**右腿（右项 `Shape`）与正例侧原先无控**——单式 `ty_sub(τ_value ⊓ A_a(v), Shape(π))` 在裸位置判据下**全部鉴别力都在右项**：若 `Shape` 被误声明为 `⊤`、或引擎对未定义的原子（如 `Trusted`）取宽松解释（无公理的原子当可满足一切），判定**恒真 ⇒ 静默通过**（同一类洞，换了腿）；反之若 `Trusted` 被声明为与 `string` **互斥**的原子类，则正例左项 `Trusted ⊓ string = ⊥` ⇒ C3 判失败 ⇒ **正控全灭**（§6.4-1「净化路径编译通过」不成立）。**C5 因此是必需的**，不是补充项。

| # | 约定（C） | 内容 |
|---|---|---|
| **C1** | **左侧只加约束（单调）** | `A_a(v)` 必须是**加约束式单调展开**（纯合取式的**正**编码，如 `Trusted ⊓ string` / 原子类约束）；**禁止**用否定形式编码属性（`untrusted ↦ ¬Trusted` 之类） |
| **C2** | **要求一律写右侧** | 属性**要求**（sink 需要什么）一律写在 `Shape(φ)` 侧（右侧），**不写**在左侧值项上 |
| **C3** | **⊥ 非真（vacuous truth 禁令）** | 判定入口显式守卫：`ty_inhabited(τ_value ⊓ A_a(v)) == 0`（左侧为 ⊥ / 标注不一致）时**不得**判为通过——落 §2.2 的 unknown 分支（诊断「标注不一致 / 义务不可判」），按该族 policy 处置。**⊥ 视为判定失败，不视为真** |
| **C4** | **负控 / 正控（测试）** | ① 构造一条**以否定形式展开的 `A_a`** → 断言**不得放行**（落 ④ 或具名诊断）；②「左侧塌 ⊥」探针用例 → 断言按失败处理（C3）；③ **非退化正控**（C5②）：`Trusted ⊓ string ≠ ⊥` 的正例必须通过；④ **右项 ⊤ 负控**（C5①）：`Shape(π)` 为 `⊤` 的策略 → 断言**装载期拒装**（§3.6）。四项进 §7-#8 |
| **C5** | **非退化性（2026-09-11 裁决 D11；堵右腿 + 锁正例）** | ① **右项非退化**：`Shape(π)` 在 `syntax` / `syntax_raw` 位置**不得为 `⊤`**——**policy 装载期校验**，违者诊断**拒装**（§3.6）；② **正例非 ⊥**：每条轴取值 `v` 必须有**非退化正例**（`τ ⊓ A_a(v) ≠ ⊥`，典型 `Trusted ⊓ string ≠ ⊥`），以 C4③ 的正控锁死；③ **假 / unknown 分因 + 未定义原子规则**：`ty_sub(τ, Shape)` 的「假」= **违法**、「unknown」= **③/④**（§2.2 点 1/2 同款），并明写「**未定义原子的解释规则 = unknown，不得取真**」——否则同一份 policy 数据下诊断档位会在 ③/④ 与硬错之间摆动 |

- 落地接口：C3 用 P0 引擎**已有** API（`ty_inhabited`，R2 §3.2 已实施）；C5① 是**装载期数据校验**（§3.6），C5② 是**正控**，C5③ 是**诊断分因要求**——**三者都不新增判定算子**（§3.3 第三条不变）。

- **现状事实**：`parser.cr:689-719` 的声明标签位已支持三类标签——内建（`mut`/`pub`/`apx`）、**插件注册标签**（查 `g_plugin_tags`）、未知标签 → `TA08`（`EC_TA_UNKNOWN_TAG=4008`）。`apx` = **变量级标签、零新语法**（`numeric-types-design.md:29`「与 mut/pub 同族，零新语法」）。

### 3.6 装载期校验（policy loader；D6 + D11①，**规范性**）

- **受控命名空间（D6(a)）**：**形状项 / 根声明**只在**受控命名空间内有效**——**装载期校验**；「**谁有权声明形状项 / 根**」记入 policy 面，**对装载器可见**（审计面）。**不启用 `pub` 强制**（`pub` 今日全仓无消费：`parser.cr:662/697`，见「代码级缺陷 5」）；**选项 (b)「库内可见性 / 构造器封闭」不实施**。理由：根声明权与形状项声明权本是**治理层数据**，塞进语言权限模型会与 §1.4 的判定边界打架。

## 4. enforcement 通道（动态档落地）

### 4.1 先例（**现状事实——enforce 档的原型已经在跑**）

`IR_BOUNDS_CHECK`（`ast.cr:559`，op 30）：语义 = `if ρ(s1) ≥ᵤ s2 → ud2`（`ir-op-semantics.md:196`）；发射 = `ext_safety.cr:27,33`（**插件 + 钩子**形态，不是语言特判）；解释器侧已实现（`interp.cr:289`）；ELF 侧编码 = cmp + jb + ud2。失败语义 = **中止而非未定义值（安全优先）**；负索引由无符号比较天然捕获。

**结论**：enforce 档**不需要新机制**——它就是「插件钩子 + 图侧检查节点 + 硬陷阱」的推广。

### 4.2 插入面与发射门控

- **插入面**：pass 层（与 `ProvenanceVerify` / `RegionCheck` / `ext_safety` 同级），检查节点 = 图上节点（**不新增语义**——检查是映射实例层的保护带）。
- **发射门控**（与 TODO「边界判定图 pass」**同构**）：
  - 证明恒安全（引擎真）→ **不发射**（prove 档，零字节）；
  - 证明恒违法（引擎假）→ **编译期拒绝**（§2.2 违法分支）；
  - 判不出（unknown）→ 保留检查 + **图推导必要性标注**（证明失败的原因随节点落盘，兼作验证证据）。
- 需要新 opcode 时，成本面 = `ast.cr` 分配 + 解释器 + x86 编码 + 判据（先例：`IR_BOUNDS_CHECK` 全链）；**本 spec 的切片不新增 opcode**（§6.2）。

### 4.3 失败语义（**本 spec 的裁决**）

| 语义 | 内容 | 适用 |
|---|---|---|
| **abort（默认）** | 硬陷阱（ud2/SIGILL），与 `IR_BOUNDS_CHECK` 先例一致 | 安全类 sink 的默认 |
| degrade | 净化降级后继续（例如转义/白名单） | 库声明（policy 数据） |
| report | 报告并返回错误值/错误码 | 库声明（policy 数据） |

- 默认 = **abort**：**中止优于未定义行为**（先例已立此判据）。
- degrade 必须由 policy **显式**声明（否则等于静默放行——违反契约 §1.2 原则 3）。

### 4.4 成本纪律

- 仅在该 sink 发射检查；**无轴使用的程序零产物变化**（判据沿用仓库既有形态：byte-identical）。
- 语义层不承诺检查存在（T4）——「是否发射」是映射/策略决策，不是语义承诺。

### 4.5 与定案 14 声明式边界的处理

检查节点落在**命令式下限**（执行面），但它是**图构造**（与 state edges / region 同层），不是新的顺序语义或语义本体条目。承 v4 §十一「证明完毕不下发」：证明产物（含检查的必要性标注）不下发到运行期，只有检查本身按 §4.2 门控发射。

### 4.6 双路径一致性（判据要求）

enforce 档一旦落地，检查语义必须**解释器 / ELF 双路径一致**——沿用 R1 的判据形态（同一用例双路径精确 rc，`test_global_init.py` 先例）。切片 1 不含运行期检查（§6.2），该项列为切片 2 判据。

## 5. 未证明义务的落法（诊断面）

### 5.1 义务状态机与禁令

```
open ──prove(真)──→ proved（零成本）
open ──enforce────→ enforced（检查节点已发射）
open ──proof 提供──→ proof-provided（proof/contract 归档，验证管线可复核）
open ──strict 未满足──→ rejected（编译拒绝）
open ─────────────────→ **passed 不存在**（禁令：不静默）
```

**禁令（契约 §1.2 原则 3 的可实施形态）**：证不出 → 必落 ②/③/④ 之一，**绝不静默当通过**。③ 的「登记」状态是 **open**（未处置），**不是** passed——清单中它是待办，不是已通过项。

### 5.2 三面可见（缺一不可）

| 面 | 内容 | 现状接口 |
|---|---|---|
| **a) 诊断面** | `error[XXXX]` / `warning` 体系，新增「安全义务」码段。必须区分三类语义：**不可判定 ≠ 不合法**（R2 §3.3 同款）/ **未处置 ≠ 通过** / **预算耗尽 ≠ 判定为假** | `diag.cr` + `EC_*` 段（`ast.cr`）+ R2 §7 的分段策略 |
| **b) 清单面** | **义务清单**（obligations manifest）：轴 / 源 / 汇 / 落档 / 状态 / 图→源码位置映射。是人类与 CI 的门槛通道（strict 档 = CI 断言清单为空）。**§3.1「放行 / 声明条目」的每一条（含豁免形态者）必须在此出现**（D2：放行必须落清单） | 落点实施批定（编译输出过渡态先行；`.ccr` 段随 §3.4 = R2 P4）。**格式归 S-D 线统一（D29）**——各族只写消费点，不写格式 |
| **c) 产物面** | 义务清单 = 图数据的投影（语义保鲜兑现，R2 §6.4 同构）——验证工具直接消费，不必重跑前端 | `.csr`/TagNode 图验证线（coreir-schema「图即验证」） |

### 5.3 「不静默」的可测判据（把承诺变成断言）

- **负控**：故意留一条未处置义务 → 编译输出**必须**含具名诊断（轴 + 源位置 + 汇位置）+ 清单条目；测试断言二者均存在。
- **strict 负控**：同一条义务在 strict 档 → 编译**必须**拒绝（非零退出 + 错误码）。
- **正控**：净化后 → 通过，且清单中该义务状态 = proved，无诊断。
- 「静默通过」的**反判据**：任何「义务存在但输出无诊断且清单无条目」的场景 = 本 spec 的**违约**，测试必须覆盖。

### 5.4 档 ④ 的措辞要求

拒绝必须给**出路**（否则等于死墙）：补 proof/contract / 加 declassify / 显式例外入口（`unsafe` 边界——**放行记入清单**，承 v4「例外入口授权可追踪（信任链）」）。

## 6. 最小可实施切片（S-A 第一批）

### 6.1 选型与理由

- **轴 = `trust`**：唯一同时具备 ① 现状 source（`read_file`/`get_env`/argv）② 现状 sink（`src/stdlib/os.cr:30` `system(cmd)` = **fork + execve("/bin/sh","-c",cmd)**，教科书级命令注入点）③ 净化先例（declassify 同构）④ **不需要新 opcode**（静态纪律）的轴。
- **策略 = 一条**：`untrusted ↛ system 的 cmd 参数（语法位）`——S-B1（注入族）的**前身**，但本切片**只做流纪律与档位流程，不做领域库**（SQL/HTML 留给 S-B1）。
- **正控 / 负控**：负控 = `get_env("X")` 直达 `system(...)`；正控 = 经净化节点（库提供的 sanitize 内建/显式 declassify）后通过。
- **启动条件（已满足）**：切片 A 的判据基础 = `trust` 的**可判传播**语义——2026-09-11 裁决 **D1(a)** 保住 S-A §1.1 为出处（§1.1 对表），**该阻断项已解除**，切片 A 可开工；前置依赖 = §6.2 的「不依赖」清单 + R2 引擎已就位。

### 6.2 切片边界（明确的「不做」）

- **不新增 opcode**、不做 enforcement 实施（② 档**只留接口位** + 复用 `IR_BOUNDS_CHECK` 先例登记，实施归切片 2）；

- 不碰隐式流（③ 档在本切片只以**登记**形态出现，不判定）。

### 6.3 组分（三项；**按三批排期**：T1 → T2 → T3，各自带判据；2026-09-11 A 线评审 I5 修法）

| 任务 | 内容 |

1. **正控**：净化路径编译通过；产物与「无轴标注版本」**byte-identical**（prove 档零成本）。

### 6.5 候选切片 B：`determinism` 族的「隐式竞争 reject」执法面（**与切片 A 并列，二选一或两者**）

- **范围（以负控侧为主）**：图上「共享条目被两个并发 region 触碰 + 两 region 间无 state edge 顺序源 + 无显式请求标注」→ **reject**（§2.6 行 4）。**正控侧**（显式 `race` / `select_any` 通过 + 报告条目）**依赖 S-E 四形态语义**——若 S-E 未定稿，切片 B **先只做负控**（隐式竞争必须 reject），正控登记为 S-E 就位后的增量。

  1. **负控**：隐式竞争用例 → 编译拒绝；诊断指出**共同条目 + 两个 region 位置**（图→源码映射）。
  2. **正控（S-E 就位后）**：显式 `race` / `select_any` → 通过，且报告面条目存在（S-D 接口）。
  3. **零回归**：无并发构造的既有语料 → **零产物变化**（byte-identical）+ 全套件 / 自举关卡同切片 A（§6.4-4）。
  4. **不静默**：④ 的诊断必须给**出路**（显式请求标注 / 补顺序源 / 提供汇合证明——按该族 policy 当前可用者）。

- **越界声明**：切片 B **不定义** `merge_*` / `race` / `select_any` 的语义（属 S-E，§0.2）；只消费其**图上显式标记的存在性**（§1.9 接口需求 1）。

## 8. 不承诺

> 逐条引用共享契约 §1.3 三类**不可消**的残留，说明本族落在哪类。

| # | 契约 §1.3 类别 | 本族（S-A + 属性轴/义务阶梯）的落点 |
|---|---|---|
| 1 | **错误 specification** | 本族只能证明「**程序忠实实现了 policy**」，**不能**证明 policy 本身正确：policy 漏声明的 sink / 错形状的 source / 错误的 `A_a(v)` 映射 → 义务阶梯**结构上无法覆盖**它。故本族**不承诺**「程序安全」，只承诺「相对 policy 的忠实性 + 义务不静默」。这是第 1 类的**纯落点** |
| 2 | **恶意/失陷外部实体** | `trust` 轴提供**声明与检查**通道（untrusted 标记 + 净化节点），但**不能**证明「被声明为 trusted 的组件真的可信」——供应链 / 编译机 / 密钥 / 硬件后门不可用语言语义证明。本族贡献 = 把信任假设**显式化**（可审计、可追踪、最小权限，承 v4「可追踪信任链」），**不是消除它**。`determinism` 族的 `D_external`/`D_timing` 同落此类：外部世界的时间与环境**不可证明**，只能**归因 + 三值标注**（`PROVED`/`MODELED`/`UNKNOWN`）——不承诺消除物理不确定性，只承诺**不许撒谎**（§1.9） |
| 3 | **需求本身允许危险行为** | shell / browser / kernel / JIT 必须执行外来代码——`system(cmd)` 本身就是需求（§6.1 的 sink 不是 bug）。本族目标 = 证明**隔离边界**（形如「不可信数据不能到达解释器语法位」的流纪律），**不是禁止能力**；`declassify` / `unsafe` = 危险行为的**显式授权点**（登记可追踪） |

**全局禁令（原文遵守）**：**不承诺**「能自动证明所有程序安全」——判定引擎是**三态 + 预算守卫**的，unknown 是设计内的第一等结果（Rice/halting 边界，契约 §1.2 原则 3）。

## 9. 不做项（YAGNI）与开放问题

### 9.1 不做项

- **不改 Graph 本体**：零新 opcode（切片 1）、零新关键字、零新图结构（契约 §1.1 policy 定义）。
- **不建第二判定体系**：判定一律走引擎（契约 §1.2 原则 4）；不新增判定算子。
- **不做自动证明搜索**：归 TODO「证明搜索自动」（proof-search）；本 spec 只做**档位与流程**。
- **不做隐式流完整判定**（timing/cache 面）：登记为「不可强制」类（§2.3），边界归 S-B3。
- **不做运行期标签**：轴标注 = 编译期图数据，证明完毕不下发（与能力同理，v4 §十一）。
- **不做 policy DSL**：policy = 条目数据，不是策略语言（新语法 = 违反契约；需要表达力时用 `A_a(v)` 映射数据）。
- **不做「安全开关」语义**：policy 档位（strict/宽松）是**策略数据**，不是语言模式；不存在「关掉安全 = 语义不同」的开关（同 CORE_SAFE 的调试语义需在实施批单独裁决）。
