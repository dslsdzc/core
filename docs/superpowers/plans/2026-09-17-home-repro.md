## 1. 现状根因（`file:line` 逐条实读；行号为 develop `66eb9589` 实况）

### 1.1 完整影响链（`$HOME` 到产物字节）

```
import io 解析（module.cr:504-535）
  └─ :522-530   home_dir := get_env("HOME");  [为空时硬编码 "/home/DslsDZC"（module.cr:526）]
                so_idx_path := home_dir + "/.core/lib/" + fs_path + "/index"
                so_idx := read_file(so_idx_path)
                if str_len(so_idx) > 0 { reg_so_funcs(so_idx, fs_path) }   ← 唯一的读点
        └─ reg_so_funcs（module.cr:226-395）逐行解析 `name: params [-> ret] [, tags]`
              ├─ module.cr:385  fni := str_intern(func_name)      // STR 段新增串
              └─ module.cr:387-393  追加 SYM 条目：
                     sym_set_kind(SYM_SO_FN) / sym_set_type(tag_flags) / sym_set_node(type_encoding)
                     g_sym_count++                                 // SYM 段新增条目
```

因此 `g_syms` 条目数变化会平移后续所有符号索引。NOD（`IR_CALL.src3` 为 callee 名索引）、IFACE 等都引用这些索引，因此扰动会扩散到 4 个段。这与 V2b 实测「同尺寸异 sha，差异散布 STR/SYM/NOD/IFACE」一致。

### 1.3 优先级实核：索引条目覆盖同名 `.cr` 声明

`find_gsym`（`:816`）反向扫描。`check_all` 在 `collect_decls()` 之后把 SO_FN 条目追加到表尾（`:3899-3911`）。因此同名时后出现的 SO_FN 先被命中，`print`/`println`（`src/stdlib/io.cr:6,12` 有声明，索引里也有）在索引存在时解析为 SO_FN。

### 1.4 本轮新增实核（3 个实验，全部在 `core-modws` 用本区 `build/corec` 运行）

| # | 实验 | 结果 | 含义 |
|---|---|---|---|
| E1 | `generics_test.cr --static` 在 `HOME=空` 与 `HOME=含 io/index` 下的 ELF | 逐字节相同（37582B，`f1f78683…` 两侧一致） | 索引对语义面（发射）零影响 |
| E2 | 同上两态的 `.ccr` | 142908 `a1f7b99c…` 与 142936 `704316c8…`（+28B） | 影响只在实现方式面 |

两种情形的性质不同，必须分开裁：

- 引用索引独有名字的语料中，索引是关键（E3：没有它编不过）。该类程序的产物天然依赖索引内容，跨机可复现性不可得，除非把元数据源移入仓库，见方案 C。

## 2. 候选方案（逐案：改动面、风险、检查、对 canary 与五条出处的影响）

> 五条出处 = `tools/baseline/canary_values.tsv`（`canary_elf` + `.ccr` 四条）。

### 方案 A，改动最小：只删硬编码后备（#83），#82 登记为「已知不可复现」

- 改动：`module.cr:526` 删除 `if str_len(home_dir)==0 { home_dir="/home/DslsDZC"; }`。HOME 为空时直接查 `/…/.core/lib/…` 失败，因此不注册；其余不动。
- 检查：#83 达成（HOME unset 后不再读任何家目录路径）。
- #82：未达成（索引在场仍会改变产物）。
- 五条出处：不变（实现方式已把 HOME 固定为空，因此 A 不影响归一化态产物）。
- 评价：不足。#83 只是 #82 的一个子面；只做 A 等于承认检查可跨机不成立。

### 方案 B，推荐主选：`.cr` 声明优先 + 未引用不物化（use-driven 注册）

语义规则新增两条，取代现状的「导入即注册、SO_FN 覆盖」：

1. 只为被引用的名字物化：`res_imports` 阶段把索引解析到侧表，不 `str_intern`，不追加 `g_syms`；仅当 `find_gsym`/`find_so_fn` 在主表未命中且侧表命中时，才当场物化。
2. `.cr` 声明优先：若该名字已有来自 `.cr` 的 `SYM_FN` 条目，则不引入 SO_FN，消除 1.3 的覆盖。

效果：

- `generics_test`：`print_int`/`println_int` 从未被引用，因此不物化，产物等于无索引态；`print`/`println` 已被 `.cr` 声明，规则 2 使其仍走 `SYM_FN`，产物也等于无索引态。因此检查1（两个 `$HOME` 逐字节相同）在 canary 上成立。
- `print_int` 用例（E3）：主表未命中、侧表命中，因此物化，仍可编译，关键面得以保留。
- 改动面：`module.cr`（新增侧表，`reg_so_funcs` 改为解析入侧表，新增 `so_materialize`）、`checker.cr`（`find_gsym`/`find_so_fn` 各加一次侧表回退；`check_all:3870-3911` 的保全块可按需保留或简化）、`interp.cr`（若也走 `find_gsym` 则自动受益）。
- 风险：1 物化时机从导入期变为首次查找期，符号索引赋值时点改变，须确认没有「早期必须存在」的假设（`checker.cr:826` 的注释「SO_FN 在 SYM_FN 之前」是现状描述，改造后须同步修改注释或删除该假设）；2 规则 2 改变 `print` 的解析路径（SO_FN 改为 SYM_FN），虽然 E1 证明 ELF 无差异，仍须全语料实证；3 侧表命中判定要给大小写和命名空间留约定。
- 检查：见第 3 节（实现方式兼容）和「canary 五条不变」（见第 4 节零影响）。
- 对五条出处：预期全部不变（归一化态本来就没有索引，因此物化不发生，产物相同）。

### 方案 C，治本的正交项：元数据源从 `$HOME` 迁入仓库（项目内声明）

- 内容：把 `.so` 扩展索引从 `$HOME/.core/lib/<mod>/index` 改为仓库内可达位置（如 `Core.toml` 的 `[ext]` 段或 `ext/<mod>.index`），`$HOME` 路径可保留为后备或移除。
- 效果：索引成为构建输入的一部分，随提交走，因此跨机可复现对全体程序成立（含 E3 类）。
- 改动面：中等（新配置读取面、搜索顺序、文档、可能的测试夹具）。
- 与 B 的关系：正交。B 管「未引用条目不进产物」，C 管「被引用时元数据从哪来、是否随源走」。
- 风险：为兼容旧行为需决定优先级（仓库优先还是 HOME 优先），须取裁。

### 方案 D，严格 (b)：元数据完全不进产物

- 内容：SO_FN 元数据只留在内存侧表，永不写 `g_syms` 或 STR；后端不受影响（1.2 节已证零消费）。
- 效果：产物严格等于 `f(源 + CLI)`，检查1无条件成立。
- 代价：`.ccr` 丢失「该调用指向 .so extern」的已记录信息（当前无消费者，但属于信息面收缩）；`checker.cr:3870-3911` 的保全块可整块删除（净简化）。
- 评价：作为备选。若维护者判定「实现方式应只描述程序」是硬原则，则取 D；若判定「extern 来源属于语义信息，值得记录」，则取 B。

## 5. 零影响论证（实现方式归一化前提下，五条是否应保持不变）

- 实现方式采集时 `HOME` 恒为受控空目录，因此索引不存在，方案 B 的侧表为空，「物化」永不发生，产物与当前归一化态逐字节相同，因此五条出处预期不变（J6）。
- B 的规则 2（`.cr` 优先）在无索引时是空操作（没有 SO_FN 条目可覆盖），因此同样零影响。
- 因此五条若变化，就是回归（B 不应触及无索引路径）。例外：若取裁 D，且 D 选择「连已引用的 extern 也不记录」，则无索引态也没有 SO_FN 条目，该态产物本来就与今天相同，因此仍不变。D 只在有索引态改变产物。四案在实现方式面均零影响，五条均应不变。
