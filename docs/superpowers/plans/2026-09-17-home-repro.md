## 1. 现状根因（`file:line` 逐条实读；行号为 develop `66eb9589` 实况）

### 1.1 完整影响链（`$HOME` → 产物字节）

```
import io 解析（module.cr:504-535）
  └─ :522-530   home_dir := get_env("HOME");  [为空 ⇒ 硬编码 "/home/DslsDZC"（module.cr:526）]
                so_idx_path := home_dir + "/.core/lib/" + fs_path + "/index"
                so_idx := read_file(so_idx_path)
                if str_len(so_idx) > 0 { reg_so_funcs(so_idx, fs_path) }   ← 唯一的读点
        └─ reg_so_funcs（module.cr:226-395）逐行解析 `name: params [-> ret] [, tags]`
              ├─ module.cr:385  fni := str_intern(func_name)      ⇒ **STR 段**新增串
              └─ module.cr:387-393  追加 SYM 条目：
                     sym_set_kind(SYM_SO_FN) / sym_set_type(tag_flags) / sym_set_node(type_encoding)
                     g_sym_count++                                 ⇒ **SYM 段**新增条目
```
⇒ `g_syms` 条目数变化会**平移后续所有符号索引**，而 NOD（`IR_CALL.src3` = callee 名索引）、
IFACE 等都引用这些索引 ⇒ **扰动扩散到 4 个段**（与 V2b 实测「同尺寸异 sha，差异散布
STR/SYM/NOD/IFACE」一致）。

### 1.2 消费点（**全部在前端**；后端零消费 —— 实核）

| 消费点 | `file:line` | 读什么 |
|---|---|---|
| 调用返回型推断 | `src/compiler/ir_gen.cr:753-765` | `find_gsym` 命中 `SYM_SO_FN` ⇒ 用 `sym_node` 的类型编码解出返回型 |
| 调用类型检查 | `src/compiler/checker.cr:2796-2812` | 同上 + `sym_type` 的 tag_flags |
| 符号查找 | `src/compiler/checker.cr:815-823` | `find_gsym`：**反向扫描**，命中最后一个 `kind ∈ [SYM_FN, SYM_SO_FN]` |

| 跨 reset 保全 | `src/compiler/checker.cr:3870-3911` | `check_all()` 开头把 `SYM_SO_FN` **搬进临时数组**，`g_sym_count=0` 后**再追加回去** |

### 1.3 优先级实核：索引条目**覆盖**同名 `.cr` 声明

`find_gsym`（`:816`）**反向**扫描；而 `check_all` 在 `collect_decls()` **之后**把 SO_FN 条目
**追加**到表尾（`:3899-3911`）⇒ 同名时**后出现的 SO_FN 先被命中** ⇒ `print`/`println`
（`src/stdlib/io.cr:6,12` 有声明，索引里也有）**在索引在场时解析为 SO_FN**。

### 1.4 本轮新增实核（3 个实验，全部在 `core-modws` 用本区 `build/corec` 跑）

| # | 实验 | 结果 | 含义 |
|---|---|---|---|
| **E1** | `generics_test.cr --static` 在 `HOME=空` vs `HOME=含 io/index` 下的 **ELF** | **逐字节同**（37582B · `f1f78683…` 两侧一致） | 索引对**语义面（发射）零影响** |
| **E2** | 同上两态的 **`.ccr`** | 142908 `a1f7b99c…` vs 142936 `704316c8…`（+28B） | 影响**只在载体面** |
| **E3** | `import io` + 调用 **`print_int(42)`**（`io.cr` **未声明**的名字） | 无索引 ⇒ **rc=1 `error[N06] Undefined function 'print_int'`**、无 `.ccr`；有索引 ⇒ **rc=0**、产出 119673B `.ccr` | **索引对「索引独有名字」是承重输入** |
| E4（前批） | 良性索引（只列 `print`/`read_file`，都已在 `io.cr`） | **尺寸同、sha 变**，差异散布 STR/SYM/NOD/IFACE 四段 | 触发因是**条目在场**本身（覆盖 + 索引平移），不是新名数量 |

⇒ **两种情形性质不同，必须分开裁**：
- **不引用索引独有名字**的语料（**canary 五条全属此类**：`ptr_arith` 零 import；`generics_test`
  只调 `print`/`println`/`int_str`/`str_len`，均非索引独有）⇒ 索引是**纯载体泄漏**（E1/E2）。
- **引用索引独有名字**的语料 ⇒ 索引**承重**（E3：无它编不过）⇒ 该类程序的产物**天然**
  依赖索引内容，跨机可复现性**不可得**（除非把元数据源移入仓库，见方案 C）。

## 2. 候选方案（逐案：改动面 / 风险 / 判据 / 对 canary 与五条真源的影响）

> 五条真源 = `tools/baseline/canary_values.tsv`（`canary_elf` + `.ccr` 四条）。

### 方案 A —— **声音最小**：只删硬编码兜底（#83），#82 登记为「已知不可复现」

- 改动：`module.cr:526` 删 `if str_len(home_dir)==0 { home_dir="/home/DslsDZC"; }`（HOME 空 ⇒
  直接查 `/…/.core/lib/…` 失败 ⇒ 不注册）；其余不动。
- 判据：#83 达成（HOME unset ⇒ 不再读任何家目录路径 ✓）。
- #82：**未达成**（索引在场仍改产物）。
- 五条真源：**不变**（载体已把 HOME 钉空 ⇒ A 不影响归一化态产物）。
- 评价：**不足**。#83 只是 #82 的一个子面；只做 A 等于承认判据可跨机不成立。

### 方案 B —— **推荐主选**：`.cr` 声明优先 + **未引用不物化**（use-driven 注册）

**语义规则（新增两条，取代现状的「导入即注册、SO_FN 覆盖」）**：
1. **只为被引用的名字物化**：`res_imports` 阶段把索引解析到**侧表**（不 `str_intern`、不追加
   `g_syms`）；仅当 `find_gsym`/`find_so_fn` 在**主表未命中**且**侧表命中**时才当场物化。
2. **`.cr` 声明优先**：若该名字已有来自 `.cr` 的 `SYM_FN` 条目 ⇒ **不引入 SO_FN**（消除 1.3 的覆盖）。

- 效果：
  - `generics_test`：`print_int`/`println_int` **从未被引用** ⇒ 不物化 ⇒ 产物 = 无索引态 ✓；
    `print`/`println` 已被 `.cr` 声明 ⇒ 规则 2 使其仍走 `SYM_FN` ⇒ 产物 = 无索引态 ✓
    ⇒ **判据①（两个 `$HOME` 逐字节同）在 canary 上成立**。
  - `print_int` 用例（E3）：主表未命中 + 侧表命中 ⇒ 物化 ⇒ **仍可编译** ✓（保住承重面）。
- 改动面：`module.cr`（新增侧表 + `reg_so_funcs` 改为「解析入侧表」+ 新增 `so_materialize`）·
  `checker.cr`（`find_gsym`/`find_so_fn` 各加一次侧表回退；`check_all:3870-3911` 的保全块
  可按需保留/简化）· `interp.cr`（若也走 `find_gsym` 则自动受益）。
- 风险：① 物化时机从「导入期」变为「首次查找期」⇒ 符号索引赋值时点改变，须确认无「早期
  必须存在」的假设（`checker.cr:826` 的注释「SO_FN 在 SYM_FN 之前」是**现状描述**，
  改造后须同步改注释/删除该假设）；② 规则 2 改变 `print` 的解析路径（SO_FN → SYM_FN），
  虽 E1 证明 ELF 无差，仍须全语料实证；③ 侧表命中判定要给「大小写/命名空间」留口径。
- 判据：见 §3（载体兼容）+「canary 五条不变」（见 §4 零足迹）。
- 对五条真源：**预期全部不变**（归一化态本就无索引 ⇒ 物化不发生 ⇒ 产物同）。

### 方案 C —— **治本的正交项**：元数据源从 `$HOME` 迁入仓库（项目内声明）

- 内容：把 `.so` 扩展索引从 `$HOME/.core/lib/<mod>/index` 改为**仓库内可达位置**
  （如 `Core.toml` 的 `[ext]` 段 / `ext/<mod>.index`），`$HOME` 路径可保留为**后备**或**移除**。
- 效果：索引成为**构建输入的一部分**（随提交走）⇒ 跨机可复现**对全体程序成立**（含 E3 类）。
- 改动面：中（新配置读取面 + 搜索顺序 + 文档 + 可能的测试夹具）。
- 与 B 的关系：**正交**。B 管「未引用条目不进产物」，C 管「被引用时元数据从哪来、是否随源走」。
- 风险：为兼容旧行为需决定优先级（仓库 > HOME？）——**须取裁**。

### 方案 D —— **严格 (b)**：元数据完全不进产物

- 内容：SO_FN 元数据只留在内存侧表，**永不**写 `g_syms`/STR；后端不受影响（§1.2 已证零消费）。
- 效果：产物严格 = `f(源 + CLI)`，判据①**无条件成立**。
- 代价：`.ccr` 丢失「该调用指向 .so extern」的**已记录信息**（当前无消费者，但属**信息面收缩**）；
  `checker.cr:3870-3911` 的保全块可整块删除（净简化）。
- 评价：**作为备选**。若维护者认为「载体应只描述程序」是硬原则 ⇒ 取 D；若认为「extern 来源
  属语义信息，值得留痕」⇒ 取 B。

## 5. 零足迹论证（**载体归一化前提下，五条是否应保持不变**）

- 载体采集时 `HOME` 恒为**受控空目录** ⇒ 索引**不存在** ⇒ 方案 B 的侧表为空 ⇒
  「物化」永不发生 ⇒ **产物与当前归一化态逐字节同** ⇒ **五条真源预期不变**（J6）。
- B 的规则 2（`.cr` 优先）在**无索引**时是**恒真空操作**（没有 SO_FN 条目可覆盖）⇒ 同样零足迹。
- ⇒ **五条若变 ⇒ 是回归**（B 不应触及无索引路径）。**例外**：若取裁 **D** 且 D 选择「连已引用
  的 extern 也不留痕」，则无索引态**也无 SO_FN 条目** ⇒ 该态产物本就与今天相同 ⇒ **仍不变**。
  （D 只在「有索引」态改变产物。）⇒ **四案在载体面均零足迹，五条均应不变**。

**附带发现（本批侦查挖出，建议独立登记，本批不修）**：
- **F1 · `checker.cr:3872-3874` 临时数组容量硬编码 128 且写入无界**：
  `so_names/types/nodes := alloc(128*8)`，随后 `loop { … w64(so_names, so_count*8, …) }` **无上界检查**
  ⇒ 索引行数 **>128** 时**越界写堆**（静默内存破坏）。触发条件 = 某模块的索引 >128 行。
  判据（修复时）：索引 >128 行 ⇒ 要么扩容要么显式拒绝（不得静默越界）。
- **F2 · 索引与 stdlib 命名漂移**：`src/stdlib/io.cr` 声明 `print_i`/`println_i`，而索引写
  `print_int`/`println_int` ⇒ 索引描述的是**另一套命名**（无人引用的「幽灵条目」正是 +28B 的来源）。
  建议在 C（迁入仓库）时同步清理，或登记为「扩展索引需与 stdlib 对齐」的纪律。
