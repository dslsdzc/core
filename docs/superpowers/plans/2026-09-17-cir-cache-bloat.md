### 1.3 「全图边表」里到底有多少是跨函数的（**决定性实测**）

方法：v18 节点记录含 `first_edge/edge_count`，前插链可从盘面**完全还原**；链上边的 `from` = 该节点的
**绝对 id** ⇒ 可离线推断**本函数节点 id 区间** `[base, base+node_count)`，再逐边分类。4 档实测：

| 快照 | base | 节点 | 全图边 | **本函数边（intra）** | 跨入（from 在外/to 在内） | 跨出 | 其它函数边 |
|---|---|---|---|---|---|---|---|
| `addr_taken_add` | 113,893 | 34 | 73,206 | **16** | **0** | **0** | 73,190 |
| `pass_cse` | 157,614 | 551 | 101,562 | **379** | **0** | **0** | 101,183 |
| `load_cir_cache` | 155,123 | 962 | 100,289 | **786** | **0** | **0** | 99,503 |
| `type_selftest_run` | 76,462 | 17,501 | 60,467 | **12,822** | **0** | **0** | 47,645 |

**两条独立核对一致**：`Σ node.edge_count` = 16 / 379 / 786（本实例另一次逐文件求和）= 上表 intra 列；
**全 1,618 档复核**：`Σ node.edge_count ≡ intra` **0 档不符**、`bad local order` **0 档** ⇒ 前插链可逐档
从盘面完全还原（推理方法本身被全档验证）。

**全档扩展（1,618 档实跑）**：跨入 **1 条**（唯一命中档 = `tests_suite_at_test.cr::test_inline_hint.cir`，
in=1/out=0）、跨出 **0 条**、kind≠0 边 **0 条**、含任何跨边界边的档 = **1/1,618**。

**⇒ 修法判据（由实测逼出的两条硬约束）**：
1. **收窄必须用「边范围」而非「from 落在本函数节点区间」过滤**——写侧 `df_begin_func` 记
   `g_df_func_edge_start := g_df_edge_count`，本函数边 = `[edge_start, g_df_edge_count)`
   （**O(1)**，且那 1 条例外边天然被收进来；若按 from 区间过滤会**丢边**）。
2. **相对 id 必须是有符号的**：该例外的 `rel_from < 0`（源节点在更早的函数里）⇒ 装载期映射为
   `base_node + rel_from` 仍指向正确的相对位置；**只有这一形态**（快照内出现越界 rel）需要额外见证——
   见 §3 候选 ① 的「条件见证」。

| 基线见证（**放尾部 trailer**） | **尾部 +16B**（`off = dlen − 16`）：`var_start`（写者保存时点的 `g_ir_var_count`，**恒校验**）+ `node_start`（写者保存时点的 `g_df_node_count`，**条件见证**，见下）。**为什么放尾部而不是头部**：头部一改，两个测试解析器的硬编码偏移（`name_len@40` / `name@48` / var 24B / node 64B）**全部失锁**；放尾部 ⇒ **零偏移改动、重锁面最小**（与裁-4「契约风险最小」同精神）。装载期**先读 trailer 校验**（`dlen` 已由 `cir_read_snapshot` 给出）**再做**破坏性恢复。var 是唯一无法低成本重映射的域（var 下标出现在节点 `dest`/`s1..s3` 与指令 `s1..s3`，按 opcode 分类重映射 = 高风险大改）。**⚠ 新增入口面的硬边界（维护者要求，关键）**：**`dlen ≥ 头长 + 16` 才允许读 trailer**，否则 **fail-closed miss**；trailer 内容不符 ⇒ **miss**，**不是**「读垃圾继续」——本入口面与 `load_cir_cache` 头注（`:391`）记的「暖态 rc=139」**同类**：**截断/异常文件必须落进 miss，不得落进未定义行为**（判据 = P4，§5.2） |
| 装载 | 逐函数：`base_node := g_df_node_count` ⇒ 节点照写（`base_node + rel`）⇒ **对每条盘边调 `df_add_edge_kind(base_node + rel_from, base_node + rel_to, kind)`**（与冷路径**同一函数**、同一前插序 ⇒ 链序逐条同态）⇒ **三条 fail-closed 校验**：① `g_ir_var_count != var_start` ⇒ `-1`；② 重建出的逐节点计数 ≠ 盘 `edge_count` ⇒ `-1`；③ **仅当快照含越界 rel**（`rel_from < 0 \|\| rel_to < 0 \|\| rel_to >= node_count`——全档实测只 1/1,618 档命中此形态）时追加 `g_df_node_count != node_start` ⇒ `-1`（**条件见证**：常态下节点基线平移**不**影响相对 id 的正确性，故不无条件校验——否则每次编辑都会让「被编辑函数之后的所有条目」集体 miss，缓存失去意义） |
| 盘面影响 | 头 48B 与节点 64B **均不变**、边 32→24B + 条数 O(E)→O(own)、尾部 +16B ⇒ 仍**格式换代必 bump**（§6 撞面） |
| 装载侧新索引 | 无需新索引：节点基线 = 装载时点 `g_df_node_count`，边基线 = `g_df_edge_count`（`df_add_edge_kind` 自增） |
| 正确性风险 | **低**。边面**结构性免疫**基线平移（相对 id ⇒ 部分 rebuild 也正确，R3 闭合）；唯一保留的镜像依赖 = var 域（恒 fail-closed：错 ⇒ miss 而非静默）+ 越界 rel 形态（条件见证）。风险点：① 链重建的**保真性**已**全档实测**（§1.3：`Σ edge_count ≡ intra` 0 档不符；前插序重放 = 冷路径同一函数 ⇒ 链序同态），且盘 `edge_count` 保留为逐节点见证；② 那 1 条例外边（`rel_from < 0`）是**唯一**需要见证的形态，落在**条件见证**下；③ state 链（kind=1）**不在写时点**（`df_state_finalize` 在全部 save 之后 ⇒ v15 契约不变，全档实测 kind≠0 边 = 0）；④ 尾部 trailer 的读取**先于**恢复（否则恢复失败时已污染全局数组——装载期顺序是本条的实现要点） |

### 候选 ②（**条件项／T3**）：① + 字符串段 **delta 化**

- 只写**自上一快照以来新增**的串（`str_base = 写者保存时点 `g_ir_str_const_count``）；装载侧逐条
  `ni := str_intern(s); if ni != 盘上记的名字索引 ⇒ return -1`（**逐条 verify**，同时消灭今天的
  静默索引漂移面）。
- 收益：消灭**最后一个 O(单元) 项**（实测 0.6–1.3%/条 × 1,618 条 ≈ 数十 MB = 修后体积的**主要残余**）。
- 风险：**命中率对「编辑即失配」敏感**——前端在 parse 期驻留串 ⇒ 源改动可能整体平移索引 ⇒ 级联 miss
  （正确性无损，性能面退化）。⇒ **列为条件项**：T2 落地后用 T1 的墙钟/体积数据取裁（裁-3）。

### 候选 ③：表外置（单元级共享表文件 + 函数快照只存索引）——**不推荐**

改动面更大（新文件生命周期/失效/并发写/GC 均为新面），收益与 ② 相当（边已收窄后字符串本是唯一大项），
且引入**跨文件一致性**这一新静默面（表文件与快照的代际错配）。仅当 ② 的命中率实证崩坏时重估。

### 候选 ④（兜底）：退掉/默认关缓存——**不推荐为主选，保留为停条件出口**

证据两面：**支持**——暖态卡点（**条件式**：在本机当时状态下 >254s 未完成 vs 冷 231s；因果层 = 缓存规模，

零覆盖；缓存面已消耗多批正确性工作（v12–v18、#2026-09-10-1、#2026-09-15-5）。
**反对**——铁律 1「不许绕过问题」（bump/删除是绕过根因）；缓存意图（增量构建）真实有价值，修后应转正收益；
本仓已有「关缓存」**兜底先例**（`g_optrep_on`，`main.cr:488-493`）⇒ 它是**兜底**不是**修法**。
⇒ **用途 = T2 的性能判据不达标（暖不显著快于冷）时的取裁出口**（裁-5）。

### 推荐（两步走）

1. **T2 = 候选 ①（**裁-1 = 取向 ①**，无条件）**：改动集中（`cir_cache.cr` 两个函数 + `dataflow.cr`/`ast.cr`/

   trailer**（零偏移改动 ⇒ 重锁面最小）。

## 11. 方法论三条（**可被判据引用**；2026-09-17 批 7 收官后写进文档，**追加不重写**）

> 形式 = **结论** + **它防止的具体事故** + **何时用它**。三条同属一个主题：
> **判据网不只校验实现，也在修正实现——包括修正流程**。
> 写进文档缘起：这三条原先只活在 PR #104 的描述里，而**PR 描述是仓库外的信道**；方法论必须落在提交里（本仓先例 = spec-grammar §17）。

### 方法论-1：判据网**修正实现**（既有判据抓出新实现的过严）
- **结论**：新实现引入的严格性必须与**既有契约**对齐；既有判据网报红时，**先按「谁破坏了既有契约」定性**，不得先改判据。
- **防止的事故**：批 7 首版把 `.cir` trailer 定位在 `dlen−16` 并要求载荷「**恰好**」铺到 trailer 前 ⇒ 破坏「装载**容忍条目尾随字节**」的既有契约——既有套件的断言（`tests/selfhost/test_cir_warm_path.py` **D5**：补零条目**仍须命中**）当场红。修法 = trailer 定位于**结构扫描终点**（`p + 16 <= dlen`）、容忍尾随字节，**截断仍 fail-closed**。
- **何时用它**：给**已存在的装载/解析/格式面**加校验、动语义边界或容忍度时（判据先跑既有套件，再谈新增判据）。

### 方法论-2：判据网**修正流程**（本地判据前移到「推前」）
- **结论**：**凡改 `TODO.md` / 格式面 / 既有权衡约定 ⇒ 推前先跑对应本地判据**；且「本地判据绿」的复核点必须落在**提交**（`jj file show -r @ <file>`），不是工作副本。
- **防止的事故**：批 7 首推 PR #104 后 `bootstrap-tests` **6 s 红**——解 `TODO.md` 冲突时把 jj 的 diff 残留标记（`+| …` / `+### …`）拼回正文 ⇒ **条目标题被前缀污染** ⇒ `tests/harness/test_todo_id_migration.py` 的 **J2「无悬空」报 5 处悬空**。修法 = **剥前缀**（16 行）+ **推前本地跑 J1–J5**。
- **何时用它**：每次 rebase 解 `TODO.md` 冲突之后（批 7 两次踩到）· 任何**批量文本改写**之后 · 推 PR 前的最后一道自检。

### 方法论-3：**本地绿 ≠ 内容在提交里**（发布前以远端判据为准）
- **结论**：本地判据读**工作副本**，CI 读**推送出去的提交**；两者可以分离。**推送后以 CI 判据为准**，本地绿只作预警。
- **防止的事故**：① 同族旁证（批 6）：内容收敛后本地判据全绿，随后 `jj edit`/bookmark 操作把合成内容从**尖端提交**带走 ⇒ **尖端丢内容**，抓住它的是 **CI**；② 批 7 同族再现：`jj rebase` 撞上**已合入的同段内容**（#107 已进 develop）时产生「重复内容」冲突块——若照原样重推，等于**回退已合入的语义**。处置 = 删冲突书签 → abandon 冲突提交 → **在 develop 上重建 delta** → 推前 `jj bookmark list` 实查书签存在。
- **何时用它**：任何「大内容收敛 / rebase / bookmark 迁移」之后，以及每次推送前的最终自检。
