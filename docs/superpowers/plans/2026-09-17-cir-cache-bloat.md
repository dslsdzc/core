### 1.3 「全图边表」里到底有多少是跨函数的（决定性实测）

方法：v18 节点记录含 `first_edge/edge_count`，前插链可从盘面完全还原；链上边的 `from` = 该节点的
绝对 id，因此可离线推断本函数节点 id 区间 `[base, base+node_count)`，再逐边分类。4 档实测：

| 快照 | base | 节点 | 全图边 | 本函数边（intra） | 跨入（from 在外/to 在内） | 跨出 | 其它函数边 |
|---|---|---|---|---|---|---|---|
| `addr_taken_add` | 113,893 | 34 | 73,206 | 16 | 0 | 0 | 73,190 |
| `pass_cse` | 157,614 | 551 | 101,562 | 379 | 0 | 0 | 101,183 |
| `load_cir_cache` | 155,123 | 962 | 100,289 | 786 | 0 | 0 | 99,503 |
| `type_selftest_run` | 76,462 | 17,501 | 60,467 | 12,822 | 0 | 0 | 47,645 |

两条独立核对一致：`Σ node.edge_count` = 16 / 379 / 786（本实例另一次逐文件求和）= 上表 intra 列；
全 1,618 档复核：`Σ node.edge_count ≡ intra` 0 档不符、`bad local order` 0 档，因此前插链可逐档
从盘面完全还原（推理方法本身被全档验证）。

全档扩展（1,618 档实际运行）：跨入 1 条（唯一命中档 = `tests_suite_at_test.cr::test_inline_hint.cir`，
in=1/out=0）、跨出 0 条、kind≠0 边 0 条、含任何跨边界边的档 = 1/1,618。

因此修法检查（由实测得出的两条硬约束）：
1. 收窄必须用「边范围」而非「from 落在本函数节点区间」过滤，写侧 `df_begin_func` 记
   `g_df_func_edge_start := g_df_edge_count`，本函数边 = `[edge_start, g_df_edge_count)`
   （O(1)，且那 1 条例外边天然被收进来；若按 from 区间过滤会丢边）。
2. 相对 id 必须是有符号的：该例外的 `rel_from < 0`（源节点在更早的函数里），因此装载期映射为
   `base_node + rel_from` 仍指向正确的相对位置；只有这一形态（快照内出现越界 rel）需要额外见证，
   见第 3 节候选 1 的「条件见证」。

### 1.5 条目2「有缓存状态阻塞点」：候选机制 + 判别实验（设计前侦查项；本轮未运行任何重型实验）

现象（批 6 实测；条件式）：`corec ccr src/compiler/main.cr` 有缓存状态第二次运行 `timeout 900` 截断（进度停 35/74）·
`State: D (disk sleep)` · %CPU 1–3% · rchar 44MB（另一轮 169MB）· RSS 219MB；同轮空缓存状态运行 231s 写
1.4GB / 1011 条。对照臂（同二进制/命令/机器/负载，只变缓存规模）：`ptr_arith.cr` 冷 1s · 缓存 15 条/352K ·
暖 0s。
机器状态快照（同一时点）：swap 5838/12127 MB · loadavg 14.7/16.2/17.2 · `vmstat b=12` · `wa 15%到80%` ·
有效磁盘吞吐 ~1.8MB/s（批 5：19 reads/10s、~937KB/read）· 常驻大户 = 4 个 bun 进程 ~2.4GB RSS。

形态判读：%CPU 1–3% + D 态 = 阻塞在内核 I/O 等待、不是在算，因此优先查「大块读写 syscall / 单次尺寸 /
页缓存压力 / 缺页」，不是算术热点。

I/O 面清单（静态实读，非推测）：

| 面 | 每条目 | 定位点 |

## 2. 根因链（分两个条目：膨胀 / 阻塞点，可能同源、可能不同源，分别用证据说话）

### 2.A 条目1：膨胀（体积 / 写读总量；机制已定位）

### 候选 2（条件项／T3）：1 + 字符串段 delta 化

- 只写自上一快照以来新增的串（`str_base = 写者保存时点 `g_ir_str_const_count``）；装载侧逐条
  `ni := str_intern(s); if ni != 盘上记的名字索引 则 return -1`（逐条 verify，同时消灭今天的
  不报错地索引变化面）。

### 候选 3：表外置（单元级共享表文件 + 函数快照只存索引），不推荐

改动面更大（新文件生命周期/失效/并发写/GC 均为新面），收益与 2 相当（边已收窄后字符串本是唯一大项），
