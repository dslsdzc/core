## §0 根因（一句话 + `file:line`）

> **`src/compiler/checker.cr` 的 `infer_expr` 在「被调已解析为 Core `fn`」时提前 `return sym_type(si)`（`:2817`），而「推实参（for side effects）」循环在函数尾（`:2833-2839`）——只在 `func_ni < 0` 时可达 ⇒ 对任何**有名**被调都是死码 ⇒ 已解析直调的实参表达式从不被推断。**

**两种表现（本批两条腿都得修）**：

| 表现 | 机理 | 现状 |
|---|---|---|
| **响亮面 = SIGSEGV 139** | 实参位的内层调用若是 `EXPR_FIELD` 被调（方法 / 模块限定），其 `ast_data` 只能由 checker 的模块/方法分支回填（`:2584`/`:2645`）⇒ 从没回填 ⇒ 保持 parser 初值 **0** ⇒ `istr_get(0)` = 文件首个 interned 串（`"import"`）⇒ 后端查不到 ⇒ 外部位重定位 ⇒ 139 | 9 例（`test_arg_inference_gap.py` 腿 A） |
| **静默面 = 零诊断** | 实参里的未定义函数/变量、常量越界**完全不查** ⇒ `check` rc=0（运行时同样 139） | 1 例（腿 B：`g(nosuchfn(1))`） |

**旁证（对照组的价值）**：外层若是**模块限定/方法调用**，`checker.cr:2623` 另有一份「推实参」循环 ⇒ 那些形态**当前即正确**（可作 oracle，见 §1）。⇒ 修法很可能是**接线**而非造机制。

## §1 放大面预判（**本批最大风险 = 行为放大**）

**oracle 法（零构建、可复用）**：外层用**模块限定调用**（当前即推实参）⇒ 它报出的诊断 = 修后直调将新出现的诊断。

| 实参里的坏形态 | 外层=模块调用（**推实参**） | 外层=已解析直调（**不推**） | 修后新出现 |
|---|---|---|---|
| `nosuchfn(1)`（未定义函数） | **`error[N06]`** | 无 | **N06** |
| `undefvar`（未定义变量） | **`error[N01]`** | 无 | **N01** |
| `arr[9]`（`arr : [int;2]`，常量越界） | **`error[R02]`** | 无 | **R02** |
| `s.nofield`（未知字段） | 无 | 无 | — |
| `s.nomethod()`（未知方法） | 无 | 无 | — |
| `1 + "s"`（类型不符） | 无 | 无 | — |
| `g0(1)`（实参个数不符） | 无 | 无 | — |
| `s.m("x")`（方法实参类型不符） | 无 | 无 | — |

**结论（预判）**：放大面**限于 3 个族**——**`N06`（未定义函数）· `N01`（未定义变量）· `R02`（常量越界索引）**。
⇒ 这三族**都是「代码本来就坏」的结构性错误**（不是风格/精度类），**因此「新增诊断 = 误报」的先验概率低**；但仍**必须逐条归因**（腿 C）。

**尚不能预判的部分（T1 实测回填）**：
1. **74 档语料 + 29 档行为探针 + `check src/compiler`（自源）** 里有多少存量命中这三族 ⇒ T1 逐档实测；
2. **泛型实例化副作用**：实参位若含泛型调用，实参被推断后可能**新增实例** ⇒ 可能改 `.cir`/`.ccr`（当前 `ieq(idf(7), 7)` 绿说明实例化另有路径，但**未逐一核**）⇒ 列入 T1 观察。
3. **第三类诊断**是否存在（本 oracle 只覆盖 8 形态）⇒ T1 用「放大面扫面」补齐（见 §4 T1）。

- **判据**：腿 A 各例由 139 → **rc=1 + 定位诊断**（若 (a) 已修则本护栏**无触发面**，其价值 = 防未来同类回归）。
