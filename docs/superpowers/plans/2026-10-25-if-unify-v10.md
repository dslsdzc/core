# if 统一到 CASE（bool-only + IR_MATCH）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `if` 条件收紧为 `bool`-only，并让 `if` 走 v10 的统一决策节点 `IR_MATCH` + 24B CASE；`while` 等其余条件分支暂留 `IR_BRANCH`。

**Architecture:** 复用现有 `IR_MATCH`/CASE 语义层与后端。`if` 编码为一行 `VALUE(0) -> else/merge` 加一行 `DEFAULT -> then`，保持 then-fallthrough 布局；bool-only 下这等价于 v9.1 的 `{1 -> then}` + default else。后端对“单 VALUE(0) + 紧邻 DEFAULT”发射 `test`/`je`，避免通用线性路径的额外 `jmp`。

**Tech Stack:** Core 自举编译器（`.cr`）、Python 测试 harness、jj、x86_64 后端、`.ccr` v10 CASE。

**Spec:** `docs/superpowers/specs/2026-10-23-pattern-matching-ir-design.md`（v9.1 统一分支节点；v10 现行 CASE 模型）

## Global Constraints

- `if` 条件只允许 `bool`；`while` 已是 bool-only，二者共用一条 `IP_COND` 规则。
- 只改 `if`；`while`、`for`、`&&`/`||`、边界检查、optional 表示位分派继续使用 `IR_BRANCH`。
- `.ccr` v10 的 CASE 24B 物理布局不变；不 bump `CIR_CACHE_VER`（缓存键已含编译器身份哈希）。
- 所有工作在 `/home/DslsDZC/data/tmp/opencode/if-unify-ws`，不改主工作区的 import-graph WIP。
- canary 重锁前必须看到 D1 两次构建逐字节相同；新增值必须留归因。
- 提交与文档用中文。

## Review Focus

- `if` / `else if` / 嵌套 `if` / 空分支。
- `if` 作为表达式赋值，而不是仅作为语句。
- 条件为 bool 变量、字面量、比较、`&&`/`||`。
- `if` 位于循环、递归、arena/region 内。
- warm CIR cache 复用后 `IR_MATCH` 与 CASE 仍正确。
- interp 与 ELF 对同一 `if` 程序的退出码一致。
