## 1. 机理

### 1.1 根因链（全部【读码】，行号 = develop 3e461edd）

1. **实例创建只深克隆函数体**。`monomorph.cr:600`：
   `if k == EXPR_FN { d2 := gen_clone_tree(d); n := ast_alloc(k, a, b, c, iv, tv, d2, ln, cl); ... }`
   —— `EXPR_FN` 的 `a`=名、`b`=首形参、`c`=形参数 **原样复制**；只有 `d`（函数体）走克隆。
   ⇒ **实例与声明共用同一个形参节点链**。
2. **`EXPR_PARAM` 的克隆分支存在但走不到**：`monomorph.cr:604`
   `if k == EXPR_PARAM { d2 := gen_clone_tree(d); n := ast_alloc(k, a, b, c, iv, tv, d2, ln, cl); ... }`
   —— 克隆 `d`（类型节点）的能力已有；但 `EXPR_FN` 分支从不访问 `b`，该分支对**实例的形参**恒不可达。
3. **形参序言按「声明面节点」定槽型**。`ir_gen.cr:3071-3081`：
   ```
   3071  param_type : ., mut = ast_type_val(pn);      // 泛型形参 = 0
   3072  if param_type < 0 { param_type = TI_INT; }   // ⇒ TI_INT（GP 类）
   3073  if param_type == TI_DEX { param_type = TI_DEX_S; }
   3080  else if dex_opt_type_node(ast_data(pn)) != 0 { param_type = TI_DEX_S; }
   3081  pvar := new_ir_var(pname, param_type);
   ```
   泛型形参 `t: T` 的节点 `ast_type_val` = 0 ⇒ **槽型恒 `TI_INT`**；`t: T?` 的 `dex_opt_type_node` 见下条 ⇒ 恒假。
4. **`dex_opt_type_node` 看不穿泛型形参**。`ir_gen.cr:1127-1134`：要求内层节点 `ast_kind(inner) == 0`；泛型形参引用是 `EXPR_IDENT`（kind ≠ 0）⇒ 对 `T?` 恒返回 0 ⇒ 声明面的 dex 门恒假。
5. **调用点对齐环按「声明面参数链」判门，且发生在实例重定向之前**。`ir_gen.cr:1964-2008`：
   `cfi := find_func(func_ni)`（= **声明**）→ 环门 `ir_gen.cr:1984-1985`：
   `if ast_type_val(cpn) == TI_DEX || (cfn_ext == 0 && dex_opt_type_node(ast_data(cpn)) != 0)`
   ⇒ 泛型形参两个子判据皆假（第 3/4 条同因）⇒ **不转换**。
   实例重定向在 `ir_gen.cr:2072-2077`（`spec_ni := gen_find_or_create_*` → `func_ni = fi_name(spec_ni)`），**在环之后**。
6. **ABI 分类由实参 var 的 IR 型决定，与被调形参槽型是两个独立面**。`callseq.cr:66-89`（`cs_args_dispatch`）：
   `pt := irv_type(fa + ai); if pt == TI_DEX { →XMM(fr_cnt) } else { →GP(ir_cnt) }`；栈参判定同规则（`callseq.cr:95-106`）。
   ⇒ 调用点按 `TI_DEX` 放 XMM，而被调侧（第 3 条）按 `TI_INT` 读 GP ⇒ **寄存器类失配**。
7. **`fi_param_type` 救不了场**：实例的形参型是**逐位抄声明**（`monomorph.cr:844-850`，`fi_set_param_type(new_fi, pi, fi_param_type(func_ni, pi))`）。
   【实测·本轮只读】全仓 grep：`fi_param_type(` 的**唯一读取点**就是这条拷贝自身（`monomorph.cr:849`）；其余全是 `fi_param_count`。
   ⇒ 后端 ABI 不读 FuncInfo 形参型（只读实参 var 型）⇒ 「把 FuncInfo 抄对」**不是**承重面。

**合起来**：实例的形参「类型」在三面各说各话——节点面（`ast_type_val` = 0）、类型行面（未解析）、FuncInfo 面（抄声明）。
调用链上唯一把两面拴在一起的是**调用点对齐环**（第 5 条），而它对泛型形参**恒不生效**。

## 2. 修法候选（≥2）与影响面矩阵

### 候选 A（推荐）：实例侧形参链具体化 + 调用点按实例签名对齐（A1 + A2 成对）

- **A1（被调面）**：在 `gen_create_instance`（`monomorph.cr:812-870`）克隆体之后，**同一趟**克隆声明形参链：
  逐形参克隆 `EXPR_PARAM`（复用 `monomorph.cr:604` 分支语义 ⇒ 类型节点经 `EXPR_IDENT`/`EXPR_OPTIONAL` 分支代入），
  组成新的参数 run，`ast_set_b(new_fn_node, <新首形参>)`（`c` 保持 = 形参数）。
  **必须同时重算 `param.type_val`**：现有 `EXPR_PARAM` 分支把 `tv` 原样拷贝 ⇒ 泛型形参的 `type_val` 仍是 0，
  §1.1-3 的槽型仍会是 `TI_INT`。做法对齐 parser 的写点（`parser.cr:1472-1476`：基类型时 `param.type_val` = 基类型码）。
- **A2（调用面）**：让调用点对齐环看到**实例**签名。两条实现路线（择一，**不得两都做**）：
  - A2a 后置第二遍：在重定向后（`ir_gen.cr:2076` 之后、IR_CALL 发射前）用实例 `cfi` **再跑一遍**对齐环；
    前提 = 环已抽成 cfi 参数化、幂等的函数（**这正是 `aaa054fe` 半成品的形态**，见 §7）。
  - A2b 前置换序：把泛型解析（`ir_gen.cr:2072`）**移到对齐环之前**，使 `cfi` 一开始就是实例。
    注意 `type_args` 的回落路径（`ir_gen.cr:2048-2066`）按实参 var 型取名字串，`TI_DEX`/`TI_DEX_S` **同映射 "dex"**
    ⇒ 换序对键无影响【读码】；但换序会改动**所有调用**的路径（面大、回归风险高）。

**A 的代价**：A1 增 AST 节点（每实例每形参 + 类型子树）；A2 触及调用发射前的公共段。**A1 单独无效**——调用点仍按声明面判门 ⇒ 实参仍以 `TI_DEX` 走 XMM（§1.1-5/6），失配只是**换向而不是消失**。

> **A2a 覆盖面限定（2026-09-18，见 §10）**：A2a 只覆盖**直调形**（`g(1,d)` ⇒ `EXPR_IDENT`）；
> **模块限定形**（`ml.g(1,d)` ⇒ `EXPR_FIELD` ∧ `is_module_call`）**不进重定向块** ⇒ **本批不覆盖**（显式登记，见 §10-1）。

### 候选 B：消费点按实例绑定解析（不改 AST）

- 实例创建时把**代入后的形参类型行**持久化（现表 `g_gen_instances` 只存 `(源 fi, 键串, 新 fi)` 三元组，`monomorph.cr:861-866` ⇒ 需新表或键串回解）；
- 新增单入口 helper（如 `inst_param_slot_ti(fi, pi)`），把 `ir_gen.cr:3071-3081` 与 `ir_gen.cr:1984-1985` **两处**都改为经它取值。

**B 的代价**：替换逻辑要在**没有 `gen_clone_tree` 代入机制**的情况下重写一遍（`T`、`T?`、`[T;N]`… 都要自己解），
且「两处读点都要改」——漏一处即静默类（正是本条要消灭的形态）。收益 = 零 AST 扰动。
**结论：机制上可行、工程上比 A 贵且更易漏；只在前者被实测证否时启用。**

### 候选 C：只修 dex 族（分层最小面）

只对「代入后为 `dex` 族」的形参做具体化（序言 + 对齐门）。面最小、最快拿到红→绿，但：
① 概念上只治 ABI 面的一半（`T=string` 等槽型仍错，语义保鲜哲学里 IR 型不忠实）；
② 若作为**终态**交付即是变通（铁律 1）。**定位 = 可选的落地分期（先 dex 族收口 → 再一般化），不是替代方案**；是否分期由维护者裁。

### A1 的实现陷阱（实施轮必须逐条核）

1. **参数 run 的扫描契约**：序言与对齐环都靠「`pn = pn+1` 起向前扫到下一个 `EXPR_PARAM`」（`ir_gen.cr:3116-3120`、`ir_gen.cr:2003-2007`）定位下一形参；
   克隆必须保持「形参节点与其类型子树相邻、且按形参顺序分配」，否则扫描会跨过形参或串位。
2. **dedup 交互**：`gen_dedup_add` 按**源节点**去重（`monomorph.cr:479-483`）。两个形参共享同一类型节点时，第二次克隆命中 dedup
   ⇒ 类型子树不会重复分配（扫描仍能落在下一个形参上，**但须实测确认**）。
3. **`type_val` 重算**（§2-A1）：不重算 = 槽型仍 `TI_INT`，整个修复白做——**这是最易漏的一步**。
4. **`ast_data(pn)` 的消费点**：`ir_gen.cr:3086-3091`（`ptn := ast_data(pn)` → `irv_set_decl_ti` / optrep 形参信道）在 `g_optrep_on` 下走 `res_type_node(ptn)`；
   代入后的类型节点必须能 `res_type_node` 成功（`inst_type_node_of_ti` 合成的节点满足「根节点占单槽」契约，`monomorph.cr:170-175`）。

- **P2（ABI 面显式断言）**：对实例形参槽型断言（IR 面读回：`dex` 族形参槽 = `TI_DEX_S`），

- **P5（突变自证 / 可证伪）**：预置至少 2 个突变，每个必须让 ≥1 条判据转红：
