## §0 结论前置（红旗：**A 类的「排除」证不出来**）

**A 类（49 点）无法写出满足两向钉子的判据式**——它与真异型**在类型面上逐字段同形**，本仓**也没有可用来区分的 handle 型**。

| 来源 | 台账行（同一台二进制、同一格式） | 形状 |
|---|---|---|
| **A 类**（语料真样本，`tests/suite/conc_test.cr`） | `9917 523 23 0 3 0 sched_enqueue` | **`p=3(string) ← a=0(int)`** |
| **真缺陷**（对照探针 `fn takes(s: string)` ← `n : int = 7`） | `9917 5 11 0 3 0 takes` | **`p=3(string) ← a=0(int)`** |

**三型分类（实据）**：
1. **45 点**：实参 = `cur_g := sched_get_curg()` / `recv_wait := r64(ch, 48)` ⇒ **普通 int 变量，AST 看不出 handle**（`r64` 按 `-5` 是设计旁路、其 int 返回有契约）；
2. **4 点**：`ch := go square(21)` ⇒ **变量中介**（`EXPR_GO` 的 int 先落变量再传 `chan_recv`）⇒ 与 `#2026-09-19-4` 的 `await` 那条**同型**；
3. **无 `TI_HANDLE` 常量**：`grep 'TI_HANDLE\|TI_CHAN\|TI_GOROUTINE' src/compiler/ast.cr` = **空**（handle 就是 `string`，A₂ 定的模型）。

**推理链**：抑制 49 点的唯一可实现规则 = 「按 (callee, param) 列全」（`sched_enqueue(g)` · `chan_recv/chan_send/chan_close(ch)` · `g_free(g)`）⇒ 该规则**必然让「int 变量 → `chan_recv`」不再报** ⇒ **反向钉子按构造不可能存在**。
⇒ **且 (丙) 也退化**：要「刀 4 不覆盖 A 面」**也需要一条抑制规则** ⇒ 同样回到 (乙)。
⇒ **唯一出路 = (甲)：把 A 的产出侧真正改型** ⇒ **这正是维护者裁定一**（§A）。

## §A 两句维护者裁定（原话级）与各自的性质

### 裁定一（**新语言特性**）

> `go f(x)` 的型 = **引入句柄类型 `Future<T>`**（携带元素型；`await` 从它取值型）。

- **性质 = 新语言特性**（不是修补）：新类型构造子 + `await` 取值型规则 + 引擎（`ty_shadow` / `type_terms` / 变型表）+ `res_call_type` 分支 + 语料。
- **连带待定**：`chan_recv` / `chan_make` / `g_new` / `sched_go` 这一族**要不要一起改成 `Future<T>` / `Chan<T>`**——**A₂ 当时把它们对齐成了 `string`**（裁定原文：「**(A)：语料/stdlib 向模型对齐**（**(C) handle 兼容明令禁止；(B) 改 `alloc` 模型亦否**）」）⇒ **那条对齐与本次裁定冲突，必须显式处理**（§7 第 7 项，本计划最大未决点）。
- **⇒ 刀 4 押后**：前置从「三条」变为「三条 + 本特性的实现」。

### 裁定二（**改契约**）

> `&x` **改判 `TYP_REF`**（不是「调用点拒」）。

- **性质 = 改契约**：`&x` 产出 `*int` 是**文档化语义**——**编译器自己的用户可见诊断**就这么写（`error[TA02]: Variable declared as &int, got *int`）⇒ 按本仓口径**必须单独立项**。
- **`#2026-09-19-1` 的状态随之变更**：**「定性待裁」→「已裁：改判 `REF`，待实施」**（该条目即本裁定的载体）。
- **它独立可做**，且**消掉了 F 类那 2 点**：改判后 `&x` 与 `&T` **同 kind** ⇒ F 的「REF 形参 ← PTR 实参」自然不再存在 ⇒ **F 的临时排除不必写**（§2.2 因此从「排除」改为「由裁定二消解」）。

**⇒ 推荐**：**加 `TYP_REF` 并同批重写 `(i)` 的判据**——因为 `(i)` 的原文理由（「`&x` 解析到 `TYP_PTR`」）**已被裁定二作废**，保留它等于把一条**前提已死的判据**留在仓里。

### §8.4 拆的条件

裁定二落地 ⇒ **F 的临时排除不存在了**（§2.2）⇒ 刀 4 的未落环排除**只剩 A**。

## §9 两句裁定各自的**两向钉子**（改契约类尤其要防误杀）

| 裁定 | 正向（该变的变了） | 反向（防误杀） | 对照（防「一律」） |
|---|---|---|---|
| **一**（`Future<T>`） | `go f(x)` 的型 = `Future<T>`；`await h` 取 `T`（**运行值 + `--dump-types` 双读**） | 合法 `await` 链**不报**（`p_go.cr` 形） | 非 `go` 的普通值**不受影响** |
| **二**（`&x`→REF） | `&x` 的 kind = `TYP_REF`（`--dump-types`）；`g(p)`（`&NA` 形参 ← `&x`）**不报** | **`@raw_int(&x)` 仍须可用**（§8.3 的抉择结果）；**`*T` 形参 ← REF 值仍须报** | 同 kind 的 REF/REF 与 PTR/PTR **不受影响**；`int → string` 真异型**仍报** |
