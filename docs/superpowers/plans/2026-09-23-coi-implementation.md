### S1 —— 容器与序列化

**Files:** 新建 `src/compiler/coi_io.cr`；`build_selfhost_native.py`（清单三面同核）。

- **做什么**：定长头（`magic` / `format_version` / `seg_count` / `reserved`）+ 段表（`{tag, off, size}`）+ 段体；
  段布局按规格 §十八分节：**generic 段 / target-descriptor 段 / target-record 段 / index 段 / integrity 段**。
  `source_ref` = 带标签变体（见上）；`kind` 用**点分命名空间字符串的 intern id**（**不是**封闭枚举）。
- **⚠ 与 `.ccr` 的三处必须不同**（规格 §十五.2）：magic **不同值** · 版本闸**独立** · **未知段 ⇒ 跳过**（`.ccr` 是 `return -1`）。
- **完成判据**：
  1. `./build/corec check src/compiler/coi_io.cr` rc=0（自源即语料：**任一诊断即 rc=1**）。
  2. 自产自读往返：写一个含 3 段 × 各 2 条记录的文件 → 读回 → **逐字段相等**（`python3 tests/selfhost/test_coi_roundtrip.py`）。
  3. **确定性**：同一输入两次独立生成 ⇒ `sha256` 相同（防「过程历史混入」，规格 #12 的确定性闸）。
  4. 段表界闸：构造 `offset+size > filesize` / `offset` 重叠 / `seg_count` 越界 三类坏档 ⇒ **全部 rc≠0**。

### S2 —— 读写器（含跳过能力）

**Files:** `src/compiler/coi_io.cr`（续）。

- **做什么**：`coi_save(path)` / `coi_load(data, fsize)`；**未知段跳过**、**未知 `kind` 跳过**并继续；
  payload 一律**不透明字节 + 长度**（格式层**永不**递归解析，规格 §十七.2 结论 2）。
- **完成判据**（**规格 #8 的两向钉子，必做**）：
  1. 正向：注入一条 `kind` = 未知值的记录 ⇒ 装载成功，**其余记录的命中数不变**。
  2. **反向钉子**：把该注入记录的 `kind` 换成**已知值**但 schema 非法 ⇒ **必须拒绝**（证明「跳过」不是「一律不校验」）。
  3. 未知**段**（tag 不在已知集）⇒ 装载成功且已知段结果不变。
  4. 无回溯：`strace`-free 判据 = 对 1 MB 构造档的装载 CPU 时间 **线性**（两点法：1 MB vs 2 MB，比值 ≤ 2.5）；
     ⚠ 若做不了计时判据，则退化为**代码闸**：`coi_load` 内**零递归调用**（`grep` 函数自引用 = 0）。

### S3 —— 身份与失效（**双闸**）

**Files:** 新建 `src/compiler/coi_ref.cr`；**读**（不改）`src/compiler/cir_cache.cr:179`。

- **做什么**：
  - **闸 1 结构指纹**：对记录**自己声明的引用区间**（NOD/ENT/REG/TYPE 坐标 + 其内容）做结构化摘要；
  - **闸 2 生产者身份**：沿用 `.cir` 的「运行中二进制内容哈希」形态（**复用** `cir_compiler_identity()` 的取法，不另造）；
  - **两闸都匹配才命中**；**身份不可证 ⇒ 整档不用**（= 无 `.coi` 态，**绝不落「身份 0」条目**——照 `cir_cache.cr:172-178` 的退化纪律）。
- **⚠ 硬约束**：`source_ref` 的**主锚用数值坐标**；字符串名只作 `debug_name`**诊断字段、不参与失效判定**（规格 §9.4 的 STR 陷阱）。
  落地判据：**`.coi` 的任何读写都不调用 `str_intern`**——`grep -n 'str_intern' src/compiler/coi_*.cr` = **0**。
  （理由：新增 intern 会破「`.ccr` 逐字节不变」判据——规格 §9.4。）
- **完成判据**（**规格 #7 的两向钉子，必做**）：
  1. 正向：改动被引用结构的**一个字节** ⇒ 该记录失效，且产物与无 `.coi` 态**相同**。
  2. **反向钉子**：**不**改动 ⇒ 该记录**必须命中**（防「恒失效」假绿）。
  3. 局部性：改 region A ⇒ **只有**声明引用 A 的记录失效；声明引用 region B 的记录**命中数不变**。
  4. 退化：身份取不到（模拟：`/proc/self/exe` 不可读）⇒ **零记录落盘**（不是「身份 0 条目」）。

### S4 —— 与管线接线（**只读、候选位**）

**Files:** `src/compiler/corearch.cr`（改）；`src/targets/x86_64-linux/main.cr`（改，若双入口都接）。

- **做什么**：把 `.coi` 装载结果接进**候选位**——即**只产出候选集供后续评估**，**不直接改变发射决策**。
  ⚠ **本步是「接线」不是「采用」**：`.coi` 诚实地**暂时不产生优化收益**（收益在规格 §二十二 落地顺序里排最后）。
- **⚠ 边界纪律**：不进 `checker` / `type_engine` / `ir_gen` 的**判定位**。
- **完成判据**（**规格 #3/#4，本批最重要的一组**）：
  1. **#3(a) 移除态对拍**：同源 pre/post，删除全部 `.coi` ⇒ ELF + `.ccr` **sha256 相同**且 rc=0。
  2. **#3(b) 结构钉子** ⭐：`g_coi_disabled := 1`（编译期常量，把所有 `.coi` 读点强制「未命中」）⇒ 产物**仍逐字节相同**。
  3. **#4(a) 敌意载荷对拍** ⭐：`.coi` 全部载荷换成**固定种子伪随机** ⇒ 产物与无 `.coi` 态**逐字节相同**且 **rc=0**（不崩、不报错）。
  4. **#4(b) 结构闸**：`grep -rn 'coi' src/compiler/checker.cr src/compiler/type_engine.cr src/compiler/ir_gen.cr` = **0**（注明必要不充分，须与 3 同用）。
  5. canary 硬闸：`bash tools/baseline/canary_check.sh` 全绿（**本步预期全绿**——若变即停，见 §四）。
  6. 自举链：`src/ci/run.sh` `full-bootstrap` = `corec2` vs `corec3` `cmp` IDENTICAL + N06=0 + 冒烟 42。

### S5 —— 索引

**Files:** 新建 `src/compiler/coi_index.cr`。

- **做什么**：按规格 §十六的六个维度建索引（`source entity` / `region` / `relation fingerprint` / `kind` / `target predicate` / `pattern signature`）。
  ⚠ 索引是**加速结构**，**不参与失效判定**。
- **完成判据**：
  1. **可重建**：删除整个索引段 ⇒ 装载结果（候选集）**逐条相同**（只有工作量差异）。
  2. 索引**不改变**任何命中判定：带索引 vs 无索引两条装载路径产出的候选集**逐条相同**。

### S6 —— 目标谓词

**Files:** 新建 `src/compiler/coi_pred.cr`。

- **做什么**：DNF 求值（`&` / `|` / `>=` / `<=` / `==` / `!=`）；部分匹配 = 子句按能力名集合的包含关系比较。
  ⚠ **词汇表不进 `.coi`**（规格 #10）——键来自 HIT 表（`src/arch/x86_64/core-x86.toml`），`.coi` 只**引用**。
- **完成判据**：
  1. **#5**：目标未知 ⇒ generic 记录条数**不变**；目标已知 ⇒ 候选集 ≥ generic 条数；**反向钉子**：**不** compatible 的目标记录**不在**候选集。
  2. **#6**：`target_id` 悬空 / 谓词为空 ⇒ **拒绝**（规格 §四 #6 的本文建议；**若维护者取「跳过」则改判据**——见 §七 A-G）。
  3. **#10 词汇闸**：**未知 feature 名 ⇒ 该记录不可匹配**（**不是**「当作满足」）。
  4. 确定性：同一 `(source_ref, kind, target)` 两次独立编译产出**逐字节相同**。

### S7 —— 合并

**Files:** 新建 `src/compiler/coi_merge.cr`。

- **做什么**：装载器收**列表**；合并 = **排序 + 去重**（**不做冲突消解**——原文 §17「conflicting candidates are not semantic conflicts」）。
  优先序四条 = **候选集内的排序键**：`validity` > `specificity` > `schema 新旧` > `verified`。
- **完成判据**：
  1. 规格 §十七三源（`generic.coi` + `vendor-gpu.coi` + `deployment-profile.coi`）⇒ 候选集 = 三源并集。
  2. 排序键：构造 validity 冲突对 ⇒ 排序结果稳定且**两条都在**（未消解）。
  3. ⚠ **上界纪律**（规格 §二十.2 待裁 A6）：候选集必须有上界；**暂定上界 = 待裁**，未裁前判据 = **打印候选集大小**（不得静默无界）。

### S8 —— 安全面

**Files:** `tests/selfhost/test_coi_fuzz.py`（新）+ `coi_io.cr` 的边界闸。

- **做什么**：全文校验——lengths / offsets / section bounds / record versions / reference validity / target descriptor bounds / payload schema（规格 §十七.1 七项）。
- **完成判据**（**每条都可跑**）：
  1. **fuzz 不崩**：≥1000 例（随机字节 / 截断 / 长度溢出 / 越界偏移 / 段表重叠）⇒ 全部 **rc≠0 或安全跳过**，**不得 SIGSEGV**（判据须含**崩溃面**，不能只看返回值）。
  2. 上界：装载 1 MB 构造档的峰值内存 ≤ 常数 × 文件大小（`/usr/bin/time -v` 的 Max RSS 比值 ≤ 4）。
  3. 七项校验逐项有**至少一条**触发用例（计数 = 7，逐项点名）。

| # | 事实 | 出处 | 对 `.coi` 的意义 |
|---|---|---|---|
| **V-1** | V8 引入 **`EntityRef` = 稳定身份**（= v1 的 Symbol 改名）；`id` **opaque**，「Core 只认它」，唯一语义 = **相等性** | V8 规格 `§三 3.1`（`ccr-v8-open-relational-lattice.md:312-346`） | **这正是 `.coi` §20 Q3 问的那个「stable entity identity scheme」**——V8 可能**直接提供**它 |
| **V-2** | V8 的 **`EntityRef` 编码形态「未定」**——tag 是「派生前缀」还是「携带字段」未定，且原文同一处出现 `target.reg` / `target.register` **两种拼写** | V8 规格 §十 **待裁 新-4**（`:1086`） | ⚠ **V8 自己也没冻结身份编码** ⇒ 「等 V8」**不等于**「等一个已定义的接口」 |
| **V-3** | V8 下 **NOD id 失去垄断**：「坐标仍是 HDFG 侧的，但 `.ccr` 的语义面**不再由坐标承载**——EntityRef / Relation / RelationDomain 才是语义面；NOD id **退化为某个 relation domain 内的命名**」 | V8 规格 §九 D1（`:886`） | ⚠ **规格 §二十三 Q3 的结论（「用 NOD 文件序坐标作主锚」）在 V8 后可能不再是最优** |

> 📌 **本文展开——这三条合起来给出一条反直觉但重要的结论**：
> **「等 V8 冻结」不是一个可等待的单一事件**——V8 的**身份编码**（V-2）本身仍待裁。
> ⇒ **把 `.coi` 的身份步整个串行到 V8 之后，等于把一个待裁项变成自己的阻塞项**。
> **正确做法**：把身份**承载形状**（S1 的带标签变体框架）**先行落地**，
> 把身份**具体 kind 语义**后挂（V8 冻结后新增一个 kind 值，**零重做**）。
> **这就是「可先行」与「必须等」的真实分界线——不在「身份 vs 非身份」，而在「框架 vs 取值」。**

### 2.2 逐条判定表

| 步 / 面 | 判定 | 理由 |
|---|---|---|
| **S1 容器与序列化** | ✅ **可先行**（完全并行） | 纯格式机械；`source_ref` 在容器眼里只是**带标签的不透明变体**——**V8 定成什么形状都不影响容器布局** |

### 2.3 ⚠ 唯一的**真串行点**：`g_opt_meta` 搬迁（待裁 A9）

**为什么是真串行**（不是保守，是判据面冲突）：

1. 搬迁会动 `.ccr` 字节（SYM 段 −4B——`opt_meta` 是 SYM **最后一个**子节）；
2. 而 V8 落地会**必然作废** `.ccr` canary 四条（爆炸半径 §4 第 1 条，原话「**必然作废**（整文件字节布局变）」）；
3. ⇒ 若 `.coi` 批**先**搬、V8 **后**落地，则 **`.ccr` 判据重锁要做两遍**，且中间态无任何一方能给出稳定基线。

⇒ **本文建议**：**A9 与 V8 同批（或 V8 之后）**，**不在本批动 `.ccr` 一个字节**。
**本批的 `.ccr` 面 = 严格只读**（边界纪律已锁）。
⚠ 该建议**须维护者裁**（§七 A9）——**未裁前不得搬迁**。

### 2.4 可并行/串行的一句话总结

> **可先行 = 一切「不知道 V8 什么样也能做对」的**：容器、序列化、跳过、分节、索引、谓词、合并、安全面、
> 身份**框架**、生产者身份闸。
> **必须等 = 一切「输入是 V8 决定的那个东西」的**：与 `.ccr` 的**读取面接线**、结构指纹的**覆盖对象**、
> 以及**任何动 `.ccr` 字节**的操作（A9）。
> **本批可在 V8 冻结前完成的部分 ≈ 工序总表 8 步中的 7 步**（S4 除外，S3 的一半、S6 的一个子项待裁）。
> ⚠ 但这**不是**「先做 7 步、以后再补 1 步」的**分期**——S4 是**同一批交付**的一部分，
> 只是它的**开工时点**受 V8 约束。**顺序 ≠ 分期**。

## 四、判据（**每条都能在本仓跑**；不写「人工检查」）

### 4.1 判据纪律（**先定死，再取数**）

1. **不写 `.ccr` 字节值**：本批判据**一律不**断言任何 `.ccr` 的 `sha256`/字节数（V8 会必然作废它们）。
   需要「产物不变」时，用**同源 pre/post 自比**（`cmp` 两次构建的产物），**不锚定绝对值**。
2. **不钉编译器二进制**：输入锚用**源修订**，不用二进制（二进制随编译器源变而产物可能不变）。
3. **两条腿**：凡「产物不变」类判据，必须给**机制证据**（为什么不该变）+ **红了先归因**的退路。
4. **每条判据默认两向**：单向判据对反向缺陷恒绿 ⇒ 每个「必红」都要配一个「必绿」的对照。
5. **读数前 `clean-cache`**：暖态读数前必须清 `.core/cache`（暖态合成串陷阱：VER 17–20 四代全复现）。
6. **cwd = 仓库根**：`.core/cache` 与 import 解析都**相对 cwd**；在 `/tmp` 下跑会得假结果。
7. **`nice -n 19`**：全部编译/测试任务限 CPU（铁律 #6）；一构建一编译**串行**，每段前 `ps` 实查。
