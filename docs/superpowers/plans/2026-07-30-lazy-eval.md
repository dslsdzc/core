# 惰性求值 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automatic lazy evaluation — compiler defers pure function calls that are used in only one branch, without `lazy` keyword.

**Architecture:** Side-effect analysis marks pure functions. Usage-count analysis on dataflow graph identifies deferrable calls. `IR_LAZY_THUNK(46)` wraps values. `IR_LAZY_FORCE(47)` evaluates on first access.

**Tech Stack:** Core self-hosted compiler, dataflow analysis, x86-64 ELF backend

## Global Constraints

- No `lazy` keyword — automatic optimization
- `IR_LAZY_THUNK = 46`, `IR_LAZY_FORCE = 47`
- Thunk = 9 bytes (1 byte computed flag + 8 byte value)
- Pure function = no IO, no FFI, no unsafe writes, no global mutation
- Uses `jj` for version control

### Task 3: IR Gen — Lazy Thunk Emission

**Files:**
- Modify: `src/compiler/ir_gen.cr`

**Step 1: Emit lazy thunks for deferrable calls**

In `gen_expr`, after emitting a call to a pure function, check if the result is used in only one branch. If so, wrap with `IR_LAZY_THUNK`:

```core
if is_pure_func(func_ni) && is_single_branch_use(result_var) {
    thunk_var := new_ir_var("_lazy", TI_UNIT);
    emit(IR_LAZY_THUNK, thunk_var, result_var, 0, 0, 0);
    return thunk_var;  // return thunk instead of raw value
}
```

At the usage point, emit `IR_LAZY_FORCE` to extract the value.
