### 2. ⚠⚠ **【S·通用】可选值 `==` 恒假（含 `None == None`）**（`TODO #2026-09-17-6`）

- **现象（实测五读数）**：`n==Some(7)` ⇒ **0** · `n==None` ⇒ **0** · **两个 `None` 变量比较 ⇒ 0** ·
  两个值为 7 的可选比较 ⇒ **1** · `n == 7`（可选 vs 内层值）⇒ **1**。
- **最小复现**：
  ```core
  fn main() -> int { n : int? = None; if n == None { return 1; } return 0; }   // 期望 1；实测 0
  ```
- **机理（2026-09-18 重锚 + 定性更正）**：`==` 走 `gen_expr`（`ir_gen.cr:1192` 起）内的**通用落点 `:1465-1467`**
  （`emit(IR_BINARY, v, left_var, right_var, op, fti)`）**不读 rep 位** ⇒ **逐槽比较原始值**：
  bare（rep=0）= 值本身 ⇒ `7==7` 真；**boxed（`Some`/`None` 对象）= 指针** ⇒ 指针 vs 值、指针 vs 另一指针**恒假**。
  既有「读 rep」先例（可作修法模板）：`irv_rep`（`ir_gen.cr:230`）在 match 解包（`:2424`）、`?` 解包（`:2981`）、
  写点（`:1496`）三处被读取——**比较点是缺口**。
  **行锚更正**：原文引的 `:1453` 落在 **`gen_expr` 内的 dex 定点分支**中（`:1412` 开块、`:1453-1459` 为「缩放整数比较」），
  **不是通用落点**；两个非 dex 操作数（如可选）走 `:1465`。
  **机理定性（重要）**：本节机理属**读码推断、未实测**——`TODO #2026-09-17-6` 的登记原文即「**机理未定位**……**勿据本条推断根因**」；
  引用时须与「现象五读数（实测）」分层（§1-1 的教训 = 读码推断可被实测推翻）。
- **机理无关的验证法（2026-09-18 补；取代「按机理选突变点」）**：① 实施前**先在改前构建上复现五读数**（`0/0/0/1/1`）——**现象锚**，与机理无关；
  ② 突变自证 =「按**改前五读数**反向注入探针期望值 ⇒ 必红」+「修复后逐条取反」。
- **判据要件**：① `Some(x)==Some(x)` **必真**；② `None==None` **必真**；③ `Some(x)==None` **必假**；
  ④ **同源自比较 `x==x` 必真**（bare/boxed 两表示都测）；⑤ 非可选 `==` 语义与产物**零变化**（canary/`.ccr` IDENTICAL）。
- **判据强度补强（2026-09-18 实测）**：**①–④ 全部可被「只比 tag、不比载荷」的实现满足**（同 tag ⇒ 真 / 异 tag ⇒ 假 / `x==x` ⇒ 真）⇒
  **判据全绿而 `Some(7)==Some(8)` 仍错误为真**。⇒ 必补：
  ⓐ **载荷不等必假**（`Some(7)==Some(8)` ⇒ 假）+ **方向对称**（`None==Some(7)` 必假；`x==None` ↔ `None==x` 两向同判）；
  ⓑ **混合形语义钉**（`n == 7` = 可选 vs 内层值，现状 **1**——见现象第 5 读数；判据要件原无它 ⇒ 修法可把它改成 0 而**全绿** = 语义退化）；
  ⓒ **断言面 = 程序运行退出码**：本探针**修复前后 corec 都 rc=0**，只差返回值 ⇒ 以 corec rc 为断言 = **真空通过**（全批唯一红线）；
  ⓓ 要件 ⑤ 的**仪器覆盖缺口**：canary/`.ccr` 四条对 `==` 面**零覆盖**（同族先例 = `tests/selfhost/test_apx_conversion.py:18-21` 明文
    「apx 面零覆盖……**不得以『canary 还绿着』代替**」）⇒「非可选零变化」须由**该面行为钉子 + 全语料对拍**承担（§5-2 / U3）。
- **突变自证（2026-09-18 改机理无关形式）**：见上方「机理无关的验证法」——**不得**用「把比较点退回『不读 rep』」这类**预设缺陷点**的突变
  （若真机理不在比较点，该突变**改不到缺陷处** ⇒ 探针与判据**双双保持绿** = 自证失效）。
- **停条件**：若裁决为「表示敏感相等」（保持现状）⇒ 本条**移出本批**、降级为语言语义登记（见裁门 G3）。

### 3. **【fail-closed 缺口】`extern` 形参不校验可选**（`TODO #2026-09-17-7`）

- **现象（实测）**：`extern fn e(x: dex?)` ⇒ **`check` rc=0（零诊断）**、`build` rc=0、运行期 **139**；
  对照 `extern fn e(x: int?)` ⇒ **同形同判**（非 dex 特有）。
- **最小复现**：
  ```core
  extern fn e_opt(x: dex?) -> int;
  fn main() -> int { d : dex, apx = 7.0; return e_opt(d); }    // check=0（应拒未拒）；运行期 139
  ```
- **机理（读码）**：`checker.cr:2167` `if ast_kind(fn_node) == EXPR_EXTERN { return; }` ⇒ **extern 声明的形参/体检查整段跳过**
  ⇒ 无「C ABI 可表示性」校验；`ir_gen.cr:1985` 的 `cfn_ext == 0` 守卫使实参环**对 extern 侧不扩**（无约定可依）。
- **判据要件**：① `extern` 声明含可选形参 ⇒ `check` rc=1 + 专属诊断 + **零产物**；② 非可选 `extern` 行为**逐字节不变**；
  ③ `dex?` 与 `int?` **同一拒收路径**。
- **突变自证**：撤掉新校验（或放行该形态）⇒ 探针回 `check=0` ⇒ **必红**。
- **停条件**：若实测发现 C ABI 实际支持某可选形态（e.g. 指针型可选）⇒ 停下报 lead 再定粒度。

### 4. ⚠ **【S】顶层兜底静默吞 token**（分诊/登记面；`parse_declaration` 裸 `advance_tok()`）

- **现象（实测三态）**：① 顶层多余 `}` ⇒ `check=0 · build=0 · 运行 7`（**零诊断静默接受**）；
  ② `stuct S { f: int }`（typo、未使用）⇒ `check=0 · build=0 · 7`（**声明被无声丢弃**）；
  ③ 同上但**使用** `S` ⇒ `check=1`（`error[TF01]` = **误报**）+ **build=0** ⇒ 运行期 **139**。
- **机理（`file:line`）**：`parser.cr` 的 `parse_declaration()` **末尾为裸 `advance_tok();`**（函数尾、紧随
  「New syntax global variable declaration」分支之后；实读时在 `:1540` 邻域）⇒ **无法识别的顶层 token 被静默消费**，
  既不 `add_error` 也不定位。③ 的 TF01 与**条目 6 同族**（静默丢弃 ⇒ 后续误归）。
- **判据要件**：① 无法识别的顶层 token ⇒ `check` rc=1 + 定位诊断 + **零产物**；② 合法顶层形态

- **突变自证**：恢复裸 `advance_tok()` ⇒ ①/② 两条探针回 `rc=0` ⇒ **必红**。
- **停条件**：若合法顶层形态与兜底分支**共用入口**（`mod {}`/宏体等），无法无歧义区分 ⇒ 停下报 lead 取裁粒度。
