# `.cir` 快照串域跨进程 id 缺陷：修法计划（2026-09-18）

状态：计划，未实施（只读调查轮产物；等裁定 (a)/(b)/(c) 与换代后再开实施批）。

性质：有缓存状态（cache hit）不报错地错值。同一源、同一二进制，第二次构建得到不同 IR；两次 `build` 均 rc=0。

## 0. 一句话结论

`.cir` 快照把串操作数存成写侧进程的绝对 intern id，装载侧原样恢复，不做任何重映射。读侧进程的 intern 表布局取决于哪些函数被生成、哪些被装载。因此，凡首次 intern 发生在 IR 生成期的串（多字段 `@fields`、合成变量名、`Some`/`None` 类合成名等），在读侧会解析到别的串。实测可解析到含 NUL 的无效字节。

## 2. 三案并列（参考 `sh_tk_split_load`（v18）先例作为第三形态）

> v18 先例：nodes 第 6 槽（派生码）不信任盘值，按结构重建（`sh_tk_split_load` 由 `(opcode, 派生码)` 重新派生两槽）。它不是重映射 id，而是盘上不存跨进程量、装载期重建。

| 案 | 做法 | 盘面改动 | 改哪些函数 | 有缓存状态收益 | 主要风险 |
|---|---|---|---|---|---|
| (a) 内容为键重映射 | 装载期按内容 `str_intern` 得到新 id，建立旧 id 到新 id 的映射表并改写串槽 | 增加「串到写侧 id」的对应（F6 证明无法从现有盘面推出） | `save_cir_cache` · `load_cir_cache` · 尺寸计算 | 保留命中 | 槽位判定完备性：哪些槽是串 id 须按 `(opcode,tk)` 派生；漏点会导致不报错地重新生效 |
| (b) 串域恒校验见证（fail-closed） | 重新 intern 后逐条比对写侧基线或摘要；不符则拒绝（miss） | 增加见证字段（写侧串表基线或逐串摘要） | `save_cir_cache` · `load_cir_cache` · 头部/尾部布局 | 失去命中（须实测：编辑一文件后重建的命中率） | 命中率可能回落到批 7 之前（收益面，不是正确性面） |
| (c) 装载期重建（照 v18 先例） | 盘上不存跨进程 id，改存条目自洽量（本条目的 str 段下标）；装载期按 `(opcode,tk)` 判定串槽，并以 `str_intern(条目内串)` 重建 id 写回 | 值语义改变（id 改为段下标） | `save_cir_cache` · `load_cir_cache` · 尺寸计算 · 可能的 dump 通道 | 保留命中 | 同 (a) 的槽位判定完备性（两案可共用同一份写点审计） |

建议：(c) 优先。它最接近本仓既有先例，盘面不留跨进程量，且与 (a) 共用同一审计面。(b) 作为后备严格性：若槽位判定审计无法收敛，则退到 (b)，用 miss 换正确。(a) 仅在 (c) 被否且槽位判定已完备时，等价于 (c) 的弱化形态。

### 换代（`CIR_CACHE_VER`）分案推理（检查为旧条目在新装载器下会不会被错误解释）

- (a)：若只做装载侧重映射、盘面零改动，使旧条目也能被正确重映射，则可以不 bump。但该前提实测不成立（F6：盘面只有串内容、没有 id，位置不等于 id，因此没有对应关系可建）。因此 (a) 必须改盘面，必须 bump。
- (b)：新增见证字段。旧条目缺该字段，绝不能把「读到 0 或缺字段」当作「一致」（那正是本单的不报错地类重新生效），则 bump，让旧条目整体 miss 并无害重建。
- (c)：盘面值语义改变（写侧 id 改为段下标）。旧条目的值是跨进程 id，被新装载器按段下标解释会得到错图，因此 bump。
- 结论：三案一律 bump。这与既有 19 代同族，每一代都是「快照携带了会随进程态或格式变化的量」；`cache miss = 无害重建` 是本仓既定纪律。

## 3. 验收要求（修复批必须全部通过；检查须自带突变自证）

1. 入口固定：`repro_6line` 形态，空缓存状态 `"x,y"`/3 且有缓存状态 `"x,y"`/3（rc 相同 + 产物 `cmp` 相同）。
2. 判别实验进入检查：`scope_firstintern` 形态，`ONE=x`（解析期已 intern）有缓存状态必须正确，`TWO=x,y` 有缓存状态必须正确。
3. 三条注入路径各一探针。不接受「修了主路径，另两条顺带」；另两条今天未独立复现，只是没有构造探针，不代表安全：
   - 路径 1 · 指令/节点操作数：`scope_fields`（`IR_CONST` 串槽），行为和 ELF 逐字节相同。
   - 路径 2 · var 名 `irv_name`：以 `.ccr` 为观测面（F8 的串池差集），检查是冷、暖 `.ccr` 逐字节相同，且串池集合相等；探针使用含合成变量名的形态（`_cat0`/`_cat1` 类）。
   - 路径 3 · str 段重新 intern 的顺序：删条目回归（F5）就是它的探针。删任意缓存条目后重新运行，仍须与空缓存状态逐字节相同。它直接改变命中集合，因此会改变重新 intern 的顺序，是本缺陷判别力最强的一条。
4. 空缓存状态与有缓存状态各一条检查和固定值：分别断言同一字面量固定值（不是只看「都 rc=0」），并逐字节对比产物。
5. 突变自证和断言命中目标：测试内提供「关掉重映射、见证或重建」（或改成恒等映射）的注入，检查必须失败；突变须自证「改到的那一行确实是目标」。
6. 实现方式与接入点：`tests/selfhost/test_cir_str_domain_warm.py`，挂到 `src/ci/run.sh` 的 `selfhost-tests`，因此位于 PR 门内。不得只增加 `tests/suite/*.cr`（PR 门只跑 3/5 档，语料档在 PR 上不运行）。同批把 `tools/cir-str-domain/run_scope.sh --assert` 的矩阵并入该测试。纪律：对比两侧各自运行 clean-cache。本缺陷的存在本身就是这条纪律的由来。
7. label 域回归触发器：见第 5 节。

## 5. 结论与开放项

- locals/scope：边界可判定，依据三条。1 `cir_cache.cr` 段表没有 locals 段，因此结构上不存在跨进程恢复面；2 唯一消费者 `find_local` 只在生成期调用（`ir_gen.cr` 468/498/580/606/1398/1698），命中函数整段跳过生成，因此没有消费者；3 参数绑定（`ir_gen.cr:3257`）和块级绑定都在生成路径上，且未定义名是硬错误（实测 `probes/undefined_name.cr`：`build` rc=1、无产物），因此合法程序不会以未绑定名落入 `find_local`。残余问题（另立条目）：若某日 checker 对某形态放行未定义名，「前一函数残留绑定」面会与缓存交互；那属于既有面，不是本串域。
- label 域触发器（须随条目长期保留）：「label id 只在本函数内消费」是 F10 判无罪的前提。若出现第二个直接接受 label id 的消费点，或改成按 distance 选择短跳编码，本结论失效，须重新运行 `label_collision.cr` 的撞车实验。
- 串槽写点完备性（(a)/(c) 的共同前提）：本调查只证明「存在未被重映射的串槽」，未做全枚举。实施批第一步是枚举 `ir_gen.cr` 全部「`str_intern(` 后入槽」点，以及 `irv_set_name`/`irv_name` 写点，并用注入式探针逐点收敛。
- `Some`/`None` 合成名：读码确认在串域内，但无法构造「既触发、又不在源里点名这两个标识符」的可观测探针，留给实施批的注入式探针。

## 7. 实施（2026-09-18 实施批；裁定为 (d)：生成期 intern 日志 + 装载期按序重放 + bump）

裁定经过：lead 先裁 (c) 主案 + (b) 后备。实施第一步的结构性槽位审计给出反例：`IR_CONST.s1` 在 `tk=TI_INT` 下可携带变体名 id（`str_intern("None")` 的 tag 值，见 `ir_gen.cr::opt_cmp_extract_boxed`），与整数立即数在盘面不可区分。因此按 `(op,tk)` 判定串槽的表在原理上无法完备，不是审计做不全。据此停止并上报，lead 改裁 (d)，(b) 仍作后备。(a)/(b)/(c) 都在解释跨进程量，解释需要表，表会漏；(d) 不解释，而是复现写侧状态。

实现（`CIR_CACHE_VER` 从 20 改为 21）：

- `globals.cr`：`g_cir_rec_{on,ids,count,cap,base}` + `g_cir_skip_journal`（隐藏 debug）。
- `dyn_arr.cr::str_intern`：在唯一插入路径上调用 `cir_rec_push(g_str_count - 1)`。单点保证「生成期新 intern 必进日志」，因此不存在「判定表漏点」这一失效面。
- `main.cr`：`cir_rec_begin/end` 夹住 `ir_gen_func`（仅在缓存启用时）；隐藏 flag `--inject-cir-skip-journal`（仅检查突变自证用）；见证面清单补 4 行（`g_strs` 和 `g_str_count` 归位，以及「何时被漏、为何被漏」和触发器）。
- `cir_cache.cr`：写侧新段 `{基线见证, 条数, ×(len, bytes)}`（只存内容）；装载侧先校验基线见证，再按序重放（必须先于任何 id 消费者）；VER 从 20 改为 21（v20 段原文保留）。
- 实现方式同步更新（grep 机械枚举 + 旧值记录）：`CIR_CACHE_VER`、`test_cache_identity.py::VER_EXPECTED`、`test_ccr_types.py` 两处 `assert ver ==`、`test_cir_warm_path.py` 检查重定（STR 段由「暖 = 冷前缀（预存约定）」改为「冷 == 暖逐条逐字节相同」，`CONTRACT_TAGS` 从 7 段改为全 8 段）。

顺序确定性论证（对应第 5 节要求 4-1）：1 跨函数：`main.cr` 的函数循环只有一个顺序，写侧在该循环里生成，读侧在同一循环里装载；2 函数内：两侧共用唯一插入路径 `str_intern`（记录顺序等于插入顺序）；3 窗口外的插入（parse/check 等）两侧同源同序，因此不进日志也不影响结果。因此归纳成立：前序函数同态，所以本篇起点同态。基线见证把这条不变量变成运行时校验：不符即 miss。

检查（17 例，`tests/selfhost/test_cir_str_domain_warm.py`，挂 `src/ci/run.sh` 的 `selfhost-tests`）：A 入口（6 行复现：输出、ELF、`.ccr` 三面相同；固定 `fields=[x,y] len=3`）· B 判别实验（两半有缓存状态都必须正确）· C var 名路径（`.ccr` 逐字节相同，含合成名）· D 混合命中态（删首、中、末、多条，输出和 ELF 相同；正式化第 5 节要求 4-2）· E 突变自证（`--inject-cir-skip-journal`，有缓存状态取回 `arena_reset`）+ 非真空控制（无串槽语料上突变不改变输出）· F 日志段结构（ver=21，count≥1）。`tools/cir-str-domain/run_scope.sh --assert` 一并挂入门内（`known-baseline-red.txt` 收录基线既有失败 `interp`，即插值解析失败，不是本缺陷面）。

实施时实测到两条新观察（未修，另立条目）：1 混合命中态 `.ccr` 的 NOD 段有 20B 级差异；段级定位显示只有 NOD 和 TYPE 项索引随重生成顺序变化，ELF 和行为不受影响；2 `IR_CONST.s1` 的「立即数与 intern 名 id」在盘面不可区分，属于格式设计问题。
