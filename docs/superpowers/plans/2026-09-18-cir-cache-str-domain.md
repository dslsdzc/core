# `.cir` 快照「串域」跨进程 id 缺陷——修法计划（2026-09-18）

**状态**：**计划，未实施**（只读调查轮产物；裁 (a)/(b)/(c) 与换代 ⇒ 再开实施批）。
**登记条目**：`TODO.md` 的 `#2026-09-18-9`（含实测更正层）。
**性质**：暖态（cache hit）静默错值——同一源、同一二进制，第二次构建得到**不同 IR**；两次 `build` 均 `rc=0`。
**证据包（已入仓）**：`tools/cir-str-domain/`（探针 + runner + README，可复跑）。

---

## §0 一句话结论

`.cir` 快照把「串操作数」存成**写侧进程的绝对 intern id**，装载侧**原样恢复、不做任何重映射**；
而读侧进程的 intern 表布局取决于「哪些函数被生成、哪些被装载」⇒ **凡首次 intern 发生在 IR 生成期的串**
（多字段 `@fields`、合成变量名、`Some`/`None` 类合成名…）在读侧解析到**别的串**（实测可到含 NUL 的垃圾字节）。

## §2 三案并列（照 `sh_tk_split_load`（v18）先例作为第三形态）

> v18 先例：nodes 第 6 槽（派生码）**不信任盘值、按结构重建**（`sh_tk_split_load` 由 `(opcode, 派生码)`
> 重新派生两槽）——它不是「重映射 id」，而是「盘上不存跨进程量、装载期重建」。

| 案 | 做法 | 盘面改动 | 改哪些函数 | 暖态收益 | 主要风险 |
|---|---|---|---|---|---|
| **(a) 内容为键重映射** | 装载期按内容 `str_intern` 得新 id，建 `old→new` 表并**改写串槽** | **+「串→写侧 id」对应**（F6 证明无法从现有盘面推出） | `save_cir_cache` · `load_cir_cache` · 尺寸计算 | **保命中** | **槽位判定完备性**（哪些槽是串 id，须按 `(opcode,tk)` 派生；漏点 ⇒ 静默复活） |
| **(b) 串域恒校验见证（fail-closed）** | 重 intern 后逐条比对写侧基线/摘要；不符 ⇒ **拒绝（miss）** | **+见证字段**（写侧串表基线或逐串摘要） | `save_cir_cache` · `load_cir_cache` · 头部/尾部布局 | **失命中**（须实测：编辑一文件后重建的命中率） | 命中率可能回落到批 7 之前（收益面，非正确性面） |
| **(c) 装载期重建**（照 v18 先例） | 盘上**不存跨进程 id**，改存**条目自洽量**（本条目的 str 段下标）；装载期按 `(opcode,tk)` 判定串槽并以 `str_intern(条目内串)` **重建** id 写回 | **值语义改变**（id → 段下标） | `save_cir_cache` · `load_cir_cache` · 尺寸计算 · 可能的 dump 通道 | **保命中** | 同 (a) 的槽位判定完备性（**两案可共用同一份写点审计**） |

**建议**：**(c) 优先**（最贴本仓既有先例、盘面不留跨进程量、且与 (a) 共用同一审计面）；(b) 作为**兜底严格性**（若槽位判定审计无法收敛，则退 (b) 用 miss 换正确）；(a) 仅在 (c) 被否且槽位判定已完备时等价于 (c) 的弱化形态。

### 换代（`CIR_CACHE_VER`）**分案推理**（判据 = 「旧条目在新装载器下会不会被**错误解释**」）

- **(a)**：若纯装载侧重映射、盘面**零改动** ⇒ 旧条目也能被正确重映射 ⇒ **可不 bump**。
  **但该前提实测不成立**（F6：盘面只有串内容、没有 id，位置 ≠ id ⇒ 无对应可建）⇒ (a) 必须改盘面 ⇒ **bump**。
- **(b)**：新增见证字段。旧条目**缺该字段**——绝不能把「读到 0/缺」当作「一致」（那正是本单的静默类复活）⇒ **bump**
  （让旧条目整体 miss = 无害重建）。
- **(c)**：盘面值语义改变（写侧 id → 段下标）。旧条目的值是**跨进程 id**，被新装载器按段下标解释 = **错图** ⇒ **bump**。
- **结论：三案一律 bump**。与既有 19 代同族——每一代都是「快照携带了会随进程态/格式漂移的量」；
  且 `cache miss = 无害重建` 是本仓既定纪律。

## §3 判据要件（修复批必须全绿；**判据须自带突变自证**）

1. **入口锚定**：`repro_6line` 形态——冷 `"x,y"`/3 **且** 暖 `"x,y"`/3（rc 同 + 产物 `cmp` 同）。
2. **判别实验入判据**：`scope_firstintern` 形态——`ONE=x`（解析期已 intern）暖态**必须**正确、`TWO=x,y` 暖态**必须**正确。
3. **三条注入路径各一探针**（**不接受「修了主路径、另两条顺带」**——另两条今日未独立复现只是**没构造探针**，不是安全）：
   - **路径 1 · 指令/节点操作数**：`scope_fields`（`IR_CONST` 串槽）——行为 + ELF 逐字节同。
   - **路径 2 · var 名 `irv_name`**：以 **`.ccr` 为观测面**（F8：串池差集）——判据 = 冷/暖 `.ccr` 逐字节同 +
     串池集合相等；探针用**含合成变量名**的形态（`_cat0`/`_cat1` 类）。
   - **路径 3 · str 段重 intern 序**：**删条目回归**（F5）即其探针——删任意缓存条目后重跑仍须与冷态逐字节同
     （它直接改命中集合 ⇒ 改重 intern 序，是本缺陷判别力最强的一条）。
4. **两腿同判 + 锚定值**：冷腿与暖腿各自断言**同一字面量锚定值**（不是「都 rc=0」），并逐字节对拍产物。
5. **突变自证 + 断言命中目标**：测试内提供「关掉重映射/见证/重建」（或改成恒等映射）的注入 ⇒ 判据**必红**；
   且突变须自证「改到的那一行确实是目标」。
6. **载体与挂点**：`tests/selfhost/test_cir_str_domain_warm.py`（挂 `src/ci/run.sh` 的 `selfhost-tests` ⇒ **在 PR 门内**）。
   **不得**只加 `tests/suite/*.cr`（PR 门只 3/5 档，语料档在 PR 上不跑）。同批把 `tools/cir-str-domain/run_scope.sh --assert`
   的矩阵并入该测试。**纪律**：对拍**两侧各自 clean-cache**（本缺陷的存在本身就是这条纪律的由来）。
7. **label 域回归触发器**：见 §5。

## §5 收口与开放项

- **locals/scope：判出边界**（依据三条）——① `cir_cache.cr` 段表**无 locals 段** ⇒ 结构性不存在跨进程恢复面；
  ② 唯一消费者 `find_local` 只在**生成期**调用（`ir_gen.cr` 468/498/580/606/1398/1698），命中函数整段跳过生成 ⇒ 无消费者；
  ③ 参数绑定（`ir_gen.cr:3257`）与块级绑定都在生成路径上，且**未定义名是硬错误**（实测 `probes/undefined_name.cr`：
  `build` rc=1、无产物）⇒ 合法程序不会以未绑定名落入 `find_local`。
  **残余（另立条目范畴）**：若某日 checker 对某形态放行未定义名，「前一函数残留绑定」面会与缓存交互——那属**既有面**，非本串域。
- **label 域触发器（须随条目长期保留）**：「label id 只在本函数内消费」是 F10 判无罪的前提；**若出现第二个直接吃
  label id 的消费点、或改成按 distance 选短跳编码 ⇒ 本结论失效**（须重跑 `label_collision.cr` 的撞车实验）。
- **串槽写点完备性**（(a)/(c) 的共同前提）：本调查只证「存在未被重映射的串槽」，**未做全枚举** ⇒ 实施批第一步
  = 枚举 `ir_gen.cr` 全部「`str_intern(` 后入槽」点 + `irv_set_name`/`irv_name` 写点，并用**注入式探针逐点**收敛。
- **`Some`/`None` 合成名**：读码在串域内，但无法构造「既触发又不在源里点名这两个标识符」的可观测探针 ⇒ 留给实施批的注入式探针。
