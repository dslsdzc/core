# .ccr v11: drop REG, move function node ranges into SYM

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the consumer-less REG segment from `.ccr` and make SYM the owner of each function's NOD range.

**Architecture:** v11 has eight segments: STR, TYPE, IFACE, SYM, NOD, ENT, EDG, CASE (tags 1..8). The SYM function header grows from 24B to 28B: `{name u32, param_count u32, ret_type u32, instr_start u32, instr_count u32, first_ent i32, last_ent i32}`. The loader validates that function ranges tile `[0, nod_count)` and fills `g_ir_func_instr_start/count` directly. `g_sgs` stays in memory for frontend passes; it is no longer serialized.

**Tech Stack:** Core self-hosted compiler, `.ccr` byte contract, Python selfhost test suite, ELF canary.

**Spec:** `docs/superpowers/specs/2026-10-23-lattice-ccr-v10-design.md` (v10 baseline); this plan records the v11 delta.

## Global Constraints

- No compatibility path for v10; `.ccr` is regenerated. The loader rejects every non-v11 version.
- ELF canary must remain byte-identical; only `.ccr` canary values may change.
- `g_sgs` remains the frontend region table and `.cir` cache source. Only REG's disk segment is removed.
- Function node ranges must tile the whole NOD space, with zero-length functions allowed.
