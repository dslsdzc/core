## §0 形式模型与不变量（**先读后判**，逐条实读）

| 面 | 事实 | 出处（实读） |
|---|---|---|
| 两个 dex 形式 | `TI_DEX`=1 = binary64 位模式（apx 快路径）· `TI_DEX_S`=8 = 定点缩放整数（S=10⁶，精确/默认世界/跨函数边界统一形式，**哨兵行**不入类型表） | `ast.cr:262/:274` · `ir_gen.cr:1026-1032` |
| `apx` 是 LET 专属标签 | parser 对**任意声明**接受（`int, apx` 亦接受且**静默忽略**，实测 p_e1/p_e2 = 3/3） | `parser.cr:819` · 本轮探针 p_e1/p_e2 |
| 可选表示（rep 位） | 槽配 1 个 int 表示位：`0` = **裸**（槽值即载荷）/ `1` = **装箱**（Some 对象，载荷在 `obj.1`）；解包侧按位分派 | `ir_gen.cr:2520`（`opt_rep_slot`）· `:2386-2425`（match 分派）· `:2453-2472`（载荷读） |
| **关键缺口** | **rep 位只有 1 比特**：它承载「裸/装箱」，**承载不了「形式」**（bits/scaled）。⇒ 一个 `dex?` 槽若要同时支持两形式，需 2 位信息 —— 现有表示不可表达（§3 方案 C 的不可行性论证） | 本表上两行 |
| 既有单一源结论 | 「**聚合面不存在 apx 形式**」 ⇒ 字段/元素/元组元素/枚举载荷/指针 pointee 的**规范槽形式恒 scaled**，写点由漏斗 `dex_slot_norm` 保证、读点由 `agg_*_read_form` 定型 | `ir_gen.cr:406-416`（注释）· `:1110-1120`（漏斗） |
| **`dex?` 属哪一面** | `dex?` 槽是**容器**（裸槽 = 载荷直存；装箱槽 = Some 对象）且**无 apx 标签位可用** ⇒ 与上文同族 ⇒ 规范形式 = **scaled**（裁决门 G1） | 本文件 §3/§4 |

### 1.1 四态矩阵（裸/装箱 × bits/scaled）——**主判据的基元**

源（四条，仅源值形式与是否 `Some` 不同）：

```core

fn main() -> int {                             fn main() -> int {
    d : dex, apx = 7.0;                            e : dex = 7.0;
    x : dex? = d;                                  x : dex? = e;
    return match x { Some(v) => { return @raw_int(v) / 1000000; } None => { return 0; } };
}
// a3 装箱+bits（`x : dex? = Some(d)`）· a4 装箱+scaled（`Some(e)`）同形
```

**结论 1（与 TODO 原文的差异）**：四态里**只有「裸+bits」直接红**；`Some(d)` 路径已被 apx 批漏斗
（`:2752` 的 `dex_slot_norm`，对 `Some`/`None` 关键字形 `enum_payload_ti` 返 -1 ⇒ 装箱为空操作 ⇒
norm 落在**值**上）修好。**不得**照抄 TODO 原文「整族全红」的措辞。

**结论 2（可达性不对称，比四态矩阵重要）**：「装箱+bits」**不能**由 `Some(...)` 直接构造，但可由
**6 条间接路径**到达，且**全部红**：`&x` 强制装箱（b2）· 形参信道（b4）· 结构体字面量字段（b5）·
全局槽（b7）· 指针写（c2）· 用户枚举的 `dex?` 载荷（c3）。⇒ **四态对拍只是入口，家族面才是本批的主体**。

**数值自洽校验（防桩式断言）**：`bits(7.0) = 4619567317775286272`；
`4619567317775286272 / 10⁶` 低 8 位 = **15**（= p_a1/b1/b2/b3/b5/b7/c2/c3 的实得值）；
`4619567317775286272 % 100 = 72`（= p_d5 interp 的 172 = 100+72）；
`7000000 % 100 = 0`（= p_d6 的 100 与 a2 的 7）。⇒ 全部读数落在同一条「bits 原样入槽 + 读回按 scaled/@raw_int 解释」链上。

### 1.3 IR 级正据（`corec cir` 原文节选）

**p_a1（裸+bits，红）**——转换序列**不存在**，槽里是 bits 常量：

```
      const             dex = 7000000            ← 字面量本体（scaled，未被使用）
      const             dex = 4619567317775286272  ← bits（apx 快路径）
      store             d <- dex
      approx
      const             x_rep = 1
      alloc             x : unit
      store             x <- d                   ← ★ bits 直接入 x 槽（无 `_dxs`/`F2I` 序列）
      const             x_rep = 0
```

**p_a2（裸+scaled，绿）**——同形但槽里是 scaled（`store x <- e`，`e = 7000000`）⇒ 对照成立。

**p_b5（结构体字面量字段，红）**——装箱序倒置的**直接证据**（箱载荷 = bits）：

```
      const             dex = 4619567317775286272
      store             d <- dex
      approx
      make_enum         box = make_enum(Some)     ← 先装箱
      store_field       box.1 <- d                 ← ★ 载荷 = bits（norm 在装箱之后 ⇒ 落在箱对象上 = 空转）
      store_field       struct.0 <- box
```

**p_b4（形参面，红·分歧）**——callee 序言从**实参表示信道**读 rep，但**值**走 ABI 分类：

```
Function: g
      load              x_prep = __optrep_arg0     ← rep 信道（全局 cell）
      …
      binary            rep_isbare = x_prep == _rz
```
⇒ caller 按实参 var 的 IR 型 `TI_DEX` 分类为 **binary64（XMM）**，callee 的 `x` 槽型 = `TI_INT`
（见 §1.4 R3）⇒ 走 **GP** ⇒ 读到的不是实参值（ELF 侧垃圾；interp 无寄存器类概念 ⇒ 按位置拷贝 ⇒ bits）。
这就是 p_b4/p_d5 「ELF ≠ interp」的机理。

⇒ 「apx 批的漏斗**在位**，但被调用序绕过」——这是「**改了一处、漏了另一处的序**」类缺陷，
与 #2026-09-16-29 原文「写点整段跳过转换」是**两个不同机理**（原文只说了 R1）。

**R3 声明面在 `unpack_type` 塌陷 ⇒ 形参/返回/全局的 ABI 级后果**：
- `unpack_type(EXPR_OPTIONAL)` 返 **0**（定义 `parser.cr:150-153`：`if ast_kind(typ)==0 …else 0`；形参节点写入 `parser.cr:1427`
  的 `unpack_type(pty)` ⇒ `EXPR_PARAM.type_val`），而 `TY_INT==TI_INT==0`
  ⇒ `EXPR_PARAM.type_val`（读点 `ir_gen.cr:3008`）= 0 ⇒ **`dex?` 形参槽型 = `TI_INT`**（`:3011` 的 `TI_DEX→TI_DEX_S` 分支不触发）。
- 实参转换环门 = `ast_type_val(cpn) == TI_DEX`（`:1954`）⇒ `dex?` 形参**不进环** ⇒ apx 实参不转（`:1965-1968` 不执行）。
- 返回点门 = `g_cur_ret_ti == TI_DEX`（`:2630`），而 `g_cur_ret_ti = fi_return_type(fi)`（`:2988`）= unpack_type 结果 = 0 ⇒ 不触发。

## §2 与相邻面的关系（逐条：正交 or 相交）

### 2.1 (A) 批 **INV-1**（取址槽恒持装箱值）——**相交（真交点）**

- INV-1 表述：地址被取过的可选槽（局部/形参）**恒持装箱值**、表示位恒 1（`docs/superpowers/plans/2026-09-16-opt-rep-follows-storage.md:172`；
  实现点 = LET `:2589-2592`、形参序言 `:3026-3043`、赋值 `:1471-1474`）。
- 交点：INV-1 只保证「**装箱**」，**不保证载荷的形式**。`x : dex? = d`（apx）+ `&x` ⇒ 装箱 + **载荷 bits** ⇒ b2 实测红（15）。
- 另一重交点：INV-1 使「裸」态在取址槽**不可达** ⇒ 取址面退化为「装箱 × {bits, scaled}」两态；本批修法**必须保持**
  「装箱点仍恒装箱、表示位仍恒 1」，只改**载荷形式**（否则会破 INV-1/INV-3 的到达一致性定理）。
- ⇒ 本批**不改** INV-1 的任何判定/置位逻辑，只在装箱前插入形式规范化（顺序修正，见 R2）。

### 2.2 `#78` 批（聚合读丢型）的**读点定型**——**相交（半边）**

- #78 已修面 = 结构体字段读 / 数组·切片元素读 / match 臂载荷绑定（枚举行）/ 比较点声明面查表（`agg_*_read_form`，`ir_gen.cr:405-460`）。
- **不含**面 = 「**optional 声明**的载荷读」：`agg_payload_read_form` 只认枚举行（`:443-460`），`Some` 关键字形无枚举行 ⇒ 返 `TI_INT`。
- ⇒ 本批与 #78 **在同一机制上相邻但不重叠**：本批的读点若并入，判据面（节点级零 alloc）与 #78 同款
  （候选通道 = `irv_decl_ti(match_val)`：LET 已在 `:2517` 登记 optional 声明行 ⇒ **纯表读、零 alloc**）。
- **裁决门 G2**：并入（推荐）或登记为未覆盖面（则本批判据限 `@raw_int` 口径，`v` 参与 dex 运算的面转登记）。

### 2.3 apx 批的漏斗 `dex_slot_norm`（`:1116`）——**相交（被序绕过）**

- 本批**不新增第二个漏斗**：复用同一 `dex_bits_to_scaled`（`:1039`）与既有 `dex_slot_norm`（`:1116`）语义，
  只做两件事：① 把漏斗接进**缺失/序倒**的写点；② 新增「**可选面声明判据**」`dex_opt_*`（节点级 + 纯表读，零 alloc，GC12 纪律）。
- 与 apx 批的**不变量**一致（「聚合/容器面恒精确」），不冲突。

## §5 判据设计

### 5.1 主判据 = **四态对拍**（不是逐例钉值）

对每个「源 × 消耗路径」组合，取四态（裸/装箱 × bits/scaled）**同一语义值**，断言：

1. **对拍式**：四格 ELF 返回值**互等**（关系式 ⇒ 能抓「两格同错」的部分形态，如 bits 与 scaled 混装）；
2. **锚定式**：**scaled 两格**必须等于语义值（经 `@raw_int` 锚定；本批 = `7` 与 `100 + 0`）；
3. **禁第三态**（interp 腿）：bits 源 ⇒ interp ∈ {255, 锚定值}，出现其它值 = **红**（当前 a1 的 15、b4 的 15 正是「第三态」）。

**当前四态实测（改前基线）**：`{15, 7, 7, 7}` ⇒ 对拍失败（第 1 格离群）⇒ 主判据**红**。
