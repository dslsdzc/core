### 1.3 计时面不一致的**性质**（这一节是 S0.0 的存在理由）

`[我·复算]` 我的 `bench2.json` 原始读数（min-of-3，逐条 clean-cache，`nice -n 19`）：

| 语料 | `check` | `cir` | `ccr` | loadavg |
|---|---|---|---|---|
| s500 | 0.303 | 0.805 | 1.204 | ≈12 |
| s1000 | 0.627 | 1.524 | 8.030 | ≈12 |
| s2000 | 1.142 | **25.336** | **20.791** | 12.5 |

**三个不能忽略的事实：**

1. **单调性被违反** `[我·复算]`：`ccr`(s2000) = 20.79 s **<** `cir`(s2000) = 25.34 s。
   而 `ccr` 的工作量**严格包含** `cir` 的工作量（`main.cr`：`cir` 分支在 `df_state_finalize` 后**提前 return**，
   `ccr` 继续跑三个 pass + lower + save）。
   ⇒ **读数已经失去分辨它要测量的量的能力**。这不是「噪声大」，是**协议在该负载下失效**。
   ⚠ **评估的数据没有这个问题**（它的 s2000 `ccr` 13.075 > `cir` 3.288）——**不能因此说我的数据更差；
   只能说评估那三次采样恰好落在机器较空的窗口**（见下条）。

2. **同一命令两次独立 min-of-3 差 7.7×** `[我·复算]`：
   `s2000 cir` 评估 min = **3.288 s**（样本 `3.288 / 11.290 / 21.318`）；
   我的 min = **25.336 s**（样本 `29.185 / 25.336 / 26.970`）。
   **评估的 min 比我的 min 低 7.7×，且低于我三次样本的**最小值**。**
   ⇒ min-of-3 **不足以**在 loadavg ≈ 12 / 4 核的条件下取到真值。

3. **块序采样放大了漂移** `[我·复算]`：`s1000 ccr` 样本 `9.538 / 8.030 / 17.190`，
   紧接着的 `s2000 cir` 块样本 `29.185 / 25.336 / 26.970`。
   **同一块内的三次采样高度聚集，跨块的量级却跳变** ⇒ 漂移在**块间**，不在块内。
   ⇒ **块序（block-sequential）采样是错的**，必须**交错（interleaved）**。

**⇒ 对 §2.3 那 30 s / 72.7 % 的处理**（本档的正式立场）：
- `[推理]` **定性结论保留**：分析面**远贵于**前端，且其增长**远快于**节点数——这一条在我这轮**同样成立甚至更极端**
  （`cir` 在 1000→2000 上 ×16.6，而 `check` 只 ×1.82）。
- `[推理]` **定量结论一律作废**：`72.7 %`、`×4.71`、`≈30.0 s`、`41.27 s` **都不是可复用的常数**。
  **S0 必须先建立新基线，不得以旧基线做「修后」对拍。**

## 二、判据纪律（**本计划的第一等交付物**）

> **为什么判据纪律要单独成节、且排在 S0 之前**：§1.3 已证「修前」读数是**分布**且分布**跨会话不可比**。
> 计量学上的常识：**没有稳定基线的 A/B 对拍不构成判据**。**所以协议本身是被交付的东西，不是脚注。**

### 2.1 测量协议（**计时类判据一律套用；不套用的计时读数一律不得引用**）

| # | 规则 | 理由 / 出处 |
|---|---|---|
| P1 | **`nice -n 19`** 一律（铁律 6）。**不得**为了"测得准"而免 nice | 铁律 6；`canary_check.sh` 亦遵此（其 `CANARY_NO_NICE=1` 仅供自证/牙用） |
| P2 | **逐采样 clean-cache**（`rm -rf .core/cache`，**相对 cwd**） | `.cir` 缓存跨重建不失效 |
| P3 | **交错采样**：`A,B,A,B,A,B,…`（不是 `A,A,A,B,B,B`） | `[我·复算]` §1.3 事实 3——漂移在块间 |
| P4 | **N ≥ 5**（评估与本档首轮都只用 3，**不足以**） | `[我·复算]` §1.3 事实 2 |
| P5 | **每个采样记录 `loadavg`**（采样前 + 采样后各一次） | 「不带负载的计时读数不可比」 |
| P6 | **报分布，不只报 min**：至少给 min / median / max 与样本表 | 「读数不带采样次数 = 分布被当常量」 |
| P7 | **比值优先于绝对值**；比值的**分母必须是同会话同语料的 `check`**（**线性控制**） | `[我·复算]` `check` 是唯一可复现的量（A5：1.19× / 1.03×，比值同构） |
| P8 | **单调性闸**（零成本，必做）：每语料必须 `ccr ≥ cir ≥ check`，且 `×1` 起每步 ≥ 前一步 | `[我·复算]` §1.3 事实 1——**违反即该批读数整体作废，不得解释、不得挑样本** |
| P9 | **阴性对照**（凡断言"变快/不变"）：`check` 的读数必须在两次之间保持同阶（±30 %） | 若 `check` 也漂 ⇒ 是环境不是改动 ⇒ 读数作废 |
| P10 | **禁止跨会话比绝对值**：只允许**同会话**内的 pre/post 比 | §1.3；先例 = 本仓 `docs/superpowers/plans/2026-09-17-spec-grammar.md:360` 的 25.6 s vs 评估的 15.24 s（**同命令、不同会话、差 1.68×，未归因**） |
| P11 | **计时判据不进 CI 门** | 门只 3/5（`check` / `bootstrap-tests` / `selfhost-tests`；`suite` + `full-bootstrap` 只在 `workflow_dispatch` 可达）；且 CI 环境不可控 ⇒ 计时进 CI = 造一条**必然 flaky** 的假门 |
| P12 | **字节面判据照旧进 CI**（非计时） | 见 §2.3 |

### 2.2 协议的**自证**（协议本身也要有判据，否则是自述句）

- **协议自证**：用**已知答案**的合成语料跑一遍——`s500`/`s1000`/`s2000` 上
  `check` 的相邻点比值必须落在 `[1.8, 2.2]`（节点比 ×1.85–1.98）。
  `[我·复算]` 我这一轮：0.303→0.627 = ×2.07；0.627→1.142 = ×1.82 ⇒ **落在带内** ⇒ 协议对"线性量"有效。
- **协议失效的判据**：`check` 的相邻点比值**越出 `[1.6, 2.4]`** ⇒ 该会话全部读数作废，**重测**。
- ⚠ **不得**用 `ccr`/`cir` 做协议自证（它们是待测量，不能用待测量校准测量仪）。

### 3.3 S0.2 —— 修法（**在 S0.1 给出机制之后才写死**）

**候选机制（评估 `[推理]`，前提 = S0.1 证实）**：`pa_in_unsafe` / `is_in_unsafe` 每次调用全扫所有区段 ⇒ `O(节点 × 区段)`。

**`[我·复算]` 现成先例（**同一文件里**，评估实测的那条，我逐字复核）**：

```
src/compiler/region_check.cr:5-11
fn subgraph_containing(node_seq: int) -> int {
    // 显式映射：O(1) 归属查询（g_df_node_region 由 df_create_node 写入）
    if node_seq >= 0 && node_seq < g_df_node_count {
        return r64(g_df_node_region, node_seq * 8);
    }
    return -1;
}
```
- `g_df_node_region` 的**写点唯一**：`dataflow.cr:103` `w64(g_df_node_region, nid * 8, g_cur_sg);`（在 `df_create_node` 内，**每节点一次**）。
- ⇒ **修法是「去掉每调用全扫」，不是发明新算法。**

**⚠ 一处必须**先想清**的语义差（评估未写，本档补）**：
`subgraph_containing(n)` 返回的是 **最内层**区段；而 `is_in_unsafe(n)` 要的是
**「n 是否落在**任一** `SG_UNSAFE` 区内」**。二者**不等价**——
例如 `unsafe { if c { … } }` 里的节点，最内层是 `SG_IF`、但**祖先里有 `SG_UNSAFE`**。
⇒ 修法**必须**是「取最内层 + 沿父链上溯」。

**父链是现成的** `[我·复算]`：
- `dyn_arr.cr:150` `OFF_SG_PARENT : int = 24;  // parent subgraph index`
- `dataflow.cr:57`（`sg_push` 写 parent）、`:87`（`sg_pop` 恢复 `g_cur_sg`）
- **上溯先例（同文件）**：`region_check.cr:70` `rc_releasing_region(alloc_node)`——
  `:68` 注逐字「分配点 → 最近一个「出口归还内存」的区域（含自身；**沿 `OFF_SG_PARENT` 上溯**）」
⇒ ⇒ `[推理]` 修法 = **`subgraph_containing` + 父链上溯**，复杂度 `O(节点 × 嵌套深度)`；
嵌套深度由**句法嵌套**界定（远小于 `g_sg_count`）。

**三处收敛为一份**（**`[我·复算]` 评估说「两份副本」，实际是三份**——本档的更正）：
