目标：消除同族不报错地缺陷：全局行（IR var 索引小于当前函数的 `var_start`）的操作数地址没有经过全局分派，就直接使用 `g2_slot`。`g2_slot` 对全局行返回帧外的伪 rbp 偏移（指向调用者帧的合法位移），因此读侧不报错地得到错误值，写侧不报错地丢失写入，个别形态明确触发 SIGSEGV，而 `corec build` 始终 rc=0。本批统一处理读侧 seam（`e2_load_var` 已存在的形态无关单入口，加新增的 dex 面两个入口），并逐点迁移；写侧和相邻三项按裁决门确定范围。

本批边界：
- 零影响优先：新的 seam 只允许改变全局行的发射字节。所有非可选、非全局形态（包括局部行、`E2_REG_SLOT_BASE` 寄存器槽、既有已修点）的发射字节必须逐字节不变。检查是 ELF canary 加发射面 diff，见 Global Constraints。

## 现状根因（一句话 + file:line）

`g2_slot`（`src/arch/x86_64/instr.cr:55-72`）对全局行返回帧外伪 rbp 偏移（第 71 行；`v < g_current_func_var_start`，因此偏移为正，所以落在调用者帧），而「全局 vs 局部」的分派被要求在每个操作数消费点各自手写（正确者走 `e2_load_var`；遗漏者直接使用 `g2_slot`），因此同族缺陷按 `IR_*` 分支逐个漏：已修 4 处（`IR_LOAD`/`IR_LOAD_FIELD`/`IR_REF` 取址/`IR_LOAD_ENUM_TAG` 读源）后，同族仍有 6 条实际位置 + 1 条次序不变量缺失（B7）+ 1 条仅表实例可达（B8），全族后果统一为读不报错地错值 / 写不报错地丢写 / 个别明确 139，且 `corec build` rc=0、解释器路径正确，所以双路径分歧。

结构判断（本批的立项理由）：这不是「六个孤立的漏点」，而是「判定散落」，同一形态判定（`r64(g_x86_is_global, v*8) != 0`）在 int 面已收进 `e2_load_var` 单入口，dex 面（`e2_sd_*` 五件）与写侧（三处手写 rip 序）从未收编。只修点 = 治标（本仓已有「修 `IR_REF` 后仍漏 `IR_SLICE`/`IR_AWAIT`」的先例）。

## 设计候选（三条；逐条给 改动面 / 风险 / 可证伪检查 / 与 canary 零影响的关系）

### (i) 纯 seam 收编（推荐主体）
法则：全局/局部判定收进单入口，调用点只表达「取哪个操作数」，不再表达「怎么寻址」。
- 新增三个入口（放 `instr.cr`，紧邻 `e2_load_var`；架构轴，OS 轴 `callseq.cr` 消费）：
  1. `e2_lea_glob(buf, pos, var_idx) -> int`，`lea r11,[rip+0]`（`e2_lrb`）+ `g_x86_rip_patch_*` 登记（与 `e2_load_var` 内联段同规约：`pos+3` = disp32 位置）；只在 `r64(g_x86_is_global, v*8) != 0` 时调用。
  2. `e2_sd_ld_var(buf, pos, xmmn, v) -> int`，全局：`e2_lea_glob` + `movsd xmm{n}, [r11]`（`F2 0F 10 /n`，ModRM `mod=00 reg=n%8 rm=3`）；局部：现 `e2_sd_load`/`e2_sd_load1`/`e2_sd_load_x(g2_slot(v))` 逐字节原样（三形按 `xmmn` 分派，字节 = 现状）。
  3. `e2_sd_cvt_var(buf, pos, v) -> int`，全局：`e2_lea_glob` + `cvtsi2sd xmm0,[r11]`（`F2 48 0F 2A 03`）；局部：现 `e2_sd_cvt(g2_slot(v))` 原样。
  4. `e2_sd_st_var(buf, pos, v) -> int`，全局：`e2_lea_glob` + `movsd [r11],xmm0`（`F2 0F 11 03`）；局部：现 `e2_sd_store(g2_slot(v))` 原样。
- 调用点迁移：B1（520/521）· B2（468）· B5（1345，改走 `e2_load_var`）· B4（1334/1335，改走 `e2_load_var`）· B6（`callseq.cr:73`/`:126` 改为 `e2_sd_ld_var`）· B7（按裁-SEAM-4）· B8（按裁-SEAM-5）。
- scratch 寄存器安全性论证（必须写进实现注释 + 检查）：全局形用 r11（与 `e2_load_var` 同寄存器），每次 `lea` 后立即消费进 xmm/寄存器，不跨指令存在；B1 双全局操作数 = 两次「lea r11 + movsd xmm{n}」序列，xmm0/xmm1 各自独立，因此无需第二 scratch；`e2_push_xmm0`（`instr.cr:393-398`）在 dex 栈参序列中在装载之后，所以无 r11 冲突。
- 改动面：`instr.cr`（+4 助手、~8 调用点）、`callseq.cr`（2 调用点 + 取裁的 B7）。零前端、零 `.ccr`、零解释器。
- 风险：1 助手内分支写错，因此非全局行字节变化（检查 = canary + 发射面 diff 直接拦截）；2 r11 存在期假设错，所以需在 T4 用「双全局 B1 探针 + 局部对照」实测。
- 可证伪检查：1 六点探针双路径同值（见 “探针设计表”节）；2 canary IDENTICAL；3 `.ccr` 四值不变；4 全量检查集（Global Constraints）。
- 与 canary 零影响的关系：canary 档 `tests/suite/ptr_arith.cr` 实读无全局、无 dex（`cat` 全文 15 行；无 `g_` 行、无 `dex`），因此新全局分支构造性不可达，非全局分支 = 逐字节复制现状，所以预期 IDENTICAL（仍须实测，不得只做构造性论证）。

### (ii) seam 收编 + 完备性清单/限制（推荐 = (i) + 本项）
在 (i) 之上加两层防护：
