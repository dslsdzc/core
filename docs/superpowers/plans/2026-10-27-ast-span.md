# AST span：8 字节字节区间替换行/列

> 状态：已批准，待实施
> 日期：2026-10-27
> 关联：`src/compiler/source.cr` · `src/compiler/dyn_arr.cr` · `src/compiler/lexer.cr` · `src/compiler/parser.cr`

## 概述

AST 节点当前用两个 8 字节字段存行号和列号，节点占 72 字节。改成两个 32 位字段存全局字节区间，节点降到 64 字节；行号和列号由 SourceManager 在需要时换算。这样诊断、LSP 和 dump 都从同一个来源取位置信息，不再依赖全局行表反查。

## 决定

1. 节点位置字段是 `lo`、`hi`，各 32 位，合起来 8 字节。`lo` 是起始字节，`hi` 是结束字节，区间左闭右开。
2. 偏移是全局字节偏移。SourceManager 给每个文件分配 `byte_base`，文件内偏移加上 `byte_base` 得到全局偏移。
3. 文件身份由 `lo` 落在哪个 `[byte_base, byte_base + len)` 区间决定。文件按注册顺序排列，查找用二分。
4. 行号、列号由 `sm_span_line(lo)` 和 `sm_span_col(lo)` 从该文件的 `line_starts` 二分得到。现有 `sm_line_index` 已经是这个算法。
5. `ast_line(node)`、`ast_col(node)` 保留为包装函数，签名不变。调用点不改。
6. 解析器写节点时传 token 的 `lo`/`hi`。token 现有的 `file`/`lo`/`hi` 三个字段保持不变，`lo`/`hi` 改为全局偏移。
7. 合成节点（monomorph 克隆之外的补丁节点）用零宽区间，即 `lo == hi`，指向触发点所在 token。没有触发点时写 `lo = hi = 0`，换算后是第 1 行第 1 列。
8. monomorph 克隆节点时整体复制原节点的 `lo`/`hi`，不重新定位。
9. `.ccr` 不因本改动变化。行号只出现在诊断和 LSP，不进产物。

## 数据结构

节点布局，改前 9 个 8 字节字段，改后 8 个：

| 字段 | 改前 | 改后 |
|---|---|---|
| `kind` | 8B | 8B |
| `a` | 8B | 8B |
| `b` | 8B | 8B |
| `c` | 8B | 8B |
| `int_val` | 8B | 8B |
| `type_val` | 8B | 8B |
| `data` | 8B | 8B |
| `line`、`col` | 16B | — |
| `lo`、`hi` | — | 8B |
| 合计 | 72B | 64B |

SourceManager 新增字段：

| 字段 | 含义 |
|---|---|
| `byte_base` | 该文件第一个字节的全局偏移 |
| `byte_len` | 文件字节数，已有 |
| `g_sm_byte_total` | 下一个文件的 `byte_base` |

## 实施顺序

每一步都必须让树可构建、测试可跑。

1. **SourceManager 加字节轴**：`byte_base` 分配、`sm_span_file(lo)`、`sm_span_line(lo)`、`sm_span_col(lo)`、`sm_span(lo, hi)`（已有同名函数，扩展它）。这一步只增不改，编译器和产物零变化。
2. **token 的 lo/hi 改全局**：`tokenize` 写入时加上 `byte_base`。此时还没有调用方依赖，验证方式是新旧值相差一个常量。
3. **节点布局切换**：`ESZ_ASTNODE` 72 → 64，`OFF_AS_LINE`/`OFF_AS_COL` 换成 `OFF_AS_LO`/`OFF_AS_HI`，`ast_line`/`ast_col` 改为经 SourceManager 换算，新增 `ast_lo`/`ast_hi`。解析器的 `tok_ln`/`tok_cl` 换成 `tok_lo`/`tok_hi`（约 222 处，机械替换）。
4. **消费方对齐**：`diag.cr` 不再用 `g_line_fileid` 反查文件，改用 `sm_span_file`；`lsp/analysis.cr` 的位置换算同样改用 span；`dump.cr` 如有行号输出，经 `ast_line` 保持。
5. **monomorph 与合成节点**：检查全部 `ast_alloc` 直调点，确认 span 被复制或被显式置零宽。
6. **收尾**：更新 `docs/ir-schema` 中描述 AST 布局的段落；登记 `g_line_fileid` 的剩余用途（`.ccr` 行号字段、LSP 行偏移），为后续删除做准备。

## 验收

1. `check src/compiler` 通过。
2. 全部 selfhost 套件通过，重点：`test_cast`、`test_struct_impl`、`test_import_graph`、`test_lsp_visibility`、`test_diag_gate`。
3. 诊断行号与改动前一致。用 `tests/selfhost/test_diag_gate.py` 的逐条行号断言比对。
4. LSP 定义跳转、诊断范围与改动前一致（`test_import_graph` 的 LSP 用例 + `test_lsp_visibility`）。
5. canary 5/5 不变。AST 布局不进 `.ccr`，所以不应有重锁。
6. 内存：`check src/compiler` 的峰值 RSS 不高于改动前；节点数乘以 8 字节的差值可估算。
7. 编译时间：`check src/compiler` 不比改动前慢超过 2%。超过就停下查原因。

## 不包含

1. 删除全局行表 `g_line_fileid`。它仍被 `.ccr` 行号字段和部分 LSP 路径使用，留到后续批次。
2. 修改 `.ccr` 的行号编码规则。
3. 把 token 的 `file` 字段删掉。本轮只改 `lo`/`hi` 的含义。
4. 多文件合并的字节空间压缩。全局偏移直接按文件顺序累加。
