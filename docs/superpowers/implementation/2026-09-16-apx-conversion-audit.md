# apx（dex）形式转换完备性审计，bits 与 scaled 跨边界走查

日期：2026-09-16 · 性质：只读审计（零构建、零测试运行、零源码改动）· 体例：照 `2026-09-16-preexisting-bug-ledger.md`

## 0. 形式模型（读码）

| 形式 | 常量 | 语义 | 默认世界 |
|---|---|---|---|
| 精确（scaled） | `TI_DEX_S`=8（`ast.cr:274`）| 定点缩放整数，S=10⁶ | 跨函数边界统一形式（`ir_gen.cr:971-972`）|
| 近似（apx） | `TI_DEX` | binary64 位模式（快路径） | 仅 apx 标签的局部变量（`parser.cr:819`：`apx` 是 LET 专属标签）|

转换机构（4 个 helper，全部在 `ir_gen.cr`）：`dex_bits_to_scaled`（`:982`，bits 到 scaled，6 位定点半进舍入）· `dex_scaled_to_bits`（`:1016`）· `dex_scale_int`（`:1027`，int 到 scaled ×S）· `dex_store_adjust`（`:1044`，按目标槽 IR 型分派前两者）。
契约（读码自注释 `:973-976`）：「存储/边界处按槽位形式转换」，本审计即逐边界核对这条契约。

转换调用点全集（11 处）：`:1253/:1259/:1272/:1273`（二元运算操作数对齐）· `:1349`（局部赋值）· `:1366`（全局赋值）· `:1703`（`@raw_int`）· `:1827/:1832`（调用实参环）· `:2424`（LET）· `:2495`（返回点）。

## 3. N-3 / N-1 同族判定（本审计最重要结论）

结论（修订后）：两条为同一根因，前端转换环的覆盖面缺失项（两个触发模式），因此下一组 = 一个阶段。
（修订留痕：本文件首版按「N-3 = 门 / N-1 = 前后端约定交互」判两条独立根因；补齐 7a 与 callee 侧读码后据实改判，理由见下，旧表述不会无提示抹去。）

共同根因 = 转换环（`ir_gen.cr:1806-1839`）是「Core 函数 dex 实参」的唯一转换点：全仓再无其它实参转换通道（转换调用点全集见 0 节），而两个后端在调用边界只做运输、零 dex 逻辑（ELF：`callseq.cr:66-132` 按 `irv_type` 分类 + `frame.cr:115-140` 保存；解释器：`interp.cr:240-244` 按位置拷贝实参、无任何 dex 判断）。因此环漏转一个实参，因此双路径必同错（同一个错 IR），与 (B) 两条实测的「双路径同错」形态一致。

触发模式 1（= N-3）：调用形态门。门 `:1806` 写死 `ast_kind(func_node)==EXPR_IDENT`，因此 `EXPR_FIELD`（方法调用）整段跳过（表 A 1c）。

触发模式 2（= N-1）：环内逐形参的配对/类型读取未命中。机理（读码判定，高置信）：
1. 环按 `ast_type_val(cpn) == TI_DEX` 决定转换（`:1821`），`cpn` 沿「下一个 `EXPR_PARAM`」前扫（`:1839-1843`，与 F4/#21 同族的形参链导航），若某深度的形参类型读取未命中，因此该实参不转换；
2. 未转换的 apx 实参在后端按 `irv_type == TI_DEX` 被判为 binary64 类（`callseq.cr:71/97/99/125`），因此走 XMM / float 栈；而 callee 形参槽恒为 `TI_DEX_S`（`:2866`），因此
 - 主错 = 值形式：callee 拿到 bits（按 scaled 读），因此无提示错值；
 - 次错（可达、未实证）= 落位公式不对称：callee 的栈参偏移按形参序号算（`frame.cr:129/131`：`caller_off := 16 + (pi - 6) * 8`），caller 的落栈判定按类型类（`callseq.cr:89-105`），因此类混合时两边对「第 7 个实参是否在栈上/第几槽」可给出不同答案（同一实参被放进 XMM 而 callee 从栈读）。
3. 两路径同错的机理：主错发生在前端已定的 IR（值形式未转换），因此 ELF 与 interp 一致地错是。

须实测才能逐一坐实（插模拟点，供下一组使用）：
- 插模拟点 A（环内）：`:1815-1843` 每轮打印 `cpi` / `ast_type_val(cpn)` / `irv_type(arg_vars[cpi])`（转换前后），因此直接看第 9 形参是否被环看见：若 `ast_type_val` ≠ `TI_DEX`，因此模式2坐实；若 = `TI_DEX` 且转换发生，因此模式2证伪，因此转查落位公式（次错）。
- 插模拟点 B（分类 vs 落位）：`callseq.cr:66-105` 打印每实参 `irv_type(fa+i)` + 类计数 + 落栈判定；`frame.cr:118-140` 打印每形参 `pty` + `caller_off`，因此两表对照即判「次错」是否存在。
- 改写条件：若插模拟点 A 显示环确已转换第 9 实参，因此 N-1 根因回到「落位公式不对称」（与 N-3 不同），因此本行改回「两条独立根因」（检查已给，可直接改）。

## 4. 优先级建议

| 优先级 | 条目 | 理由 |
|---|---|---|
| P0 | B-2（返回）/ B-3（字段）/ B-4（元素）/ B-5（元组）/ B-6（载荷）| 无提示错值 + 双路径同错（本项目最主要的危害）；全部普通代码可达（无需 apx 生僻语法：B-2 只要函数返回局部 apx 值）|
| P0 | B-1（=N-3 方法调用）| 同上；`impl` 方法是主语法 |
| P0 | B-9（=N-1 栈参）| 同上（(B) 已实测）|
| P1 | B-7（`as`）| 无提示；`as` 在 dex 上的语义未定，因此需先裁语义（「`d as dex` 是恒等还是转换」）再修 |
| P1 | B-8（比较）| 无提示，但派生自 B-3/B-4，因此修好聚合面后自然收敛；保留探针防回退 |
| P2 | 7a 全局初值（待核）| 本轮未读完 `inject_global_init` 区，因此未实证；若与 7b 同源则无需修 |

修法方向（已获维护者背书 2026-09-16，理由 = 「语义一致性」哲学：判定应以语言层语义（声明型/签名型）为准，不该以已降级过的 IR 值型为准）：把「按槽位形式转换」的唯一汇聚点收敛到 `dex_store_adjust`（`:1044`），并让所有写点（含 4 类聚合写 + `as` + 返回）与读点定型（`:2520` 等处的 `TI_INT` 硬定型，因此应保留元素/字段的声明型）都过这一汇聚点；转换触发应以「声明型/签名型」而非「IR 值型」为准（B-2/B-9 的共同教训：值型在多处丢失或被改写）。

## 5. 边界清单外的新发现（补）

1. 聚合读的统一类型丢失（`:2520` `new_ir_var("field", TI_INT)`；元素读同类），因此是 B-2/B-8 类「转换不触发」的放大器（不止 dex：可选表示的 `rep`/声明面亦受影响，与 (A) 阶段 T3 的「声明面登记」修法正交，勿混）。
2. `@raw_int` 是唯一显式形式通道（`:1703`）：所有探针的期望值检查都应经 `@raw_int` 表达（否则比较面自身即触发 B-8）。
3. extern 面已排除（1b）：apx 实参照传 = C ABI（binary64）正确；但 extern 返回值在 Core 函数里 `return` 会触发 2a（B-2 的变体）。
