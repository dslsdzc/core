# 字符串插值展开实施记录

> 对应计划：[plans/2026-09-18-interp-expansion.md](../plans/2026-09-18-interp-expansion.md)

## 概述

记录覆盖 2026-09-18 的字符串插值展开，包括对抗复核五条的处置、零影响与换代、未覆盖面、纪律增量和两个检查的分工。实现已实施并自测。核心决定是保留 `CIR_CACHE_VER` 从 21 到 22 的换代，但把依据改为编译器身份检查加语义面变化，因为 `.cir` 的两个指纹都不覆盖函数体。切段和洞扫描放在 lexer，按 part-token 设计把洞边界作为 token 边界交给 parser，并显式跳过嵌套字符串、char 字面量、行注释和块注释。非插值语料 37 档的 `.ccr` 和 ELF 逐字节 IDENTICAL。插值的硬错为 P027、P028、P029。`char` 洞、`dex` 洞两形态、泛型洞 `T` 和 bootstrap 不展开仍属于未覆盖面。

## 改动

### D 换代

保留 bump，版本从 21 改为 22，但依据改正。

复核实测更正：`.cir` 的两个指纹都不覆盖函数体。`ir_gen.cr:3964-3996` 的注释声称 walk body，代码实际是 stub。展开不改源文件字节，fp 和 sig 前后完全相同。计划初稿“指纹会变，因此必须 bump”的前提与代码相反。

真正的防线是编译器身份检查。`cir_cache.cr:549-551` 的规则为 `cid == 0 || entry_cid != cid` 时 miss。`cid` 是运行中 ELF 的全文件哈希。任何源码改动都会触发重建，身份必然变化，旧条目整体被拒收。

处置有两条。第一，把 `cir_cache.cr` 的本代注释改为“依据为身份检查加语义面变化”，并写明指纹不覆盖函数体。第二，登记 `#2026-09-18-16`：指纹不覆盖函数体，身份检查是唯一防线；若将来身份检查降级，函数体级编辑会不报错地恢复旧 IR。

### B 配平

复核建议 lexer 保持原文保真，配平放在 parser 的切段和洞步骤，并且必须用同一词法器重扫，或至少显式跳过字符串、char 字面量、注释和转义。禁止手写 `{}` 计数。复核点名的漏点是 `'{'` 和洞内注释。

本实现把切段和洞扫描放在 lexer。这是 part-token 设计的必然结果：洞边界要作为 token 边界交给 parser。洞扫描已按复核要求显式跳过四类内容：嵌套字符串字面量，含转义；char 字面量；行注释；块注释。扫描在跨行或 EOF 时终止，语义等价于“用词法器扫描”。

偏离理由有三条：

1. part-token 让 parser 无需知道 `{}`、字符串和注释规则，它只消费 token。
2. “用同一词法器重扫”在 lexer 内部不可行，因为会自引用。在 parser 侧则需要重建 token 边界和位置映射。
3. 检查已固定三类漏点，即 `char_lit_in_hole`、`nested_str_in_hole`、`block_comment_in_hole`，以及行注释洞。行注释洞报 P027，名称为 `linecomment_hole`。

残余风险：若日后新增词法形态，例如新注释形式或新字面量形式，洞扫描需要同步修改。检查集合当前只覆盖上述四类。

### C 就地改写

就地改写有四个检查点。

1. 别名：parser 对段和洞不去重，每个 part 新建节点。段为 `EXPR_STRING`，洞为 `EXPR_INTERP_HOLE`，各自独占。因此就地改写不会连带改到别处。
2. 新 kind 的消费者清单：本次逐个核对并处置。`monomorph.cr::gen_clone_tree` 增加显式分支，默认后备会把 `d` 当作子节点或不报错地丢树。`ir_gen.cr` 增加残留后备硬错 P029，洞到达发射面说明 checker 漏走某条路径，因此响亮拒绝，绝不当作空值。`pass.cr`、`opt.cr`、`dump.cr` 不接触，因为洞在 checker 期已被改写消灭。`src/lsp/analysis.cr` 本次同改，span 规则按 part 计算并配平。
3. 改写时机与指纹：改写发生在 checker，指纹在 `ir_gen` 之后计算。读写两路都看到改写后的 AST，结果稳定。实施纪律：不得把改写挪到 `ir_gen` 之后。
4. 未改写路径：extern 早退、实例体等路径上，洞可能原样进入 `ir_gen`。已增加 P029 后备硬错。

### A 补齐

`bool` 转换器：全仓原来没有，本次在 `fmt.cr` 新增 `bool_str(b) -> string`。该函数不经过 int，返回 `"true"` 或 `"false"`。不合成 `if` 的原因是手写 `"v=" + if b {…} else {…}` 同样得到 rc=139，属于预存缺陷，登记 `#2026-09-18-14`。因此只能走调用面。

`chr` 签名：`chr(c: int)` 与 char 洞的 `TI_CHAR` 不符。实测 `chr(char)` 输出空，原因是把串指针当作码点。若改为恒等，则会遇到 `string + char` 导致 rc=139，登记 `#2026-09-18-13`。因此 `char` 洞在本次按 P028 硬错处理，列为未覆盖面，见 `-11` 条目。

泛型洞 `T`：显式判为硬错，并列为未覆盖面。洞型在实例化前不可得，与 (乙) 泛型擦除同族。检查为 `C.generic_hole.reject`。

“其它”类型：`dex` 的 bits 和 scaled 两形态各一例、struct、泛型 `T` 已进入检查。其余类型，包括 unit、never、dyn、元组、数组、可选、枚举，走同一条 P028 后备分支，检查抽样覆盖。

### E 检查补六类

六类检查全部实施：

1. `${}` 为空，报 P027。
2. 泛型洞，报 P028。
3. `dex` 两形态各一例，报 P028。
4. `bool` 转换，检查 `bool_str` 存在性，并断言 `"true"` 和 `"false"` 的值。
5. 未闭合两形态，换行终止和行注释内 `}` 也归为未闭合。
6. `\${` 反斜杠约定，使用 `escaped` 例。

断言面是运行值，不是 corec rc。值组全部用 `println` 取得实际值后断言。

build 面零产物做显式断言。`-o` 和 `<out>.ccr` 都不落盘，C 组每条都断言 `not art`。

既有检查集合拦截：`nested_braces` 用例随展开一并重定，值断言从“原文”改为“展开后”。本次改了 lexer，即 part-token，因此按复核的“二选一”纪律，同阶段更新该档并修改注释。

两个前端分歧：self-hosted 展开，bootstrap 不展开。D 组把该事实固定成检查，随阶段登记，见 `-11` 条目。

### 零影响与换代

非插值语料：`tests/suite` 和 `tests/fixtures` 的 37 档 `.ccr` 和 ELF 逐字节 IDENTICAL，对照为展开前二进制。

`check src/compiler/main.cr` 的 rc=0。自源即语料。P027 诊断文案里曾带 `${}`，导致自举检查自己源码时立即失败，因此已把 `$` 转义。

canary 的内容面发生变化。`fmt.cr` 增加 `bool_str` 后，凡 `import fmt` 的程序都会变大。因此按裁定 ① 同阶段更新，保留旧值，并把“内容面不等于发射面”的区分写入值表头注。

`CIR_CACHE_VER` 从 21 改为 22。语义面原因是含插值的源在修复前后生成的 IR 不等价。

### 未覆盖面

显式登记，理由为实测：`char` 洞、`dex` 洞两形态、泛型洞 `T`、bootstrap 面不展开的分歧、洞扫描对新词法形态的同步。最后一项属于残余风险。

### 纪律增量

1. 版本号域同样适用“先合先占”。本次原定 `CIR_CACHE_VER 21`，但 `#123` 先合并并占用了 21，属于串域阶段，因此本次改为 22。这与 TODO 取号域是同一个问题，`#125` 的 `-11` 和 `-12` 并集冲突同源。落笔时先 fetch 查看 develop 当前值，再定号。并集冲突要在同一提交里重排并记录。
2. 换代同步更新必须声明取数环境，本地或 CI run。本次值表注已声明“本机空缓存状态加同提交 CI 档同值”。
3. canary 值对编译器源码的任何改动都敏感，包括 intern 顺序位移。编译器自身的字符串集一变，被编译程序的 `.ccr` 串域 id 就会顺移。因此同步更新必须在所有编译器改动落定后做一次，不要中途更新。

### 两个检查的分工

| 检查 | 面 | 检查内容 | 本次实例 |
|---|---|---|---|
| `corec check src/compiler` 等 self-hosted 检查面 | 诊断 | 自源即语料。新代码进入必经路径后，任何一条诊断都会失败。 | 插值 P027 文案里带 `${}`，导致检查自身源码时失败，已修。 |
| CI `check` job 的 bootstrap 构建面 | 语法和构建 | 自源语法面可用性等于 bootstrap 面可用性。本地 corec 能编、bootstrap 会中断的形态会被发现。 | S2 的 `as` 转换：self-hosted 探针可用，bootstrap 四形态全部 parse 失败，导致构建立即失败，因此全量回退。 |

纪律有三条：

1. 验证“编译器源码可用的语法”必须使用 bootstrap 面，探针要用 bootstrap 编译一遍。
2. 回退的检查是清单和插模拟回到与基线逐点一致，不是“看起来没事”。
3. 同类问题已有四例，包括 `as`、`@builtin(args)`、`|` 和 `&`，以及与可用的 `@name` 标记形对照。
