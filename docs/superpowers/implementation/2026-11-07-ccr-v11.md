# .ccr v11: drop REG, SYM owns function NOD ranges

日期：2026-11-07
分支：`format/ccr-v11`

## 1. 格式

v11 是 8 段：

```text
STR(1) TYPE(2) IFACE(3) SYM(4) NOD(5) ENT(6) EDG(7) CASE(8)
header: magic "CCR1", version 0x000B0000, seg_count 8
table:  8 × 12B, first body at 112
```

SYM 函数头从 24B 增到 28B：

```text
{name u32, param_count u32, ret_type u32,
 instr_start u32, instr_count u32, first_ent i32, last_ent i32}
```

`instr_start/instr_count` 直接给出函数的 NOD 范围；loader 要求它们连续铺满
`[0, nod_count)`，零长度函数允许。REG 段、`root_region`、`ccr_func_root_sg`
和 REG 解析/校验全部删除。

`g_sgs` 保留为前端 region 表和 `.cir` 缓存结构，但 `.ccr` loader 不再重建它。
v10 及更早版本整类拒收。

## 2. 尺寸与 ELF

冷态 canary：

| artifact | v10 | v11 | delta |
|---|---:|---:|---:|
| pa_ccr | 100202 | 98142 | −2060 |
| pa_static_ccr | 100314 | 98254 | −2060 |
| gt_ccr | 137022 | 134170 | −2852 |
| gt_static_ccr | 137134 | 134282 | −2852 |

ELF canary 不变：`fd37b88a…`，61622B。差值归因 = 删除 24B/region + SYM
函数头 +4B/function 的净和；`.ccr` 值已按 canary 换代纪律在同一批记录旧值、
新值、原因和出处。

## 4. 后续

- match 热路径提示不能继续假设 `.ccr` 有 REG；需要另设载体（如 `.coi` 或新只读段）。
- 若未来 corearch 需要 region 感知优化，应显式新增段并升版本，不得恢复
  “REG 只作为校验数据”的旧形态。
