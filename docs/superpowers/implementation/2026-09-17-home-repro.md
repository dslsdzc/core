# 第 4 批：#82/#83，`.ccr` 跨机不可复现（`$HOME/.core/lib/*/index`）与家目录硬编码实施记录

> 对应计划：[plans/2026-09-17-home-repro.md](../plans/2026-09-17-home-repro.md)

## 概述

记录覆盖 2026-09-17 的第 4 批 T0 至 T5，工作区为 `core-modws`，分支为 `feature/home-repro`。本批处理 #82 的 `.ccr` 跨机不可复现、#83 的家目录硬编码后备，并顺带消除 #99 的越界写堆。核心改动是把索引函数注册从主符号表移到侧表，注册期不再 intern 索引字符串；主表有同名符号时不物化侧表条目，保证用户源码的 `.cr` 声明优先；删除 `check_all` 的保全缓冲和回填循环。新档 `test_so_index_repro.py` 为 8/8 PASS，五个 CI job 全部 rc=0，全枚举为 65/66，唯一失败与本批无关。另发现并登记一个预存缺陷：调用索引独有名字并使用 `--static` 时，构建 rc=0 但运行 rc=139。

### 三项改动

1. #83 家目录硬编码后备。现象是 `HOME` 未设时，编译器去读原开发者家目录。根因是 `module.cr` 的 `if str_len(home_dir)==0 { home_dir = "<写死常量>" }`。修法是嵌套 if，只在 HOME 非空时查索引。不能写 `&&`，因为 bootstrap 会对两侧无条件求值。检查为 J4 静态零命中加 J5 行为，`unset` 等价于空。算顺带的原因是它与 #82 在同一段代码、同一读点，改 #82 必然要重写这段。
2. `.cr` 声明被索引覆盖。现象是主机家目录里的一个文件改写了用户源码声明的含义，`print` 和 `println` 被解析为 SO_FN。根因是导入期注册，加上 `find_gsym` 反向扫描命中表尾 SO_FN。修法是主表有同名时不物化。检查为 J2 良性档零影响，前批实测为“同尺寸异 sha、四段扰动”。算顺带的原因是它是侧表改造的唯一自然位置，不定义优先级就得保留覆盖行为。
3. #99 越界写堆。现象是索引超过 128 行时越界写。N=200 不报错地，N=2000 对合法 `read_file` 报假诊断。根因是 `check_all` 三缓冲 `alloc(128*8)` 加写入无界。修法是消除实现方式。惰性物化晚于复位，保全块变成不可达代码，因此整块删除。检查为 J9，N=2、N=200、N=2000 的产物逐字节相同且 rc 正常。算顺带的原因不是顺带修循环，而是修 A 使 B 的实现方式消失，比单独修更彻底。

### 突变控制

突变在仓库外实际拷贝进行，命令为 `jj workspace add /tmp/mut1 -r @`，改完后构建并复测探针。

M1 去掉 `find_gsym` 的侧表回退，改为恒返回 `-1`。结果仅 C3 和 J3 失败，失败信息为“有索引时 use_ext 应 rc=0，实际 1”，其余 7 条仍通过。该结果说明关键面被检查真正固定，且信号精确，不是一片失败。

M2 恢复导入期注册，把 `reg_so_funcs` 尾部改回 `str_intern` 加追加 SYM。结果 C1 两种形式失败，数值为 `142765` 对 `142793`，正是改前的 +28B 签名；C2 良性档失败；C4 和 J9(N=2) 失败；C3 失败。该结果说明产物面检查确实能发现改前行为。

M2 的 C3 失败是复合效应，不是 M2 单因。M2 恢复了导入期注册，但 T3 已删除保全块，那些条目在 `g_sym_count` 复位时被销毁且无人回填，因此 `print_int` 找不到，rc=1。这不影响该突变证明产物面检查有效，但如实记录其复合性。

### 预存缺陷

本批发现一个预存缺陷，已实测对照，非本批引入，登记为 TODO #2026-09-17-3。

现象：调用“索引独有名字”并使用 `--static` 时，构建 rc=0 但运行 rc=139。机理：`SYM_SO_FN` 让未知目标看起来“已定义”，因此走直接调用路径，不记录 `g_x86_ext_rel_*`，`corearch.cr` 的 F16② 守卫不触发。对照实验：改前版编译器 `/tmp/prefix-check`，基于本批改前提交，同样 rc=0 且运行 139，因此与本批无关。未修，属于本批范围外，检查见 TODO #2026-09-17-3。
