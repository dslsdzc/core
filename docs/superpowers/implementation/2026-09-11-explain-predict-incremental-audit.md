### 0.2 论题

三条线索是同一个机制在三种用途上的表现：

> 把「编译器做出的决定」变成图上的正式对象（决策记录）。
> 解释是读取这些记录，回答为什么这样做；预测是记录的一个子类，给出这种做法的资源上界；增量是记录的依赖闭包，说明它依赖什么，以及什么变化会使它失效。

可解释面向人，可预测面向调度和约束，语义增量面向机器；三者共用 4 节的记录表和依赖边，不各自建一套。

计划 1.4 节的报告部分（2026-09-11 追加）是同一机制在确定性轴族上的表现：`D_value`…`D_mapping` 的逐项状态 = 该轴上的决定记录；不确定性 provenance 链 = 同一条 `evidence` 闭包的另一种读法（从「为何选」读成「这个不确定性从哪来」）。因此它是第四条线索，不是第四个系统（1.7 节）。

## 1. 可解释（`core explain`）

### 1.1 原则：自动化但不隐藏过程

编译器替用户完成工作，但不应隐藏做出决定的过程。可解释的标准不是「能打印大量信息」，而是：

1. 用户能从一个他能指认的定位点（源码位置 / 符号 / 图节点）出发，问一个他关心的问题类，得到编译器实际做过的决定及其原因；
2. 答案只由产物决定，不能靠「重新运行编译器并打开日志」得到，同一产物两次查询必须逐字节同（与 3 节同一条规则）；
3. 答不出就说答不出（`unattributed`），不得凭空生成理由，这是 1.2 节原则 3「义务不会无提示消失」在解释面的同构规则：解释不会无提示凭空生成。

反面（明确不做）：把 `explain` 做成又一个 dump 通道。现状已有 7 个 dump 旗标（`--dump-entries` / `--dump-coexist` / `--dump-regassign` / `--dump-objects` / `--dump-events` / `--dump-table` / `--check-regalloc`），它们是整图转储：无定位点、无问题类、无稳定 schema、不回答「为什么」。（原第 8 个 `--type-shadow-dump` 已随 R2 P5 Task 5 影子通道下线删除，R2 P6 Task 5 勘误。）

### 1.2 查询面：定位点 × 问题类

定位点（用户指认得出的对象）：

| 定位点形态 | 语法（草案） | 解析路径 |
|---|---|---|
| 源码位置 | `corec explain FILE.cr:LINE:COL` | 复用 `src/lsp/analysis.cr` 的「位置到 令牌到 符号」反查（快照只读，不触发检查） |
| 符号 | `--fn NAME` / `--global NAME` | `g_funcs` / 符号表 |
| 图对象 | `--node DFN` / `--instr IRN` / `--region ID` | `.cir` / `.ccr` 产物 + dump 通道 |
| 记录 | `--record ID` | 决策记录表（L9 内容寻址 id） |

问题类是由各生产者注册的开放清单（不是 CLI 硬编码 switch，否则每新增一个 pass 都须改 CLI，变成逐项特殊处理）：

| 问题类 | 问什么 | 生产者（决策产出点） | 就绪度 |
|---|---|---|---|
| `checks` | 这条指针或下标为什么插入了 runtime check | `ext_safety.cr:18` `ext_safety_on_array_access` + `ir_gen.cr:17-65` F11 长度侧表（`g_ir_slice_lens`）+ `IR_BOUNDS_CHECK`（`ast.cr:559`）+ checker R002 | 目前已有（S-D1 切片） |
| `ptr` | 这条指针为什么判定为安全 | `ptr_analysis.cr` 三 pass + `region_check.cr` + `provenance_verify.cr`；LSP hover v1 已有「points-to 闭包近似 / 方法 = 产生节点」 | 目前已有（近似） |
| `placement` | 这个节点为什么放在 CPU 上，为什么被驱逐或再生 | `docs/regalloc-cache-mapping.md`（寄存器分配 = 缓存语义映射实例）+ `--dump-regassign` / `--check-regalloc` | 部分（后端侧已有 dump，缺记录） |
| `bounds` | 这个循环或序列的上界来自哪里 | `bounds-inference`（待实现，TODO「边界判定图 pass」）+ F11 长度来源链 | 待 pass 实现（2 节） |
| `vectorize` | 为什么没有向量化 | auto-vectorize（TODO 性能自动化族归 S-C） | 未实现，`explain` 必须能答「生产者未产出记录（功能未实现）」，而不是猜 |

最后一行是设计的关键约束：查询面对没有记录的问题类必须给确定答案，答案分三种，「未实现」「未评估」「评估后拒绝」，三者不得混同（`alternatives` 字段区分：空 = 未评估，非空 = 已评估被拒）。

### 1.3 决策记录的保存方式（本文的核心数据结构）

一条记录是一次编译器决策的内容寻址快照：

| 字段 | 语义 | 备注 |
|---|---|---|
| `id` | 内容哈希（kind + subject + 输入摘要 + 原因码） | L9：不随构建序号变化 |
| `kind` | 记录类别（开放注册：`check_emitted` / `ptr_verdict` / `reg_choice` / `bound` / `obligation` / `cache_verdict` …） | 与问题类多对一 |
| `subject` | 图对象引用（DFNode / 边 / region / IR 指令 / 符号 / 源码 span） | 与 `.cir`/`.ccr` 的既有 id 空间对齐 |
| `phase` | 产生阶段（checker / ir_gen / dataflow / 判定引擎 / regalloc / emit） | 决定由谁负责 |
| `choice` | `selected` / `rejected` / `forced` / `unknown` | 四种取值，与引擎的三态（真、假、unknown）同构 |
| `cause` | 原因码 + 参数（规则 id / 启发式 id / 计数器 / 预算余量） | 原因码是稳定标识符，不是自由文本；人读文本由渲染层生成 |
| `alternatives` | 被拒方案 + 各自原因码（可空） | 空不等于拒绝，空表示未评估 |
| `evidence` | 输入引用集（图节点 / 侧表项 / 类型项 / 约束） | 同时是 3 节的依赖边（4.1 节） |
| `determinism` | `det` / `heuristic` / `env` | L3；含 `heuristic` 或 `env` 的记录不得跨构建复用（3 节） |

单一依据（决定 D27 / A 线 M1）：本表是全仓唯一的 schema 来源；使用者（如 S-C 5 节 R1）只引用本表字段集和各自的补充项，不得另建字段表（S-D 4.1 节要求避免两处定义不一致）。

不需要重写的部分（复用依据）：记录表不是新的分析，它只是把既有产出记录下来，迁移期的影子对照途径（从 R2 P1 起使用，已随 R2 P5 Task 5 全部移除）曾把判定决策记成分类计数（AGREE / OLD_STRICTER / OLD_LOOSER / UNKNOWN），只是没有 id、没有 subject、没有写入磁盘；目前同类的保存位置是 `--verify-named-dedup` / `--verify-evp-nodes`（默认关闭的校验途径）以及行为探针和结构性断言；`--dump-regassign` 已经是 `placement` 记录，只是没有原因码。本文要求统一条目和统一查询，不重写这些 pass。（先例实现方式更新 = R2 P6 Task 5 / E-16。）

开销规则（沿用 R2 P1 的先例）：R2 P1 已经实测「记录途径默认关闭，关闭和开启两态产物逐字节相同（sha256 `95084e7b…d475`）」。本文沿用这条规则，并采用更严格的版本：

- 记录生成默认开启（轻量：只写 `id/kind/subject/phase/choice/cause` 码）；
- 记录展开按需进行（只有 `explain` 时才把 `evidence` 引用和 `cause` 参数渲染成人读文本）；
- 关闭记录途径后，产物逐字节相同（守卫条件见 5 节 S-D1）。

理由：如果记录生成也默认关闭，缓存命中路径上的决策就永远不会被记录（缓存条目里没有记录），`explain` 会随冷缓存和热缓存状态给出不同答案，这正是 L8 要禁止的情况。

### 1.4 输出格式

一份数据，两种渲染方式（人读文本由结构化数据生成，不能反过来由文本生成结构）：

```
{
```

强制要求：

1. 确定性：同一产物两次 `explain`（包括 stdout）逐字节相同，不含时间戳、PID、地址和目录绝对路径；排序先按记录 id。
2. 带版本：`schema` 字段在破坏性变更时递增；golden 快照测试直接比较字符串。
3. `unattributed` 必须显式列出：无法归因的情况（启发式内部状态、记录缺失、功能未实现）写入这一栏，不得用空的 `records` 表示「没有发生任何决策」。
4. 人读模式（默认）：`cause.code` 到稳定措辞表（`diag.cr` 风格：原因码到 一句中文 + 一行证据链）；`--json` 出结构化。原因码到 措辞表是独立文件/表（照 `error_codes` 先例），保证措辞可审、可译、可测。
5. 不扩展协议（沿用 LSP spec 第 6 节）：LSP hover 用 markdown 渲染同一结构；coreview 读取 JSON。不新增 LSP 方法。

### 1.7 确定性报告部分：`core analyze --determinism`（计划 1.4 节，2026-09-11 追加）

定位（L2/L12 的直接推论）：`analyze --determinism` 不是新工具，它是 1.2 节查询核在程序级定位点上的视图：

| 命令 | 定位点 | 问题 | 共用 |
|---|---|---|---|
| `corec explain FILE:LINE --qclass <类>` | 单定位点（源码/符号/图对象） | 为什么这里这样做 | 同一记录表 + 同一查询核 |
| `corec analyze --determinism [--at ANCHOR]` | 程序 / 每个可观测输出（边界 sink：打印/写文件/返回值/网络） | 这个输出的不确定性从哪来 | 同上 |

#### 1.7.1 报告格式

输出包含轴族逐项状态和不确定性 provenance 链（两份都由 1.3 节的记录表生成）：

```
$ corec analyze --determinism FILE.cr
axis         status    evidence / residual
D_value      PROVED    merge_deterministic @12:3；无可达边界
D_effect     UNKNOWN   state edges 覆盖 #41、#44、#52（store 家族）；调用 print@#58 未入链，按保守面降级（硬约束 8）
D_memory     PROVED    region 绑定 + bump/reset 全静态（arena #0/#3）
D_timing     UNKNOWN   residual: 循环 #61 迭代次数依赖外部输入
D_resource   PROVED    结构层：进行中任务 ≤ 4（spawn_count）；值个数 ≤ …
D_external   EXPLICIT  boundary #27（stdin），边界节点 = 一类合法显式源，归属方 = #27（决定 D19）
D_mapping    PROVED    无机器相关假设（映射无关段）

uncertainty provenance:
  boundary #27、parser、branch #61、output "report"
  （每跳 = 记录 id + kind + 边类型；断链时记为 UNKNOWN，并登记断链位置）
```

强制约束（承本文 1.4 节输出契约约束 1–5 + 计划 1.4 节全部）：

1. 状态值域 = `{PROVED, MODELED, UNKNOWN, EXPLICIT}`（计划 1.4 节逐字）；`D_timing` 只用前三值（时间三值化，硬性，不设 `EXPLICIT`：耗时的物理性使「源码明文允许」不构成状态；源码显式放行不确定时，该不确定落在 `D_value`/`D_effect`，`D_timing` 相应为 `UNKNOWN`）。
2. 每行必须带证据或残余：`evidence`（可指认的记录链）或 `residual`（剩余不确定源清单）。空 evidence + 空 residual 非法（= 无提示，计划 1.4 节精神禁止）。
3. 链可指认性：provenance 链的每一跳必须能在记录表里查到（L9 内容寻址 id）；查不到时为 `UNKNOWN`，并登记断链位置（L14，不得补全猜测）。
4. 链终止：终止于边界节点（缓存语义规则 4「边界公理」：MMIO / FFI / 输入 / 测量 = 唯一无方法条目）或显式语义源标注。到达既非边界又无方法的内部节点时记为断链（这同时是标注器/pass 的缺陷信号，须登记）。
5. 状态传播 = 沿依赖闭包取 join（部分序，不假设全序）：
 - 任一环节为 `UNKNOWN`，则整体为 `UNKNOWN`（优先暴露无法归因的项，这是报告的基本要求）
 - 无 `UNKNOWN`、含 `MODELED`，则整体为 `MODELED`（时间轴专属：混入机器相关估计即不得称证明）
 - 无 `UNKNOWN`/`MODELED`、含 `EXPLICIT`，则整体为 `EXPLICIT`
 - 全为 `PROVED`，则整体为 `PROVED`
 - `MODELED` 与 `EXPLICIT` 不可比：同时存在时并列标注（`MODELED + EXPLICIT`），并必须让 `EXPLICIT` 的源可指认，不得用任一值覆盖另一个。
6. 报告自身确定性：同产物两次运行逐字节同（含 stdout，无时间戳/路径/地址；排序 = 轴名序 + 记录 id 序），照本文 1.4 节约束 1。
7. 汇合与不确定性的最小字段面（承 S-E 5.2.3 节；B 线 I3/决定 D20）：报告项必须包含：形态 / 汇合点 id / 输入边集 / 顺序源（`ordered`）/ k 与 `Obs(M)` 基数界（`race`）/ 见证引用（witness，若暴露）/ 分类（已证明 · 已声明 · 冗余声明 · 拒绝）。`冗余声明` 类照 S-E 1.5 节证明优先规则单列（标了 `race` 而已证确定者）。此前「格式归 S-D」两侧都以为对方保存，因此本条就是实现位置（S-E 5.2 节-3 已回指）。
8. 效应证据的充分性（决定 D17/B 线 I4）：`D_effect` 的 `PROVED` 证据必须声明 state 链的覆盖范围；链未覆盖 `IR_CALL_EXTERN` 或未被判定为纯的调用时，按 S-E 1.1 节保守判定降级 `UNKNOWN` + `residual`。覆盖现状（2026-09-11 效应/纯度阶段后）：链覆盖 = 函数内 store 家族 + `purity_op_effect` 全清单（`IR_CALL_EXTERN`/`IR_SPAWN`/`IR_YIELD`/`IR_HOTPATCH_ROUTE`/`IR_DYN_DISPATCH`/`IR_STORE_PTR`/`IR_AWAIT`）+ 一切不可解析调用 + 一切未证纯的可解析调用（修复前约定 = 「所有调用」，见 1.6 节历史条）；残余 = lazy 判定冻结（`ir_gen.cr:1590` 生成期读乐观默认值）+ 链每函数重置。「有 state 边 ≠ 确定」（S-E 4.1 节方向性提醒），不得把「state edges 全序」单独读成 `PROVED`。
9. 局部 prove 的覆盖标注（D10）：`race` / `select_any` 的 `EXPLICIT` 项必须标注「该保证未覆盖观测点」（S-E 5.2 节-6：prove 范围 = 局部，只覆盖汇合点本身）。

#### 1.7.2 时间三值化（`D_timing`，硬性）

| 值 | 语义 | 数字来源 | 显示限制 |
|---|---|---|---|
| PROVED | 机器无关上界：分配次数/字节 · 进行中任务数 · 通信量（可由 region / 图证明） | 2 节结构层（本文） | 不得声称这是「时间上界」（次数 ≠ 时间） |
| MODELED | 机器相关时间 = 成本模型估计 | S-C 成本模型（2.6 节接口） | 必须明标「模型估计，非证明」；禁止呈现为 WCET 证明 |
| UNKNOWN | 无法判断 / 模型不可用 / 链断 | — | 不得渲染为任何界（2.2 节同规则） |

「PROVED 的机器无关量」与「时间」的分界是本报告部分的核心规则：分配次数/进行中任务数/通信量可证，但它们不是时间，报告部分必须把两者分列，不得让读者把「已证明的指令数上界」读成「时间上界」（这正是计划 1.4 节「不得给出错误结论」的实现位置）。

#### 1.7.3 与 S-C 的接口（`MODELED` 的来源，L15）

```
cost_model_query(kind, subject, mapping_desc) -> {
    cost,            // 估计值
    band,            // 不确定带（必填：单点数字给人"精确"错觉 = 过度承诺）
    model_id,        // 成本模型标识
    model_ver,       // 版本
    assumptions[]    // 模型成立的前提（必须随报告呈现）

```

报告部分只做三件事：调用、贴标签（1.7.2 节的禁令措辞）、把 `model_id`/`model_ver`/`assumptions` 记进记录的 `evidence`（，因此进 3.3 节的 `phase_ver`，模型换版本则报告与相关记录自动失效）。
不做：不重造成本模型、不读其内部状态（内部状态不可归因，因此违反 1.2 节「解释不会无提示凭空生成」）、不缓存模型结果。
禁令：模型不可用（S-C 未实现 / 预算耗尽），因此必须是 `UNKNOWN`，不得用「经验常数」回退成 `MODELED`。

#### 1.7.4 与 S-A / S-E 的边界（只归因，不定义来源）

与计划 1.4 节执行归入档位表的逐行对应（本报告部分只出「呈现列」，执行列为谁负责）：

| 计划 1.4 节情形 | 本报告部分呈现 | 执行归属 |
|---|---|---|
| 依赖/状态边足证「汇合与调度无关」 | `PROVED`（零成本） | S-A |
| 顺序由显式顺序源固定（`merge_ordered`） | `PROVED` + evidence 指向该顺序源 | S-E 定义形态 / 本面呈现 |
| 语义明文允许（`race` / `select_any`） | `EXPLICIT`（必须可指认归属方） | S-E 定义形态 / 本面呈现 |
| 既未证明也未标注（隐式竞争） | `UNKNOWN` + 归因链（只读版不拒绝，L12） | S-A/S-E 执行 = reject（真正的执行点） |

- `EXPLICIT` 的判定 = 「该不确定可追溯到一条已登记的显式语义源标注」或「链终止于边界节点」。标注的存在性与合法性归 S-A（轴标注登记）/ S-E（汇合形态定义）；本报告部分只回答「归因到哪」，不判定「某个 `race` 标注是否该合法/是否该 reject」，执行点（隐式竞争，结果为 reject）归 S-A/S-E（L12：本 slice 只读）。
- 边界节点 = 一类合法的显式不确定源（决定 D19/B 线 I5）：边界链（`D_external`：MMIO / FFI / 输入 / 测量，缓存语义规则 4 的既有四类）的归属方 = 边界节点 id，链状态 = `EXPLICIT`，与 S-A 的轴标注登记并列，不因「无标注」降为 `UNKNOWN`。边界清单的最小面按上述四类起步（O11），扩展须登记。
 与 S-A 1.9 节来源列的对齐（B 线 N4，规范性）：S-A 的 `D_external` 来源列写「领域库/部署声明」；本报告部分读作，边界 = 声明的一种（边界公理即其声明，规则 4 的「无方法条目」本身即标记）。两者不冲突：归因（链终止于边界，因此归属方 = 边界 id，因此 `EXPLICIT`）今天可用、不依赖 S-A 实现；放行（该边界是否被允许/被治理层认可）不由本报告部分判定，也不构成放行，报告部分只归因（L12 只读）。故 S-D4「依赖 = 无」与其检查2 相容（2 只要求归因，不要求声明登记）。
- 局部 prove 的呈现（D10）：`race` / `select_any` 的项标注「该保证未覆盖观测点」（强制约束 9），保证范围与呈现范围必须一致，不得让读者把局部保证读成整条路径的保证。
- 汇合语义本身（`merge_deterministic` / `merge_ordered` / `race` / `select_any` 四形态、及其 lowering/调度不得引入未声明不确定的降级义务）逐字归 S-E，本文零定义。
- 现状如实呈现：`select` 现语义（「最早到达的令牌」= 物理调度顺序混入语义，计划 1.4 节定性 = 待修），报告部分会如实把链指向该语义源，不隐藏、不替它辩解；重新确定与兼容窗口归 S-E。
- `D_mapping`（Core 特有轴）：语义 ≥ 映射，因此报告约定 = 「该输出的语义是否依赖某条映射假设」；映射假设的清单来自 hw-map/S-C，本报告部分只查询与呈现。

## 2. 可预测（资源上界）

### 2.1 上界三层与可判定性

| 层 | 量 | 可判定性 | 归谁 |
|---|---|---|---|
| 结构层 | 最大进行中任务数（并发 goroutine 数）· 最大通信条数/值个数 · 循环迭代次数上界 · 每 arena 的值个数上界 | 图 + region + state edges + spawn 计数直接可判（无依赖 region 的可并行性判定已有声明，TODO 性能自动化族） | 本文|
| 映射层 | 最大字节内存 · 最大通信字节量 · 峰值 live storage | 需尺寸/对齐标注，R2 2.1 节已确定定「尺寸/对齐 = 映射层 / hw-map 领域，语义层不承诺布局」 | S-C / hw-map（本文只定义记录格式与「界如何被使用」） |
| 时间层 | deadline（墙钟/周期上界） | 语义层不可判（成本模型属 S-C；共享机器/OS 调度/中断不可归因，1.3 节残留第 2 类） | 只能 2enforce / 3proof-required（2.4 节） |

三层不可混报：`explain --bounds` 的输出必须标层。结构层上界不蕴含映射层上界（值个数少但值大）；把两层混成一个「内存上界」是本设计明确禁止的过度承诺。

### 2.2 保证与平均的区分：状态值域（统一承计划 1.4 节）

上界与轴族状态共用同一个值域（不另造一套标签，这是「三线共用一套」的直接后果）：

| 状态 | 含义 | 渲染约束 |
|---|---|---|
| `PROVED` | 对声明的全部执行成立（符号传播 + 图结构给出，机器无关） | 可称「保证」；须附 `assumptions[]`（空 = 无条件） |
| `MODELED` | 依赖成本模型（机器相关） | 必附 `model_id`/`model_ver`/`band`/`assumptions[]`；人读必须打「模型估计，非证明」标（1.7.2 节禁令） |
| `UNKNOWN` | 判不出（预算耗尽 / 依赖不可判 / 生产者未实现 / 链断 / 模型不可用） | 不得渲染为 bound；走 `unattributed`（本文 1.4 节约束 3）+ 登记 |
| `EXPLICIT` | 语义明文允许该不确定（有明确来源的不确定） | 必须指明归属方（标注的位置与来源）；不得与 `UNKNOWN` 混同 |
| （`measured`） | 实测（PGO/剖析/回归数据） | 不是状态、不是保证；只允许出现在诊断/建议语境，样式中不得与前四者同形 |

假设是修饰不是状态：`PROVED`/`MODELED` 都可以带假设清单（原「assumed」= `PROVED + 非空 assumptions` 的读法）；假设不成立则界不成立，此约定比单列一档 `assumed` 更准确（不会让读者以为「有假设的界」与「无条件证明」是同一类对象）。

这就是 1.2 节原则 3「义务不会无提示消失」在预测面的同构规则：上界不会无提示降级，`PROVED` 退到 `MODELED` 时必须写清模型与假设；退到 `UNKNOWN` 时必须显式登记。禁止把 `MODELED` 呈现为 WCET 证明（L13，契约硬性）。

### 2.3 现状基础（可复用，不重造）

1. 每 goroutine 独立 arena + 不共享内存 + 值在 channel 边界拷贝（`docs/superpowers/specs/2026-07-30-concurrency-design.md`；实现 `src/stdlib/goroutine.cr:54` 写 `arena_id`、`sched.cr:45` 主 goroutine `arena_id = -1`）。

### 2.4 deadline 约束的语义

超时动作 = 仅诊断（已确定，决定 D8，2026-09-11）：编译期标注 + 报告，不改运行时语义，语言只说「此处声明了 deadline 约束」，不说「超时会怎样」；超时的硬行为（终止 / 降级 / 补偿）留给库 / 运行时实现，且不得呈现为语言保证（与「模型非证明」一致：语言不承诺时间上界）。据此，deadline 在语言语义上只能是：

| 档 | 语义 | 何时可用 |
|---|---|---|
| 3 proof-required | 要求用户提供「步数/成本上界」的证明义务 | 硬实时子集，验证切片轮后 |
| 4 reject | 高安全模式下无法处置到 拒绝编译 | policy 数据裁量 |
| （2 enforce 不在语言面） | 若库 / 运行时自行实现超时动作，那是库的语义，语言不承诺其行为，也不得把运行期动作提升为语言保证（决定 D8） | — |

明确不在 1：即使将来有成本模型，deadline 的 prove 仍依赖调度/硬件假设（计划 1.3 节残留第 2 类），`PROVED` 的 deadline 只可能在「声明域内 + 单核 + 无中断」这类显式声明的封闭假设下成立，且必须把假设挂在 `assumptions[]` 里。

`MODELED` 的位置：deadline 可以在非安全关键语境以 `MODELED`（S-C 成本模型估计 + 不确定带）呈现，但必须明标「模型估计，非证明」（L13），且不得作为调度/安全/适航类检查的输入。超时动作 = 仅诊断（已确定，决定 D8；O5 已解决）：报告部分只呈现「该约束的 `D_timing` 状态 + 残余」，不得承诺任何超时行为。S-C 侧同款（其 1 节资源行 + 8 节 O5）。

### 2.5 与义务分级的关系（实例化，不重新定义）

资源上界 = 义务分级在资源轴上的实例（本节只做映射，不新增档）：

| 资源约束的处置 | 四档实现位置 |
|---|---|
| 静态可证界 | 1 prove（零成本，状态 `PROVED`） |
| 不可证界但可运行时强制（计数器 + 检查） | 2 enforce（状态 `PROVED + assumptions[]` 或 `MODELED`+enforcement 记录） |
| 判不了也不可强制 | 3 proof-required（要求用户声明上界 = policy 数据） |
| 高安全模式仍无法处置 | 4 reject |

实现方式 = policy 数据（原则 2 / 1.1 节：`G + P ⊢ Safe` 的 `P`），不提升为语言 primitive，资源上界声明是图上约束数据，不是新关键字。依赖 S-A：`P` 的接口与义务判定通道归 S-A，本文提供的是「结构层界的计算 + 记录格式 + 状态值域规则」。

时间层的 `MODELED` 与映射层（字节）的数字来源不在本文：时间 = S-C 成本模型，字节 = hw-map 尺寸标注（R2 2.1 节已确定：尺寸/对齐是映射层领域，语义层不承诺布局）。接口形态与禁令见 1.7.3 节（`cost_model_query`：`cost` + 必填 `band` + `model_id`/`model_ver` + `assumptions[]`）：

## 4. 三者的公共基建

### 4.1 一套记录表 + 三个视图 + 一条追踪

是共用一套，理由不是「省代码」，而是语义上必须：

- 1 节问「为何选」，读记录的 `cause` / `alternatives`；
- 1.7 节问「这个不确定性从哪来」，读同一条记录的 `evidence` 闭包（沿依赖边走，终止于边界/显式源）；
- 3 节问「依赖了什么」，读同一条记录的 `evidence` / `determinism`；
- 2 节的界是 `kind = bound` 的同表记录（`choice = selected` 的界 + `alternatives` = 被拒的更弱界 + `cause` = 判定来源）。

即：失效追踪 = 决策记录的输入依赖闭包。一条记录若没有 `evidence`，它就不可增量（只能整块失效），这把「记录完整性」与「失效精度」变成同一个变量，是设计上必须承认的成本驱动（粒度先粗后细，5 节）。

三个视图：解释视图（人读「为何选」）｜归因视图（人读「不确定性从哪来」= 1.7 节的 provenance 链）｜失效视图（机器读依赖闭包），同数据、同边、不同渲染。不允许为失效追踪或归因链另建一套依赖表：那会立刻产生「记录说 A 依赖 B，依赖表说 A 依赖 C」的双源不一致（先例：`res_type_node` 双份 TY 到 TI 的映射，R2 4 节步 3 明确要合一）。

### 4.4 不得各建一套的反例

差距 B（`.ccr` 冷热两态 sha256 不同）就是「没有共用实现方式」的代价：编译器的决定没有随产物走，于是缓存命中路径「少做了一些决定」，而没有任何数据结构能说明少了什么。若 1 节自建一套解释数据、3 节自建一套失效数据，则：
- `explain` / `analyze --determinism` 在冷/热两态给出不同答案（因为决定没随条目走），直接违反本文 1.4 节约束 1 与 1.7.1 节约束 6；

，因此 L8 的强制：记录随缓存条目一起存取。

## 6. 不承诺

### 6.1 计划 1.3 节三类不可消残留在本文的处理方式

| 残留 | 本文的处理方式 |
|---|---|
| 错误 specification | `explain` 报告的是「编译器为何这样做」，不是「这样做对」。记录的 `cause` 是原因码而非正确性证明；增量主要检查（L1 逐字节同）是「同一编译器的两态一致」，不等于语义正确，不得当作验证证据引用。|
| 恶意/失陷外部实体 | 决策记录的实现方式是磁盘文件（旁路 + 缓存），可被篡改；伪造的记录可令 `explain` 给出不实结论，也可令增量复用错误的决定。故：1 `explain` 输出不是安全证据（它只谈编译器做出的决定）；2 对抗篡改靠可复现构建/签名（计划范围内、本文范围外）；3 记录必须随缓存条目一起校验（分量不匹配即 miss，3.5 节）。|
| 需求本身允许危险行为 | 本文不禁止任何能力：上界是约束数据，解释是只读视图。隔离边界（S-B 族）与上界声明是两件事，上界不构成隔离证明，反之亦然。|

计划 1.4 节面的同一读法（确定性报告）：

- 错误 specification：报告指出「这个输出的不确定性归因到边界 #27 / 标注 #12」，归因正确不等于该归因合法、也不等于该 `race` 标注是用户本意。报告部分只呈现，不判合法性（执行归 S-A/S-E）。
- 恶意/失陷外部实体：物理不确定性的主要来源正是这一类（调度、中断、外部输入、受损环境），报告部分能指出「不确定性从哪来」，不能消除它；`D_mapping`/`D_external` 的 PROVED 只对声明域内成立。
- 需求本身允许危险行为：`race` / `select_any` 是显式请求的不确定（1.4 节第 3 档），报告部分把它呈现为 `EXPLICIT`（有明确来源），不阻止、不试图消除；「不确定性 = 显式请求」的全部要求就是它不得在未声明的情况下发生。

### 6.2 本文特有的四条不承诺

1. 不承诺所有决策都可解释。启发式的内部状态（预算余量、搜索顺序、成本启发式）可能不可归因；此类情形必须归入 `unattributed` + 登记（1.4 节约束 3），不得事后凭空生成原因码。`heuristic`/`env` 分级（L3）就是为这条服务。
2. 不承诺上界对所有程序可判。`UNKNOWN` 是合法输出（2.2 节）；动态 spawn、外部输入驱动的循环界、无尺寸标注的映射层、`D_timing` 无成本模型，都落在 `UNKNOWN`。把 `UNKNOWN` 渲染成 bound 等同无提示降级（禁止）。
3. 不承诺增量对所有变更正确。承诺的是：检查可测（3.4 节三级 + 负向对照）＋ 失效面覆盖（分量表 3.3 节）＋ 未覆盖即明确回退全量（3.5 节）。未覆盖的变更面必须登记（7.2 节 / TODO），不得沉默。
4. 不承诺 `MODELED` 是证明，也不承诺报告部分能消除不确定性。报告部分只归因（每条不确定性有一个归属方：边界 / 显式源 / 成本模型 / 断链），不承诺把它变成 `PROVED`。`MODELED` 的数字永远带 `band` + `assumptions[]` + 模型版本，禁止呈现为 WCET 证明（L13）；`EXPLICIT` 是被明文请求的不确定，呈现它、不替用户消除它；`UNKNOWN`（含断链）是合法终局，不得用启发式常数补成 `MODELED`（1.7.3 节禁令）。
