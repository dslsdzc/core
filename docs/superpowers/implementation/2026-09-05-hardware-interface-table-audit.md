## 1. 定位与命名

硬件接口表（HIT）= 运行的唯一平台依赖。corearch 除优化问题外没有平台代码，指令发射、运行时资源、系统边界全部查表。替换表即更换目标平台或范式：同一 Core 程序（v6 NOD + 图语义）配不同表可以直接运行。

- 命名：使用接口表而不是映射表。接口 = 语义契约（签名），实现 = 范式投影；映射暗示经典绑定，接口本身表明范式无关
- 与类型系统定案同族：语言类型接口注册表（int/dex/string 原生条目）加硬件接口表，都是“接口 = 图上契约”在编码层的实例
- 与 MMIO hw-map 同构：语义表（范式无关）加投影表（平台实例），本表是该结构在指令和运行层的推广

## 2. 最小核（运行契约，4 事件）

底层实现这 4 个接口事件即可运行 Core（其余语义全部编译或合成为这 4 个）；硬件内部实现自由（微码、查表、专用加速），契约只约束对外暴露的部分。

| 事件 | 签名要点 | 不可去论证 |
|---|---|---|
| `sub` | 算术完备单点：add(x,y) = x−(0−y)；比较 = 差符号；neg 不需要额外事件 | 全算术在它上合成 |
| `nand` | 逻辑完备单点：全部布尔（and/or/xor/not）组合可得；布尔 = 算术进位基础 | 全位逻辑在它上合成 |
| `load` | 效果事件：“读世界”（外部状态得到值流） | 计算完备替代不了读世界 |
| `store` | 效果事件：“写世界”（值流写入外部状态，state edge 语义落点） | 同上 |

- 事件签名没有宽度、没有寄存器、没有寻址（图边已包含搬运，Core 不需要 mov 类事件；宽度和形状归投影）
- 可合成项全部落为扩展事件：add/mul/div/移位/and/or/xor/not/cmp/select/const/branch/call…
- 合成代价属于编译器问题，不属于契约问题（硬件内部可以加速）

## 3. 表结构

### 3.1 事件条目（接口 = 签名）

```
事件条目：
 event_id （最小核固定 1-4：sub=1 nand=2 load=3 store=4；扩展从 5 起）
 签名：输入角色数 / 输出角色数 / 副作用类（纯 | effect | volatile）
 语义定位点：指向规约层（.corespec）的可选引用
```

签名只描述接口，不描述实现。任何范式的投影都是“该事件在范式里如何实例化”：

### 3.2 投影条目（范式实例）

```
投影条目：
 event_id -> 范式实例描述
 经典离散：编码规则（ISA 模板/编码序列），“实现它”
 通道类范式（oracle/交互）：外部通道映射，“接通它”
 连续/量子类：动力学元件描述，“演化它”
 无实现：条目缺失，编译期拒绝或 unsafe 外部入口
 （超图灵事件 × 经典投影 = 缺失；与 MMIO 动态地址同角色，先例已在）
```

投影不一定编码成字节。投影 = 事件到范式资源的实例化，经典行恰好是 ISA 编码。

### 3.3 运行条目（运行的资源都跟表相关）

除指令发射外，运行所需资源同为表条目（替换表即可更换 ABI/运行时）：

```
运行时条目：
 调用资源：call/ret 机制（栈约定 | 续体 | 通道），最小核无 call，属扩展
 存储资源：load/store 的地址语义（线性内存 | 区域 | 通道寻址）
 系统边界：extern/入口点约定
 宽度/形状：事件无宽度，投影在此声明（int 无限精度如何落到机器字）
```

优化（寄存器分配/调度/CSE）不走表：判定与分配在格形态层（regalloc-cache-mapping 四条），表只描述材料，不描述放置策略。

## 4. 大表（扩展事件全集）

最小核之上，大表是平台的完整事件目录：

```
1-4 最小核（契约，必须）
5+ 扩展事件（可选加速/平台能力）：
 add sub mul div shl shr and or xor not cmp select const branch call ret
 atomics / vector / float / extern(oracle) …
```

- 程序只用最小核，则任意表可运行（可移植子集）
- 程序使用扩展事件，则该表必须包含对应投影（查表缺失时编译期拒绝，或由编译器降级合成）
- 表是编译器与平台的能力协商面：corec 产出的事件不超过表，平台保证运行

## 5. 合成层（IR 到核事件）

Core 语言/IR 操作数（38 op）合成为表事件：

- 编译器持有事件降低规则（op 到核事件组合）：add 降低为 sub 反减；and 降低为 nand；移位降低为重复；const 使用图常量注入机制
- 表声明了扩展事件时，降低规则改为直接发射（优先查表，没有表项再合成）
- 合成层位置：corec（IR 层降低）或 corearch（读表后降低），实施期确定（倾向 corearch：表属于运行层，降低随表走，换表即换合成策略）

## 6. 实施阶段目标

M1 最小核运行完整流程（当前目标，先把最小核表运行起来）：
1. HIT 表文件格式定稿（文本还是二进制？先行使用文本 toml/json 或 Core 语法，v6 后并入二进制段）
2. 表驱动发射框架：corearch 读表发射（先做 x86 投影：sub/nand/load/store 4 条真实编码）
3. 合成层最小实现：现有 IR op 到 4 个核事件的降低规则（先覆盖快速验证程序所需子集）
4. 快速验证完整流程：`.cr`（加减/位运算/内存读写程序）经最小核表生成 ELF，运行正确
5. 回归不破：大表（38 op 直通条目）保留期间，全套测试仍通过，最小核表作为新后端路径与现路径并行验证

M2 全表驱动：instr.cr e2_* 硬编码改为大表数据；运行时条目接入；v6 接表
M3 范式扩展：第二张表（arm64 或参考机）；超图灵接口条目语义定稿

## 7. 边界（YAGNI）

- 优化不进表（判定/分配 = 格形态层）
- 本设计不定义“图执行契约”（范式无关保证在图层，由验证清单 8 项承接），只定义事件解释器族的标准路径
- 合成规则的完备性证明（一切 IR op 可降到 4 核）属于验证层事项，实施期以快速验证和回归实证

## 8. crasm 取代说明（2026-09-05 定稿）

独立 `.crasm` 格式取消（旧文档 `docs/crasm.md` 与 `specs/2026-08-08-crasm-design.md` 标注废弃/退役）：

| crasm 诉求 | HIT 框架下的取代 |
|---|---|
| 跨平台统一汇编 | HIT 事件 + 投影表：换表即换平台，无中间汇编语言 |
| 无限虚拟寄存器 | 寄存器概念整个取消：图边包含搬运，值 = 流引用 |
| 平台映射表（x86/ARM/RISC-V 私有） | HIT 投影条目（唯一表，编译器与手写共用） |
| 特权指令固定集（mmio/barrier） | HIT extern/接口事件 + `.cr` unsafe，不预绑硬件 |
| 寄存器生命周期验证 pass | 验证语义上移到图和格框架（值流没有生命周期问题） |

内核路线（project-book 第五阶段）的“汇编级”需求 = `.cr` unsafe 加 HIT 接口事件；事件层的可读形态 = v6 NOD 文本 dump（工具，不是语言）。
