# 可选表示位随存储位置走

## 概述

修复可选值的表示位与存储位置不一致的问题。问题表现为同一段程序在 ELF 和解释器上得到不同的错误值，且没有诊断。

修复方案是：表示位跟随实际存储位置，指针写入按被指向值的可选性装箱。实现已完成，验收通过。

## 问题

复现程序：

```core
x : int? = 5;
p := &x;
*p = Some(9);
match x { … }
```

修复前，ELF 返回 8，解释器返回 216。两条路径都给出错误值，没有任何诊断。

受影响的形态：

| 形态 | 修复前 | 修复后 |
|---|---|---|
| 局部变量经指针裸写 | 139/139 | 7/7 |
| 数组元素经指针裸写 | 139/139 | 7/7 |
| 全局变量经指针裸写 | ELF 0 / interp 139 | 5/5 |
| 全局变量经指针装箱写 | ELF 0 / interp 5 | 5/5 |
| 结构体字段 `&s.a` | 写入丢失 | 仍登记，见遗留问题 |
| 表示位为 0 时写裸值 | 7/7，正确但不稳定 | 7/7 |
| 表示位为 1 时写裸值 | 139/139 | 7/7 |
| 表示位为 0 时写装箱值 | ELF 8 / interp 96 | 写入 9，解包后等于 9 |

## 根因

1. 表示位只在直接写点设置。`emit_rep_set` 只在 LET、赋值和形参序言等位置发射；指针写走 `IR_STORE_PTR`，绕过表示位，导致槽的表示和值不一致。
2. 指针指向哪类存储无法静态闭合。无条件装箱会把原本正确的裸写形态变成错误，因此不能对所有指针写统一装箱。
3. 全局变量的 `IR_REF` 使用了帧内偏移。`src/arch/x86_64/instr.cr:1095` 对全局源生成 `e2_lb(g2_slot(s1))`，即 `lea r10,[rbp+off]`。全局行的 `g2_slot` 是帧外偏移，因此 `&g` 取到无效栈地址。经指针读写自身一致，但与全局槽脱节。
4. 推断得到的可选数组或切片元素写点没有装箱。元素写点查询声明表，而声明表只在带注解的 LET 中登记；字面量 `Some(x)` 的 IR 变量是 `TI_UNIT` 占位，`IR_SLICE` 变量是 `TI_INT`。

## 修复

- 取址预扫：收集被取址的变量名索引，写入 `g_addr_taken_names`。
- 赋值和 LET 写点：如果目标可能持有可选值，就装箱，并把表示位固定为 1。
- 形参序言：按条件装箱，并把表示位固定为 1。
- 指针写：`IR_STORE_PTR` 按被指向值的可选性决定是否装箱。
- 零影响保护：所有新增逻辑先判断 `g_optrep_on`，未开启可选表示时完全跳过。
- 全局 `IR_REF`：改为 `lea r10,[rip+rel32]` 加 RIP 补丁，沿用 `IR_STORE` 和 `e2_load_var` 的全局分支。
- 推断元素写点：字面量预扫数组级可选性并登记；切片按源可选性登记；LET 和全局初值把值面的登记继承到绑定变量。

布局和 `.ccr` 格式不变。
