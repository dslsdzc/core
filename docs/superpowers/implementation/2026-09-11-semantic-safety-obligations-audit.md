## 1. 属性轴（基础七轴 + `determinism` 族）

### 1.0 轴的形式公设（本文的决定）

> 术语「属性轴（attribute axis）」按共享契约 1.1 节逐字使用：图对象/边上的开放标注维度，七轴 = `trust`（可信度）/ `secrecy`（机密性）/ `integrity`（完整性）/ `authority`（授权）/ `lifetime`（生命周期）/ `state-version`（状态版本）/ `effect`（副作用）。

- A1 值域不固定：本文不为任何轴固定值域、偏序或格代数，三者均为 policy 数据。理由 = v4「无格承诺」（4.6 节）：判定与定理只在关系层面陈述；任何具体格 = 签名 + 恒等式 = 封顶。
 - 各轴必须具备三件结构（形式要求，非具体取值）：1 值域（有限或无限）2 偏序（关系层面，用于「谁强于谁」）3 传播规则（沿值流边如何派生）。
 - 承 A1 的直接后果：新增轴 = 在标注空间加一个维度（v4「加标签不是新机制」），不动 Graph 本体、不加关键字（契约 1.1 节 policy 定义）。
- A2 不提升 primitive：轴 = 开放 semantic annotation / relation；只有义务可能拒绝编译（契约 1.2 节原则 1，承 M1 定论与定案 1/12）。
- A3 传播单调：派生不提升信任、不降低机密性、不提升完整性、不延长生命周期（各轴方向由 policy 定，但单调性本身是形式要求）。唯一例外 = 显式净化/降密节点。
- A4 唯一放行通道 = declassify（共享契约 1.1 节：`Secret 到 Public` 的唯一合法通道；同构地 `Untrusted 到 Trusted` 的净化节点）。且 declassify 节点自身带 authority 义务（降密需要授权），这是轴间耦合的第一实例（1.8 节）。

### 1.1 `trust`（可信度）

| 字段 | 内容 |
|---|---|
| 语义定义 | 值是否由受控方产生：`untrusted ⊑ trusted`（信任只降不升，派生不提高信任；唯一提升 = 净化节点） |
| 载面 | 节点标注（source 节点）+ 沿值流边的传播（与 provenance 同族，出生节点记录来源，传播 = 图上可达性） |
| 来源 | 领域库声明（不可信来源：`read_file`/`get_env`/argv/网络）+ 自动推导（传播）+ 显式标注（净化节点 = 库提供的类型化构造器，契约 1.1 节 sink/source 模型） |

## 2. 义务四档

> 术语「义务（obligation）」按共享契约 1.1 节逐字使用：由属性轴导出的、必须在编译/验证期被处置的判定要求。四档 = 1 prove（静态可证到 零成本通过）2 enforce（不可证但可运行时强制到 插入 enforcement）3 proof-required（不可证也不可强制到 要求用户提供 proof/contract）4 reject（高安全模式下仍无法处置到 拒绝编译）。

### 2.1 义务的形态

```
义务 O =（轴 a，源标注 S，汇要求 R，落档策略 policy）
判定输入 = 图上由 S 到 R 的「值可达性 / 形状包含性」判定（判定形态见 3.3 节）
义务状态 = open 变为 {proved | enforced | proof-provided | rejected}；不存在 open 到 passed（5.1 节 禁令）
```

### 2.2 从义务到档位判定：判定决策树（本文的决定）

```
义务 O（轴 a，源标注 S，汇要求 R）
  │
  ├─ 引擎判定（ty_sub 三态；常量档 = 判定输入为编译期常量）
  │    ├─ 真 所以 1 prove（零成本通过；不下发任何字节）
  │    └─ 假 所以 违法（编译错误；任何 policy 档位都拒绝）
  │              唯一放行 = 显式例外入口（declassify / 净化节点 / unsafe 边界 /
  │              授权族的 grant 声明，均入 3.1 节 放行·声明条目并落记录表，D2），
  │              且放行本身登记为义务（不省略提示，v4「例外入口授权可追踪」）
  │
  └─ unknown（三态第三态：判定预算耗尽 / 桥接失败 / 名称不展开）
       ├─ 存在 enforcement 点（检查语义定义良好 + 图上有插入面）
       │    ├─ policy 允许 所以 2 enforce（插检查节点；失败语义按策略，默认硬陷阱）
       │    └─ policy 档位 strict 所以 4 reject（或要求 proof 覆盖该检查点）
       └─ 不存在 enforcement 点（不可强制：隐式流 / 信任假设 / 规范正确性）
            ├─ policy 允许 所以 3 proof-required（登记义务 + 要求 proof/contract；
            │                  未提供时 = 显式诊断 + 记录表条目，不是通过）
            └─ policy strict 且未提供 所以 4 reject
```

三点关键区分（防误读）：

1. 「违法」与「4 reject」不同：违法 = 已判定为不合法（引擎返回假），任何档位下都拒绝；4 = 无法处置（判不出、不可强制、又不满足 policy），是「不知道」的结果。前者措辞 = 违反（含反例值，复用 `tt_witness`）；后者措辞 = 未处置（含出路建议）。
2. 三态是决策树的地基：R2 P0 引擎的三态（真 / 假 / unknown，unknown 含预算耗尽与未覆盖面）使「证不出」不是异常而是第一等输入。这与 R2 3.3 节的「预算超限 ≠ 类型不兼容」同构：不可判定 ≠ 不合法。
3. 档位选择是 policy 数据：同一条义务在不同 policy 档位下落不同档，「同一程序、不同 policy、不同档」是特性而非缺陷，即「安全 = 相对 policy」的准确面（8 节第 1 类）。

附：默认强度分层（2026-09-11 用户决定 D3(c)，规范性）：

| 面 | 默认（本地 / 开发） | 严档（strict / CI / 高安全） | 依据 |
|---|---|---|---|
| 档 3 | 登记 + 继续编译（3 = `open`，不是通过） | 拒编（4） | 5.1 节状态机；9.2 节-1 已确定 |
| 档 2 | 默认启用（可 enforce 的一律 enforce） | 关闭 enforce 通道，因此4 | 档位 = policy 数据（3.1 节） |
| 未声明的边界条目 | 取 `unknown`（保守判定方向），不拒编，归入 3 + 报告部分可见 | 拒编 | 不得把「不知道」渲染成「确定 / 公开」（S-B3 8.2 节 Q9 随此裁） |
| CI 条件 | — | 从严（strict 档 = CI 断言义务清单为空，5.2 节 b） | 「本地不阻塞、CI 守门」分成两个面 |
| `select` 迁移 | 窗口 W1 = 1 个发布周期（窗口内 lenient + 具名诊断） | 窗口后强制标注 | 共享契约 1.4 节；实现归 S-E；不承诺永久 lenient |

- 本表是规范形态：各族的「默认 / strict」两栏取值一律引用本表，不得各自发明（档位取值见 3.1 节）。族级例外由 S-A 的族级决定给出（如 2.6 节 / 1.9 节给 `determinism` 族取 `allow_enforce=false`，见 3.1 节的每策略覆盖，D15），各族只引用，不自设数值；本句限定并存（A 线 N5）。

### 2.3 四档 × where 三档映射（定案 5 的补完）

| where 三档（定案 5） | 四档落位 | 说明 |
|---|---|---|
| 常量档（约束输入 = 编译期常量） 到编译错误/通过 | 真到 1 prove；假到 违法 | 与三档原语义一致 |
| 符号档（约束输入 = 符号项） 到 VC 义务 | 真到 1；unknown 归入 3 proof-required（VC 义务，验证管线使用）；假到 违法 | 三档的 VC 面 = 四档 3 的一个来源 |
| 动态档（约束输入 = 运行期值） 到运行时检查 | 2 enforce（插运行时检查）；strict 归入 4 | 四档的收紧点：三档把「运行时检查」当动态档的固定归宿；四档把它降格为允许的回退之一（0.3 节 T2） |
| （三档无对应）不可强制义务 | 3 / 4 | 四档的新增面：隐式流（branch/timing）、信任假设（供应链）、规范正确性，三档结构上未覆盖。实例：确定性族的隐式竞争归入 4（该族 policy 固定，1.9 节） |

- 三档自带的「防『证明不了也不会无提示』」措辞（定案 5 原文）与契约 1.2 节原则 3 同向，四档把它补完为档位谱 + 拒编。
- 现状注：`where` 三档当前仅设计态，parser 无 `where`/`requires`/`ensures` 终结符（TODO :440 待实现，语法实现未实现）。故 2.3 节映射停在语义层：四档流程可先于 where 语法实施（6 节切片不依赖 where）。

### 2.4 每档的成本与可判定性边界

| 档 | 经典路径成本 | 可判定性边界 | 失败语义 |
|---|---|---|---|
| 1 prove | 零新增字节（证明完毕不下发，与 bounds-inference、缓存语义 v4 十一同款） | 引擎可判定子集内且预算内返回真 | n/a |
| 2 enforce | 检查节点字节（先例 `IR_BOUNDS_CHECK` ≈ cmp+jb+ud2）；最坏 = 每 sink 一次 | 不可判定但检查语义可定义（检查点存在） | 默认硬陷阱/中止（与先例一致：「中止而非未定义值（安全优先）」，`ir-op-semantics.md:196`）；库可声明其他（4.3 节） |
| 3 proof-required | 零运行期成本；成本 = 用户/领域库的 proof/contract 撰写 + 验证管线时间 | 不可判定且不可强制（隐式流 / 信任假设 / 规范正确性） | 默认：诊断 + 清单条目（登记，不是通过）；strict：拒绝 |
| 4 reject | n/a | 策略档位的后果（非判定结果） | 编译错误（明确 + 出路建议，5.4 节） |

- 预算边界（准确项）：引擎有判定预算守卫（R2 P0）。预算耗尽到 unknown 到按本决策树归入 2/3/4，绝不视作通过；且诊断必须区分「预算耗尽」与「判定为假」（R2 3.3 节同款）。

### 2.5 判定的可靠性责任（待确定，登记）

本文定的判定入口 = 引擎（契约 1.2 节原则 4）；「判定为真，因此该族的流规则成立」这一可靠性是各族的证明义务，不是本文的承诺：

- 判定目标形态 = 单值判定：`ty_sub(τ_value ⊓ A_a(v), Shape(sink))`（3.3 节）。
- 待确定的前提：轴传播单调（A3）+ 单值判定的忠实编码，因此图上「源到汇」的路径性质（不可达性）。若某族该前提不成立（典型：隐式流，值未流动但信息流动），该族归入 3（不可强制）或另立图可达性 pass，不得用单值判定冒充。
- 登记项：各族在自身 spec 中给出「判定真，因此规则成立」的论证或反例边界。

### 2.6 `determinism` 族的归入档位规则（1.4 节的实例化，规范形态）

> 本族不新增档：1.4 节逐字「执行 = 四档义务（与 1.1 节四档同构）」。轴表与载面见 1.9 节；本节给规范形态（实施阶段以此为准）。

| 判定输入（图上事实） | 归入档位 | 依据（1.4 节对表） |
|---|---|---|
| 依赖 / 状态边足证「汇合与调度无关」 | 1 prove（零成本） | 1.4 节行 1 |
| 显式顺序源存在（`merge_ordered`） | 落到确定实现（义务已由显式顺序源处置，不新增档） | 1.4 节行 2 |
| 显式不确定请求（`race` / `select_any`）且「声明-实现一致性」证明成立 | 1 prove + 报告义务（非第五档；报告部分登记归 S-D） | 1.4 节行 3，「语义明文允许，因此程序说的是它想说的，因此义务已处置」；证明范围 = 局部（报告部分须标注「未覆盖观测点」）；证明不成立，因此3 登记（D10(a)） |
| 既未证明也未标注（隐式竞争） | 4 reject（1.4 节「真正的执行点」） | 1.4 节行 4，该族 policy 取值 `allow_enforce=false` + `require_proof=false` + `strict=true`（3.1 节数据） 到 2.2 节决策树固定归入 4，无需改树 |

两条强制约束：

1. 4 的直接性来自 policy 取值，不是判定结果：隐式竞争在引擎侧是 unknown（判不出「汇合无关」，也不存在显式请求）；其 4 是该族 policy 禁止 2/3 回退的结果。若未来放宽（例如「要求提供汇合证明」 归入 3），改的是 policy 数据，决策树与判定器不动。
2. `select` 判定侧禁令（1.9 节）：S-E 重新确定前，`select` 不得作为「显式顺序源」输入 prove，否则把现有语义缺陷固化为证明前提。

## 3. policy 接口

> 术语「policy」按共享契约 1.1 节逐字使用：一组图上约束（`G + P ⊢ Safe` 里的 `P`），数据而非语法，新增安全模型不改 Graph 本体、不加关键字。

### 3.1 policy 条目形态（设计已定，字段为建议集，实施阶段可增补）

| 字段 | 内容 |
|---|---|
| `name` / `ns` | 策略名 + 命名空间（沿用 `register_plugin_tag` 的 `(ns_ni, name_ni)` 冲突规则：同名不可重复注册、命名空间不遮蔽无限定条目，`globals.cr:317-327`） |
| 涉及轴 | 该策略使用的轴（基础七轴或 `determinism` 族之一或其组合，1.8 节/1.9 节） |
| source 声明集 | 哪些节点是来源（领域库声明的类型化构造器，契约 1.1 节 sink/source 模型） |
| sink 声明集 | 哪些汇是危险落入点；每个 sink 需区分语法位与值位（S-B1 的参数化通道） |
| 流规则规则 | 非法边的形状（例如「untrusted 源头沿值流可达 sink 的语法位」） |
| 归入档位规则 | 本策略对 2/3/4 的取舍（`allow_enforce` / `require_proof` / `strict`），2.2 节决策树的 policy 输入 |
| declassify 通道 | 本策略认可的净化/降密节点（A4 的唯一放行通道）。与下行「放行 / 声明条目」的关系（A 线注意：2，防实施阶段建两张表）：本栏不是第二张表，它是下行条目栏的 `kind=declassify` 视图（同一存储面、同一 schema，只是按策略视角列出"本策略认可哪些"）。实现只建一张表（放行 / 声明条目）；本栏 = 该表按 `kind` + 策略名的查询视图 |
| 放行 / 声明条目（D2(a) 统一 schema） | 任何绕过义务的通道（`¬义务到 义务`）只经本栏条目，且必须落清单（5.2 节 b）。条目字段 = `kind{declassify｜grant｜deny｜mint｜stability} · 主体/身份 · 目标/范围 · 理由 · 派生源 · 义务引用`。`kind` 语义：`declassify` = 显式降密/净化放行；`grant`/`deny` = 对既存对象/权限的授予/拒绝声明；`mint` = 能力创建点（根声明 / `alloc_at` 类例外入口授权，声明的目标本身即新建的域，与 `grant`「授予既存对象的权限」语义不同；B 线 N2 修法采纳「增一枚」支）；`stability` = 治理层稳定性注解。形态默认 = 图上显式节点（可枚举、可审计）；偏离节点形态者必须在本栏显式豁免并给出理由，且一律补齐审计字段（理由 / 派生源 / 义务引用），不得沉默。四族填法（各写一行「本族条目在本栏的形态」）：S-B3 3.1 节（`kind=declassify`，节点）/ S-B2 0.3 节·5.1 节（`kind=grant｜deny`，声明型边集合）/ S-B4 Q9（`kind=mint`，根声明条目，声明即注册，能力创建点） / S-B5 2.1 节 C3（`kind=stability`，治理层注解） |
| 档位粒度（D15） | 两级：全局默认 + 每策略覆盖（键 = `(ns, policy_name)`）；每轴粒度留扩展位（键形式预留，不实施）。默认值取自 2.2 节附的强度分层表 |
| 诊断码 / 消息模板 | 沿用 `error[XXXX]` 体系（5.2 节 a） |

### 3.2 挂法：与 R2 双轴注册表并列，判定共用入口

- 并列表（不复用 `g_ifaces`/`g_impl_for`），三条理由：
 1. 语义不同：策略不是类型接口，混表 = 把漏洞类型做成类型特判（契约 1.2 节原则 2 禁止把 lint 改名）。
 2. 布局遗产：`g_ifaces`（1432B/条、16 方法 × 88B 上限）+ `g_impl_for` 的名字拼接遗留是 R2 2.4 节的升级对象；策略表另立到 两者互不阻塞。
 3. 增量性：策略新增 = 加数据行（契约：新增安全模型不改 Graph 本体）。
- 共用入口：查询 API 与 R2 `iface_*` 家族同风格（`policy_*`），判定唯一走引擎（契约 1.2 节原则 4：「不另建判定体系」）。
- 现状事实：`g_plugin_tags`（24B/条 `ns/name/data`）已是「插件可注册的开放表」原型，策略表是其语义提升（同一形态，语义从「标签位」升为「策略条目」），非新机制。

### 3.3 策略到图上的形状项和约束（判定走引擎）

```
A_a(v)：轴 a 的取值 v 到 类型项（policy 数据，各族自定；A1 不固定值域）
Shape(sink)：sink 的形状项（policy 数据；语法位 / 值位的区分在此编码）
判定：ty_sub( τ_value ⊓ A_a(v) , Shape(sink) )   其中 ⊓ 表示引擎 INTER（不新增判定算子）
```

- 引擎返回三态到 直接进 2.2 节决策树。
- 反例值：判定失败时用 `tt_witness` 给具体值示例（R2 3.2 节已有），诊断质量直接受益。
- 不新增判定算子、不新增规范化规则、不新增 memo 语义，策略侧只提供数据（0.3 节 T1）。
- 已知边界：`A_a(v)` 的声明责任在 policy（领域库），声明错（漏 sink / 错形状）属「错误 specification」类，本族不承诺（8 节第 1 类）。

#### 3.3.1 健全性约定：`A_a` 只做加约束式单调展开（规范性；与 S-B1 约定/N5 互为对偶）

风险（跨 spec 健全性洞，S-B1 提出）：若 `A_a` 以否定形式展开（如 `untrusted ↦ ¬Trusted`），左侧求交可能塌为 `⊥`，而 `⊥ ⊑ 任意 φ` 恒真，因此判定对所有 sink 放行，因此无提示通过（违反契约 1.2 节原则 3）。R2 类型项语言含 `¬`（`NOT` 构造子），故此洞是判定形态的结构性风险，不是表达力问题。

两条检查都要覆盖（2026-09-11 A 线评审 C3 + 决定 D11）：C1/C3 约束左检查（否定展开，因此左项塌 `⊥`）；右检查（右项 `Shape`）与正例侧原先无控，单式 `ty_sub(τ_value ⊓ A_a(v), Shape(π))` 在裸位置检查下全部鉴别力都在右项：若 `Shape` 被误声明为 `⊤`、或引擎对未定义的原子（如 `Trusted`）取宽松解释（无公理的原子当可满足一切），判定恒真，因此无提示通过（同一类洞，换了检查）；反之若 `Trusted` 被声明为与 `string` 互斥的原子类，则正例左项 `Trusted ⊓ string = ⊥`，因此 C3 判失败，因此正向对照全部失败（6.4 节-1「净化路径编译通过」不成立）。C5 因此是必需的，不是补充项。

| # | 约定（C） | 内容 |
|---|---|---|
| C1 | 左侧只加约束（单调） | `A_a(v)` 必须是加约束式单调展开（纯合取式的正编码，如 `Trusted ⊓ string` / 原子类约束）；禁止用否定形式编码属性（`untrusted ↦ ¬Trusted` 之类） |
| C2 | 要求一律写右侧 | 属性要求（sink 需要什么）一律写在 `Shape(φ)` 侧（右侧），不写在左侧值项上 |
| C3 | ⊥ 非真（vacuous truth 禁令） | 判定入口显式守卫：`ty_inhabited(τ_value ⊓ A_a(v)) == 0`（左侧为 ⊥ / 标注不一致）时不得判为通过，落 2.2 节的 unknown 分支（诊断「标注不一致 / 义务不可判」），按该族 policy 处置。⊥ 视为判定失败，不视为真 |

## 4. enforcement 通道（动态档实现）

### 4.1 先例（现状事实，enforce 档的原型已运行）

`IR_BOUNDS_CHECK`（`ast.cr:559`，op 30）：语义 = `if ρ(s1) ≥ᵤ s2` 则 `ud2`（`ir-op-semantics.md:196`）；发射 = `ext_safety.cr:27,33`（插件 + 钩子形态，不是语言特判）；解释器侧已实现（`interp.cr:289`）；ELF 侧编码 = cmp + jb + ud2。失败语义 = 中止而非未定义值（安全优先）；负索引由无符号比较天然捕获。

结论：enforce 档不需要新机制，它就是「插件钩子 + 图侧检查节点 + 硬陷阱」的推广。

### 4.2 插入面与发射条件控制

- 插入面：pass 层（与 `ProvenanceVerify` / `RegionCheck` / `ext_safety` 同级），检查节点 = 图上节点（不新增语义，检查是映射实例层的保护带）。
- 发射条件控制（与 TODO「边界判定图 pass」同构）：
 - 证明恒安全（引擎真） 到不发射（prove 档，零字节）；
 - 证明恒违法（引擎假） 到编译期拒绝（2.2 节违法分支）；
 - 判不出（unknown） 到保留检查 + 图推导必要性标注（证明失败的原因随节点写入磁盘，兼作验证证据）。
- 需要新 opcode 时，成本面 = `ast.cr` 分配 + 解释器 + x86 编码 + 检查（先例：`IR_BOUNDS_CHECK` 全链）；本文的切片不新增 opcode（6.2 节）。

### 4.3 失败语义（本文的决定）

| 语义 | 内容 | 适用 |
|---|---|---|
| abort（默认） | 硬陷阱（ud2/SIGILL），与 `IR_BOUNDS_CHECK` 先例一致 | 安全类 sink 的默认 |
| degrade | 净化降级后继续（例如转义/允许清单） | 库声明（policy 数据） |
| report | 报告并返回错误值/错误码 | 库声明（policy 数据） |

- 默认 = abort：中止优于未定义行为（先例已立此检查）。
- degrade 必须由 policy 显式声明（否则等于无提示放行，违反契约 1.2 节原则 3）。

### 4.4 成本规则

- 仅在该 sink 发射检查；无轴使用的程序零产物变化（检查沿用仓库既有形态：byte-identical）。
- 语义层不承诺检查存在（T4），「是否发射」是映射/策略决策，不是语义承诺。

### 4.5 与定案 14 声明式边界的处理

检查节点落在命令式下限（执行面），但它是图构造（与 state edges / region 同层），不是新的顺序语义或语义本体条目。承 v4 十一「证明完毕不下发」：证明产物（含检查的必要性标注）不下发到运行期，只有检查本身按 4.2 节条件控制发射。

### 4.6 双路径一致性（检查要求）

enforce 档一旦实现，检查语义必须解释器 / ELF 双路径一致，沿用 R1 的检查形态（同一用例双路径精确 rc，`test_global_init.py` 先例）。切片 1 不含运行期检查（6.2 节），该项列为切片 2 检查。

## 5. 未证明义务的处理方式（诊断面）

### 5.1 义务状态机与禁令

```
open ──prove(真)── 变为 proved（零成本）
open ──enforce──── 变为 enforced（检查节点已发射）
open ──proof 提供── 变为 proof-provided（proof/contract 归档，验证管线可复核）
open ──strict 未满足── 变为 rejected（编译拒绝）
open ───────────────── 到 passed 不存在（禁令：不省略提示）
```

禁令（契约 1.2 节原则 3 的可实施形态）：证不出到 必归入 2/3/4 之一，绝不会无提示视作通过。3 的「登记」状态是 open（未处置），不是 passed，清单中它是待办，不是已通过项。

### 5.2 三面可见（缺一不可）

| 面 | 内容 | 现状接口 |
|---|---|---|
| a) 诊断面 | `error[XXXX]` / `warning` 体系，新增「安全义务」码段。必须区分三类语义：不可判定 ≠ 不合法（R2 3.3 节同款）/ 未处置 ≠ 通过 / 预算耗尽 ≠ 判定为假 | `diag.cr` + `EC_*` 段（`ast.cr`）+ R2 7 节的分段策略 |
| b) 清单面 | 义务清单（obligations manifest）：轴 / 源 / 汇 / 归入档位 / 状态 / 图到源码位置的映射。是人类与 CI 的条件通道（strict 档 = CI 断言清单为空）。3.1 节「放行 / 声明条目」的每一条（含豁免形态者）必须在此出现（D2：放行必须落清单） | 实现位置实施阶段定（编译输出过渡态先行；`.ccr` 段随 3.4 节 = R2 P4）。格式归 S-D 线统一（D29），各族只写使用位置，不写格式 |
| c) 产物面 | 义务清单 = 图数据的视图（语义一致性兑现，R2 6.4 节同构），验证工具直接使用，不必重跑前端 | `.csr`/TagNode 图验证线（coreir-schema「图即验证」） |

### 5.3 「不会无提示」的可测检查（承诺的可断言化）

- 负向对照：故意留一条未处置义务到 编译输出必须含具名诊断（轴 + 源位置 + 汇位置）+ 清单条目；测试断言二者均存在。
- strict 负向对照：同一条义务在 strict 档到 编译必须拒绝（非零退出 + 错误码）。
- 正向对照：净化后到 通过，且清单中该义务状态 = proved，无诊断。
- 「无提示通过」的反检查：任何「义务存在但输出无诊断且清单无条目」的场景 = 本文的违约，测试必须覆盖。

### 5.4 档 4 的措辞要求

拒绝必须给出路（否则等于无出路）：补 proof/contract / 加 declassify / 显式例外入口（`unsafe` 边界，放行记入清单，承 v4「例外入口授权可追踪（信任链）」）。

## 8. 不承诺

> 逐条引用共享契约 1.3 节三类不可消的残留，说明本族落在哪类。

| # | 契约 1.3 节类别 | 本族（S-A + 属性轴/义务分级）的实现位置 |
|---|---|---|
| 1 | 错误 specification | 本族只能证明「程序忠实实现了 policy」，不能证明 policy 本身正确：policy 漏声明的 sink / 错形状的 source / 错误的 `A_a(v)` 映射到 义务分级结构上无法覆盖它。故本族不承诺「程序安全」，只承诺「相对 policy 的忠实性 + 义务不会无提示」。这是第 1 类的纯实现位置 |
| 2 | 恶意/失陷外部实体 | `trust` 轴提供声明与检查通道（untrusted 标记 + 净化节点），但不能证明「被声明为 trusted 的组件真的可信」，供应链 / 编译机 / 密钥 / 硬件后门不可用语言语义证明。本族贡献 = 把信任假设显式化（可审计、可追踪、最小权限，承 v4「可追踪信任链」），不是消除它。`determinism` 族的 `D_external`/`D_timing` 同落此类：外部世界的时间与环境不可证明，只能归因 + 三值标注（`PROVED`/`MODELED`/`UNKNOWN`），不承诺消除物理不确定性，只承诺不虚假陈述（1.9 节） |
| 3 | 需求本身允许危险行为 | shell / browser / kernel / JIT（just-in-time 编译）必须执行外来代码，`system(cmd)` 本身就是需求（6.1 节的 sink 不是 bug）。本族目标 = 证明隔离边界（形如「不可信数据不能到达解释器语法位」的流规则），不是禁止能力；`declassify` / `unsafe` = 危险行为的显式授权点（登记可追踪） |

全局禁令（原文遵守）：不承诺「能自动证明所有程序安全」，判定引擎是三态 + 预算守卫的，unknown 是设计内的第一等结果（Rice/halting 边界，契约 1.2 节原则 3）。

### 9.1 不做项
