## 一、重点项（须用户裁决，D1–D10）

### D1（轴语义）`trust` / `integrity` 谁是判定轴

- 问题：同一术语在三份 spec 里被判成不同东西，S-A 说 `trust` 可判可传播、`integrity` 是另一条轴（可篡改性）；S-B3 说 `trust` 不可判、可传播的那条叫 `integrity`；S-B1 的判据又跑在 `trust` 上并把 S-B3 第4.2 的「S-B1 = integrity 实例」正面顶回去。
- 提出方：两簇（A-C1 = A-U3；B 侧相邻：U5 标注实现方式）
- 重点项：是（判定对象与判定面归属未定 = 方向性取舍）
- 设计者建议：A-C1 修法 (a)（保 S-A 第1.1 为真源），改动面最小、不破「术语唯一真源」契约
- 若不裁决的后果：S-A 切片 A（`semantic-safety-obligations-design.md` 第6.1）与 S-B1 切片 2（`policy-injection-design.md:379`）双双不可开工；S-B3 第1.2 对照表 / D4 默认源 / 第4.2 实例化表述全部悬空。
- 可选答案：
  - (a) 保 S-A 第1.1 为真源（推荐）：`trust` = 可判传播轴；S-B3 第1.2 的「不可判」改写为「来源真实性的 attestation 不可判（第1.3-②），但程序内传播可判，该传播面即 `trust` 轴」；删/改 S-B3 第4.2 的实例化表述为「S-B1 的裸位置判据消费 trust 轴（S-A 供给）」；`integrity` 在 S-B3 退为对偶表述，不再单列判定面。
  - (b) 采纳 S-B3 两轴分工：可传播判定轴改称 `integrity`，`trust` 退出来源事实（不再进判定）；S-B1 第2.4/第4.6 全文改指 `integrity`；S-A 第1.1「自动推导（传播）」条目删除、第6.1 切片措辞与首消费方表随动。代价：S-A/S-B1 双改 + 术语迁移；收益：attestation 边界更干净。
  - (c) 冻结 trust 判定：先只落 S-B3 的 secrecy/integrity 面，S-A 切片 A 与 S-B1 切片 2 挂起，待 attestation 设计出台再定。代价：安全主线停摆、计划切片顺延。
- 推荐理由：(a) 只改 S-B3 两处、S-A/S-B1 的语义与切片不动，且与 第1.3 三类不可消的划分自洽（「来源真实性」本来就属不可判的第 2 类，把它与「程序内传播」拆开即可）；(b) 触发四份 spec 的术语迁移，(c) 代价最大。
- 共同要求（选任一条都要做）：三份 spec 的「谁定义 / 谁判定 / 谁是消费者」各写一行对表（可照 S-A 第1.9 的「接口需求 / 供给」体例）。

### D2（放行声明）放行 / 信任声明是「一个机制」还是「三个」

- 问题：`declassify`（S-B3 = 图上节点，明言「不是标注、不是 pragma」）、`grant/deny`（S-B2 = 边集合 / 例外条目，自述是 declassify 的同构对应物）、C3 稳定性（S-B5 = 治理层注解）三者功能同构但形态不同，且无一落在 S-A 第3.1 同一张 schema 上。
- 提出方：两簇（A-C2 = A-U2；S-B2 第8.2-7、S-B3 Q4、S-B5 Q3）
- 重点项：是（触及「唯一合法通道」的语义承诺与审计面）
- 设计者建议：A-C2 修法，S-A 第3.1 增设「放行 / 声明条目」栏，规定任何绕过义务的通道只经本栏且必须落台账
- 若不裁决的后果：S-B2 第5.1、S-B3 第3.1、S-B5 C3 的接口栏不定；D4 的实现方式段无 schema 可依；语法位 sink 的 `required` 声明会出现两族各报一条诊断（M1 边界）。
- 可选答案：
  - (a) 统一 schema（推荐）：S-A 第3.1 增设栏目 = `kind{declassify|grant|deny|stability} · 主体/身份 · 目标/范围 · 理由 · 派生源 · 义务引用`；S-B2 第5.1 / S-B3 第3.1 / S-B5 C3 各写一行「本族条目在本栏的形态」；节点形态仍为默认，C3 若坚持注解形态须在 S-A 显式豁免并补审计字段（不得沉默）。
  - (b) 三机制并存：各写明区别与豁免理由（流放行 = 节点、授权 = 边集合、稳定性 = 注解），三者各自补齐审计 / 派生源字段，S-A 处集中登记。
  - (c) 二合一：`declassify` 与 `grant` 合并为统一「放行条目」（都是「¬义务 到 义务」的唯一合法通道），stability 注解单列并补审计。
- 推荐理由：(a) 一次消掉 4 项开放问题（A-C2 原话），且保住「唯一合法通道 + 落台账」承诺，不牺牲节点形态的可审计性；(b) 留下三套审计口径的变化面，(c) 会把授权族与流族的义务粒度差异抹平。

### D3（默认强度）默认强度 / strict / 档③ / `select` 窗口

- 问题：③ 默认是「登记 + 继续编译」还是拒绝（S-A 第9.2-1）；strict 是否把未声明的边界条目当 unknown 从而拒编（S-B3 Q9）；enforce 是否默认启用（S-B2 第3.3）；`select` 未标注时的默认形态 + W1 窗口长度 + 是否有永久 lenient（S-E Q3）。
- 提出方：两簇（A-U1 · B-U2 · B-U11）
- 重点项：是（= 产品承诺：误报率 vs 保证强度）
- 设计者建议：分层默认（见选项 c）
- 若不裁决的后果：全部切片的正 / 负控与 CI 要求无法定稿；台账能否为空未定；S-E 第5.1-(5) 的 `select` 判据无落点。
- 可选答案：
  - (a) 全严：③ 默认拒绝编译；enforce 默认启用；未声明边界条目按 unknown 且拒编；`select` 未标注即 reject（无窗口）。
  - (b) 全宽：③ = 登记 + 继续编译；enforce 需显式开启；未声明边界按最宽处理（不拒编）；`select` 永久 lenient。
  - (c) 分层（推荐）：③ 默认「登记 + 继续编译」、strict 档拒编、CI 要求为严；enforce 默认启用（可 enforce 一律 enforce，高安全档关闭）；未声明边界条目取 unknown（保守判定方向）但不拒编，报告面可见；`select` 给显式迁移窗口 W1（默认 1 个发布周期），窗口内 lenient + 诊断，窗口后强制标注。
- 推荐理由：本地开发不阻塞、CI 守门，两个强度在两个面上各就各位；未声明边界取 unknown 与 S-E / S-B5 的保守方向一致（避免把「不知道」渲染成「确定」）；窗口制给迁移成本留口子而不承诺永久 lenient。

- 问题：轴标注走既有插件标签通道 vs 独立语法（S-A 第9.2-2）；policy 条目的注册形态；S-B5 形状项语法；S-B1 声明记法；参数级档位约束声明面（I5 新增：`sql_text(lit: string)` 上怎么标 κ=const，R2 的 interface 语法不覆盖）；`merge_ordered` 允许清单是否纳入「显式序号域」（B-U4，与本条同源）。

- 若不裁决的后果：语言面改动面不定；S-B1 切片 1 的硬前置（参数级档位约束声明面）无法开工；S-E Q2 的顺序源覆盖面悬空。
- 可选答案：
  - (a) 零新语法（推荐）：轴 / 汇合 / 上界 / 局部性标注全部落插件标签通道；参数级档位约束落 policy 数据表（不新增声明语法）；`merge_ordered` 允许清单不纳入「显式序号域」，顺序源仍限 `state-chain` / `region-order`。

  - (c) 立新语法：轴标注 / 显式序号域 / 参数级约束各自立语法或关键字（表达力最强，契约破例最大）。
- 推荐理由：「零新语法」是已写入契约的承诺，破例应先证明既有通道确实不足；参数级约束用 policy 数据可满足 I5 的判定需求且不触语法面。(b)(c) 会把「语言面 vs 策略数据」的边界永久模糊化。
