## 0. 范围与决定

### 0.1 论题

> 汇合点的语义必须由图决定，不能由调度决定。
 > 物理到达顺序可以决定处理顺序，但只有两种情形合法：1 图中已证明该影响不可观测（`merge_deterministic`）；2 图中已显式声明该影响（`race` / `select_any`）。二者之外 = 隐式竞争 = 拒绝编译。

本文处理执行模型层的语义，即汇合（merge）这个图事件。它不涉及属性轴与义务机制本身的定义（S-A），也不涉及报告部分的 CLI 与输出契约（S-D），只提出对二者的接口需求（5 节）。

现状缺陷（用户在 2026-09-11 决定待修）：三处文档把 `select` 的语义写成「最早到达的令牌」（`docs/dataflow-design.md:102`、`docs/project-book.md:241`；`docs/dataflow-design.md:61-74` 的 load_balancer 例是该语义的实例）。这是把物理调度顺序混入语义，而 `docs/execution-model.md:15` 同时声称「DAG 因此依赖偏序，无反馈，确定性」。两句话互相矛盾：要么 DAG 的确定性不成立（汇合点可以由物理顺序赋值），要么 `select` 的语义是错的。按共享契约 1.4 节的「不确定性 = 显式请求」，错的是后者。

### 0.3 决定清单（本族的定案）

- L1 汇合点 = 图对象，四形态 = 图标注。汇合点 M 定义为「跨执行流 / region 汇合的 DFNode」，可判定检查（B 线 C3 限定为 收敛批 v3 语义定位点，取代原「入数据边 ≥ 2」字面与原 region 身份定位点；B-N1）：M 的入数据边 ≥ 2 且至少满足其一：
 - 1 并发汇合：M 的输入前驱之间无依赖路径（在数据边 / state 边 / region 迭代序的传递闭包中互不可达），且每个前驱各自可达一个不确定源根，并发根 `IR_SPAWN`（`ast.cr:556` = 27）｜迭代根（`SG_LOOP` / `SG_FOR` 的 从 `nstart` 到 `exit` 序，`dataflow.cr:213`）｜边界根（无方法条目，memory-model 规则 4）。
 - 2 迭代汇合：M 的输入前驱在 `SG_LOOP` / `SG_FOR` 上跨迭代边界汇合（同一节点在两个迭代上的产出）。
 - 3 定序汇合（`merge_ordered` 候选面）：M 的输入前驱之间存在跨 ≥ 1 个 region 边界的定序路径（state 边链 / region 迭代序），M 走 1.5 节步 3 判定（不是「无依赖路径」那一支）。
 - 4 边界汇合：M 的每个输入前驱各自可达边界节点（无方法条目）。
 为何从 region 身份改为依据语义（B-N1 实测，硬性）：今日 `sg_push` 的全部产生点 = `SG_FUNC`（`dataflow.cr:473`）、`SG_IF`（`ir_gen.cr:1622`）、`SG_LOOP`（`ir_gen.cr:1693`）、`SG_FOR`（`ir_gen.cr:1751`，经 `sg_alloc_push`）、`SG_UNSAFE`（`ir_gen.cr:2158`，同）；`SG_FLOW` 无任何产生点，因此恒不产生（4.2 节现状断言已改）；`IR_PHI` 今日零发射（只被使用：`ptr_analysis.cr:310` / `dump.cr:196` / `ent_kernel.cr:369`）。而今日并发 = `IR_SPAWN` 且 `go` 体降为独立函数，因此两路 spawn 的产出在其使用者处汇合时，两个前驱同属调用者的 `SG_FUNC`，因此原 1 不成立、原 2 不适用、原 3 恒假、原 4 不适用，因此执行会无提示变成 no-op，而验收面察觉不到。语义定位点使该场景可判，且不依赖 region 区间细节。
 负向对照：普通直线程序的二元节点（`a - b`、`s1 + s2 + s3` 的中间节点）与 `SG_IF` 两分支交叉（`SG_IF` 覆盖 `[condition, merge)`，`ir_gen.cr:1622`，因此分支内取值的节点与分支外的节点在 merge 后同现时前驱分属 `SG_IF` / `SG_FUNC`）都不满足任一条件，因此不属于汇合点，不得进入 1.5 节决策序、更不得 reject（N7 两例；原字面的过捕获 = B-C3/D18）。
 登记（不作为今日检查）：`IR_PHI` 及将来的 phi 形节点实现后，其出现可重新作为独立充分条件（原检查 2）；`SG_FLOW` 若将来实现，其容器语义同样重新作为充分条件（原检查 3）。四形态不是四个关键字，而是 `determinism` 轴族（契约 1.4 节）上的开放标注：`deterministic` / `ordered(src)` / `race(k)` / `any`。命名对照（本文两套记法同义，避免误读为八种东西）：形态名 `merge_deterministic` 与 标注名 `deterministic`；`merge_ordered` 与 `ordered(src)`；`race` 与 `race(k)`；`select_any` 与 `any`。形态名用于论述，标注名是图上实际标注的拼写。不加关键字、不改 Graph 本体（承契约 1.2 节-1「属性不提升为语言 primitive」、定案 1「类型 = 图标注」）。标注的实现方式与注册通道归 S-A（存储实现方式随 D4 决定：与 R2 P4 同波进 `.ccr` 段）；本文只给语义内容与必填字段（5.1 节）。
- L2 四形态的区分量 = 观测结果对到达序的函数依赖。设 M 的语义函数 `F_M(c, π)` 得到 `obs`，其中 `c` = 输入值多重集、`π` = 物理到达序（π 不是图对象，这是本文一切定义的前提）：恒定，得到 `deterministic`；仅经显式顺序源 σ 依赖 π，得到 `ordered`；依赖但声明允许，得到 `race`；只声明对来源身份不敏感，得到 `any`。未证明且未标注，结果为 reject（唯一执行点，并发面；外部不可见面的同形执行归 S-B5，4.1 节 D23）。
- L3 观测（observation）面必须先定义，否则四形态不可判定。`obs(·)` = 1 值输出（数据边出边上的值）；2 效应（`STORE` / 通道 send / extern 调用 / `YIELD`）；3 控制去向（后续 region 归属，SG_IF/SG_LOOP 的走向）。唯一不在观测面内的量 = 到达位置 / 到达时刻 / 到达顺序本身，这就是本族的去物理化操作。任何把物理序提升为可观测值的图结构（读时钟、自旋计数、原子序号、优先级抢占痕迹）都是 π 的代理量，见 2.2 节。
- L4 `race` 的结果集语义 = 只承诺集合，不承诺元素。`Obs(M) ≜ { obs(F_M(c, π)) : π ∈ Π }`，集合本身确定，唯一的不确定是"集合内选哪个"。声明的附加义务：集合可枚举（或显式声明不可枚举到 高安全模式 reject）。
- L5 `merge_ordered` 的顺序源允许清单（首版即终版）= state 边链 ∪ region 迭代序。两者都是图上显式对象。允许清单外的一切"顺序"都不是顺序源：物理时间戳、`sleep`、线程 id、就绪队列位置、声明式优先级，它们读的是 π 的代理，归入 `race` 或 reject（见 1.2 节否定例）。显式序号域（用户标注 order key）已确定（D5）：不纳入，坚持不新增语法，允许清单不扩展。
- L6 `select` 保留关键字拼写，语义重新确定为 `race(1)` 的语法简写。存量无实现（3.1 节已核实），因此迁移是文档语义迁移而非代码迁移。未标注的 `select` 默认结论 = 「未证明未标注，结果为 reject」；兼容窗口 W1 = 1 个发布周期（D3）内降为 warning + 自动标注 `race(1)`（3.3 节；strict 档 / CI 条件窗口内不放宽）。
- L7 自动并发只移动已证明的 `merge_deterministic`（承 TODO 2026-08-30 与契约 1.4 节）。移动 = lowering，须满足 2 节的全部三条检查面。`merge_ordered` 的保序并行已确定纳入（Q5/D21）：前置 = 两个条件（可判定性 + 确定性判定），lowering 须证「state 边序 = 观测序」，见 4.3 节。
- L8 本族没有 enforce 通道（定稿结论）。确定性不可能运行时强制：事后检测到"结果不同"已经太晚，事前强制 = 换实现 = 改语义形态（那是 `ordered` 的事，需要用户同意）。因此本族在四档上只使用 `prove` / `proof-required` / `reject`，enforce 档不使用。S-A 1.9 节已按此决定：族级 policy 取 `allow_enforce=false`（隐式竞争因此固定归入 4 reject，无需改决策树）。不得用"插入运行时检查"代替（5.1 节-(2)）。

## 1. 四形态语义（图级定义）

### 1.0 共同图模型与判定问题

| 记号 | 含义 | 是否是图对象 |
|---|---|---|
| `M` | 汇合点：跨执行流 / region 汇合的 DFNode（可判定检查见 L1，语义定位点 = 输入前驱间无依赖路径 ∧ 各自可达不确定源根；非普通二元节点） | 是（`g_df_nodes`） |
| `c` | M 的输入值多重集（无视顺序） | 否（运行时值） |
| `π ∈ Π(M)` | M 的输入令牌的物理到达排列 | 否，不是图对象，不可读、不可命名 |
| `obs(·)` | 观测（L3）：值 + 效应 + 控制去向 | 是（出边 + state 边 + region 归属） |
| `F_M(c, π)` | M 的语义函数（图 + 输入到 观测） | 是（图决定其形状） |
| `σ` | 显式顺序源：图上的定序对象 | 是（state 边链 / region 迭代序） |

判定问题：`∀ π, π' ∈ Π(M)，obs(F_M(c, π)) = obs(F_M(c, π'))` 是否成立？

记号前提（B 线 C3 附加）：`c` 写作多重集仅在「位置绑定由图固定」时充分，入边的位置绑定（哪个输入接哪个操作数位）由边身份决定（图对象），不是 π 的一部分、也不计入 π；若某形态的位置绑定随调度可变，则该形态不在四形态管辖内（须先修本表记号）。普通二元节点的位置绑定是编译期固定的，因此不属本族（L1 预筛拦截；D18 选项 3 的记号问题在此结束）。

四个形态 = 对这个问题四种语义承诺，其区别只在「F 对 π 的依赖被如何处置」：

| 形态 | 承诺 |
|---|---|
| `merge_deterministic` | 恒定：F 与 π 无关 |
| `merge_ordered` | 投影依赖：若 `σ(π) = σ(π')`，则 `F(c,π) = F(c,π')`，且 σ 由图决定 |
| `race(k)` | 集合确定：`Obs(M)` 是确定的有限集，元素由实现自由选 |
| `select_any` | 身份不敏感：F 只依赖"有输入"这件事，不依赖"从哪条边来" |

这四行是语义，不是实现建议；下文的图表示 / 检查 / 归入档位 / 可见性全部从这四行导出。

### 1.1 `merge_deterministic`

图表示：M 携带 `deterministic` 标注（或因无标注而被分析器证明后赋予）。要求 M 的输入集合闭合：所有可能到达 M 的输入边在图上是可枚举的（无"运行时新连的边"，动态图重连须先经 2 节检查）。

判定检查（三合取）：

| # | 检查 | 判定面 | 手段 |
|---|---|---|---|
| (a) | 无 state 边入边：M 不在副作用链上（kind=1 入边计数 = 0） | 结构 | 分析器自动（O(边数)） |
| (b) | 无 π 代理量：从 M 沿 def-use + state 链可达的节点中，不存在读取到达位置/时刻/顺序的量（`now_monotonic`、自旋计数、原子序号、线程 id、就绪队列位置），也不存在以"到达次数/第几个到达"为条件的 BRANCH | 结构 | 分析器自动（π 不可命名，因此一切"序依赖"都必然经由代理量，故本条可判定） |
| (c) | 组合函数序无关：M 的计算在输入多重集上良定义，组合算子满足交换 ∧ 结合（+ 幂等，若存在重复到达路径） | 值 | 引擎判定（R2：类型项/形状项）；证不出则由用户提供证明 |

检查 (b) 的可判定性论证（本族的关键结构事实）：π 不是图对象，图上没有"到达序号"这种输入端口。因此"依赖物理序"在实践中只能通过代理量实现，而代理量是图上的普通节点、可被扫描。这使「隐式竞争」成为可判定的（而非传统自动并行化那样靠依赖猜测，TODO 2026-08-30 记的同一论据）。

检查 (a) 的可靠性前提（硬性，假阴性风险；已于 2026-09-11 效应/纯度批满足，修复前快照见下）：检查 (a)「无 state 边入边」只在 state 链覆盖全部可观测效应时才是充分的；否则 (a) 会假阴性，把实际有序依赖的汇合误判为 `deterministic`。前提已于 `762bd429`+`c9099d73` 满足：
- 入链检查 = 单一依据 `purity_op_effect`（`checker.cr:2912`），store 家族 + `IR_CALL_EXTERN` + `IR_SPAWN`/`IR_YIELD`/`IR_HOTPATCH_ROUTE`/`IR_DYN_DISPATCH`（间接调用）/`IR_STORE_PTR`/`IR_AWAIT` 全入链（`df_connect_state`，`dataflow.cr:146`）；
- `fi_ispure` = `compute_all_purity`（`checker.cr:2959`）真值（保守起点「全不纯」+ 调用图不动点 + 递归/SCC 保守 + 不可解析调用保守），因此一切未证纯的可解析调用（`print` / `read_file` / `chan_send` / `sched_go`…）入链。保守方向保证无假阴性（宁可多判 `ordered`，不可漏判 `deterministic`）。
- 修复前（历史快照，保留备查）：`df_connect_state`（`dataflow.cr:160-177`）分类表不含 `IR_CALL_EXTERN`（`ast.cr:572` = 45）；`fi_ispure` 唯一写入点（`checker.cr:1107`「all functions are pure」/ `:1142` extern）值恒 1，因此除 store 家族与不可解析调用（builtin）外没有任何调用进入 state 链；且链每函数重置（`dataflow.cr:401`）。

### 1.2 `merge_ordered`

图表示：M 携带 `ordered(src)` 标注，`src ∈ {state-chain, region-order}`（L5 允许清单）；且图上存在从 `src` 到 M 的每条入边的定序见证（witness）。标注必填字段 = src 的类型 + 见证的边集。

判定检查：

1. 溯源：M 的每条入数据边可溯源到一个顺序源（state 边链的链序，或 region 迭代序 从 `nstart` 经 … 到 `exit`）；
2. 全序：src 在 M 的输入集合上是全序（任意两条输入可比较；不冲突、不并列）；并列时不得无提示 tie-break（那会把 π 从后门放回来）；
3. 非代理：src 是图上显式对象，不是 π 的代理（即 1.1 节(b) 的反面检查，src 自身不得含 π 代理量）。

否定例表（必须写清，否则"优先级 select"会被误当 ordered）：

| 候选 | 为什么不是顺序源 |
|---|---|
| 物理时间戳 / `sleep` 时长 | 读物理时间，因此π 的代理 |
| 线程 id / 就绪队列位置 | 调度器内部状态，因此π 的代理 |
| 声明式优先级（"req 优先于 signal"） | 只决定谁赢在同时就绪时；而"同时就绪"本身由物理决定，因此仍是 π 的函数。因此归入 `race`（可选：优先级作为 tie-break 规则记录进报告，但不消除不确定性） |
| 通道 FIFO 序 | 半合法：同一 channel 上的 send 序是图上的（生产者之间的 state 边链），跨 channel 则不是。因此只在"每个输入边各自有 state 链"时可作 src |

义务归入档位：prove（src 全序 + F 被唯一确定）；src 存在但覆盖不全到 proof-required（补顺序源或补证明）。

观测可见性：确定。不进不确定列表；可进"已证明（顺序源：state 边 / region 序）"列表。

### 1.3 `race`

图表示：M 携带 `race(k)` 标注（k = 胜者数；缺省 k=1）。必须显式，无标注的竞争 = 隐式竞争 = reject（3.3 节窗口内降为 warning）。

判定检查：`Obs(M) = { obs(F_M(c, π)) : π ∈ Π }` 良定义且可枚举（基数已知或可静态上界），或显式声明为不可枚举（到高安全模式 reject）。

义务归入档位：1 prove + 报告义务（S-A 1.9 节已确定决：显式请求 = 义务已被「程序说的是它想说的」处置，不新增第五档）+ 报告部分强制登记（S-D）。prove 的证明内容不是空话，须证明「该汇合点是此处唯一的不确定源」（声明不得成为隐藏相邻不确定性的挡箭牌）。证明范围已确定（D10）= 局部：只覆盖汇合点本身；报告部分必须显式标注「该保证未覆盖观测点」（准确性由报告部分承担，S-D 1.7.1 节强制约束 9）。升档到「到观测点整条路径」为未来候选（若实测证明挡箭牌不足再升；只动义务范围，不返工已有检查）。

观测可见性：报告部分必须列出：1 race 点 id；2 输入边集；3 k；4 结果集 `Obs(M)` 的基数上界（或"不可枚举"标记）；5 provenance 链（5.2 节）；6 prove 范围 = 局部（未覆盖观测点）。
禁止：分支体把"当前分支是第一个到达"当作不经 witness 通道的可读事实（例如以到达序索引写共享输出）。
胜者身份作为显式出参（witness）= 已确定（D9）：允许，witness 是图上的一条显式值边（不是 π 代理），登记为 `EXPLICIT` 不确定源 + 报告义务；`select` 现有分支体写法（`req = recv => …` 用了 `req`）据此可平迁，`load_balancer` 例保留。

race 不豁免确定性：它承诺的是"集合确定"。把 race 读成"此处随便"是误读，`Obs(M)` 本身是程序语义的一部分，报告部分要能把它列出来。

### 1.4 `select_any`

图表示：M 携带 `any` 标注。语义 = `obs` 对来源身份不敏感：分支体的观测不依赖"哪个输入先到/到了哪个"。

判定检查（两条路径）：

| 路径 | 条件 | 结果 |
|---|---|---|
| (i) 等价升级 | 各分支体观测等价（值 + 效应 + 控制去向三项等价，由引擎的等价判定给出） | 升级为 `merge_deterministic`，归 prove，零成本 |
| (ii) 默认 | 不可证等价 | 与 `race` 同：显式不确定 + 报告部分；`Obs(M) = { 各分支体的观测 }`（有限，可枚举） |

路径 (i) 的地位（区分设计与待确定）：设计已定等价即确定的推理是直接的（分支选谁都一样，因此 obs 恒定）。待确定"观测等价"的判定能力，R2 引擎目前判定 `ty_sub`/`ty_equiv` 等类型项，尚无效应等价（effect equivalence）判定器。因此 (i) 是目标形态，实现依赖引擎的效应判定扩展；在此期间 (ii) 是实际路径。不得把 (i) 呈现为已可用。

义务归入档位：(i) prove（确定性，零成本）；(ii) 1 prove + 报告义务（同 race：证明内容 = 该点是此处唯一不确定源；范围 = 局部，D10，报告部分标注「未覆盖观测点」）。

观测可见性：(i) 不进报告；(ii) 进报告，附"来源身份不敏感"说明。

### 1.5 判定序（本族的决策过程）

给定 M，按下序判定，先到先得：

```
0. 汇合点预筛：M 满足 L1 检查（跨执行流 / region 汇合，语义定位点：1 无依赖路径 ∧ 各自可达不确定源根 / 2 迭代边界 / 3 跨 region 定序路径 / 4 边界根）
 否则不进入本序、且不做任何判定（既不得 reject、也不得归入 3；检查不得因「根本不识别」而空过，B-N1）
   （普通二元节点与`SG_IF`分支交叉均不属于本族管辖，不得 reject，B 线 C3 负向对照 + N7）
1. 结构预筛：无 state 边入边 ∧ 无 π 代理量 ∧ 输入集闭合，则为候选 deterministic
2. 引擎判定组合函数序无关（交换 ∧ 结合），判为 merge_deterministic   [prove]
3. 顺序源 σ 在允许清单内 ∧ 对 M 的输入全序 ∧ src 非代理，判为 merge_ordered         [prove]
4. 顺序源存在但覆盖不全，归 proof-required（补证明/补顺序源）
5. 有 race/any 显式标注，归 1 prove（声明与实现一致）+ 报告义务（+ 可枚举义务）
6. 其余（未证明 ∧ 未标注），判为 reject，这是唯一执行点（并发面；与 S-B5 的分界见 4.1 节 D23）
```

证明优先于声明（冲突规则）：若第 2 步已证明序无关，则即使 M 带 `race`/`any` 标注，报告部分按实际分类（= 确定），标注降级为冗余声明诊断（warning，非错误）。理由：报告必须显示程序实际的不确定性，而不是用户声明的不确定性，否则 `race` 会成为"隐藏本来可证的程序"的通道，与「不确定性 = 显式请求」的意图相反（请求要显式，但不得伪装）。

## 2. 物理不能推出语义：降级义务

### 2.1 「引入不确定性」的检查（定义）

> 引入：存在同一张图 G、同一输入 c 的两次执行 e₁, e₂，使 `obs(G, c, e₁) ≠ obs(G, c, e₂)`，而 `G` 上没有任何节点声明 `race`/`any`，且差异可归因于 {发射层, 调度器, 求值顺序} 三个物理面之一。

即：`∀G, c：obs(G,c,·)` 恒定，除非 G 上有对应声明。违反 = reject（编译错误，属"物理不能推出语义被破坏"）；无法判定到 proof-required。

本节论题句（写进实现规则）：被限制的不是调度器的自由度，而是「自由度泄漏进 `obs`」。调度器可以任意选择（性能面），只要选择不影响观测。

### 2.2 三个检查面

| 面 | 检查内容 | 例子（合法 / 非法） |
|---|---|---|
| 发射层（lowering） | IR 到机器码 / 表条目的 lowering 不得引入序依赖 | 合法：`merge_deterministic` 的 n 输入加法降低为"按寄存器分配顺序发射的链"，加法可结合，序不影响值。非法：把非结合算子（浮点加/乘、饱和加法、定长截断/溢出包裹、多字 tag/2L 编码下的饱和路径）降低为序敏感实现；或把"先到先累加、超界即截断"当作确定性汇合 |
| 调度器 | 就绪队列顺序（round-robin / work-stealing）不得成为语义输入 | 选择函数只允许读图上声明的顺序源（state 边就绪标记、region 迭代指针）；禁止用时间片计数 / 线程 id 作 tie-break 并让该 tie-break 影响 `obs` |
| 求值顺序（编译器内部） | pass 重排 / 内联 / CSE / 寄存器分配不得改变 merge 点的输入到达集合，或引入序依赖 | 特别：LICM / 惰性下沉不得把带 state 边的节点跨越 merge 点移动；CSE 合并两个 race 点会改变 `Obs(M)` 基数，因此须检查 |

这条给编译器 pass 的可陈述不变量：每个变换都保 `obs`。原文（TODO / pass 文档）里"凭感觉安全"的表述，应由本检查替代。

### 2.3 与「部署配置不改语义」的关系

`docs/execution-model.md:19`「执行方式（串行/并行/调度策略）由部署配置决定，图语义不变」，本节的检查正是这句话的可检查形式：部署配置切换调度策略后 `obs` 必须不变（除已声明点）。因此本族加强而非削弱该原则：把"图语义不变"从口号变成合规条件。

理由：1 现状无实现，因此无迁移成本（3.1 节）；2 拼写保留使既有文档/示例保持可读，改动面收敛到语义段；3 四形态不进关键字表（L1：形态是图标注，源码拼写由 S-A 的标注通道保存，如 `where`/annotation），所以"保留 select"与"不加新关键字"不冲突：`select` 是汇合语法（图构造），`race`/`any`/`deterministic` 是图上标注（属性面）。

未采用备选：把 `select` 收编为库函数/宏（`chan.select(...)`）。理由：汇合是图构造而非库调用，它改变图的拓扑（多输入边汇合点），库函数无法在类型层表达"入边集合"这一图结构。

### 5.2 给 S-D（`core analyze --determinism` 报告部分）

provenance 链的形状要求（本文只给形状，格式归 S-D）：

```
来源节点 ──(传播)──▶ 汇合点 ──(传播)──▶ 观测点
boundary #27 到 parser 到 branch 到 output

 外部输入面    数据边/state边   race/any    ACTIVE_OP
 (D_external)   (图传播)        标注点    (可观测)
```

即：每条不确定性的报告项 = 从源到可观测点的一条链，链上必须标出汇合点（不确定性被引入/放行的位置）与形态。要点：

### 6.3 检查的表述原则（本族的方法论立场）

- 一切检查表述为「图 + 输入到 观测」，不得表述为"运行 N 次结果一致"，后者是概率证据，不是检查（承契约 1.2 节-3「义务不会无提示」：检查不得靠采样）。
- 检查必须非空可测（B-N1 新增，规范性）：正向对照与负向对照都必须断言「本族识别出的对象（汇合点 id）出现在报告 / 诊断中」，否则检查在「根本不识别汇合点」时空过为真（正向对照全部通过、负向对照不触发），执行无提示退化为 no-op 而不被察觉。字段面借 S-D 1.7.1 节强制约束 7（形态 / 汇合点 id / 输入边集 / …），本文不另立格式。
- N5 的"双调度对照"是对检查"的实证手段（用于在实施早期捕获 2 节违规），不是验收检查本身。两者不得混同，这条要在实施批的测试设计里写明。

## 7. 不承诺

逐条对齐共享契约 1.3 节的三类不可消残留（本族落在哪里）：

1. 错误 specification：本族证明的是"汇合与调度无关"，不是"用户的 `race` 声明是合理的"。`race(k)` 的内容（此处允许竞争是否满足需求）是需求层的事，语言只保证它被显式化并进报告。因此本族不承诺"程序的所有不确定性都是可接受的"。
2. 恶意 / 失陷外部实体：外部输入本身的不确定性（`D_external`）不由本族消除。本族承诺的是：外部不确定性进入图之后不得被放大为隐式竞争，也不得被悄然隐藏（必须出现在 provenance 链上，5.2 节）。恶意来源可以通过 boundary 提供的时序影响哪些 race 结果出现，本族不证明其结果集之外的任何事情。
3. 需求本身允许危险行为：并发竞争本身可能正是需求（负载均衡器抢单、超时竞速、取消传播）。本族不禁止竞争，只要求它显式（`race`/`any` 声明 + 报告 + 可枚举义务）。与 1.3 节的对应：本族做的是"把能力与它的代价同时写进图"，而不是禁止能力。

本族另外明确不承诺：

- 不承诺"Core 程序无数据竞争"，那是内存模型面（arena/region 隔离、借用检查）的事。本族只管可观测语义序，不管字节级并发访问。两者不互相蕴含（隔离的内存上仍可有汇合语义的不确定；反之亦然）。
- 不承诺 `race` 的结果集在跨机器 / 分布式执行下可枚举，那是 `D_mapping`（跨机器语义确定性）面，与 S-C / S-D 的衔接点。语义 ≥ 映射：映射换而集合语义不变，但集合的具体元素分布是映射的事。
- 不承诺代价模型（并行是否值得）= S-C。
