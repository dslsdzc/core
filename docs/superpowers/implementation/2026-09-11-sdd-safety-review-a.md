## Critical findings

### C1（Critical）`trust` / `integrity` 轴在三份 spec 里被赋予互相矛盾的性质与归属

**证据**：
- S-A `semantic-safety-obligations-design.md:76-80`：`trust` 语义 = 「值是否由受控方产生」；**载面 = 节点标注 + 沿值流边的传播**；来源 = 库声明 **+ 自动推导（传播）** + 净化节点。首消费方 = S-A 切片、S-B1、S-B4。
- S-A `:97`：`integrity` = 「值是否可能被非授权方改写（**与 trust 对偶但不同轴**——trust 问来源，integrity 问可篡改性）」。
- S-B3 `policy-information-flow-design.md:70-79`（§1.2 专设对照表）：**「trust 能否被语言判定 = 不能——属 §1.3 第 2 类……只能靠可复现构建/签名/provenance 缩小」**；「integrity 能——沿图单调传播」；一句话「把 `trust` 直接当流纪律用会立刻退化成不可判定」。D4（`:45`）：integrity 源 = 边界条目**一律 Untrusted**。
- S-B1 `policy-injection-design.md:295`（§4.6）：本族消费 **`trust`（不可信度，完整性方向）**，S-B3 消费 `secrecy`，「两者是不同轴」，**本文不定义 `integrity` 轴用法**；`:204-212`（§2.4）裸位置的判定依据 = `⊢ Trusted(v)`，且**「常量 ⇒ Trusted 可证」= 对 trust 做了语言判定**。
- S-B3 `:237-246`（§4.2）：**「S-B1 的『非法边』= 完整性标签到达一个 `required = Trusted` 的语法位端口——S-B1 是 S-B3 完整性轴在『解释器端口』这一类 sink 上的实例化」**。

**冲突**：同一条轴（互不相同的三套说法）：① S-A：trust 可判、可传播，integrity 是另一条轴（可篡改性）；② S-B3：trust **不可判**，可传播的那条轴叫 integrity；③ S-B1：判定依据跑在 trust 上（可判、沿传播），且 integrity 不归自己。S-B3 §4.2 又把 S-B1 纳入为 integrity 的实例 —— 与 S-B1 §4.6「不同轴」正面冲突。这不是措辞差异：**判定对象是谁、判定面在哪份 spec** 直接决定实现归属，也决定 S-A §6.1 切片（`untrusted ↛ system(cmd)`，跑的就是 trust 传播）能否成立。

**连锁影响**：S-A 切片 A（`:427-429`）与 S-B1 切片 2（`:379`）都建立在「trust 可判」之上；若采纳 S-B3 §1.2 的立场，两者同时失效。反之若采纳 S-A 立场，S-B3 §1.2 的整张对照表与 D4 的默认源设计（secrecy 声明式 / integrity 默认不可信）需重写为「integrity = 传输轴，trust = 上游来源事实（不进判定）」并把 §4.2 的「S-B1 = 实例化」删掉或改为「S-B1 在其端口上**消费** integrity 标签（由 S-B3 供给）」——但那时就不该叫 trust。

**修法建议（择一，须用户裁决）**：
(a) **保持 S-A §1.1 为真源**：`trust` = 可判传播轴；把 S-B3 §1.2 的「不可判」改写为「**来源真实性的 attestation 不可判**（属 §1.3-②），但**程序内传播**可判 —— 该传播面即 S-A 的 `trust` 轴」；删/改 S-B3 §4.2 的实例化表述为「S-B1 的裸位置判定依据消费 `trust` 轴（S-A 供给）」；`integrity`（S-A §1.3 = 可篡改性）在 S-B3 里退为「与 trust 对偶的表述」，不再单列判定面。
(b) **保留 S-B3 的两轴分工**：S-A §1.1 `trust` 的「自动推导（传播）」条目删除、改指 integrity；S-B1 §2.4/§4.6 全文改指 integrity；S-A §6.1 切片的措辞与首消费方表随动。
**共同要求**：无论选哪条，三份 spec 的「谁定义、谁判定、谁是消费者」必须各写一行对表；S-A §1.9 式的「接口需求/供给」体例可照抄。

### C2（Critical）显式放行/信任声明是「一个机制」还是「三个」——未收敛，且节点/注解的原则冲突

**三处说法**：
- S-B3 `:183-190`（§3.1，承契约 §1.1 `declassify`）：放行 = **图上显式节点**，四字段（目标标签 / 范围 / 理由 / **授权**）；`:194`（§3.2-1）明确「只存在两类合法通道……二者都在图上是一个节点，**不是一处标注、不是一个 pragma**」；授权字段「本 spec 不判，**作为义务交 S-B2**」。
- S-B2 `:50-56`（§0.3）：唯一合法通道 = **显式治理层声明（grant 边 / 例外条目）**，派生源必须可追踪；并自述「这是计划 §1.1 `declassify` 在授权族的**同构对应物**」；`:220-229`（§5.1-(a)）声明式条目「复用现有声明形式，**不新增关键字**，形态实施阶段定」。
- S-B5 `:92`（C3）：「κ 在图存在区间内被声明为『外部代理不推进它』（独占/不可变）——**治理层注解**，非语义本体」；`:225`（Q3）「C3 归谁：治理层注解（**S-A policy 接口**）vs 领域库 contract——本族倾向后者，待 S-A 对表」。
- S-A `:283-293`（§3.1 policy 条目）：栏目 = name/ns · 涉及轴 · source 集 · **sink 集** · 流纪律 · 落档规则 · **declassify 通道** · 诊断码 —— **没有** grant/deny 边栏位，也**没有**「稳定性/信任假设声明」栏位；`:148`（§1.8）已登记 `secrecy × authority` = 「declassify 自身带 authority 义务」→ S-B3+S-B2。

**问题**：(i) 三者功能同构（都是「¬义务 → 义务」的唯一合法通道 + 必须可追踪），但**形态不同**（节点 / 边集合 / 注解）；(ii) S-B3 立的原则「放行必须成节点，不得是注解」被判 S-B5 的 C3 = 注解直接违反；(iii) 三条声明都没有落在 S-A §3.1 的同一张 schema 上，而 S-A 是「术语与机制的唯一真源」；(iv) 审计承诺不一致：S-B3 说放行进三面可见 + 台账四字段；S-B2 说派生源可追踪；S-B5 对 C3 **未写任何审计/派生源要求**（只在 §6-1 把「外部代理不推进」整条推向「不可证明、只能声明」）。

**修法建议**：S-A §3.1 增设一栏（名称建议 `放行/声明条目`，字段 = kind{declassify|grant|deny|stability} · 主体/身份 · 目标/范围 · 理由 · **派生源** · 义务引用），并规定「任何绕过义务的通道**只**经本栏条目、且必须落台账」；然后 S-B2 §5.1、S-B3 §3.1、S-B5 C3 各写一行「本族条目在本栏的形态」+ 与节点形态的关系（若 C3 坚持非节点形态，须在 S-A 处显式豁免并补审计字段，不能沉默）。**这一条同时消掉 4 项开放问题**（见合并清单 U7）。

### C3（Critical）§3.3.1 C1-C4 只堵「左塌 ⊥」，同类恒真放行可从右路径回来；正例的非退化性无控

**被问的问题**：C3「⊥ 非真」是否真能堵住「否定展开 → 左侧塌 ⊥ → 恒真放行」？**答：能堵该路径，但不完备。**

**证据与推理**：
- 左路径 ✓ 被堵两层：C1（`S-A:323` 禁止否定形式编码）+ C3（`:325` 用 `ty_inhabited(τ_value ⊓ A_a(v)) == 0` 判失败；`ty_inhabited` 已实施 `src/compiler/type_engine.cr:414` ✓）。
- **右路径无控**：C2（`:324`）把属性要求**一律**写到右项 `Shape(φ)`；S-B1 `:100` 规定 `Shape(π)` 由 policy 数据给出（值位 = ⊤；`syntax(D,φ)` = φ；`syntax_raw` = 该策略的 Trusted 形状项）。而 C1 又把「不可信 ↦ ⊤＝不加约束」（S-B1 `:101`）——于是**裸位置判定依据的全部鉴别力都在右项**：`ty_sub(τ, Trusted)`。若 `Shape` 被误声明为 `⊤`、或引擎对未定义的 `Trusted` 原子取宽松解释（把无公理的原子当 ⊤/可满足一切），判定恒真 ⇒ **不报错地通过**（同一类洞，换了路径）。**规范性文本里没有任何一条要求右项非退化**（无 C5）。
- **正例的非退化性同样无控**：C3 + C1 联合要求「可信值」的左项 `Trusted ⊓ string` **非 ⊥**。若 `Trusted` 被声明为与 `string` **互斥的原子类**（R2 P0 已含「原子类互斥公理」，见 `2026-09-10-type-interface-unification-design.md:247`），则正例左项 = ⊥ ⇒ C3 令其落 unknown ⇒ **正控全灭**（S-A §6.4-1「净化路径编译通过」不成立）。这一条正是 S-B3 `:140`（§2.2-义务 2「维度隔离」）已经识别、并要求引擎承担的义务，但 S-A（规范性来源）**没有把它写成约定或正控**，S-B1 也未引用。
- **附带的档位不稳定**：S-B1 `:325` 规定裸位置判定依据失败（unknown）落 ③/④；但若引擎对 `ty_sub(string, Trusted)` 返回**假**而非 unknown（例如把两者声明为互斥原子类），按 S-A `:207-225` 决策树即「**违法**」⇒ 硬编译错。同一份 policy 数据、同一句判定依据，诊断档位在 ③/④ 与「违法（硬错）」之间摆动，取决于一条**未写下的引擎/公理假设**。

**修法建议（加 C5，两小句 + 两负控）**：
> **C5 非退化性**：①`Shape(π)` 在 `syntax`/`syntax_raw` 位置**不得为 ⊤**（policy 装载期校验，违者诊断拒装）；②对每条轴取值 v，`τ ⊓ A_a(v)` 必须存在**非退化正例**（`Trusted ⊓ string ≠ ⊥`）——以正控用例锁死；③`ty_sub(τ, Shape)` 的「假 / unknown」必须**分因**（假 = 违法、unknown = ③/④），并在 S-A §3.3.1 明写「未定义原子的解释规则（必须 unknown，不得真）」。

## Important findings

### I1（Important）S-A §1.9 落档规则与 S-E 的 `race` 证明义务不一致（同一档位两种说法）

- S-A `:182`（接口需求 1）：「S-A 的落档规则（§2.6）**只消费「标记存在性」**，不读其内部语义」；`:177`/`:268` 行 3：显式不确定 ⇒ **① prove + 报告义务**（「程序说的是它想说的 ⇒ 义务已处置」）。
- S-E `:131`（§1.3）：「**prove 的证明内容不是空话**——须证明『该汇合点是此处**唯一**的不确定源』」；`:415`（Q1）该证明的**范围未裁**；`:168`（§1.5 第 5 步）落档前还有一道「**声明与实现一致**」检查。
- 后果：若唯一性证明失败（或 Q1 裁为「传递到观测点」），S-E 侧义务未处置，S-A 侧按标记存在性已经落 ① —— **同一义务两家结论相反**，且「失败落哪档」无人写。S-E 已声明「不新增第五档」，所以失败只能落 ③（登记）或 ④；两种都必须由 S-A 的文本给出，否则实施阶段会各自发明。
- **修法**：S-A `:177`/`:268` 行 3 改为「① prove **当且仅当**该族的『声明-实现一致性』证明成立（S-E §1.3/§1.5-5，范围见 Q1）；否则落 ③ 登记」，或（若意图是「声明即处置」）把 S-E §1.3 的该句改述为**报告面义务（S-D）**，不再是四档上的证明义务。二者择一，两处同步。

### I2（Important）「沿 def 链倒推」的图面分析无唯一 owner（S-B2 ① 与 S-B4 派生链）

- S-B2 `:131`（§2.1 步①）：`Cap(o,r)` 由**图验证 pass**（与 PointerAnalysis/RegionCheck/ProvenanceVerify 同级）导出；`:275`（§6.3）自认「复用既有 provenance/RegionCheck 结果**是否真的零新分析**——实施阶段必须先侦查，否则切片缩到只做 `SrcOK`」。
- S-B4 `:310`（Q4）：「派生链合法性判定的位置：本 spec 建议**图面**（沿 def 链倒推，复用 ProvenanceVerify 形状）……需与 S-B2 capability path 判定**去重**（同一判定不得两处实现）」——**去重只登记在 S-B4，S-B2 未回引**；S-B5 `:143` 也把「κ 可靠性」挂到同一映射层面。
- 后果：同一份 def 链倒推分析可能被 S-B2（SemOK）、S-B4（派生链/根封闭）、S-B5（handle 身份）各实现一次，或三家互相等对方。
- **修法**：指定唯一 owner（建议 = S-B2 §2.1 步①，输入 = provenance/RegionCheck 既有结果，输出 = `Cap` + 派生链见证，接口 `g_*` 只读），并把 S-B4 Q4 的裁决回填到 S-B2 §2.1/§6.3 与 S-B5 §3.2 各一行。

### I3（Important）S-B5 ④ 与 S-E「隐式竞争 reject」声明为同一执法点，但缺可判定的分界规则
