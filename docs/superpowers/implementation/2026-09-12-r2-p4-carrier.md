### Task 5：可选运行期表示

Step 1 至 Step 5 全部实现，三根因逐条实测见报告。实现方式裁定为 (a) 表示位侧表，这是推荐项。实现形态在 IR 层，不使用后端帧旁路字节。每个可选槽（局部变量、形参、调用结果）配一个普通 int IR 变量作为表示位，0 表示裸值，1 表示装箱。写点置位；静态已知时写常量，源已有表示位时拷贝。两个解包点按位分派，分别是 `match` 的 Some/None 臂和 `?`。实现是纯 IR，因此没有新 opcode，没有 ABI 或帧布局改动，ELF 后端与解释器天然同源。对照 `g_x86_mw_tag_off` 先例：后端旁路 tag 区需要两个后端各写一份，本任务不需要。

跨函数面使用隐藏全局信道。这是计划允许的 (a) 扩展面，实现是纯 IR。返回点写、调用点读，使用返回信道单元。调用点写、被调函数序言读，每个形参位一个单元，被调函数序言的读点先于任何可改写信道的调用。读点必须紧跟真实调用，因此可选值的惰性 thunk 关闭。thunk 把调用推迟到 force 点，读点会悬空，实测遇到过。

门控没有影响。AST 没有 `EXPR_OPTIONAL`，也没有 `Some` 或 `None`，因此整个面不启用。不注册隐藏全局，也不发任何表示指令。非可选程序的发射面逐字节不变，`ptr_arith` 与 `generics_test` 的八段以及 ELF canary 都实测 IDENTICAL。

未覆盖面按实测三态登记：结构体字段、数组元素、全局槽、match 结果、可选值的惰性 thunk。这些面不配表示位，解包回落到既有装箱假定。裸值形态明确失败，两条路径的 rc 都是 139，不是不报错的分歧。装箱形态照常正确，`test_optional.py` 的两个用例分别固定了这两种形态。

第三根因由实测挖出，不在计划面内。同族有两处，另有一处后续实测补充。ELF 后端逐 op 的全局行分派缺失。第一处是 `IR_CONST` 没有全局行分支。`g2_slot` 对全局返回帧外伪偏移，因此写栈垃圾，表现为不报错地丢写；解释器对同一 IR 直写 `g_ir_vals`，因此两条路径分歧。本任务首次出现「IR_CONST 落全局行」的发射点，即形参信道单元，按分支修复，修法与 IR_LOAD、IR_STORE 的全局分派相同。第二处是 `IR_LOAD_ENUM_TAG` 的 tag 读取源同样缺失。实测形态为全局可选槽 `g : int? = Some(5)` 加 `Some` 臂，ELF 得到 0，解释器得到 5，是不报错的双路径分歧，基线同样有问题。修复方式相同，读取源走 `e2_load_var`。目的槽的全局行仍然零发射点，已在注释中登记。

第四根因在 Python bootstrap。`gen_let_decl` 只对裸字面量记录 `constant_value`。`-1` 是 UnaryOp，因此丢失初值，生成 `.quad 0`。自举链二进制的负值文件级常量因此不报错地读 0。同类既存面是 `cir_cache.cr` 的 `CIR_CACHE_MAGIC`。本任务改走 `oe_bare()` 与 `oe_boxed()` 函数。

第五个面是表示位侧表。该表是编译期进程内状态，`.cir` 快照不载入。命中恢复路径与冷路径的产物因此分歧。可选面启用时关闭 `.cir` 缓存，以正确性优先。非可选程序照常缓存。
