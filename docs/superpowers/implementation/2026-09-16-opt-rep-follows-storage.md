### Task 2 实现

改动面有四个文件。`src/compiler/ir_gen.cr` 增加 128 行、删除 11 行。`src/compiler/globals.cr` 增加 4 行。`src/arch/x86_64/instr.cr` 增加 19 行。`tests/selfhost/test_optional.py` 增加 122 行，用例从 48 改为 66。

实施中遇到两条自伤型问题，都是「假绿或退化」的成因。

1. `EXPR_UNARY.int_val` 是 `is_mut` 位，不是操作数名索引。`parser.cr:250` 的 `alloc_node(EXPR_UNARY, op, 0, UOP_REF, is_mut, 0, 0, …)` 说明了这一点。首版把它当作 `ni` 查取址表，所以标记面恒查错名。局部形态因为 `irv_rep(op_var) >= 0` 覆盖而假通过。全局形态漏装箱，所以得到 139。修法是取 `ast_int_val(ast_a(node))`。
2. 全局声明面只能「升级」，不能「覆盖」。`global_decl_ti(ni)` 如果当作 pointee 首选项，会把全局 IR var 自带的可选类型降级为非可选。因此 W5 不装箱，由 5/5 退化为 139/139，interp 也红。修法是仅当 `ti_is_optional(gti)` 时才采纳。

第二根因是计划外的新发现。ELF 后端的 `IR_REF` 全局取址有错误。`src/arch/x86_64/instr.cr:1095` 一律使用 `e2_lb(g2_slot(s1))`，也就是 `lea r10,[rbp+off]`。全局行的 `g2_slot` 是帧外伪偏移，与已经修复的 `IR_LOAD_FIELD` 同型。因此 `&g` 取到栈上垃圾：写读经指针自洽，所以被掩盖，但与全局槽脱钩。

固定基线实证使用 `/tmp/capt6/base/corec`：`g_mut` 的 ELF 为 1、interp 为 5；`g_refread` 的 ELF 为 36、interp 为 1。因此这是预存缺陷。修法是全局源使用 `lea r10,[rip+rel32]` 加 RIP 补丁，照 `IR_STORE` 的全局分支。形态③的 ELF 侧检查在这个修复之前不可能正确。T1 的 `ELF 0` 和 `interp 139` 分歧就是这个原因。语料面方面，canary 使用的 `ptr_arith` 不含 `&全局`，所以发射面零变化。

pointee 声见面是 W5 的前提件。`UOP_REF` 的 ident 分支按 `slot_decl_ti` 改为 `irv_type`，再按全局的 `global_decl_ti` 升级序解析 pointee。取址标记使具可选能力者的 pointee 记为 `TYP_OPTIONAL`，由 `alloc_type` 完成。非可选槽的 rep 小于 0，且声明非可选，所以双形态都不触发，零影响。

突变有三条，全部失败并精确回滚。M1 去掉预扫，得到 63/66，param、c1、c3 重新失败，暴露预扫关键面是初值裸槽的表示位固定为 1。M2 去掉 `IR_STORE_PTR` 装箱，得到 57/66，9 例返回 -11。M3a 门控恒开，所以 canary 变为 `47ed24a9…`，32918B，不等于 28822B，`.ccr` 四条全变，零影响证据重新失败。回滚自身验证：三源 sha 逐条等于备份，canary IDENTICAL，66/66。
