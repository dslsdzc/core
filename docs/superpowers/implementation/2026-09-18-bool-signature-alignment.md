# bool 类 171 处签名统一（批 8）实施记录

> 对应计划：[plans/2026-09-18-bool-signature-alignment.md](../plans/2026-09-18-bool-signature-alignment.md)

裁定依据来自 team-lead：`bool` 类的 171 处先做。这批改动只改 helper 签名，不引入新语法，与 2(a) 新内置批相互独立。S2 的 `string` 与 `int` 桶等 2(a) 处理。检查要求是逐处记录、零行为变化、清单中 bool 桶归零、突变自证。

## 概述

本记录覆盖批 8 的 bool 类 171 处签名统一工作。目标是消除 `ts_check` 第二实参从 bool 到 int 的隐式转换接缝，避免 bool 不再当作 int 之后自测计数失准。结论是 171 处调用点改为 `ts_check_b` 或 `ps_check_b`，bool 桶归零，清单从 239 点降到 68 点，`selftest-types` 和 `selftest-purity` 的输出与改前逐字节相同，`tests/selfhost/test_s1p_liveness.py` 已经接入 `selfhost-tests`。残桶 68 点仍然属于 `string` 与 `int`，留给 S2。

## 改动

### 问题形态

自测和 bridge 通道的计数惯用式是 `fails = fails + ts_check(name, <谓词>, 1|0)`。`ts_check` 的第二和第三形参声明为 `int`，而第二实参本来就是 bool 表达式，也就是谓词。旧写法依靠 bool 隐式当作 int 的 0 或 1 参与 `!=` 比较，因此恰好得到正确结果。

这正是 S1P 插模拟报告里的 `形参 int ← 实参 bool`，读数为 `p_ti=0 / a_ti=2`。它不是错误值，而是依靠隐式转换维持的接缝。一旦完成结束，bool 不再当作 int，见 S2 和 S3，这批调用点会大面积变成错误。失败信号是「自测数不准」，不是编译错误，因此属于第 1 类不报错问题。

### 方法

改写规则收紧过一次，见下一节。规则是把 `ts_check("名", <bool 表达式>, 1|0)` 改为 `ts_check_b("名", <bool 表达式>, true|false)`。新增两个签名 helper：

```core
fn ts_check_b(name: string, got: bool, want: bool) -> int   // type_selftest.cr
fn ps_check_b(name: string, got: bool, want: bool) -> int   // purity_selftest.cr
```

二者返回 int 的 1 或 0，`fails = fails + …` 惯用式保持不变，因此累加值不变。零行为变化的验证见验收结果。

枚举的 oracle 是被修对象自己的输出，也就是 S1P 清单，不是文本扫描。命令是：

```sh
CORE_S1P=1 ./build/corec check src/compiler/main.cr | grep -E '^991[78] '
```

收敛检查是逐桶清点，不采用「grep 到几处」这类弱结论。

#### 两次过匹配事故

| # | 规则 | 后果 | 处置 |
|---|---|---|---|
| 1 | 文本规则为「凡 `ts_check(` 第二实参为 bool 形态」 | 179 处被改，清单出现 163 加 16 个新 `bool←int` 点，把 int 实参改成了 bool | 全量回退，重新定规则 |
| 2 | 规则同上，未排除 `ts_isat_b2i(...)`，这是 int 返回型转换器 | 62 点 | 回退后增加条件：第二实参须以 `(` 开头且含 bool 运算符，或者为 `true` 或 `false` |
| 3 | 收紧后仍漏 1 处 | — | 该处第二实参另起一行，属于多行调用，行内文本不以 `(` 开头。最终检查改为看实参首字符，不再以行首为准 |

结论是规则要以实参为单位表述，使用 AST 或括号配平。以行内文本为单位，会在多行调用上漏判或错判。

### 检查接入

`tests/selfhost/test_s1p_liveness.py` 新增以下检查，并接入 `selfhost-tests`。

- ⓪ 正则自检：5 条合成行固定 `HIT` 形状，包括可选 ` @@ ` 后缀、行首绑定、缺字段负例。目的是防止「格式变化导致 0 命中，探针没有输出」。本档在 CI 上正是这样失败过一次。
- ⑦ 自源清单：先断言清单非空，否则 `bool 桶=0` 与「插模拟没有安装」无法区分。再断言 bool 桶为 0。

### 多态槽事实

清单覆盖面是非字面量实参面。S1P 插模拟对字面量多态实参主动跳过，护栏③要求 `f(3)` 必须零插模拟，见套件内 `LITERAL` 检查。因此「bool 桶归零」的效力边界是非字面量面。字面量面不在本检查内，也不受本轮改写影响，171 处第二实参全是非字面量谓词表达式。

方法调用面不在本点。套件内 `METHOD_GAP` 检查固定 `s.m(b)` 异型 0 插模拟。171 处均经直调到达检测点。方法面待 S2 和 S3 扩大覆盖后再判。该不可达分支不得当作不可达代码删除。

清单归零不等于语义正确。残桶 68 点仍然是 `string` 与 `int`，其中 46 个 `0←0`、22 个 `2←3`，未修。S2 路线 1 的验收须逐点给出语义依据，并证明零行为变化，不得只看数字。

### 版本位与缓存面

本改动不改变任何已接受程序的 IR、`.ccr` 或 ELF 语义，只改编译器自身的两个自测文件的调用形态。唯一在产物面变化的是 `build/corec` 二进制本身，它多一个 helper 和若干调用点。

因此不存在「已接受程序 IR 变化」，版本位不动。提升版本号的正当理由只有一条：缓存会让坏产物重新生效。相关检查是身份检查不覆盖的面，见 `cir_cache.cr` 的身份检查和 TODO #2026-09-18-16「指纹不含函数体」。

缓存面：`type_selftest.cr` 和 `purity_selftest.cr` 两个文件的 AST 变化，因此它们自身的条目 miss 并重建。其余文件条目语义等价，命中无害。身份检查仍然是后备。

## 验收结果

### 零行为变化

`selftest-types` 421 行，结果为 `415/415`，rc=0。`selftest-purity` 28 行，结果为 `26/26`，rc=0。两者都与改前基线逐字节相同，`cmp` 无差异。基线取自改前二进制。

记录一个取数陷阱。首轮比较因为 fish noclobber 没有真正执行，重定向失败，`cmp` 比较的是旧文件，因此得到假的 IDENTICAL。改用 `>|` 并核对 rc 和行数后重新运行，结果才有效。

### 清单 bool 桶归零

清单从 239 点降到 68 点，bool 桶为 0。分解是 `0←0` 46 点、`2←3` 22 点，后者属于 `string` 与 `int`。

### 突变自证

突变有两条，均断言命中了目标。

1. 清单读数：回退 1 处改写，目标是 `t1.var_seq_elem_invariant`，已经断言改到的正是该行。清单变为 69，bool 1，含源行片段 `@@ tt_atom(AK_SEQUENCE, -1, tt_cons(`，说明读数有效。
2. 检查 ⑦：在同一突变态运行 `tests/selfhost/test_s1p_liveness.py`，恰好 1 项失败，失败项是 `selfsource_bool_bucket_zero`，其余全部通过。说明检测具有特异性，不是整档一起失败。

### CI 接入

`tests/selfhost/test_s1p_liveness.py` 已经接入 `selfhost-tests`，新增 ⓪ 和 ⑦ 两项检查。实测 PASS 16 秒，使用 nice。突变态 rc=1。
