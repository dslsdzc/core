## 二、Findings

### Critical

C1｜S-C 成本模型契约与 第 1.4 节 / S-D 断裂（三处）
`performance-without-commitment-design.md:64-75`（第 0.5 节 合规表缺 第 1.4 节行）、`:126-140`（第 2.3 节 接口：输出 = 相对成本估计 + 约束满足判定）、`:135-140`（契约四条，无 band/版本/假设）、`:16`+`:205`（"S-D 未落盘"）、`:244-259`（第 7 节 不承诺，无"模型非证明"）。
对照 `explain-predict-incremental-design.md:62`（D13 硬性）、`:64`（D15）、`:228`（MODELED 行"必须明标模型估计，非证明"）、`:236-247`（`cost_model_query(kind,subject,mapping_desc) -> {cost, band 必填, model_id, model_ver, assumptions[]}` + 禁令"模型不可用 因此 UNKNOWN，不得用经验常数后备"）、`:290`（第 2.2 节 MODELED 渲染约束）、`:382`（`phase_ver` 含 `model_ver`）。
后果：S-D 宣称「`MODELED` 数字的唯一来源 = S-C 成本模型」（第 1.7.2 节/第 2.6 节），而 S-C 的接口不产出 `band`/`model_id`/`model_ver`/`assumptions`，也没有"模型不可用"的定义 因此 S-D 的 `MODELED` 档与两条禁令在供应链上无法实施；`phase_ver` 的模型版本分量同样无来源。
修法（S-C 单侧即可，4 行）：① 第 2.3 节 输出行补 `+ band（必填）/model_id/model_ver/assumptions[]`；② 第 2.3 节 契约四条补第 5 条「模型非证明：估计值不得呈现为 WCET 证明/时间上界（承契约 第 1.4 节）」；③ 第 0.5 节表补 第 1.4 节行；④ `:16`/`:205` 改为「S-D 已落盘，接口以 S-D 第 1.7.3 节/第 2.6 节 为准」并交叉引用。

C2｜效应事实的现状前提不成立（S-C 首切片合法性门失守；S-E 保守面措辞不足）
实证（本次读码，强于三份 spec 的现有描述）：
- `src/compiler/dataflow.cr:160-177` 分类表 = STORE×4 + `IR_CALL`（"函数名解析不出或非纯则计副作用"），引文正确；
- 但 `fi_ispure` 的唯一写入点是 `src/compiler/checker.cr:1107`（普通函数）与 `:1142`（extern），值恒 1（`dyn_arr.cr:369` 是 setter，全仓无第二处写入）因此 `dataflow.cr:171` 的 `fi_ispure(cfi)==0` 在名字可解析时恒假 因此 除 store 家族与不可解析调用（builtin，如 `syscall3`）外，没有任何调用进入 state 链（`print`/`read_file`/`chan_send`/`sched_go`…均为 `IR_CALL` + 可解析 + "纯"）；链还是每函数重置的（`dataflow.cr:395-402`）；
- `IR_CALL_EXTERN`（`ast.cr:572` = 45）同样不入链（`dataflow.cr:217` 只建数据边）；
- 同一乐观旗标还被 `ir_gen.cr:1590`（THUNK 判定）消费。
后果：① S-C 第 6 节 切片的前提「纯度（效应集），已有显式边（state edges + effect 轴）」（`:222-225`）与 第 2.2 节 合法性门「无效应（memo）」（`:120`）、第 1 节 纯度行（`:88`）、第 4 节 row 1 自动并发（`:186`）建立在一个今天不成立的事实上 因此 memo 可能删掉可观测效应（判据 2「效应次数不增」是事后网，不是前提）；② S-E 第 1.1 节（`:91-92`）只点名 `IR_CALL_EXTERN`，其保守要求的措辞「与一切『纯度不可判』的调用」不足以覆盖"被乐观标记为纯的可解析调用"，照字面读，`print` 不属于"纯度不可判"（checker 说它纯）；③ S-A 第 1.7 节 `effect` 轴来源、S-D 第 1.6 节 缺口清单同源缺席。
修法：S-C 第 1 节/第 2.2 节/第 6 节 加保守规则「效应 = 除引擎判定纯者外的一切 `IR_CALL`/`IR_CALL_EXTERN`；今日等价于"所有调用"」；S-E 第 1.1 节/第 4.1 节 把保守面从"extern + 纯度不可判"扩到"任何调用（今日无函数被标记为不纯：写入点仅 checker.cr:1107/:1142，值恒 1）"，N6 同理扩面；S-D 第 1.6 节 登记该缺口；S-A 第 1.7 节 加同款注记（跨族，交 safety-review-a）。

C3｜S-E 汇合点定义过捕获 因此 第 1.5 节 决策序会误拒普通非交换运算
`merge-semantics-design.md:38`（D-1「汇合点 M = 入数据边 ≥ 2 的 DFNode」）、`:55`、`:62`（判定问题）、`:66-73`（四形态承诺）、`:75-94`（第 1.1 节 (a)(b)(c)）、`:161-170`（第 1.5 节 决策序）、`:172`（证明优先）。
按字面：普通二元节点（`a - b`、`s1 + s2 + s3` 的中间节点）入度即 ≥ 2 因此 进 第 1.5 节；step 2（交换 ∧ 结合）对减法失败；step 3 的顺序源允许清单 `src ∈ {state-chain, region-order}`（`:42` D-5）不含数据依赖定序；step 4/5 不适用 因此 step 6 reject。即：一个不含并发、不含循环的直线程序会被拒绝编译。spec 的意图（`:280` 第 4.2 节「跨 region 汇合…是典型候选」）与形式定义不一致，而 D-1/第 1.0 节 是实施依据。
修法（择一，建议 ①）：① 把 M 收窄为"跨执行流/region 的汇合"（判据可用 region 归属 + 存在 `IR_PHI`（`ast.cr:22`=22）/`SG_FLOW`/父 region 汇合）；② 允许清单加"同一值位的确定生产者（数据依赖序）"；③ 明确 position 绑定不算 π（`F_M(c,π)` 对多操作数节点本就不是多重集上的函数，`c = 输入值多重集` 的记号对非交换节点无定义，须先修 第 1.0 节 记号）。并补负控：`a - b` 不得 reject。

C4｜S-D3 判据②（差距 B 收敛）超出其声明范围；且判据②/依赖的 D8 无机制承接
`explain-predict-incremental-design.md:365`（差距 B 冷/热 `.ccr` sha256 不同）、`:367`（"核心证据…历史路径的函数"）、`:452-459`（S-D3 范围 = 键多分量；不做 = 不实现增量后端、不改 `.ccr` 格式）、`:459`（判据②「同二进制冷/热两态 `corec ccr` 输出逐字节同」）、`:400`（"验收升级：`clean-cache` 不再必要 = 本切片最硬的验收线"）。
键的覆盖面只决定"是否复用"，不决定"复用路径的产物与未复用路径逐字节同"，后者是命中路径的产物保真问题（字符串驻留序／全局初始化注入不重放，S-D 自己在 第 3.2 节 差距 A/C 描述过），落在"条目内容"面，而 S-D3 明确排除了该面。因此 判据② 按其声明的范围不可达。
修法：或把"命中路径产物保真"的最小机制写进 S-D3 范围（如条目内携带字符串/初始化的等价重放信息，或命中路径强制重放该最小面），或把②降级为登记（判据改为"差距 A 转为通过 + 差距 B 仍失败并附根因清单 + D7 保留为整体目标"），二者必须择一，不能维持现状。
