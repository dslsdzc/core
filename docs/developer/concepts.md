# 核心概念导览

> 定位:受众 = 开发者(理解 Core 的设计思维);状态 = active。
> 本文用开发者语言讲四个核心概念——每节末尾给"深入阅读"链接(维护者细节不在这里展开)。

## 一、程序 = 一张图

Core 里所有代码编译后构成一张**数据流图**:节点是操作,边是值流动的方向。变量、函数调用、分支、循环在图上都是结构,不是"语句序列":

- 简单函数 = 无环图:值从输入流向输出,依赖顺序即执行顺序
- 循环 = 图中的环:每轮迭代值沿环流动一周
- `go` = 图运行时生长出新的子图,与主图并行流动

**对开发者的含义**:不需要声明"模式"(顺序/并发/实时);代码写了什么,图就反映什么。调试 = 沿图走值。心智模型从头到尾一致——这也是学习路径(tutorial)概念只增不减的原因。

深入:执行模型与图实现见 `../maintainer/design/execution-model.md`(维护者视角,可不读)。

## 二、内存:自动、无 GC、无标注

Core 没有 borrow checker,也不用手动 free——内存按**子图区域**自动管理:

- 函数/循环等子图有独立内存区域;子图结束,区域整块回收
- 分配 = 指针碰撞(O(1));回收 = 游标重置(无 GC 停顿)
- 指针安全(来源追踪 + 边界核对)由编译器在图上自动完成——不用写生命周期标注

对开发者可见的只有:指针和 C 一样自由,越界与悬垂由编译器拦截或运行时陷阱。

深入:内存模型(经典映射)见 `../maintainer/design/region-model.md`。

## 三、部署配置与代码分离

代码只描述计算;**物理世界(内存策略/多核/OS)在部署配置里声明**:

```toml
[deploy.mcu]
allocation = "static"        # 禁止动态分配

[deploy.server]
allocation = "dynamic"
```

同一份代码配不同部署配置 = 不同目标(裸机零运行时 / 桌面原生 / 教学解释执行)。代码不改,语义不变。

> 现状注:部署配置的完整落地(平台桥:IO 流/时钟等语义接口)为设计态——当前 `deploy.toml` 是声明文件,消费范围见 TODO。

## 四、规约:验证不用学第二门语言

Core 的"验证"入口是 **#check/#ensure 标注**——直接写在函数上,用 Core 表达式表达性质:

```core
fn divide(a: int, b: int) -> int?
    #check(b != 0)
    #ensure(result.is_some() implies (a / b) == result.unwrap())
```

- 编译器自动推导能推导的一切(#pure/#terminating 等标签)
- 表达不出的性质用 `spec fn`(纯 Core 检查函数)写
- 验证管线(证明/证书)为设计态——当前标注不改变运行行为

**为什么":语义保鲜**——编译中间表示保留全部类型与语义,验证器消费 IR 即获得完整语义模型,不需要你为验证重写一遍程序。

深入:规约系统设计见 `../maintainer/design/spec-design.md`;存储语义理论见 `../academic/cache-semantics.md`(学术读者向)。
