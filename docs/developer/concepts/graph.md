# 概念：程序 = 一张图

> 定位：受众 = 开发者；状态 = active。

## 图的结构

Core 编译后的程序是数据流图，不是指令序列。节点是操作（取址、解引用、算术、调用），边表示值的流动。控制流不是另外加入的机制，它就是图的结构：

| 代码 | 图上 |
|---|---|
| 顺序语句 | 值沿依赖关系流动（互不依赖的部分不会互相阻塞） |
| if/else | 两条候选路径，由条件选择一条 |
| loop/for | 一个环，值沿环流动，每圈对应一次迭代 |
| go | 运行时从当前节点生成并行的子图 |

## 对编码的影响

不需要“模式”概念。没有 debug、release 或并发模式之间的切换，代码写了什么，图就反映什么。学习、单步调试和并发是同一张图的不同观察方式：

- 单步调试：沿图传递值
- 并发：图上有并行的子图
- 惰性：没有被需要的路径不求值

## 表达力上限

图能表达的范围不限于经典机器可以执行的顺序。非因果、概率和模糊语义在图上都有标注位置（设计态，超出本文范围；术语见 `../../glossary.md`）。
