# 文档写作规范

> 定位：受众 = 文档作者；状态 = active。

这份规范说明 Core 文档的正文怎么写。它管表达方式，不管技术内容。

## 基本写法

用陈述句说明事实和规则。先写做什么，需要时再写原因。

不要用命令口吻，也不要写违反规则的后果。写“提交前运行测试”，不写“必须运行测试，否则后果自负”。

句子的长短按内容决定。一个意思用一句写完；包含多个条件时，可以拆成几句。不要为了简短省略必要的主语和条件，也不要把一个简单的意思拉成长段。

## 不用比喻和拟人

描述程序行为时使用常用名称。检查结果写“通过”或“失败”，问题状态写“已修复”或“未修复”，自动检查写“自动检查”。不要借用身体部位、生死状态、战争、建筑等领域的词来描述程序，也不要把程序说成会思考、会长期等待、会睡觉的对象。

一个概念需要反复使用时，第一次出现给出定义，之后一直使用这个名称。

技术术语按 `docs/glossary.md` 的写法。英文术语保留原文；没有通用中文译名时，不要生造直译。中文句子按中文语序组织，不要把英文句子逐词翻译过来。

常见的逐词直译写法：

- “基于 X”改成“使用 X”或“根据 X”。
- “进行 + 动词”改成直接动词，例如“进行分析”改成“分析”。
- “被……所……”改成主动句。
- 过长的定语拆成短句，不要写“这是一个用于……的……的……”这种句子。
- “当……时”改成“……时”。

## 工程文档的结构

工程文档按下面的顺序组织。没有内容的节可以省略。

1. 标题。
2. 概述：这份文档解决什么问题，结论是什么。一段写完。
3. 核心原则或设计决定：每条一句话，说明做什么和为什么。
4. 接口、数据结构、流程：用表格或代码块给出具体形式。
5. 实施清单：文件、改动、验收方式。
6. 不包含的功能：明确写出这次不做什么。
7. 未决问题：只写还没有定论的事项，并注明需要谁决定。

不要写“本文说明”“以下为”“原文移动”“本章介绍”这类元叙述，直接写内容。不要写改写过程、迁移说明或自检仪式；这些放在提交信息里。

## 记录，不写个人意见

工程文档记录事实、动作、证据、决定和结果。不要写个人意见，也不要用第一人称。需要指代文档本身时写“本文”或“本报告”。

- 实测结果写成“实测结果：……”，并给出命令或证据位置。
- 未验证的内容写成“未验证：……”，不要写成结论。
- 决定写成“决定：……”，并给出依据。
- 不确定的地方写明不确定的范围，不要用“大概”“应该”代替证据。

## 不要压缩词语

一句话只讲一个事实。不要把多个条件、结果和限定塞进一句，也不要用“/”“·”“⇒”把几层意思连在一起。

不要用行话代替说明。常见行话包括“判据、落点、口径、定位点、实现方式、检查、收口、对齐、完整流程、收编、归口”。第一次出现某个缩写时写出全称，例如“CIR（增量缓存快照格式）”。

能用“因为……所以……”写清楚的地方，不要用箭头。表格用于数据，不用表格代替解释。

例如，不要写“三 sha = 允许清单 + `cmp` ×3 + 验证 42”；写成“三个 sha 与允许清单相同；与基线做了三次 `cmp`，结果都是 IDENTICAL；快速验证返回 42”。

## 编号用阿拉伯数字

列表和选项一律用 1、2、3、4。不要用天干编号，也不要用圈号。章节编号可以用 1.、2.、3.，也可以沿用已有文档的编号。

## 标点与排版

中文正文使用全角标点：，。：；？！（）。代码、标识符、命令、路径和英文句子内部使用半角标点。

不用箭头（`→`、`⇒`）表示推理或步骤。写成“因此”“然后”，或者拆成两句。代码、命令、流程图和任务记录中的箭头属于记号，可以保留。

不使用 emoji、警告符号、对勾符号和【】标签。需要提醒读者时，写“注：”“重要：”或“警告：”。

粗体只用于读者快速浏览时需要找到的内容。不要每个段落都加粗。

标题直接说明这一节的内容，不加编号。已有文档的编号如果被其他位置引用，保留编号。

## 图表

流程图、架构图、时序图和状态机使用 Mermaid fenced block（````mermaid`）。不要用 ASCII 箭头拼流程图。节点和边写成 Mermaid 语句，节点标签用引号包住中文和标点。

数据表继续使用 Markdown 表格。代码、伪代码和命令继续使用普通代码块，不要放进 Mermaid。

## 修改已有文档

旧结论用带日期的说明保留，例如“2026-09-14 起改用 v9 格式，旧值为……”。不要使用删除线，也不要在正文里记录修改过程。

修改文字时，事实、数字、链接目标、`file:line` 和提交 sha 保持不变。文字修改和内容修改分开提交。

保留文档原有的定位声明、真源规则和分类结构。

## 计划和实施记录

计划文档写要做什么、怎么做、验收条件。实施记录写实际做了什么、结果、偏差和完成状态。两者分开存放，开头互相链接。

## 检查

文档是否易读由人判断，不设自动检查。修改完成后确认链接目标仍然存在。
