# Core 标识符对照表（伪代码术语表）

> 本表是全部伪代码文档的跨文件一致性锚点。共享标识符（出现于多个文件、或以 g_ 开头、
> 或为 struct/enum 类型名、或为 stdlib 公开函数）必须使用本表名字，禁止自造。
> 生成方式：`python3 tools/pseudocode_extract.py`

## 命名规则

| 规则 | 说明 | 示例 |
|------|------|------|
| 动词函数直译动作 | 如 tokenize、parse、check、emit 等 | tokenize -> 分词、res_imports -> 解析引入 |
| 名词结构意译含义 | 如 DFNode、Token、SGNode 等 | DFNode -> 数据流节点、Token -> 词法单元 |
| 缩写展开 | 常见缩写的全称映射 | calc -> 计算、res -> 解析、tbl -> 表、instr -> 指令 |
| g_ 前缀省略 | 全局性由文档「全局状态」节体现 | g_tok_cap -> Token 数组容量 |
| 相似名必须可区分 | 容量/计数/长度 不可混用 | g_tok_cap（容量）vs g_token_count（计数） |
| 每条中文名可无歧义回源 | 任何人看到中文名能推出对应原名 | 出现文件数 列可用于交叉验证 |
| e2_ 前缀 | 后端指令发射（emit）系，如 e2_mov → 发射 MOV | e2_mov → 发射 MOV |
| g2_ 前缀 | 后端全局变量寻址系，如 g2_slot → 全局变量槽位 | g2_slot → 全局变量槽位 |
| region 保留英文 | HDFG 专名保留英文；函数名中的 region 若指「区域检查」动作则译为「区域」，指 HDFG 领域概念时保留英文 | g_df_node_region → 数据流节点所属 region |
