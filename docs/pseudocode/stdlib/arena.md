# arena.cr 伪代码

> 源文件：src/stdlib/arena.cr（99 行）
> 功能概要：竞技场（Arena）内存模型——基于子图（subgraph）的 bump 分配器。每个子图（函数/循环/遍历（for）/非安全（unsafe） 块）获得自己的竞技场。分配（alloc）操作检查当前竞技场（g_current_arena），若已设置则使用竞技场分块。

## 函数 内部：扩展竞技场元数据（_grow_arena_meta）

### 作用

按需扩展竞技场元数据数组（游标、大小、父项）。当需要更多槽位时，分配更大的缓冲区、清零、拷贝旧数据。

### 逻辑

如果 所需槽位数（needed）小于 竞技场容量，那么：返回  // 容量已足够
令 新容量（nc）= 竞技场容量 乘以 2
如果 新容量 小于 64，那么：新容量 = 64
如果 新容量 小于 所需槽位数，那么：新容量 = 所需槽位数 加 64
// 扩展游标数组
令 新缓冲区（nb）= 分配（新容量 乘以 8）  // 每个槽位 8 字节
令 零初始化索引（zi）= 0
循环（当 零初始化索引 小于 新容量 乘以 8 时）：
    写单字节（新缓冲区, 零初始化索引, 0）
    零初始化索引 = 零初始化索引 加 1
如果 竞技场容量 大于 0，那么：内部：动态拷贝（竞技场游标数组, 竞技场容量 乘以 8, 新缓冲区）
令 竞技场游标数组 = 新缓冲区
// 扩展大小数组
令 新缓冲区2（nb2）= 分配（新容量 乘以 8）
令 零初始化索引 = 0
循环（当 零初始化索引 小于 新容量 乘以 8 时）：
    写单字节（新缓冲区2, 零初始化索引, 0）
    零初始化索引 = 零初始化索引 加 1
如果 竞技场容量 大于 0，那么：内部：动态拷贝（竞技场大小数组, 竞技场容量 乘以 8, 新缓冲区2）
令 竞技场大小数组 = 新缓冲区2
// 扩展父项数组
令 新缓冲区3（nb3）= 分配（新容量 乘以 8）
令 零初始化索引 = 0
循环（当 零初始化索引 小于 新容量 乘以 8 时）：
    写单字节（新缓冲区3, 零初始化索引, 0）
    零初始化索引 = 零初始化索引 加 1
如果 竞技场容量 大于 0，那么：内部：动态拷贝（竞技场父项数组, 竞技场容量 乘以 8, 新缓冲区3）
令 竞技场父项数组 = 新缓冲区3
令 竞技场容量 = 新容量

### 测试要点

1. 初始状态（竞技场容量 = 0，所需槽位数 = 1）：分配 64 槽位
2. 所需槽位数 = 10，竞技场容量 = 8：扩容到 64（新容量 = 8 乘以 2 = 16，小于 64 设 64）
3. 所需槽位数 = 200，竞技场容量 = 64：扩容到 264（新容量 = 64 乘以 2 = 128，小于 200 设 200 加 64）
4. 所需槽位数 小于 竞技场容量 时直接返回，不分配
5. 旧数据被拷贝到新缓冲区

## 函数 初始化竞技场（arena_init）

### 作用

初始化全局竞技场系统：分配内存池，设置默认分块大小，初始化空闲链表和计数器。

### 逻辑

令 竞技场内存池数据 = 分配（pool_size）
令 竞技场最大大小 = 默认分块大小（arena_size）
令 竞技场空闲列表 = -1
令 竞技场计数 = 0
令 竞技场容量 = 0
令 当前竞技场索引 = -1

### 测试要点

1. 内存池大小 = 1048576，默认分块大小 = 65536：设置 1 兆字节（MB）内存池和 64 千字节（KB）默认分块
2. 空闲链表初始为 -1（空）
3. 当前竞技场初始为 -1（无活动竞技场）

## 函数 新建竞技场（arena_new）

### 作用

创建新的竞技场并激活为当前竞技场。优先从空闲列表中复用已释放的槽位；无空闲时扩展元数据数组并分配新槽位。设置父竞技场为之前的当前竞技场。

### 逻辑

令 竞技场 ID（ai）= -1
// 先尝试空闲列表
如果 竞技场空闲列表 大于等于 0，那么：
    令 竞技场 ID = 竞技场空闲列表
    令 竞技场空闲列表 = 读 64 位（竞技场父项数组, 竞技场 ID 乘以 8）  // 弹出链表头：空闲列表通过父项数组的偏移 0 处存放下一个空闲槽位索引
// 若无空闲槽位则分配新槽位
如果 竞技场 ID 小于 0，那么：
    令 所需槽位数（need）= 竞技场计数 加 1
    内部：扩展竞技场元数据（所需槽位数）
    令 竞技场 ID = 竞技场计数
    令 竞技场计数 = 所需槽位数
// 初始化新槽位
写 64 位（竞技场游标数组, 竞技场 ID 乘以 8, 0）   // 游标从 0 开始
写 64 位（竞技场大小数组, 竞技场 ID 乘以 8, 竞技场最大大小）  // 分块大小
写 64 位（竞技场父项数组, 竞技场 ID 乘以 8, -1）  // 父项暂设为 -1
// 设置父竞技场为之前的当前竞技场
如果 当前竞技场索引 大于等于 0，那么：
    写 64 位（竞技场父项数组, 竞技场 ID 乘以 8, 当前竞技场索引）
// 激活该竞技场
令 当前竞技场索引 = 竞技场 ID
返回 竞技场 ID

### 测试要点

1. 首次调用时从空闲列表取不到（-1），分配新槽位
2. 空闲列表非空时复用旧槽位，调整空闲列表头
3. 父竞技场正确设置为之前活跃的竞技场
4. 游标和大小初始化为 0 和默认分块大小
5. 返回的竞技场 ID 与当前竞技场索引一致

## 函数 重置竞技场（arena_reset）

### 作用

释放竞技场（将其放回空闲列表），恢复当前竞技场为其父竞技场。在空闲列表覆写父项数组之前保存父项值。

### 逻辑

如果 竞技场 ID（ai）小于 0 或 竞技场 ID 大于等于 竞技场计数，那么：返回  // 越界检查
// 在空闲列表覆写之前保存父项值
令 父竞技场（parent）= 读 64 位（竞技场父项数组, 竞技场 ID 乘以 8）
// 推入空闲列表：将当前空闲列表头写入父项数组，然后更新空闲列表头
写 64 位（竞技场父项数组, 竞技场 ID 乘以 8, 竞技场空闲列表）
令 竞技场空闲列表 = 竞技场 ID
// 恢复当前竞技场为父竞技场
如果 父竞技场 大于等于 0，那么：
    令 当前竞技场索引 = 父竞技场
否则：
    令 当前竞技场索引 = -1

### 测试要点

1. 有父竞技场时，重置后当前竞技场指向父竞技场
2. 无父竞技场时，重置后当前竞技场为 -1
3. 竞技场 ID 超出范围时函数直接返回
4. 被释放的竞技场进入空闲列表，可被新建竞技场复用
5. 空闲列表正确维护（链表通过 g_arena_parents 实现）

## 函数 竞技场可用大小（arena_avail）

### 作用

查询指定竞技场的剩余可用空间（分块大小 - 当前游标）。

### 逻辑

如果 竞技场 ID（ai）小于 0 或 竞技场 ID 大于等于 竞技场计数，那么：返回 0
令 游标（cursor）= 读 64 位（竞技场游标数组, 竞技场 ID 乘以 8）
令 上限（limit）= 读 64 位（竞技场大小数组, 竞技场 ID 乘以 8）
返回 上限 减 游标

### 测试要点

1. 新创建的竞技场返回完整的分块大小（g_arena_max_size）
2. 已部分使用的竞技场返回剩余空间
3. 竞技场 ID 超出范围时返回 0
4. 竞技场用尽（cursor >= limit）时返回 0 或负数
