## 零、为什么是缓存——以及它是哪一类

Core 的存储语义本体是**存在格(Materialization / Existence Space)**——范式无关的存储抽象,不是字节内存,也不是寄存器。它回答:一个语义对象如何"存在"、在哪里存在、哪些存在形式可以同时成立、哪些可以被替换或重新构造(四问详见 materialization-space.md §2.1)。

**缓存是这个层里最直接的一类映射实例,不是这个层的名字:**

- 传统编译器的内存模型从机器出发(字节寻址 + 权限),范式绑死
- 缓存映射从"值如何产生与保留"出发:值 = 配方(可重算),存储 = 配方结果的保留(可驱逐)
- 机器内存、寄存器、VRAM 都是缓存映射的实例;量子存储、持久映射是其他实例——范式映射表由此成立

**边界(2026-09-20 修订补)**:缓存一词偷带的假设——有一个权威值、可以复制、可以驱逐、可以重新物化、存在 backing store、不同副本表示同一值——**只对 可再生且可复制 的那一类成立**。MMIO 读、随机数、一次性 token、线性资源、事务临时状态、分布式唯一 authority 落在同一层内但**不满足这些假设**(逐条卡点见 materialization-space.md §三),因此不能用「缓存」给整个层命名。

实现从来就是这张存在格(HDFG):节点 = 配方(值的产生方式),边 = 值流,state edges = 顺序约束,驱逐/再生 = 丢令牌/重跑节点。此前的文档层错误是把 CompCert v2 字节模型当语义本体——已纠偏(2026-08-15,零代码改动)。

## 一、七条条款(权威)

> 这七条是**存在格这一层**的规则,不是「缓存这一类」的私产——缓存映射是最直接实现它们的一类实例
> (见 §零)。条款 1–7 的**层定义上下文**(四问/七字段/归类表/划界)见 docs/maintainer/design/materialization-space.md。

1. **值 = 配方**。条目的语义 = (产生它的图节点, 输入边)。不存在独立于配方的"存储事实"。
2. **驱逐不变量**。**对可再生条目**(recipe = recomputable)驱逐图内任意条目(丢弃存储物、保留配方)不改变可观测语义——只影响性能,不影响正确性。形式化目标:⟦G ∖ storage(e)⟧ = ⟦G⟧。这是**缓存映射这一类**的定义性质;层的一般判据见 2′。
3. **再生等价**。重跑配方节点产生的值与原条目可观测等价。这是条款 2 的机制保证,也是"任何范式都能换映射"的语义依据。
4. **边界公理**。图边界输入(MMIO/FFI/输入/测量)是无配方条目(边界类),语义上是符号常量。语法层叫 `unsafe`(边界标注),语义层只叫"边界"。边界之外才需要 state,边界之内全是可重算的。
4b. **图内不可重算(v4 并入,M4 输入)**。执行标注空间(神谕 / BSS 实数 / FIXPT 声明 / 模糊融合,见 docs/maintainer/design/dataflow-design.md §8)存在**图内**无配方条目——非边界、不可重算。驱逐不变量/再生等价对其不成立(重跑神谕 ≠ 原结果):其存储必须持久(home 保有材料),驱逐必须写回;身份 = 产生节点(图节点身份)。边界条目与图内不可重算条目统一为「无配方条目」规则,一视同仁、不按范式枚举。
5. **赋值 = 版本化**。`x = x + 1` 在语义上 = "x₁ 创建、x₀ 失效、绑定移动",不是修改内存单元。顺序约束由 state edges 表达。"可变"不是内存单元的属性,是绑定可移动的许可。
6. **地址 = 映射**。`&x` = (条目标识, 偏移),字节地址只是经典投影,不是语义对象。指针算术合法性由条目标识 + 偏移域验证(现有 provenance 三 pass 保留不动)。
7. **映射实例正确性**。区域/arena/字节权限(CompCert v2)是经典映射实例,其正确性标准 = 保持条款 1–6 的可观测语义。

**2′. 驱逐的完整判据(2026-09-20 补;把条款 4b 从「例外」并入同一条判据)**

```
Evictable(x)  ⟺  Recoverable(x) ∨ PreserveRequiredState(x)
```

一个 materialization 可以消失,当且仅当:**之后能重新得到等价状态**(Recoverable);**或者消失前已把必须保留的状态转移到其他合法 materialization**(PreserveRequiredState)。

条款 2 是 x 落在 Recoverable 侧时的情形;条款 4/4b 是 x 落在 PreserveRequiredState 侧时的情形——**二者本是同一条判据的两支**,此前写成「规则 + 例外」,现并为一条。两点必须同时遵守:

- **Recoverable 是语义判据,不是语法判据**:配方存在 ≠ 可重算。volatile MMIO 读有"地址意义上的配方",但重读一次 ≠ 原值且有副作用,故 `Recoverable = false`。
- **判不出 ⇒ 不可驱逐(fail-closed)**:归属判定返回「未知」时判为不可驱逐,而不是可驱逐——否则「义务未满足」与「义务未被检查」在观测上不可区分,就是静默语义破坏。

展开、反例形态(含 `recipe = no` 的义务面)与判据形状见 docs/maintainer/design/materialization-space.md §四。

## 二、条款细读

### 条款 1:值 = 配方

"条目"是存储的一项,它的语义完全由产生方式决定。不存在"内存单元里存了什么"这种脱离产生方式的存储事实——问"这个值是什么"永远可以还原为"它是哪个图节点、用什么输入产生的"。这对验证的含义:验证器不需要为存储建模,只需要为配方(图)建模。

### 条款 2 + 3:驱逐与再生(缓存的两面)

驱逐不变量**在可再生的那一类上是**定义性质:凡配方还在的物化都可以被丢弃。再生等价是机制保证:重跑配方得到可观测等价的值。

**对无配方条目(条款 4/4b)这一支不成立**——它走 2′ 的 `PreserveRequiredState` 侧:材料必须保有或被合法转移,不得靠"重算"覆盖。

二者合起来给出编译器优化的正确性依据:
- 寄存器分配中把值溢出到 home(材料移走)= 驱逐 + 按需再生
- rematerialization(重算代替装载)= 条款 3 的直接应用
- 任何映射实例层(缓存/寄存器/持久)的动作都不改变语义——性能是唯一代价维度

### 条款 4 + 4b:无配方条目(`recipe = unrecomputable`;2′ 的 PreserveRequiredState 侧)

两类条目没有配方,驱逐必须写回、不可再生(即 `Evictable` 只能经 2′ 的第二支成立):

| 类别 | 例子 | 语法层标注 |
|---|---|---|
| 边界(图外输入) | MMIO、FFI 返回值、输入、测量 | unsafe(边界标注) |
| 图内不可重算 | 神谕、BSS 实数、FIXPT 声明、模糊融合 | 执行标注(见 dataflow-design §8) |

统一规则:无配方条目必须有 home(持久位置),驱逐必写回;身份 = 产生节点。不按范式枚举——新增范式时无配方规则不变。

### 条款 5:赋值 = 版本化

非 SSA 语言中变量的多次赋值在语义上是版本序列:x₁ 创建、x₀ 失效、绑定移动。这解释了三件事:

- "可变"不是内存单元的属性,是绑定可移动的许可(语义层不承诺任何内存单元)
- 顺序约束不属于存储,属于 state edges(副作用链)
- 存在区间(live range)是版本级别的——每条版本有自己的定值点与最后使用点(IR 载体见 existence-structure.md)

### 条款 6:地址 = 映射

`&x` 在语义层是 (条目标识, 偏移)——字节地址是经典投影(编码层对象)。由此指针算术的合法性 = 条目标识 + 偏移域验证,与类型无关;provenance(归属)与 offset 是图上本有的信息(推论 C,见 region-model.md)。

### 条款 7:映射实例正确性

任何映射实例(区域/arena/字节权限/寄存器)的正确性标准是同一个:保持条款 1–6 的可观测语义。由此"范式映射表"= 映射正确性定理表——经典行 = 证明条款 1–6 ⊇ 字节内存实现(CompCert 式语义保鲜);量子行 = 将来证明条款 1–6 ⊇ 量子存储实现。语义保鲜从"编译正确性定理"升级为"映射正确性定理"。

## 三、推论:范式映射表

| 行 | 映射实例 | 正确性定理 |
|---|---|---|
| 经典 | 字节内存 + 权限(CompCert v2) | 条款 1–6 ⊇ 字节内存实现 |
