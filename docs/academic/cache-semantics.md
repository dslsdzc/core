# 存储语义规则 1 到 7

这七条规则定义 Core 存储语义的存在格层。规则供验证器、翻译桥和 CIC 内核使用。实现与文档冲突时，以本文件为准。

缓存映射是这一层最直接的一类映射实例，不是这一层的名字。层定义见 `docs/maintainer/design/materialization-space.md`，存在结构的 IR 表示见 `docs/maintainer/design/existence-structure.md`，经典映射见 `docs/maintainer/design/region-model.md`，总览见 `docs/maintainer/design/memory-model.md`。

## 存在格与缓存映射

Core 的存储语义本体是存在格（Materialization Space，也叫 Existence Space）。它不绑定字节内存，也不绑定寄存器。它回答四个问题：

1. 哪些物化是合法的。
2. 哪些物化可以共存。
3. 哪些物化表示同一个条目和同一个版本。
4. 哪些转换保持语义。

缓存映射是这一层里最直接的一类实例。传统编译器的内存模型从机器出发，使用字节寻址和权限，被具体范式绑定。缓存映射从值的产生和保留出发：值由生成方法决定，存储是生成方法结果的保留。

机器内存、寄存器和 VRAM 都是缓存映射的实例。量子存储和持久映射是其他实例。范式映射表由此成立。

“缓存”这个词隐含六个假设：存在一个权威值、值可以复制、存储内容可以移除、值可以重新物化、存在后备存储、不同副本表示同一个值。这些假设只对可重算且可复制的那一类成立。MMIO 读、随机数、一次性 token、线性资源、事务临时状态和分布式唯一权威都在同一层内，但不满足这些假设。逐条分析见 `materialization-space.md` 第三节。因此不能用“缓存”给整个层命名。

实现一直就是这个存在格。HDFG 的节点是生成方法，边是值流，state edge 是顺序约束，移除和重算对应丢弃存储内容与重跑节点。早期文档把 CompCert v2 字节模型当成语义本体，这个错误已经在 2026-08-15 纠正，代码没有改动。

## 七条规则

这七条是存在格这一层的规则，不是缓存这一类映射的专属规则。缓存映射是最直接实现它们的一类实例。

1. 值等于生成方法。条目的语义由产生它的图节点和输入边组成。不存在独立于生成方法的存储事实。
2. 移除不变量。对可重算条目（`recipe = recomputable`），移除图内任意条目的存储内容、保留生成方法，不改变可观测语义，只影响性能。形式化写作 `⟦G ∖ storage(e)⟧ = ⟦G⟧`。这是缓存映射这一类的定义性质；层的一般检查见 2′。
3. 重算等价。重跑生成方法节点产生的值与原条目可观测等价。这是规则 2 的机制保证，也是更换映射时保持语义的依据。
4. 边界规则。图边界输入（MMIO、FFI、输入、测量）是无生成方法条目，属于边界类，语义上是符号常量。语法层用 `unsafe` 标注边界，语义层只称“边界”。边界之外需要 state，边界之内都是可重算的。
4b. 图内不可重算。执行标注空间（外部输入、BSS 实数、FIXPT 声明、模糊融合，见 `docs/maintainer/design/execution-annotation-space.md`）中存在图内无生成方法的条目。它们不是边界，也不能重算。规则 2 和规则 3 对它们不成立，因为重跑外部输入不等于原结果。它们的存储内容必须持久保留在 home 中，移除前必须写回。身份等于产生节点。边界条目和图内不可重算条目统一按“无生成方法条目”规则处理，不按范式枚举。
5. 赋值等于版本化。`x = x + 1` 在语义上表示 `x₁` 创建、`x₀` 失效、绑定移动，不是修改内存单元。顺序约束由 state edge 表达。“可变”不是内存单元的属性，是绑定可以移动的许可。
6. 地址等于映射。`&x` 是条目标识加偏移，字节地址只是经典投影，不是语义对象。指针算术的合法性由条目标识和偏移域验证。现有 provenance 三个 pass 保留不动。
7. 映射实例正确性。区域、arena 和字节权限（CompCert v2）是经典映射实例。它们的正确性标准是保持规则 1 到 6 的可观测语义。

### 规则 2′：完整的移除检查

规则 4b 原先写成规则 2 的例外。2026-09-20 起合并为一条检查：

```text
Evictable(x)  ⟺  Recoverable(x) ∨ PreserveRequiredState(x)
```

一个物化可以消失，当且仅当满足下面任一条件：

- 之后能重新得到等价状态（`Recoverable`）。
- 消失前已经把必须保留的状态转移到其他合法物化（`PreserveRequiredState`）。

规则 2 是条目落在 `Recoverable` 一侧的情形。规则 4 和 4b 是条目落在 `PreserveRequiredState` 一侧的情形。两者是同一检查的两个分支。

有两点必须同时遵守：

- `Recoverable` 是语义检查，不是语法检查。生成方法存在不等于可以重算。volatile MMIO 读在地址意义上有生成方法，但重读不等于原值，而且有副作用，因此 `Recoverable = false`。
- 无法判定时不可移除，也就是失败关闭。归属判定返回“未知”时，判为不可移除，不判为可移除。否则“义务未满足”和“义务未被检查”在观测上无法区分，会破坏语义而不报错。

展开、反例形态和检查形状见 `docs/maintainer/design/materialization-space.md` 第四节。

## 规则细读

### 规则 1：值等于生成方法

条目是存储的一项，它的语义完全由产生方式决定。不存在“内存单元里存了什么”这种脱离产生方式的存储事实。问一个值是什么，答案永远是：它是哪个图节点、用什么输入产生的。

对验证来说，验证器不需要为存储建模，只需要为生成方法（图）建模。

### 规则 2 和 3：移除与重算

对可重算条目，移除不变量是定义性质：只要生成方法还在，物化就可以丢弃。重算等价是机制保证：重跑生成方法得到可观测等价的值。

对无生成方法条目（规则 4 和 4b），这个分支不成立。它走 2′ 的 `PreserveRequiredState` 一侧：存储内容必须保留或合法转移，不能用重算覆盖。

两条合起来给出编译器优化的正确性依据：

- 寄存器分配把值溢写到 home，相当于移除存储内容并按需重算。
- rematerialization（重算代替装载）是规则 3 的直接应用。
- 任何映射实例层的动作都不改变语义，性能是唯一的代价。

### 规则 4 和 4b：无生成方法条目

两类条目没有生成方法。移除时必须写回，不能重算。它们只能通过 2′ 的第二个分支变为可移除。

| 类别 | 例子 | 语法层标注 |
|---|---|---|
| 边界（图外输入） | MMIO、FFI 返回值、输入、测量 | `unsafe`，边界标注 |
| 图内不可重算 | 外部输入、BSS 实数、FIXPT 声明、模糊融合 | 执行标注，见 `execution-annotation-space.md` |

统一规则：无生成方法条目必须有 home，也就是持久位置；移除前必须写回；身份等于产生节点。规则不按范式枚举，新增范式时无生成方法规则不变。

### 规则 5：赋值等于版本化

非 SSA 语言中，变量的多次赋值在语义上是版本序列：`x₁` 创建、`x₀` 失效、绑定移动。这解释三件事：

- “可变”不是内存单元的属性，是绑定可以移动的许可。语义层不承诺任何内存单元。
- 顺序约束不属于存储，属于 state edge，也就是副作用序列。
- 存在区间是版本级别的。每个版本有自己的定值点和最后使用点。IR 表示见 `existence-structure.md`。

### 规则 6：地址等于映射

`&x` 在语义层是条目标识加偏移。字节地址是经典投影，属于编码层。因此指针算术的合法性由条目标识和偏移域验证决定，与类型无关。provenance（归属）和 offset 是图上已有的信息，见 `region-model.md`。

### 规则 7：映射实例正确性

任何映射实例（区域、arena、字节权限、寄存器）的正确性标准相同：保持规则 1 到 6 的可观测语义。

因此范式映射表就是映射正确性定理表。经典行证明规则 1 到 6 包含字节内存实现，使用 CompCert 式语义保持。量子行将来证明规则 1 到 6 包含量子存储实现。语义保持从“编译正确性定理”扩展为“映射正确性定理”。
