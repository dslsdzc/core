## 一、三层映射

```
不同范式 / 计算语义
        |
        v
       图(HDFG)：关系空间，发生什么
        | 图到格映射
        v
       格(内存模型)：状态/存储空间，如何存在
        | 格到编码映射
        v
      编码：物理编码空间，如何实现
```

### 格这一层的必要性

图回答“这个计算世界中有什么关系、什么可能发生”；格回答“这些东西如何成为具有状态和位置的可实现存在”。如果图和编码直接相连，大量“如何存在”的问题（节点是什么内存对象、关系怎么保存状态、两个可能分支的状态怎么共存、非因果怎么落到地址、节点生命周期）都会被放进一个承担全部工作的图到机器码映射器。

### 三层的数学定位

- 图 = 关系空间：表达可以超越经典图灵机执行模型的语义（非因果、模糊、超图灵）。超图灵性属于图，不属于格。
- 格 = 状态/存储空间：提供足够一般的状态模型，使图能够被映射下来；格不需要理解超图灵，只需让可被当前执行环境实现的部分拥有状态、位置、关系和可访问性。
- 编码 = 物理编码空间：把格编码成具体机器的地址、字节、指令、位模式（2026-08-27 更名：早期名称“二进制”固定了经典惯例，不符合零硬件惯例；量子、模拟和光学都不是二进制。）
- 格不重新引入程序顺序：传统 IR（SSA/LLVM）本质上是“另一种程序”，按执行路径组织；格是中间存在空间，不必重新引入程序顺序。

### 跨范式自由度（格的价值）

- 不同范式（命令式、函数式、数据流、并发、事件驱动、非确定、模糊、超图灵）的差异首先由图的标注空间表达。
- 格没有被某个有限、固定的传统计算范式预先设上限，可构造的表达空间无界。
- 真正的问题是“C 的语义能否找到一个格映射”，而不是“格能不能表示 C”。格本身不需要知道范式是什么。

## 二、术语澄清：格的两义

| 术语 | 含义 |
|---|---|
| 格（层） | 内存模型 = 中间存在空间（第二层映射），本文主体 |
| 格（Lattice） | 层内组织代数成分（偏序 + join/meet）。v4：映射参数，不是层本体承诺 |

## 三、定稿原则

### 规则封闭、对象开放（v4 定稿）

- 规则封闭，不新增规则：规则 1–7 加最弱理论（关系层面）。新范式出现时层本体不变，维护范围有界（2026-09-20 层定义修订只更换层名和表述用词，规则数不变）。
- 对象（开放，无界）：条目、方法、标注。任何范式的值都可以容纳（量子振幅、FIXPT 不动点、模糊隶属度），对象开放意味着表达范围无界。
- 一切结构是图层导出或映射参数：共存关系是图层导出（图活性），不是格层承诺；格代数、区域、字节、寄存器都是映射实例。

### 无格承诺（v4 定稿）

- 任何具体格都是签名加恒等式，恒等式会给表达空间设上限。解法不是选择更宽的格，而是把语义写在比格更弱的理论里：最弱理论有最多模型，因此无界。
- 存储判定需要的最弱结构是共存关系（对称关系，无传递性：a 与 b 共存、b 与 c 共存时，a 与 c 不必共存），连预序规则都不需要。
- 格（Lattice 代数）降级为映射实例的组织参数：经典行用乘积格，量子行用别的，未来范式用未知格；每个范式引入自己的代数都是参数。
- 数学原则：用函子式或普适构造定义层，不用情形分析；对象由普适性质定义（直到同构唯一），不选具体结构。
- 验证视角：判定/定理写在最弱理论里，对一切格成立；CIC 内核里任何具体格都是该理论的一个模型，健全性对理论成立，就对所有模型成立。

## 四、新范式只需三件事，不是新建格

1. 图标注空间加标签：统一空间，加标签不是新机制（FUZZY/FIXPT/Oracle/CORE 已是标签）。
2. CIC 内部定义新结构：一个逻辑，健全性继承。
3. 硬件映射：不可避免的工程，但是映射工作，不是层工作。

判定规则对条目类型是通用的：只操作“条目”这个类别（位置 + 方法 + 存在），不读取值的内容。新增条目种类不需要新的判定规则。
