## 一、三层映射

```
不同范式 / 计算语义
        ↓
       图(HDFG)     —— 关系空间:发生什么
        ↓ 图 → 格映射
       格(内存模型)  —— 状态/存储空间:如何存在
        ↓ 格 → 编码映射
     编码          —— 物理编码空间:如何实现
```

### 为什么需要格这一层

图回答"这个计算世界中有什么关系、什么可能发生";格回答"这些东西如何成为具有状态和位置的可实现存在"。若图 → 编码直连,大量"如何存在"的问题(节点是什么内存对象、关系怎么保存状态、两个可能分支的状态怎么共存、非因果怎么落地址、节点生命周期)都会被迫塞进一个万能的图 → 机器码映射器。

### 三层的数学定位

- **图 = 关系空间**:表达可超越经典图灵机执行模型的语义(非因果、模糊、超图灵)——**超图灵性属于图,不属于格**
- **格 = 状态/存储空间**:提供足够一般的状态模型使图能被映射下来;格不需要理解超图灵,只需让可被当前执行环境实现的部分拥有状态/位置/关系/可访问性
- **编码 = 物理编码空间**:把格编码成具体机器的地址、字节、指令、位模式(2026-08-27 更名:原"二进制"硬编码经典惯例,违反零硬件惯例——量子/模拟/光学皆非二进制)
- **格不重新引入程序顺序**:传统 IR(SSA/LLVM)本质上仍是"另一种程序"——按执行路径组织;格 = 中间存在空间,不必重新引入程序顺序

### 跨范式自由度(格的价值)

- 不同范式(命令式/函数式/数据流/并发/事件驱动/非确定/模糊/超图灵)的差异首先被图吸收(图层标注空间)
- 格不被某个有限、固定的传统计算范式预先封顶——可构造表达空间无界
- 真正的问题是"C 的语义能否找到一个格映射",而不是"格能不能表示 C"——**格本身不需要知道范式是什么**

## 二、术语澄清:格的两义

| 术语 | 含义 |
|---|---|
| 格(层) | 内存模型 = 中间存在空间(第二层映射)——本文主体 |
| 格(Lattice) | 层内组织代数成分(偏序 + join/meet)——**v4:映射参数,非层本体承诺** |

## 三、定稿原则

### 规则封闭、对象开放(v4 定稿)

- **规则(封闭,永不新建)**:缓存语义七条 + 最弱理论(关系层面)。新范式出现时层本体一字不改——**规则封闭 = 维护有界**
- **对象(开放,无界)**:条目、配方、标注。任何范式的值都装得下(量子振幅、FIXPT 不动点、模糊隶属度)——**对象开放 = 表达无界**
- 一切结构是图层导出或映射参数:共存关系是图层导出(图活性),不是格层承诺;格代数、区域、字节、寄存器都是映射实例

### 无格承诺(v4 定稿)

- 任何具体格 = 签名 + 恒等式 → 恒等式封顶表达空间。解法不是选更宽的格,而是**把语义写在比格更弱的理论里**——最弱理论 = 最多模型 = 无界
- 存储判定需要的最弱结构 = 共存关系(对称关系,无传递性——a 与 b 共存、b 与 c 共存,a 与 c 不必共存),连预序公理都不需要
- 格(Lattice 代数)降级为**映射实例的组织参数**:经典行用乘积格、量子行用别的、未来范式用未知格——每范式引入自己的代数都是参数
- 数学原则:**用函子式/普适构造定义层,不用情形分析**;对象由普适性质定义(直到同构唯一),不选具体结构
- 验证视角:判定/定理写在最弱理论里,对一切格成立;CIC 内核里任何具体格都是该理论的一个模型——健全性对理论成立,就对所有模型成立

## 四、新范式只需三件事(不是"新建格")

1. **图标注空间加标签**——统一空间,加标签不是新机制(FUZZY/FIXPT/Oracle/CORE 已是标签)
2. **CIC 内部定义新结构**——一个逻辑,健全性继承
3. **硬件映射**——不可避免的工程,但是映射工作,不是层工作

判定规则是**条目泛型**的:操作"条目"这个类别(位置 + 配方 + 存在),不读值的内容——新条目种类不需要新判定规则。

## 五、范式映射表(推论)

范式映射表 = 映射正确性定理表(cache-semantics 条款 7 的推论):

| 行 | 映射实例 | 正确性定理 |
|---|---|---|
| 经典 | 字节内存 + 权限 | 缓存语义 ⊇ 字节内存实现 |
| 寄存器 | 寄存器缓存 + home | 判定四条(regalloc-cache-mapping) |
| 量子(将来) | 量子存储 | 缓存语义 ⊇ 量子存储实现 |

每行定理共享七条——新范式不需要新的存储语义,只需要新映射与新证明。
