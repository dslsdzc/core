# ADR-0009: 规约系统 v2：CIC 内核 + SMT 证书架构

- 日期：2026-08-11（v2 定稿）
- 状态：accepted（设计定稿，未实现）
- 决策者：DslsDZC

## 背景

规约系统的早期形态没有确定验证后端和表达力上限。待定的问题是：规约表达力、验证健全性和使用要求三者如何平衡。

## 决策

- 规约语言编译为 CIC 项（归纳构造演算）：量词、归纳和高阶都在内核内，表达力没有上限。
- SMT 证书由外部求解器生成：目标一阶化，交给 SMT 求解，得到证书，翻译成 CIC 证明项，再由内核重新验证。健全性的唯一来源是 CIC 内核（SMTCoq 模式）；SMT 只承担搜索器角色。
- 使用要求分层：编译器自动推导，然后是 `#check`/`#ensure`，再到 `spec fn`（用 Core 编写的纯检查函数），最后是用户入口分层（`#induct`/`#lemma`/证明项逃逸）。
- 语法形态 2026-09 定稿：`#check`/`#ensure` 标注，`.cr` 内联（与 ADR-0001 的退役同步）。

## 后果

- 正面：表达力与健全性解耦，内核是最小信任根；证明驱动优化，已证明的性质可以作为优化器的输入条件。
- 负面：整个流程未实现（解析/翻译桥/SMT 通道/内核绑定）；CIC 内核的选择尚未决定（Rocq 与 Lean 4，等待社区结论）。
