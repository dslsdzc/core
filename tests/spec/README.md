# 规约语法检查语料（批 6：正式规约语法 `#check` / `#ensure`）

性质：是编译单元（由 `tests/selfhost/test_spec_grammar.py` 逐档驱动：`build --static`，
负例断言 rc=1 + 诊断码 + 零产物）。不进分支 1（`tools/baseline/parity_run.sh`，76 档）与
分支 2（`tests/probes/`，29 档）两套语料。那两套是既有行为回归检查，其计数不变本身就是
“本批对旧面零扰动”的最强证据（维护者 2026-09-17 确认）。

命名规则：`t2_*` = 语法面（T2），`t3_*` = 检查面（T3），`t4_*` = dump 通道（T4），
`delta_*` = `.ccr` 零影响对拍对（`_plain` / `_annot` 成对使用，见下）。
正控 = 期望 rc=0 + 有产物；负控 = 期望 rc=1 + 零产物。

## `delta_*` 对的用法（检查 D，不可拆）

`delta_d9_plain.cr` / `delta_d9_annot.cr`（及 `d0` 对）是同一程序分别带注解和不带注解的最小对拍对，
用于 `.ccr` 零影响的三段式检查：

1. ELF 逐字节同（带注解和不带注解）；
2. `.ccr` 除 STR 外 7 段逐字节同；
3. STR Δ 恰为公式值：`Δ = Σ(4 + len(m))`，`m` 遍历注解独有词素（即不会被驻留的标识符或关键字）。

机制（勿删）：`src/compiler/lexer.cr` 的 `add_tok_str` 对每个 IDENT/关键字词素都调
`str_intern`，这是既有行为、非本批引入。因此“带注解和不带注解逐字节全同”不可构造（注解里的新词素
必然进 STR）；最强可构造形就是上面三段式。多一字节即失败。
`d0` 是零 Δ 用例（注解词素已在程序别处驻留，所以 Δ 必须 = 0），它保证检查不会反过来要求非零 Δ。

## 增删纪律

- 正控只增不减；负控若因能力变更改为正控（如未来支持注解内调用，例如 `t3_neg_call_banned.cr`），
  须在套件里登记其失效证据并把用例移入正控，不得直接删除。
- 新增语料须同步 `tests/selfhost/test_spec_grammar.py` 的对应组与计数注。
